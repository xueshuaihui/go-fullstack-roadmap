// SERVER-FIRST · 22 WEEKS

从零手写 HomeCube 服务端

目标是 app 壳基座 + 家庭记账全功能的服务端：72 条接口、约 22-25 张表、一个模块化单体。
每天一张卡：一个知识点 + 一个当天能收尾的增量。工作日 20-30 分钟，周六 4 小时，周日 2 小时读前端。

Go 1.24+GinGORM Postgres 16golang-migrateJWT 双 token Vue 3uni-appDocker Compose
总体进度（勾选每日「完成检查」自动累计）0%

每周怎么跑（~10 小时）

时段做什么投入
周一 ~ 周五每天一张 d1-d5 卡：读讲义 → 落一个微增量。只允许六类（第六类只给 S8）：加字段/struct、加路由或 handler 骨架、补一个测试、写一条迁移、把假数据换成真查询、工程化收口产物20-30 分钟 ×5
周六d6 卡：把本周 5 个微增量串成一条完整能力，补齐测试约 4 小时
周日前半f1 卡：前端线。代码由 agent 写，你的判据是能读懂、能改、能定位 bug 在哪一层约 2 小时
周日后半费曼复盘（不看资料把本周讲一遍）→ 提交 → 在 notes/ 写下周第一天做什么约 2 小时

收工时仓库必须绿：make build 过、已有测试过。当天做不完说明切得太大，当场再切小——不许留半成品到第二天。

落后不追赶：顺延，不裁剪判据。服务端与前端两条线各自顺延，互不挪用时间。卡面只写相对序号（S1·D3），不承诺任何日期。

勾选状态存在你自己的浏览器里（localStorage），换设备会清零，属正常现象。

走完 22 周的你

Go 与分层徒手写出 handler / service / repo 三层，讲得清每层为什么在那
数据建模Postgres 双 schema、迁移可 up→down→up 重放、每表带 family_id 与软删
鉴权与隔离JWT 双 token + 四级角色矩阵，越权读返 404 与不存在同形
并发能用 -race 证明自己修好了数据竞争，讲得清 channel 与 Mutex 各自该用在哪
财务口径金额整数分、游标分页、时间窗五档、季/年 = 月桶之和且前端二次累加为 0
壳基座面集合四层在服务端一处合成，客户端零裁剪；未读口径唯一、三个出口同值
交付docker compose 起全套，干净机器照着 README 能复现
前端能读懂任意一页、能改字段与样式、能不靠 agent 说出一个 bug 在哪一层
纪律72 条接口逐条划掉，四条历史反例一条没犯
