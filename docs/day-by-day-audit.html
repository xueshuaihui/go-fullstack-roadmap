五、除了字数，还补了什么

1. 每张表都指向「会怎么坏」

报错对照表统一写成现象 → 原因 → 修法三列，且第一列是报错原文（可直接搜）。新增 30+ 张，覆盖 database is locked、superfluous WriteHeader、DATA RACE、UNIQUE constraint failed、no such file or directory（其实是缺动态链接器）等真实报错。

2. 每天一个「5 分钟最小验证」

先跑一个 5 分钟的实验，再去做 3 小时任务。例：Docker 那天先 docker run --rm ledger-api id 看 uid；分页那天先造 5 条同日期数据逼出排序不稳定。

3. 自测第三题改成「跑一下会看到什么」

例如 P5D7 问「连续两次 Where 后第二条 SQL 带不带第一个条件」，答案是「跑 go test -run TestSessionIsolation -v 对比两条 SQL」。这类题背不出来，只能动手。

4. 修掉了几处会把人带偏的错误

P1D14 的金额单位前后矛盾（一处「分」一处「元」）已统一为「入口转分、出口转元」；P1D9 的任务把 amount 写成 REAL 已改回 INTEGER 分；P5D7 原本写「这里有歧义，必须实测」的答案改成了确定结论 + 验证方法。

5. 补上跨阶段「互相打脸」的地方

P6D5 的健康检查用 wget，但 P6D4 建议用 distroless（没有 wget）——现在明确给出「给二进制加 healthcheck 子命令」的解法；P6D12 明确了 CSRF cookie 必须 HttpOnly: false，与 session cookie 相反。

6. 任务都带验收命令

例：P5D19「把 GetEntry 的 user_id 去掉，隔离用例必须变红」；P6D6「在 00002 里塞一条错误 SQL，确认 api 不会启动」。能被破坏的验收，才是真的验收。

七、给学生的一句话

这份材料不会让你「读完就会」。它给你的是一条每天可验证的路径：先花 5 分钟跑一个最小实验，再读讲解，再合上答案自测，再亲手弄坏一处代码看它怎么报错，最后做当天的任务。卡住时不要重读，去看「报错对照」那一栏——大多数卡点不是概念不懂，而是报错没读懂。
