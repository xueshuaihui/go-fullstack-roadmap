## 〇、这份计划是什么

**不是交付计划，是学习计划。**

两者的区别很关键：

| | 交付计划 | 学习计划（本文件） |
|---|---|---|
| 分母是 | 功能点 | **能力** |
| 阶段划分依据 | 模块边界 | **认知难度** |
| 排期单位 | 人月 | **每周 15 小时** |
| 判据 | 功能做完 | **能不能讲清 / 能不能独立写出来** |
| 落后时 | 加人赶工 | **顺延，不裁剪完整度** |

### 三条设计原则

| # | 原则 | 做法 |
|---|---|---|
| 1 | **交替而非串行** | 每天 1/3 时间做前端（你最熟，快速建信心）+ 2/3 学后端 |
| 2 | **难度递增而非模块切分** | 阶段按认知难度排，不按 PRD 章节排。硬骨头集中攻|
| 3 | **每天必须有可运行产物** | 收工时仓库绿、当天的东西能跑 |

**为什么第1 条重要**：前 4 周全砸在 Go 语法上，你看不到任何能点的东西，坚持率会崩。而前端是你最熟的，用它建信心成本最低。

## 四、阶段详解

### 每阶段的固定结构

```
第 1-N 周   新知识点（每天 1 张卡：概念 + 为什么需要 + 最小代码 + 一个坑）
最后 1 周    缓冲（重做 + 补课，不学新东西）
```

**工作日微增量（1h/天）只允许这四类**：
1. 加一个字段 / 一个 struct / 一个枚举
2. 加一条路由 + handler 骨架（先返回假数据）
3. 补一个测试用例
4. 写一条迁移的 up 或 down

**硬约束**：收工时仓库必须绿。当天做不完就当场再切小，**不留半成品到明天**。

### S0 · 工具链与环境（W1-W2 · 12 张卡）

**为什么放最前**：环境装不通，后面每一周都在和「为什么跑不起来」打架。这是最容易放弃的地方。

| 天 | 知识点 | 做什么 | 当天可验证 |
|---|---|---|---|
| 1 | 版本管理心智 | `git init` + `.gitignore` + 第一次 commit | 仓库建起来了 |
| 2 | 进程与端口 | 装 Go，跑 `go run` 一个 hello world | 浏览器看到输出 |
| 3 | 容器是什么 | 装 Docker + PostgreSQL，`docker run` 起库 | `psql` 连进去看到空库 |
| 4 | 环境变量与配置 | 把密码从代码里拿出来 | 重启容器换密码生效 |
| 5 | 前端工具链 | 装 Node，跑起 uni-app 官方模板 | 模拟器或浏览器出页面 |
| 6（周六） | 串起来 | Docker Compose 起「Postgres + 一个 Go 服务 + 一个 Vue 页」 | `docker compose up` 全套跑通 |

**周日**：复盘——不看资料讲清「容器 / 进程 / 端口 / 环境变量」四者的关系。

**通过判据**：
- `docker compose up` 一条命令起全套，看到一个真实页面
- 能讲清「容器里跑的是什么、端口映射是什么、数据存在哪」
- Go / Node / Docker / Postgres 四个工具都能独立启动

### S1 · Go 语言地基（W3-W6 · 24 张卡）

**全项目最枯燥的一段，但跳不过去。** 目标不是「学会 Go」，是「能读懂 Go 代码的结构」。

| 周 | 知识点 | 配套产出 |
|---|---|---|
| W3 | 包与模块、变量与类型、结构体与方法 | 命令行工具：把一段 JSON 格式化输出 |
| W4 | slice / map、循环分支、指针 | HTTP 客户端：请求公开 API 并解析响应 |
| W5 | interface 与隐式实现、`error` 包装、defer | 日志库：三种级别 + 写文件 |
| W6 | goroutine 与 channel、select、context | 并发抓取器：并发 10 个 URL，超时 3s |

**通过判据**（四条全过）：
1. 徒手写出：struct + method + interface 隐式实现 + error 包装
2. **讲清**：interface 为什么隐式实现、error 为什么要包装而不是直接 return
3. **讲清**：channel 和 `sync.Mutex` 各自该用在哪
4. 读得懂一段陌生的 Go 代码，能说出它做了什么、有什么坑

> **缓冲**：这 4 周大概率会超。超了不压缩，往后顺延。

### S3 · 数据持久化（W9-W12 · 24 张卡）

**本项目最贵的知识之一。** 游标分页、多租户隔离、迁移可重放，三件事都在这里。

| 周 | 知识点 | 配套产出 |
|---|---|---|
| W9 | SQL 基础与 Postgres DDL | 徒手写 `CREATE TABLE`，理解每个约束 |
| W10 | GORM 基础与关联、**迁移工具** | 内存存储换 Postgres；`up→down→up` 可重放 |
| W11 | **游标分页**（不用 offset） | 1000 条数据翻完不重不漏 |
| W12 | 事务、软删、**多租户隔离** | 每张表带 `family_id`，每条查询带 `WHERE family_id=?` |

**通过判据**：
1. 迁移 `up → down → up` 可重放，数据无损
2. **游标分页在 1000 条样本上翻完，不重复不遗漏**（硬判据）
3. **讲清**：为什么用游标不用 offset（offset 在大数据量下会跳数据）
4. **讲清**：多租户为什么每条查询都带 `WHERE family_id`
5. 能设计一张带 `family_id` + `version` + `deleted_at` 的表，说出三者各自解决什么

### S4 · 身份与鉴权（W13-W17 · 31 张卡 · 系数 1.3）

**第一个硬骨头。** 前端的人最容易在这里低估难度——JWT 的过期、刷新、轮换、失效时机，每一条都有坑。

| 周 | 知识点 | 配套产出 |
|---|---|---|
| W13 | 密码哈希（为什么不能明文、为什么不能用 MD5） | 用户表 + bcrypt 注册/登录 |
| W14 | **JWT 双 token**：access + refresh | access 15 分钟过期，refresh 存哈希 |
| W15 | refresh 轮换与失效链 | 旧 token 作废、登出、重置密码后全链失效 |
| W16 | 鉴权中间件与上下文注入 | 中间件解析 token，把 `member_id`/`family_id` 注入上下文 |
| W17 | 缓冲 + 重做 | 把 W13-W16 串成完整链路 |

**通过判据**：
1. 注册 → 登录 → 拿 token → 访问受保护接口，全链路通
2. **access 过期后能自动用 refresh 换新**
3. **登出后 refresh token 立即失效**（不是等自然过期）
4. **讲清**：token 里放什么、不放什么；为什么 refresh 存哈希
5. 能说清「为什么手机号验证码不需要密码，但注册又要密码」这类边界怎么定

### S5 · 权限与多租户隔离（W18-W23 · 34 张卡 · 系数 1.4）

**全项目最难的一段。** 唯一能发现做错的方式是**越权测试**。

| 周 | 知识点 | 配套产出 |
|---|---|---|
| W18 | 四级角色 owner / member / ward / guest | 角色枚举从建表起就存在 |
| W19 | 三维权限 `scope = module/data/action` | 模块级判定（能看见哪些面） |
| W20 | 数据级与字段级可见性 | 「他人私密流水只有作者与管理员能读」 |
| W21 | **越权测试**（先红后绿） | 写测试：child 读他人私有数据，**必须被拒** |
| W22-23 | 缓冲 + 重做 | 把 W18-W21 串起来 |

**通过判据**（**全是硬判据，没有一条是「讲清了就算过」**）：
1. **用 A 家 token 读 B 家数据 → 404，不是 403**（安全基线）
2. child 读 adult 私有流水 → 被拒且落审计
3. 四级角色每级的权限清单能列出来，且与代码判定**逐条对得上**
4. **讲清**：为什么越权返 404 不返 403（403 等于告诉攻击者「东西存在」）
5. 有一个**跑在代码里**的越权测试循环，不是手动点几次

### S8 · 时间系统 Calendar（W28-W33 · 36 张卡 · 系数 1.2）

**这一段是最需要理解「为什么」的阶段。** `calendar` 是与HomeOS 同级的独立系统级面，不是它的模块。

**PRD 给的理由**：时间系统是唯一被全部业务面横切依赖的能力。留在 HomeOS 里会让它同时承担「连接」和「到期触发」两种职责，而设计原则是「一面一系统、系统有边界」。命名同源要求一个 code 对应一个服务、一个 schema、一条迁移序列——横切能力没有自己的 code，就无法被门禁如实描述。

| 周 | 知识点 | 配套产出 |
|---|---|---|
| W28 | **独立服务的边界**：建第二个服务、第二个 schema、第二条迁移序列 | `svc-calendar` 起得来，`calendar` schema 建得出 |
| W29 | **三张表** `calendar_event`/`todo`/`reminder` | 三表 + 改名迁移（理解「改名不新建表」） |
| W30 | **9 条接口** `/api/calendar/*` | 见下方清单 |
| W31 | **七类命名域** | 能默写 `calendar` 这一列的七个值 |
| W32-33 | 周期规则：每天/周/月/年、自定义、跳过、顺延 | 重复规则能算下一个触发日 |

**要实现的 9 条接口**：

| 接口 | 说明 |
|---|---|
| `POST /api/calendar/events` | 仅管理台手工补录（业务面不得调） |
| `GET /api/calendar/events` | 到期中心读接口，日/周/月三视图按已出生服务聚合 |
| `GET /api/calendar/events/{id}` | 详情带 `source_system`/`source_id`，供深链 |
| `POST /api/calendar/todos` | 创建待办 |
| `GET /api/calendar/todos` | 列表（分配给我/我创建的/已归档） |
| `PUT /api/calendar/todos/{id}` | 编辑（带 `version`），完成回写发 `calendar.todo.completed` |
| `POST /api/calendar/reminders` | 创建提醒 |
| `GET /api/calendar/reminders` | 提醒列表 |
| `PUT /api/calendar/reminders/{id}` | 编辑（暂停与删除发 `{code}.due.revoked`） |

**通过判据**（对应里程碑 M4）：
1. **第二个服务独立跑起来**：自己的 schema、自己的迁移序列、独立启停
2. **9 条接口全通**，`/api/calendar/*` 与 `/api/homeos/*` 是两个不同的域
3. **三张表前缀都是 `calendar_`，且不在 `homeos` 的 schema 里**
4. **讲清**：为什么它不能寄生在 HomeOS 里
5. **讲清**：日历页为什么在主包内、不建 `pages/calendar` 分包
6. 周期规则能算对下一个触发日，含跳过与顺延

### S9 · 到期注册契约与跨面读取（W34-W37 · 23 张卡 · 系数 1.3）

**全项目「系统间怎么协作」的第一次真实演练。**

**核心机制**：
```
业务对象有 due_at
   ↓ 业务面在自己写事务内登记注册意图
   ↓ 经事件发布 {code}.due.registered
calendar 消费 → 落 calendar_reminder（幂等键去重）
   ↓ 到点
calendar 发 calendar.reminder.fired
   ↓ homeos 消费
homeos 落 Notification（分型 reminder）→ 站内信 + push
```

| 周 | 知识点 | 配套产出 |
|---|---|---|
| W34 | **注册契约**：字段映射（`source_system`/`source_id`/`source_family_id`/`done_returns_to`） | 业务对象能注册到 calendar，幂等键 `(source_system, source_id, kind)` |
| W35 | **撤销与级联失效**：业务对象删了，注册项也要失效 | 撤销链路 + 删除语义 |
| W36 | **完成回写**：在到期中心点了完成，要回写业务对象 | `done_returns_to` 回调跑通 |
| W37 | **跨面只读 + 降级**：`due_today` 怎么拿、失败怎么办 | 超时 ≤300ms、重试 ≤1 次、降级为「暂不可用」 |

**通过判据**：
1. **重复注册同一对象 → 只有一条注册项**（幂等键生效）
2. **业务对象删除 → 对应注册项级联失效**
3. **在到期中心点完成 → 业务对象状态真的被回写**（不回写视为缺陷）
4. **`calendar` 不可达时首页今日区显示「暂不可用」但到期入口保留**，不是整页崩
5. **讲清**：为什么触发归 calendar、通知下发归 homeos
6. **讲清**：为什么业务面不能自己起定时器（多套定时器 = 多套真相 + 重复通知）

> **这条链路是全项目最重要的技术资产**：后面的预算超支通知、周期记账自动入账、家庭动态流，全都是同一个模式的重复。

### S10 · 功能域：账户 + 流水（W38-W43 · 33 张卡 · 系数 1.1）

**第一个有难度的业务功能域。** 流水包含转账、乐观锁、幂等、软删、回收站、附件六件事。

| 周 | 内容 |
|---|---|
| W38 | 账户：余额计算、默认账户、**归档（余额非 0 拒绝）** |
| W39 | 流水：增删改查、**游标分页 + 多条件筛选** |
| W40 | **转账**（一笔业务两个账户，事务边界） |
| W41 | **乐观锁**（`version` 冲突返 409）+ **幂等键**（`client_request_id`） |
| W42 | **软删 + 回收站恢复** |
| W43 | 附件上传（≤3 张/笔、≤5MB/张）+ **把流水的 `due_at` 注册到 S9 的到期中心** |

**通过判据**：
1. 两人同时改一笔流水 → 后到者得 **409 且带双方版本**，不静默覆盖
2. 同一 `client_request_id` 重复提交 → **只产生一笔**
3. **账户余额非 0 时归档被拒绝**，返回业务错误码
4. **软删有、恢复入口也有**（软删没恢复入口 = 数据进黑洞）
5. 附件超 3 张或超 5MB 被服务端拒绝
6. **一笔带 `due_at` 的流水能被注册到 calendar，并在到期中心看到**
7. **讲清**：乐观锁和幂等分别解决什么问题，能不能互相替代

## 六、每日时间模板

### 工作日（1h/天 · 5 天 = 5h）

```
0-10min   打开昨天的东西，跑一遍，确认是绿的
10-40min  今天的新知识点（先读卡，再写代码）
40-55min  写代码，把知识点落成真实增量
55-60min  写当日笔记：这个概念解决什么问题 + 卡在哪
```

**笔记放哪**：项目内 `notes/YYYY-MM-DD.md`（如 `notes/2026-10-15.md`），一天一文件，追加不覆盖。

**每天的 20 分钟前端时间**（原则 1）：把这 20 分钟花在「今天新知识点的可视化」上——比如 S3 学了游标分页，就把分页的翻页效果在页面上做出来。

### 周六（5h · 一个功能域的完整链路）

```
09:00-10:00  本周 5 个微增量串起来，补齐缺的
10:00-12:00  功能域冲刺：契约 → 后端 → 前端
14:00-16:00  测试 + 联调
16:00-17:00  演示一遍，记下哪里卡住
```

### 周日（5h）

```
前 3h   补周六没跑通的
后 2h   **费曼复盘**：不看资料，把本周学的讲一遍
        讲不下去的地方 = 下周第一个要补的
        写下周第一天的具体任务
```

> **复盘是这份计划里最有价值的两小时。** 它比任何进度表都准——进度表只能告诉你走到哪，复盘能告诉你哪里没懂。

## 七、判据与纪律

### 四级判据

| 层级 | 判据 |
|---|---|
| **一日** | 仓库绿（`make build` 过 + 已有测试过）+ 当天的东西能跑 + `notes/` 写清「这个概念解决什么问题」 |
| **一周** | 周日费曼复盘无卡壳 + 代码已提交 |
| **一阶段** | 该阶段的判据全过 + **有一个能跑起来演示的产物**（不是笔记） |
| **一里程碑** | 五道 M 判据之一成立 |

### 七条纪律

1. **不跳过阶段**。跳课造成的空洞会在 S4/S5/S9 以数倍时间偿还。
2. **不压缩完整度**。判据不达标就顺延，不删功能。
3. **每天必须能收尾**。做不完就当场再切小，不留半成品到明天。
4. **不追进度**。落后就顺延，不赶。
5. **不碰旧仓**。不读 `~/www/HomeCube` 与 `~/www/family-ledger/server/` 的业务代码。表结构和接口自己设计。
6. **契约先于实现**。每个功能域第 1 步永远是定契约。
7. **范围对齐表是排期的分母**。新增能力前先改 §一那张表。**v2 就是因为漏了这步，丢了整整一个系统。**
