项目分层

前三天的代码全堆在 main.go 里，500 行时就会变成意大利面。今天把主线项目重构进 handler → service → repository 三层结构——这是 Go 后端团队的通用布局，第 3 周接数据库时只需要换掉 repository 一层，其余代码原封不动。这就是分层的复利。

今日目标

↑ 这五条是「学习目标」，学的过程中随时回来勾；页面底部还有 5 条「完成检查」，全部勾掉今天才算结束。

课前须知：你为什么已经会分层了

把 React 项目倒过来看。页面组件（收 props、渲染）≈ handler；自定义 hooks / store 里的业务动作（校验、组合调用）≈ service；src/api/request.js 封装（只管发请求、拿数据）≈ repository。你写过的「组件不直接 fetch，走 api 层」的直觉，在这里 1:1 平移：handler 不碰数据存取，repository 不认识 HTTP。

Go 编译器强制包之间不允许循环依赖——A 引 B、B 又引 A 直接编译失败。所以今天不是「学习最佳实践」，是「不了解规则就写不编译」。

知识讲义

1. 三层各干什么

层职责绝对不做前端类比
handler解析参数/DTO 绑定、调 service、把结果/错误写成统一响应不写业务规则、不碰存储路由级页面组件：收参、渲染
service业务规则：重名检查、默认值、跨仓库编排、返回 error不 import gin（没有 *gin.Context！）hooks / store action：纯业务
repository数据的增删改查（今天是 map，第 3 周换 GORM）不判断 HTTP 状态码、不打印响应src/api 请求封装层
model数据结构定义，被所有层引用不 import 任何其他内部包types/ + zod schema

数据旅行路线（一次请求来回）：

textHTTP 请求
  → handler   ShouldBindJSON 得到 DTO
  → service   业务检查，DTO 转 model
  → repositorymap 存取，返回 model 或 error
  ← service   原样上抛 error（或包装）
  ← handler   error → HTTP 状态码 + 业务 code；model → response.OK
HTTP 响应 {code, message, data}

2. 目录结构与依赖方向

treegin-api/
├── go.mod                       # module gin-api
├── cmd/server/main.go           # 唯一入口：组装依赖 + 启动（cmd/xxx = 可执行程序的惯例位置）
├── internal/                    # 私有代码：别的模块 import 不到，Go 编译器强制
│   ├── model/                   # User、Article、CreateXxx/UpdateXxx DTO（ID 一律 uint）
│   ├── repository/              # 接口 UserRepository/ArticleRepository + 内存实现 MemRepo/ArticleRepo（map+RWMutex）
│   ├── service/                 # 业务规则：user_service.go / article_service.go
│   ├── handler/                 # gin handler + 路由注册：user_handler.go / article_handler.go / bind_err.go
│   └── middleware/              # 昨天的 CORS/Timer/Auth 搬进来
└── pkg/response/                # 与前两天一致的统一响应

依赖只能从上往下单向指：handler → service → repository → model。箭头反了（比如 repository 想调 service）就是 import cycle。记住口诀：下层不知道上层存在——repository 根本不知道谁在用它，所以它才能同时被 HTTP、CLI、定时任务复用。

4. 接口（interface）+ repository 层：map + RWMutex

W1 day4 埋的"接口"伏笔今天兑现。先给一句话定义，再落到代码：

interface ≈ TS 的 interface，但不用 implements。Go 的接口是隐式实现（duck typing）：只要一个类型的方法集齐了接口声明的全部方法，它就自动满足该接口，不需要写 implements/extends。对照 TS：interface UserRepository { list(): User[] }，任何有 list() 的对象都能当 UserRepository 传——Go 同理。差别是 Go 的方法名要大写开头（导出）才能被别的包看见。

为什么实现里到处是 Lock/RLock：Gin 每个请求跑在独立 goroutine 里（W1 day5 见过），map 并发读写会直接让进程崩溃（fatal error: concurrent map writes，连 Recovery 都拦不住——fatal ≠ panic，见 day3 3.5）。所以内存实现读用 RLock（读读并行）、写用 Lock（独占），并且 defer Unlock 紧跟在 Lock 后。第 5 周并发周会把这套讲透，今天先把锁加对。

internal/repository/user_repo.gopackage repository

import (
    "errors"
    "sync"

    "gin-api/internal/model"
)

// ErrUserNotFound 哨兵错误：service/handler 用 errors.Is 识别，第 3 周换成 GORM 后语义不变
var ErrUserNotFound = errors.New("用户不存在")

// UserRepository 是"一个用户仓储能做什么"的契约。service 只认这个接口，不认具体实现，
// 于是内存版（今天）和 MySQL 版（第 3 周）可以无缝替换——这就是分层的复利。
type UserRepository interface {
    List() ([]model.User, error)
    Get(id uint) (model.User, error)
    Create(u model.User) (model.User, error)
    Update(u model.User) error
    Delete(id uint) error
}

// MemRepo 用 map 实现 UserRepository。名字沿用 W1（内存实现）；现在有了两个资源，
// 用户这份仍叫 MemRepo，文章那份叫 ArticleRepo（见下方），命名不强行对称，读代码更顺。
type MemRepo struct {
    mu     sync.RWMutex
    nextID uint
    users  map[uint]model.User
}

func NewMemRepo() *MemRepo {
    return &MemRepo{nextID: 1, users: make(map[uint]model.User)}
}

// 编译期契约检查：MemRepo 少实现任意一个方法，这一行就让编译失败
var _ UserRepository = (*MemRepo)(nil)

func (r *MemRepo) Create(u model.User) (model.User, error) {
    r.mu.Lock()
    defer r.mu.Unlock() // defer 保证任何 return 路径都解锁，比 JS 的 try/finally 更顺手
    u.ID = r.nextID
    r.nextID++
    r.users[u.ID] = u
    return u, nil
}

func (r *MemRepo) List() ([]model.User, error) {
    r.mu.RLock()
    defer r.mu.RUnlock()
    out := make([]model.User, 0, len(r.users))
    for _, u := range r.users { // map 遍历无序，第 3 周 ORDER BY id 解决
        out = append(out, u)
    }
    return out, nil
}

func (r *MemRepo) Get(id uint) (model.User, error) {
    r.mu.RLock()
    defer r.mu.RUnlock()
    u, ok := r.users[id]
    if !ok {
        return model.User{}, ErrUserNotFound
    }
    return u, nil
}

func (r *MemRepo) Update(u model.User) error {
    r.mu.Lock()
    defer r.mu.Unlock()
    if _, ok := r.users[u.ID]; !ok {
        return ErrUserNotFound
    }
    r.users[u.ID] = u
    return nil
}

func (r *MemRepo) Delete(id uint) error {
    r.mu.Lock()
    defer r.mu.Unlock()
    if _, ok := r.users[id]; !ok {
        return ErrUserNotFound
    }
    delete(r.users, id)
    return nil
}

哨兵错误定义在 repository 包里、由上层 import 使用，方向仍是上层 → 下层，不产生循环。若哪天 service 想「不认识 repository」，就把错误再下沉到 model 包——依赖永远指向稳定的底层。接口也放同一个 repository 包，这样 service/handler 只需 import repository 就能拿到 UserRepository/ArticleRepository 两个契约类型。

从 struct 仓库到接口仓库：今天学 interface 只为这一件事

第 1 周 day4 那版 service 握的是具体结构体 *MemRepo；今天唯一的变化是把它换成契约 repository.UserRepository，函数体一行都不用改：

对照（左边删、右边加）// W1 day4：service 认识具体实现
type UserService struct {
    repo *MemRepo
}
func NewUserService(repo *MemRepo) *UserService {
    return &UserService{repo: repo}
}

// W2 day4：service 只认识契约
type UserService struct {
    repo repository.UserRepository
}
func NewUserService(repo repository.UserRepository) *UserService {
    return &UserService{repo: repo}
}

调用处 userSvc := service.NewUserService(userRepo)（讲义 6 装配里就是这一行）一个字都不用改——因为 *MemRepo 方法齐了，Go 自动认它满足 UserRepository（隐式实现，不用写 implements）。第 3 周接上 MySQL 时，动的只有它上面那行 var userRepo repository.UserRepository = repository.NewMemRepo() 的右边，service 与 handler 原地不动。

代价只有一处：接口和实现分家后，少实现一个方法 = 编译期就炸，而不是等到运行时 nil pointer。把 MemRepo 的 Update 方法名手滑写成 Updata 试试：

shell$ go build ./...
# 报错指向的是那行契约检查，不是调用点——这正是它存在的意义
internal/repository/user_repo.go:26:27: cannot use (*MemRepo)(nil) (value of type *MemRepo) as UserRepository value in variable declaration: *MemRepo does not implement UserRepository (missing method Update)

对照 TS：TS 里类型不匹配会在 tsc 阶段报 Property 'Update' is missing；Go 也有这一层，只是它不检查"声明过关系"，只在你把具体值交给接口类型（这里就是 var _ UserRepository = (*MemRepo)(nil)，或 NewUserService(NewMemRepo()) 的实参处）才做结构匹配。所以那行 var _ ... 不是废话：它把"检查点"提前到了定义处，不写也可能到 main.go 才报错，离根因远三层。

5. service 层：业务规则的家

构造函数依赖接口，不依赖具体实现。上一节把契约抽成了 UserRepository 接口，这里 service 的字段就写成 repo repository.UserRepository（接口），而不是 *repository.MemRepo（具体类型）。这样今天传内存实现，第 3 周传 GORM 实现，service 一行不改——这正是"依赖倒置"落地的地方。

internal/service/user_service.gopackage service

import (
    "errors"
    "fmt"
    "time"

    "gin-api/internal/model"
    "gin-api/internal/repository"
)

// 本层的两个业务错误（重名、作者不存在），handler 用 errors.Is 翻译成对应码
var (
    ErrUsernameExists = errors.New("用户名已被占用") // -> HTTP 409 + code 1006
    ErrAuthorNotFound = errors.New("作者不存在")       // -> HTTP 400 + code 1004（引用完整性，是调用方传错）
)

type UserService struct {
    repo repository.UserRepository // 依赖接口，不依赖 *MemRepo
}

func NewUserService(repo repository.UserRepository) *UserService {
    return &UserService{repo: repo}
}

func (s *UserService) Create(dto model.CreateUserDTO) (model.User, error) {
    all, err := s.repo.List() // 业务规则 1：用户名不许重复（第 3 周换成 WHERE username=? 一句搞定）
    if err != nil {
        return model.User{}, fmt.Errorf("check dup: %w", err)
    }
    for _, u := range all {
        if u.Username == dto.Username {
            return model.User{}, ErrUsernameExists
        }
    }
    role := dto.Role // 业务规则 2：角色缺省为 user
    if role == "" { role = "user" }
    return s.repo.Create(model.User{
        Username: dto.Username, Email: dto.Email,
        Password: dto.Password, Role: role, CreatedAt: time.Now(),
    })
}

func (s *UserService) Get(id uint) (model.User, error)        { return s.repo.Get(id) }
func (s *UserService) List() ([]model.User, error)             { return s.repo.List() }
func (s *UserService) Update(u model.User) error               { return s.repo.Update(u) }
func (s *UserService) Delete(id uint) error                    { return s.repo.Delete(id) }

// 给 handler 用的错误判定助手，handler 不必直接 import repository 也能识别"不存在"
func IsNotFound(err error) bool        { return errors.Is(err, repository.ErrUserNotFound) }
func IsUsernameExists(err error) bool { return errors.Is(err, ErrUsernameExists) }
internal/service/article_service.gopackage service

import (
    "errors"
    "fmt"
    "time"

    "gin-api/internal/model"
    "gin-api/internal/repository"
)

type ArticleService struct {
    repo    repository.ArticleRepository // 同样是接口
    userSvc *UserService                 // 跨资源校验：service -> service 单向，允许
}

func NewArticleService(repo repository.ArticleRepository, userSvc *UserService) *ArticleService {
    return &ArticleService{repo: repo, userSvc: userSvc}
}

func (s *ArticleService) Create(dto model.CreateArticleDTO) (model.Article, error) {
    // 业务规则：作者必须真实存在。查不到就是调用方传错 author_id -> ErrAuthorNotFound
    if _, err := s.userSvc.Get(dto.AuthorID); err != nil {
        if IsNotFound(err) {
            return model.Article{}, fmt.Errorf("author_id=%d: %w", dto.AuthorID, ErrAuthorNotFound)
        }
        return model.Article{}, fmt.Errorf("check author: %w", err)
    }
    return s.repo.Create(model.Article{
        Title: dto.Title, Content: dto.Content, AuthorID: dto.AuthorID, CreatedAt: time.Now(),
    })
}

func (s *ArticleService) List() ([]model.Article, error) { return s.repo.List() }

// 文章层新增一个判定：作者不存在 = 400/1004（不是 404/1001）
func IsAuthorNotFound(err error) bool { return errors.Is(err, ErrAuthorNotFound) }

注意 service → service（ArticleService 依赖 UserService）必须单向：绝不能让 UserService 反过来 import service 包里的 ArticleService，否则 import cycle not allowed。跨资源校验永远"高层依赖低层"，这里文章是高层、用户是低层。

6. handler 层与 main.go 组装

handler 只做三件事：绑参、调 service、把结果/错误写成统一响应。先补一个 day2 的 bindErrMsg（它跟着校验走，属于"接入层翻译"，放在 handler 包里；也可下沉到 internal/pkg/binderr 供多资源复用——今天就近放 handler 包）：

internal/handler/bind_err.gopackage handler

import (
    "errors"
    "strings"

    "github.com/go-playground/validator/v10"
)

// bindErrMsg 与 day2 讲义 3 完全一致：把 validator 报错翻译成一句中文
func bindErrMsg(err error) string {
    var ves validator.ValidationErrors
    if errors.As(err, &ves) {
        msgs := make([]string, 0, len(ves))
        for _, ve := range ves {
            switch ve.Tag() {
            case "required": msgs = append(msgs, ve.Field()+" 不能为空")
            case "min":      msgs = append(msgs, ve.Field()+" 长度不足 "+ve.Param())
            case "max":      msgs = append(msgs, ve.Field()+" 长度超限 "+ve.Param())
            case "email":    msgs = append(msgs, ve.Field()+" 不是合法邮箱")
            case "oneof":    msgs = append(msgs, ve.Field()+" 只能是: "+ve.Param())
            default:          msgs = append(msgs, ve.Field()+" 校验失败("+ve.Tag()+")")
            }
        }
        return strings.Join(msgs, "；")
    }
    return "请求体不是合法 JSON"
}
internal/handler/user_handler.gopackage handler

import (
    "net/http"
    "strconv"

    "github.com/gin-gonic/gin"

    "gin-api/internal/model"
    "gin-api/internal/service"
    "gin-api/pkg/response"
)

type UserHandler struct { svc *service.UserService }

func NewUserHandler(svc *service.UserService) *UserHandler { return &UserHandler{svc: svc} }

// Register 把路由收在 handler 身上；public 组只放读，auth 组放全部写（POST/PUT/DELETE）。
// 与 day3 练习 2「GET 匿名、POST/PUT/DELETE 必须带 Bearer token」的口径一致。
func (h *UserHandler) Register(public, auth *gin.RouterGroup) {
    public.GET("/users", h.List)
    public.GET("/users/:id", h.Get)
    auth.POST("/users", h.Create)
    auth.PUT("/users/:id", h.Update)
    auth.DELETE("/users/:id", h.Delete)
}

// parseID：路径 :id 转 uint（CANONICAL：ID 一律 uint）。失败已写 400 响应，返回 ok=false 让调用方 return
func parseID(c *gin.Context) (uint, bool) {
    id, err := strconv.ParseUint(c.Param("id"), 10, 64)
    if err != nil || id == 0 {
        response.Fail(c, http.StatusBadRequest, response.CodeInvalidParam, "id 必须是正整数")
        return 0, false
    }
    return uint(id), true
}

func (h *UserHandler) List(c *gin.Context) {
    users, err := h.svc.List() // 接口 List 现在返回 ([]model.User, error)
    if err != nil {
        response.Fail(c, http.StatusInternalServerError, response.CodeInternal, "服务繁忙")
        return
    }
    response.OK(c, users)
}

func (h *UserHandler) Create(c *gin.Context) {
    var dto model.CreateUserDTO
    if err := c.ShouldBindJSON(&dto); err != nil {
        response.Fail(c, http.StatusBadRequest, response.CodeInvalidParam, bindErrMsg(err)) // ← day2 版 bindErrMsg，不再直接吐 err.Error()
        return
    }
    u, err := h.svc.Create(dto)
    if service.IsUsernameExists(err) {
        response.Fail(c, http.StatusConflict, response.CodeUserExists, err.Error()) // 重名 -> HTTP 409 + 1006
        return
    }
    if err != nil {
        response.Fail(c, http.StatusInternalServerError, response.CodeInternal, "服务繁忙")
        return
    }
    response.Created(c, u)
}

func (h *UserHandler) Get(c *gin.Context) {
    id, ok := parseID(c)
    if !ok { return }
    u, err := h.svc.Get(id)
    if service.IsNotFound(err) { // HTTP 404 + 业务 1001
        response.Fail(c, http.StatusNotFound, response.CodeUserNotFound, "用户不存在")
        return
    }
    if err != nil {
        response.Fail(c, http.StatusInternalServerError, response.CodeInternal, "服务繁忙") // 5000 常量，别写裸数字
        return
    }
    response.OK(c, u)
}

func (h *UserHandler) Update(c *gin.Context) {
    id, ok := parseID(c)
    if !ok { return }
    var dto model.UpdateUserDTO
    if err := c.ShouldBindJSON(&dto); err != nil {
        response.Fail(c, http.StatusBadRequest, response.CodeInvalidParam, bindErrMsg(err))
        return
    }
    cur, err := h.svc.Get(id)
    if service.IsNotFound(err) {
        response.Fail(c, http.StatusNotFound, response.CodeUserNotFound, "用户不存在")
        return
    }
    if err != nil {
        response.Fail(c, http.StatusInternalServerError, response.CodeInternal, "服务繁忙")
        return
    }
    if dto.Username != "" { cur.Username = dto.Username } // 只覆盖传了的字段
    if dto.Email != ""    { cur.Email = dto.Email }
    if dto.Password != "" { cur.Password = dto.Password }
    if dto.Role != ""     { cur.Role = dto.Role }
    if err := h.svc.Update(cur); err != nil {
        response.Fail(c, http.StatusInternalServerError, response.CodeInternal, "服务繁忙")
        return
    }
    response.OK(c, cur)
}

func (h *UserHandler) Delete(c *gin.Context) {
    id, ok := parseID(c)
    if !ok { return }
    if err := h.svc.Delete(id); err != nil {
        if service.IsNotFound(err) {
            response.Fail(c, http.StatusNotFound, response.CodeUserNotFound, "用户不存在")
            return
        }
        response.Fail(c, http.StatusInternalServerError, response.CodeInternal, "服务繁忙")
        return
    }
    response.OK(c, gin.H{"deleted": id}) // 本周统一 200 + JSON body（W1 是 204 无 body，差异原因见 summary）
}

cmd/server/main.go（W2 终态装配：接口注入 + 鉴权组 + /api/v1）package main

import (
    "net/http"

    "github.com/gin-gonic/gin"

    "gin-api/internal/handler"
    "gin-api/internal/middleware"
    "gin-api/internal/repository"
    "gin-api/internal/service"
    "gin-api/pkg/response"
)

func main() {
    // 组装依赖：new 具体实现（*MemRepo / *ArticleRepo），但用接口类型接住，再交给上层
    var userRepo repository.UserRepository = repository.NewMemRepo()
    var articleRepo repository.ArticleRepository = repository.NewArticleRepo()
    userSvc := service.NewUserService(userRepo)              // service 只知道自己拿到的是 UserRepository 接口
    articleSvc := service.NewArticleService(articleRepo, userSvc)

    r := gin.New()
    r.Use(gin.Logger(), gin.Recovery(), middleware.CORS(), middleware.Timer())
    r.HandleMethodNotAllowed = true // day1 讲过的开关，默认 false：不开的话「用 PUT 打只有 GET 的路」会被当成 404，
                                      // 而不是 405。装配阶段就把它打开，day5 验收表里的 405 才复现得出来
    r.NoRoute(func(c *gin.Context) {
        response.Fail(c, http.StatusNotFound, response.CodeUserNotFound, "接口不存在: "+c.Request.URL.Path) // 404 + 1001
    })
    r.NoMethod(func(c *gin.Context) { // 405 + 1003（day1 的两个兜底都要带上，只写 NoRoute 会漏掉方法错的用例）
        response.Fail(c, http.StatusMethodNotAllowed, response.CodeForbidden, "方法不允许")
    })

    // 健康检查按 CANONICAL 不带前缀
    r.GET("/health", func(c *gin.Context) { response.OK(c, gin.H{"status": "ok"}) })

    api := r.Group("/api/v1")  // 同一个前缀开两个组：api 只挂匿名可读的 GET
    auth := r.Group("/api/v1") // auth 同前缀，额外挂鉴权：所有写操作 POST/PUT/DELETE 都进来
    auth.Use(middleware.RequireAuth())

    handler.NewUserHandler(userSvc).Register(api, auth)
    handler.NewArticleHandler(articleSvc).Register(api, auth)

    r.Run(":8080")
}

注意 main.go 在 cmd/server/ 下，启动命令变成 go run ./cmd/server（或编译 go build ./cmd/server）。忘了路径前缀报 no Go files 或在错误目录执行都算新手礼。中间件（day3 的 CORS/Timer/RequireAuth）今天从仓库根的 middleware/ 搬进 internal/middleware/，所以 import 路径由 gin-api/middleware 变成 gin-api/internal/middleware——搬完记得全局改 import。

练习 2：GET /users/:id 与 PUT/DELETE 全链路错误码（40 分钟）
