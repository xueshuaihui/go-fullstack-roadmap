Gin 路由

上周你用 net/http 手写了待办服务，每一步都要自己拆。今天换上 Go 生态最流行的 Web 框架 Gin：路由匹配、参数解析、JSON 输出全部一行搞定。今天的成败标准只有一个——8 个路由全部跑通，并能把每个参数原样打印出来。

课前须知：框架替你做了什么

上周的痛点还记得吗？net/http 里 r.URL.Path == "/todos" 是最笨的字符串比较——/todos/ 多个斜杠就匹配不上，/todos/3 还要自己 strings.Split 拆 ID。Gin 底层是 httprouter（基数树路由），/users/:id 声明一次，ID 自动进 c.Param("id")。

给前端同学的坐标。Gin 在 Go 里的地位类似前端的 Vite + React Router 组合：不是语言的一部分，但几乎是团队项目默认选型。会用 Gin 的 handler ≈ 会用路由中间件的「请求处理器」：进来一个 *gin.Context，出去一个 JSON。

本周主线项目：内存版用户 + 文章 REST API（/users 全套 CRUD + /articles）。今天就从搭路由骨架开始，数据先用内存 map，周五收口成完整分层项目。

知识讲义

1. 安装 Gin 与第一个服务

shell$ mkdir gin-api && cd gin-api
$ go mod init gin-api                       # 生成 go.mod，项目模块名定为 gin-api
$ go get -u github.com/gin-gonic/gin        # ≈ npm install，写进 go.mod 的 require

创建 main.go。注意 Gin 的导入路径以 gin-gonic/gin 结尾，包名是 gin：

main.gopackage main

import (
    net/http

    "github.com/gin-gonic/gin"
)

func main() {
    gin.SetMode(gin.ReleaseMode) // 发布模式：日志更干净；开发调试可换 gin.DebugMode
    r := gin.Default()           // 创建引擎，自带 Logger + Recovery 两个中间件（明天细讲）

    r.GET("/ping", func(c *gin.Context) {
        c.JSON(http.StatusOK, gin.H{"message": "pong"})
    })

    r.Run(":8080") // 监听 8080；r.Run() 不带参数默认也是 :8080
}
shell$ go run .
# 另开终端
$ curl localhost:8080/ping
{"message":"pong"}
构造方式自带中间件适用场景
gin.New()无，一张白纸生产项目：中间件全部显式注册，可控
gin.Default()Logger + Recovery练手 / 快速起服务，今天用它

gin.H 只是 map[string]any 的简写，c.JSON(200, gin.H{...}) 会自动序列化并设置 Content-Type: application/json。上周手写 json.Marshal + Header().Set 那五行，现在一行。

2. 四种 HTTP 方法

引擎 r 上每个动词一个方法，签名全是 (路径, handler)，handler 统一为 func(c *gin.Context)：

main.gousers := []string{"ada", "linus"}

r.GET("/users", func(c *gin.Context) {
    c.JSON(http.StatusOK, gin.H{"data": users})
})
r.POST("/users", func(c *gin.Context) {
    c.JSON(http.StatusCreated, gin.H{"data": "创建成功"}) // 201
})
r.PUT("/users", func(c *gin.Context)  { c.String(http.StatusOK, "PUT /users") })
r.DELETE("/users", func(c *gin.Context) { c.String(http.StatusOK, "DELETE /users") })

对照 Express 写法（Node 圈约定，帮你定位概念，不需要会）：app.get('/users', (req, res) => res.json(users)) ↔ r.GET("/users", func(c *gin.Context) { c.JSON(200, users) })。req/res 两个参数被 Gin 合并成一个 c *gin.Context——请求和响应都在它身上；回调从匿名 JS 函数变成匿名 Go 闭包，仅此而已。

3. 路径参数与查询参数

main.go// 路径参数：/users/42 里的 42
r.GET("/users/:id", func(c *gin.Context) {
    id := c.Param("id")       // "42"，取到的是 string，别忘了 strconv.Atoi 转数字
    id2 := c.Param(":id")      // 带冒号也兼容，推荐不带
    c.JSON(http.StatusOK, gin.H{"id": id, "id2": id2})
})

// 查询参数：/articles?page=2&size=10&keyword=go
r.GET("/articles", func(c *gin.Context) {
    page := c.Query("page")               // "2"；不存在时返回 ""
    size := c.DefaultQuery("size", "10")  // 不存在时用默认值 "10"
    kw, ok := c.GetQuery("keyword")        // 第二个返回值告诉你参数是否存在
    c.JSON(http.StatusOK, gin.H{"page": page, "size": size, "kw": kw, "ok": ok})
})
参数来源URL 长相Gin 取法
路径参数/users/42c.Param("id")
查询参数?page=2&size=10c.Query / c.DefaultQuery / c.GetQuery
表单字段body: name=adac.PostForm("name")
请求头Authorization: Bearer xc.GetHeader("Authorization")
JSON body{"name":"ada"}明天 ShouldBindJSON，今天先用 c.GetRawData() 拿原始字节

路径带 ?page=2&size=10 时，终端里的 & 会被 shell 当后台符，curl 的 URL 一定加引号：curl "localhost:8080/articles?page=2&size=10"。

4. 路由分组 r.Group

接口一多，每个路径都手写 /api/v1 前缀既啰嗦又难改版本。分组把公共前缀（和公共中间件，明天讲）收敛到一处：

main.goapi := r.Group("/api/v1")
{
    api.GET("/users", func(c *gin.Context) { c.JSON(http.StatusOK, gin.H{"uri": "/api/v1/users"}) })
    api.POST("/users", func(c *gin.Context) { c.JSON(http.StatusCreated, gin.H{"uri": "/api/v1/users"}) })

    v2 := api.Group("/v2") // 分组可以嵌套：/api/v1/v2/…
    v2.GET("/users", func(c *gin.Context) { c.JSON(http.StatusOK, gin.H{"uri": "嵌套组"}) })
}

大括号 { } 不是语法必需，只是社区习惯——让一个分组下的路由像列表一样收在一起，读起来舒服。

5. 404：NoRoute 与 NoMethod

默认 404 返回纯文本 404 page not found，前端 JSON.parse 会当场爆炸。约定好「所有响应都是 JSON」，就要接管兜底：

main.go// 路径完全没注册过 → NoRoute
r.NoRoute(func(c *gin.Context) {
    c.JSON(http.StatusNotFound, gin.H{"code": 404, "message": "接口不存在: " + c.Request.URL.Path, "data": nil})
})
// 路径存在但方法不对（如 GET /ping 换成 POST）→ 405，Gin 自动处理，也可接管 NoMethod
r.NoMethod(func(c *gin.Context) {
    c.JSON(http.StatusMethodNotAllowed, gin.H{"code": 405, "message": "方法不允许", "data": nil})
})

注意区分：路径 /users/999 能匹配到 /users/:id 这条路由，所以 NoRoute 不会触发——「用户不存在」是业务上的 404，要在 handler 里自己返回（本周五统一接入错误码 1001）。NoRoute 只兜「根本没这个接口」。

6. 路由注册规则与限制

  • 同方法 + 同路径重复注册（r.GET("/a",…) 两次）：启动即 panic。
  • 同层级参数名必须一致：/user/:id 与 /user/:name 共存会 panic；改成一个名字即可。
  • 支持通配符兜底：r.GET("/static/*filepath", …) 可吃到 /static/css/app.css。
  • 路由匹配按方法分树：GET /users 与 POST /users 互不干扰。
main.go// 通配符示例：/files/any/deep/path 全部命中
r.GET("/files/*filepath", func(c *gin.Context) {
    c.JSON(http.StatusOK, gin.H{"filepath": c.Param("filepath")}) // 注意带前导 /
})

7. 运行模式与端口

Gin 有三种运行模式，影响日志详细度和 debug 警告：

模式设置方式特点
gin.DebugMode默认值 / gin.SetMode(gin.DebugMode) / 环境变量 GIN_MODE=debug输出全部路由表、警告信息，开发用
gin.ReleaseModegin.SetMode(gin.ReleaseMode) / GIN_MODE=release go run .干净日志，不打印 debug 警告，部署用（第 7 周默认它）
gin.TestMode仅代码里设置第 4 周 httptest 自动化测试时用，今天知道即可
main.gofunc main() {
    gin.SetMode(gin.ReleaseMode)
    r := gin.New()
    // ... 注册路由 ...
    if err := r.Run(":8080"); err != nil {
        // Run 内部会返回 http.Server 的 error：端口被占、权限不足等
        panic(err) // main 里启动失败没救，panic 退出是合理的；Web 请求里的 panic 才需要 Recovery
    }
}

启动时终端会打印一份 [GIN-debug] GET /users --> main.main.func1 (3 handlers) 的路由表——每次改完路由都扫一眼它，路径、方法、handler 对不上，一眼就能看出来，比 curl 试错快得多。

练习 1：跑通 8 个路由并打印参数（60 分钟，主线项目骨架）

要求：在 gin-api 项目里注册本周主线项目的全部 7 个接口，外加 1 个 /health，共 8 个路由；每个 handler 都要解析并回显收到的参数。

  • GET /health 返回 {"message":"ok"}
  • GET /users、GET /users/:id、POST /users、PUT /users/:id、DELETE /users/:id
  • GET /articles（支持 page/size 查询参数）、POST /articles

步骤：① 按讲义第 2、3 节写好全部路由；② 每条路由配一个 curl 验证命令写进注释；③ 全部返回 {"echo": 收到的参数} 形式的 JSON。

参考答案（节选核心路由，完整 8 条照此模式补齐）：

main.gopackage main

import (
    net/http
    "github.com/gin-gonic/gin"
)

func main() {
    r := gin.Default()

    r.GET("/health", func(c *gin.Context) {
        c.JSON(http.StatusOK, gin.H{"message": "ok"})
    })

    r.GET("/users", func(c *gin.Context) {
        c.JSON(http.StatusOK, gin.H{"page": c.DefaultQuery("page", "1")})
    })
    r.GET("/users/:id", func(c *gin.Context) {
        c.JSON(http.StatusOK, gin.H{"id": c.Param("id")})
    })
    r.POST("/users", func(c *gin.Context) {
        raw, _ := c.GetRawData() // 明天换成 ShouldBindJSON
        c.JSON(http.StatusCreated, gin.H{"raw": string(raw)})
    })
    r.PUT("/users/:id", func(c *gin.Context) {
        raw, _ := c.GetRawData()
        c.JSON(http.StatusOK, gin.H{"id": c.Param("id"), "raw": string(raw)})
    })
    r.DELETE("/users/:id", func(c *gin.Context) {
        c.JSON(http.StatusOK, gin.H{"id": c.Param("id")})
    })

    r.GET("/articles", func(c *gin.Context) {
        c.JSON(http.StatusOK, gin.H{
            "page": c.DefaultQuery("page", "1"),
            "size": c.DefaultQuery("size", "10"),
        })
    })
    r.POST("/articles", func(c *gin.Context) {
        raw, _ := c.GetRawData()
        c.JSON(http.StatusCreated, gin.H{"raw": string(raw)})
    })

    r.Run(":8080")
}

常见坑（新手 100% 会踩）

坑现象正确姿势
同层参数名不一致启动 panic：conflicts with existing wildcard/user/:id 与 /user/:name 二选一；不同资源用不同段（/users/:id/posts/:pid 是 OK 的，层级不同）
方法用错去测curl POST 一个只注册 GET 的路径，返回 405 不是 404405 = 路径存在方法不对；404 = 路径都没注册。用 curl -i 看状态码再排查
Param 是字符串id := c.Param("id") 直接参与比较/运算编译失败id, err := strconv.Atoi(c.Param("id"))，err 非 nil 时返回 400
URL 没加引号curl ...?a=1&b=2 只有 a 传到了URL 整体用双引号包住，防 shell 吃掉 &
端口被占address already in uselsof -ti:8080 | xargs kill（macOS/Linux）或换端口
handler 里忘了写响应请求挂住，最后空 200 或超时每条分支都必须以 c.JSON/c.String/return 收尾
