第 2 周：Gin + REST API 基础 —— 总结与验收

五天里你把一个 main.go 手工作坊，升级成了有目录规范、统一响应、中间件流水线和文档的像样的后端项目。今天做三件事：串知识地图、按参考骨架冲刺主线项目、逐条过验收标准。验收不过周不算完。

本周知识地图

Day主题核心产出一句话复盘自测动作
D1Gin 路由gin.New/Default、c.Param/c.Query、r.Group、NoRoute/NoMethod + HandleMethodNotAllowed 开关路由声明式匹配替代字符串比较，参数从 Context 取盲写 /users/:id 路由 + curl 验证
D2绑定与验证ShouldBindJSON（对照 ShouldBind：按 Content-Type 分发，认不出就退回表单解析，不会报 415）、binding tag、pkg/response结构体即 schema：解析、校验、统一 {code,message,data} 一步到位故意发非法 JSON，拿到 400+1004
D3中间件Logger/Recovery、Timer、手写 CORS、鉴权雏形 + panic/recover 最小认识洋葱模型：c.Next() 分进出，c.Abort() 熔断内层画出 A→B→handler→B→A 执行图
D4项目分层cmd/server + internal 三层 + UserRepository 接口 + map/RWMutex 仓库依赖单向 handler→service→repo→model，下层不知上层；接口让上层只认能力不认实现口述 import cycle 成因与解法
D5接口测试curl 五件套、Postman collection、README 文档、smoke.sh 回归脚本状态码 + 业务码双验收；错误路径（400/401/404/500）也是功能Runner 一键全绿 + 陌生人照 README 跑通

贯穿线：「API 设计约定」（手册第十三节）本周落地——统一响应 {code,message,data}、HTTP 状态码管大类 + 业务码管细分（0 成功、1001 资源不存在、1002 密码错误、1003 禁止、1004 参数错误、1005 未认证、1006 用户名已存在、2001 文章不存在、5000 内部错误）、成功一律 200/201+code 0。下周接数据库时这套外壳不再改动。

全局：未注册路径 404 + code 1001 的 JSON；panic 被自定义 Recovery 兜 500 + code 5000（空 body 不算过）且进程不死；OPTIONS 预检 204 + Allow 头

鉴权口径（day3 讲义 6 + day4 装配）：同一前缀 /api/v1 开两个组——api 匿名只挂 GET，auth 额外 Use(middleware.RequireAuth()) 挂全部写操作（POST/PUT/DELETE）。所以连创建用户都要带 -H "Authorization: Bearer go-fullstack-2026"；下面的验收命令已经全部带上，复制即可跑。

type Body struct {

const (
    CodeOK = 0; CodeUserNotFound = 1001; CodeBadPassword = 1002

)

func OK(c *gin.Context, data any)      { c.JSON(http.StatusOK, Body{Code: CodeOK, Message: "ok", Data: data}) }
func Created(c *gin.Context, data any) { c.JSON(http.StatusCreated, Body{Code: CodeOK, Message: "ok", Data: data}) }
func Fail(c *gin.Context, st, code int, msg string) { c.JSON(st, Body{Code: code, Message: msg, Data: nil}) }
internal/repository/user_repo.go（节选：接口 + 内存实现）var ErrUserNotFound = errors.New("用户不存在")

// 上层只依赖这五条方法，不关心底下是 map、MySQL 还是 Redis
type UserRepository interface {
    Create(u model.User) (model.User, error)
    List() ([]model.User, error)
    Get(id uint) (model.User, error)
    Update(u model.User) error
    Delete(id uint) error
}

type MemRepo struct {
    mu     sync.RWMutex
    nextID uint
    users  map[uint]model.User
}

func NewMemRepo() *MemRepo { return &MemRepo{nextID: 1, users: make(map[uint]model.User)} }

var _ UserRepository = (*MemRepo)(nil) // 编译期契约检查：漏一个方法就编译不过

func (r *MemRepo) Get(id uint) (model.User, error) {
    r.mu.RLock()
    defer r.mu.RUnlock()
    u, ok := r.users[id]
    if !ok { return model.User{}, ErrUserNotFound }
    return u, nil
}
// Create/List/Update/Delete 同模式：写路径 Lock，读路径 RLock；ID 一律 uint（全站基准）
internal/service/user_service.go（节选：依赖接口 + 哨兵错误）var (
    ErrUsernameExists = errors.New("用户名已被占用") // handler -> 409 + 1006（与 day4 文案一致）

type UserService struct { repo repository.UserRepository } // 字段是接口，不是 *repository.MemRepo

func NewUserService(repo repository.UserRepository) *UserService { return &UserService{repo: repo} }

func (s *UserService) Create(dto model.CreateUserDTO) (model.User, error) {
    list, _ := s.repo.List()
    for _, u := range list {
        if u.Username == dto.Username {
            return model.User{}, ErrUsernameExists   // 重名：专属哨兵，别用 fmt.Errorf 造匿名错误
        }
    }
    role := dto.Role
    if role == "" { role = "user" }
    return s.repo.Create(model.User{Username: dto.Username, Email: dto.Email,
        Password: dto.Password, Role: role, CreatedAt: time.Now()})
}

func (s *UserService) Get(id uint) (model.User, error) { return s.repo.Get(id) }

// handler 侧只调这些助手判断语义，不直接 import repository 的错误变量
func IsNotFound(err error) bool         { return errors.Is(err, repository.ErrUserNotFound) }
func IsUsernameExists(err error) bool   { return errors.Is(err, ErrUsernameExists) }
internal/handler/user_handler.go（节选）type UserHandler struct { svc *service.UserService }

// 读挂 public，全部写挂 auth（day3 讲义 6 的分组口径）
func (h *UserHandler) Register(public, auth *gin.RouterGroup) {
    public.GET("/users", h.List)
    public.GET("/users/:id", h.Get)
    auth.POST("/users", h.Create)          // ShouldBindJSON → svc.Create → Created
    auth.PUT("/users/:id", h.Update)
    auth.DELETE("/users/:id", h.Delete)
}

func (h *UserHandler) Get(c *gin.Context) {
    id, ok := parseID(c)                   // ParseUint(param, 10, 64) -> uint；失败已回 400 + 1004
    if !ok { return }
    u, err := h.svc.Get(id)
    if service.IsNotFound(err) {
        response.Fail(c, http.StatusNotFound, response.CodeUserNotFound, "用户不存在")
        return
    }
    if err != nil {
        response.Fail(c, http.StatusInternalServerError, response.CodeInternal, "服务繁忙") // 5000，别写裸数字
        return
    }
    response.OK(c, u)
}
// List/Create/Update/Delete + parseID 见 day4 讲义 6
cmd/server/main.gofunc main() {
    // 自底向上 new：repo → service → handler；用接口类型接住具体实现
    var userRepo repository.UserRepository = repository.NewMemRepo()
    var articleRepo repository.ArticleRepository = repository.NewArticleRepo()
    userSvc := service.NewUserService(userRepo)
    articleSvc := service.NewArticleService(articleRepo, userSvc)

    r := gin.New()
    r.Use(gin.Logger(), middleware.Recovery(), middleware.CORS(), middleware.Timer()) // Recovery 用 day3 §3.6 那份：day4 讲义里还是 gin.Recovery()，day5 练习 4 换成它。用官方版时 500 的 body 是空的（Content-Length: 0），下面第 4 节最后一条与「毕业标准」第 2 条就过不了
    r.HandleMethodNotAllowed = true // 默认 false：不打开的话「方法用错」会被当成没匹配上，返回 404 而不是 405（day1 第 5 节）

    // NoRoute 也走双层约定：HTTP 404 + 业务码 1001，禁止把状态码当业务码写成 code:404
    r.NoRoute(func(c *gin.Context) {
        response.Fail(c, http.StatusNotFound, response.CodeUserNotFound, "接口不存在: "+c.Request.URL.Path)
    })
    // 路径在、方法不对 → 405 + 1003（码表无 405 专属码，本周借用 1003）
    r.NoMethod(func(c *gin.Context) {
        response.Fail(c, http.StatusMethodNotAllowed, response.CodeForbidden, "方法不允许")
    })

    // 健康检查按基准不带 /api/v1 前缀
    r.GET("/health", func(c *gin.Context) { response.OK(c, gin.H{"status": "ok"}) })

    api := r.Group("/api/v1")   // 匿名读
    auth := r.Group("/api/v1")  // 同前缀第二组：全部写操作
    auth.Use(middleware.RequireAuth())

    handler.NewUserHandler(userSvc).Register(api, auth)
    handler.NewArticleHandler(articleSvc).Register(api, auth)

    r.Run(":8080")
}

自评三卡

代码量体检三层每层都写过 ≥ 100 行？handler 里还残留业务 if 判断吗？service 里还能搜到 gin.Context 吗？——有则回 day4 返工。

常见卡点（历届学员周报高频词）

卡点典型症状解法
三层拆完不会组装main.go 里 new 顺序混乱、字段全 nil 的 panic严格按 repo→service→handler 自底向上 new；每个 NewXxx 构造函数字段赋值齐全再返回
响应双写日志 superfluous WriteHeader，body 出现两个 JSON 拼接全局搜索 response.Fail 与 c.JSON，确认每分支后紧跟 return
required 误伤 0/falseauthor_id:0 或分页 size 为 0 被拒，行为诡异允许零值的字段改 omitempty,gte=0，缺省逻辑放 service
JSON 输出 {}repository 明明存了数据，接口却空对象检查字段是否大写开头、json tag 是否写、是否把未导出结构体直接扔进了 gin.H
并发下 map 崩Runner 一跑并发就 fatal error: concurrent map writes锁必须覆盖读和写；读用 RLock；确认 defer Unlock 在 Lock 的同一函数内
OPTIONS 被鉴权拦死预检返回 401，浏览器永远 CORS 失败CORS 中间件注册在 Auth 之前，且对 OPTIONS AbortWithStatus(204)（见 day3）

下周预告：为什么要真数据库，Docker 登场

内存 map 的三宗罪，本周你一定已经撞上：

  • 重启即灭：Ctrl+C 再 go run，用户全没了——第 1 周「重启待办仍在」的验收标准本周被我们自己打破了，第 3 周用 MySQL 把它捡回来。
  • 单进程独食：内存数据没法多实例共享，也撑不了任何数据量，List 全表遍历纯属暴力。
  • 没有查询语言：day4 里手写 for 循环找重名用户，第 3 周变成一句 WHERE username = ?，外加索引提速。

第 3 周（MySQL + GORM + Docker 入门）：用 docker compose up 三十秒起一个带数据卷的 MySQL，GORM AutoMigrate 建表，把本周项目原样改造——handler/service 几乎不动，只重写 repository 层（这正是 day4 那个 UserRepository 接口的兑现：换存储不改上层）。你会亲眼看到分层架构的回报。

扩展阅读（完全可选，不是预习任务）：第 3 周 day1 的「课前须知」会从零讲清 Docker 的镜像/容器/卷，并带你装好 Docker Desktop，不提前看也完全跟得上。如果你这周末还有余力，可以顺手扫两眼官方 compose.yaml 说明里 MySQL 服务那一段，纯粹混个眼熟——别在这上面花超过 20 分钟，本周的复盘比它值钱。
