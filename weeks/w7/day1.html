Go 多阶段 Dockerfile

课前须知

本周起点（承接 W6D5）：仓库归置在第 6 周 Day 5 已经做完，现在是 monorepo：goblog/ 下 backend/（第 3–4 周的 Go 服务：gin + gorm，含 go.mod/go.sum/cmd/server/main.go/internal/，监听 8080，业务路由挂 /api/v1，另有一个不查数据库的 GET /health）和 frontend/（第 6 周的 React + Vite 项目，VITE_API_BASE=/api/v1）。本周不需要再挪一次目录。今天所有命令都在 backend/ 里执行，明天换 frontend/，后天起回仓库根 goblog/。

还有一件事今天就要用上：第 4 周写的 internal/config 是 fail-fast 的——JWT_SECRET、DB_PASS 这类必填项缺失，进程直接 log.Fatal 退出。所以今天不能只 docker run 镜像 就完事，必须把环境变量注进容器，否则容器秒退（第 5 节给了带 --env-file 的完整命令和 docker logs 验证输出）。镜像里故意不带 .env——它被 .dockerignore 挡在门外，密钥进镜像等于进公网。

给前端同学的一句话类比：你从来不会把 node_modules 和 TS 源码部署到 CDN，只上传 dist 产物。Docker 多阶段构建就是这个思路的容器版——第一阶段是"厨房"（装满编译工具），第二阶段是"餐桌"（只端上最终那道菜：一个二进制文件）。

知识讲义

1. 反面教材：镜像为什么要小

最"省事"的 Dockerfile 长这样，它能跑，但错得离谱：

Dockerfile（反面教材）FROM golang:1.24            # 完整 Debian 环境 + Go 工具链，基座就 850MB
WORKDIR /app
COPY . .                # 整个构建上下文进镜像：源码、.git、本地编译出的 server、连 backend/.env 都拷
ENTRYPOINT ["go", "run", "./cmd/server"] # 每次启动都现场编译，冷启动几十秒

构建完执行 docker images，你会看到 1.2GB+：如果偷懒在项目根跑 docker build -f backend/Dockerfile .，上下文就是整个 monorepo，frontend/node_modules（动辄四五百 MB）全被塞了进去；而运行这个容器真正需要的东西只有一个 15MB 左右的二进制。对比各种基座镜像的裸体积：

镜像裸体积（约）里面有什么适合当
golang:1.24850 MBDebian + 完整 Go 工具链 + gccbuilder 阶段
golang:1.24-alpine230 MBalpine + Go 工具链builder 阶段（推荐）
alpine:3.207.8 MBbusybox 提供的极简 shell 和 apk 包管理器运行阶段（推荐）
scratch0 MB字面意义上一无所有，连 shell 都没有运行阶段（极限版）
nginx:1.27-alpine53 MBalpine + nginx 本体明天的前端运行阶段

体积直接影响三件事：push/pull 速度（云服务器带宽小，1GB 镜像一次发布好几分钟）、攻击面（镜像里每一个工具都是潜在漏洞）、冷启动（拉镜像越快，容器调度越稳）。

2. 正确姿势：完整的多阶段 Dockerfile

把下面这份文件保存为 backend/Dockerfile（文件名无后缀），每一个指令今天都会讲到，直接可用：

backend/Dockerfile# ---------- 阶段一：编译（builder，只在构建时存在）----------
FROM golang:1.24-alpine AS builder

WORKDIR /app

# 先只拷依赖清单——go.mod/go.sum 不变时，下面的 download 层永远命中缓存
COPY go.mod go.sum ./
RUN go mod download

# 再拷全部源码（配合 .dockerignore 剔除垃圾），改业务代码只重跑这一层之后
COPY . .

# 静态编译：CGO 关掉才不依赖 libc；-s 去符号表、-w 去调试信息，二进制再瘦 20–30%
RUN CGO_ENABLED=0 GOOS=linux go build -ldflags="-s -w" -o /out/server ./cmd/server

# ---------- 阶段二：运行（最终镜像只包含这一阶段）----------
FROM alpine:3.20

# 两个"必装件"，为什么必需见下一节；--no-cache 表示装完即清 apk 索引，不留垃圾
RUN apk add --no-cache ca-certificates tzdata

ENV TZ=Asia/Shanghai

# 从第一阶段只取那个二进制，builder 阶段的 230MB 工具链统统不带
COPY --from=builder /out/server /server

# EXPOSE 只是文档声明，真正映射端口靠 docker run -p / compose 的 ports
EXPOSE 8080

ENTRYPOINT ["/server"]

逐条拆解最容易考到的三个点：

指令为什么这样写
COPY go.mod go.sum ./ 放在 COPY . . 前面Docker 镜像按"层"叠放，每层有缓存 key（内容哈希）。依赖清单很少变、源码天天变——先拷清单，则改代码时 go mod download 层直接 CACHED 跳过，构建从 1 分钟降到 5 秒。反过来先 COPY . . 是新手第一大错，每次构建都重新下载全部依赖
CGO_ENABLED=0默认 Go 会链接系统 libc。alpine 用的是 musl 而不是 glibc，动态链接的二进制放进 alpine 会报 not found 或 GLIBC_x.y not found。关掉 CGO 产出纯静态二进制，放进 alpine 甚至 scratch 都能跑。验证：go build 后在宿主机执行 file server，输出含 statically linked 即合格
-ldflags="-s -w"-w 去掉 DWARF 调试信息，-s 去掉符号表。对生产运行零影响（panic 堆栈的行号会略糙，日志里错误信息仍然完整），二进制体积减 20–30%

Go 是"编译成单个静态二进制"的语言，天生适合容器化——不像 Node 镜像必须带 node 运行时和 node_modules，我们的最终镜像里连 Go 本身都不需要。

顺手记住指令速查：FROM 选基座、WORKDIR 定目录、COPY 搬文件、RUN 在镜像里执行命令（产生新层）、ENV 设环境变量、EXPOSE 声明端口、ENTRYPOINT/CMD 定启动命令。今天这份 Dockerfile 已覆盖全部常用指令。

3. 运行阶段的两个保命包：ca-certificates 与 tzdata

alpine 裸镜像 7.8MB 的意思是"几乎什么都没有"。以下两个包缺一个，线上就炸一类事故：

包不装的事故报错长相
ca-certificates后端调外部 HTTPS 接口时（第 8 周文件上传要调对象存储、接 GitHub OAuth 要调 api.github.com），Go 的 net/http 找不到根证书验证对方身份，直接拒绝连接x509: certificate signed by unknown authority
tzdata容器默认 UTC：日志/评论时间比北京时间差 8 小时；代码里 time.LoadLocation("Asia/Shanghai") 直接报错，因为时区数据库文件 /usr/share/zoneinfo 根本不存在unknown time zone Asia/Shanghai

配套动作：ENV TZ=Asia/Shanghai 让容器内进程默认时区生效；MySQL 侧第 3 周就配过 loc=Local，两边一起才是完整闭环。

为什么不用 scratch 当默认运行阶段？scratch（见今日练习 2）体积极限最小，但没有 shell——线上出问题时 docker exec 进不去、nslookup 不了、什么调试都做不了，且 psql/curl 全缺。学习阶段和绝大多数生产 Go 服务，alpine 是体积与可运维性的最佳折中。

4. .dockerignore：别让垃圾进厨房

COPY . . 拷的是"构建上下文"——Docker 会先把整个目录打包发给守护进程，再按 .dockerignore 过滤。不过滤的代价：每次构建白传几百 MB、.git 历史进缓存、.env 密钥进镜像层（镜像是会 push 到公网仓库的！）。保存为 backend/.dockerignore：

backend/.dockerignore.git
.gitignore
# 构建上下文是 backend/，本不该有这些东西；写上是为了防"在项目根跑 build -f backend/Dockerfile ." 时手滑
node_modules
frontend/node_modules
frontend/dist
dist
# 密钥绝不入镜像：运行时由 docker run --env-file 或 compose 的 environment 注入
.env
.env.*
# 杂项
*.md
.idea
.vscode
*.test
coverage.out
Dockerfile
docker-compose*.yml

对比前端认知：.dockerignore ≈ .gitignore，但控制的是"哪些文件进入构建上下文"。两者建议都配上，内容高度重合。

6. 体检：一个健康的 /health 长什么样

整周的健康检查都靠它，确认你的后端有这样一个不依赖数据库的探针（第 4 周应已写过，没有就补上；注意它不带 /api/v1 前缀，全站统一）：

backend/cmd/server/main.go（节选）r := gin.Default()
r.GET("/health", func(c *gin.Context) {
    response.OK(c, gin.H{"status": "ok"})   // W2 起的统一 Body：{code, message, data}
})
// 探针只证明"进程活着"。依赖型检查（查 DB）另开一个 /readyz，探针与就绪分开是行业惯例

响应体就是第 5 节 curl 打出来的那行：{"code":0,"message":"ok","data":{"status":"ok"}}。探针不查库的原因：healthcheck 如果依赖 MySQL，那么"数据库挂了"会让每个容器的状态都变红，还容易在启动依赖链里造成死锁式的循环等待。

7. 三个实用约定：镜像标签、构建平台、非 root 用户

  • 标签（tag）：goblog-api:0.1 里的冒号后就是 tag，不写默认 latest——生产大忌（你永远不知道 latest 是哪版）。练习阶段用日期或 git 短哈希：docker build -t goblog-api:$(git rev-parse --short HEAD) .，出问题能精确追回某次构建。
  • 平台（platform）：M 系列 Mac 构建出的镜像是 linux/arm64，直接推到 x86 云服务器会报 exec format error。本手册的路线是代码上服务器现构（W7D5），天然规避；将来若走镜像仓库，构建命令加 --platform linux/amd64 即可，今天先知道有这回事。
  • 运行用户（USER）：容器默认用 root 跑进程，严格的生产镜像会再压一层权限，在 COPY 之后、ENTRYPOINT 之前加：
# alpine 里先建一个没有家目录、没有登录 shell 的低权限用户，再切过去运行进程
RUN adduser -D -u 10001 app
USER app

好处是：万一有人通过你的接口打进容器，他也只是个 uid=10001，改不动 /etc、绑不了 80 端口。本课从简，不加这两行（体积和排错都比不上"先跑通"重要），但你得知道有这一层防御，第 8 周之后可以自行补上。

8. 构建机制速览：一次 docker build 到底发生了什么

shell（观察一次构建的完整动线）$ docker build -t goblog-api:0.2 .
# ① 打包当前目录（扣除 .dockerignore）→ 发送给 Docker daemon（"transferring context"）
# ② 从第一条指令起逐条执行，每条产出一层；层哈希 = 指令文本 + 输入文件内容
# ③ 命中缓存的指令打印 CACHED，直接复用旧层；一旦某层失效，其后所有层全部重做
# ④ 只有【最后一个 FROM 阶段】的文件系统被组装成最终镜像
现象解释
改一行 Go 代码，构建要 8 秒而不是 90 秒builder 层的 go mod download 命中缓存，只重跑 COPY . . 与其后的编译层
第一次构建某条 RUN 特别慢，之后秒过该层入缓存了；docker builder du 可以看缓存占了多少磁盘，docker builder prune 可清理
没改任何东西也整个重来多半是 Dockerfile 前置指令的输入变了（如 go.sum 被 go mod tidy 重排）——层缓存对"内容字节"严格敏感

[GIN-debug] GET    /health      --> main.main.func1 (3 handlers)

构建阶段最常见的报错是 go: downloading ... 卡住（网络问题，给 Docker Desktop 配代理或换镜像源）与 pattern ./cmd/server: directory not found（入口路径不对，按你实际 main 包位置改，比如 go build -o /out/server .）。运行阶段最常见的两个：Exited (1) + 配置加载失败: 缺少环境变量 JWT_SECRET（忘带 --env-file，见第 5 节反例）；数据库连接失败: dial tcp 127.0.0.1:3306: connect: connection refused（DB_HOST 写成了 localhost，改成 host.docker.internal）。

练习 2：scratch vs alpine 体积对比（20 分钟）

把运行阶段整段替换为 scratch 版本，重新构建为 goblog-api:scratch，对比 docker images 两个体积；再另起一个容器试着 docker exec -it … sh 进去，观察现象（api-dev 在第 5 节末尾已经被你删掉了，这里重新 run 一个即可）。

Dockerfile（scratch 运行阶段）FROM scratch

# scratch 连证书和时区文件都没有，从 builder 阶段（golang:alpine 里自带）抠出来
COPY --from=builder /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/
COPY --from=builder /usr/share/zoneinfo /usr/share/zoneinfo
COPY --from=builder /out/server /server

ENTRYPOINT ["/server"]

预期：体积再小 8MB 左右（正好省掉 alpine 基座那 7.8MB，与第 1 节表格同一口径；但你自己 COPY 进去的证书 + 全量时区库仍占 4–5MB，所以 scratch 版仍有一层"必需文件"的体积）。实测数字大致是 0.1 → 28.4MB、scratch → 20.1MB。然后：

shell$ docker run -d --name api-scratch --env-file .env.docker -p 8081:8080 goblog-api:scratch
$ docker exec -it api-scratch sh
OCI runtime exec failed: exec: "sh": executable file not found     # ← "不能调试"的实感
$ docker rm -f api-scratch

验证完把 Dockerfile 换回 alpine 方案（scratch 只作为对照实验，本周交付物用 alpine）。

练习 3：分层缓存实验（15 分钟）

三轮构建并记录 docker build 输出里 CACHED 的出现情况：① 什么都不改再 build 一次；② 只在 cmd/server/main.go 里改一行注释后 build；③ 在 go.mod 里加一行（比如随便加一个 replace 注释使其内容变化）后 build。

预期结论：① 全部 CACHED，秒完；② COPY go.mod 和 go mod download 仍 CACHED，从 COPY . . 层开始重做；③ 从 COPY go.mod go.sum ./ 层开始全部失效——这正是"清单与源码分两次 COPY"的价值。

在 backend/README.md 增补「容器化」小节：Dockerfile 位置、build/run 命令、alpine 与 scratch 的体积对比数字。用数据说话是作品集项目 README 的基本素养，第 8 周验收会检查。

今日名词卡

术语一句话解释
多阶段构建（multi-stage）一个 Dockerfile 里多个 FROM，最终镜像只保留最后一个阶段的文件系统
静态链接（上）Go 交叉编译能力同源：GOOS/GOARCH 一变即产出对应平台的独立二进制
构建上下文（build context）docker build 时先打包发给守护进程的当前目录，.dockerignore 控制其内容
apk add --no-cachealpine 装包不留索引缓存，镜像层的标准姿势
层缓存（layer cache）每条 Dockerfile 指令≈一层，指令内容与文件哈希未变则跳过（CACHED）
静态链接二进制自带全部运行所需代码，不依赖系统 libc，是"一个文件到处跑"的前提
scratchDocker 的空镜像，体积 0，Go 静态二进制极限部署方案
层缓存（build cache）逐指令执行、按内容哈希复用旧层，docker builder prune 可清理
就绪探针 /readyz与存活探针 /health 分工：前者查依赖（DB 可达），后者只证明进程活着

今日一句话总结：把"工具链留在厨房，只把菜端上桌"贯彻到每一条 Dockerfile 指令里——先清单后源码是它的缓存形态，多阶段是它的体积形态，.dockerignore 是它的卫生形态。明天的前端篇会原样复用这套思想（node 构建阶段 + nginx 运行阶段）。
