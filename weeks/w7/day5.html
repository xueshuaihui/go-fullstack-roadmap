课前须知

先用你熟的东西类比：今天干的事，本质就是"把 CI 产物发布到一台机器上"，只不过构建机就是那台机器自己。你熟悉的 vercel deploy / GitHub Pages 帮你藏掉了三件事——服务器是谁（SSH）、代码怎么到机器上（Deploy Key）、密钥从哪来（平台 Variables）。今天这三件事全部由你手动做一遍，做完之后你会对"部署"这两个字脱敏：以后接手任何公司的发布流程，拆开看都是今天这一页。

开工前该有的东西，缺一样先去补：

准备项状态确认
一台云服务器（1 核 2G、Debian 12 或 Ubuntu 22.04/24.04）能在云控制台里看到公网 IP，能用密码或已有密钥 ssh 上去
一个域名（不用买贵，首年几块的 .xyz/.top 就够练）能进控制台加解析记录；选大陆地域的机器就要现在就提备案（1~2 周，与今天所有事并行）
GitHub 上的私有仓库 goblog（第 6 周 D5 建的）git remote -v 指向 github.com/<你的用户名>/goblog，且 main 分支已经推过
本周产物齐套backend/Dockerfile、frontend/Dockerfile + nginx.conf、三份 compose 文件、.env.example、migrations/00000* 四对、Caddyfile（今天第 7 节写）

三把钥匙，别搞混（今天最容易被问倒的一处）：① 你本机 → 服务器的登录密钥：~/.ssh/id_ed25519，公钥进服务器的 /root/.ssh/authorized_keys（第 1 节 ssh-copy-id）；② 服务器 → GitHub 的取码密钥：服务器上新生成一把公钥，贴进仓库的 Deploy Keys（第 3 节）；③ GitHub 网页 / HTTPS 路线用的 PAT（第 3 节的替代方案）。每把钥匙只开一把锁：拿 ① 去 git clone 会 Permission denied (publickey)，拿 ② 去 ssh 服务器同理。两把私钥永远不进 Git，公钥才是要贴出去的那半截。

目录口径全周写死：/opt/goblog。本页所有脚本、crontab、巡检命令都按这个路径写。为什么是 /opt：Linux 的 /opt 就是"第三方自装应用"的位置，独立于系统包管理、也不在任何用户家目录下（放 /root/ 或 /home/deploy/ 里的项目，将来换部署用户、加备份任务都要改路径）。/var/www/ 是"只放静态站"的老习惯，本项目里 nginx 的静态文件在容器里，宿主机不需要 web 根目录。

还有一件事要先接受：从你按下 up -d 那一刻起，全站就在公网上了。几小时内 docker compose logs backend 里就会出现扫描器打 /phpmyadmin、/wp-login.php 的 404 记录。所以第 4 节那份"必改清单"不是形式主义——弱口令的 MySQL 在公网活不过几分钟。

知识讲义

1. 云服务器选购与开工准备

维度口径为什么
配置1 核 2G 起步够用，系统盘 ≥ 40GB，Debian 12 或 Ubuntu 22.04/24.04 镜像内存大头是 MySQL（约 500MB），backend 才 20–50MB，nginx/caddy 几十 MB
带宽按固定带宽 3–5Mbps 或按量计费均可本项目静态资源才 2MB，流量极小
地域就近选；一句话差异：中国大陆地域绑定域名对外提供 Web 服务需先完成 ICP 备案，海外/港澳台地域免备案但延迟略高未备案域名解析到大陆机器，80/443 会被运营商拦截
安全组放行 22（SSH）、80、443 三个入方向端口即可；3306、8080 不放行（而且 D3 的 base 里根本没映射它们）数据库和后端由 Nginx/Caddy 统一从 80/443 转发，直接暴露 = 被全网爆破

1G/2G 内存必做：加 swap。MySQL 冷启动和 docker build 编译 Go 都可能在瞬时打满内存，OOM 会直接杀掉 mysqld（表现：容器离奇 Restarting）。登录后先执行：

shell（服务器上 root 执行，一次性）$ fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
$ echo '/swapfile none swap sw 0 0' >> /etc/fstab     # 开机自动启用
$ free -h                                               # 确认 Swap 行出现 2.0Gi
$ timedatectl set-timezone Asia/Shanghai                # 服务器层时区，总结页卡点四"时区三连"的第一环（另两环：D1 镜像的 tzdata、D3 的 TZ + DSN loc）
$ timedatectl show -p Timezone --value                  # 只回一个值：Asia/Shanghai。别用 head -3 去截，Time zone 恰好是第 4 行，会被切掉

SSH 免密（本机执行）。第一次连接会问 Are you sure you want to continue connecting (yes/no)?——那是主机指纹确认，输 yes 后写进 ~/.ssh/known_hosts：

shell（macOS / Linux 本机）$ ssh-keygen -t ed25519 -C "laptop@$(hostname)"      # 已有 ~/.ssh/id_ed25519 就跳过，别覆盖
$ ssh-copy-id root@<你的服务器IP>                  # 输一次密码：它把公钥 append 到服务器 ~/.ssh/authorized_keys
$ ssh root@<你的服务器IP> 'hostname && date && docker --version'   # 连通性验证（docker 那条现在会失败，正常）
你在用什么ssh-copy-id 没有怎么办dig 没有怎么办
Windows 10/11 + 自带 OpenSSH（PowerShell）没有这个命令，手动送公钥：
Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub | ssh root@<IP> "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys"		nslookup blog.example.com，或 Resolve-DnsName blog.example.com -Type A
Git Bash / WSL命令与 macOS 一致，直接 ssh-copy-idGit Bash 没 dig，用 nslookup；WSL 里 sudo apt install dnsutils 后有 dig
不想装任何工具云控制台都有"网页终端/VNC"，登进去手动粘公钥即可在线 DNS 传播检测（各云厂商控制台都有"拨测/解析生效查询"）

SSH 本身也是公网端口：买机时若选了"密码登录"，尽快改为本机公钥 + 关闭密码认证（/etc/ssh/sshd_config 里 PasswordAuthentication no 后 systemctl restart sshd；Ubuntu 24.04 上还要顺手确认 KeyboardInteractive no，否则它还会弹密码）；22 端口同样有全网爆破。更稳妥的做法是云控制台"仅允许我的 IP 段访问 22"，学生项目至少做到密钥登录。

2. 安装 Docker 与 Compose 插件

官方一键脚本自动识别发行版、配好 apt 源与 systemd 服务（比"文档十一步"省事且不易错）：

shell（服务器上执行）$ curl -fsSL https://get.docker.com | sh
$ systemctl enable --now docker
$ docker --version          # Docker version 27.x
$ docker compose version    # Docker Compose version v2.2x.x —— 注意是 docker compose 两个词，带空格
$ command -v docker         # /usr/bin/docker ← 第 11 节的 cron 要用到这条信息

和第 3 周本机的区别：服务器上的 docker compose 是 v2 插件形态，命令与你熟悉的完全一致。旧文档里的 docker-compose（带横杠的 v1，Python 写的）已停止维护，见到就换掉。

本页有一个硬依赖：docker compose version 必须 ≥ v2.24。因为第 7 节要在 prod 文件里写 ports: !reset [] 抹掉 base 给 frontend 的 80:80（D3 §5.2 实测过 ports: [] 是无效的，列表是追加合并）。get.docker.com 装的版本、近两年安装的 Docker Desktop 都满足；先跑这一句确认，版本不够就 curl -fsSL https://get.docker.com | sh 再跑一次升级，或者按第 7 节末尾的降级方案改文件。

3. 让服务器拉到你的代码：Deploy Key（或 PAT）

私有仓库不能被服务器匿名 clone，两条路都给你配好，选一条走完就行。SSH Deploy Key 是本课主线（无密码提示、能写进 CI）。

3.1 主线：仓库级 Deploy Key

shell（在【服务器】上执行）# ① 为"服务器 → GitHub"这一把专门生成密钥：-N '' = 不设 passphrase（否则每次 pull 都要你输入）
$ ssh-keygen -t ed25519 -C "goblog-deploy@$(hostname)" -f /root/.ssh/goblog_deploy_key -N ''
$ chmod 600 /root/.ssh/goblog_deploy_key
$ cat /root/.ssh/goblog_deploy_key.pub      # ← 整行输出复制下来（一行的那半截是公钥，可以外贴）
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAI… goblog-deploy@iZbp1…

把这行公钥贴到 GitHub：仓库页 → Settings（右上角那个，不是账号的）→ 左侧 Deploy keys → Add deploy key；Title 写 goblog-prod-server，Key 框里粘贴，不要勾 Allow write access（Deploy Key 一旦勾了写权限，服务器被攻破时别人就能往你的主干推代码；本课只需要 git pull，只读足够）→ Add key。

shell（还是服务器）# ② 告诉 ssh：访问 github.com 时用这把专用密钥（不然它拿默认那把去试，照样 Permission denied）
$ cat >> /root/.ssh/config <<'EOF'
Host github.com
    HostName github.com
    User git
    IdentityFile /root/.ssh/goblog_deploy_key
    IdentitiesOnly yes
EOF
$ chmod 600 /root/.ssh/config

# ③ 验证：GitHub 回一句 Hi 就成了（它本来就不给 shell，报 not provide shell access 是预期）
$ ssh -T git@github.com
Hi <你的用户名>/goblog! You've successfully authenticated, but GitHub does not provide shell access.

$ mkdir -p /opt && cd /opt
$ git clone git@github.com:<你的用户名>/goblog.git
Cloning into 'goblog'...
remote: Enumerating objects: 812, done.

报错对照，两句就够：Permission denied (publickey) = 公钥没贴 / 贴错地方（贴到了账号的 SSH keys 也能用，但那是"账号级"权限，一台服务器能读你所有仓库）/ IdentityFile 路径写错；Error response from daemon: repository not found = 仓库名或用户名打错。IdentitiesOnly yes 那行不是装饰：不加它，ssh 会先把你默认密钥挨个试一遍，试到第三个 GitHub 就断连（too many authentication failures）。

3.2 替代路线：HTTPS + Personal Access Token

22 端口被公司网络封了、或者你就是不想配 SSH，就走这条：

shell（服务器）$ cd /opt
$ git clone https://github.com/<你的用户名>/goblog.git
$ cd goblog
$ git config credential.helper 'store --file=/root/.git-credentials'   # token 存进只有 root 读得到的文件
$ git pull
Username: <你的 GitHub 用户名>
Password: <粘贴 PAT>                # ← 这里绝不是账号密码：GitHub 从 2021-08 起禁用了密码认证
$ chmod 600 /root/.git-credentials

Token 从哪儿来：GitHub 右上角头像 → Settings → Developer settings（页面最底部左侧）→ Personal access tokens → Tokens (classic) → Generate new token (classic)，Name 写 goblog-prod，Expiration 设 30/90 天（到期换一次，等于强制轮换），Scope 只勾 repo（私有仓库读取必需）。更细粒度的 Fine-grained token 能限定到单个仓库、只给 Contents: read，比 classic 香，练手用哪个都行。

不要把 token 写进 remote URL。git remote set-url origin https://user:github_pat_xxx@github.com/… 确实最省事，但那条串会落在 /opt/goblog/.git/config 里——它会跟着你的项目目录一起被打包备份、被 cat 进排查截图。用 credential.helper 单独存到 600 文件里，至少 .git/config 是干净的。同理：Deploy Key 私钥、.env 都不许出现在任何提交或截图里。

4. 生产 .env：必改清单

D4 的 .env.example（进 Git 的键名清单）这时候发挥作用了——服务器上那份是它的一份副本，填上真值、权限收紧：

shell（在 /opt/goblog）$ cp .env.example .env && chmod 600 .env
$ grep -c '=' .env                       # 11 个键：D3 §4 那份口径，今天一个都不新增
$ vi .env                                 # 或者 scp 本机那份过来：绝对不要 git add .env
$ openssl rand -hex 24                    # 给 DB_PASS / MYSQL_ROOT_PASSWORD 现生成（纯十六进制，零转义风险）
$ openssl rand -base64 32                    # 给 JWT_SECRET / JWT_REFRESH_SECRET 现生成（两把必须不同）
.env 键必改动作不改的下场
DB_PASS / MYSQL_ROOT_PASSWORD各自 openssl rand -hex 24 现生成。compose 里 MYSQL_USER/MYSQL_PASSWORD/MYSQL_DATABASE 引用的是 DB_USER/DB_PASS/DB_NAME，所以改这两个就够了，不要去 .env 里找 MYSQL_PASSWORD 这个键公网 MySQL 弱口令几分钟内就会被扫描器爆破，轻则肉鸡、重则删库勒索——这不是吓唬，是全网常态
JWT_SECRET / JWT_REFRESH_SECRET各自现生成，两值必须不同沿用示例值 = 任何人可伪造任意用户的 token 直接登录
DB_HOSTmysql（服务名，不要改成 127.0.0.1）容器里的 localhost 是它自己 → backend Restarting（D3 §2 三连击）
GIN_MODEreleasedebug 模式泄露堆栈与路由信息、性能差
AUTO_MIGRATEfalse（D4 做的开关，今天正式用上）生产结构被代码"顺手"改动，和迁移文件打架
PORT / DB_PORT / DB_USER / DB_NAME保持 8080 / 3306 / goblog / goblog 就行—（真要改，记得 .env 与 compose 只有这一处事实源）

密码换了，库里的用户不会跟着换。D3 §4 讲透的机制在服务器上一样成立：mysql 镜像只在数据目录为空时执行建库建用户设密码。你是首次上线（第 5 节才会 up），所以现在改 .env 有效；如果这台机器以前跑过一次，改完 DB_PASS 要么 docker compose down -v 清卷（数据全没，想清楚），要么进容器 ALTER USER 'goblog'@'%' IDENTIFIED BY '新值';（D3 给过这条命令，注意整条在容器里展开）。判断依据：docker volume ls | grep goblog 有没有东西。

验证密钥没进 Git 的土办法但有效：git log -p | grep -i password 应该只有 .env.example 的键名行，没有真值（前提是你从第 4 周起就没提交过 .env；提交过的话历史里就有，需要换密钥而不仅是删文件）。

5. 首次上线：三步曲 + 日常四板斧 + 发布五步

服务器上每条 compose 命令都带三个旗，先把它变成一个短命令（只在交互 shell 里有效，脚本与 cron 里要写全，第 11 节会强调）：

shell（在 /opt/goblog；这条 alias 只影响你这个登录会话）$ echo "alias dc='docker compose -f docker-compose.yml -f docker-compose.prod.yml --env-file .env'" >> /root/.bashrc
$ source /root/.bashrc
$ dc config --quiet && echo "yml 与 .env 都对 ✔"      # D3 教的纯语法体检，不启动任何容器

首次部署就是 D4 的三步曲（生产口径），顺序不可拆：

shell（三步曲 1/3）先起库，等 healthy$ dc up -d mysql
$ dc ps
NAME           IMAGE       STATUS
goblog-mysql   mysql:8.0   Up 40 seconds (healthy)
shell（2/3）点名跑迁移：四对文件建出全部表结构$ docker compose --profile tools run --rm migrate up
4
$ docker compose --profile tools run --rm migrate version
4
dirty: false
shell（3/3）结构就绪，再起应用（服务器上第一次构建，会慢）$ dc up -d --build
✔ Built goblog-backend:local       # 1h2G 上第一次 go build 要 1~2 分钟，别急
✔ Container goblog-mysql    Healthy
✔ Container goblog-backend  Started
✔ Container goblog-frontend Started
$ dc ps                             # 三个 (healthy)
$ curl -s -o /dev/null -w "%{http_code}\n" http://<服务器IP>/    # 200（此刻还没有 HTTPS）

为什么第 2 步的 run 不用 dc？写成 dc … run 也能跑（migrate 不在 prod 文件里，合并无害），但 run 会真的起一个临时容器，输出直接打在你的终端、退出码 0 才算成功——这一步不需要 prod 的 restart/logging 那些差异，用默认口径（base + 没有 override，因为你显式没写 -f）最干净。记住这条命令的形状就好：docker compose --profile tools run --rm migrate <up|version|down 1|force N>，D4 第 8 节、D5 第 10 节、第 8 周 D1/D2 用的都是它。

shell（日常四板斧）$ dc logs -f backend --tail=50          # 追日志（Ctrl+C 退出，不影响容器）
$ dc ps                                  # 看状态：Up / Restarting / unhealthy
$ dc exec backend sh                     # 进容器：alpine 基座有 sh（D1 推荐它的理由之一），scratch 进不去
$ dc restart backend                     # 只重启某个服务
shell（更新发布五步——以后每次上线就这五行）$ cd /opt/goblog
$ git pull                                              # ① 拿代码
$ docker compose --profile tools run --rm migrate up     # ② 带了新迁移就先跑（在 up 之前！）
$ dc up -d --build                                       # ③ 只重建 Dockerfile 上下文有变化的镜像（层缓存也在），mysql 完全不动
$ dc logs backend --tail 20                              # ④ 确认新进程正常
$ docker image prune -f                                  # ⑤ 清掉被替换下来的旧镜像，防磁盘堆积

② 那一步没新迁移时是无害的空操作（输出还是 4），所以直接写进流程里比"想起来才跑"可靠。第 8 周你加了 000005/000006，靠的就是这一行不用改。

6. 补上 D2 欠的那条：location = /health

D2 警告过、D3 实测过：宿主机 http://localhost/health 会命中 location / 的 try_files 兜底，返回 <!doctype html> + 200——假绿探针，状态码说"服务很好"，其实一行 Go 都没跑到。今天把这条路打通（改 frontend/nginx.conf，加在 location /api/ 后面就行）：

frontend/nginx.conf（只贴新增这一段，其余 D2 原样不动）location = /health {                      # 精确匹配：优先级最高，抢在 location / 前面（D2 §4.1）
    proxy_pass http://backend:8080;           # 不带结尾 URI → 后端收到的仍是 /health（D2 那条斜杠纪律）
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    access_log off;                          # healthcheck 每 15 秒打一次，别把访问日志刷成噪音
}

location / {                               # 这条还在，仍然是 SPA 兜底；但 /health 已经不归它管了
    try_files $uri $uri/ /index.html;
}

改了镜像里的配置文件就必须重建（D2 那句"nginx.conf 是 COPY 进镜像的，改了要 rebuild"）：

shell（本地改 → 提交 → 服务器重建，一次来回）$ # 本机：改 frontend/nginx.conf → git commit → git push
$ # 服务器：
$ git pull && dc up -d --build frontend
$ curl -s https://blog.example.com/health        # 还没上 HTTPS 就用 http://<IP>/health
{"code":0,"message":"ok","data":{"status":"ok"}}    # ← 是 JSON 而不是 <!doctype html>，才算打通
$ curl -s -o /dev/null -w "%{http_code}\n" https://blog.example.com/no-such-page
200                                       # 前端路由兜底仍返回 index.html：这就是"状态码不能单独当健康判据"

顺手说清为什么用 = 而不是前缀 location /health：精确匹配只吃 /health 这一条 URI，不会连带把 /healthz、/health/detail 之类意外转给后端。本项目健康检查路径只有 /health 这一个（D4 那套、CANONICAL 那条都写死了它；/healthz 这类 k8s 味道的路径不在本课出现）。

7. 域名解析 + Caddy 自动 HTTPS

① 域名 A 记录：在域名控制台加一条解析——主机记录 blog（或 @），记录类型 A，记录值 = 服务器公网 IP。大陆地域须先完成备案。验证：

shell（本机执行）$ dig +short blog.example.com
47.98.xx.xx                 # 返回你的服务器 IP 即生效（DNS 全球生效一般几分钟到半小时）
# Windows / Git Bash 没有 dig：nslookup blog.example.com（见第 1 节那张表）

② Caddy 是什么、为什么是它：Caddy 是自带 HTTPS 的 Web 服务器：你只需写一行"域名 → 反代到哪个上游"，它自动向 Let's Encrypt 申请证书、验证、90 天自动续期、HTTP 自动 308 跳 HTTPS。Nginx + certbot 也能做到，但要多维护一个续期定时器。代价是：Caddy 要接管对外的 80/443，frontend 在 base 里那条 80:80 必须抹掉（否则宿主机端口冲突，caddy 直接 Bind for 0.0.0.0:80 failed: port is already allocated；而且对外多了个明文入口）：

docker-compose.prod.yml（在 D3 那份的 services 下追加）services:
  frontend:
    ports: !reset []              # ★ 抹掉 base 的 80:80，只让 Caddy 对外。写 ports: [] 无效（D3 §5.2）
  caddy:
    image: caddy:2-alpine
    container_name: goblog-caddy
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy-data:/data           # 证书与 ACME 账户存这里，named volume 重启不丢
      - caddy-config:/config
    depends_on:
      - frontend
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://127.0.0.1/health"]   # 走自己的反代全链路：caddy→frontend→backend
      interval: 30s
      timeout: 5s
      retries: 3

volumes:
  caddy-data:
  caddy-config:
Caddyfile（写在 /opt/goblog/Caddyfile，进 Git）# blog.example.com 换成你的真实域名（A 记录已指向本机）
blog.example.com {
    # 证书自动申请/续期，HTTP 自动 308 跳 HTTPS，无需任何额外配置
    encode gzip zstd
    reverse_proxy frontend:80     # 整站反代：静态文件与 /api/ 转发仍由容器里的 nginx 完成（D2/D6 那套）
}
shell$ dc up -d --build                          # 现在 frontend 的 80 映射没了、caddy 起来了，80 由 caddy 持有
$ dc config | grep -A 6 'ports:'           # 合并结果只该看见 caddy 的 80/443 一处
$ curl -s -o /dev/null -w "%{http_code} %{redirect_url}\n" http://blog.example.com/
308 https://blog.example.com/              # ← HTTP 自动跳转生效
$ curl -s https://blog.example.com/health
{"code":0,"message":"ok","data":{"status":"ok"}}

签发失败三查：① 安全组 80/443 是否放行；② dig +short 域名 是否已指向本机 IP（没生效就等一会再 dc restart caddy 重试）；③ 大陆服务器域名未备案（80/443 被拦，永远签不下来）。再看 dc logs caddy 里的 ACME 报错原文。ACME 有失败频率限制（同一域名每小时 5 次），连续失败会被暂停重试——所以调试期不要拿真域名反复试，本地用第 8 节那套 tls internal 演练。

8. 本地预演路线（服务器没买 / 备案没下来的间隙别闲着）

整条流水线除"公网 HTTPS 签发"外都能在 Mac 或 Windows 本地 1:1 走通（Docker Desktop / OrbStack / Rancher Desktop 任一，docker compose version ≥ v2.24）：

shell（本地，在项目根目录）# ① 与服务器同样的三步曲（用 prod 口径起，才演练得到 ports 被抹掉的那一幕）
$ docker compose up -d mysql
$ docker compose --profile tools run --rm migrate up
$ docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build

# ② 临时把 Caddyfile 的站点地址改成本地假域名 + 明确自签（见下面那份文件）
$ docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d caddy
$ curl -sk https://blog.localhost/health -H "Host: blog.localhost"
$ docker compose -f docker-compose.yml -f docker-compose.prod.yml logs caddy --tail 15
# … served with initial issuer … "tls": {"automatic": …} ← 只要看到它服务 443，链路就算演练过
Caddyfile（本地预演版：两行差别，标注清楚）blog.localhost {
    # ★ 关键一行：明确告诉 Caddy 用【内置 CA 自签】，别去公网申请。
    #   理由：Let's Encrypt 永远不会给 localhost / .localhost / 内网 IP 签证书；
    #   Caddy 对 .localhost、.test 这类保留后缀"通常"会自动走内部 CA，
    #   但那是版本相关的隐式行为——本课一律写死 tls internal，所见即所得。
    tls internal
    encode gzip zstd
    reverse_proxy frontend:80
}

把 tls internal 的产物和"真证书"的区别一次讲透：Caddy 用自己生成的本地 CA 给 blog.localhost 签了一张证书，浏览器一定会告警（NET::ERR_CERT_AUTHORITY_INVALID），点"继续前往"即可——这是预期行为，不是配置失败。你要验的是"反代链路通不通、header 传没传对、SPA 刷新会不会 404"，这些跟证书来源无关。想用 curl 验就把 -k 加上（跳过校验）。纯 HTTP 演练更省事：站点地址写成 http://localhost:8080 { … }（带 scheme 就完全不走 TLS），只是那一刻你演练的是"没有 HTTPS 的链路"，308 跳转那条测不到。/etc/hosts 那条 127.0.0.1 blog.localhost 在 macOS/Linux 上通常是多余的（.localhost 本身就被解析到回环），加上无害，Windows 那份要写 C:\Windows\System32\drivers\etc\hosts（用管理员权限的编辑器改）。

只有两件事必须等真服务器：公网可达（拿手机 4G 验证）与 真证书（Let's Encrypt 不会给 localhost/内网 IP 签发）。预演把其余 90% 的坑都提前踩掉，上线当天只做"搬运工"。

备案是"并行任务"：域名下单、备案材料提交和今天的本地预演同一周做，等备案短信到来时你早已万事俱备。海外机器则跳过备案直接解析上线。

11. 每日巡检与备份例行：两个脚本

小站没有监控告警，纪律就是监控。两个脚本都放 /opt/goblog，都要 chmod +x。

/opt/goblog/healthcheck.sh（30 秒跑完的健康卡）#!/bin/sh
cd /opt/goblog || exit 1
COMPOSE="docker compose -f docker-compose.yml -f docker-compose.prod.yml --env-file .env"

$COMPOSE ps                                  # 全部 Up (healthy)？有无 Restarting？
df -h /                                      # 磁盘 >85% 就要 image prune + 清日志
free -h                                      # available 低于 100Mi？查谁在吃内存
docker volume ls | grep goblog               # 数据卷在不在（怀疑数据问题第一步）

# 库活着吗？—— 整条命令在容器里展开，宿主机不需要知道密码（D4 第 5 节的姿势）
$COMPOSE exec -T mysql sh -c 'exec mysqladmin ping -h127.0.0.1 -uroot -p"$MYSQL_ROOT_PASSWORD" --silent'

# 结构版本对不对？（今天四对迁移 = 4，且 dirty 必须是 0）
$COMPOSE exec -T mysql sh -c 'exec mysql -u"$MYSQL_USER" -p"$MYSQL_PASSWORD" "$MYSQL_DATABASE" -e "SELECT * FROM schema_migrations;"'

# 全链路探针：走 caddy → nginx 的 location = /health → backend，真打到 Go
curl -s -o /dev/null -w "entry: %{http_code}\n" https://blog.example.com/
curl -s https://blog.example.com/health      # 必须是 {"code":0,…}，出现 <!doctype html> 就是那条 location 丢了
/opt/goblog/backup.sh（每周日凌晨跑，保留 4 份滚动）#!/bin/sh
set -e                                       # 任何一步失败就停下：备份脚本"半成功"等于没备份
cd /opt/goblog
STAMP=$(date +%F)                            # ← 宿主机 shell 的变量：外层双引号里由脚本自己展开
mkdir -p /root/backups

docker compose -f docker-compose.yml -f docker-compose.prod.yml --env-file .env exec -T mysql \
  sh -c 'exec mysqldump -u"$MYSQL_USER" -p"$MYSQL_PASSWORD" --single-transaction "$MYSQL_DATABASE"' \
  > /root/backups/goblog_$STAMP.sql

gzip -f /root/backups/goblog_$STAMP.sql
find /root/backups -name 'goblog_*.sql.gz' -mtime +28 -delete
echo "$(date +'%F %T') backup done: goblog_$STAMP.sql.gz $(du -h /root/backups/goblog_$STAMP.sql.gz | cut -f1)"
shell（crontab -e 追加一行：只调脚本，不写长命令）0 4 * * 0 /opt/goblog/backup.sh >> /var/log/goblog-backup.log 2>&1
# 每周日 04:00；日志落文件，出问题时才有东西可查（cron 的 stdout 默认没人看）

为什么备份一定要写成脚本、而不是把长命令塞进 crontab？三个真实的坑：① cron 的 PATH 只有 /usr/bin:/bin，命令里的 docker 万一在 /usr/local/bin 就找不到；② crontab 行里的 % 有特殊含义（表示换行），$(date +%F) 那种写法必须写成 \%F，忘转义就会得到一个诡异的空文件名；③ 长命令里 "$MYSQL_PASSWORD" 到底在宿主机还是容器里展开，三个月后没人读得懂——脚本里外层单引号包住 sh -c 的内容，是本课唯一口径。验证脚本单独跑一次：sh /opt/goblog/backup.sh && ls -lh /root/backups。

每月一次把备份 scp 回本机：scp root@<IP>:/root/backups/goblog_*.sql.gz ~/Downloads/（Windows PowerShell 自带 scp，命令一样）。只存在原机器上的那份不算备份——磁盘故障、误删卷、被入侵加密，都是同一把火。

练习 1：完整上线（必做，90 分钟）

按讲义 1→7 节顺序执行：买机/加 swap/设时区/安全组 → 装 Docker（确认 ≥ v2.24）→ Deploy Key + clone 到 /opt/goblog → .env 必改清单 → 三步曲部署 → location = /health → A 记录 + Caddy 上 HTTPS。验收：手机用 4G 网络（排除本机缓存干扰）打开 https://你的域名，完成一次注册 + 发帖，并 curl -s https://你的域名/health 贴出那行 JSON。截图存档——第 8 周 README 直接用。

练习 2：超时 vs 拒绝，学会定位卡在哪一层（15 分钟）

把服务器上的 caddy 停掉 dc stop caddy，curl 观察 Connection refused（端口没监听）；恢复后在云控制台临时移除安全组 80 放行，从手机 4G 访问感受一直转圈直到 timeout（包被防火墙丢弃）。记住这个判据：refused 查服务，timeout 查防火墙/安全组。练完把安全组恢复。

术语一句话解释

PAT（Personal Access Token）替代账号密码的 HTTPS 凭证，可按 scope/仓库收窄、可设到期日
A 记录把域名指向一个 IPv4 地址的 DNS 记录，一条即可
ACME / Let's Encrypt自动签发免费证书的协议与机构；Caddy 是它的最省心客户端（但不给 localhost/内网 IP 签）
tls internal让 Caddy 用自带本地 CA 自签证书，本地演练专用；浏览器必然告警，属预期
swap磁盘划出的虚拟内存，小内存服务器的 OOM 安全带
mysqldump --single-transaction不锁表的一致性备份方式，InnoDB 专用
假绿探针不存在的路径被 try_files 兜成 index.html + 200；location = /health 就是来终结它的
ICP 备案大陆服务器对域名对外 Web 服务的登记流程，约 1–2 周，与买机并行办理
发布回滚git 路线回滚 = git revert/checkout + 重新 up -d --build；镜像路线 = 退一个 tag
异地副本备份文件至少存两个物理位置（服务器 + 你自己电脑），才算真备份
