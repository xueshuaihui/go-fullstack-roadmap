知识讲义

1. docker-compose.yml 全文（可直接抄用）

docker-compose.yml# Compose v2 规范：顶层没有 version 字段（那是老 YAML 的遗物，加了会警告）
name: goblog

services:
  # ---------------- 数据库 ----------------
  mysql:
    image: mysql:8.0                     # 官方镜像，直接 pull，无需构建
    container_name: goblog-mysql
    restart: unless-stopped              # 机器重启后自动拉起；手动 stop 则不拉
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      MYSQL_DATABASE: ${MYSQL_DB:-goblog}          # :- 提供默认值
      MYSQL_USER: ${MYSQL_USER:-goblog}
      MYSQL_PASSWORD: ${MYSQL_PASSWORD}
      TZ: Asia/Shanghai
    command: --character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci
    volumes:
      - mysql-data:/var/lib/mysql        # named volume：删容器不删数据
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "127.0.0.1", "-u", "root", "-p${MYSQL_ROOT_PASSWORD}", "--silent"]
      interval: 10s
      timeout: 5s
      retries: 10
      start_period: 30s                  # MySQL 首次初始化很慢，前 30 秒失败不计数
    # 生产不暴露 3306；本地要图形化工具连库时，在 override 文件里放开（见第 5 节）

  # ---------------- Go 后端 ----------------
  backend:
    build:
      context: ./backend                 # 本地构建；image 给出产物 tag
    image: goblog-backend:local
    container_name: goblog-backend
    restart: unless-stopped
    environment:
      GIN_MODE: release
      SERVER_PORT: "8080"
      # 灵魂一行：主机名是服务名 mysql，不是 localhost、不是 127.0.0.1！
      MYSQL_DSN: ${MYSQL_USER:-goblog}:${MYSQL_PASSWORD}@tcp(mysql:3306)/${MYSQL_DB:-goblog}?charset=utf8mb4&parseTime=True&loc=Local
      JWT_SECRET: ${JWT_SECRET}
      JWT_REFRESH_SECRET: ${JWT_REFRESH_SECRET}
    depends_on:
      mysql:
        condition: service_healthy       # 等 mysql 的 healthcheck 通过才启动我
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://127.0.0.1:8080/health"]   # alpine 自带 busybox wget
      interval: 15s
      timeout: 5s
      retries: 5
      start_period: 10s

  # ---------------- 前端 + 反代 ----------------
  frontend:
    build:
      context: ./frontend
    image: goblog-frontend:local
    container_name: goblog-frontend
    restart: unless-stopped
    ports:
      - "80:80"                        # 全栈唯一对外端口
    depends_on:
      - backend                          # 数组式：只保证"它先起"，不等健康

    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://127.0.0.1/"]
      interval: 30s
      timeout: 5s
      retries: 3

# 顶层声明 named volume；名字会自动加项目前缀 → goblog_mysql-data
volumes:
  mysql-data:
字段要点
build vs image只有 image = 从仓库拉现成镜像（mysql）；build = 从本地 Dockerfile 构建。两者可同写：build 的产物打上 image 这个 tag。W7D5 服务器上就是直接 up -d --build 现场构建，不需要镜像仓库账号
${VAR} / ${VAR:-默认}compose 自动读取同目录 .env 做变量替换。密钥进 .env（不进 Git），编排进 yml（进 Git），从此密码不出现在任何提交里
ports 只给 frontendbackend:8080、mysql:3306 故意不映射：内网服务名互访根本不需要发布端口。少暴露一个端口少一分被扫描爆破的风险——这是今天最重要的安全观

2. 经典坑正解：服务间网络 DNS，DSN 主机名为什么是 mysql

compose 默认把同一文件里的所有服务挂进一个 bridge 网络（goblog_default），并内置 DNS 服务器：服务名 = 容器名别名 = 可直接解析的主机名。于是 backend 里写 tcp(mysql:3306)，Docker DNS 把 mysql 解析成数据库容器的内网 IP。

localhost 三连击（本周报错率第一名）：① 在 backend 容器里，localhost:3306 指向 backend 自己——那里没有 mysqld，日志刷 dial tcp 127.0.0.1:3306: connect: connection refused；② 在宿主机 curl 容器内端口也没用（没映射就不存在）；③ 图形化工具从宿主机连库，则要反过来用 127.0.0.1:3306 且先在 override 里映射端口。判断口径只有一句话：我此刻在哪个网络命名空间里？

动手验证 DNS 机制（三行命令看穿黑盒）：

shell$ docker compose exec backend sh -c "getent hosts mysql"
172.18.0.2      mysql                      # 服务名解析出了容器 IP ✔

$ docker inspect goblog_mysql --format '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}'
172.18.0.2                                # 与上面对得上 ✔

$ docker network inspect goblog_default --format '{{range .Containers}}{{.Name}} {{end}}'
goblog-mysql goblog-backend goblog-frontend  # 三兄弟同网 ✔

3. 启动顺序：裸 depends_on 与 service_healthy 的差别

裸 depends_on（数组式）只保证"MySQL 容器被创建并启动"再启动我。而 MySQL 容器起来 ≠ mysqld 可用——首次初始化要 20~40 秒，这期间 TCP 能连上但认证/查询全失败，backend 连库报错直接退出。这就是第 3 周你见过"backend 崩一次、第二次才活"的原因。

正解是健康检查驱动的依赖：depends_on.mysql.condition: service_healthy，它会轮询 mysql 自己的 healthcheck，真的能 ping 通了才放行 backend。frontend 对 backend 用数组式即可（nginx 起不来无非 502，不需要强等）。

healthcheck 五件套含义
test容器内执行的探测命令，退出码 0 即健康。三种写法：CMD（直接执行，需镜像里有该二进制）、CMD-SHELL（丢给 sh 跑，可写 -p${VAR} 这类变量展开）、裸数组等价 CMD
interval / timeout每 10s 探测一次 / 单次超 5s 算失败
retries连续失败 N 次才判 unhealthy
start_period启动宽限期，此期间失败不计数（MySQL 必需，否则初始化就被判死刑）

各服务的探测命令选择：MySQL 用 mysqladmin ping；有 shell 的 Linux 发行版镜像（alpine/debian）用 wget -qO-；scratch 镜像连 wget 都没有，只能让程序自己实现（不少 Go 项目引入 google/go-containerregistry 的 /healthz 风格探针或干脆把探测放到编排层）——这也是 W7D1 推荐 alpine 的原因之一。

4. .env 与变量注入

.env（模板：值全部换成你自己的强随机串，此文件加入 .gitignore）MYSQL_ROOT_PASSWORD=<生成: openssl rand -base64 24>
MYSQL_USER=goblog
MYSQL_PASSWORD=<生成: openssl rand -base64 24>
MYSQL_DB=goblog
JWT_SECRET=<生成: openssl rand -base64 32>
JWT_REFRESH_SECRET=<生成: openssl rand -base64 32，与上面必须不同>

两条规则分清：yml 里的 ${VAR} 是 compose 在渲染阶段做的文本替换（读的是项目目录 .env）；environment: 注入的值才是容器内进程真正读到的环境变量。踩过的坑在这里汇合：变量没定义时替换成空串，MySQL 拿到空 root 密码照常初始化，backend 带密码连库则 Access denied for user——报错和真因隔着十万八千里。

YAML 特殊字符雷区：密码里含 # 会被 YAML 当注释截断、含 : 可能破坏键值解析、含 $ 会被 compose 再做一次变量展开。最省事：密码只用字母数字（openssl rand -hex 24 就是安全且免转义的），或整值加双引号。

5. 开发 vs 生产：override 文件思路

base 文件保持"生产形态"，环境差异用叠加文件解决。compose 的合并规则：docker compose up 会自动加载 docker-compose.yml + docker-compose.override.yml；生产则显式指定，不走默认：

docker-compose.override.yml（开发专用，仓库里也提交它——里面没有密钥）services:
  mysql:
    ports:
      - "127.0.0.1:3306:3306"   # 只绑回环：本机能连库调试，公网扫不到
  backend:
    environment:
      GIN_MODE: debug            # 覆盖 base 的 release
docker-compose.prod.yml（服务器上不放或只放加固差异）services:
  backend:
    restart: always              # 机器重启必须自动拉起
    logging:
      driver: json-file
      options:
        max-size: "10m"          # 日志限量，防止刷爆系统盘
        max-file: "3"
shell# 开发（本机）：自动合并 base + override
$ docker compose up -d --build

# 生产（服务器）：显式两文件，.env 用 --env-file 指定绝对路径更稳
$ docker compose -f docker-compose.yml -f docker-compose.prod.yml --env-file .env up -d --build

原则：能合并、不复制。绝不维护两份完整的 compose 文件——那是一切"改了这边忘了那边"事故的温床。

常见坑（新手 100% 会踩）

坑现象正确姿势
DSN 写 localhostbackend Restarting 循环，日志 connection refused同网络一律用服务名；理解"容器里的 localhost 是它自己"
裸 depends_on 就完事首次冷启 backend 连不上还没初始化完的 MySQL依赖方 depends_on + 被依赖方 healthcheck，二者缺一不可
.env 变量没定义MySQL 空密码初始化"成功"，backend 却 Access denied渲染后先 docker compose config 肉眼过一遍；关键变量可用 ${VAR:?报错文案} 强制要求存在
密码含 # : $ 未加引号行为诡异：配置"明明写了"却不生效只生成字母数字密码，或整值双引号
给所有服务映射端口8080/3306 公网裸奔，等着被爆破只有需要外部访问的才 ports；内网走服务名
改了代码 up 了个"没变化"的站部署后跑的还是旧逻辑up -d --build；或先 docker compose build backend 再 up。周末总结页的卡点复盘专题
