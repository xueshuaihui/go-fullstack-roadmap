卡点复盘：本周五大经典事故

卡点一：终态与既有代码不一致——env 键名 / 表列名 / 路由前缀 / 仓库目录（发生率第一）

为什么排第一：本周没有一行"新逻辑"，做的全是对第 3–6 周代码的搬迁与接线。搬迁不出错的前提是"名字逐字对得上"，而名字有四处必须同时成立——差一个字就是全站瘫。

症状① backend 起来就退出：日志里 DB_PASS 是空串，或 Access denied for user 'goblog'@'172.18.0.3' (using password: YES)；② migrate up 报 Error 1146 Table 'goblog.users' doesn't exist，或 up 成功但接口 500 说 Unknown column 'bio'；③ 前端点登录一直转圈，手动 curl 打 /api/login 是 404，改成 /api/v1/auth/login 才通；④ docker compose build 报 COPY failed: file not found
病因四张"名字表"至少错了一张：compose 里的 env 键名 ≠ config.go 里 getEnv 读的键名（或自己造了 DB_PASSWORD/MYSQL_DSN 这类别名）；迁移文件的列名 ≠ model 的字段映射（password_hash vs password、漏了 nickname/article_count）；前端调用的前缀 ≠ nginx location 能匹配上的前缀；build 上下文（build: ./backend）≠ Dockerfile 里 COPY 的相对路径基准。凭记忆改写、而不是照抄已经存在的那份，是本事故的唯一成因
药方① 键名以 .env.example 为唯一出处，改任何一处全仓库搜一遍：grep -rn "DB_PASS" .；② 列名以 backend/internal/model 为唯一出处，迁移写完立刻 SELECT COLUMN_NAME FROM information_schema.COLUMNS WHERE TABLE_SCHEMA='goblog'; 逐行对；③ 前缀只有一套：location /api/ 覆盖 /api/v1/*，后端注册 r.Group("/api/v1")，验收永远打完整路径；④ 凡是"照抄"的段落，从已定稿的那一页重新复制，不要从自己的记忆里复制——本周已五次三番栽在 ${VAR} 与 $$VAR 的差别上，同一个道理
验证三条命令连过一次，即本事故不存在：dc config --quiet（渲染无警告）→ docker compose --profile tools run --rm migrate version（4 / dirty: false）→ 登录 curl 拿到 access_token。外加一条：docker compose exec mysql sh -c 'exec mysql -u"$MYSQL_USER" -p"$MYSQL_PASSWORD" "$MYSQL_DATABASE" -e "SHOW COLUMNS FROM users;"' 的输出与 model 一字不差

卡点二：backend 连不上 MySQL——localhost 之祸（几乎人人中招）

症状backend 状态 Restarting，日志 dial tcp 127.0.0.1:3306: connect: connection refused
病因把宿主机视角写进了容器视角：容器里的 localhost 是它自己的网络命名空间，那里没有 mysqld
药方DSN 写 tcp(mysql:3306)（compose 网络内服务名）；宿主机工具连库才是 127.0.0.1:3306 且需 override 映射。判据永远是"我此刻在哪个命名空间"
验证docker compose exec backend sh -c "getent hosts mysql" 能解析出 IP 即网络层通

卡点三：明明"部署了"，跑的还是旧代码——镜像没重建

症状改了代码、compose up 也执行了，页面纹丝不动；或浏览器强刷才生效
病因up -d 只保证"镜像存在且有容器"，不会重新 build；Vite 变量是构建期烧录的，改 env 不重 build 等于没改
药方发布肌肉记忆 up -d --build（层缓存让它并不慢）；验证看前端 assets 文件名 hash 是否变化、build 日志有没有重跑目标层
连带坑浏览器缓存了旧 index.html → 永远在引用旧 JS。D2 的 index.html no-cache 配置就是为消灭这一层

卡点四：网站打不开，转圈到超时——安全组没放行

症状服务器上 docker compose ps 一切正常、本机 curl 127.0.0.1 通，外就是不访问；浏览器 timeout
病因云厂商控制台的安全组（机器外面的防火墙）没开 80/443——它和机内 ufw 是两层，任何一层都拦
药方定位口诀：refused 查服务有没有监听，timeout 查防火墙/安全组；云控制台补放行后手机 4G 复测
举一反三同法可查 22 被封锁（换网/控制台 VNC 应急）、443 通了但证书没签（回看 DNS 生效与备案）

卡点五：时间全差 8 小时——时区三连

症状评论/文章时间比现实早或晚 8 小时，或日志时间戳对不上
病因三处各管一段：① 容器默认 UTC（缺 tzdata 时连 LoadLocation 都报错）；② MySQL 服务端时区；③ GORM DSN 的 loc 参数
药方本周文件里已全部配齐：D1 镜像 apk add tzdata + ENV TZ；D3 mysql 环境 TZ=Asia/Shanghai；DSN parseTime=True&loc=Local；服务器层 timedatectl set-timezone Asia/Shanghai（D5 第 1 节里已经执行过，并且写进了 D5 完成检查与本页验收第 3 条——它是验收项，不是可选项）
验证发一条帖，页面时间、backend 日志时间、SELECT created_at 三者一致且等于手表时间

面试模拟：这十二个问题现在都答得上来

问题答题要点（本周都讲过）
为什么 Dockerfile 要分两个 FROM？工具链与运行时分离；最终镜像只含二进制+最小基座，体积/攻击面/速度三赢
改一行代码重建，为什么依赖没重新下载？层缓存按内容哈希判定；清单先 COPY 使 go mod download 层保持 CACHED
CGO_ENABLED=0 和 -s -w 各干什么？前者静态链接保证 alpine/scratch 可跑；后者去符号表与调试信息再瘦身
SPA 刷新 404 的根因与解法？pushState 不发请求，服务器不认识前端路由；try_files 兜底 index.html
proxy_pass 结尾带斜杠有何区别？带则剥掉 location 前缀转发，不带则原样透传——路径不匹配即 404
backend 怎么连上 mysql 的？同 compose 网络内置 DNS，服务名即主机名；localhost 指向容器自身
depends_on 能解决"库还没就绪"吗？裸 depends_on 只管启动顺序；要配 healthcheck + condition: service_healthy
生产为什么禁用 AutoMigrate？不删列/改名留残列/类型变更锁表/无版本不可回滚/多副本竞改
schema_migrations dirty=1 怎么办？手工善后半途 SQL → force 目标版本清标记 → 继续 up
down 和 down -v 的区别？前者留 named volume；后者删卷＝删库，不可恢复
compose 里 migrate 的固定参数为什么写 entrypoint: 而不是 command:？run --rm <服务> <子命令> 会替换 command、把参数追加到 entrypoint；写进 command 就等于每次都要重敲连接串，还容易漏 multiStatements=true
docker compose exec mysql -p"$MYSQL_PASSWORD" 为什么必然 Access denied？引号外的 $VAR 由宿主机 shell 展开，而那个键只存在于容器环境里 → 传进去是空串；改成 exec mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD"'，让容器自己取值

能把这十二题连珠炮般答完，你的"会部署"就已经超过了多数只会照抄 YAML 的候选人——第 8 周简历项目栏可以放心写"Docker Compose 全栈编排 + 云服务器自动化上线"。

写进笔记的本周十二条军规

  1. 清单先 COPY，源码后 COPY——层缓存是构建速度的全部秘密。
  2. CGO_ENABLED=0 + ca-certificates + tzdata，Go 容器三件套。
  3. .env 永不进 Git，密钥只在 .env.example 里留键名。
  4. 容器互访用服务名；判断网络问题先问"我在哪个命名空间"。
  5. depends_on 要配 healthcheck，"起了"≠"能用"。
  6. 只有需要被外部访问的服务才映射端口，80/443 之外都是内网。
  7. 变量在谁的 shell 里展开，就得在谁的环境里存在：要在容器里取 $MYSQL_PASSWORD，就把整条命令写进 sh -c '…' 交给容器，宿主机那份永远是空的。
  8. 照抄只抄"已定稿的那一页"：env 键名、表列名、路由前缀、目录层级这四个东西，一个字都不许凭记忆重写。
  9. 迁移文件合入后永不修改，错误用新迁移纠正。
  10. 生产不用 AutoMigrate；先关 AUTO_MIGRATE 再 migrate up，上线前在预发库跑一遍 up。
  11. down 不带 -v；备份必须有异地副本，且恢复演练过——没验过能恢复的备份不叫备份。
  12. 发布 = pull → migrate up → --build → 验证 → prune；回滚演练过才敢按按钮。

排障速查卡：出事先跑这九行

shell（服务器 / 本机通用，从上到下逐层定位）$ docker compose ps                          # 谁不正常：missing / Restarting / unhealthy？
$ docker compose logs <问题服务> --tail 30    # 它的报错原文（先读三遍再搜索）
$ docker compose exec backend sh -c "getent hosts mysql"   # 网络层：服务名解析通吗
$ docker compose exec backend sh -c "wget -qO- :8080/health"  # 容器内自测服务本身活着吗
$ curl -s -o /dev/null -w "%{http_code}\n" http://localhost/  # 宿主机层：对外入口通吗
$ docker compose exec mysql sh -c 'exec mysql -u"$MYSQL_USER" -p"$MYSQL_PASSWORD" "$MYSQL_DATABASE" -e "SHOW TABLES; SELECT version, dirty FROM schema_migrations;"'   # 结构层：表在不在、迁移到第几号（注意：整条交给容器里的 shell）
$ docker volume ls                           # 数据卷在不在（怀疑数据问题第一步）
$ df -h / && free -h                          # 机器层：磁盘满 / 内存OOM 是两大隐形杀手
$ docker compose -f docker-compose.yml -f docker-compose.prod.yml --env-file .env config   # 配置层：渲染后的最终 YAML，键值一目了然

都通了但时间不对卡点五 时区三连，逐处核对 timedatectl / TZ / loc
全 healthy、页面能开，但接口 404 或 500 Unknown column卡点一 终态不一致：路由前缀或表列名没对上既有代码，先跑它那一节的三条验证命令

顺序有讲究：从 ps 到 logs 是"哪一层坏了"，从 exec 自测 到 宿主机 curl 是"坏在容器内还是链路外"。养成按卡排查的肌肉记忆，比任何一次灵光乍现都可靠。

下周预告：第 8 周 · 综合项目实战（收官）

最后一周不再学新"部署"，而是回到功能：还是同一个 goblog monorepo、同一个 /opt/goblog、同一套 compose 与三步曲，只做增量——加三张表/一列、加两个中间件、加一组接口，然后收尾成作品集。

  • RBAC 角色权限（D1）：users 表那个 role 列是你自己用 000002 建好的，下周直接 WHERE role = 1 用它——权限中间件按角色放行，admin 管理全站文章与用户；
  • 文件上传（D2）：Gin FormFile / SaveUploadedFile、扩展名 + 魔数 + 大小三件套校验、头像与封面落盘；新迁移 000006_add_avatar_to_users 给 users 补一列，并给 uploads 目录挂 named volume（这周的卷与 compose 知识立刻还债）；
  • 评论 + 前端权限与收尾（D3）：新表 comments 走 000005_add_comments，文章详情页加评论区与删除入口，前端按 role 控制可见性；
  • 联调测试修 bug（D4）：把第 4 周那条 CI workflow 升级成 -race 全量 + 覆盖率，发布前跑一遍真实回归；
  • 部署 + README + API 文档（D5）：把今天的"发布五步"补成六步（备份在前、健康检查在后），再把首页链接、手机截图、那张架构图、启动说明整理成能放进简历的作品集页面。

带着三个问题进入下周，你的 D1 会顺畅十倍：① 权限中间件该注册在路由组的哪一层？② 上传的封面文件落在容器里，compose 重建后去哪找？③ README 里的架构图敢不敢直接用本周的 docker-compose.yml 画？
