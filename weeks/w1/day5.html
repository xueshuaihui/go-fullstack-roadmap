知识讲义

1. 一次请求长什么样：报文六件套

HTTP 是纯文本的问答协议：客户端先说话（请求），服务端回答（响应）。curl -v 能把这层文本全打印出来，后端调试试错第一步就是读它。

shell：GET 的完整报文$ curl -v http://localhost:8080/health
> GET /health HTTP/1.1        # 请求行 = 方法 + 路径 + 协议版本
> Host: localhost:8080        # 请求头：每行一个 Key: Value
> User-Agent: curl/8.4.0
>                             # 空行 = 头结束，下面本可以跟请求体
< HTTP/1.1 200 OK             # 状态行 = 协议 + 状态码 + 原因短语
< Content-Type: text/plain; charset=utf-8  # 响应头
< Date: Sun, 20 Sep 2026 09:12:33 GMT
<                             # 空行
{"status":"ok"}               # 响应体：状态码和头之外，你真正要的数据
$ curl -v -X POST localhost:8080/todos -H "Content-Type: application/json" -d '{"title":"学习Go"}'
> POST /todos HTTP/1.1        # 方法换成 POST
> Content-Type: application/json   # 告诉服务端 body 是什么格式
> Content-Length: 20          # body 字节数：HTTP 靠它知道 body 到哪结束
>
> {"title":"学习Go"}          # 请求体
< HTTP/1.1 201 Created        # 新建成功是 201，不是 200
< Location: /todos/3          # 新资源的地址，REST 的礼貌约定
方法语义有没有 body幂等？成功码
GET取资源，不该有副作用一般没有是200
POST创建 / 提交处理有否（点一次建一条）201 / 200
PUT整体替换资源有是（换十次结果一样）200 / 204
PATCH局部更新（本周用它标记完成）有（可空）是（本项目）200
DELETE删除资源一般没有是204 / 200
状态码含义本周什么时候返回
200 OK成功，有 bodyGET 列表 / GET 单条 / PATCH 成功
201 Created创建成功，body 是新资源POST /todos
204 No Content成功，但故意没有 bodyDELETE /todos/:id
400 Bad Request客户端错了：参数/JSON 不合法坏 JSON、空 title、id 不是数字
404 Not Found资源不存在（也可能路径没注册）GET/PATCH/DELETE 一个不存在的 id
500 Internal Server Error服务端错了，且不是调用方的锅写文件失败、panic 被兜住

你在前端 fetch 里写的 res.ok、res.status、res.headers.get("Content-Type")，对应这里的状态行和响应头。4xx 与 5xx 的分界是后端最基本的职业素养：4xx = 你请求得不对，5xx = 我这边出事了。把数据库失败返回成 400，前端会以为是参数错而疯狂重试。

2. REST：URL 是名词，方法是动词

REST 的核心只有一句：资源用 URL 表示，动作用 HTTP 方法表示，不要把这个动作塞进 URL。

需求REST 写法反面写法（别学）
待办列表GET /todosGET /getTodos、POST /todoList
新增一条POST /todos + bodyGET /addTodo?title=xx
看单条GET /todos/3GET /getTodo?id=3
标记完成PATCH /todos/3GET /todos/3/done
删除DELETE /todos/3POST /deleteTodo
集合过滤 / 分页GET /todos?done=false&page=2（查询参数）GET /todos/done-false-page-2

路径参数（/todos/{id}）标识"哪一个"，查询参数（?done=false）标识"要哪些 / 怎么排"。第 2 周 Gin、第 3 周 GORM 分页、第 6 周前端 axios 全都沿用这套约定，现在就把它当母语。

3. net/http 三大件：Handler、ServeMux、Server

标准库只有三个概念要记：http.Handler（接口，一个方法）、http.ServeMux（路由器，按路径+方法找到 Handler）、http.Server（监听端口、每个请求开一个 goroutine）。

hello.gopackage main

import (
    "fmt"
    "log"
    "net/http"
    "time"
)

// http.Handler 是只有一个方法的接口：ServeHTTP(w, r)
// 任何类型实现了它就是一个处理器——Day 4 的隐式实现立刻用上
type greeter struct { name string }

func (g greeter) ServeHTTP(w http.ResponseWriter, r *http.Request) {
    fmt.Fprintf(w, "hi %s，你访问的是 %s", g.name, r.URL.Path)
}

func main() {
    mux := http.NewServeMux()
    // ① 挂一个实现了 Handler 接口的值
    mux.Handle("GET /greet", greeter{name: "ada"})
    // ② 常用：直接挂函数，签名 func(w, r) 就是 http.HandlerFunc 类型
    mux.HandleFunc("GET /health", func(w http.ResponseWriter, r *http.Request) {
        w.Header().Set("Content-Type", "application/json; charset=utf-8")
        fmt.Fprintf(w, `{"status":"ok","time":%q}`, time.Now().Format(time.RFC3339))
    })
    // ③ Go 1.22 起 pattern 可带方法与 {参数}，取值用 r.PathValue（不用再手写解析）
    mux.HandleFunc("GET /todos/{id}", func(w http.ResponseWriter, r *http.Request) {
        fmt.Fprintf(w, "你要找的待办 id = %s", r.PathValue("id"))
    })
    log.Fatal(http.ListenAndServe(":8080", mux)) // 阻塞服务；它返回非 nil 就是出错了
}

两个细节：① 方法+通配的 pattern 要求 Go 1.22 以上，所以 go.mod 里的 go 版本别写太低（go 1.22 起生效）；② w 只能"往前写"：w.Header().Set 必须在 WriteHeader／第一次 Write 之前调用，之后设的头会被静默丢弃。

对比 Express/Koa：app.get('/todos', (req, res) => …) 里 req/res 是 Node 封装过的对象，还有 next() 串中间件；Go 的 ResponseWriter 极其朴素——它只是一个 io.Writer 加上头/状态码方法，写之前记得自己 return。第 2 周 Gin 的 gin.Context 才把这套东西包得顺手。

4. JSON 收发：一个出口 + 一个入口

API 的 body 就是 JSON。Go 用 encoding/json 在结构体字段和 JSON key 之间映射，靠的是 Day 2 结尾提到的 struct tag。

json.go（片段：只看读写两个动作，讲义 5 已把它们整合进 server.go）// 写：所有响应都走这一个出口，顺序固定——设头 → WriteHeader → 写 body
func writeJSON(w http.ResponseWriter, status int, v any) {
    w.Header().Set("Content-Type", "application/json; charset=utf-8")
    w.WriteHeader(status)
    if err := json.NewEncoder(w).Encode(v); err != nil {
        log.Println("encode:", err) // 头已发出，无法再改状态码，只能记日志
    }
}

// 读：用匿名 struct 只接你关心的字段，多传字段自动忽略，少传就是零值
func createTodo(w http.ResponseWriter, r *http.Request) {
    var in struct {
        Title string `json:"title"`
        Done  bool   `json:"done"`
    }
    if err := json.NewDecoder(r.Body).Decode(&in); err != nil {
        writeJSON(w, http.StatusBadRequest, map[string]string{"error": "body 不是合法 JSON"})
        return                       // 忘了 return 会继续往下跑：这是 500 的头号来源
    }
    if strings.TrimSpace(in.Title) == "" {
        writeJSON(w, http.StatusBadRequest, map[string]string{"error": "title 不能为空"})
        return
    }
    writeJSON(w, http.StatusCreated, in)
}

JSON 映射三铁律（第 2 周 Gin 的 ShouldBindJSON 一模一样）：① 字段必须大写开头才导出，小写字段 JSON 里永远收不到；② 想要 snake_case 的 key 就写 `json:"author_id"` tag；③ 指针或 omitempty 用来区分"没传"和"传了零值"——本项目 Done bool 不传即为 false，正好符合语义。

5. 本周项目核心代码：标准库 HTTP 待办服务

把 Day 3 的 Load/Save 与 Day 4 的 TodoRepository（含 MemRepo / FileRepo、ErrNotFound、ErrEmptyTitle）放进同一个 package main，再写下面这个 server.go，项目就齐了。组装时注意：三处重复声明的 Todo 和哨兵错误各只保留一份（以 Day 4 的为准），Day 4 里的 demo 和它自己的 main 要删掉，一个包只能有一个 main()。handler 只依赖接口：明天想换 MySQL，只改仓储实现，这里一行不动。

server.go（与 Day 3/4 的代码同属 package main）package main

import (
    "encoding/json"
    "errors"
    "fmt"
    "log"
    "net/http"
    "strconv"
    "time"
)

const dataFile = "todos.json"
var (
    ErrBadID   = errors.New("id must be a number")       // 本文件新增的两个哨兵，都翻译成 400
    ErrBadJSON = errors.New("body is not valid JSON")
)
// server 只持有一个接口：List / Get / Create / Complete / Delete 全在接口里
type server struct { repo TodoRepository }

func writeJSON(w http.ResponseWriter, status int, v any) {
    w.Header().Set("Content-Type", "application/json; charset=utf-8")
    w.WriteHeader(status)
    if err := json.NewEncoder(w).Encode(v); err != nil { log.Println("encode:", err) }
}

// fail：把 Day 4 的错误链翻译成状态码——验收要的 400 / 404 / 500 全在这一段
func (s *server) fail(w http.ResponseWriter, err error) {
    switch {
    case errors.Is(err, ErrEmptyTitle), errors.Is(err, ErrBadID), errors.Is(err, ErrBadJSON):
        writeJSON(w, http.StatusBadRequest, map[string]string{"error": err.Error()})
    case errors.Is(err, ErrNotFound):
        writeJSON(w, http.StatusNotFound, map[string]string{"error": "待办不存在"})
    default:
        log.Println("internal:", err)      // 500 要把真实原因写日志，只给客户端一句人话
        writeJSON(w, http.StatusInternalServerError, map[string]string{"error": "服务内部错误"})
    }
}

func (s *server) health(w http.ResponseWriter, r *http.Request) {
    writeJSON(w, http.StatusOK, map[string]any{"status": "ok", "time": time.Now().Format(time.RFC3339)})
}

func (s *server) listTodos(w http.ResponseWriter, r *http.Request) {
    todos, err := s.repo.List()
    if err != nil { s.fail(w, err); return }
    writeJSON(w, http.StatusOK, todos)    // slice 编码成 JSON 数组；空列表是 [] 而不是 null
}

func (s *server) getTodo(w http.ResponseWriter, r *http.Request) {
    id, err := strconv.Atoi(r.PathValue("id"))
    if err != nil { s.fail(w, ErrBadID); return }
    t, err := s.repo.Get(id)
    if err != nil { s.fail(w, err); return }
    writeJSON(w, http.StatusOK, t)
}

func (s *server) createTodo(w http.ResponseWriter, r *http.Request) {
    var in struct { Title string `json:"title"` }
    if err := json.NewDecoder(r.Body).Decode(&in); err != nil {
        s.fail(w, fmt.Errorf("decode: %w", ErrBadJSON)); return // 坏 JSON 也是客户端的错 -> 400
    }
    t, err := s.repo.Create(in.Title)     // 仓储内部会落盘，接口自己返回错误
    if err != nil { s.fail(w, err); return }
    w.Header().Set("Location", "/todos/"+strconv.Itoa(t.ID))
    writeJSON(w, http.StatusCreated, t)   // 201 + Location：新建资源的标准响应
}

func (s *server) completeTodo(w http.ResponseWriter, r *http.Request) {
    id, err := strconv.Atoi(r.PathValue("id"))
    if err != nil { s.fail(w, ErrBadID); return }
    t, err := s.repo.Complete(id)
    if err != nil { s.fail(w, err); return }
    writeJSON(w, http.StatusOK, t)
}

func (s *server) deleteTodo(w http.ResponseWriter, r *http.Request) {
    id, err := strconv.Atoi(r.PathValue("id"))
    if err != nil { s.fail(w, ErrBadID); return }
    if err := s.repo.Delete(id); err != nil { s.fail(w, err); return }
    w.WriteHeader(http.StatusNoContent)   // 204：成功但没有 body，别再 Write
}

func main() {
    repo, err := NewFileRepo(dataFile)    // Day 4 练习 3 的文件仓储（内部用 Day 3 的 Load/Save）
    if err != nil { log.Fatal("启动失败:", err) }
    s := &server{repo: repo}

    mux := http.NewServeMux()
    mux.HandleFunc("GET /health", s.health)
    mux.HandleFunc("GET /todos", s.listTodos)
    mux.HandleFunc("POST /todos", s.createTodo)
    mux.HandleFunc("GET /todos/{id}", s.getTodo)
    mux.HandleFunc("PATCH /todos/{id}", s.completeTodo)
    mux.HandleFunc("DELETE /todos/{id}", s.deleteTodo)

    // 最简日志中间件：http.Handler 是接口，包一层就能在处理前后加动作
    logged := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        start := time.Now()
        mux.ServeHTTP(w, r)               // 交给真正的路由
        log.Printf("%s %s -> %s", r.Method, r.URL.Path, time.Since(start))
    })

    srv := &http.Server{Addr: ":8080", Handler: logged, ReadHeaderTimeout: 5 * time.Second}
    log.Println("待办服务已启动: http://localhost:8080")
    log.Fatal(srv.ListenAndServe())       // 一直阻塞，Ctrl+C 退出；返回错误说明服务挂了
}
shell：验收命令（另开一个终端执行）$ go run .                                 # 或 go run ./cmd/server，看到"已启动"即可
$ curl -s localhost:8080/health            # {"status":"ok","time":"..."} 200
$ curl -si -X POST localhost:8080/todos -d '{"title":"学习Go"}' | head -n 1  # 201 Created

$ curl -si localhost:8080/todos/999 | head -n 1     # 404 Not Found
$ curl -si -X POST localhost:8080/todos -d '{bad json' | head -n 1  # 400 Bad Request
$ curl -si -X PATCH localhost:8080/todos/1 | head -n 1   # 200，done 已变 true

练习 1：最小的 /health 服务（20 分钟）

不抄讲义，自己从零写一个只监听 8080、只有一个 GET /health 的服务，返回 {"status":"ok"} 和 Content-Type: application/json。然后用 curl -v 检查：状态行是不是 200 OK、响应头有没有 Content-Type、换一个不存在的路径（/healt）服务器返回什么。

answer.gopackage main

import ("log"; "net/http")

func main() {
    mux := http.NewServeMux()
    mux.HandleFunc("GET /health", func(w http.ResponseWriter, r *http.Request) {
        w.Header().Set("Content-Type", "application/json; charset=utf-8")
        w.WriteHeader(http.StatusOK)
        w.Write([]byte(`{"status":"ok"}`))
    })
    log.Fatal(http.ListenAndServe(":8080", mux))
}

观察点：没注册的路径由 ServeMux 兜底返回 404 page not found（纯文本）。第 2 周会把它换成统一 JSON 响应。

练习 2：POST 收发 JSON 并做校验（25 分钟）

加一个 POST /echo：请求体形如 {"name":"ada","age":30}，服务端解析后原样返回并附加一个字段 "hello":"hi ada"。要求：① 坏 JSON → 400；② name 为空 → 400；③ 正常 → 200。注意每一步都要 return。

answer.go（另需在 main 里注册 POST /echo）func echo(w http.ResponseWriter, r *http.Request) {
    var in struct {
        Name string `json:"name"`
        Age  int    `json:"age"`
    }
    if err := json.NewDecoder(r.Body).Decode(&in); err != nil {
        writeJSON(w, http.StatusBadRequest, map[string]string{"error": "bad json"})
        return
    }
    if in.Name == "" {
        writeJSON(w, http.StatusBadRequest, map[string]string{"error": "name 不能为空"})
        return
    }
    writeJSON(w, http.StatusOK, map[string]any{"name": in.Name, "age": in.Age,
        "hello": "hi " + in.Name})
}
练习 3：路径参数与状态码四连（25 分钟）

实现 GET /todos/{id}：id 不是数字返回 400，数字合法但没有这条返回 404，存在返回 200 + JSON。再用 curl 逐一验证四种情况：正常 200、不存在 404、/todos/abc 得 400、对 /todos 用 DELETE 方法（只注册了 GET/POST）得 405。

answer.gofunc (s *server) getTodo(w http.ResponseWriter, r *http.Request) {
    raw := r.PathValue("id")            // 拿到的一律是 string
    id, err := strconv.Atoi(raw)
    if err != nil {                     // "/todos/abc"：客户端写错了
        writeJSON(w, http.StatusBadRequest, map[string]string{"error": "id 必须是数字: "+raw})
        return
    }
    t, err := s.repo.Get(id)
    if err != nil {                     // 数字合法但没有这条：ErrNotFound -> 404
        s.fail(w, err)
        return
    }
    writeJSON(w, http.StatusOK, t)
}

常见坑（新手 100% 会踩）

坑现象正确姿势
先 Write 再设头Content-Type 永远是 text/plain，头设置被丢弃w.Header().Set → WriteHeader → 写 body，顺序不能换
写完响应不 return日志出现 superfluous WriteHeader call，body 里两个 JSON 拼在一起每个失败分支写完后立刻 return
204 还写 body客户端解析出错、连接行为诡异204 只 WriteHeader，不写任何字节
手写字符串切路径strings.Split(r.URL.Path, "/") 一旦加层级就崩用 Go 1.22 pattern GET /todos/{id} + r.PathValue
JSON 字段小写开头Decode 后字段全是零值，Encode 出来是 {}导出字段 + `json:"snake_case"` tag
500 把内部错误原文吐给客户端泄漏路径 / SQL / 依赖版本，前端也看不懂日志里存详情，响应里给一句人话
不检查 ListenAndServe 返回值端口被占，程序"看起来在跑"其实秒退log.Fatal 或自己处理，别把 error 丢了

今日名词卡

术语一句话解释
报文（message）一次 HTTP 问答的文本格式：请求行/头/体，状态行/头/体
幂等（idempotent）同一请求执行一次和执行 N 次，服务器状态一样：GET/PUT/DELETE 幂等，POST 不幂等
RESTURL 表示资源（名词）、方法表示动作（动词）、状态码表达结果的接口风格
http.Handler只有一个方法 ServeHTTP(ResponseWriter, *Request) 的接口，万物皆处理器
ServeMux路由器：按"方法 + 路径 pattern"找到 Handler，没匹配上返回 404
ResponseWriter响应对象的写接口：设头、写状态码、写 body，只能按顺序往前用
中间件雏形包一层 Handler，在调用真实路由前后加日志/计时，第 2 周正式展开
