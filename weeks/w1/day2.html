结构体与方法

昨天你写了函数和变量，今天要把它们组织成数据模型。后端开发的日常就是：定义一个 struct（用户、文章、订单），给它挂几个方法，然后在 HTTP handler 和数据库之间搬运这些结构体。Go 没有 class、没有 extends、没有 this——它用结构体 + 方法 + 组合三件套替代了整套面向对象语法。今天的 User/Article 练习，就是第 2 周 CRUD API 的数据模型雏形。

课前须知：三句话换掉你的 JS 直觉

1. struct 是值类型，JS 的 object 是引用类型。Go 里 b := a（a 是 struct）会完整复制一份，改 b 不会影响 a。这是今天最容易翻车的地方。

2. 方法和数据是分开写的。没有 class User { sayHi() {} }，Go 先写 struct，再在外面写 func (u User) SayHi() {}。

3. 首字母大小写 = 公开/私有。Go 没有 public/private/export 关键字，字段名 Name 对外可见，name 只在包内可见（第 4 天讲包时会反复用到）。

知识讲义

1. struct 定义与字段

结构体把一组不同类型的字段打包成一个具名类型。Go 没有默认值也没有构造函数语法糖，声明后每个字段都是自己的零值：

d2s3/model.gopackage main

import "fmt"

// 字段名大写开头 = 对外可见（导出）；反引号里的是 json tag，§6 专门讲，先照抄
type User struct {
    ID     int    `json:"id"`
    Name   string `json:"name"`
    Email  string `json:"email"`
    Age    int    `json:"age"`
    Active bool   `json:"active"`
}

四种常用初始化写法（推荐永远用带字段名的方式，顺序写错编译器抓不到）：

d2s3/model.go（片段，接上面的 type User）func initDemo() {
    // ① 字段名（推荐）：没写的字段取零值
    u1 := User{ID: 1, Name: "小明", Active: true}

    // ② 按顺序全量赋值：加字段时会全线崩，慎用
    u2 := User{2, "小红", "hong@ex.com", 20, true}

    // ③ 零值 struct：声明即可用，字段全为 0/""/false
    var u3 User

    // ④ 直接拿指针，后端传"引用"最常用
    u4 := &User{ID: 4, Name: "小刚"}

    u1.Age = 18  // 导出字段可读写
    fmt.Println(u1.Name, u1.Age, u2.Email, u3, u4)
}
shell：等 §3 那份 d2s3/main.go 写好后，把它的 func main 临时改成 main() { initDemo() } 再跑（§2 的 valueTypeDemo 同理；一个目录始终只有一个 main）$ cd d2s3 && go run .
小明 18 hong@ex.com {0   0 false} &{4 小刚  0 false}

JS 的 const u = { } 加字段靠 u.xxx = 1 随意扩展；Go 的 struct 字段在类型定义时就写死了，运行时不能新增字段。想要"动态键值对"，那是第 3 天的 map。

结构体字面量的闭括号 } 不要单独另起一行后接其他语句（Go 会在行尾自动补分号）；写完让编辑器 gofmt 格式化即可。

2. struct 是值类型：赋值、比较、指针

d2s3/model.go（片段，继续接在 initDemo 下面）func valueTypeDemo() {
    a := User{ID: 1, Name: "A", Age: 20}
    b := a            // 完整复制一份！不是引用
    b.Name = "B"
    fmt.Println(a.Name, b.Name) // A B —— a 完全没变

    p := &a           // p 指向 a
    p.Age = 99       // 通过指针改，a 真的变了（Go 自动解引用）
    fmt.Println(a.Age) // 99

    // 字段全部可比时，== 逐字段比较（含 slice/map/func 字段则不可比）
    fmt.Println(a == b) // false
}

// 传参同样是拷贝：这个函数改不到调用方的 struct
func bumpCopy(u User)  { u.Age++ }
// 想改动调用方，必须传指针
func bumpPtr(u *User) { u.Age++ }

经验法则：方法要修改 struct，或 struct 比较大，就传 *T。Go 没有 C++ 的引用参数语法，一切靠传指针（等价于拷贝一个 8 字节地址）。

3. 方法：给类型挂函数

方法是"带接收者（receiver）的函数"，接收者写在函数名前面：方法属于 (u User) 这个类型，不属于某个对象实例。下面这份是完整的 d2s3/main.go（type User 已在同目录的 model.go 里，同包直接拿来用，不要 import 自己）：

d2s3/main.go（完整可跑）package main

import "fmt"

type Article struct {
    ID        int
    Title     string
    Content   string
    Author    User
    Tags      []string
    Views     int
    Published bool
}

// 普通方法：只读字段
func (a Article) Summary() string {
    return fmt.Sprintf("《%s》 by %s (%d 标签)", a.Title, a.Author.Name, len(a.Tags))
}

// 指针方法：修改字段并返回自己，方便链式调用
func (a *Article) Publish() *Article {
    a.Published = true
    return a
}

func (a *Article) AddViews(n int) *Article {
    a.Views += n
    return a
}

func (a Article) IsDraft() bool { return !a.Published }

func main() {
    art := Article{ID: 1, Title: "Go 入门", Author: User{Name: "小明"}, Tags: []string{"go", "web"}}
    fmt.Println(art.Summary())

    // art 是可寻址的变量，Go 自动把 art.Publish() 变成 (&art).Publish()
    art.Publish().AddViews(10).AddViews(5)
    fmt.Println("浏览量:", art.Views, "草稿?", art.IsDraft())
}
shell$ cd d2s3 && go run .
《Go 入门》 by 小明 (2 标签)
浏览量: 15 草稿? false

对比 JS：① 方法不写在 class 里，而是"类型 + 方法"分离；② 没有 this，接收者名字（这里叫 a）完全由你定，同类方法请保持一致；③ 调用方不需要 bind，方法值 f := art.Summary 也是合法的，但今天不必深究。

同一个类型的所有方法，接收者风格要统一。别一半 (a Article) 一半 (a *Article)：go vet 会提示，而且混合后很容易出现"改了个拷贝、调用方没变"的隐蔽 bug。

4. 值接收者 vs 指针接收者（今天最重要的一节）

写法方法里拿到的是能改原对象每次调用开销典型场景
func (u User) X()一份拷贝否拷贝整个 struct小 struct 的只读计算、格式化输出
func (u *User) X()地址是只拷贝一个指针（8 字节）修改字段、大 struct、含 sync.Mutex

表里那个 sync.Mutex：第 5 周正式教，今天只需要知道它是防止多个人同时改同一份数据的"排队锁"（同一时刻只让一个改写者进去，其他人排队等）。含锁的 struct 一旦被值拷贝，锁也跟着被复制一份，排队就失效了——这就是"含 mutex 的类型只能有指针方法"的原因。

d2s4/main.go（完整可跑）package main

import "fmt"

type Counter struct {
    Count int
    Name  string
}

// 陷阱版：改的是拷贝，调用方永远看不到变化
func (c Counter) IncBad()  { c.Count++ }

// 正确版：改原对象
func (c *Counter) IncGood() { c.Count++ }

func (c Counter) String() string { // fmt.Stringer 接口，Day4 细讲
    return fmt.Sprintf("%s=%d", c.Name, c.Count)
}

func main() {
    c := Counter{Name: "点击量"}

    c.IncBad()
    fmt.Println("IncBad 之后:", c.Count)  // 0  ← 白改了

    c.IncGood()
    c.IncGood()
    fmt.Println("IncGood 之后:", c.Count) // 2

    // 注意：函数收到值类型时，指针方法带来的修改也随之丢失
    doubleIt(c)
    fmt.Println("doubleIt 之后:", c.Count) // 仍是 2

    fmt.Println(c) // 点击量=2 —— fmt 自动调用了 String()
}

func doubleIt(c Counter) { c.Count *= 2 } // 又是拷贝
shell$ cd d2s4 && go run .
IncBad 之后: 0
IncGood 之后: 2
doubleIt 之后: 2
点击量=2

三条选择规则，记住就够了：

  • 方法要修改接收者，或 struct 字段多/含 slice+map 混合 → 用 *T；
  • struct 很小且方法纯读 → 值接收者 T，能让并发读更安全（拷贝隔离）；
  • 拿不准就用 *T，并保持该类型所有方法一致。后端服务里的 model 基本全是 *T。

指针可以是 nil：对 nil 指针调用方法不会立刻 panic，方法体内访问字段才 panic（排查 500 错误时会遇到）。

5. 组合替代继承：嵌入（embedding）

Go 没有 extends。它提供"匿名嵌入"：把一个类型作为字段写进去（只写类型名不写字段名），于是内层类型的字段和方法会被"提升"到外层，看起来像继承，本质是转发。

d2s5/main.go（完整可跑）package main

import "fmt"

type Address struct {
    City   string
    Street string
    Zip    string
}

func (a Address) FullAddress() string { return a.City + "市" + a.Street + "(" + a.Zip + ")" }

type Contact struct {
    Email string
    Phone string
}

func (c Contact) BestWayToReach() string {
    if c.Phone != "" {
        return "打电话 " + c.Phone
    }
    return "发邮件 " + c.Email
}

// 没有继承，只有"我里外含有这两块能力"
type Customer struct {
    Address  // 嵌入：字段名即类型名
    Contact  // 嵌入：Customer 自动获得两边的字段与方法
    Name    string
    Level   int
}

func main() {
    cus := Customer{
        Address: Address{City: "杭州", Street: "文三路", Zip: "310000"},
        Contact: Contact{Email: "a@ex.com", Phone: "138"},
        Name:    "大客户",
        Level:   3,
    }

    fmt.Println(cus.FullAddress()) // 提升方法，等价于 cus.Address.FullAddress()
    fmt.Println(cus.City)          // 提升字段，等价于 cus.Address.City
    fmt.Println(cus.BestWayToReach()) // Contact 的方法被提升，直接可用

    cus.Street = "文三路 100 号" // 提升字段可读写
    fmt.Println(cus.Name, cus.Level, cus.Address.FullAddress())
}
shell$ cd d2s5 && go run .
杭州市文三路(310000)
杭州
打电话 138
大客户 3 杭州市文三路 100 号(310000)

两个嵌入类型里有同名字段或方法时，编译器不会猜：外层自己定义的优先级最高；同层的两个嵌入类型同名则报 ambiguous selector，必须写全路径 cus.Contact.BestWayToReach()。

JS 的 class B extends A 同时继承"数据形状"和"行为"，且父类一改子类跟着变，是后端大坑（脆弱的基类问题）。Go 的嵌入是显式组合：你只声明"我需要什么能力"，没有隐式的 super、没有构造函数链、没有抽象基类。

6. 预告：struct tag（明天 JSON 的关键）

结构体字段后面反引号里的字符串叫 tag，是包名到字段的元数据。encoding/json 用它决定 JSON 键名，Day 3/Day 5 全靠它（下面代码里每对反引号就是 tag 本体）：

d2s6/main.go（完整可跑）package main

import (
    "encoding/json"
    "fmt"
)

type Todo struct {
    ID       int    `json:"id"`
    Title    string `json:"title"`
    Done     bool   `json:"done"`
    Internal string `json:"-"`        // 永远不序列化
    Comment  string `json:"comment,omitempty"` // 零值时省略
}

func tagDemo() {
    t := Todo{ID: 1, Title: "学结构体"}
    b, err := json.Marshal(t)
    if err != nil {
        fmt.Println("序列化失败:", err) // 结构体几乎不会失败，但 err 必须处理
        return
    }
    fmt.Println(string(b))
}

func main() { tagDemo() }
shell$ cd d2s6 && go run .
{"id":1,"title":"学结构体","done":false}

json.Marshal(t) 首次出现，两句话讲清：① 它把 Go 值转成 JSON 字节，等价于 JS 的 JSON.stringify，反方向叫 json.Unmarshal(b, &x)（≈JSON.parse，Day 3 正式用）；② 返回值是 ([]byte, error) 两个——[]byte 是字节切片（不是 string，所以要 string(b) 转一下才能打印），err 照样必须当场判。

先照抄语法即可（这份文件已经带你写好了 import "encoding/json"）。字段不写 tag 时 JSON 键名就是字段原名（Name 而不是 name），前端会骂人——所以 tag 必写。

这里这份 Todo 只为演示 tag（Internal / Comment 两个字段是编出来的）。本周正式模型是 Day 3 §6 / Day 4 model.go 里那一份：Todo{ ID int; Title string; Done bool; CreatedAt string }，四个字段配四个 tag，后面所有页面都用它，别再往正式模型里加字段。

练习 1：定义 User 与 Article（35 分钟）

要求：① User 含 ID/Name/Email/Articles 字段/Active；② Article 含 ID/Title/Content/Author(User)/Tags([]string)/Views/Published；③ 写方法 Intro() string、IsVisible() bool（已发布且作者 Active 才可见）；④ main 里造 2 个用户 3 篇文章并打印。

d2ex1/main.go（完整可跑）package main

import "fmt"

type User struct {
    ID       int
    Name     string
    Email    string
    Active   bool
    Articles []*Article // 存指针：避免拷贝，也方便后续直接改文章
}

type Article struct {
    ID        int
    Title     string
    Content   string
    Author    User
    Tags      []string
    Views     int
    Published bool
}

func (a Article) Intro() string {
    return fmt.Sprintf("#%d %s｜作者 %s｜标签 %v", a.ID, a.Title, a.Author.Name, a.Tags)
}

func (a Article) IsVisible() bool { return a.Published && a.Author.Active }

func main() {
    u1 := User{ID: 1, Name: "小明", Email: "ming@ex.com", Active: true}
    u2 := User{ID: 2, Name: "被封号的人", Active: false}

    a1 := &Article{ID: 1, Title: "Go 结构体心得", Author: u1, Tags: []string{"go", "base"}, Published: true}
    a2 := &Article{ID: 2, Title: "草稿：指针接收者", Author: u1, Tags: []string{"go"}}
    a3 := &Article{ID: 3, Title: "看不见的文章", Author: u2, Published: true}

    for _, a := range []*Article{a1, a2, a3} { // range 拿「下标 + 元素」，Day 1 §5 学过；下标不要就写 _
        fmt.Println(a.Intro(), "可见:", a.IsVisible())
    }
}

练习 2：值接收者 vs 指针接收者实验（25 分钟）

给 Article 加两个方法：值接收者 ReadingTime() int（每 300 字符算 1 分钟，向上取整，最少 1），指针接收者 Visit() 和 Unpublish()。然后在 main 里分别用值变量、指针变量、把方法赋给变量三种方式调用，观察是否报错、修改是否生效。

d2ex1/main.go（片段：接在练习 1 的文件里，把它的 main 换成 receiverTest()）func (a Article) ReadingTime() int {
    n := len(a.Content)
    if n == 0 {
        return 1
    }
    return (n + 299) / 300 // 整数向上取整技巧
}

func (a *Article) Visit()      { a.Views++ }
func (a *Article) Unpublish() { a.Published = false }

func receiverTest() {
    var art Article = Article{Title: "t"}
    art.Visit()             // OK：art 可寻址，编译器自动取 &art
    fmt.Println(art.Views)  // 1

    // 临时值不可寻址 —— 下面这行会编译失败，注释掉先跑通
    // Article{Title: "tmp"}.Visit()      // cannot call pointer method on composite literal
    Article{Title: "tmp"}.ReadingTime() // 值接收者 OK

    s := []Article{{Title: "s"}}
    s[0].Visit()            // OK：切片元素可寻址
    // map 的 value 不可寻址：m["k"].Visit() 编译失败，所以 map 要存 *Article
}

跑法：把练习 1 的 main() 换成 func main() { receiverTest() }，只打印一行 1；再依次把注释里的两行"不可寻址"写法取消注释，看编译器怎么骂你。

练习 3：用组合给模型加能力（25 分钟）

定义 Base（含 ID int、CreatedAt string，方法 Key() string）、SoftDeletable（含 DeletedAt string，方法 IsDeleted() bool）。用嵌入得到 User、Article，两者都免费获得 Key() 与 IsDeleted()。再写函数 printKey(k interface{ Key() string })，把 User、Article 都传进去（这是 Day 4 接口的开胃菜）。

本题的 User/Article 和练习 1 同名，必须放在新目录 d2ex3/ 里跑，否则报 User redeclared in this block（见页首「今天的文件怎么放」）。

d2ex3/main.go（完整可跑）package main

import "fmt"

type Base struct {
    ID        int
    CreatedAt string
}

func (b Base) Key() string { return fmt.Sprintf("#%d@%s", b.ID, b.CreatedAt) }

type SoftDeletable struct { DeletedAt string }

func (s SoftDeletable) IsDeleted() bool { return s.DeletedAt != "" }

type User struct    { Base; SoftDeletable; Name string }
type Article struct { Base; SoftDeletable; Title string }

// 只要求"有 Key 方法"，User/Article 都能传进来 —— Day 4 接口预告
func printKey(k interface{ Key() string }) { fmt.Println(k.Key()) }

func main() {
    u := User{Base: Base{ID: 1, CreatedAt: "2026-09-21"}, Name: "小明"}
    a := Article{Base: Base{ID: 9, CreatedAt: "2026-09-22"}, Title: "组合"}
    printKey(u)
    printKey(a)
    fmt.Println(u.IsDeleted(), a.IsDeleted()) // false false
}

今日名词卡

术语一句话解释
struct（结构体）把固定的一组命名字段打包成的具名类型，字段类型编译期确定
值类型 / 引用语义Go 中 struct、数组是值类型（赋值即拷贝）；slice、map、指针、channel 内部带引用
方法（method）带接收者的函数，语法 func (r T) Name()，方法属于类型而非实例；接收者 T 拿拷贝、*T 拿地址
可寻址（addressable）变量、切片元素、结构体字段可寻址；map 元素、函数返回值、常量不可，故无法调用指针方法
嵌入 / 组合匿名嵌入字段，内层类型的字段与方法被"提升"到外层，Go 用它替代继承；无 super、无菱形问题
rangefor i, v := range xs 一次给「下标 + 元素」，不要的用 _ 丢弃；Day 1 §5 教的三种写法今天开始天天用
json tag字段后面反引号里的元数据，encoding/json 靠它决定键名；`json:"-"` 永不输出，,omitempty 零值时省略
