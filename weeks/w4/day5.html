单元测试与接口测试

前四天你把认证、配置、日志都搭好了，但每次改动还是靠手动 curl 回归？今天上自动化测试：纯函数用表驱动单测，HTTP 接口用 httptest 不打网络直接测。三件事收尾——把 service 从数据库上拽下来单测、把第 2 天欠的「谁能动这篇文章」补成完整的 Delete 并写进权限矩阵、再交一份 workflow 给 GitHub Actions。这是第 4 周工程化的收官拼图，也是第 5 周「并发」的地基——那一周要靠 -race 抓数据竞争，前提是你有一套三秒就能跑完的回归网。

课前须知：给 JS 开发者的两句话

1. 没有独立测试框架。testing 是标准库、go test 是子命令：测试文件放同包下、命名 xxx_test.go，go test 自动发现——不需要装 jest/vitest 三件套，也不会有「你用的哪个 runner」的争论。

2. 断言就是 if。Go 官方没有 expect(x).toBe(y)，失败就调 t.Errorf；社区有 testify 的 require.Equal 可用（本课示例保持零依赖）。

2. 表驱动测试：Go 社区的它 = 你的 describe.each

先给第 1 天写的密码强度校验（internal/service/auth.go 里的 passwordStrong）补一个纯函数单测——它不碰数据库、不碰网络，是最好下手的靶子：

internal/service/auth_test.gopackage service

import testing

// 表驱动：一张切片描述所有用例，加用例=加一行，不复制粘贴断言
func TestPasswordStrong(t *testing.T) {
    cases := []struct {
        name string
        pass string
        want bool
    }{
        {"常规强密码", "goodpass123", true},
        {"太短", "abc1", false},
        {"无数字", "abcdefghij", false},
        {"无字母", "12345678", false},
        {"空串", "", false},
    }
    for, tc := range cases {
        t.Run(tc.name, func(t *testing.T) {     // 子测试：失败时精确到用例名
            if got := passwordStrong(tc.pass); got != tc.want {
                t.Errorf("passwordStrong(%q) = %v, want %v", tc.pass, got, tc.want)
            }
        })
    }
}

报错格式 got ... , want ... 是 Go 测试的礼仪：让失败信息不用看代码就知道差在哪。表驱动 ≈ Jest 的 it.each，但它是纯语言特性（就是个 slice），没有任何魔法。

3. 先把 service 拽下来单测：假仓储（memUserRepo）

第 1 天把 NewAuthService 的第一个参数定成接口而不是 *gorm.DB，回报就在今天：测试里塞一个 map 版的假仓储，不开数据库、不装 sqlite、不起 Docker，几十毫秒把「强度校验 / 唯一冲突 / 防枚举」三条分支全跑一遍。

internal/service/auth_test.go（接在第 2 节的 TestPasswordStrong 后面：同一个文件、同一个 package service）package service

import (
    "errors"
    "testing"

    "goblog/internal/model"
    "goblog/internal/repository"
)

// 两把测试密钥：和 .env 里的真值毫无关系，长度照真实密钥给（各 ≥ 32 字节）
// 注意 access 与 refresh 仍是两个不同的值——测试也要守住双密钥这条纪律
const (
    testAccessSecret  = "unit-test-access-secret-32-bytes-long"
    testRefreshSecret = "unit-test-refresh-secret-32-bytes-long!!"
)

// memUserRepo 是 repository.UserRepository 的 map 实现，只在测试里存在。
// 接口要求的七个方法必须齐全：少写一个，编译器当场拒绝把 *memUserRepo 当 UserRepository 传给 NewAuthService
type memUserRepo struct {
    nextID uint
    rows   map[uint]*model.User
}

func newMemUserRepo() *memUserRepo {
    return &memUserRepo{nextID: 1, rows: map[uint]*model.User{}}
}

func (r *memUserRepo) Create(u model.User) (model.User, error) {
    for _, exist := range r.rows {
        if exist.Username == u.Username {
            // 文案刻意写成 sqlite 那套，好让 service 里的 isDuplicateOn 认得它
            return model.User{}, errors.New("UNIQUE constraint failed: users.username")
        }
        if u.Email != "" && exist.Email == u.Email {
            return model.User{}, errors.New("UNIQUE constraint failed: users.email")
        }
    }
    u.ID = r.nextID                          // 模拟自增主键 + GORM 的 ID 回填
    r.nextID++
    saved := u                               // 存副本：接口是「收值返值」（第 3 周口径），库里的数据和调用方手里那份互不干扰
    r.rows[u.ID] = &saved
    return u, nil
}

func (r *memUserRepo) ByUsername(username string) (model.User, error) {
    for _, u := range r.rows {
        if u.Username == username { return *u, nil }
    }
    return model.User{}, repository.ErrUserNotFound  // 与 gorm 版同一个业务错误：service 分不出真假仓储，这正是分层的目的
}

func (r *memUserRepo) Get(id uint) (model.User, error) {
    if u, ok := r.rows[id]; ok { return *u, nil }
    return model.User{}, repository.ErrUserNotFound
}

// 剩下四个方法本轮测试用不到：panic 占位。将来谁在测试里调到它，报错信息直接告诉你为什么
func (r *memUserRepo) List() ([]model.User, error)                     { panic("List: not used in W4 tests") }
func (r *memUserRepo) Update(u model.User) error                     { panic("Update: not used in W4 tests") }
func (r *memUserRepo) Delete(id uint) error                           { panic("Delete: not used in W4 tests") }
func (r *memUserRepo) ExistsUsername(username string) (bool, error) { panic("ExistsUsername: not used in W4 tests") }

// TestRegister：表驱动，每个子测试一套干净的假库（seed=true 就先塞一个 alice）
func TestRegister(t *testing.T) {
    cases := []struct {
        name     string
        seed     bool
        username string
        password string
        email    string
        wantErr  error
    }{
        {"正常注册", false, "alice", "goodpass123", "alice@example.com", nil},
        {"弱密码被拦", false, "alice", "123", "", ErrWeakPassword},
        {"用户名撞车", true, "alice", "goodpass456", "other@example.com", ErrUsernameTaken},
        {"邮箱撞车", true, "carol", "goodpass789", "alice@example.com", ErrEmailTaken},
    }
    for, tc := range cases {
        t.Run(tc.name, func(t *testing.T) {
            svc := NewAuthService(newMemUserRepo(), testAccessSecret, testRefreshSecret)
            if tc.seed {
                if _, err := svc.Register("alice", "goodpass123", "alice@example.com", "爱丽丝"); err != nil {
                    t.Fatalf("准备数据失败: %v", err)
                }
            }
            _, err := svc.Register(tc.username, tc.password, tc.email, "")
            if !errors.Is(err, tc.wantErr) {   // wantErr 为 nil 时，errors.Is(nil, nil) 返回 true：期望成功就用 nil 表达
                t.Errorf("err = %v, want %v", err, tc.wantErr)
            }
        })
    }
}

// TestLogin：D2 把 Login 的返回值从 uint 换成了 *model.User，这里按 D2 终态断言
func TestLogin(t *testing.T) {
    svc := NewAuthService(newMemUserRepo(), testAccessSecret, testRefreshSecret)
    user, err := svc.Register("alice", "goodpass123", "alice@example.com", "爱丽丝")
    if err != nil { t.Fatalf("准备数据失败: %v", err) }

    got, err := svc.Login("alice", "goodpass123")
    if err != nil { t.Fatalf("正确密码不该失败: %v", err) }
    if got.ID != user.ID { t.Errorf("got.ID = %d, want %d", got.ID, user.ID) }

    // 两条失败路径必须给出同一个错误（防枚举是行为契约，只能靠测试钉住）
    for, tc := range []struct { username, password string }{
        {"alice", "wrongpass1"},   // 用户存在、密码错
        {"nobody", "goodpass123"}, // 用户不存在
    } {
        if _, err := svc.Login(tc.username, tc.password); !errors.Is(err, ErrBadCredential) {
            t.Errorf("Login(%q) err = %v, want ErrBadCredential", tc.username, err)
        }
    }
}

这份文件是「整份替换」第 2 节那个 auth_test.go。一个文件里 package 声明和 import 块只能有一份：把第 2 节那行 "testing" 合并进上面的 import 块，TestPasswordStrong 原样留在本文件顶部即可（它用不到假仓储，但同属一个被测包）。
还有两处同名不冲突要提前知道：本文件和第 4 节的 internal/handler/auth_test.go 文件名相同、也都含一个 TestLogin——它们在两个不同的包里，Go 各管各的；跑 go test ./... 会看到两行 --- PASS: TestLogin，靠上面的 ok goblog/internal/… 区分是谁。

对照 Jest：假仓储 ≈ jest.mock('./repository/user')，但 Go 不需要 mock 框架——接口 + 一个实现它的类型就是 mock。这也是第 3 天 Config 用参数传而不是全局变量的回报：这里 NewAuthService(repo, 密钥A, 密钥B) 三个依赖全是显式递进去的，测试想换哪个就换哪个。

别把假仓储写进 internal/repository 的正式文件里，就让它留在 _test.go：Go 的编译规则是 _test.go 只进测试二进制，go build 出来的生产包里根本没有 memUserRepo 这个类型——放错文件就等于把测试脚手架发布上线。

4. httptest 测 handler：不起端口、不打网络

httptest.NewRecorder() 造一个「假 ResponseWriter」收集 handler 写了什么，请求直接用 engine 喂进去——整个 HTTP 层都在进程内，快且无端口冲突：

internal/handler/auth_test.gopackage handler

import (
    "bytes"
    "encoding/json"
    "io"
    "log/slog"
    "net/http"
    "net/http/httptest"
    "testing"

    "github.com/gin-gonic/gin"
    "gorm.io/driver/sqlite"
    "gorm.io/gorm"

    "goblog/internal/middleware"
    "goblog/internal/model"
    "goblog/internal/pkg/jwtutil"
    "goblog/internal/repository"
    "goblog/internal/service"
)

// 两把测试密钥：和 .env 里的真值毫无关系，长度照真实密钥给（各 ≥ 32 字节），
// access 与 refresh 仍然是两个不同值——测试也守住双密钥这条纪律。
// 第 3 节 service 包里那两个同名常量与这里互不相干：_test.go 只在自己的包内可见，
// 换了包就得重新声明一次，不是「重复定义」错误
const (
    testAccessSecret  = "handler-test-access-secret-32-bytes"
    testRefreshSecret = "handler-test-refresh-secret-32-bytes"
)

// env 把「被测系统 + 造数据的手」一起交到用例手里：
// router 发请求；auth 注册用户（密码哈希在 service 里做，绕过它就测不了登录）；
// db 直接塞文章——第 5 节的权限测试要用
type env struct {
    router *gin.Engine
    auth   *service.AuthService
    db     *gorm.DB
}

// newTestEnv：每个测试起一套自己的「服务」，等价 jest 的 setup 文件
func newTestEnv(t *testing.T) *env {
    t.Helper()                                  // 报错行号指向调用方而不是这里
    gin.SetMode(gin.TestMode)                    // 关掉启动横幅，日志安静

    // 库名取测试名：sqlite 的 cache=shared 含义是「整个进程共享同名内存库」，
    // 若所有用例都写 file::memory: 就会共用同一张 users 表，互相串数据（练习 3 会让你亲眼看到）
    dsn := "file:" + t.Name() + "?mode=memory&cache=shared"
    db, err := gorm.Open(sqlite.Open(dsn), &gorm.Config{})
    if err != nil { t.Fatalf("打开内存 sqlite 失败: %v", err) }
    if err := db.AutoMigrate(&model.User{}, &model.Tag{}, &model.Article{}); err != nil {
        t.Fatalf("迁移失败: %v", err)
    }
    t.Cleanup(func() { if d, e := db.DB(); e == nil { d.Close() } })

    // ↓↓ 装配：构造函数、参数个数、参数顺序和 main.go 完全一致，一层都不能省。
    // 少一层，你测的就是一根和生产不同的接线
    userRepo := repository.NewGormUserRepo(db)
    artRepo  := repository.NewGormArticleRepo(db)
    h        := New(service.NewUserService(userRepo, artRepo), service.NewArticleService(artRepo, userRepo))

    authSvc := service.NewAuthService(userRepo, testAccessSecret, testRefreshSecret)
    // 第 4 天给 NewAuthHandler 加的第 4 个参数在这里补上。
    // 日志指向 io.Discard：测试不读日志，但少了这个参数就编译不过
    logger := slog.New(slog.NewTextHandler(io.Discard, nil))
    authH  := NewAuthHandler(authSvc, testAccessSecret, testRefreshSecret, logger)

    r := gin.New()
    v1 := r.Group("/api/v1")
    pub := v1.Group("/auth")                   // 公开组：注册 / 登录 / 换发
    pub.POST("/register", authH.Register)
    pub.POST("/login", authH.Login)
    pub.POST("/refresh", authH.Refresh)

    // 保护组：中间件必须在注册路由之前挂好（第 2 天第 6 节那个坑，在这里同样会踩）
    priv := v1.Group("", middleware.Auth(testAccessSecret))
    priv.GET("/users/me", authH.Me)
    priv.PUT("/articles/:id", h.ArticleUpdate)
    priv.DELETE("/articles/:id", h.ArticleDelete)
    return &env{router: r, auth: authSvc, db: db}
}

// doJSON 往 engine 里灌一个请求，返回 recorder；token 传空串表示不带 Authorization
func doJSON(e *env, method, path string, body any, token string) *httptest.ResponseRecorder {
    b, _ := json.Marshal(body)
    req := httptest.NewRequest(method, path, bytes.NewBuffer(b))
    req.Header.Set("Content-Type", "application/json")
    if token != "" {
        req.Header.Set("Authorization", "Bearer "+token)
    }
    w := httptest.NewRecorder()
    e.router.ServeHTTP(w, req)                  // 进程内直接调，无需真实端口
    return w
}

// testResp 对齐统一响应结构 {code,message,data}。
// 别把名字缩成 resp：第 5 周教 HTTP 客户端时 resp 全课固定指 *http.Response 变量，
// 同名不同形，跨章节复制粘贴必撞车；test 前缀也顺便标明「这是测试专用的解码壳」
type testResp struct {
    Code    int            `json:"code"`
    Message string         `json:"message"`
    Data    map[string]any `json:"data"`
}

// decode 把 recorder 的 body 解成 testResp：非 JSON 直接 Fatal，把原始 body 打出来
func decode(t *testing.T, w *httptest.ResponseRecorder) testResp {
    t.Helper()
    var got testResp
    if err := json.Unmarshal(w.Body.Bytes(), &got); err != nil {
        t.Fatalf("响应不是合法 JSON: %v, body=%s", err, w.Body.String())
    }
    return got
}

func TestLogin(t *testing.T) {
    e := newTestEnv(t)
    // Arrange：先注册一个用户（直接调 service，不依赖注册接口的测试先通过）
    if _, err := e.auth.Register("alice", "goodpass123", "alice@example.com", "爱丽丝"); err != nil {
        t.Fatalf("准备数据失败: %v", err)
    }

    cases := []struct {
        name       string
        body       any
        wantStatus int
        wantCode   int
    }{
        {"成功登录", gin.H{"username": "alice", "password": "goodpass123"}, http.StatusOK, 0},
        {"密码错误", gin.H{"username": "alice", "password": "wrongpass1"}, http.StatusUnauthorized, 1002},
        {"用户不存在", gin.H{"username": "nobody", "password": "goodpass123"}, http.StatusUnauthorized, 1002},
        {"缺少字段", gin.H{"username": "alice"}, http.StatusBadRequest, 1004},
    }
    for, tc := range cases {
        t.Run(tc.name, func(t *testing.T) {
            w := doJSON(e, http.MethodPost, "/api/v1/auth/login", tc.body, "")

            if w.Code != tc.wantStatus {           // 断言 1：HTTP 状态码
                t.Fatalf("status = %d, want %d (body=%s)", w.Code, tc.wantStatus, w.Body.String())
            }
            got := decode(t, w)                    // 断言 2：解析 body 看业务 code
            if got.Code != tc.wantCode {
                t.Errorf("code = %d, want %d", got.Code, tc.wantCode)
            }
        })
    }

    // 成功路径再单独验一次 data 的形状：登录响应必须同时给出 user / access_token / refresh_token
    // 第 6 周前端就是按这三个键取数的，少一个键就是接口契约被悄悄改坏
    w := doJSON(e, http.MethodPost, "/api/v1/auth/login",
        gin.H{"username": "alice", "password": "goodpass123"}, "")
    got := decode(t, w)
    if u, ok := got.Data["user"].(map[string]any); !ok || u["username"] != "alice" {
        t.Errorf("data.user 里应有 username=alice，实得 %#v", got.Data["user"])
    }
    for, key := range []string{"access_token", "refresh_token"} {
        if s, ok := got.Data[key].(string); !ok || s == "" {
            t.Errorf("data[%q] 应为非空字符串，实得 %#v", key, got.Data[key])
        }
    }
}

上面这组只测到「参数进、响应出」。鉴权中间件是本周验收的灵魂，它也得有测试——而且这里正好能顺手把「密钥分开」这件事测出来：

internal/handler/auth_test.go（接在 TestLogin 后面）func TestAuthMiddleware(t *testing.T) {
    e := newTestEnv(t)
    user, err := e.auth.Register("bob", "goodpass456", "", "小鲍")
    if err != nil { t.Fatalf("准备数据失败: %v", err) }

    access, err := jwtutil.NewAccessToken(testAccessSecret, user.ID)
    refresh, err2 := jwtutil.NewRefreshToken(testRefreshSecret, user.ID)
    if err != nil || err2 != nil { t.Fatalf("签测试 token 失败: %v / %v", err, err2) }

    cases := []struct {
        name       string
        token      string
        wantStatus int
        wantCode   int
    }{
        {"不带 token", "", http.StatusUnauthorized, 1005},
        {"拿 refresh 冒充 access", refresh, http.StatusUnauthorized, 1005},  // 密钥不同 + typ 不符，两道关都得拦住
        {"正常 access", access, http.StatusOK, 0},
    }
    for, tc := range cases {
        t.Run(tc.name, func(t *testing.T) {
            w := doJSON(e, http.MethodGet, "/api/v1/users/me", nil, tc.token)
            if w.Code != tc.wantStatus {
                t.Fatalf("status = %d, want %d (body=%s)", w.Code, tc.wantStatus, w.Body.String())
            }
            if got := decode(t, w); got.Code != tc.wantCode {
                t.Errorf("code = %d, want %d", got.Code, tc.wantCode)
            } else if tc.wantStatus == http.StatusOK {   // 放行时还要确认中间件把 uid 传对了
                u, _ := got.Data["user"].(map[string]any)
                if u["username"] != "bob" {
                    t.Errorf("data.user.username = %v, want bob（c.Set/c.GetUint 类型对不上就会出现这种结果）", u["username"])
                }
            }
        })
    }
}

两个前提先对齐（都是前面几天定下的，别改名）：归属字段是 model.Article 的 UserID uint（第 3 周就有），当前用户是 c.GetUint(middleware.CtxKeyUserID)（中间件 c.Set 进去的就是 uint）——两边同类型，判断就是一行。

internal/service/article.go（在 D2 的 Update 下面补这一段）// Delete 删一篇文章。userID 是中间件放进 context 的当前用户。
// 校验顺序不能反：先确认存在，再确认归属——反过来写的话，
// 「文章不存在」和「不是你的文章」会混成一个 403，前端没法人肉区分
func (s *ArticleService) Delete(id, userID uint) error {
    a, err := s.arts.Get(id)
    if err != nil {
        return err                       // ErrArticleNotFound → handler 返回 404 + 2001
    }
    if a.UserID != userID {
        return ErrNotOwner              // → handler 返回 403 + 1003（D2 定义的那个哨兵）
    }
    return s.arts.Delete(id)          // gorm.Model 带 DeletedAt，仓储层的 Delete 就是软删除
}
internal/handler/article.go（补 ArticleDelete；ArticleUpdate 是 D2 那段，原样留着）// 需要 import："errors"、"net/http"、"strconv"、gin、
// goblog/internal/middleware、goblog/pkg/response、goblog/internal/repository、goblog/internal/service
func (h *Handler) ArticleDelete(c *gin.Context) {
    id, err := strconv.ParseUint(c.Param("id"), 10, 64)
    if err != nil {
        response.Fail(c, http.StatusBadRequest, response.CodeInvalidParam, "id 必须是数字")
        return
    }
    if err := h.arts.Delete(uint(id), c.GetUint(middleware.CtxKeyUserID)); err != nil {
        switch {
        case errors.Is(err, repository.ErrArticleNotFound):
            response.Fail(c, http.StatusNotFound, response.CodeArticleNotFound, "文章不存在")
        case errors.Is(err, service.ErrNotOwner):
            response.Fail(c, http.StatusForbidden, response.CodeForbidden, "只能删除自己的文章")
        default:
            response.Fail(c, http.StatusInternalServerError, response.CodeInternal, "服务器开小差了")
        }
        return
    }
    response.OK(c, gin.H{"id": uint(id)})   // 删除没有内容可回，把被删的 id 还回去方便前端摘除那一行
}

// newArticle 直接往测试库里塞一篇文章并回填 ID。

// accessToken 走真接口登录换 token：顺便把 /auth/login 也回归了一遍
func accessToken(t *testing.T, e *env, username, password string) string {
    t.Helper()
    w := doJSON(e, http.MethodPost, "/api/v1/auth/login",
        gin.H{"username": username, "password": password}, "")
    if w.Code != http.StatusOK {
        t.Fatalf("登录 %s 失败: status=%d body=%s", username, w.Code, w.Body.String())
    }
    tok, _ := decode(t, w).Data["access_token"].(string)
    if tok == "" {
        t.Fatalf("登录响应里没有 access_token，权限用例无法进行")
    }
    return tok
}

// 200 / 403+1003 / 404+2001 / 401+1005 四条分支从此有人守着
func TestArticleOwnerOnly(t *testing.T) {
    e := newTestEnv(t)
    alice, err := e.auth.Register("alice", "goodpass123", "alice@example.com", "爱丽丝")
    if err != nil { t.Fatalf("准备数据失败: %v", err) }
    bob, err := e.auth.Register("bob", "goodpass456", "bob@example.com", "小鲍")
    if err != nil { t.Fatalf("准备数据失败: %v", err) }

    mine := newArticle(t, e, alice.ID, "alice 的文章")
    theirs := newArticle(t, e, bob.ID, "bob 的文章")
    aliceTok := accessToken(t, e, "alice", "goodpass123")

    cases := []struct {
        name       string
        method     string
        path       string
        token      string
        body       any
        wantStatus int
        wantCode   int
    }{
        {"改自己的", http.MethodPut, articleURL(mine.ID), aliceTok, gin.H{"title": "改定了", "content": "x"}, http.StatusOK, 0},
        {"偷改 bob 的", http.MethodPut, articleURL(theirs.ID), aliceTok, gin.H{"title": "偷改", "content": "x"}, http.StatusForbidden, 1003},
        {"改不存在的", http.MethodPut, articleURL(9999), aliceTok, gin.H{"title": "不存在", "content": "x"}, http.StatusNotFound, 2001},
        {"不带 token 改", http.MethodPut, articleURL(mine.ID), "", gin.H{"title": "裸请求", "content": "x"}, http.StatusUnauthorized, 1005},

        {"删完再删", http.MethodDelete, articleURL(mine.ID), aliceTok, nil, http.StatusNotFound, 2001},
        {"删 bob 的", http.MethodDelete, articleURL(theirs.ID), aliceTok, nil, http.StatusForbidden, 1003},
    }
    for, tc := range cases {
        t.Run(tc.name, func(t *testing.T) {
            w := doJSON(e, tc.method, tc.path, tc.body, tc.token)
            if w.Code != tc.wantStatus {
                t.Fatalf("status = %d, want %d (body=%s)", w.Code, tc.wantStatus, w.Body.String())
            }
            if got := decode(t, w); got.Code != tc.wantCode {
                t.Errorf("code = %d, want %d (message=%q)", got.Code, tc.wantCode, got.Message)
            }
        })
    }
}

用例顺序本身就是断言的一部分。「删自己的」排在「不带 token 改」之后、「偷改 bob 的」排在任何删除之前：一旦有人把删除那两行挪到表头，后面的用例会集体从 403 变成 404（文章已经软删除、查不见了）。这不是测试写错了，是它诚实地告诉你「这些用例有共享状态」——真要彻底解耦，就给每个用例单独 newTestEnv(t)，代价是多花几十毫秒。

练习 1：把鉴权与注册打成矩阵（60 分钟，主线）

照讲义第 4 节写通 TestLogin（成功 / 错密码 / 用户不存在 / 缺字段四条）和 TestAuthMiddleware（不带 token / 拿 refresh 冒充 access / 正常 access 三条），全绿为准。再给 POST /api/v1/auth/register 补三条：弱密码 → 400+1004、重复用户名 → 409+1006、重复邮箱 → 409+1006。

参考答案（要点）

登录成功那条额外断言 data["access_token"] 与 data["refresh_token"] 都是非空字符串、data["user"]["username"] == "alice"（第 6 周前端就按这三个键取数，键名被人改了只有测试会喊）；错密码与用户不存在两条都断言 1002 + message 恰为「用户名或密码错误」，这就是把第 1 天「防枚举」那句口头承诺钉成契约；缺字段那条只传 username，期望 400+1004。
注册重复的两条都期望 409 + 1006，但 message 不同：一个是「用户名已存在」，一个是「该邮箱已被注册」——同一个业务码配两句文案，这是本课在第 1 节就定下的取舍。isDuplicateOn（第 1 天）已经同时认 MySQL 的 1062 和 sqlite 的 UNIQUE constraint failed，所以在内存库里这两条用例照样绿；如果你的实现只认 1062，这里就会红，别去改测试期望，改 isDuplicateOn。全绿后跑 go test -cover ./internal/... 记下覆盖率。

练习 3：测试隔离验证（20 分钟）

把 newTestEnv 里的 DSN 从 "file:" + t.Name() + "?mode=memory&cache=shared" 分别改成 "file::memory:?cache=shared"（所有用例同名）和 "test.db"（文件库），各跑两次 go test ./internal/handler，观察用户数是否跨进程残留，说明三种模式差异。

参考答案

file::memory:（不带 cache=shared）每个连接一个独立内存库，同一条 SQL 连接池里换个连接就看不到刚建的表，会随机冒出 no such table: users；file:<名字>?mode=memory&cache=shared 是「进程内所有连接到同一个共享内存库」，名字相同即数据相同——所以把名字写死后，article_test.go 里的 TestArticleOwnerOnly 先注册了 alice，auth_test.go 里的 TestLogin 再注册就撞唯一键：auth_test.go:96: 准备数据失败: 用户名已存在；文件库 test.db 更狠，进程退出数据还在，第二次跑直接全红，测试「自己脏了自己的数据」。三种模式的解法是同一个：库名带上测试名，各占各的库。

练习 4：读覆盖率，再补一条 refresh 用例（25 分钟）

go test -coverprofile=c.out ./... && go tool cover -func=c.out 逐函数看一遍，挑出两个 0.0% 的函数，判断「该补」还是「故意不测」，写一句话说明；然后给 POST /api/v1/auth/refresh 补一条用例（路由在第 4 节的 newTestEnv 里已经注册好了，直接发请求即可）。

参考答案

典型答案一：service.ArticleService.Create 0.0%——故意不测，第 5 节造数据直接用了 db.Create，它归第 3 周的接口管；写清楚理由比刷高数字重要。典型答案二：handler.AuthHandler.Refresh 0.0%——该补，它是双密钥设计的唯一兑现点。
补法（两条一组才有意义）：拿 access token 当 refresh 传 → 401 + 1005；拿真 refresh token 传 → 200 + 0，且 data 里有 access_token 和 refresh_token（注意 Refresh 不返回 user，第 2 天就这么定的）。签真 refresh 用 jwtutil.NewRefreshToken(testRefreshSecret, user.ID)。
顺带说明一处本周的空白：本项目没有 Logout handler——无状态 JWT 在服务端不存任何东西，「让已签发的 token 立刻作废」这句话无处落地（第 2 天第 7 节那三档讨论，含「refresh 每次换发会签一把新的、但旧的那把照样活满 7 天」这个细节）。本周的登出方案就是「前端删掉本地两把 token + 各自等到期」，所以覆盖率报告里找不到 Logout、也不必去找它——覆盖图里那些 0% 只可能来自 Refresh、User/Article 那些本周没动的第 3 周老代码。

常见坑（新手 100% 会踩）

坑现象正确姿势
测试污染开发库跑一次 test，开发库 users 表多了一排 "alice"，演示数据全乱sqlite 内存库（库名带测试名）或独立的 goblog_test 库 + DSN 单独走 TEST_DB_DSN，别复用 DB_*
函数名不合约定func testLogin(...) 小写开头，go test 报 "no tests to run"必须 TestXxx（Test 后接大写字母）且签名为 (t *testing.T)
用 t.Error 写「必须中止」的断言setup 里 Open 失败继续往下跑，后面 panic 刷屏看不到根因后续步骤无法继续时用 t.Fatalf，仅记录失败用 Errorf
测试之间共享状态单独跑绿，一起跑红（顺序依赖）；报错永远是先注册 alice 的那个测试赢每个测试自己 newTestEnv(t)，内存库名字取 t.Name() 天然隔离；共享同名内存库和 test.db 是两大罪魁
在 handler 测试里打真网络http.Get("localhost:8080...")，忘了起服务就全红，端口还会撞车httptest.NewRecorder + router.ServeHTTP 进程内驱动；真要一个能报给别处的 URL（并发压测那种），是第 5 周总结课用 httptest.NewServer 的场合，本周不碰
只测成功路径覆盖率看着还行，某天把 if a.UserID != userID 重构掉了，接口照样 200，越权三个月没人发现每个 4xx 分支至少一条用例：401/403/404/409 各打一次（第 4、5 节那三张表就是范本）
