单元测试与接口测试

前四天你把认证、配置、日志都搭好了，但每次改动还是靠手动 curl 回归？今天上自动化测试：纯函数用表驱动单测，HTTP 接口用 httptest 不打网络直接测。这是第 4 周工程化的收官拼图，也是第 5 周「测试并发」的地基。

课前须知：给 JS 开发者的两句话

1. 没有独立测试框架。testing 是标准库、go test 是子命令：测试文件放同包下、命名 xxx_test.go，go test 自动发现——不需要装 jest/vitest 三件套，也不会有「你用的哪个 runner」的争论。

2. 断言就是 if。Go 官方没有 expect(x).toBe(y)，失败就调 t.Errorf；社区有 testify 的 require.Equal 可用（本课示例保持零依赖）。

知识讲义

1. go test 机制：对照 Jest 理解

shell$ go test ./...            # 全仓库跑测试，≈ jest 无参数
$ go test ./internal/service -run TestLogin -v   # 指定包/用例名前缀/详细输出，≈ npx jest -t "Login"
$ go test -cover ./...     # 附带覆盖率，≈ jest --coverage
JestGo testing说明
auth.test.jsauth_test.go同目录、以 _test.go 结尾才被视为测试文件
describe + itfunc TestXxx(t *testing.T) + t.Run 子测试函数名必须 Test 开头 + 大写字母，参数必是 *testing.T
expect(a).toEqual(b)if a != b { t.Errorf(...) }t.Error 记失败继续跑；t.Fatal 记失败立即中止本用例
beforeEach/afterEacht.Cleanup(func(){...})Cleanup 注册在创建资源之后，作用域即当前(子)测试
一个 repo 一套 jest config测试与被测代码同包同目录没有 test 文件夹约定，service/ 里既是源码也是测试

2. 表驱动测试：Go 社区的它 = 你的 describe.each

先给昨天写的密码强度校验补一个纯函数单测（无依赖、最好下手）：

internal/service/auth_test.gopackage service

import testing

// 表驱动：一张切片描述所有用例，加用例=加一行，不复制粘贴断言
func TestPasswordStrong(t *testing.T) {
    cases := []struct {
        name string
        pass string
        want bool
    }{
        {"常规强密码", "goodpass123", true},
        {"太短", "abc1", false},
        {"无数字", "abcdefghij", false},
        {"无字母", "12345678", false},
        {"空串", "", false},
    }
    for, tc := range cases {
        t.Run(tc.name, func(t *testing.T) {     // 子测试：失败时精确到用例名
            if got := passwordStrong(tc.pass); got != tc.want {
                t.Errorf("passwordStrong(%q) = %v, want %v", tc.pass, got, tc.want)
            }
        })
    }
}

报错格式 got ... , want ... 是 Go 测试的礼仪：让失败信息不用看代码就知道差在哪。表驱动 ≈ Jest 的 it.each，但它是纯语言特性（就是个 slice），没有任何魔法。

3. httptest 测 handler：不起端口、不打网络

httptest.NewRecorder() 造一个「假 ResponseWriter」收集 handler 写了什么，请求直接用 engine 喂进去——整个 HTTP 层都在进程内，快且无端口冲突：

internal/handler/auth_test.gopackage handler

import (
    "bytes"
    "encoding/json"
    "net/http"
    "net/http/httptest"
    "testing"

    "github.com/gin-gonic/gin"
    "gorm.io/driver/sqlite"
    "gorm.io/gorm"

    "studyblog/internal/model"
    "studyblog/internal/service"
)

// setupTestRouter：每个测试文件自己的"起服务"，等价 jest 的 setup 文件
func setupTestRouter(t *testing.T) (*gin.Engine, *gorm.DB) {
    t.Helper()                                  // 报错行号指向调用方而不是这里
    gin.SetMode(gin.TestMode)                    // 关掉启动横幅，日志安静

    db, err := gorm.Open(sqlite.Open("file::memory:?cache=shared"), &gorm.Config{})
    if err != nil { t.Fatalf("打开内存 sqlite 失败: %v", err) }
    if err := db.AutoMigrate(&model.User{}); err != nil { t.Fatalf("迁移失败: %v", err) }
    t.Cleanup(func() { if d, e := db.DB(); e == nil { d.Close() } })

    svc := service.NewAuthService(db, "test-secret-test-secret-32bytes!")
    h := NewAuthHandler(svc, "test-secret-test-secret-32bytes!")

    r := gin.New()
    r.POST("/auth/register", h.Register)
    r.POST("/auth/login", h.Login)
    return r, db
}

// doJSON 往 engine 里灌一个 JSON 请求，返回 recorder
func doJSON(r *gin.Engine, method, path string, body any) *httptest.ResponseRecorder {
    b, _ := json.Marshal(body)
    req := httptest.NewRequest(method, path, bytes.NewBuffer(b))
    req.Header.Set("Content-Type", "application/json")
    w := httptest.NewRecorder()
    r.ServeHTTP(w, req)                          // 进程内直接调，无需真实端口
    return w
}

type resp struct {                        // 对齐统一响应结构 {code,message,data}
    Code    int            json:"code"
    Message string         json:"message"
    Data    map[string]any json:"data"
}

func TestLogin(t *testing.T) {
    r, db := setupTestRouter(t)
    // Arrange：先注册一个用户（直接走库，不依赖注册接口测试通过）
    if err := service.NewAuthService(db, "test-secret-test-secret-32bytes!").Register("alice", "goodpass123"); err != nil {
        t.Fatalf("准备数据失败: %v", err)
    }

    cases := []struct {
        name       string
        body       any
        wantStatus int
        wantCode   int
    }{
        {"成功登录", gin.H{"username": "alice", "password": "goodpass123"}, http.StatusOK, 0},
        {"密码错误", gin.H{"username": "alice", "password": "wrong"}, http.StatusUnauthorized, 1002},
        {"缺少字段", gin.H{"username": "alice"}, http.StatusBadRequest, 1004},
    }
    for, tc := range cases {
        t.Run(tc.name, func(t *testing.T) {
            w := doJSON(r, http.MethodPost, "/auth/login", tc.body)

            if w.Code != tc.wantStatus {           // 断言 1：HTTP 状态码
                t.Fatalf("status = %d, want %d (body=%s)", w.Code, tc.wantStatus, w.Body.String())
            }
            var got resp                        // 断言 2：解析 body 看业务 code
            if err := json.Unmarshal(w.Body.Bytes(), &got); err != nil {
                t.Fatalf("响应不是合法 JSON: %v, body=%s", err, w.Body.String())
            }
            if got.Code != tc.wantCode {
                t.Errorf("code = %d, want %d", got.Code, tc.wantCode)
            }
        })
    }
}

对照 Jest 里的 supertest：request(app).post('/auth/login').send({...}).expect(401)——Go 版只是把「假响应收集器」(NewRecorder) 和「假请求」(NewRequest) 手动拼起来，思想完全一样：不监听端口，直接驱动 app 对象。

4. 测试数据库：sqlite 内存版 vs MySQL test 库

sqlite 内存版MySQL 专用 test 库
连接串sqlite.Open("file::memory:?cache=shared")，零安装零网络root:pass@tcp(127.0.0.1:3306)/blog_test?...
隔离性✅ 进程内存，天然不碰开发库⚠️ 必须连的是 blog_test，配错一个字符就污染开发数据（今天最大的坑）
方言忠实度❌ 1062 报错文案、AUTO_INCREMENT 行为与 MySQL 有差异，涉及方言的用例可能误报/漏报✅ 和生产同引擎
适用CRUD 逻辑、handler 流程测试（本课程用它）CI 里跑集成测试（CI 起 MySQL 容器很便宜）
shell$ go get gorm.io/driver/sqlite     # 基于 mattn/go-sqlite3，需要本地有 cgo/gcc
$ # 装不动 gcc 的同学可换纯 Go 驱动：go get github.com/glebarez/sqlite（用法相同，import 路径不同）

二选一的底线原则只有一条：测试永远不要连开发/生产库。选 MySQL test 库的话，DSN 必须来自独立的环境变量（如 TEST_DB_DSN），并在测试开头断言库名以 _test 结尾，不满足直接 t.Fatal。

5. 覆盖率与 CI 预告

shell$ go test -cover ./...
ok  studyblog/internal/service   0.412s   coverage: 68.5% of statements
$ go test -coverprofile=c.out ./... && go tool cover -func=c.out | tail -1  # 逐函数看

一句话预告第 5 周：go test ./... 退出码非 0 即失败，把它写进 GitHub Actions 的 workflow，每次 push 自动跑——从此「测试挂了」不再是口口相传而是机器人拦门。

CI 速览（第 5 周细讲）steps:
  - uses: actions/checkout@v4
  - uses: actions/setup-go@v5
    with: { go-version: "1.24" }
  - run: go test -race -cover ./...   # -race 顺带把并发隐患也盯上

覆盖率是仪表盘不是 KPI：别为了凑 90% 去测 getter。优先覆盖的三层——纯逻辑（密码校验、DSN 拼装）、出错分支（401/403/409）、鉴权中间件（本周验收的灵魂）。目标先定 60%，把关键路径罩住。

今日练习

练习 1：为 /auth/login 写 3 个用例（60 分钟，主线）

照讲义第 3 节完成成功 / 错密码 / 格式错三条表驱动用例，全绿为准；再给 /auth/register 补「重复用户名 → 409+1006」一条（用 sqlite 时注意：重复键判定若依赖 1062 文案会失效，把 service 判断抽成 isDuplicateErr(err) 并对 sqlite 的 UNIQUE constraint failed 也返回 true）。

参考答案（要点）

登录成功用例额外断言 got.Data["access_token"] != ""；错密码断言响应 message 恰为「用户名或密码错误」（防把 1001/1002 泄露话术测漏）；格式错只传 username 得 400+1004；重复注册第二次调用返回 409。全绿后跑 go test -cover ./internal/... 记录覆盖率。

练习 2：让一个坏味道暴露（20 分钟）

故意把 handler 里 401 分支的业务码从 1002 改成 1001，跑 go test -run TestLogin -v，读一遍失败输出，再改回来。

参考答案

失败输出应精确到子用例名：--- FAIL: TestLogin/密码错误 ... code = 1001, want 1002——这就是 t.Run 给用例命名的价值，Jest 里 describe/it 文案同理。

练习 3：测试隔离验证（20 分钟）

把 setupTestRouter 里的连接串从 file::memory:?cache=shared 分别改成 :memory: 和 test.db（文件库），各跑两次测试，观察用户数是否跨进程残留，说明三种模式差异。

参考答案

:memory: 每个连接独立内存库（gin 测试够用，但多连接看不到彼此的表）；cache=shared 同进程内共享一个内存库，进程退即销毁；文件 test.db 会持久残留，第二次跑 register 用例直接撞唯一键——测试「自己脏了自己的数据」。

练习 4：覆盖率报告（15 分钟）

go test -coverprofile=c.out ./... && go tool cover -html=c.out 打开浏览器版覆盖图，找出一个 0% 的函数（大概率是 Logout），在 TODO 里记一笔。

常见坑（新手 100% 会踩）

坑现象正确姿势
测试污染开发库跑一次 test，开发库 users 表多了一排 "alice"，演示数据全乱sqlite 内存库或独立的 blog_test 库 + DSN 单独走 TEST_DB_DSN 环境变量
函数名不合约定func testLogin(...) 小写开头，go test 报 "no tests to run"必须 TestXxx（Test 后接大写字母）且签名为 (t *testing.T)
用 t.Error 写「必须中止」的断言setup 里 Open 失败继续往下跑，后面 panic 刷屏看不到根因后续步骤无法继续时用 t.Fatalf，仅记录失败用 Errorf
测试之间共享状态单独跑绿，一起跑红（顺序依赖）每个测试自己 setupTestRouter，内存库天然隔离；共享的 test.db 是罪魁
在 handler 测试里打真网络http.Get("localhost:8080...")，忘了起服务就全红，端口还会撞车httptest.NewRecorder + r.ServeHTTP 进程内驱动；真需要起服务时用 httptest.NewServer

今日名词卡

术语一句话解释
go test内置测试 runner：编译期收集 _test.go，退出码反馈成败，无需任何第三方框架
表驱动（table-driven）用切片声明「输入+期望输出」集合，循环生成子测试，Go 社区标准风格
testing.T每个测试函数的上下文对象：Errorf/Fatalf/Run/Cleanup/Helper 全从它来
httptest.ResponseRecorder实现了 http.ResponseWriter 接口的「录音机」，handler 写什么它存什么
t.Cleanup注册当前（子）测试结束时执行的钩子，对应 afterEach
coverprofile覆盖率原始数据文件，go tool cover 可转 HTML/函数级报告
