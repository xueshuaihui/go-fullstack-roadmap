JWT 双 token 鉴权

昨天登录成功只能拿回一个 user_id，今天要把「登录态」变成服务器可以无状态验证的凭证：JWT。我们直接采用生产级方案——access(15 分钟) + refresh(7 天) 双 token，第 6 周 React 前端的 axios 拦截器就对接今天的 POST /auth/refresh。

课前须知：给 JS 开发者的两句话

1. 服务端 Session vs JWT。Session 是「服务器记账」：登录态存内存/Redis，cookie 里只放个编号；JWT 是「带公章的纸条」：服务器不记任何东西，每次请求验证纸条上的签名即可。水平扩容友好，代价是「签发出去就收不回来」——这也是今天最后讨论 logout 的原因。

2. 你在 npm 里熟的 jwt/jsonwebtoken 库，Go 对应 github.com/golang-jwt/jwt/v5。概念完全一致：sign 签发、verify 校验，只是 v5 的 API 把校验拆成了 ParseWithClaims + 手动断言 Claims 类型。

知识讲义

1. JWT 三段结构：拆一个真 token

JWT 就是 header.payload.signature 三段 base64url 字符串用点连接。下面是一个真实的 HS256 token（签名密钥为 s3cr3t-key-change-me，仅供教学）：

tokeneyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJ1aWQiOjEsInJvbGUiOiJ1c2VyIiwiaWF0IjoxNzU4NjA0ODAwLCJleHAiOjE3NTg2MDU3MDB9.jjWqB0tiZM5DNL1O_fwvj0Gov_5-rAXBmF1M2yMffbU

把前两段各做一次性 base64url 解码，原文立刻现形：

shell$ echo 'eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9' | base64 -D
{"alg":"HS256","typ":"JWT"}                    # header：算法与类型

$ echo 'eyJ1aWQiOjEsInJvbGUiOiJ1c2VyIiwiaWF0IjoxNzU4NjA0ODAwLCJleHAiOjE3NTg2MDU3MDB9' | base64 -D
{"uid":1,"role":"user","iat":1758604800,"exp":1758605700} # payload：claims 声明
段内容作用
header{"alg":"HS256","typ":"JWT"}声明签名算法
payload业务字段 + 标准字段（exp 过期时间戳、iat 签发时间戳、sub、iss 等）承载「谁、什么角色、何时过期」
signatureHMAC-SHA256(header + "." + payload, secret) 再 base64url公章：改一个字签名就对不上

常用标准 Claims 先记四个：exp（过期时间，服务器强制校验）、iat（签发时间，refresh 判断用）、sub（主体标识）、iss(签发者)。今天我们把 userID/role 做成自定义字段。

2. 签名 ≠ 加密

上面你亲手解码了 payload——任何人都能。signature 只保证「不被篡改」（改 "role":"user" 为 "admin" 后没有密钥就重算不出合法签名），不保证不被看见。铁律：payload 里只放 userID、role 这类不敏感标识，绝不放密码、手机号、身份证、支付信息。

推论：JWT 的_SECRET_只有一个作用——签名。泄露 secret 等于攻击者可以任意伪造 admin token，所以它和数据库密码同级对待（明天配置课把它收进 .env）。

3. 签发与解析：golang-jwt/jwt/v5

shell$ go get github.com/golang-jwt/jwt/v5
internal/pkg/jwtutil/jwt.gopackage jwtutil

import (
    "errors"
    "time"

    "github.com/golang-jwt/jwt/v5"
)

type Claims struct {
    UserID int64  json:"uid"
    Role   string json:"role"
    Type   string json:"typ" // "access" 或 "refresh"，两种 token 靠它区分
    jwt.RegisteredClaims      // 内嵌标准字段：exp / iat / sub 全在这
}

const (
    AccessTTL  = 15 * time.Minute
    RefreshTTL = 7 * 24 * time.Hour
)

// sign 通用签发：HS256 + 密钥字节
func Sign(secret string, c Claims) (string, error) {
    return jwt.NewWithClaims(jwt.SigningMethodHS256, c).SignedString([]byte(secret))
}

func NewAccessToken(secret string, userID int64, role string) (string, error) {
    now := time.Now()
    return Sign(secret, Claims{UserID: userID, Role: role, Type: "access",
        RegisteredClaims: jwt.RegisteredClaims{
            IssuedAt:  jwt.NewNumericDate(now),
            ExpiresAt: jwt.NewNumericDate(now.Add(AccessTTL)),
        }})
}

func NewRefreshToken(secret string, userID int64, role string) (string, error) {
    now := time.Now()
    return Sign(secret, Claims{UserID: userID, Role: role, Type: "refresh",
        RegisteredClaims: jwt.RegisteredClaims{
            IssuedAt:  jwt.NewNumericDate(now),
            ExpiresAt: jwt.NewNumericDate(now.Add(RefreshTTL)),
        }})
}

// ErrTokenType 自定义错误：token 本身合法但用途不对（拿 access 当 refresh 用）
var ErrTokenType = errors.New("token 类型不符")

// Parse 校验签名 + exp，并确认 typ 字段符合预期用途
func Parse(secret, tokenStr, wantType string) (Claims, error) {
    var empty Claims
    tok, err := jwt.ParseWithClaims(tokenStr, &empty, func(t *jwt.Token) (any, error) {
        if _, ok := t.Method.(*jwt.SigningMethodHMAC); !ok { // 防算法混淆攻击
            return nil, jwt.ErrTokenSignatureInvalid
        }
        return []byte(secret), nil
    }, jwt.WithValidMethods([]string{"HS256"}))
    if err != nil { // 过期: errors.Is(err, jwt.ErrTokenExpired)
        return empty, err
    }
    if !tok.Valid || empty.Type != wantType {
        return empty, ErrTokenType
    }
    return empty, nil
}

v5 与旧版（v3/v4）最大区别：keyfunc 返回 (any, error)、过期判断用 errors.Is(err, jwt.ErrTokenExpired) 而不是布尔比较。网上大量老教程贴的是 v4 写法，抄过来编译会挂，认准 v5。

4. 登录发双 token + /auth/refresh 换发

internal/handler/auth.go// Login 成功后返回体（替换昨天只回 user_id 的版本）
func (h *AuthHandler) Login(c *gin.Context) {
    var req struct {
        Username string json:"username" binding:"required"
        Password string json:"password" binding:"required"
    }
    if err := c.ShouldBindJSON(&req); err != nil {
        resp.Fail(c, 400, 1004, "参数错误"); return
    }
    user, err := h.svc.Login(req.Username, req.Password) // svc.Login 今天把返回值升级为 (*model.User, error)
    if err != nil { resp.Fail(c, 401, 1002, "用户名或密码错误"); return }

    access, err1 := jwtutil.NewAccessToken(h.secret, user.ID, user.Role)
    refresh, err2 := jwtutil.NewRefreshToken(h.secret, user.ID, user.Role)
    if err1 != nil || err2 != nil { resp.Fail(c, 500, 5000, "签发失败"); return }
    resp.OK(c, 200, gin.H{"access_token": access, "refresh_token": refresh})
}

// Refresh：只接受 refresh token，校验通过换发一对新 token（滚动续期）
func (h *AuthHandler) Refresh(c *gin.Context) {
    var req struct {
        RefreshToken string json:"refresh_token" binding:"required"
    }
    if err := c.ShouldBindJSON(&req); err != nil {
        resp.Fail(c, 400, 1004, "缺少 refresh_token"); return
    }
    claims, err := jwtutil.Parse(h.secret, req.RefreshToken, "refresh")
    if err != nil {
        resp.Fail(c, 401, 1005, "token 无效或已过期，请重新登录"); return
    }
    access, _ := jwtutil.NewAccessToken(h.secret, claims.UserID, claims.Role)
    refresh, _ := jwtutil.NewRefreshToken(h.secret, claims.UserID, claims.Role)
    resp.OK(c, 200, gin.H{"access_token": access, "refresh_token": refresh})
}

为什么要两种 token？access 短命（15 分钟），被截获损失有限；refresh 长命（7 天）但只在 /auth/refresh 一个端点使用、不参与日常 API 调用，暴露面小。前端日常请求只带 access，401 时拿 refresh 静默换发——这就是第 6 周拦截器的完整闭环。

5. 鉴权中间件

internal/middleware/auth.go// import "strings"、"studyblog/internal/pkg/jwtutil"、"github.com/gin-gonic/gin"
func Auth(secret string) gin.HandlerFunc {
    return func(c *gin.Context) {
        raw := c.GetHeader("Authorization")
        const prefix = "Bearer "
        if !strings.HasPrefix(raw, prefix) {       // 缺头 / 不是 Bearer 格式
            c.AbortWithStatusJSON(401, gin.H{"code": 1005, "message": "未登录", "data": nil})
            return                                // ← 这个 return 不能省！
        }
        claims, err := jwtutil.Parse(secret, raw[len(prefix):], "access")
        if err != nil {
            c.AbortWithStatusJSON(401, gin.H{"code": 1005, "message": "token 无效或已过期", "data": nil})
            return
        }
        c.Set("userID", claims.UserID)          // 后续 handler 从这里取当前用户
        c.Set("role", claims.Role)
        c.Next()
    }
}

6. logout：一个诚实的讨论

Session 时代登出 = 删服务器上的记录。JWT 无状态——服务器根本没记，想「让已签发的 token 立刻作废」就必须重新引入状态。三种务实选择：

方案做法代价
纯前端「登出」客户端删掉本地 token，服务端什么都不做token 在有效期内其实还活着；对 15 分钟的 access 通常可接受
黑名单（Redis/内存表）登出时把 access 的 jti、refresh 整串塞进黑名单，存活到原过期时间为止；中间件多查一次重新引入状态与一次存储查询，但粒度可控，生产常用
库内版本戳users 表加 token_version，改密码/全端登出时 +1，校验时比对每请求多一次查询；实现简单，适合中小项目

本项目今天采用第一档 + 说明：POST /auth/logout 只由前端清 token，README 写明「access 剩余有效期内仍可能可用」。等第 5 周学了并发、你有 Redis 经验后再升级黑名单——诚实地记录技术债，比假装安全强。
