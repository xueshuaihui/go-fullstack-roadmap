Docker Compose + MySQL + GORM 入门

前两周的数据都存在内存里，重启就没了。今天开始，数据要落到真实的 MySQL 里：用 Docker Compose 一键起数据库，用 GORM 连上去并自动建表。今天的成功标准很具体——容器重启、电脑重启之后，docker exec 进数据库还能看到你写进去的那行数据。

课前须知：为什么本周先学 Docker

安装 MySQL 这件事本身就被 Docker 消灭了。以前你要下载 dmg、选版本、配 my.cnf、记住 root 密码、卸载时满Finder找残留。现在是一行 docker compose up -d，两分钟后一个干净的 MySQL 8 就在跑；不想要了 docker compose down，宿主机零残留。所以规划里把 Compose 基础前移到第 3 周——它只是你使用数据库的前置技能，学习成本半小时。

本周只讲「把数据库跑起来」所需的最小 Docker 知识：镜像、容器、卷、端口、日志。多阶段构建（Dockerfile 编译 Go）、前端 Nginx、完整多服务编排、上线部署全部在第 7 周。今天不要碰 Dockerfile。

需要先装 Docker Desktop（macOS/Windows 官网下载 .dmg/.exe，Linux 装 docker-ce + docker-compose-plugin）。验证：docker version 和 docker compose version 都有输出即可。国内网络拉镜像慢时，在 Docker Desktop 的 Docker Engine 配置里加镜像加速地址后 Restart。

知识讲义

1. 三个概念：镜像 / 容器 / 卷（用 npm 世界类比）

Docker一句话npm / Node 世界的类比
镜像 image一个只读的软件打包成品（MySQL 8 的程序 + 依赖 + 配置默认值）npm registry 里发布的一个包版本，比如 lodash@4.17.21 的 tarball：下载前它是死的、只读的、全球同一个
容器 container镜像跑起来的一个实例，有独立进程、网络、文件系统写入层npm install 后真正在跑的那个 node 进程 + 它的 node_modules。同一个镜像可以开多个容器 ≈ 同一份代码起多个服务实例
卷 volume挂在容器外的持久磁盘目录，容器删了它还在数据库的数据文件相当于 package-lock.json 之外的用户数据：你可以重装 node_modules（重建容器），但绝不能丢项目里写的文件
docker-compose.yml声明「要起哪些容器、怎么连、参数是什么」package.json 的 scripts + 依赖声明：docker compose up 之于 Docker，就像 npm run dev 之于那堆命令行
Dockerfile怎么造一个镜像（本周不用）≈ 打包发布 npm 包前的 tsup/tsconfig 构建配置，第 7 周见

容器是可丢弃的，卷才是你的数据。容器（container）的文件系统在重建时必然丢失——这是设计如此，不是 bug。所有你不想丢的东西（MySQL 的 /var/lib/mysql、以后上传的图片）都必须挂到卷或宿主机目录。本周 90% 的「我数据怎么没了」事故都源于这一行没配。

2. docker-compose.yml：逐字段拆解

新建项目目录 goblog，在里面放 docker-compose.yml（文件名固定，Compose 认它）：

docker-compose.ymlservices:
  mysql:                              # 服务名，自己起；服务之间用名字互相访问
    image: mysql:8.0                  # 镜像名:标签 —— 只读的「软件成品」
    container_name: golearn-mysql     # 固定容器名，方便 docker exec 直呼其名
    restart: unless-stopped           # Docker 重启后自动拉起，手动 stop 则不拉
    environment:                      # 官方镜像认这些环境变量（等价于初始化配置）
      MYSQL_ROOT_PASSWORD: "root123456"
      MYSQL_DATABASE: "study_plan"     # 首次启动自动 CREATE DATABASE
      MYSQL_USER: "golearn"            # 建一个业务账号，别拿 root 连应用
      MYSQL_PASSWORD: "golearn123"
    ports:
      - "3306:3306"                    # 宿主机端口:容器端口 —— 让 127.0.0.1:3306 能连进去
    volumes:
      - mysql-data:/var/lib/mysql      # 命名卷 → 容器里的数据目录，重启不丢全靠它
    command:
      - --character-set-server=utf8mb4  # 服务端默认字符集，emoji 也存得下
      - --collation-server=utf8mb4_unicode_ci
    healthcheck:                       # 「真的能接请求了」的判据，不只是进程活着
      test: ["CMD", "mysqladmin", "ping", "-h127.0.0.1", "-uroot", "-proot123456"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 30s              # 首次初始化要 20 秒，前 30 秒失败不计数

volumes:                              # 顶层 volumes 块：声明这个卷归 Compose 管
  mysql-data: {}

为什么不写 version: "3.8"？新版 Compose（docker compose 带空格，是 v2）已废弃顶层 version 字段，写了会警告。老教程里的 docker-compose（带横杠）是 v1，已经停止维护，看到 docker-compose up 一律换成 docker compose up。

shell$ cd goblog
$ docker compose up -d        # -d = detached，后台运行；首次会拉 ~600MB 镜像
[+] Running 2/2
 ✔ Network goblog_default    Created
 ✔ Container golearn-mysql   Started

$ docker compose ps            # 等 20~40 秒，STATE 从 (health: starting) 变 Up (healthy)
NAME            IMAGE       STATUS                   PORTS
golearn-mysql   mysql:8.0   Up 40 seconds (healthy)  0.0.0.0:3306->3306/tcp

ports: "3306:3306" 左边的宿主机端口可以换：本机已经装了 MySQL（Homebrew 常见）时会报 Address already in use，改成 "3307:3306" 即可，Go 的 DSN 里也写 3307。

3. 三条保命命令：ps / logs / exec

shell# ① 看状态：容器活着吗？健康检查过了吗？
$ docker compose ps
$ docker compose ps -a          # 连已退出的一起看（Exited(1) 说明启动即崩）

$ docker compose logs -f mysql          # -f 跟随，Ctrl+C 退出（不会停容器）
$ docker compose logs --tail=50 mysql   # 只看最后 50 行

# ③ 钻进容器：用命令行客户端连上自己的库
$ docker exec -it golearn-mysql mysql -ugolearn -pgolearn123 --database=study_plan

| VERSION() |
+-----------+

# 其他常用：进 shell / 重启 / 停掉但不删数据 / 删干净（危险）
$ docker exec -it golearn-mysql bash

记住 docker ps 与 docker compose ps 的差别：前者看整机所有容器，后者只看当前目录下这份 yml 管的容器。日常在项目目录里用后者。

5. 连接字符串（DSN）：parseTime 与 charset 不能省

GORM 连 MySQL 靠一个 DSN 字符串，格式对 JS 开发者很好记——账号:密码@协议(地址:端口)/库名?参数：

config.gopackage config

// 用户名:密码@tcp(host:port)/数据库名?参数
const DSN = "golearn:golearn123@tcp(127.0.0.1:3306)/study_plan" +
    "?charset=utf8mb4&parseTime=True&loc=Local"
参数作用不写会怎样
charset=utf8mb4通信字符集默认 utf8（MySQL 的残缺 utf8，3 字节），存 emoji / 生僻字直接报错或乱码
parseTime=True把 MySQL 的 DATETIME 自动扫进 Go 的 time.Time最坑的一个：time.Time 字段读出来是 []byte，GORM 报 unsupported scan 或者你手工转，很多人在这卡半天
loc=LocalDSN 层面按本机时区解释时间只写 parseTime=True 不写 loc，MySQL 存 UTC、Go 当本地时间 → 时间差 8 小时

容器里的 MySQL 默认时区是 UTC（TZ 环境变量没设）。你 20:00 北京时间写入的一行，created_at 存的是 12:00。加上 loc=Local 让驱动负责换算，读出来就是 20:00；也可以在 compose 的 environment 里加 TZ: "Asia/Shanghai" 并把 command 换成 --default-time-zone=+08:00。两种都行，但只选一种，全项目统一。

6. 第一次连接 + AutoMigrate 建表

完整可运行程序（cmd/server/main.go）：

cmd/server/main.gopackage main

import (
    fmt
    log
    time

    gorm.io/driver/mysql
    gorm.io/gorm
    gorm.io/gorm/logger
)

// 模型：一个 struct = 一张表，一个字段 = 一列
type User struct {
    ID        uint      `gorm:"primaryKey"`
    Name      string    `gorm:"size:64;not null"`
    Email     string    `gorm:"size:128;uniqueIndex"`
    CreatedAt time.Time
    UpdatedAt time.Time
}

func main() {
    dsn := "golearn:golearn123@tcp(127.0.0.1:3306)/study_plan?charset=utf8mb4&parseTime=True&loc=Local"

    db, err := gorm.Open(mysql.Open(dsn), &gorm.Config{
        Logger: logger.Default.LogMode(logger.Info), // 开发期把执行的 SQL 打到终端
    })
    if err != nil {
        log.Fatalf("连不上数据库: %v", err)
    }

    // AutoMigrate：结构体变了 → 帮你把表结构改成一致（只加/改，从不删）
    if err := db.AutoMigrate(&User{}); err != nil {
        log.Fatalf("迁移失败: %v", err)
    }

    db.Create(&User{Name: "小明", Email: "xiaoming@example.com"})

    var users []User
    db.Find(&users)
    fmt.Printf("库里现在有 %d 个用户\n", len(users))
}

AutoMigrate 的能力边界（本周最重要的 ORM 认知）：它只会 CREATE TABLE / ADD COLUMN / CREATE INDEX。它永远不会：删列、删表、删索引、把已有列改类型（可能丢数据时）。所以「模型里删了字段，数据库里的列还在」是正常现象；真要改结构，写 SQL 或用第 7 周的版本化迁移工具。

今日练习

练习 1：把 MySQL 起成 healthy（20 分钟）

照第 2 节抄一份 docker-compose.yml，改成你自己的库名/账号密码，起容器并用 docker compose ps 等到 (healthy)；然后故意把 MYSQL_ROOT_PASSWORD 改成空字符串再 up -d，用 docker compose logs mysql 看它怎么报错，改回来。

参考答案：空密码时日志出现 MYSQL_ROOT_PASSWORD, but you have set it blank. Instead of that, you can use MYSQL_RANDOM_ROOT_PASSWORD，容器反复重启（docker compose ps -a 看到 Restarting）。结论：容器起不来先 logs，不要凭猜。

练习 2：命令行里手工插一行 + Go 读出来（30 分钟）

先用 SQL 手动写数据：INSERT INTO users (name,email,created_at,updated_at) VALUES ('阿花','ahua@example.com',NOW(),NOW());（表还不存在就先把讲义第 6 节的 main.go 跑一遍，AutoMigrate 会建出 users 表）。再在 Go 里 db.Find(&users) 打印，确认能看到两行。

参考答案：能读到即说明「数据库是共享的外置存储，不是 Go 进程内存」——这正是本周和上周的本质区别。若报 Error 1146 (42S02): Table 'study_plan.users' doesn't exist，说明 Go 程序还没跑过 AutoMigrate，或者库名对不上（SELECT DATABASE(); 自查）。

练习 3：数据持久化实验（本周验收的预演，25 分钟）

依次执行并记录每次 SELECT COUNT(*) FROM users; 的结果：① docker compose restart mysql；② docker compose down 然后 up -d；③ docker rm -f golearn-mysql 然后 docker compose up -d。最后把 volumes 那行注释掉重复 ②，观察差异。

参考答案：①②③ 行数都不变（卷活着）；注释掉卷之后 down/up，行数变 0（Go 程序重新跑才又插回去）。这就证明了持久化 100% 来自那一行 mysql-data:/var/lib/mysql，和 restart 策略、和容器名都无关。

练习 4：亲眼看一次 parseTime 事故（15 分钟）

把 DSN 里的 parseTime=True 删掉再跑练习 2 的查询程序，把报错原文记进笔记；然后只删 loc=Local 保留 parseTime=True，对比打印出来的 CreatedAt 与 date 命令的本机时间差几小时。

参考答案：删 parseTime=True → Error 1 (HY000): sql: Scan() argument 4 cannot be ... 或 GORM 报 unsupported Scan, storing driver.Value type []uint8 into type *time.Time；删 loc=Local → 时间比实际早 8 小时。两个参数都得写。

常见坑（新手 100% 会踩）

坑现象正确姿势
忘挂命名卷down / 升级镜像后数据全丢，像被删库volumes: - mysql-data:/var/lib/mysql + 顶层 volumes 声明，缺一不可
手滑 down -v卷被删，SHOW TABLES 空了日常只用 docker compose down；-v 只在你确认要清库时用
