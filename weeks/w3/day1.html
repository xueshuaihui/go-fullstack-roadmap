课前须知：为什么本周先学 Docker

安装 MySQL 这件事本身就被 Docker 消灭了。以前你要下载 dmg、选版本、配 my.cnf、记住 root 密码、卸载时满Finder找残留。现在是一行 docker compose up -d，两分钟后一个干净的 MySQL 8 就在跑；不想要了 docker compose down，宿主机零残留。所以规划里把 Compose 基础前移到第 3 周——它只是你使用数据库的前置技能，学习成本半小时。

本周只讲「把数据库跑起来」所需的最小 Docker 知识：镜像、容器、卷、端口、日志。多阶段构建（Dockerfile 编译 Go）、前端 Nginx、完整多服务编排、上线部署全部在第 7 周。今天不要碰 Dockerfile。

需要先装 Docker Desktop（macOS/Windows 官网下载 .dmg/.exe，Linux 装 docker-ce + docker-compose-plugin）。验证：docker version 和 docker compose version 都有输出即可。

装好了但 docker compose up 卡住不动？（国内网络大概率会）

Docker 默认从 registry-1.docker.io 拉镜像，国内经常卡在 dial tcp ... i/o timeout。解决办法是配镜像加速地址（registry mirror）——它只是一个提速用的缓存，不影响本周任何一行的正确性：不加也能学完，只是慢。

macOS / Windows：托盘图标 → Settings → Docker Engine，把下面这段贴进右边那个 JSON 编辑器（保留原有的键，只加 registry-mirrors），点 Apply & Restart。

Linux：同样内容写进 /etc/docker/daemon.json，然后 sudo systemctl restart docker。

daemon.json（Docker Engine 配置）{
  "registry-mirrors": ["https://<你的加速地址>.mirror.aliyuncs.com"],
  "builder": { "gc": true },
  "features": { "containerd-snapshotter": false }
}

其中 <你的加速地址> 那一串是每人不同的专属前缀：登录阿里云控制台 → 搜「容器镜像服务 ACR」→ 左侧「镜像工具 → 镜像加速器」，页面里那行 https://xxxx.mirror.aliyuncs.com 复制过来即可（免费，需实名登录）。填对了验证方式：

shell$ docker info | grep -A 2 "Registry Mirrors"
 Registry Mirrors:
  https://xxxx.mirror.aliyuncs.com/       # 有你刚填的地址 = 生效

加速器只对 docker pull 生效，不是翻墙代理；它偶尔会失效（第三方镜像站关停是常态）。失效时把 registry-mirrors 那两行删掉、换一个新的地址即可，本周项目文件一行都不用改。

为什么不直接在 gin-api 里改？三个教学理由：① 本周的主线是 GORM，如果原地改造，你要一边删 MemRepo 的 sync.RWMutex、一边处理 ID uint 变 gorm.Model、还要顺手改内存版遗留的 CreatedAt time.Now() 赋值——三件不相干的事挤在同一次改动里，报错时你分不清是数据库没连上还是改造没改净。② 新开模块后，gin-api（内存版）和 goblog（MySQL 版）同一套接口两种实现并存，day2 你能真的把两份代码并排 diff，「依赖倒置」这词才有实物可指。③ 第 2 周项目的 POST /users 入参是明文密码 + Role string，本周模型要按第 4 周的 bcrypt 与 role tinyint 定稿，原地改会把上周的验收命令全打翻。结论：gin-api 目录留在原地别删，它是你这周的对照样本。

知识讲义

1. 三个概念：镜像 / 容器 / 卷（用 npm 世界类比）

Docker一句话npm / Node 世界的类比
镜像 image一个只读的软件打包成品（MySQL 8 的程序 + 依赖 + 配置默认值）npm registry 里发布的一个包版本，比如 lodash@4.17.21 的 tarball：下载前它是死的、只读的、全球同一个
容器 container镜像跑起来的一个实例，有独立进程、网络、文件系统写入层npm install 后真正在跑的那个 node 进程 + 它的 node_modules。同一个镜像可以开多个容器 ≈ 同一份代码起多个服务实例
卷 volume挂在容器外的持久磁盘目录，容器删了它还在数据库的数据文件相当于 package-lock.json 之外的用户数据：你可以重装 node_modules（重建容器），但绝不能丢项目里写的文件
docker-compose.yml声明「要起哪些容器、怎么连、参数是什么」package.json 的 scripts + 依赖声明：docker compose up 之于 Docker，就像 npm run dev 之于那堆命令行
Dockerfile怎么造一个镜像（本周不用）≈ 打包发布 npm 包前的 tsup/tsconfig 构建配置，第 7 周见

容器是可丢弃的，卷才是你的数据。容器（container）的文件系统在重建时必然丢失——这是设计如此，不是 bug。所有你不想丢的东西（MySQL 的 /var/lib/mysql、以后上传的图片）都必须挂到卷或宿主机目录。本周 90% 的「我数据怎么没了」事故都源于这一行没配。

2. docker-compose.yml：逐字段拆解

新建项目目录 goblog，在里面放 docker-compose.yml（文件名固定，Compose 认它）：

docker-compose.ymlservices:
  mysql:                              # 服务名，自己起；服务之间用名字互相访问
    image: mysql:8.0                  # 镜像名:标签 —— 只读的「软件成品」
    container_name: goblog-mysql      # 固定容器名，方便 docker exec 直呼其名（第 7 周沿用这个名字）
    restart: unless-stopped           # Docker 重启后自动拉起，手动 stop 则不拉
    environment:                      # 官方镜像认这些环境变量（等价于初始化配置）
      MYSQL_ROOT_PASSWORD: "goblogroot"
      MYSQL_DATABASE: "goblog"        # 首次启动自动 CREATE DATABASE
      MYSQL_USER: "goblog"             # 建一个业务账号，别拿 root 连应用
      MYSQL_PASSWORD: "goblog123"
    ports:
      - "3306:3306"                    # 宿主机端口:容器端口 —— 让 127.0.0.1:3306 能连进去
    volumes:
      - mysql-data:/var/lib/mysql      # 命名卷 → 容器里的数据目录，重启不丢全靠它
    command:
      - --character-set-server=utf8mb4  # 服务端默认字符集，emoji 也存得下
      - --collation-server=utf8mb4_unicode_ci
    healthcheck:                       # 「真的能接请求了」的判据，不只是进程活着
      test: ["CMD", "mysqladmin", "ping", "-h127.0.0.1", "-uroot", "-pgoblogroot"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 30s              # 首次初始化要 20 秒，前 30 秒失败不计数

volumes:                              # 顶层 volumes 块：声明这个卷归 Compose 管
  mysql-data: {}

为什么不写 version: "3.8"？新版 Compose（docker compose 带空格，是 v2）已废弃顶层 version 字段，写了会警告。老教程里的 docker-compose（带横杠）是 v1，已经停止维护，看到 docker-compose up 一律换成 docker compose up。

这套名字（库 goblog、账号 goblog/goblog123、root goblogroot、容器 goblog-mysql）从第 3 周用到第 8 周，第 4 周的 .env、第 7 周的 compose.yaml 都按它对齐。学习用的密码就长这样，别照抄到真项目。

5. 连接字符串（DSN）：parseTime 与 charset 不能省

GORM 连 MySQL 靠一个 DSN 字符串，格式对 JS 开发者很好记——账号:密码@协议(地址:端口)/库名?参数：

internal/config/config.gopackage config

// 用户名:密码@tcp(host:port)/数据库名?参数
// 账号密码要和 docker-compose.yml 里的 MYSQL_USER / MYSQL_PASSWORD 完全一致
const DSN = "goblog:goblog123@tcp(127.0.0.1:3306)/goblog" +
    "?charset=utf8mb4&parseTime=True&loc=Local"

这是全项目唯一的 DSN：文件放在 internal/config/config.go，第 6 节的 cmd/server/main.go 直接 config.DSN 引用它，后面每一天的 cmd/seed、连接池代码也都从这一处取。端口换成 3307 时只改这一行，别去各文件里散着改。第 4 周会把它换成读 .env（真项目里密码不该进 git），今天先照抄常量。

参数作用不写会怎样
charset=utf8mb4通信字符集默认 utf8（MySQL 的残缺 utf8，3 字节），存 emoji / 生僻字直接报错或乱码
parseTime=True把 MySQL 的 DATETIME 自动扫进 Go 的 time.Time最坑的一个：time.Time 字段读出来是 []byte，GORM 报 unsupported scan 或者你手工转，很多人在这卡半天
loc=LocalDSN 层面按本机时区解释时间只写 parseTime=True 不写 loc，MySQL 存 UTC、Go 当本地时间 → 时间差 8 小时

容器里的 MySQL 默认时区是 UTC（TZ 环境变量没设）。你 20:00 北京时间写入的一行，created_at 存的是 12:00。加上 loc=Local 让驱动负责换算，读出来就是 20:00；也可以在 compose 的 environment 里加 TZ: "Asia/Shanghai" 并把 command 换成 --default-time-zone=+08:00。两种都行，但只选一种，全项目统一。

6. 第一次连接 + AutoMigrate 建表

模型先照抄一遍（internal/model/user.go，全周唯一的 User 版本，day2 只补关联字段不重定义）：

internal/model/user.gopackage model

import (
    "gorm.io/gorm"
)

// User 一个 struct = 一张表。字段顺序 = 建表时的列顺序
type User struct {
    gorm.Model                              // 内嵌：ID uint / CreatedAt / UpdatedAt / DeletedAt（软删除）
    Username string `gorm:"type:varchar(32);uniqueIndex;not null" json:"username"`
    Nickname string `gorm:"type:varchar(32)" json:"nickname"`
    Email    string `gorm:"type:varchar(128);uniqueIndex" json:"email"`
    Password string `gorm:"type:varchar(72);not null" json:"-"` // json:"-" 永不外泄
    Role     Role   `gorm:"column:role;type:tinyint;not null;default:0;index" json:"role"`

    // Articles []Article `gorm:"foreignKey:UserID" json:"articles,omitempty"` // day2 建好 Article 再打开
}

// Role 用自定义整型，避免裸 int8 到处传

    RoleUser  Role = iota // 0 普通用户

连库收到一个函数里（internal/repository/db.go），后面 cmd/seed、day5 的连接池都复用它：

internal/repository/db.gopackage repository

import (
    log

    "gorm.io/driver/mysql"
    "gorm.io/gorm"
    "gorm.io/gorm/logger"
)

// New 打开连接池并探活。全周唯一的建库入口。
func New(dsn string) (*gorm.DB, error) {
    db, err := gorm.Open(mysql.Open(dsn), &gorm.Config{
        Logger:            logger.Default.LogMode(logger.Info), // 开发期把执行的 SQL 打到终端
        BlockGlobalUpdate: true,             // 没有 WHERE 的 UPDATE/DELETE 直接报错（day2 第 5 节解释）
    })
    if err != nil {
        return nil, err
    }
    sqlDB, err := db.DB() // 拿到底层 *sql.DB 才能 Ping；db.DB() 返回的就是连接池
    if err != nil {
        return nil, err
    }
    if err := sqlDB.Ping(); err != nil {
        return nil, err       // gorm.Open 是惰性的，不 Ping 就会「连上了但一查就炸」
    }
    return db, nil
}

// MustConnect 给脚本/启动阶段用：连不上就直接退出，不留一个半死的进程
func MustConnect(dsn string) *gorm.DB {
    db, err := New(dsn)
    if err != nil {
        log.Fatalf("连不上数据库: %v", err)
    }
    return db
}

然后是今天的 main（cmd/server/main.go，完整可跑）：

cmd/server/main.gopackage main

import (
    fmt
    log

    "goblog/internal/config"
    "goblog/internal/model"
    "goblog/internal/repository"
)

func main() {
    db := repository.MustConnect(config.DSN)

    // AutoMigrate：结构体变了 → 帮你把表结构改成一致（只加/改，从不删）
    if err := db.AutoMigrate(&model.User{}); err != nil {
        log.Fatalf("迁移失败: %v", err)
    }

    u := model.User{
        Username: "xiaoming",
        Nickname: "小明",
        Email:    "xiaoming@example.com",
        Password: "abcdef123456", // 学习用的密码就长这样，别照抄到真项目
    }
    if err := db.Create(&u).Error; err != nil {
        log.Fatalf("写入失败: %v", err)
    }
    fmt.Printf("新记录 ID = %d\n", u.ID) // Create 会把自增主键回填进结构体

    var users []model.User
    if err := db.Find(&users).Error; err != nil {
        log.Fatalf("查询失败: %v", err)
    }
    fmt.Printf("库里现在有 %d 个用户\n", len(users))
}

每个终结方法都要接 err：db.Create(&u) 返回的是一个 *gorm.DB，真正的错误挂在它的 .Error 字段上。db.Create(&u) 单写一行 = 把错误丢了，插失败你只会看到「库里现在有 0 个用户」。规则：Create / First / Find / Save / Updates / Delete 一律 if err := db.Xxx(...).Error; err != nil，链式中间态（Where/Select/Order）不需要接。

第二次 go run ./cmd/server 会撞 Error 1062 (23000): Duplicate entry 'xiaoming' for key 'users.uni_users_username'（唯一索引生效，是好事）。想反复跑就换成「有则取、无则插」：db.Where("email = ?", u.Email).FirstOrCreate(&u)。注意报错里给的是索引名 uni_users_username 而不是列名——GORM 的默认命名是 uni_表_列 / idx_表_列，第 7 周手写迁移时要照抄这个名字，不然 down 脚本删不掉。

JSON 键名先知道一下：内嵌的 gorm.Model 没有打 json 标签，所以直接序列化它会得到大写键 {"ID":1,"CreatedAt":"…","UpdatedAt":"…","DeletedAt":null,"username":"xiaoming",…}。这是 Go 的默认行为（用字段名），不是 GORM 的 bug。第 6 周接前端时那些键要转成 id/created_at，届时在 DTO 里处理；今天只要知道「大模型直接吐 JSON 不好看，所以后面都走 DTO」就够了。

AutoMigrate 的能力边界（本周最重要的 ORM 认知）：它只会 CREATE TABLE / ADD COLUMN / CREATE INDEX。它永远不会：删列、删表、删索引、把已有列改类型（可能丢数据时）。所以「模型里删了字段，数据库里的列还在」是正常现象；真要改结构，写 SQL 或用第 7 周的版本化迁移工具。

7. 把第 2 周的架子接上：/api/v1 + response + 中间件

光会连库不算「接口」。把「承接第 2 周」那节 cp 过来的东西接起来，今天就要有一个能 curl 的服务。覆盖 cmd/server/main.go（模型和 repository.MustConnect 沿用第 6 节，一行不改）：

cmd/server/main.gopackage main

import (
    log
    net/http

    "github.com/gin-gonic/gin"

    "goblog/internal/config"
    "goblog/internal/middleware"
    "goblog/internal/model"
    "goblog/internal/repository"
    "goblog/pkg/response"
)

func main() {
    db := repository.MustConnect(config.DSN)
    if err := db.AutoMigrate(&model.User{}); err != nil {
        log.Fatalf("迁移失败: %v", err)
    }

    r := gin.Default() // 自带 gin.Logger() + gin.Recovery()
    r.Use(middleware.CORS(), middleware.Timer())

    r.GET("/health", func(c *gin.Context) {   // 健康检查不带前缀，第 7 周 nginx/LB 直接打它
        response.OK(c, gin.H{"status": "ok"})
    })

    api := r.Group("/api/v1")                  // 全周所有业务路由都挂这里
    api.GET("/users", func(c *gin.Context) {
        var users []model.User
        if err := db.Find(&users).Error; err != nil {
            response.Fail(c, http.StatusInternalServerError, response.CodeInternal, "读用户失败")
            return
        }
        response.OK(c, users)
    })

    r.NoRoute(func(c *gin.Context) {            // 404 也必须走统一 Body：HTTP 404 + code 1001
        response.Fail(c, http.StatusNotFound, response.CodeUserNotFound, "接口不存在: "+c.Request.URL.Path)
    })

    log.Println("goblog listening on :8080")
    if err := r.Run(":8080"); err != nil {
        log.Fatal(err)
    }
}

这一节的 api.GET("/users", …) 里直接写了 db.Find——故意的，今天只是验收架子通了。day2 第一件事就是把它拆成 handler → service → repository 三层，别在 main 里堆业务。第 2 周你已经写过一遍正确的分层，这周只是把内存仓库换成 MySQL 仓库。

另外注意 response.CodeUserNotFound 这个常量名：它的值 1001 在码表里是「资源不存在（通用）」，NoRoute 就用它。第 3 周新增了文章，也别去改这个常量的语义——文章不存在有专门的 2001（day3 会用到）。

今日练习

练习 1：把 MySQL 起成 healthy（20 分钟）

照第 2 节抄一份 docker-compose.yml，起容器并用 docker compose ps 等到 (healthy)；然后故意把 MYSQL_ROOT_PASSWORD 改成空字符串再 up -d，用 docker compose logs mysql 看它怎么报错，改回来。

参考答案：空密码时日志出现 MYSQL_ROOT_PASSWORD, but you have set it blank. Instead of that, you can use MYSQL_RANDOM_ROOT_PASSWORD，容器反复重启（docker compose ps -a 看到 Restarting）。结论：容器起不来先 logs，不要凭猜。

别顺手改库名和账号：本周后面 4 天的所有命令、DSN、连接串都按 goblog / goblog123 写死；改了就得整周跟着你翻译，练习白做。

练习 2：命令行里手工插一行 + Go 读出来（30 分钟）

先用 SQL 手动写数据（注意 username 和 password 都是 NOT NULL，必须给）：INSERT INTO users (created_at,updated_at,username,nickname,email,password,role) VALUES (NOW(3),NOW(3),'ahua','阿花','ahua@example.com','abcdef123456',0);（表还不存在就先把讲义第 6 节的 main.go 跑一遍，AutoMigrate 会建出 users 表）。再在 Go 里 db.Find(&users) 打印，确认能看到两行。

参考答案：能读到即说明「数据库是共享的外置存储，不是 Go 进程内存」——这正是本周和上周的本质区别。若报 Error 1146 (42S02): Table 'goblog.users' doesn't exist，说明 Go 程序还没跑过 AutoMigrate，或者库名对不上（SELECT DATABASE(); 自查）。如果报 Error 1054 (42S02): Unknown column 'name' in 'field list'，说明你用的是老版本讲义的列名——本表没有 name 列，只有 username（登录名）和 nickname（显示名）。

练习 3：数据持久化实验（本周验收的预演，25 分钟）

依次执行并记录每次 SELECT COUNT(*) FROM users; 的结果：① docker compose restart mysql；② docker compose down 然后 up -d；③ docker rm -f goblog-mysql 然后 docker compose up -d。最后把 volumes 那行注释掉重复 ②，观察差异。

参考答案：①②③ 行数都不变（卷活着）；注释掉卷之后 down/up，行数变 0（Go 程序重新跑才又插回去）。这就证明了持久化 100% 来自那一行 mysql-data:/var/lib/mysql，和 restart 策略、和容器名都无关。

练习 4：亲眼看一次 parseTime 事故（15 分钟）

把 internal/config/config.go 里 DSN 的 parseTime=True 删掉再跑练习 2 的查询程序，把报错原文记进笔记；然后只删 loc=Local 保留 parseTime=True，对比打印出来的 CreatedAt 与 date 命令的本机时间差几小时。

参考答案：删 parseTime=True → Error 1 (HY000): sql: Scan() argument 4 cannot be ... 或 GORM 报 unsupported Scan, storing driver.Value type []uint8 into type *time.Time；删 loc=Local → 时间比实际早 8 小时。两个参数都得写。改完记得把这一行复原，否则 day3 的 created_at 排序实验会把你带偏。
