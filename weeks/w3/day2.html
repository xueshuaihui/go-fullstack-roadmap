1. 模型定义：gorm.Model 与字段 tag

gorm.Model 是一个官方内嵌结构体，塞进来就有 ID / CreatedAt / UpdatedAt / DeletedAt 四个字段（含软删除）：

gorm.Model 展开type Model struct {
    ID        uint           `gorm:"primaryKey"`
    CreatedAt time.Time
    UpdatedAt time.Time
    DeletedAt gorm.DeletedAt  `gorm:"index"`  // ← 有这个字段就自动软删除，Day 5 细讲
}

本周主线模型的完整定义（三个文件一起给出，后三天直接复用）：

internal/model/tag.gopackage model

import (
    time

    "gorm.io/gorm"
)

// Tag 不用 gorm.Model：标签没有「改」也没有「软删」的需求
type Tag struct {
    ID        uint      `gorm:"primaryKey" json:"id"`
    Name      string    `gorm:"type:varchar(32);not null;uniqueIndex" json:"name"`
    CreatedAt time.Time `json:"created_at"`
}

// 表名：GORM 默认「结构体名 snake_case + 复数」，Tag → tags 已经对了。
// 这里显式写出来是为了立个规矩：一旦写了 TableName()，全项目所有注释/SQL 里的
// 表名都必须跟它一致（本文件后面手写 SQL 用的就是 tags / articles / users / article_tags）。
func (Tag) TableName() string { return "tags" }

三张业务表 + 一张中间表，AutoMigrate 之后的表名分别是 users、articles、tags、article_tags（many2many:article_tags 里那个字符串就是中间表名，day3 会 SELECT * FROM article_tags 亲眼看到它）。

为什么 User 里有两行「不是 §3 基准」的东西？ArticleCount 是冗余计数列（day5 用事务演示「一篇文章 + 一个计数必须同生同死」时才需要它，纯靠 COUNT(*) 也能算，但那是另一节课）；Role 在基准里由第 7 周的版本化迁移 000002_add_role_to_users 加到生产库，学习期 AutoMigrate 会提前把它建出来——所以你在第 7 周看到那条迁移时不要慌，它在生产库上是幂等的补齐。

tag作用备注
primaryKey指定主键字段名 ID 或 XxxID 会被自动认成主键/外键，所以自定义主键要显式写
column:"x"指定列名不写则用 snake_case（UserID → user_id）
type:"varchar(64)"建表用的数据库类型只在 AutoMigrate 建表/首次加列时生效
size:64GORM 自己的长度声明（varchar(64)）和 type 二选一即可，别写矛盾的两个值
not null / default:0非空 / 默认值字符串默认值要转义双引号：default:'' 或直接 default:"x"
index / uniqueIndex普通/唯一索引可带名字与组合：uniqueIndex:idx_user_name 出现在多个字段上即联合索引
autoIncrement:false自定义主键（如 UUID / slug）本周不用，知道即可
json:"-" / json:"omitempty"不是 GORM 的，是 encoding/json 的密码永不回前端；关联字段不请求就不返回

命名规则默认值：结构体 ArticleTag → 表 article_tags；字段 UserID → 列 user_id。全项目要么遵守默认，要么统一用 TableName()，别混着来。

3. 查询四件套：First / Take / Last / Find

方法生成的 SQL 关键部分找不到时用途
db.First(&u, 1)ORDER BY id LIMIT 1ErrRecordNotFound按主键/条件取「最早的一条」，最常用
db.Take(&u, 1)LIMIT 1（无排序）ErrRecordNotFound不关心顺序、想让 MySQL 自己挑最优时
db.Last(&u)ORDER BY id DESC LIMIT 1ErrRecordNotFound取最新一条
db.Find(&users)SELECT * FROM users（无 LIMIT）无错（得到空 slice）取多条，列表接口用它
db.Find(&users, 1)WHERE id = 1 仍返回 slice无错（空 slice）按主键批量
cmd/demo/main.go（续）· 查询写法// ① 传结构体做条件：非零字段才进 WHERE（零值 0 / "" / nil 被忽略！）
cond := model.User{Username: "xiaoming"}   // Email 是 "" → 不参与条件
db.Where(&cond).Find(&users)                  // WHERE username = 'xiaoming'

// ② 传 map：键是列名，零值也算条件（这是查「views = 0」的唯一稳妥方式）
db.Where(map[string]any{"username": "xiaoming", "views": 0}).Find(&articles)

// ③ 链式 + 占位符（最常用，占位符 ? 由驱动转义，天然防注入 —— day4 会亲手打断它）
db.Where("username = ? AND email LIKE ?", "xiaoming", "%example%").
   Order("id desc").
   Limit(5).
   Find(&users)

// 取部分列 / 标量
db.Select("id", "username").Find(&users)
var emails []string
db.Model(&model.User{}).Where("id < ?", 10).Pluck("email", &emails)

② 那行为什么传 articles 却写 views 条件？因为 views 是 articles 表的列——GORM 用 Find 的第一个参数决定 FROM 哪张表。所以别把两行的变量手滑写反，报的错会是 Error 1054 (42S02): Unknown column 'views' in 'where clause'（列不存在，day4 的坑表里也有它）。

4. 更新：Save vs Updates，以及零值陷阱

cmd/demo/main.go（续）· 更新对比：把上面的 demo 改成返回 error 就能整段贴进去// Save：主键非零 → UPDATE 全部列（等于把整个 struct 覆盖过去）
var u model.User
db.First(&u, 1)
u.Nickname = "小明改名"
db.Save(&u)      // UPDATE users SET username=...,nickname=...,email=...,password=...,role=...,article_count=...,updated_at=... WHERE id=1
                 // 主键为 0 时 Save 会退化成 INSERT —— 新人最常见的意外

// Updates + struct：只更新非零字段（Views=0 会被悄悄跳过！）
db.Model(&model.User{}).Where("id = ?", 1).Updates(model.User{Nickname: "批量改", Email: "b@x.com"})

// Updates + map：零值照常写入 —— 归零/清空必须用它
db.Model(&a).Updates(map[string]any{"views": 0, "content": ""})

// 单列 / 表达式自增（DB 端计算，避免读改写并发丢失）
db.Model(&model.Article{}).Where("id = ?", 1).Update("title", "新标题")
db.Model(&model.Article{}).Where("id = ?", 1).UpdateColumn("views", gorm.Expr("views + ?", 1))

// 影响行数：更新 0 行不是错误，RowsAffected 才是唯一线索
res := db.Model(&model.User{}).Where("id = ?", 99999).Update("nickname", "x")
if res.Error != nil { return res.Error }
if res.RowsAffected == 0 { return ErrUserNotFound } // 否则你会以为改成功了

对比 JS：Object.assign(user, patch) 里 undefined 不覆盖、null 覆盖。GORM 的 struct 版 Updates 是「非零值才覆盖」——Go 没有 undefined，只有零值，所以想表达「把它置空」必须换 map（或用 *int 这类指针字段，第 4 周讲）。

两个 RowsAffected 的真相，别踩：

  • MySQL 的 UPDATE 报的是「值真的被改了的行数」，不是「匹配到的行数」。所以 WHERE id=1 明明匹配到了、但把 nickname 又写成原来那个值，RowsAffected 也是 0。「更新 0 行」不能直接等价于「记录不存在」——今天 demo 里是拿不存在的 99999 演示，才看起来干净。真要做「不存在就 404」，先 Count 或 First 确认存在（练习 2 的 Update 就是这么写的）。
  • DELETE 没这个问题：RowsAffected 就是被删掉的行数，0 表示确实没这行，可以放心判 404。

Save 还有个隐藏行为：它会顺手 upsert 非空关联。如果你 First 出来的 u.Articles 里有元素（day3 Preload 之后一定会），db.Save(&u) 会连带给每篇关联文章发 UPDATE。更新主表时想只动这张表，就写 db.Omit(clause.Associations).Save(&u)（gorm.io/gorm/clause）。本周的 Update 一律走这条。

cmd/demo/main.go（续）· 删除db.Delete(&model.User{}, 1)                       // 有 DeletedAt → UPDATE deleted_at；无 → DELETE

GORM 有个隐藏保险：全局配置开 BlockGlobalUpdate: true 后，不带 Where 的 Update/Delete 会直接报 ErrMissingWhereClause，避免你把全表改了。day1 第 6 节的 internal/repository/db.go 里已经把它打开了（就是 gorm.Config 那三行里的第三行），所以你今天写 db.Delete(&model.Article{}) 不带条件时会立刻看到： ERROR: where clause required when sql kind = UPDATE。这就是它在工作。

6. ErrRecordNotFound：出错还是没数据？

先把「不存在」这两个字定义一次，全周复用（internal/repository/errors.go，新文件）。为什么放 repository 包而不是 service 包？因为错误是仓储层先发现的，依赖方向永远是 handler → service → repository，把哨兵错误放最底层，谁都能 import 它而不会形成循环。

internal/repository/errors.gopackage repository

import (
    errors
)

// 哨兵错误：全周只在这一个文件里定义，别处一律 ErrXxx 引用，不再 errors.New 第二遍
var (
    ErrUserNotFound    = errors.New("用户不存在") // → 404 + code 1001（通用「资源不存在」）
    ErrArticleNotFound = errors.New("文章不存在") // → 404 + code 2001，day3 起用
)
internal/repository/user.go（节选：把 ErrRecordNotFound 翻译掉）package repository

import (
    errors

    "goblog/internal/model"

    "gorm.io/gorm"
)

func (r *gormUserRepo) Get(id uint) (model.User, error) {
    var u model.User
    err := r.db.First(&u, id).Error
    switch {
    case errors.Is(err, gorm.ErrRecordNotFound):
        return model.User{}, ErrUserNotFound // → handler 返回 404 + code 1001
    case err != nil:
        return model.User{}, err             // → 500，数据库真出问题了，别混成 404
    default:
        return u, nil
    }
}

如果你写过 Sequelize，它的 findByPk 找不到时默认 throw；GORM 不 panic 也不 throw，而是把 ErrRecordNotFound 放在 db.Error 里。必须用 errors.Is 而不是 ==——将来错误被 fmt.Errorf("%w", ...) 包装过，== 就比不上了。

练习 2：给老接口写第二个实现（主线，90 分钟）

保持第 2 周定义好的 UserRepository 接口不动，新增 GORM 实现并在 main.go 换装配。要求 POST /users、GET /users、GET /users/:id、PUT /users/:id、DELETE /users/:id 全部行为与上周一致，只是数据落在 MySQL、路径都挂在 /api/v1 下。

internal/repository/user.go（今天的主文件，完整）package repository

import (
    errors

    "goblog/internal/model"

    "gorm.io/gorm"
    "gorm.io/gorm/clause"
)

// UserRepository 就是第 2 周那份契约：List/Get/Create/Update/Delete，方法名和签名
// 一个字节都不改。内存实现（MemRepo）不带进 goblog，所以本文件里只有 GORM 这一份实现。
type UserRepository interface {
    List() ([]model.User, error)
    Get(id uint) (model.User, error)
    Create(u model.User) (model.User, error)
    Update(u model.User) error
    Delete(id uint) error
}

// gormUserRepo 第二个实现：小写开头 = 包外拿不到具体类型，只能靠接口用
type gormUserRepo struct { db *gorm.DB }

func NewUserRepo(db *gorm.DB) UserRepository { return &gormUserRepo{db: db} }

var _ UserRepository = (*gormUserRepo)(nil) // 编译期契约检查，和上周同一行

func (r *gormUserRepo) Create(u model.User) (model.User, error) {
    if err := r.db.Create(&u).Error; err != nil {
        return model.User{}, err       // 1062 唯一冲突原样上抛，service 决定怎么翻译
    }
    return u, nil                     // u.ID 已被 Create 回填
}

func (r *gormUserRepo) List() ([]model.User, error) {
    users := []model.User{}                // 预置空 slice，保证 JSON 输出 [] 而不是 null
    err := r.db.Order("id asc").Find(&users).Error
    return users, err                     // 上周 map 遍历无序的坑，这里靠 ORDER BY 解决了
}

func (r *gormUserRepo) Get(id uint) (model.User, error) {
    var u model.User
    err := r.db.First(&u, id).Error
    switch {
    case errors.Is(err, gorm.ErrRecordNotFound):
        return model.User{}, ErrUserNotFound
    case err != nil:
        return model.User{}, err
    default:
        return u, nil
    }
}

func (r *gormUserRepo) Update(u model.User) error {
    var n int64                          // 见第 4 节：UPDATE 的 RowsAffected 是「真改了几行」，
    if err := r.db.Model(&model.User{}).Where("id = ?", u.ID).Count(&n).Error; err != nil {
        return err                        // 不能拿它判存在性」，所以先数一次
    }
    if n == 0 {
        return ErrUserNotFound
    }
    return r.db.Omit(clause.Associations).Save(&u).Error // 别连带 upsert Articles
}

func (r *gormUserRepo) Delete(id uint) error {
    res := r.db.Delete(&model.User{}, id)  // 软删除：UPDATE users SET deleted_at=NOW() WHERE id=1
    if res.Error != nil { return res.Error }
    if res.RowsAffected == 0 { return ErrUserNotFound }
    return nil
}

internal/service/user.gopackage service

import (
    fmt

    "goblog/internal/dto"
    "goblog/internal/model"
    "goblog/internal/repository"
)

type UserService struct {
    repo repository.UserRepository // 依赖接口，第 3 周换实现，这个字段类型不变
}

func NewUserService(repo repository.UserRepository) *UserService {
    return &UserService{repo: repo}
}

func (s *UserService) Create(req dto.CreateUserReq) (model.User, error) {
    ok, err := s.repo.ExistsUsername(req.Username)
    if err != nil {
        return model.User{}, fmt.Errorf("check dup: %w", err)
    }
    if ok {
        return model.User{}, ErrUsernameExists
    }
    nickname := req.Nickname
    if nickname == "" { nickname = req.Username } // 业务规则：没给昵称就用登录名兜
    return s.repo.Create(model.User{
        Username: req.Username, Nickname: nickname,
        Email: req.Email, Password: req.Password,
        Role: model.RoleUser,   // 注册永远是普通用户：DTO 里压根没有 role 字段，这条路堵死
    })
}

func (s *UserService) Get(id uint) (model.User, error)  { return s.repo.Get(id) }
func (s *UserService) List() ([]model.User, error)      { return s.repo.List() }
func (s *UserService) Delete(id uint) error             { return s.repo.Delete(id) }

// Update 走「取出来 → 覆盖字段 → 存回去」，不用 map 拼部分更新：
// 这样零值语义由我们控制，不依赖 Updates 的「非零才更新」规则（第 4 节那个坑）。
func (s *UserService) Update(id uint, req dto.UpdateUserReq) (model.User, error) {
    u, err := s.repo.Get(id)
    if err != nil { return model.User{}, err }
    if req.Nickname != "" { u.Nickname = req.Nickname }
    if req.Email != ""    { u.Email = req.Email }
    return u, s.repo.Update(u)
}
internal/handler/user.gopackage handler

import (
    errors
    net/http
    strconv

    "github.com/gin-gonic/gin"

    "goblog/internal/dto"
    "goblog/internal/service"
    "goblog/pkg/response"
)

type UserHandler struct { svc *service.UserService }

func NewUserHandler(svc *service.UserService) *UserHandler { return &UserHandler{svc: svc} }

// Register 路由收在 handler 身上：读挂 public，写挂 auth（Bearer 那套上周已建）
func (h *UserHandler) Register(public, auth *gin.RouterGroup) {
    public.GET("/users", h.List)
    public.GET("/users/:id", h.Get)
    auth.POST("/users", h.Create)
    auth.PUT("/users/:id", h.Update)
    auth.DELETE("/users/:id", h.Delete)
}

// parseID 同包函数，day3 的 ArticleHandler 直接复用，不要再抄一份
func parseID(c *gin.Context) (uint, bool) {
    id, err := strconv.ParseUint(c.Param("id"), 10, 64)
    if err != nil || id == 0 {
        response.Fail(c, http.StatusBadRequest, response.CodeInvalidParam, "id 必须是正整数")
        return 0, false
    }
    return uint(id), true
}

func (h *UserHandler) List(c *gin.Context) {
    users, err := h.svc.List()
    if err != nil {
        response.Fail(c, http.StatusInternalServerError, response.CodeInternal, "服务繁忙")
        return
    }
    response.OK(c, users)
}

func (h *UserHandler) Get(c *gin.Context) {
    id, ok := parseID(c)
    if !ok { return }
    u, err := h.svc.Get(id)
    switch {
    case service.IsNotFound(err):
        response.Fail(c, http.StatusNotFound, response.CodeUserNotFound, "用户不存在")
    case err != nil:
        response.Fail(c, http.StatusInternalServerError, response.CodeInternal, "服务繁忙")
    default:
        response.OK(c, u)
    }
}

func (h *UserHandler) Create(c *gin.Context) {
    var req dto.CreateUserReq
    if err := c.ShouldBindJSON(&req); err != nil {
        response.Fail(c, http.StatusBadRequest, response.CodeInvalidParam,
            "username(≥3)/password(≥8) 不合规")
        return
    }
    u, err := h.svc.Create(req)
    switch {
    case errors.Is(err, service.ErrUsernameExists):
        response.Fail(c, http.StatusConflict, response.CodeUserExists, err.Error())
    case err != nil:
        response.Fail(c, http.StatusInternalServerError, response.CodeInternal, "服务繁忙")
    default:
        response.Created(c, u)   // 201 + code 0
    }
}

func (h *UserHandler) Update(c *gin.Context) {
    id, ok := parseID(c)
    if !ok { return }
    var req dto.UpdateUserReq
    if err := c.ShouldBindJSON(&req); err != nil {
        response.Fail(c, http.StatusBadRequest, response.CodeInvalidParam, "参数不合规")
        return
    }
    u, err := h.svc.Update(id, req)
    switch {
    case service.IsNotFound(err):
        response.Fail(c, http.StatusNotFound, response.CodeUserNotFound, "用户不存在")
    case err != nil:
        response.Fail(c, http.StatusInternalServerError, response.CodeInternal, "服务繁忙")
    default:
        response.OK(c, u)
    }
}

func (h *UserHandler) Delete(c *gin.Context) {
    id, ok := parseID(c)
    if !ok { return }
    if err := h.svc.Delete(id); err != nil {
        if service.IsNotFound(err) {
            response.Fail(c, http.StatusNotFound, response.CodeUserNotFound, "用户不存在")
            return
        }
        response.Fail(c, http.StatusInternalServerError, response.CodeInternal, "服务繁忙")
        return
    }
    response.OK(c, gin.H{"deleted": id})
}

注意 service 里那行 Role: model.RoleUser 和 dto.CreateUserReq 里没有 role 字段这件事：这是第 2 周 Role string + if role == "" { role = "user" } 那三行的替身。基准里 role 是 tinyint，Go 零值 0 恰好就是 RoleUser，所以默认值由类型系统给，不由入参给——外部无论如何传 "role":1，注册接口都造不出管理员。第 8 周讲权限时才需要「改角色」这条通道，届时它是独立的 PATCH /api/v1/users/:id/role + 只有管理员能调。

练习 3：ID 参数解析与 404（25 分钟）

把 :id 转成 uint 交给 repository，非法 id 返回 400、找不到返回 404 + code:1001，并且必须走 response 包（不许出现 c.JSON(gin.H{...})）。做完用 grep -rn "c.JSON" internal/handler 自查，应当零命中。

if !ok { return }

// ② 交给 service（不是 db！handler 里没有 *gorm.DB 这个字段）

参考答案要点：① strconv.Atoi 返回 int，而主键是 uint——负数会绕成一个巨大的正数（uint(-1) = 18446744073709551615），所以要么用 ParseUint(s, 10, 64)（负号直接报错，天然安全），要么先判负再转；本手册用前者。② ParseUint 转 uint 时位宽写 64，写 32 的话在 64 位机上会 out of range。③ id == 0 要单独挡：/users/0 是合法数字但库里不可能有 0 号，直接 400 比让它去查库再 404 更诚实。④ 三个分支每条都要 return，忘了就会出现「404 之后又写了一次 200」的双响应，Gin 会在日志里打 panic: http: multiple response.WriteHeader calls。

坑现象正确姿势
把 db 当一次性对象上一条链式的 Where 神秘地影响了下一条查询每次查询从 r.db 起链；若复用需 db.Session(&gorm.Session{})

Save 传了零 ID本意更新，结果插了一条新行先 First 拿到带 ID 的对象再 Save，或用 Updates

用 err == gorm.ErrRecordNotFound错误被包装后判断失效，500 满天飞errors.Is(err, gorm.ErrRecordNotFound)

Where 传结构体用了零值想查 views=0 却查出全部零值条件用 map 或字符串占位
