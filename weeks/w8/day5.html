1. 本周版发布流水线：六步，一步都别并

这周加了两对迁移（000005_add_comments 建评论表、000006_add_avatar_to_users 给 users 补 avatar 列）、一个上传目录、一组 admin 接口。新代码依赖新列，老库没有列——所以顺序不能错：先备份、先迁移、再起重版本、健康检查过了才算完。第 7 周那五步（pull → migrate → up -d --build → logs → prune）继续用，今天在前面插两步、在后面补一步：

shell（服务器 /opt/goblog，发布六步）# ① 拉代码
$ cd /opt/goblog && git pull

# ② 备份数据库：让变量在「容器里」展开（第 1 天承诺过的那一种）
$ mkdir -p /root/backups
$ dc exec -T mysql sh -c \
    'exec mysqldump -u"$MYSQL_USER" -p"$MYSQL_PASSWORD" --single-transaction "$MYSQL_DATABASE"' \
    > /root/backups/goblog_pre_w8_$(date +%F).sql
$ ls -lh /root/backups/goblog_pre_w8_$(date +%F).sql   # 尺寸不为 0 才算备份成功，别信「命令没报错」

# ③ 备份上传卷（mysqldump 只保数据，图片是另一条命）
$ docker run --rm -v goblog_uploads:/d:ro alpine tar czf - -C /d . \
    > /root/backups/uploads_$(date +%F).tar.gz

# ④ 迁移先跑（--profile tools 是一次性服务的门票）
$ docker compose -f docker-compose.yml -f docker-compose.prod.yml --env-file .env \
    --profile tools run --rm migrate up
$ docker compose ... --profile tools run --rm migrate version      # 期望：6

# ⑤ 重建并滚动起来（nginx.conf 本周改过，frontend 也必须重建）
$ dc up -d --build backend frontend
$ docker image prune -f                                            # 清掉被替换下来的旧镜像

# ⑥ 健康检查：三条都要绿
$ dc ps                                                            # 四个业务容器全 (healthy)
$ dc exec backend sh -c 'wget -qO- http://127.0.0.1:8080/health'
{"code":0,"message":"ok","data":{"status":"ok"}}                # 容器内自检：DB 真的 Ping 通了
$ curl -s https://blog.example.com/health                          # 全链路：caddy → nginx → Go
{"code":0,"message":"ok","data":{"status":"ok"}}                # ← 出现 <!doctype html> 就是 W7D5 那条 location = /health 丢了

② 那行的引号是全部技术含量。外层双引号让宿主机展开 $(date +%F)（文件名要落在宿主机），里层单引号让 $MYSQL_USER / $MYSQL_PASSWORD 交给容器里的 sh 展开（这三个变量是 compose 注进 mysql 容器的，宿主机上根本没有）。写成 mysqldump -h127.0.0.1 -uroot -p"$DB_PASS" blog 会连不上：127.0.0.1 在宿主机指向你自己，而 mysql 的 3306 在生产 compose 里没有对宿主机映射；-uroot -p"$DB_PASS" 更是把「应用密码」当成 root 密码用。判据一句话：在宿主机展开的变量，只能是宿主机上真实存在的东西。

compose 里 backend 的 healthcheck 早在第 7 周 D3 就配好了（wget -qO- http://127.0.0.1:${PORT:-8080}/health）。今天要做的只有一件事——确认它打的是 /health：

docker-compose.yml（backend 节选，只做一处订正：/healthz → /health）  backend:
    build: ./backend
    environment:
      UPLOAD_DIR: /app/uploads        # ← D2 加的：覆盖 .env 里的 ./uploads
    volumes:
      - uploads:/app/uploads
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://127.0.0.1:${PORT:-8080}/health"]
      interval: 15s

配套的 Go 端点：查一次 DB 才算真健康，且响应体必须是全站那个统一 Body（第 2 周定的 response.Body）：

cmd/server/main.go（把第 3 周那行 /health 升级成带 DB 探活的版本）// 需要 import："net/http"、gin、goblog/pkg/response
r.GET("/health", func(c *gin.Context) {
    sqlDB, err := db.DB()                       // 拿到底层连接池才能 Ping（第 3 周 D5 的手法）
    if err != nil || sqlDB.Ping() != nil {
        // HTTP 状态按语义细化成 503（让 healthcheck / caddy 立刻看出来），
        // 业务码仍走全站那张表：5000。两层各管各的，别为了「统一」把 503 改成 200。
        response.Fail(c, http.StatusServiceUnavailable, 5000, "db down")
        return
    }
    response.OK(c, gin.H{"status": "ok"})       // → {"code":0,"message":"ok","data":{"status":"ok"}}
})
// 版本信息别塞进 /health（那是探针，要稳定便宜）；要给人看就做 GET /api/v1/admin/stats（D1）。

回滚预案也要一句话写死：新版本 500 飙升时 git checkout 上一个 tag && dc up -d --build backend frontend；但数据库不自动回滚——migrate down 会 DROP TABLE comments，评论数据当场没了。所以第 ② 步那份备份不是仪式，是救命的；真要退结构，先用备份重建库，再 migrate force <旧版本号> 把记录号对齐。

2. 环境变量收口：config.go 才是唯一事实源

D2 用 diff 加过两个键，今天把它们落成完整代码，并把 README 的表按 config.go 逐字抄——键名这件事上，README 抄代码，不是代码抄 README。

internal/config/config.go（W4 建、W7D4 加 AutoMigrate、本周加两行：整块对齐版）type Config struct {
    Port     string   // PORT，监听时拼成 ":8080"
    GinMode  string   // GIN_MODE：debug / release
    DSN      string   // 由 DB_HOST/DB_PORT/DB_USER/DB_PASS/DB_NAME 拼出，调用方不知道有几段
    JWTSecret        string   // JWT_SECRET（access）
    JWTRefreshSecret string   // JWT_REFRESH_SECRET（refresh）
    AutoMigrate      bool     // AUTO_MIGRATE：W7D4 的开关，生产必须 false
    UploadDir        string   // UPLOAD_DIR：上传落盘根目录（W8D2）
    CORSOrigin       string   // CORS_ORIGIN：允许的前端源，逗号分隔（W8D2）
}

func Load() (Config, error) {
    var c Config
    _ = godotenv.Load()                       // 文件不存在不报错；真实环境变量优先级更高

    // 必填：一次把缺的全列出来（fail-fast，别等第一个请求）
    if miss := missingEnv("DB_USER", "DB_PASS", "DB_NAME", "JWT_SECRET", "JWT_REFRESH_SECRET"); len(miss) > 0 {
        return c, fmt.Errorf("缺少环境变量：%s", strings.Join(miss, "、"))
    }

    c.Port = getEnv("PORT", "8080")
    c.GinMode = getEnv("GIN_MODE", "debug")
    c.JWTSecret = os.Getenv("JWT_SECRET")
    c.JWTRefreshSecret = os.Getenv("JWT_REFRESH_SECRET")
    c.AutoMigrate = getEnv("AUTO_MIGRATE", "false") == "true"

    // 上传目录：本地裸跑落 ./uploads，容器里由 compose 的 environment 覆盖成 /app/uploads。
    // 同一条绝对/相对纪律也给了 CORS_ORIGIN：默认值是第 6 周 Vite 的端口，生产同域部署用不上。
    c.UploadDir = getEnv("UPLOAD_DIR", "./uploads")
    c.CORSOrigin = getEnv("CORS_ORIGIN", "http://localhost:5173")

    host := getEnv("DB_HOST", "localhost")
    port := getEnv("DB_PORT", "3306")
    c.DSN = fmt.Sprintf("%s:%s@tcp(%s:%s)/%s?charset=utf8mb4&parseTime=True&loc=Local",
        os.Getenv("DB_USER"), os.Getenv("DB_PASS"), host, port, os.Getenv("DB_NAME"))
    return c, nil
}

// getEnv 可选配置：没设就用默认值（W4D3 就有，两个新键直接复用它）
func getEnv(key, fallback string) string {
    if v := os.Getenv(key); v != "" { return v }
    return fallback
}

本周新键只有这两个。第 7 周清掉过一轮旧别名（MYSQL_DSN、SERVER_PORT、DB_PASSWORD），今天写 README 时别把它们请回来——env 键名一改，config.go、.env.example、compose、CI、README 五处都要跟着改，漏一处就是一次「本地明明好的」事故。自检命令：grep -rn 'MYSQL_DSN\|SERVER_PORT\|DB_PASSWORD' . --include='*.go' --include='*.yml' --include='*.md' --include='.env*'，结果应为空。

3. nginx：改的是 W7 那份 frontend 镜像里的 default.conf

先纠正一个旧说法：本课没有独立的 nginx/conf.d/blog.conf，也没有在宿主机装 nginx。第 7 周 D2 定的结构是——仓库里唯一的 nginx 文件是 frontend/nginx.conf，它被 frontend/Dockerfile 里那行 COPY nginx.conf /etc/nginx/conf.d/default.conf 烧进镜像，宿主机上不存在这份配置。所以今天的改动全是在那份文件上做增量，而且改完必须重建 frontend 镜像（reload 不够：文件在镜像层里）。

frontend/nginx.conf（D2 已加的两段 + 今天补的 /swagger，其余 W7 原样不动）server {
    listen 80;

    # ── D2 已加（上传必经）：默认 1m 会把 5MB 图挡在 nginx 层，响应体还是 nginx 的 HTML ──
    client_max_body_size 12m;

    # ── W7D5 已加：精确匹配，抢在 location / 前面，专治假绿探针 ──
    location = /health {
        proxy_pass http://backend:8080;
        access_log off;
    }

    # ── D2 已加：图片由 nginx 直接 sendfile，不穿 Go 进程。
    #    /var/www/uploads 就是 compose 里那个只读挂给 frontend 的挂载点，两者必须对上 ──
    location /uploads/ {
        alias /var/www/uploads/;
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    location /api/ {
        proxy_pass http://backend:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # ── 今天新增：Swagger 反代（第 6 节会用到）。不带结尾斜杠 → 后端收到的仍是 /swagger/xxx
    location /swagger/ {
        proxy_pass http://backend:8080;
        # 生产保护三选一：① auth_basic（下面两行）；② 只在 README 放 doc.json 链接；③ 干脆不配这条 location
        auth_basic           "goblog docs";
        auth_basic_user_file /etc/nginx/.htpasswd;
    }

    location / {
        root /usr/share/nginx/html;
        try_files $uri $uri/ /index.html;
    }
}
shell（配置改完：本地提交 → 服务器重建，reload 不算）$ # 本机：改 frontend/nginx.conf → git commit → git push
$ # 服务器：
$ git pull
$ dc up -d --build frontend              # ← 只有 build 会把新的 nginx.conf 拷进新镜像层
$ docker compose exec frontend nginx -t  # 语法自检：先在这里红，好过在浏览器里红
$ # 加 Basic Auth 的话，密码文件也要进镜像或挂进去：
$ #   printf 'docs:%s\n' "$(openssl passwd -apr1 '读文档的密码')" > frontend/nginx.htpasswd
$ #   Dockerfile 里补一行 COPY nginx.htpasswd /etc/nginx/.htpasswd（改了同样要 --build）
$ curl -s -o /dev/null -w "%{http_code}\n" https://blog.example.com/swagger/index.html
401                                     # 加了 auth_basic 就是这个；未加是 200

三件事按这个顺序记：① 配置在镜像里 → 改完必须 --build；② 校验先跑 nginx -t（在容器里跑，别在宿主机跑——宿主机没装 nginx）；③ alias 的路径是「容器内路径」，写宿主机的 /opt/goblog/uploads 或旧稿的 /data/blog/uploads/ 都是 404/200-但裂图。本课 uploads 用的是 named volume goblog_uploads，宿主机上没有对应目录，用 docker volume inspect goblog_uploads 看它真正落在 /var/lib/docker/volumes/…/_data。

## 环境变量
| 变量 | 示例 / 默认 | 说明 |
|---|---|---|
| `PORT` | 8080 | Go 监听端口（拼成 `:8080`） |
| `GIN_MODE` | release | debug / release；compose 里 override 成 release |
| `DB_HOST` / `DB_PORT` | mysql / 3306 | 容器内是服务名 `mysql`，本地裸跑是 `127.0.0.1` |
| `DB_USER` / `DB_PASS` / `DB_NAME` | goblog / …… / goblog | 后端连接串的五段之二，DSN 由 config 拼装 |
| `JWT_SECRET` | `openssl rand -hex 32` | access token 签名密钥，泄露 = 全体可伪造 |
| `JWT_REFRESH_SECRET` | 同上，另取一个 | 与 access 分开，防两种 token 互相顶替 |
| `AUTO_MIGRATE` | false（生产） | 生产只认迁移文件；true 只给本地/CI（W7D4 的开关） |
| `UPLOAD_DIR` | ./uploads（本地） | 容器里 compose 覆盖成 `/app/uploads`，与卷挂载点一致 |
| `CORS_ORIGIN` | http://localhost:5173 | 允许的前端源，逗号分隔；同域部署用不上 |

> compose 里 MySQL 自己那四个 `MYSQL_*` 变量（`MYSQL_ROOT_PASSWORD`、`MYSQL_DATABASE`、
> `MYSQL_USER`、`MYSQL_PASSWORD`）是 mysql 官方镜像的约定，与上面后端读的键**分两段管理**，
> compose 文件的注释里已经区分开。

5. API 文档两种做法（一）：手写 markdown 表

全量 20 多个端点，先用最笨但最清楚的方式留一份速查表 docs/api.md——它同时是给面试官看的「接口设计能力」证明：

docs/api.md（节选）统一响应：`{ "code": 0, "message": "ok", "data": {} }`
业务码与 HTTP 状态是两层：HTTP 给基础设施看（网关/重试/healthcheck），code 给前端拦截器看。

| code | 含义 | HTTP |
|---|---|---|
| 0 | 成功 | 2xx |
| 1001 | 资源不存在（通用，NoRoute 也发它） | 404 |
| 1002 | 密码错误 | 401 |
| 1003 | 权限不足 / 禁止 | 403 |
| 1004 | 参数错误 | 400 |
| 1005 | 未认证 / token 无效 | 401 |
| 1006 | 用户名已存在（邮箱已注册共用此码，靠 message 区分） | 409 |
| 2001 | 文章不存在 | 404 |
| 5000 | 服务器内部错误 | 500 |

鉴权：除标注「公开」外均需 `Authorization: Bearer <access>`；refresh 走请求体 `refresh_token`。
列表统一形状：`{ list, total, page, size, total_page }`。

| 方法 | 路径 | 鉴权 | 说明 | 关键参数 |
|---|---|---|---|---|
| GET | /health | 公开 | 健康探针（带 DB Ping，无 /api/v1 前缀） | — |
| POST | /api/v1/auth/register | 公开 | 注册 | username, password（≥8 位，含字母与数字） |
| POST | /api/v1/auth/login | 公开 | 登录，返回双 token + user(含 role) | username, password |
| POST | /api/v1/auth/refresh | refresh_token | 换发新 access | refresh_token |
| GET | /api/v1/users/me | 登录 | 当前用户（前端 refreshUser 也用它） | — |
| GET | /api/v1/articles | 公开 | 分页列表 | page, size, keyword |
| POST | /api/v1/articles | 登录 | 发文（标题 ≤120，可带封面） | title, content, cover_image |
| GET | /api/v1/articles/:id | 公开 | 详情（浏览量 +1） | — |
| PUT | /api/v1/articles/:id | 作者或管理员 | 编辑（D4 的 CanModerate） | title, content |
| DELETE | /api/v1/articles/:id | 作者或管理员 | 删除（软删） | — |
| POST | /api/v1/uploads/avatar | 登录 | 头像（multipart 字段 file，≤5MB） | file |
| POST | /api/v1/uploads/cover | 登录 | 文章封面 | file |
| GET | /uploads/... | 公开 | 静态回显（生产由 nginx alias 直出） | — |
| GET | /api/v1/articles/:id/comments | 公开 | 评论列表（带作者，分页） | page, size |
| POST | /api/v1/articles/:id/comments | 登录 | 发评论 | content ≤500 字 |
| DELETE | /api/v1/comments/:id | 作者或管理员 | 删评论 | — |
| GET | /api/v1/admin/users | 管理员 | 用户分页列表 | page, size(≤50) |
| DELETE | /api/v1/admin/articles/:id | 管理员 | 强制下架 | — |
| GET | /api/v1/admin/stats | 管理员 | 用户 / 文章 / 评论计数 | — |

表里三处「本周才知道的事」值得在面试里主动讲：① PUT/DELETE /articles/:id 的鉴权列写「作者或管理员」，实现是 service.CanModerate(role, uid, ownerID) 这一个纯函数（D4），而不是散在各 handler 里的四行 if；② 1001 是通用「资源不存在」（评论、用户都用它），2001 才是文章专用；③ 上传的 400 文案来自 upload.Check 的四个分支，每条都有对应单测。

6. API 文档两种做法（二）：swaggo 注解生成 Swagger

手写表清楚但不能交互。用 swaggo/swag：在 handler 上写注释注解，命令行扫代码生成 OpenAPI 文档，再挂一条 /swagger/*any 路由得到可以「Try it out」的网页。五分钟上手：

shell（在 backend/ 目录下）$ go install github.com/swaggo/swag/cmd/swag@latest
$ export PATH="$(go env GOPATH)/bin:$PATH"   # ← 关键一句：swag 落在 GOPATH/bin，不加这行就是 command not found
$ swag init -g cmd/server/main.go -o docs/swagger   # 生成 docs/swagger/{docs.go,swagger.json,swagger.yaml}
# 报「swag: command not found」就是漏了上面那句 export；把它写进 ~/.zshrc 一劳永逸。
# 生成物必须提交进仓库（下一节的 _ import 依赖它，否则别人 clone 下来编译不过）。
internal/handler/admin.go（注解示例：给 D1 的 ListUsers 加）// ListUsers 管理员用户列表
//
//	@Summary		[admin] 用户分页列表
//	@Description	只返回 UserBrief（不含 password），size 上限 50 防拖全表
//	@Tags			admin
//	@Security		BearerAuth
//	@Produce		json
//	@Param			page	query		int	false	"页码，默认 1"	default(1)
//	@Param			size	query		int	false	"每页条数，默认 10，上限 50"	default(10)
//	@Success		200		{object}	response.Body{data=dto.PageResult{list=[]handler.UserBrief}}
//	@Failure		401		{object}	response.Body	"code:1005 未认证"
//	@Failure		403		{object}	response.Body	"code:1003 权限不足"
//	@Router			/api/v1/admin/users [get]
func (h *AdminHandler) ListUsers(c *gin.Context) { /* …… D1 + D3 的实现，原样不动 …… */ }

// 注意三件事：
// ① 注解必须紧贴同一个函数的 doc comment（中间不能有空行隔开它和 func），且每行都以 // 开头；
// ② 接收者是 *AdminHandler，别顺手写成别的 handler——注解扫的是「这个函数」；
// ③ 返回类型指向 D3 补的 UserBrief，而不是 model.User：password 字段带 json:"-"，
//    但让 Swagger 上出现 password 这个键名本身就是噪音。
cmd/server/main.go（挂载 + 全局注解）import (
    swaggerfiles "github.com/swaggo/files"
    ginswagger   "github.com/swaggo/gin-swagger"
    _            "goblog/docs/swagger"   // swag init 的生成包，只需 _ 导入（模块名是 goblog，不是 blog）
)

// @title			GoBlog API
// @version		1.0
// @description	Gin + GORM + React 全栈博客（含 RBAC、评论与文件上传）
// @BasePath		/
// @securityDefinitions.apikey	BearerAuth
// @in							header
// @name						Authorization
↑ 这七行必须贴在 main 函数的 doc comment 上（swag 的全局信息只认它），中间别插别的注释
func main() {
    // …… 接着 W7 的既有装配：config.Load → database.New → 中间件 → api / mine / admin 三个组 ……
    r.GET("/swagger/*any", ginswagger.WrapHandler(swaggerfiles.Handler))
    // ↑ 放在 r.Run 之前；和 /health 一样不在 /api/v1 组里——文档路由不是业务接口
}

访问：http://localhost:8080/swagger/index.html 是交互页（Authorize 里填 Bearer eyJ…，Try it out 会真的调你的接口），http://localhost:8080/swagger/doc.json 是 OpenAPI 的 JSON 源（可导入 Postman）。@BasePath 写 / 而不是 /api/v1，因为注解里每条 @Router 都已经写了全路径，两处都拼就会生成 /api/v1/api/v1/…。

三条提醒：① 每次改注解后重跑 swag init 并把生成物提交，否则 CI 里那句 go build ./... 会因为 goblog/docs/swagger 不存在而红；② 上线给 Swagger 加 Basic Auth（第 3 节那段 location）或只放 doc.json——公开可交互的 API 控制台等于给攻击者发了张地图；③ docs/ 这个目录名和手写文档的 docs/api.md 同层，生成物建议只 -o docs/swagger，别把 docs.go 甩到 docs/ 根下和 md 混在一起。

今日练习

练习 1：按六步流水线重新发布（60 分钟）

把第 1 节流程在云服务器完整执行一次（这周代码还没上线的话，现在正是时候）。要求逐步留证据：备份文件大小、migrate version 输出 6、dc ps 全 healthy、/health 那行 JSON、公网打开管理后台。

参考答案：高频翻车点依次为——① 服务器 .env 忘了加新变量，backend 起了又 crash，dc logs backend --tail 30 看到「缺少环境变量：…」（其实 UPLOAD_DIR/CORS_ORIGIN 有默认值不会 crash，真会 crash 的是 JWT_*）；② docker compose run --rm migrate up 少了 --profile tools → no such service: migrate；③ 迁移没跑就起新代码 → Error 1054: Unknown column 'avatar' in 'field list'，或评论接口 500 报 Table 'goblog.comments' doesn't exist（D3 那个「小号被跳过」的坑，用 down 1 → force 4 → up 在测试库上救）；④ 只 restart frontend 没 --build → /uploads/ 仍然 404（配置在旧镜像层里）；⑤ uploads 卷挂错路径 → 现象是「本地有图线上没图」，按 D2 练习 2 的对照法排查。

练习 2：README + api.md 成稿（60 分钟）

按模板写完整 README.md 与 docs/api.md，截图四张（首页 / 详情带评论 / 管理后台 / Swagger 页），并把「本地一键启动」在全新目录 git clone 后验证一遍。

参考答案：自检四问：新人能在 3 条命令内跑起来吗？mermaid 图在 GitHub 上渲染出来了吗（围栏配平了吗）？环境变量表里每个变量都能在 config.go 找到对应读取点、且没有一个旧别名（SERVER_PORT/DB_PASSWORD/MYSQL_DSN）？/health 与 /healthz 是否全站只剩前者？四问有一个「否」就回炉。

练习 3：swaggo 上线（45 分钟）

给 admin 三个接口 + 上传两个接口 + 登录补注解，swag init 生成、挂载路由、打开 /swagger/index.html，用 Authorize 填 admin token 后 Try it out 调通 GET /api/v1/admin/stats；最后用普通用户 token 再调一次，观察返回。

参考答案（要点）：① 装与生成：go install github.com/swaggo/swag/cmd/swag@latest 之后必须先 export PATH="$(go env GOPATH)/bin:$PATH" 才能敲 swag；在 backend/ 目录跑 swag init -g cmd/server/main.go -o docs/swagger，看到 create docs.go, swagger.json, swagger.yaml successfully。② 挂载：_ "goblog/docs/swagger" 那一行少 import 就报 undefined: docs.SwaggerInfo（gin-swagger 找不到文档实例，页面白屏或 failed to load config）。③ 验收三条：左侧列表里 admin tag 下三条端点齐全、@Router 路径是 /api/v1/… 而不是 /api/v1/api/v1/…（说明 @BasePath 拼重了）、Try it out 用 admin token 得 200 且响应体是 {"code":0,"message":"ok","data":{…}}。④ 那第二条才是本练习的重点：普通用户 token 调 stats 得 403 + code:1003，Swagger 页面会照原样把 body 显示出来——这就是「文档不是装饰，它是权限的可见证据」。如果这里返回 200，说明 admin 组漏挂了 RequireRole，先去修 D1 的路由组再回来。⑤ 上线保护：按第 3 节加 auth_basic（配 openssl passwd -apr1 生成 htpasswd）或删掉那条 location，只留 README 里的 doc.json 链接；git push 前确认生成物已提交、go build ./... 在干净 clone 里过。

练习 4：真人验收（30 分钟 + 等待）

把 https://你的域名 + README 链接发给一位朋友（最好是同行），话术就一句：「我做的博客，帮我 5 分钟随便点点，挑一个 bug 或一个不爽」。把反馈原话记进 README 下方「Known issues / Feedback」小节——这一条真实反馈就是你面试时「用户视角」的证据。

参考答案：非技术朋友最常见的三条反馈：图片上传没有进度条（其实网络很快，但没转圈就是「感觉坏了」）、评论区没有排版、移动端表格溢出。修其中成本最低的一条并回复对方——完成一次真实的用户反馈闭环。
