毕业常见疑问（FAQ）

Q：要不要现在就学 Kubernetes？A：不要。你的 compose 单机编排正在服务真实流量之前都够用；先把「一个服务的迭代闭环」（改代码 → 迁移 → 发布 → 观测 → 回滚）跑熟，K8s 解决的是十几个服务的问题，早学等于空转。

Q：简历上这个项目会不会太「教程感」？A：项目本身确实常见，不常见的是你带上了它：BUGLOG 的根因分析、上传的路径穿越防护、role 进 JWT 的一致性取舍、真实用户反馈记录——面试讲这些细节，就不像教程，像工程。

Q：接下来投什么岗位？A：Go 后端 / 全栈向的初级岗与「前端转后端」是你的差异化叙事：简历用 D5 那句作品集描述，面试主动把「你懂前端」转成「你能独立交付端到端功能」——这是八周训练的真正产出。

Q：项目还要继续加功能吗？A：优先做「减法收尾」：删掉没验证的 README 句子、补齐空状态与错误提示、把 CI 里 go test -race 跑绿。功能膨胀不如工程质量闭环，一个没维护的巨型项目不如一个精悍可跑的。

三道面试题预演（全部来自你这八周的代码）

答辩最后一步：把三句话改成你自己的话，录音听一遍。能讲顺，这个八周就真赚到了。

题 1：「你的 JWT 里放了什么？被删号/提权了怎么办？」

要点：Claims 放 uid+role（D1）；access 15 分钟把风险窗口封顶；高危的 admin 接口再按 uid 查库复核 role 真值（方案 C）；封号则 Auth 中间件查 users 不存在/已软删直接 401。

题 2：「文件上传你们怎么防攻击？」

要点：三件套（扩展名白名单 + http.DetectContentType 魔数嗅探 + 大小与 0 字节限制）；服务端随机文件名，原始名只借 filepath.Ext 的扩展名，杜绝 ../ 穿越；落盘目录挂在数据卷上且对 Nginx 只读；.dockerignore 防用户数据进镜像。

题 3：「给一个已有线上库的表加字段，流程是什么？」

要点：改 model → 写成对迁移（加列带 NOT NULL DEFAULT 不锁读写心智、建索引、回填 UPDATE）→ 测试库 up/down 各跑一遍 → 发布六步中 migrate 先于新版本启动 → 备份在前、健康检查在后（D1 + D5）。

上线后的运维最小日常

作品上线不是终点，是「有人替你值班」的起点。每周花 10 分钟过一遍这四条命令，项目就不会烂掉：

shell（每周一巡）$ ssh your-server
$ docker compose ps                      # 1) 四个容器都是 Up (healthy)？
$ docker compose logs backend --since 24h | grep -E '"level":"ERROR"|DATA RACE'
                                         # 2) 24 小时内的错误与竞态，有则记 BUGLOG
$ df -h /var/lib/docker | tail -1        # 3) 磁盘：uploads 和镜像会慢慢吃满 40G 小机器
$ du -sh /opt/blog/uploads               # 4) 上传目录体积，配 cron 定时 mysqldump + rsync 备份

# 发新版本永远走 D5 六步；巡完发现的小问题，当场修掉最好不超过 20 分钟。
症状大概率原因（本周坑表返场）一句话处置
图片忽新忽旧、重建后老图复活uploads 没挂卷或被镜像里旧内容盖回查 compose volumes 与 .dockerignore 是否都有 uploads
管理员功能时灵时不灵旧 token 的 role 快照没过期重新登录；或 admin 接口改查库复核（方案 C）
admin/users 偶发 500page/size 非法值未兜底回到 D1 handler 补边界，加 httptest 用例锁死
上传大图报 413Nginx client_max_body_size 默认 1m改 8m 后 reload，见 D5 最终版 conf

结营寄语

八周前你的目标是「能独立上手项目开发」；现在你手里有一个带认证、带权限、带上传、带测试、带文档、跑在公网上的作品，以及一条从浏览器到数据库再到容器的完整排查链路经验。更重要的是，你已经验证了自己能从「写 JS 的人」切换成「写 Go 后端的人」——这个切换能力比任何单个框架都值钱。

接下来最危险的事是停下来收藏教程。后端是手艺活，保住手感的方式在下三条路线里：要么把现在的系统接到真实流量下迭代，要么把它拆硬一点，要么把它交出去让别人 review。

下一步路线（每条一句话，选一条走一个月）

  • 微服务初探：把博客的「上传」拆成独立服务，用 gRPC 或内部 HTTP 打通，体会服务发现、配置中心与分布式 tracing 为什么会存在——先读一两个「单体拆到位」的实践，而不是上来就装 K8s。
  • Redis 缓存与高性能：给文章列表和统计接口加 Redis 缓存 + 过期策略，用 ab 或 vegeta 压出前后 QPS 对比，顺手理解缓存穿透/击穿的防御——这是简历上最有说服力的一行数字。
  • 开源贡献：给你项目用到的任意库（Gin / GORM / swaggo）提第一个 PR——从文档拼写错误修起，走完 issue → PR → review → merge 全流程，学会在公共代码库里协作。

三条全部做完的形态，恰好对应中后端岗位 JD 上最常见的三句话：能拆服务、能扛性能、能协作。从哪条开始都行，别从「再学一门语言」开始。
