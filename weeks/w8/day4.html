1. 发布前测试清单：六大类逐格验证法

别漫无目的地乱点。把功能切成六个格子，每格写清「操作 → 预期」，手动过一遍（浏览器 + curl 各半），这就是小团队最低成本的发布回归。第 8 周新增的 RBAC 与上传务必占格。

类别验证项（操作 → 预期）常用工具
① 接口GET /health → {"code":0,"message":"ok","data":{"status":"ok"}}；每个端点正常调用 → 200/201 + code:0；必填缺失 → 400 + 1004；不存在的资源 → 404 + 1001（文章专属 2001）curl + jq
② 权限未登录写操作 → 401+1005；非作者改别人的文 → 403+1003；普通用户进 /admin/* → 403+1003；管理员全通 → 200；refresh token 冒充 access → 401+1005curl（三种 token 各备一份）
③ 上传真图 → 成功且重启容器后仍可访问；伪 PNG（文本改名）→ 400「文件真实类型不是图片」；0 字节 → 400「文件为空」；6MB → 400「文件超过 5MB 限制」；.svg → 400「仅支持 jpg/png/gif/webp」curl -F + 手工改名的文本文件
④ 登录错误密码 → 401 + code:1002；access 过期 → 前端静默 refresh 无感；refresh 过期 → 跳 /login?redirect=…；退出后 localStorage 三个键全空浏览器 DevTools（改 JWT_SECRET 重启可人造「过期」）
⑤ 分页page 超界 → 空 list 不报错；size=0／负数／非数字 → 兜底默认值；admin 的 size=999 → 回落到 10；total 恒正确curl 拼参数
⑥ 搜索关键词命中 → 只出匹配项；特殊字符 % _ ' → 不报 500；空串 → 返回全量列表浏览器搜索框 + curl

// CanModerate 回答「当前用户能不能处置这条资源」：
// 等级够 RoleAdmin 的能处置任何人的；否则只有作者本人。
// 用 >= 而不是 ==，和 D1 的 RequireRole 同一个「等级」口径，将来加 RoleSuperAdmin 不用回来改。
// 它是纯函数：不查库、不碰 gin.Context，所以能脱离数据库被完整测试（今天第 2 节末尾）。
func CanModerate(role model.Role, uid, ownerID uint) bool {
    if uid == 0 {
        return false   // 拿不到身份就一律拒绝：0 不是合法用户 ID，别让它和脏数据的 owner 撞上
    }
    if role >= model.RoleAdmin {
        return true
    }
    return uid == ownerID
}

internal/pkg/upload/validate_test.go（整份复制即可编译，与被测代码同包）package upload

import (
    "strings"
    "testing"
)

// pngHead 造一个够 DetectContentType 认出 image/png 的头部：8 字节 PNG 签名 + 一堆零
// 真文件不需要，Check 只看传入的前 512 字节，这就是把它抽成纯函数的回报。
func pngHead() []byte {
    return append([]byte{0x89, 'P', 'N', 'G', '\r', '\n', 0x1a, '\n'}, make([]byte, 512)...)
}

func TestCheck(t *testing.T) {
    png := pngHead()

    cases := []struct {
        name    string
        ext     string
        size    int64
        head    []byte
        wantErr bool
        msg     string   // 可选：顺手断言文案，防止「拒是拒了，但用户看不懂」
    }{
        {"真 PNG", ".png", int64(len(png)), png[:512], false, ""},
        {"0 字节", ".png", 0, nil, true, "文件为空"},
        {"文本改名 .png", ".png", 9, []byte("just text"), true, "文件真实类型不是图片"},
        {"脚本改名 .png", ".png", 19, []byte("#!/bin/sh\nexit 1"), true, "文件真实类型不是图片"},
        {"合法内容坏后缀 .svg", ".svg", int64(len(png)), png[:512], true, "仅支持"},
        {"超 5MB", ".png", 6 << 20, png[:512], true, "超过"},
    }
    for _, tc := range cases {
        t.Run(tc.name, func(t *testing.T) {
            err := Check(tc.ext, tc.size, tc.head)
            if (err != nil) != tc.wantErr {
                t.Fatalf("Check(%q, %d) err = %v, wantErr = %v", tc.ext, tc.size, err, tc.wantErr)
            }
            if tc.msg != "" && !strings.Contains(err.Error(), tc.msg) {
                t.Errorf("错误文案 = %q，想包含 %q", err.Error(), tc.msg)
            }
        })
    }
}

两条「用例之间互相打脸」的坑先说清。① 「超 5MB」那条不会去嗅探魔数：Check 的顺序是 size 先于扩展名先于魔数，所以给它一张合法 PNG 头也照样拒——这正好证明「便宜的检查在前」这条设计成立。② 「坏后缀 .svg」和「文本改名 .png」期望的是两句不同的文案：前者栽在白名单、后者栽在魔数。如果你把 Check 的顺序改成「先嗅探再验后缀」，这两条会同时变红——不要改测试期望，去问自己哪个顺序才是你要的。

这个文件为什么写 package upload 而不是 package upload_test？因为要测的 Check 是导出的、但 allowedExt / allowedMIME 是包内私有的，同包测试可以顺手加白名单相关的用例。代价是测试和被测代码绑在一起；想强制「只用公开 API」就换 package upload_test + upload.Check(...)，两种都是正统写法，别混着用（同一个目录只能有一个包名，混了编译不过）。

// normalizePaging 是从 ListUsers 抠出来的纯函数：不碰 gin、不碰 DB，喂字符串就行。
// 入参用 c.DefaultQuery 的返回值，所以「缺参数」这件事也变成字符串（"1" / "10"）。
// 上限 50 是管理员接口的私有约定，比 dto.maxSize 的 100 更严：这里一行 = 一次全表风险。
func normalizePaging(rawPage, rawSize string) (page, size int) {
    page, err := strconv.Atoi(rawPage)
    if err != nil || page < 1 {
        page = 1
    }
    size, err = strconv.Atoi(rawSize)
    if err != nil || size < 1 || size > 50 {
        size = 10
    }
    return page, size
}

DefaultQuery("page") 只给一个参数时默认值是空串，strconv.Atoi("") 报错 → 落回 1，正好把「缺参数」和「参数是垃圾」用同一条分支处理掉了——这是抽函数顺手捡到的第二个好处。

5. httptest 测「普通用户进 admin 得 403」：全站最重要的一条断言

第 4 周用 httptest 测过「非作者改文 403」，今天加上「非管理员进 admin 403」。它不需要 DB：用一个假 Auth 塞身份，只测 RequireRole 这一段中间件链——真 token 解析是第 4 周测过的，重复测它只会让 CI 变慢。

internal/handler/admin_test.go（第二部分：httptest 打中间件链）// fakeAuth 模拟 D1 的 Auth：塞进 context 的两个键必须与生产代码逐字一致——
// "userID" 存 uint、"role" 存 model.Role（W4 讲义里那个 middleware.CtxKeyUserID 常量就是这个串的别名，
// 两种写法取值相同，但键名写成 "uid" 或把角色塞成 int8，RequireRole 会一路走 !exists / !ok 分支，
// 测试「假装」通过了，线上却是另一套）。
func fakeAuth(role model.Role) gin.HandlerFunc {
    return func(c *gin.Context) {
        c.Set("userID", uint(2))
        c.Set("role", role)
        c.Next()
    }
}

func TestAdminUsers_RequiresAdmin(t *testing.T) {
    newRouter := func(role model.Role) *gin.Engine {
        r := gin.New()
        g := r.Group("/api/v1/admin", fakeAuth(role), middleware.RequireRole(model.RoleAdmin))
        // 探针 handler：它跑没跑，就是「中间件放行没有」的证据，不需要真查库
        g.GET("/users", func(c *gin.Context) { c.String(http.StatusOK, "HANDLER RAN") })
        return r
    }
    const url = "/api/v1/admin/users"

    cases := []struct {
        name     string
        role     model.Role
        wantCode int
        wantBody string   // "" = 不断言响应体
    }{
        {"普通用户进 admin", model.RoleUser, http.StatusForbidden, `"code":1003`},
        {"管理员进 admin", model.RoleAdmin, http.StatusOK, "HANDLER RAN"},
    }
    for _, tc := range cases {
        t.Run(tc.name, func(t *testing.T) {
            w := httptest.NewRecorder()
            newRouter(tc.role).ServeHTTP(w, httptest.NewRequest(http.MethodGet, url, nil))
            if w.Code != tc.wantCode {
                t.Fatalf("status = %d, want %d", w.Code, tc.wantCode)
            }
            if tc.wantBody != "" && !strings.Contains(w.Body.String(), tc.wantBody) {
                t.Errorf("body = %s，想包含 %s", w.Body.String(), tc.wantBody)
            }
            // 反向断言：403 那条绝不能出现探针输出，否则「Abort 之后没 return」又混过去了
            if tc.wantCode == http.StatusForbidden && strings.Contains(w.Body.String(), "HANDLER RAN") {
                t.Fatal("被拒的请求居然执行了 handler")
            }
        })
    }
}

两个细节决定这份测试有没有价值。① 403 那条要断业务码 1003，而不是只断 HTTP 状态——前端拦截器看的是 code（第 6 周那条链），只断 403 的话，哪天有人把 Fail 的 code 写成 1005，测试还是一片绿。② 顺手断「handler 没跑」：RequireRole 里少了 return、或者 AbortWithStatusJSON 后面继续执行，是最典型的「403 和 200 同时发生」事故。

httptest 的思维方式与 JS 里的 supertest 一致：不起端口，直接把请求「灌」进路由函数，拿 Recorder 断响应。快（毫秒级）、稳（不占端口不依赖 DB）、适合 CI。要真实 URL（比如测 http.Client 那类）才用 httptest.NewServer——那是第 5 周的分工。

-race 需要 CGO（它靠 C 的运行库做内存影子），所以本地得有 C 工具链：macOS 装过 Xcode Command Line Tools 就有；Debian/Ubuntu apt install build-essential；Windows 得配 mingw-w64，装不动就直接在容器里跑——官方 golang 镜像自带 gcc：docker run --rm -v "$PWD":/src -w /src golang:1.24 go test -race ./...。另外别担心它和第 7 周那个静态镜像冲突：发布镜像是 CGO_ENABLED=0 编的二进制，压根不带 race，今天这些只跑在本地和 CI 里，产物一行都不用改。

没有 ab（本课也没教过它，别为这个去装 apache-utils）。两条路：要么用下面这份自包含脚本（自己登录、自己并发、自己汇总，只依赖 curl），要么一行装 hey。

backend/scripts/hammer.sh（整份复制即可跑；用法 ./scripts/hammer.sh）#!/usr/bin/env bash
# 并发轰炸本地服务：登录 / 发文 /（可选）上传，各 CONC 个请求同时打。
# 用法：
#   ./scripts/hammer.sh                         # 默认打 http://localhost:8080
#   CONC=50 IMG=~/me.png ./scripts/hammer.sh     # 连上传一起轰
#   BASE=http://1.2.3.4:8080 ./scripts/hammer.sh
# ⚠ 它会真的写数据：只对本地或测试实例跑，永远别对着生产按回车。
set -euo pipefail

BASE="${BASE:-http://localhost:8080}"
API="$BASE/api/v1"
USER="${HAMMER_USER:-xiaoming}"       # D2 建的那个账号
PASS="${HAMMER_PASS:-xiaoming123}"     # 8 位以上，注册时的强度校验才放行
CONC="${CONC:-20}"
IMG="${IMG:-}"

# 取 access_token 只靠 sed：不装 jq、不装 python3 也能跑（本课脚本一律这么写）。
# 响应是 {"code":0,…,"data":{"access_token":"eyJ….middle.sig",…}}，
# JWT 的字符集只有字母数字和 . _ -，这条正则够用。

LOGIN=$(curl -s -X POST "$API/auth/login" \
  -H 'Content-Type: application/json' \
  -d "{\"username\":\"$USER\",\"password\":\"$PASS\"}")
TOKEN=$(printf '%s' "$LOGIN" | sed -n 's/.*"access_token":"\([^"]*\)".*/\1/p')
[ -n "$TOKEN" ] || { echo "登录失败，先手动跑这条 curl 看返回：$LOGIN"; exit 1; }

codes=$(mktemp); trap 'rm -f "$codes"' EXIT
hit() { curl -s -o /dev/null -w '%{http_code}\n' "$@" >>"$codes" & }

echo "== 并发登录 ×$CONC =="
for i in $(seq 1 "$CONC"); do
  hit -X POST "$API/auth/login" -H 'Content-Type: application/json' \
      -d "{\"username\":\"$USER\",\"password\":\"$PASS\"}"
done

echo "== 并发发文 ×$CONC（标题带序号，验并发写与唯一索引）=="
for i in $(seq 1 "$CONC"); do
  hit -X POST "$API/articles" -H "Authorization: Bearer $TOKEN" \
      -H 'Content-Type: application/json' \
      -d "{\"title\":\"并发文章 $i\",\"content\":\"race detector 盯着你呢\"}"
done

if [ -n "$IMG" ] && [ -f "$IMG" ]; then
  echo "== 并发上传同一张图 ×$CONC（验随机文件名不互相覆盖）=="
  for i in $(seq 1 "$CONC"); do
    hit -X POST "$API/uploads/avatar" -H "Authorization: Bearer $TOKEN" -F "file=@$IMG"
  done
fi
wait

total=$(wc -l <"$codes" | tr -d ' ')
bad=$(grep -vc '^2[0-9][0-9]$' "$codes" || true)   # grep -c 零匹配时退出码非 0，|| true 拦住 set -e
echo "---- 请求 $total 个，非 2xx $bad 个"
[ "$bad" -gt 0 ] && { sort "$codes" | uniq -c | sort -rn; echo "有非 2xx：先看 /tmp/race.log 再记 BUGLOG"; exit 1; }
echo "全 2xx。记得跑完清掉这批测试文章（admin 强制下架或 DELETE），别让列表页长满垃圾"

8. CI：把第 4 周那份 workflow 升级

W4D5 埋的话今天兑现：「-race 铺到全量、加覆盖率上传、再挂一个 MySQL service 容器」。第 4 周那份 ci.yml 只有 Vet + go test -race -cover ./...，而且假设 go.mod 在仓库根——第 6 周归置成 monorepo 之后它在 backend/，所以今天第一件事是补 working-directory，否则 CI 会直接报「go.mod file not found」而你的本地一切正常。整份覆盖式替换：

service 容器要用 127.0.0.1:3306 连，不是服务名 mysql。GitHub Actions 的 services: 是跑在同一台 runner 宿主机上的端口映射容器（不是同 pod），所以 mysql:3306 这种 Docker Compose 写法在这儿连不通——这一点和 D3 本地 compose 里的 DB_HOST=mysql 正好相反，混用是这份 CI 最常见的红法。--health-* 那几行也不是装饰：MySQL 镜像冷启动要十几秒，没有健康检查时第一条测试会撞上 connection refused，你会误以为代码坏了。

func mustTestDB(t *testing.T) *gorm.DB {
    t.Helper()
    dsn := os.Getenv("TEST_DB_DSN")

        t.Fatalf("TEST_DB_DSN 必须指向 goblog_test，当前 = %q", dsn)

    if err != nil {
        t.Fatalf("连接测试库失败: %v", err)
    }
    return db
}

今日练习

练习 1：清单过格（60 分钟）

按第 1 节六大类清单逐项手动过一遍（浏览器 + curl 各半），任何一格与预期不符就记 BUGLOG 并当场修。今天结束时表格里应该躺着 ≥3 行。

参考答案：常见钓出的鱼——① page=999 返回 500（Offset 算成负数或溢出）；② 搜索输入 % 返回 500 或吐出全量（LIKE 通配符没转义，Where("title LIKE ?", "%"+escape(kw)+"%") 之前先处理 \ % _）；③ 上传字段名拼错（form 里写成 files）返回 500 而非 400（FormFile 返回零值 FileHeader，ValidateImage 里 file.Filename 空 → 走到「文件为空」，handler 却把它当 5000 发出去了）。三个都符合「现象/根因/修复/commit」模板。

练习 2：四个测试落盘（45 分钟）

把讲义的 rbac.go + rbac_test.go、validate_test.go、normalizePaging + admin_test.go、httptest admin 403 全抄进项目跑通，再补一条「refresh token 冒充 access 打 admin」的用例（这条要真的走 middleware.Auth，不能用 fakeAuth）。

参考答案：go test ./internal/... -v 应看到 --- PASS: TestCanModerate/管理员处置他人文章 这类子测试逐条打印。如果 CanModerate undefined，说明你把它写进了 _test.go——回第 2 节，文件名去掉 _test 后缀，调用点才会用上它。最后那条要真 token：注册两个账号、把 refresh_token 当 Bearer 发出去，期望 401 + 1005（不是 403——「你是谁」这一关就没过）；Claims.Type 的 wantType 校验（W4）在这里被复用，测试跑通就等于给「双 token 不能互换」上了锁。

练习 3：边界六连 + race（45 分钟）

逐行执行第 7 节表格里 6 条命令，把返回写成「预期 vs 实际」两列；然后 go test -race ./...，再用 CGO_ENABLED=1 go build -race -o /tmp/goblog-race ./cmd/server 起服务跑 ./scripts/hammer.sh（带上 IMG= 一张真图），确认无非 2xx 且日志无 DATA RACE。

参考答案：最容易翻车的是并发同名上传——若你 D2 用了「时间戳+rand」而 rand 源没初始化好出现重名互相覆盖，换 crypto/rand（D2 的 randHex 就是）并记 BUGLOG；race 若命中在 gin 之外的自建 map（例如你缓存了验证码），立刻上 sync.RWMutex；命中在 GORM 连接池上通常是你把 *gorm.DB 存进了包级变量又在 goroutine 里改它的 Clone——用 db.WithContext(ctx) 而不是改共享实例。轰完记得清测试数据。

练习 4：把升级后的 CI 推绿（30 分钟）

整份替换 .github/workflows/ci.yml，推一个分支并开 PR，看着两个 job 变绿；然后在 PR 描述里写三句话：为什么加了 working-directory、为什么 MySQL 那步要先跑迁移、覆盖率产物怎么在本地打开。

参考答案：常见三种红法——① go.mod file not found：漏了 working-directory: backend（或路径写成 goblog/backend，仓库根就是 goblog/，别把自己套两层）；② connection refused 或 Unknown database 'goblog_test'：健康检查缺失/重试太少，或 MYSQL_DATABASE 没建库；③ artifact 路径报 no files were provided：path 相对的是仓库根，要写 backend/coverage.out。第一版绿了之后，故意把 CanModerate 的 uid == 0 那三行删掉再推一次——看 CI 替你把这条红点拦下来，这才是这套东西的意义。

练习 5（选做）：给评论接口补一条 httptest 用例

复用第 5 节那台「假 Auth + 探针」的路由，测 DELETE /api/v1/comments/:id：普通用户删别人的 → 403+1003，删自己的 → 放行到 handler（探针回一句固定话术），管理员删别人的 → 放行。判定用的是 CanModerate，所以这条测的是「中间件 + service 分支接线」而不是角色本身。

参考答案：三条用例的期望分别落在不同错误上，别都写成 403：评论不存在要先于不是作者（404+1001 vs 403+1003），顺序反了就会用 403 遮住「这条评论根本不存在」。这条用例也是 D3 那笔「判定顺序」债的最终验收。
