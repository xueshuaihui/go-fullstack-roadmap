课前须知：先对齐列表接口的返回形状

1. 列表接口。GET /api/v1/articles?page=1&size=10&keyword=go，成功返回 data: { list: [article], total, page, size, total_page }。经过昨天的响应拦截器（拆掉 code/message/data 外壳），你的函数拿到的就是这个 data。

2. article 的字段（全周统一，后端是 snake_case）。id, title, content, summary, cover_image, views, user: { id, nickname }, created_at。注意三点：封面键是 cover_image 不是 coverImage；作者是嵌套对象 user 不是 author；时间是 created_at。前端取到 undefined 先 curl 核对，别改后端字段名迁就直觉。

3. 详情接口的 data 就是文章本身：不是 data.article，直接 article.id 取。列表页才有多余的一层 list。

4. id 不存在时后端不是返回 data:null，而是 HTTP 404 + code:2001（文章不存在）。昨天第 4 节的拦截器会把这种响应 reject 掉，并把 status/code/response 挂到 Error 对象上——所以「空态」要写在 catch 分支里判状态码，写在 then 里永远走不到。第 6 节给修正版代码。

5. 列表接口不需要登录。第 4 周定的规矩：读公开、写要 token。所以今天所有请求带不带 Authorization 都能过——这也是好事，页面能在未登录状态下先写完再测。

知识讲义

1. useEffect 里跑 async：新旧两种写法

JS 老写法直接 .then 链，能用但错误处理啰嗦；useEffect 的回调必须返回「清理函数或 undefined」，所以 async 函数不能直接当回调，标准姿势是在里面再声明一个：

jsx// ❌ 错误：useEffect(async () => {...}) 返回了 Promise，React 会警告且无法清理

// ✅ 正确写法（今天全篇都用它）
useEffect(() => {
  const run = async () => {
    setLoading(true); setError(null)
    try {
      const data = await listArticles({ page, keyword })
      setList(data.list); setTotal(data.total)
    } catch (e) {
      setError(e)
    } finally {
      setLoading(false)
    }
  }
  run()
}, [page, keyword]) // 依赖变了自动重新取数——这就是「声明式取数」

React 18 开发模式下 StrictMode 会让 useEffect 连跑两次，你会在 Network 里看到重复请求——这不是 bug，是 React 故意检查你的 effect 可否重入；生产构建只会发一次。别为此加防重逻辑。

2. 列表页：状态设计一次到位

一个列表页需要 6 个 state：list / total / totalPage / page / keyword / loading+error。后端在 PageResult 里已经算好了 total_page，前端就别再用 Math.ceil 重算一遍（两边算法不一致时会出现「后端说 3 页、前端渲染 4 个按钮」）。先把 api 函数建好，再写页面：

js// src/api/article.js —— 本周文章 CRUD 全在这
import { http } from './http'

export const listArticles = ({ page = 1, size = 10, keyword = '' }) =>
  http.get('/articles', { params: { page, size, keyword } })
  // 返回 { list, total, page, size, total_page }

export const getArticle = (id) => http.get(`/articles/${id}`)
// data 就是文章本身；id 不存在时这条 Promise 以 404+code 2001 被 reject
jsx// src/pages/ArticleList.jsx
import { useEffect, useState } from 'react'
import { Link } from 'react-router-dom'
import { listArticles } from '../api/article'
import { useDebounce } from '../hooks/useDebounce'
import { Pagination } from '../components/Pagination'
import { ArticleCard } from '../components/ArticleCard'

const SIZE = 10 // 每页几条，组件外常量，翻页和请求共用同一个值

export default function ArticleList() {
  const [list, setList] = useState([])
  const [total, setTotal] = useState(0)
  const [totalPage, setTotalPage] = useState(1) // 后端 total_page 直接拿来用
  const [page, setPage] = useState(1)
  const [keyword, setKeyword] = useState('')
  const [loading, setLoading] = useState(false)
  const [error, setError] = useState(null)
  const debouncedKeyword = useDebounce(keyword, 300) // 第 4 节实现

  useEffect(() => {
    let ignore = false // 竞态守卫：见第 5 节
    ;(async () => {
      setLoading(true); setError(null)
      try {
        const data = await listArticles({ page, size: SIZE, keyword: debouncedKeyword })
        if (!ignore) {
          setList(data.list); setTotal(data.total); setTotalPage(data.total_page)
        }
      } catch (e) {
        if (!ignore) setError(e)
      } finally {
        if (!ignore) setLoading(false)
      }
    })()
    return () => { ignore = true }
  }, [page, debouncedKeyword])

  const onSearch = (e) => {
    setKeyword(e.target.value)
    setPage(1) // 换词必须回第一页，否则会停在「第 3 页搜 go」的空结果上
  }

  if (loading && list.length === 0) return <p>加载中…</p>
  if (error) return <p style={{ color: '#f87171' }}>{error.message}</p>

  return (
    <div style={{ maxWidth: 720, margin: '24px auto' }}>
      <input placeholder="搜标题…" value={keyword} onChange={onSearch} />
      {list.length === 0
        ? <p style={{ color: '#999' }}>暂无文章，去写一篇？</p>
        : list.map((a) => <ArticleCard key={a.id} article={a} />)}
      <Pagination page={page} total={total} totalPage={totalPage} onChange={setPage} />
    </div>
  )
}

3. 分页控件：用后端给的 total_page

jsx// src/components/Pagination.jsx
export function Pagination({ page, total, totalPage, onChange }) {
  const pages = totalPage || 1 // 后端已算好：total_page = ceil(total / size)
  if (pages <= 1) return null
  return (
    <div style={{ display: 'flex', gap: 8, margin: '16px 0' }}>
      <button disabled={page <= 1} onClick={() => onChange(page - 1)}>上一页</button>
      {Array.from({ length: pages }, (_, i) => i + 1).map((p) => (
        <button key={p} disabled={p === page} onClick={() => onChange(p)}>{p}</button>
      ))}
      <button disabled={page >= pages} onClick={() => onChange(page + 1)}>下一页</button>
      <span>共 {total} 篇 · 第 {page}/{pages} 页</span>
    </div>
  )
}

前端自己 Math.ceil(total / size) 也能算，但两边各有算法时（后端 size 上限 50、前端写死 10）页码就会打脸。结论以服务端 total_page 为准；|| 1 兜住后端偶发返回 0 的情况，避免渲染出「第 1/0 页」。学习项目文章总量小，直接列全部页码没问题；真实项目超过 10 页要换成「首/尾 + 当前页 ±2 + 省略号」的窗口算法，思路一样，先不做。

4. 搜索防抖 300ms：一个 hook 讲清楚

防抖 = 停止输入 N 毫秒后才把「最新值」放出去。没有它，搜「goroutine」会依次请求 g / go / gor / gorou… 打后端 10 枪：

js// src/hooks/useDebounce.js
import { useEffect, useState } from 'react'

export function useDebounce(value, delay = 300) {
  const [debounced, setDebounced] = useState(value)
  useEffect(() => {
    const timer = setTimeout(() => setDebounced(value), delay)
    return () => clearTimeout(timer) // 关键：value 变了就撤销上一个定时器
  }, [value, delay])
  return debounced
}
时间线（delay=300ms）keyworddebouncedKeyword（发请求用）
0ms 输入「g」g''（定时器刚起）
100ms 输入「o」go''（前一个 timer 被 clear，重新起）
400ms 停手gogo → 触发 useEffect，只发这一枪

注意拆了两个 state：keyword 绑 input（打字立刻要上屏），debouncedKeyword 进依赖数组（请求慢半拍）。若直接把 keyword 放依赖，就是每字一请求；若干脆不让它受控，输入框会「卡字」。这是前端联调里最小也最常翻车的一段逻辑。

5. 竞态：快速翻页时旧响应覆盖新结果

场景：在第 1 页点了「下一页」，page=2 的请求刚发出，page=1 的慢响应却后到了——列表闪回第 1 页数据，页码却显示 2。请求没有「过期作废」机制，得自己加守卫。第 2 节代码里的 ignore 标志就是标准解：

jsxuseEffect(() => {
  let ignore = false
  listArticles({ page }).then((d) => { if (!ignore) setList(d.list) })
  return () => { ignore = true } // 依赖变化/卸载时，本 effect 的响应一律作废
}, [page])

不处理竞态，症状是「偶发的数据错页」，测试时极难复现、上线后用户天天骂。今天写列表页就把它焊死，不要等出事再补。

6. 详情页：useParams + 三态渲染（404 该走空态，不是错误态）

先看清后端对「不存在的 id」的真实响应，这决定了代码怎么写：

shell$ curl -s -i localhost:8080/api/v1/articles/99999 | head -1
HTTP/1.1 404 Not Found

$ curl -s localhost:8080/api/v1/articles/99999
{"code":2001,"message":"文章不存在","data":null}

HTTP 状态码是 404，axios 默认只把 2xx 当成功，所以这个响应根本不会进 then，而是被昨天的响应拦截器 reject 成 Error（上面那份 data:null 只是给人看的，代码里拿不到）。空态判断必须写在 catch 里按状态码分流：

jsx// src/pages/ArticleDetail.jsx —— 路由 path="/post/:id"
import { useEffect, useState } from 'react'
import { Link, useParams } from 'react-router-dom'
import { getArticle } from '../api/article'

export default function ArticleDetail() {
  const { id } = useParams() // 永远是字符串！后端 id 是数字，比较记得 Number(id)
  const [article, setArticle] = useState(null)
  const [error, setError] = useState(null)
  const [status, setStatus] = useState('loading') // loading | error | empty | ok

  useEffect(() => {
    let ignore = false
    setStatus('loading'); setError(null); setArticle(null) // 换 id 先清空，避免闪出上一篇
    ;(async () => {
      try {
        const data = await getArticle(id) // 拦截器已拆包，data 就是文章本身
        if (!ignore) { setArticle(data); setStatus('ok') }
      } catch (e) {
        if (ignore) return
        if (e.status === 404) { setStatus('empty'); return } // code 2001：内容没了，不是服务坏了
        setError(e); setStatus('error') // 500 / 断网 / 超时才叫「加载失败」
      }
    })()
    return () => { ignore = true }
  }, [id])

  if (status === 'loading') return <p>加载中…</p>
  if (status === 'empty') return (
    <p>文章不存在或已被删除。<Link to="/">返回列表</Link></p>
  )
  if (status === 'error') return (
    <p style={{ color: '#f87171' }}>加载失败：{error?.message}（HTTP {error?.status}）</p>
  )

  return (
    <article style={{ maxWidth: 720, margin: '24px auto' }}>
      <h1>{article.title}</h1>
      <p style={{ color: '#888' }}>
        {article.user?.nickname} · {article.views} 次浏览 ·
        new Date(article.created_at).toLocaleString()
      </p>
      <pre style={{ whiteSpace: 'pre-wrap' }}>{article.content}</pre>
      {/* content 是 Markdown 原文，这里先用 pre 保留换行直出；本手册三天内不引 markdown 渲染库 */}
    </article>
  )
}

如果第 4 节你的拦截器只保留了 axios 原生 error（没挂 status），这里就换成 e.response?.status === 404——两种写法等价，但必须先确认拦截器到底透出了哪个字段，这是联调里最费时间的一类「看代码觉得没问题、跑起来就是进不了分支」。基准是 Day 1 第 4 节那份挂了 e.status / e.code / e.response 的拦截器实现，今天这段代码按它写。

三态渲染是联调页的底线：loading 给反馈、error 给原因（来自拦截器抛出的后端 message）、空态给下一步指引（这里顺手放了「返回列表」链接）。只写成功分支的页面，一旦后端慢一点或数据为空，用户看到的就是白屏。

7. 封面图兜底

cover_image 可能是空字符串，也可能指向一个 404 的旧地址，两种情况都要接住。占位图用本地 inline SVG（data URI），不依赖任何外网服务：

jsx// src/components/ArticleCard.jsx
import { Link } from 'react-router-dom'

// 本地占位图：一张 600x300 的 SVG，encodeURIComponent 后当 src 用，断网也显示
const FALLBACK = 'data:image/svg+xml,' + encodeURIComponent(
  `<svg xmlns="http://www.w3.org/2000/svg" width="600" height="300">
     <rect width="100%" height="100%" fill="#eef2ff"/>
     <text x="300" y="160" fill="#6366f1" font-size="28" text-anchor="middle">Go 博客</text>
   </svg>`)

export function ArticleCard({ article }) {
  return (
    <Link to={`/post/${article.id}`} style={{ display: 'block', marginBottom: 16, color: 'inherit', textDecoration: 'none' }}>
      <img
        src={article.cover_image || FALLBACK}
        onError={(e) => { e.currentTarget.src = FALLBACK }} // 有 URL 但挂了：换占位图
        alt={article.title} width={600} height={300}
        style={{ objectFit: 'cover', borderRadius: 8 }}
      />
      <h3>{article.title}</h3>
      <p>{article.summary} · {article.user?.nickname} · {article.views} 浏览</p>
    </Link>
  )
}

src={空值 || FALLBACK} 管住「压根没传图」；onError 管住「有 URL 但挂了」。两道保险都上，破图才会绝迹。别忘了 alt 用文章标题，无障碍分+1。

为什么不用 https://placehold.co/600x300?text=Go+Blog 这类在线占位图服务：它要外网 DNS + HTTPS，公司内网、离线演示、CI 里都会变成一片破图，反而把「兜底」这件事本身搞挂。inline SVG 的代价只是一行字符串。变体：把 Go 博客 换成 ${article.title} 就能生成带标题的占位图——中文和尖括号都会被 encodeURIComponent 转成 %XX，不用自己转义。

今日名词卡

术语一句话解释
声明式取数不手写「点击→请求→渲染」流程，只声明「依赖这些 state 时数据应该长这样」，useEffect 自动重取
防抖（debounce）事件连续触发时只在停手 N 毫秒后执行一次，靠「设置定时器 + 清理上一个定时器」实现
节流（throttle）对比概念：无论多忙，N 毫秒内最多执行一次。搜索用防抖，滚动用节流
竞态（race condition）多个异步响应到达顺序不确定，后发先至的旧数据覆盖新数据；用 ignore 标志或取消请求防御
三态渲染loading / error / empty 与成功态一起写才算页面完成，缺一个都是线上事故
空态 vs 错误态「资源不存在」（404 + code 2001）走空态给引导；「服务不可用」（5xx、断网、超时）才走错误态给原因。两者混在一个分支里，用户就分不清是没内容还是崩了
