知识讲义

1. useEffect 里跑 async：新旧两种写法

JS 老写法直接 .then 链，能用但错误处理啰嗦；useEffect 的回调必须返回「清理函数或 undefined」，所以 async 函数不能直接当回调，标准姿势是在里面再声明一个：

jsx// ❌ 错误：useEffect(async () => {...}) 返回了 Promise，React 会警告且无法清理

// ✅ 正确写法（今天全篇都用它）
useEffect(() => {
  const run = async () => {
    setLoading(true); setError(null)
    try {
      const data = await listArticles({ page, keyword })
      setList(data.list); setTotal(data.total)
    } catch (e) {
      setError(e)
    } finally {
      setLoading(false)
    }
  }
  run()
}, [page, keyword]) // 依赖变了自动重新取数——这就是「声明式取数」

React 18 开发模式下 StrictMode 会让 useEffect 连跑两次，你会在 Network 里看到重复请求——这不是 bug，是 React 故意检查你的 effect 可否重入；生产构建只会发一次。别为此加防重逻辑。

2. 列表页：状态设计一次到位

一个列表页需要 5 个 state：list / total / page / keyword / loading+error。先把 api 函数建好，再写页面：

js// src/api/article.js —— 本周文章 CRUD 全在这
import { http } from './http'

export const listArticles = ({ page = 1, size = 10, keyword = '' }) =>
  http.get('/articles', { params: { page, size, keyword } })
  // 返回 { list, total, page, size }

export const getArticle = (id) => http.get(`/articles/${id}`)
jsx// src/pages/ArticleList.jsx
import { useEffect, useState } from 'react'
import { Link } from 'react-router-dom'
import { listArticles } from '../api/article'
import { useDebounce } from '../hooks/useDebounce'
import { Pagination } from '../components/Pagination'
import { ArticleCard } from '../components/ArticleCard'

export default function ArticleList() {
  const [list, setList] = useState([])
  const [total, setTotal] = useState(0)
  const [page, setPage] = useState(1)
  const [keyword, setKeyword] = useState('')
  const [loading, setLoading] = useState(false)
  const [error, setError] = useState(null)
  const debouncedKeyword = useDebounce(keyword, 300) // 第 4 节实现

  useEffect(() => {
    let ignore = false // 竞态守卫：见第 5 节
    ;(async () => {
      setLoading(true); setError(null)
      try {
        const data = await listArticles({ page, keyword: debouncedKeyword })
        if (!ignore) { setList(data.list); setTotal(data.total) }
      } catch (e) {
        if (!ignore) setError(e)
      } finally {
        if (!ignore) setLoading(false)
      }
    })()
    return () => { ignore = true }
  }, [page, debouncedKeyword])

  const onSearch = (e) => {
    setKeyword(e.target.value)
    setPage(1) // 换词必须回第一页，否则会停在「第 3 页搜 go」的空结果上
  }

  if (loading && list.length === 0) return <p>加载中…</p>
  if (error) return <p style={{ color: '#f87171' }}>{error.message}</p>

  return (
    <div style={{ maxWidth: 720, margin: '24px auto' }}>
      <input placeholder="搜标题…" value={keyword} onChange={onSearch} />
      {list.length === 0
        ? <p style={{ color: '#999' }}>暂无文章，去写一篇？</p>
        : list.map((a) => <ArticleCard key={a.id} article={a} />)}
      <Pagination page={page} total={total} size={10} onChange={setPage} />
    </div>
  )
}

3. 分页控件：从 total 算页数

jsx// src/components/Pagination.jsx
export function Pagination({ page, total, size, onChange }) {
  const pages = Math.ceil(total / size) || 1
  if (pages <= 1) return null
  return (
    <div style={{ display: 'flex', gap: 8, margin: '16px 0' }}>
      <button disabled={page <= 1} onClick={() => onChange(page - 1)}>上一页</button>
      {Array.from({ length: pages }, (_, i) => i + 1).map((p) => (
        <button key={p} disabled={p === page} onClick={() => onChange(p)}>{p}</button>
      ))}
      <button disabled={page >= pages} onClick={() => onChange(page + 1)}>下一页</button>
      <span>共 {total} 篇 · 第 {page}/{pages} 页</span>
    </div>
  )
}

学习项目文章总量小，直接列全部页码没问题；真实项目超过 10 页要换成「首/尾 + 当前页 ±2 + 省略号」的窗口算法，思路一样，先不做。

4. 搜索防抖 300ms：一个 hook 讲清楚

防抖 = 停止输入 N 毫秒后才把「最新值」放出去。没有它，搜「goroutine」会依次请求 g / go / gor / gorou… 打后端 10 枪：

js// src/hooks/useDebounce.js
import { useEffect, useState } from 'react'

export function useDebounce(value, delay = 300) {
  const [debounced, setDebounced] = useState(value)
  useEffect(() => {
    const timer = setTimeout(() => setDebounced(value), delay)
    return () => clearTimeout(timer) // 关键：value 变了就撤销上一个定时器
  }, [value, delay])
  return debounced
}
时间线（delay=300ms）keyworddebouncedKeyword（发请求用）
0ms 输入「g」g''（定时器刚起）
100ms 输入「o」go''（前一个 timer 被 clear，重新起）
400ms 停手gogo → 触发 useEffect，只发这一枪

注意拆了两个 state：keyword 绑 input（打字立刻要上屏），debouncedKeyword 进依赖数组（请求慢半拍）。若直接把 keyword 放依赖，就是每字一请求；若干脆不让它受控，输入框会「卡字」。这是前端联调里最小也最常翻车的一段逻辑。

5. 竞态：快速翻页时旧响应覆盖新结果

场景：在第 1 页点了「下一页」，page=2 的请求刚发出，page=1 的慢响应却后到了——列表闪回第 1 页数据，页码却显示 2。请求没有「过期作废」机制，得自己加守卫。第 2 节代码里的 ignore 标志就是标准解：

jsxuseEffect(() => {
  let ignore = false
  listArticles({ page }).then((d) => { if (!ignore) setList(d.list) })
  return () => { ignore = true } // 依赖变化/卸载时，本 effect 的响应一律作废
}, [page])

不处理竞态，症状是「偶发的数据错页」，测试时极难复现、上线后用户天天骂。今天写列表页就把它焊死，不要等出事再补。

6. 详情页：useParams + 三态渲染

jsx// src/pages/ArticleDetail.jsx —— 路由 path="/post/:id"
import { useEffect, useState } from 'react'
import { useParams } from 'react-router-dom'
import { getArticle } from '../api/article'

export default function ArticleDetail() {
  const { id } = useParams() // 永远是字符串！后端 id 是数字，比较记得 Number(id)
  const [article, setArticle] = useState(null)
  const [error, setError] = useState(null)
  const [status, setStatus] = useState('loading') // loading | error | ok | empty

  useEffect(() => {
    let ignore = false
    setStatus('loading'); setError(null)
    getArticle(id)
      .then((data) => {
        if (ignore) return
        setArticle(data)
        setStatus(data ? 'ok' : 'empty') // 后端对不存在 id 返回 data:null 时也走空态
      })
      .catch((e) => { if (!ignore) { setError(e); setStatus('error') } })
    return () => { ignore = true }
  }, [id])

  if (status === 'loading') return <p>加载中…</p>
  if (status === 'error') return <p style={{ color: '#f87171' }}>加载失败：{error?.message}</p>
  if (status === 'empty') return <p>文章不存在或被删除</p>

  return (
    <article style={{ maxWidth: 720, margin: '24px auto' }}>
      <h1>{article.title}</h1>
      <p style={{ color: '#888' }}>
        {article.author?.nickname} · new Date(article.createdAt).toLocaleString()
      </p>
      <pre style={{ whiteSpace: 'pre-wrap' }}>{article.content}</pre> /* Markdown 原文，明天再渲染 */
    </article>
  )
}

三态渲染是联调页的底线：loading 给反馈、error 给原因（来自拦截器抛出的后端 message）、空态给下一步指引。只写成功分支的页面，一旦后端慢一点或数据为空，用户看到的就是白屏。

7. 封面图兜底

coverImage 可能是空字符串，也可能指向一个 404 的旧地址，两种情况都要接住：

jsx// src/components/ArticleCard.jsx
const FALLBACK = 'https://placehold.co/600x300?text=Go+Blog'

export function ArticleCard({ article }) {
  return (
    <Link to={`/post/${article.id}`} style={{ display: 'block', marginBottom: 16, color: 'inherit', textDecoration: 'none' }}>
      <img
        src={article.coverImage || FALLBACK}
        onError={(e) => { e.currentTarget.src = FALLBACK }} // 404 时换占位图
        alt={article.title} width={600} height={300}
        style={{ objectFit: 'cover', borderRadius: 8 }}
      />
      <h3>{article.title}</h3>
      <p>{article.summary} · {article.author?.nickname}</p>
    </Link>
  )
}

src={空值 || FALLBACK} 管住「压根没传图」；onError 管住「有 URL 但挂了」。两道保险都上，破图才会绝迹。别忘了给占位图写 alt 之外用文章标题，无障碍分+1。

常见坑

坑现象正确姿势
useEffect 依赖数组漏写搜索词改了列表却不刷新（闭包捕获旧 keyword），或 eslint 一直 warning发请求用到的 state 全部进依赖：[page, debouncedKeyword]
把 async 函数直接传给 useEffect控制台警告「Effect callbacks must not return anything but a function」内部声明 run 再调用，回调本身保持同步
keyword 直接进依赖每敲一个字请求一次，后端日志刷屏防抖值进依赖，输入框绑原始值
useParams 拿到的是字符串article.authorId === user.id 恒为 false（number ≠ string）比较前统一 Number(id)，或全用 String()
换词不回第一页在第 3 页搜「go」，结果只有 1 页 → 空列表onChange 里 setKeyword + setPage(1) 一起干
StrictMode 双请求慌了以为 bug，给 hook 加各种防重开发模式专属行为，生产只发一次，接受它

今日名词卡

术语一句话解释
声明式取数不手写「点击→请求→渲染」流程，只声明「依赖这些 state 时数据应该长这样」，useEffect 自动重取
防抖（debounce）事件连续触发时只在停手 N 毫秒后执行一次，靠「设置定时器 + 清理上一个定时器」实现
节流（throttle）对比概念：无论多忙，N 毫秒内最多执行一次。搜索用防抖，滚动用节流
竞态（race condition）多个异步响应到达顺序不确定，后发先至的旧数据覆盖新数据；用 ignore 标志或取消请求防御
三态渲染loading / error / empty 与成功态一起写才算页面完成，缺一个都是线上事故
