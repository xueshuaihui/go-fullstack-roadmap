课前须知：先把后端契约背下来

1. 后端是第 4 周那个博客 API。Gin，监听 :8080，路由前缀 /api/v1，成功失败都返回 {code, message, data}。今天先把后端跑起来：go run .（或 docker compose up -d 起 MySQL 后再跑）。

2. token 存 localStorage，键名固定三个。accessToken、refreshToken 存字符串，user 存 JSON。全周代码都按这套键名读写，改名要全场一起改。

3. 开发环境走 Vite proxy。axios 的 baseURL 只写 /api/v1（相对路径），由 Vite 开发服务器把 /api 开头的请求转发给 http://localhost:8080，今天就当黑盒接受，Day 5 专门讲透 CORS 与 proxy 的恩怨。

3. 封装 axios 实例（含拦截器骨架）

js// src/api/http.js
import axios from 'axios'

export const http = axios.create({
  baseURL: '/api/v1',  // 相对路径，开发时由 Vite proxy 转发到 :8080
  timeout: 10000,
})

// 请求拦截器：每个请求自动带上 accessToken
http.interceptors.request.use((config) => {
  const token = localStorage.getItem('accessToken')
  if (token) config.headers.Authorization = `Bearer ${token}`
  return config // 必须 return！忘了这行请求永远发不出去
})

// 响应拦截器骨架：今天只做两件事——拆 data、统一报错
// Day 4 会往这里加 401 静默刷新逻辑
http.interceptors.response.use(
  (response) => {
    const body = response.data // { code, message, data }
    if (body.code !== 0) {
      return Promise.reject(new Error(body.message || '请求失败'))
    }
    return body.data // 拆包：调用方拿到的直接是 data
  },
  (error) => {
    const msg = error.response?.data?.message || error.message || '网络错误'
    return Promise.reject(new Error(msg))
  }
)

拦截器生效后，各种响应组合的行为如下（全周统一按这张表理解）：

HTTP + code含义拦截器行为
200/201 + code=0成功resolve，调用方直接拿 data
400/404 + code≠0参数错 / 资源不存在reject(message)，页面 catch 后弹提示
403 + code=1003非作者操作同上，Day 3 会用它验证权限
401 + code=1005token 无效/过期今天先 reject，Day 4 做静默刷新重试

4. auth API 函数：先拿 curl 确认返回结构

js// src/api/auth.js —— 三个函数对应后端三个接口
import { http } from './http'

export const register = (data) => http.post('/auth/register', data)
// data: { email, password, nickname }

export const login = (data) => http.post('/auth/login', data)
// 返回 data: { user, accessToken, refreshToken }

export const refreshToken = (refreshToken) =>
  http.post('/auth/refresh', { refreshToken })
// 返回 data: { accessToken, refreshToken }，Day 4 拦截器里调用

联调铁律：前端报字段问题，先用 curl 打一枪看真实返回。第 4 周的登录接口返回体是这样的：

shell$ curl -s localhost:8080/api/v1/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"a@b.com","password":"12345678"}'
{"code":0,"message":"success","data":{"user":{"id":1,"nickname":"小明"},\
"accessToken":"eyJ...","refreshToken":"eyJ..."}}

如果 curl 返回里出现大写键名（"AccessToken"），说明 Go 结构体字段忘了写 json tag——回第 4 周补上 AccessToken string `json:"accessToken"`，别在前端将就从后端改。

5. useAuth：登录态的读、写、恢复

React 一刷新内存就清零，所以登录态必须「写进 localStorage + 初始化时读回来」。这个 hook 全周都会用到：

js// src/hooks/useAuth.js
import { useState } from 'react'
import * as authApi from '../api/auth'

function readUser() {
  try {
    return JSON.parse(localStorage.getItem('user') || 'null')
  } catch {
    return null // 存坏了就当没登录，别让整个 App 崩
  }
}

export function useAuth() {
  // 关键：初始值同步从 localStorage 读，守卫组件（Day 4）依赖这一点
  const [user, setUser] = useState(readUser)

  const saveTokens = (data) => {
    localStorage.setItem('accessToken', data.accessToken)
    localStorage.setItem('refreshToken', data.refreshToken)
    localStorage.setItem('user', JSON.stringify(data.user))
  }

  const login = async (credentials) => {
    const data = await authApi.login(credentials) // 拦截器已拆包
    saveTokens(data)
    setUser(data.user)
    return data.user
  }

  const logout = () => {
    'accessToken refreshToken user'.split(' ').forEach((k) =>
      localStorage.removeItem(k)
    )
    setUser(null)
  }

  return { user, login, logout }
}

为什么初始值用函数 useState(readUser) 而不是 useState(readUser())？前者只在首次挂载执行一次，后者每次 render 都会跑一遍 JSON.parse。另外「同步初始化」是为 Day 4 准备的：路由守卫在首次 render 就要知道登录态，异步恢复会闪一下未登录界面。

6. 登录页：受控组件 + 提交

jsx// src/pages/Login.jsx
import { useState } from 'react'
import { useNavigate } from 'react-router-dom'
import { useAuth } from '../hooks/useAuth'

export default function Login() {
  const [form, setForm] = useState({ email: '', password: '' })
  const [err, setErr] = useState('')
  const [busy, setBusy] = useState(false)
  const { login } = useAuth()
  const navigate = useNavigate()

  const onChange = (e) =>
    setForm({ ...form, [e.target.name]: e.target.value }) // 受控：name 对键名

  const onSubmit = async (e) => {
    e.preventDefault()
    setErr(''); setBusy(true)
    try {
      const user = await login(form)
      alert(`欢迎回来，${user.nickname}！`)
      navigate('/')
    } catch (e2) {
      setErr(e2.message) // 「密码错误」「用户不存在」原样展示
    } finally {
      setBusy(false)
    }
  }

  return (
    <form onSubmit={onSubmit} style={{ maxWidth: 320, margin: '40px auto' }}>
      <h2>登录</h2>
      <input name="email" value={form.email} onChange={onChange} placeholder="邮箱" />
      <input name="password" type="password" value={form.password} onChange={onChange} />
      <p style={{ color: '#f87171' }}>{err}</p>
      <button disabled={busy}>{busy ? '登录中…' : '登录'}</button>
      <p>还没有账号？<a href="/register">去注册</a></p>
    </form>
  )
}

注册页 Register.jsx 与它几乎一样：多一个 nickname 输入框，提交调 authApi.register(form)，成功后 navigate('/login') 并预填邮箱。Editor.jsx 里再写一遍表单时你就该想抽公共组件了——今天先各写各的，跑通优先。

常见坑（今天 100% 会踩其中三个）

坑现象正确姿势
localStorage 存对象忘了 stringify读出来是字符串 "[object Object]"，JSON.parse 直接抛写入 JSON.stringify、读取 JSON.parse 包 try/catch
后端字段没 json tag前端拿到的键是 AccessToken 大写，取 data.accessToken 全 undefinedcurl 看真实返回，回 Go 结构体补 `json:"accessToken"`
baseURL 与 proxy 路径叠错请求变成 /api/api/v1/... 404baseURL 写 /api/v1，proxy 的 key 只写 /api，别重复
受控输入 value 与 state 键名对不上打字没反应或 React 警告「switching from controlled to uncontrolled」input 的 name 必须与 state 键完全一致，onChange 用 [e.target.name]
请求拦截器忘了 return config所有请求 pending，页面转圈不发枪拦截器成功分支必须把 config 原样 return 出去

术语一句话解释
axios 实例axios.create() 出来的私有副本，改它的 baseURL/拦截器不污染全局 axios
