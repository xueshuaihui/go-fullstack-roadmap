课前须知：三个写接口的契约

1. 全部需要登录。请求头带 Authorization: Bearer <accessToken>（昨天的拦截器已自动做）。不带或 token 过期返回 HTTP 401 + code 1005。第 4 周签发的 access token 只有 15 分钟寿命，写到中途突然 401 是设计内的行为，先重新登录顶过去，静默刷新明天做。

2. 创建与编辑的请求体一致，键名跟后端 JSON tag 对齐（snake_case）：{ title, summary, content, cover_image }。作者身份由后端从 token 里解（c.GetUint("userID")），前端不传也传不动——这是权限的第一道设计。

3. 权限后端说了算。非作者 PUT/DELETE 会收到 403 + code 1003（无权限）。前端做作者判断只是「不让用户点了挨揍」，真正的守门员永远是后端。

4. 创建成功是 201 不是 200。后端走 response.Created(c, article)：HTTP 201，data 就是刚建好的那篇（含 id），所以前端能直接跳详情页 navigate(`/post/${data.id}`)。编辑成功是 200，data 可能是更新后的文章、也可能是 null——取 id 写 data?.id ?? id 兜住。

3. Editor.jsx：模式判断 + 回填 + 提交（核心 90 行）

jsx// src/pages/Editor.jsx
import { useEffect, useRef, useState } from 'react'
import { useNavigate, useParams } from 'react-router-dom'
import { getArticle, createArticle, updateArticle } from '../api/article'

const EMPTY = { title: '', summary: '', content: '', cover_image: '' }
// ↑ 键名 = 后端 JSON 键名，表单直接整份当请求体发出去，省一次字段翻译

export default function Editor() {
  const { id } = useParams()          // /post/new 时 id 是 undefined
  const isEdit = Boolean(id)
  const [form, setForm] = useState(EMPTY)
  const [loading, setLoading] = useState(isEdit)
  const [busy, setBusy] = useState(false)
  const [err, setErr] = useState('')
  const navigate = useNavigate()
  const dirtyRef = useRef(false)     // 用户开始打字后置 true，防回填覆盖（见坑表）

  // —— 编辑模式：拉详情回填表单 ——
  useEffect(() => {
    if (!isEdit) return
    let ignore = false
    getArticle(id)
      .then((a) => {
        if (ignore) return // 组件已卸载 / id 已变：这次响应作废
        setLoading(false)
        if (dirtyRef.current) return // 用户已经打字：保留他的输入，别让晚到的回填吃掉
        setForm({ title: a.title, summary: a.summary, content: a.content, cover_image: a.cover_image })
      })
      .catch((e) => { if (!ignore) { setErr(e.message); setLoading(false) } })
    return () => { ignore = true }
  }, [id, isEdit])

  const onChange = (e) => {
    dirtyRef.current = true
    setForm({ ...form, [e.target.name]: e.target.value })
  }

  const onSubmit = async (e) => {
    e.preventDefault()
    setErr('')
    if (!form.title.trim() || !form.content.trim()) return setErr('标题和内容不能为空')
    setBusy(true)
    try {
      // form 的键就是后端要的 title / summary / content / cover_image，整份直接发
      const data = isEdit ? await updateArticle(id, form) : await createArticle(form)
      // 新建：201 的 data 里带新文章 id；编辑：200 的 data 可能是 null → ?? 兜回路由上的 id
      navigate(`/post/${data?.id ?? id}`)
    } catch (e2) {
      setErr(e2.message) // 「标题长度超限」(400+1004)、「无权限」(403+1003) 等后端校验原样展示
    } finally {
      setBusy(false)
    }
  }

  if (loading) return <p>回填中…</p>

  return (
    <form onSubmit={onSubmit} style={{ maxWidth: 640, margin: '24px auto', display: 'grid', gap: 10 }}>
      <h2>{isEdit ? '编辑文章' : '写新文章'}</h2>
      <input name="title" placeholder="标题" value={form.title} onChange={onChange} />
      <input name="summary" placeholder="一句话摘要" value={form.summary} onChange={onChange} />
      <input name="cover_image" placeholder="封面图 URL（可空）" value={form.cover_image} onChange={onChange} />
      <textarea name="content" rows={15} placeholder="支持 Markdown 原文" value={form.content} onChange={onChange} />
      {err && <p style={{ color: '#f87171' }}>{err}</p>}
      <button disabled={busy}>{busy ? '提交中…' : isEdit ? '保存修改' : '发布'}</button>
    </form>
  )
}

新建模式连请求都不用发，初始态就是 EMPTY；编辑模式多一个 loading 门闩，回填没完成前渲染「回填中…」而不是空表单——否则用户对着空表单先打了两字，回填一到又被覆盖，这就是本节最大的坑。

jsx// src/components/ConfirmDialog.jsx —— 一个 state 控制显隐 + 两个回调
import { useState } from 'react'

export function ConfirmDialog({ title, danger = true, onOk }) {
  const [open, setOpen] = useState(false)
  const run = async () => {
    setOpen(false)
    try { await onOk() } catch (e) { alert(e.message) }
  }
  return (
    <>
      <button onClick={() => setOpen(true)}
        style={{ color: danger ? '#f87171' : 'inherit' }}>删除</button>
      {open && (
        <div style={{ position: 'fixed', inset: 0, background: 'rgba(0,0,0,.5)',

            <h3>{title}</h3>
            <button onClick={() => setOpen(false)}>取消</button>
            <button onClick={run} style={{ marginLeft: 8, color: '#fff', background: '#dc2626' }}>
              确定删除
            </button>
          </div>
        </div>
      )}
    </>
  )
}

前端隐藏 ≠ 权限控制。懂 DevTools 的人手敲 /post/123/edit 照样能进编辑页、照样能发 PUT 请求——但后端会回 403。所以两层都要：前端判断给正常用户顺畅体验，后端判断给恶意请求兜底。今天的验收之一就是替别人验证他 403。

按钮死活不出现？先 curl 看 data 里有没有 user 这个键。后端的 User 字段带了 json:"user,omitempty"，列表/详情 handler 必须 Preload("User") 才会把作者嵌进返回体；没 Preload 时 article.user 是 undefined，前端判断永远是 false——这属于后端漏了关联加载，不是前端的锅（第 4 周那侧补一行 Preload）。

6. 成功之后：跳转与「列表为什么要刷新」

提交/删除成功后跳回哪里？跳回去列表还是旧数据怎么办？三个方案摆平了选：

方案写法优点代价 / 适用
A. 回上一页navigate(-1)一行代码，从哪来到哪去用户直接打开编辑器 URL 时 -1 会退出网站；且回到列表后是缓存前的旧数据（组件没重新挂载，useEffect 不会再跑）

C. 状态提升 / 全局 store列表数据提到 App 或引 Zustand / React Query，写操作直接改缓存（乐观更新）体验最好，业界正解学习成本最高；第 8 周或以后换 React Query 再做

练习 4：未保存修改的离开拦截（20 分钟）

利用第 3 节的 dirtyRef，离开编辑页时如果 dirtyRef.current 为 true 就拦一道。react-router 的 useBlocker 是实验性 API，而且只在 createBrowserRouter + RouterProvider 的数据路由模式下才生效——本周的 App.jsx 用的是 <BrowserRouter> + <Routes>，硬 import 会拿到 undefined。所以下面给两个今天就能跑的替代方案，两个都要做：

jsx// ① 浏览器级拦截：拦得住刷新 / 关标签页 / 手改地址栏，拦不住站内跳转
// Editor.jsx 组件内，和 useEffect 放一起
useEffect(() => {
  const onBeforeUnload = (e) => {
    if (!dirtyRef.current) return // 没动过就别拦人
    e.preventDefault()          // Chrome/Firefox 要求显式调用才弹框
    e.returnValue = ''          // 自定义文案早被浏览器禁了，留空用原生提示
  }
  window.addEventListener('beforeunload', onBeforeUnload)
  return () => window.removeEventListener('beforeunload', onBeforeUnload)
}, []) // 空依赖：只订阅一次；dirtyRef 是 ref，不需要进依赖数组
jsx// ② 站内导航：包一层自己的导航函数，「取消编辑」按钮走它
const guardedNavigate = (to) => {
  if (!dirtyRef.current || window.confirm('有未保存修改，确定离开？')) {
    dirtyRef.current = false // 放行前清脏标记，否则 ① 会在下一跳再拦一次
    navigate(to)
  }
}
// 用法：<button type="button" onClick={() => guardedNavigate(`/post/${id}`)}>取消编辑</button>
// 顶栏链接（NavBar 的「首页」）这类全局导航想一起拦，就得把脏状态下沉到共享 hook 里，
// 本周不做——真实项目普遍也只做「表单自己的取消/提交按钮 + beforeunload」这一层。

真要把「站内所有导航」都拦住，第 8 周把路由换成数据路由后用 useBlocker：const blocker = useBlocker(() => dirtyRef.current)，再在 UI 上根据 blocker.state === 'blocked' 渲染确认框，用户点确定调 blocker.proceed()、点取消调 blocker.reset()。为了它把整份路由表重写成 createBrowserRouter，本周的收益不值当，先知道有这条路。

常见坑

坑现象正确姿势
回填竞态覆盖用户输入编辑页打开瞬间开始打字，详情响应回来后打的字没了回填完成前渲染「回填中…」不显示表单；或 dirtyRef 拦截晚到的回填

新建时把 user_id 塞进请求体后端忽略还好，若后端「信任前端传的 user_id」就是越权漏洞身份永远从 token 解（c.GetUint("userID")），DTO 里那行写 `json:"-"`
