**前置说明**：你熟悉 Vue，HTTP、JSON、路由、异步不需要从零讲。本路线只聚焦**服务端视角**。

**但如果你连 Go 都没写过**，这份材料的默认假设是「你会用终端、建过文件、看过编译报错」。这三件事没人教，第一阶段第一天就会卡住。所以先花 40 分钟把下面四件事做完，再进 D1：

1. **一个能开终端的编辑器**（VS Code + Go 插件）。装完确认：保存 `.go` 文件时自动格式化（插件默认开启 `gofmt`）。
2. **会认路径**：`cd` 进目录、`pwd` 看当前位置、`ls` 看有什么。后面所有「当前目录」都指 `pwd` 打印出来的那个路径。
3. **会建文件**：`mkdir ledger && cd ledger && touch main.go`。不要用 Word 或富文本编辑器，编码必须是 UTF-8、换行用 LF。
4. **会读报错**：Go 的编译错误格式是 `文件:行:列: 说明`。先看**最上面第一条**，改完再跑；后面的错误经常是第一条引发的连锁反应。

## 怎么把当天的代码片段跑起来

讲解里的代码大多是**片段**（省了 `package`、`import`、`func main`），目的是突出当天那个机制。要真正跑起来，把它们塞进同一个文件：

```go
package main                 // 必须是 main，才能 go run

import (                     // 片段里用到什么就 import 什么
    "fmt"
)

func main() {
    // 把当天的片段贴在这里
}
```

第一次跑必然遇到下面几类报错，对照处理：

| 报错 | 原因 | 改法 |
| :--- | :--- | :--- |
| `undefined: fmt` | 用了 `fmt` 却没 import | 在 import 块里加 `"fmt"` |
| `imported and not used: "os"` | import 了但没用到 | 删掉该行，或先用 `_ = os.Args` 占位 |
| `declared and not used: x` | 变量声明了没用 | 用 `fmt.Println(x)` 打出来，或删掉 |
| `cannot use x (type int) as type int64` | Go 不做隐式转换 | 显式写 `int64(x)` |
| `no go files in ...` | 目录里没有 `.go`，或文件名以 `_`/`.` 开头 | `ls` 确认文件在，且不是 `main_test.go` |
| `expected 'package', found ...` | 文件第一行不是 `package xxx` | 补上 `package main` |

**每天至少有一个人可运行的最小验证**，不要只读。读一遍的理解是「我以为我会了」，跑通一次才是「我知道它会怎样」。

## 每天怎么用（两个版本，按你的时间选）

- **4 小时完整版**（推荐）：读前预测 10 分钟 → 读讲解 15 分钟（边读边把代码跑一遍）→ 自测 10 分钟（合上答案）→ 排错 + 迁移 25 分钟 → 动手任务 2 小时 → 勾判据 10 分钟 → 剩 50 分钟留给「卡住」。
- **90 分钟保底版**：只做三件事——读讲解、跑通当天最小验证、完成任务的**第一条**。判据里「能跑出预期结果」那几条必须勾，其余留到周末补。

**关键提醒：卡住超过 30 分钟就停下来记录**。写下「我想做什么、我期望什么、实际什么、我试过什么」，这四个字段比答案有用——它会在你后面回看时直接指出你缺的是哪个概念。

## 三个词别混：读完、会做、掌握

- **读完**：看懂了每个字。这只能证明材料写得通顺。
- **会做**：照着抄能跑。这说明你能复现，但换场景就会卡。
- **掌握**：能在**没有材料**的情况下写出关键代码，能解释**为什么这样写而不是那样**，能看懂它**出错时的报错**。这一层由「自测答得出 + 排错找得到 + 迁移想得到 + 判据全勾」共同定义。

每天页面底部要求勾满判据才算完成，就是在守这条线。
