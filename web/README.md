# HomeCube 学习站

零基础全栈学习网站。59 周、354 张日卡，从 `git init` 学到能独立部署交付一套 Go 全栈系统。

## 启动

```bash
cd ~/www/study-plans/web
npm install          # 首次或依赖变更后
npm run dev
```

浏览器打开 **http://localhost:5178**

## 站点能做什么

| 页面 | 作用 |
|---|---|
| **首页** | 总量统计、每天怎么过、五道能力里程碑 |
| **左侧 15 个阶段** | 按「筑基 / 硬骨头 / 时间系统 / 功能域批 / 收口」五段分组，每阶段显示进度 `已完成/总数` |
| **阶段页** | 该阶段的通过判据、要产出的文件清单、全部日卡入口 |
| **日卡页** | 一张卡七个板块，见下 |
| **搜索** | 搜任意词（`游标`、`乐观锁`、`404`、`nil`）直接跳到讲它的那张卡 |
| **顶部进度条** | 完成张数 / 354，存 localStorage 刷新不丢 ⚠ **当前未生效**，见文末「已知缺陷」 |
| **「继续上次」** | 自动跳回你上次看的那张卡 |

## 一张日卡有七块

1. **为什么要学这个** —— 问题是什么 / 新手会犯什么错 / 正确做法与理由
2. **知识点** —— 2-4 个概念，每个都先讲「解决什么问题」再讲「是什么」，带生活类比
3. **今天的代码** —— 完整可运行的代码，一键复制；下面给「怎么跑」和「应该看到什么」
4. **今天的步骤** —— 编号 + 每步耗时
5. **容易踩的坑** —— 错误做法 / 正确做法 / 为什么会这样
6. **自测** —— 4-5 题，点选项立即判对错并给出解析
7. **今天的产出** —— 可勾选的验收标准；卡住了看提示；末尾预告明天 ⚠ 勾选与「自动判定完成」当前未落库，见文末「已知缺陷」

## 内容原则

- **零基础友好**：每个概念先讲「解决什么问题」，不用术语代替解释
- **对照 TypeScript**：Go 概念优先与 JS/TS 对比（354 张里约 215 张有显式对照，`struct` vs `interface`、error 返回 vs try/catch、goroutine vs Promise……）；没有对应物的概念改用生活类比
- **代码能跑**：Go 示例都是完整程序，`expect` 是真实运行输出，不是手写
- **零基础到能独立交付**：S0 的第一张卡是 `git init`，S14 的最后一张（`s14-d20`）是四条阶段判据自测，其中一条就是「对着整个系统讲一遍数据从哪来、到哪去、谁写谁读」

## 项目对应

本站是一个**独立的学习网站项目**：HomeCube 只是贯穿 354 张日卡的示例载体，教材不依赖任何外部仓库的施工计划。实现代码写到哪、什么时候建目录，由学习者当天决定，本站不做规定。

教材口径见 `../docs/plan/learning-plan.md`（排期与阶段判据）与 `../docs/tech-plan.md`（示例项目的技术方案）；日卡写作规范见 `CARD-GUIDE.md`。

## 加新卡片

日卡有两份，**必须保持一致**：仓库根 `cards/{stage}.json` 是随站点发布的跟踪副本，`web/public/cards/{stage}.json` 是 dev/build 实际读取的文件。改一张卡 = 两处都改（或改一处后 `cp` 覆盖另一处）。

内容格式必须符合 `src/data/types.ts` 的 `Card` 接口与 `CARD-GUIDE.md` 的写作规范，字段一个都不能少；加完刷新页面就出现，不需要改前端代码。

阶段元信息（判据、产出清单）在 `src/data/stages.ts`，改了要重新构建。
