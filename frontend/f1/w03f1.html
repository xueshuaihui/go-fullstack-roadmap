props / emit / slot 与组件拆分

前两周都在一个组件里打转。这周解决「组件之间怎么说话」：props 下行、emit 上行、slot 让父组件塞内容。这三样凑齐，你才能读懂 agent 写出来的任何多组件页面，也才能在拆组件时说出「这个状态该放父还是放子」。今天的动手改是一次真拆分：把一个长 SFC 拆成两个。

今日目标

判据提醒：拆分的标准不是「文件短了」，而是每一块都能独立说清「输入是什么、对外发什么事件」。拆完讲不清这两句，等于没拆。

1. React → Vue：这一周的映射行

ReactVue 3差异要点
function Child(props)defineProps({ … })编译宏，不需要 import；返回的对象模板里直接用，script 里 props.x
props.onChange(v)（父传函数）emit('change', v) + 父模板 @change="…"Vue 不把回调函数当 props 传；事件名显式声明在 defineEmits
props.children<slot />具名插槽 <slot name="x" /> 对应「多个 children 分区」
解构 props 会丢响应性？React 里无所谓Vue 里解构 defineProps 的返回值会丢响应性要解构用 const { x } = defineProps(…) 前加响应式解构支持，或干脆 props.x 整拿
defaultPropswithDefaults(defineProps<…>(), { … }) 或对象写法的 default对象/数组类型的默认值必须是工厂函数

2. 三件套：props / emit / slot

一个最小的子组件，三段各司其职：

完整 · ChildDemo.vue<template>
  <div class="child">
    <p>{{ label }}：{{ count }}</p>
    <button @click="emit('bump', 1)">+1（喊父组件来改）</button>
    <footer><slot /></footer>  <!-- 父组件塞进来的内容渲染在这 -->
  </div>
</template>

<script setup>
const props = defineProps({
  label: { type: String, required: true },
  count: { type: Number, default: 0 },
})
const emit = defineEmits(['bump'])
</script>

父组件这边：

片段 · Parent.vue（count 定义在父，import 略）<ChildDemo label="点击数" :count="count" @bump="count += $event">
  我是塞进 slot 的内容
</ChildDemo>
<!-- :count 有冒号 = 绑表达式；label 没冒号 = 传字符串字面量 -->
方向机制纪律
父 → 子（数据）:count="count" → defineProps子组件里 props 是只读的；直接改会警告且不生效
子 → 父（意图）emit('bump', payload) → @bump事件名显式声明；payload 走 $event 或回调参数
父 → 子（内容）标签中间夹的内容 → <slot />slot 内容里读到的作用域是父组件的，不是子的

单向下行是军规。子组件想改 props？只有两条正路：① emit 一个事件让父改；② 如果这状态只有子自己用，那它就不该是 props——搬到子组件里当本地 ref。第三条路「子组件偷偷改 props 对象的内部字段」在 Vue 里改得动（对象是引用），但它绕开了数据流，是拆组件后最难查的一类 bug。

3. 拆分判据：状态放父还是放子

问题答案 → 归属
这个状态有第二个消费者吗（别的组件也要读）？有 → 放父（或更上层）；没有 → 放子
这个状态改变后，需要通知外面吗？需要 → 放父，子拿 props + emit；不需要 → 子组件本地 ref
典型例子：搜索框的关键词过滤结果列表要用 → 放父；只是输入框自己的临时草稿 → 放子，回车时 emit 出去
典型例子：弹窗开没开只有弹窗按钮关心 → 放子

这套判断和服务端「状态归谁管」的分层直觉是同一件事：数据的家只有一个，其他人都是租客。

定位题（四步法的第三次练习）

现象：父组件明明改了数据，子组件显示的还是旧值。

这是拆组件后最高频的一类 bug。按数据流的走向，从上游往下游一层层排：

  1. 父的数据真的变了吗？在父组件改动处加 console.log——没变 → 问题在父组件自己的逻辑，和 props 无关（回到上周的 ref / .value 排查）。
  2. 绑定写对了吗？模板里是 :count="count" 还是 count="count"？漏了冒号，传过去的是字符串字面量 "count"，父组件怎么改它都不动——这一层死得最冤，先查它。
  3. 子组件是不是在本地改过这个值？搜子组件里有没有 props.x = …（会警告）或者「拿 props 初始化了一个本地 ref，之后各走各的」——后者不报错，本地副本和 props 从此分家，父组件的更新自然「不生效」。
  4. 子组件是不是被缓存/没有重建？如果用了 v-if 切换或动态组件，检查是不是旧实例还挂着；必要时给组件加 :key 强制重建来验证猜想（验证完记得想清楚 key 该不该留）。

注意这四步的顺序就是数据流的顺序：源头 → 绑定 → 接收方本地状态 → 实例生命周期。把「props 不更新排查链」补进 notes/。

常见坑

坑现象正确姿势
绑定时漏冒号子组件永远收到同一个字符串动态值必须 :attr；只有字面量才裸写
子组件直接改 props警告 Avoid mutating a prop；且下次父更新就被冲掉emit 让父改，或把状态搬进子组件
拿 props 初始化本地 ref 后不再同步父改了子不动，不报错要么直接用 props 派生（computed），要么 watch 明确同步并写清理由
解构 defineProps 返回值解构出的变量失去响应性整对象 props.x 用；确需解构查响应式 props 解构写法
camelCase 事件名写在 DOM 模板里@updateKeyword 收不到模板里用 kebab-case：@update-keyword
对象/数组 prop 的 default 写成字面量所有实例共享同一份，互相污染default: () => ({ … }) 工厂函数

今日名词卡

术语一句话解释
props父传子的只读输入；defineProps 声明，编译宏不用 import
emit子通知父的事件机制；defineEmits 声明事件名，父用 @事件名 接
slot / 具名 slot父往子里塞内容的占位符；<slot name="x" /> 对应 <template #x>
单向下行数据只能父 → 子流；子的修改意图只能靠 emit 上行
$event模板里内联事件处理器中，拿到 emit payload 的变量
本地副本分家拿 props 初始化本地状态后不再同步——不报错的响应性断裂
v-model（预告）:modelValue + @update:modelValue 的语法糖；F2 正式用
