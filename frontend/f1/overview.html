F1 · Vue 3 读法

前端辅线的第一段。这四张卡挂在 w01-w04 的周日，与服务端 S1/S2 并行、互不挪用时间。此时 web/ 目录还不存在（agent 要到 S3 才第一次介入），所以 F1 的教材是日卡内嵌的 SFC 片段：读懂、改掉、讲清，不要求跑起来。你已经是 React 开发者，F1 的主线是把 React 心智模型逐项翻译成 Vue 3，并守住一条纪律——不许拿「页面能跑」当自己通过了，代码不是你写的。

为什么 F1 的判据全是「能讲清 / 能改」

前端线的分工是：agent 写代码，你学到能改。目标不是「会写 Vue」，是三条硬能力：① 能读懂任意一页 ② 能改字段与样式 ③ 能独立定位一个 bug 在前端还是服务端。所以每张 F1 卡都有「动手改」（带勾选框的实改动作）与「定位题」（分层排查练习），完成检查里没有一条是「代码写出来了」——那不是你的判据。

阶段判据（全过才算 F1 通过）

不通过就原地重做，不跳阶段。F1 的「读即依赖」心智模型是 F2-F6 全部判据的地基：F3 的 store 排查、F4 的列表渲染、F6 的定位硬判据，全部建立在它上面。

本阶段不做什么（明确划掉，免得手滑）

  • 不写业务前端，不建 web/——它还不存在，F1 全部练习文件放 notes/ 下，不进任何构建
  • 不学 uni-app 工程、路由、条件编译（F2）；不学 Pinia 与真对接（F3）；不学图表与游标分页列表（F4）
  • 不要求练习片段「跑起来」——F1 的验收是讲清与改对，跑起来是 F2 脚手架之后的事
  • 不把 React 当练手项目参照——它只作为概念对照出现（映射表），本站的产物与服务端仓不含任何 React 代码
