Vue 3 是什么：SFC 三段与模板语法

这张卡不写业务代码——服务端这周还在搭骨架，web/ 目录还不存在。今天只做一件事：把你脑子里的 React 心智模型，逐项翻译成 Vue 3。你已经是 React 开发者，所以这张卡 80% 的内容是「哦，原来就是这个」，剩下 20% 是「这里和 React 完全不一样，别按老习惯写」。

今日目标

前端线的判据不是「代码写没写出来」——代码由 agent 写。你的判据是：能读懂任意一页、能改字段与样式、能不靠 agent 说出一个 bug 在前端还是服务端。不许拿「页面能跑」当自己通过了。

1. 一个 SFC 长什么样

SFC = Single File Component，一个 .vue 文件就是一个组件。三段，顺序固定：

完整 · Counter.vue<!-- 第一段：模板。HTML 语法 + Vue 指令，编译成渲染函数 -->
<template>
  <div class="counter" :class="{ 'is-hot': count > 5 }">
    <p>点了 {{ count }} 次</p>
    <button @click="count++">+1</button>
    <span v-if="count > 5">手别抖了</span>
  </div>
</template>

<!-- 第二段：逻辑。script setup 是 Vue 3 的推荐写法 -->
<script setup>
import { ref } from 'vue'

const count = ref(0)
</script>

<!-- 第三段：样式。scoped = 只作用于本组件 -->
<style scoped>
.counter { padding: 8px; }
.is-hot { color: #dc2626; }
</style>

对照 React：

ReactVue 3差异要点
JSX（return <div>…）<template>模板不是 JS，是受限的 HTML 方言：不能写任意表达式，只能写 Vue 认识的语法
useState(0)ref(0)见 §3，这是最容易踩的一条
useEffect(() => …, [x])watch(x, …) / onMounted(…)Vue 把「副作用」拆成几个具名钩子，不靠依赖数组
props 参数defineProps({...})编译宏，不需要 import
children<slot />具名插槽 <slot name="x" />
onClick={fn}@click="fn"@ 是 v-on: 的缩写；: 是 v-bind: 的缩写
CSS Modules / styled<style scoped>编译时给选择器加属性哈希，天然隔离
状态更新 = 换引用（不可变）状态更新 = 改原对象（可变 + 依赖追踪）心智模型最大的一处不同，见 §3

最后一行是重点。React 要你「永远不要改 state，要换一个新对象」；Vue 反过来——直接改，state.items.push(x) 就行，视图会跟着更新。你在 React 里养成的「展开运算符拷贝一份再 setState」的习惯，在 Vue 里是多余的，而且会让依赖追踪失效。

2. 模板语法：五个指令够用 90% 场景

写法作用React 对应
{{ expr }}插值，渲染表达式的值{expr}
:attr="expr"把属性绑成动态值attr={expr}
@event="fn"绑事件onEvent={fn}
v-if / v-else条件渲染（真删 DOM）cond && <X/>
v-show条件显示（只切 display）无直接对应
v-for="(x, i) in list" :key="x.id"列表渲染，:key 必填list.map(…)

v-if 与 v-show 的差别和 React 里「条件渲染 vs CSS 隐藏」一样：频繁切换用 v-show（DOM 留着），条件几乎不变用 v-if（省渲染）。本项目里「未启用与未出生的面在客户端零请求」这条纪律，前端侧就是靠 v-if 把整块区域不渲染实现的——不是 v-show 藏起来。

:class 的对象语法值得单独记，改样式时天天用：

片段<div :class="{ active: tab === 'month', dim: !hasData }">…</div>
<!-- 键是 class 名，值是布尔表达式；为 true 才加上 -->

3. ref 与 .value：为什么模板里不用写

ref(0) 返回的不是 0，而是一个包装对象 { value: 0 }。在 JS 里读写必须走 .value：

片段 · script 里count.value++          // ✅
count++                // ❌ 把 ref 对象本身替换成数字，响应性当场断掉

但模板里自动解包，写 {{ count }} 而不是 {{ count.value }}。为什么必须有这层包装？因为 JS 的原始类型（number/string/boolean）传值不传引用——const count = 0 传进任何函数都只剩一个数字，Vue 没法在它变化时收到通知。包一层对象，引用就留住了。

三个必踩点：① 忘了 .value（在 script 里）→ 值不更新且不报错；② 把 ref 解构出来（const { count } = useCounter()）→ 解包后响应性丢失，要用 toRefs；③ 对象型状态用 ref 还是 reactive 纠结——本项目约定：一律 ref，store 里也一样，减少一种心智负担。

「这个变量改了，为什么那个地方会重渲染」的答案：模板在渲染时读过哪些 ref，就依赖哪些 ref。Vue 在渲染函数执行期间记录「读了谁」，谁变就重跑这个组件的渲染函数。没有依赖数组、没有手动声明——读即依赖。这也是 F1 的毕业判据。

动手改（今天的判据现场）

把下面这个 SFC 存成 notes/f1w1/Counter.vue（纯练习文件，不进服务端仓的构建），然后做三处改动：

完整 · 练习起点<template>

    <h3>{{ title }}</h3>
    <p>本月支出 {{ amount }} 元</p>

  </div>
</template>

<script setup>

const title = ref('十月')

</script>

没有构建环境跑不起来？没关系——今天不要求跑起来。改完逐行读一遍，确认自己说得出「这一行改的是哪一段、会影响模板里哪一处」。跑起来是 w05（F2）的事，那时 agent 会脚手架出 web/。这三条勾选框勾的是「我改完了且讲得清」。

定位题（F6 判据的第一次练习）

现象：页面上「本月支出」一直显示 0，点按钮也没反应。

不用猜。按这个顺序走，每一步都能排除一整层：

  1. 打开 devtools 的 Console：有红色报错吗？有 → 前端 JS 运行时错误，看堆栈第一行。
  2. 没有报错 → 看 Network：这个页面发请求了吗？响应体里有 amount 这个字段吗？字段根本没有 → 服务端问题（没返回 / 字段名不对 / 被响应包的外层 data 挡住）。
  3. 字段有且值非 0 → 前端绑定问题：模板里写的是 {{ amount }} 还是 {{ amount.value }}？script 里有没有把接口返回值赋给 amount.value（漏了 .value 是这一层最高频的死法）？
  4. 点按钮没反应：按钮的 @click 在吗？handler 里改的是 amount.value 还是 amount？

把这套顺序写进 notes/。以后每一个前端 bug 都先走这四步，走完再说「是前端还是服务端」——这是 F6 的硬判据，今天先练第一遍。

常见坑

坑现象正确姿势
script 里漏 .value值不更新，不报错script 里永远 x.value；模板里永远不写
解构 store / composable 的返回值解构出来的变量不再响应用 toRefs，或整对象拿着用 s.count
把 React 的不可变习惯带过来list.value = [...list.value, x] 能跑但多余Vue 里 list.value.push(x) 即可
v-for 不写 :key列表顺序变化时 DOM 复用错乱:key 用业务 id，不用 index
模板里写复杂表达式能跑但没法测、没法复用抽成 computed（w02 讲）
