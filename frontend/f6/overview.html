F6 · 调试、定位与前端线毕业

前端辅线的最后一段，与服务端 S8（收口与部署）并行，同时收拢贯穿 F1-F5 的全部定位练习。F6 不新增功能面，只做两件事：① 把定位能力练成方法论——三段定位法（Console / Network / 服务端日志 + request_id），顺带解决「服务跑进容器之后前端怎么连」；② 把整条前端线收口——三个硬能力逐条验收、全站红线复测、F1-F6 全 22 张卡判据总核账，并产出你以后长期要用的「快速复核检查单」。

F6 的硬判据只有一句话

agent 故意留一个 bug（或真出现一个），你能不靠 agent 说出它在哪一层、为什么。这就是前端辅线三条硬能力（① 能读懂任意一页 ② 能改字段与样式 ③ 能独立定位一个 bug 在前端还是服务端）的终点验收。作答格式是证据句式：「我判定 X 层，因为在 Network/日志/Console 看到了 Y，排除了 Z」——没有分界物证据的「感觉是后端问题」一律不算。

同期的服务端卡在 S8（收口与部署：Dockerfile、compose、nginx、CI 全量 + 覆盖率、对账与冒烟）；F6 只学「前端怎么连上它、怎么验收它」，部署产物本身是服务端线的活。

本阶段不做什么（明确划掉，免得手滑）

  • 不学新功能面、新框架、新状态方案——F6 只收口，任何「顺便学一下」都是对 2 小时预算的超支
  • 不亲手写部署脚本——Dockerfile / compose / nginx 配置是 S8 服务端卡的产物，前端侧只要求「看得懂连线、能冒烟」
  • 不为毕业放松任何红线——六条红线复测不过，判据就是不过，与「整体完成度很高」无关
  • 不拿「agent 写的代码一直没问题」当硬判据的替代——埋 bug 验收必须真做一次，没埋过 bug 的定位能力是没验证过的能力
  • 不做课程范围外的前瞻（离线重放的服务端侧、事件总线、远程 .wgt 下发链路）——它们只存在于服务端线的前瞻句里
