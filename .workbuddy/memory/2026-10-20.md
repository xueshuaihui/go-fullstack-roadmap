## 侧边栏「阶段下按天导航」

- `web/src/components/Sidebar.vue` 重写：阶段行改为「折叠箭头 + 阶段名」两段式按钮；每个阶段下渲染该阶段全部天（D1…D20，带完成圆点 / 半程点 / 「今」标记 / 进度条形式省略标题）。点天 → 派发 `roadmap:jump` 让 DayPlan 展开当天 → nextTick 后 `scrollIntoView`，位置落在 70px 锚点。
- 导航交互：手风琴（同时只展开一个阶段），默认展开 `nextDay` 所在阶段；点阶段名 = 定位到阶段 + 展开；天列表 `max-height: min(48vh,430px)` 独立滚动，长阶段不会把后面阶段挤出视口；跳转后自动把目标天滚进该列表可视区（`revealInList`）。
- 当前位置高亮从 IntersectionObserver 换成「参考线」算法：滚动时 rAF 节流，取最后一个 `getBoundingClientRect().top <= line` 的锚点，`line = .day 的 scroll-margin-top + 20`，避免整段/下一天误判（老实现会高亮到 D4/D5 而不是 D3）。
- `App.vue` 用 ResizeObserver 把顶栏实际高度写进 `--topbar-h`；`style.css` 的侧边栏 `top/height`、`.doc-section` / `.day` 的 `scroll-margin-top` 全部改用它。修掉窄屏顶栏折行后抽屉第一项（今天卡片）被顶栏遮住的旧问题。
- 侧边栏宽度 262 → 288px，天标题可多显示 3~4 个字；侧边栏也监听 `roadmap:jump`，搜索命中某天时自动展开对应阶段并高亮。
- 验证（CDP，headless Chrome 需 `--headless=old`，`--headless=new` 会在本机 GPU 进程崩）：94 个天条目全部渲染；初始只 1 个阶段展开；点阶段 3 箭头后仍 1 个（手风琴）；点 D18 页面落位 70px、列表 scrollTop=48、目标在列表可视区；`roadmap:jump p5-d4` 自动展开阶段 5 且高亮 D4；点「今天」回到阶段 1 D1；移动端 390px 抽屉 left=0、条目 94；Runtime 无异常；`npm run build` 通过。
