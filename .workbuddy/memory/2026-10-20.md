## markdown-it 加粗不渲染的坑（重要）

- 现象：页面露出字面量 `**`。根因不是解析器 bug，是 **CommonMark 的 delimiter run 规则**：
  - `**「X」Y**` —— 收尾 `**` 前是中文标点（`」`、`。`、`「` 等），被判为 right-flanking 失败 → 整对不生效。
  - `**……。**但更隐蔽` —— 收尾 `**` 前是 `。`（标点）、后是汉字（非空格非标点），同样失败。
- 两条可靠写法：① 被加粗文字后紧跟冒号/顿号时，写成 `「**X**」Y`；② 句末加粗时把句号移出，写成 `**整句不带句号**。` 而不是 `**整句带句号。**后面`。
- 修复脚本 `/tmp/sp-audit/fixbold.mjs`：批量把 `**「T」R**` → `「**T**」R`，改了 11 个文件 100 处（lessons/phase2、phase3、phase5、phase5b、phase6；mastery/phase1-6）。剩余 3 处（`mastery/phase1.md` 152/205/398 行）手工把句号移出加粗范围。
- 检测脚本 `/tmp/sp-audit/findbad2.mjs`：逐行剥掉行内 code 再 `md.renderInline`，输出里残留 `**` 即报告；比直接 grep `**` 可靠（`a***@x.com`、`"***"`、`.x::placeholder` 都是假阳性）。最终 `bad days 0`。
- 另一个同类坑：行内 code 里写 `\``（如 `` `CREATE TABLE \`entries\`` ``）会让 code span 提前闭合，把后面整行吞掉 → 直接改成不含转义反引号的写法。
