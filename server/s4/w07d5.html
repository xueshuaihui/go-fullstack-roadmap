鉴权中间件 middleware.Auth 与 context 键

前四天签出去的 token，今天开始有人验了。middleware.Auth 是全站受保护路由的唯一入口：解析 Bearer、验签验型、查成员状态、比对 pver，然后把身份写进 Gin context。从今天下午起，你的服务第一次有了「闲人免进」的语义——以及全站最容易写歪的一组约定：context 键纪律。

今日目标

知识讲义

1. 中间件在 Gin 里的位置

S2 你已经写过 request-id 与 recovery 中间件——Auth 是同一个物种：gin.HandlerFunc，挂在路由组上，先于 handler 执行。它做四步，任何一步不过就 c.Abort() 终止链条：

  • 取：从 Authorization: Bearer <token> 头里剥出裸 token（没有这个头、格式不对 → 401 + 1005）；
  • 验：jwtutil.Parse(accessSecret, tok, "access")——签名、过期、类型三关（失败 → 401 + 1005）；
  • 查：mid > 0 时按主键查成员：不存在、已软删、status 非在档、或库里 pver 与 token 里的 pver 不一致 → 401 + 1005。这一步是「无状态 JWT」与「可撤销」之间的桥：一次主键查询的代价，换「移除成员/改角色立即生效」；
  • 存：把身份写进 context，后面的 handler 与 scope helper 只认 context。

mid == 0（注册了还没进任何家庭的用户）跳过第三步：身份合法但无家庭上下文，familyID 为 0——家庭域接口靠 scope 查不出任何数据，自然得到 404，这正是隔离该有的样子。

2. context 键纪律：六个键，全站唯一

键类型读取姿势
"userID"int64c.GetInt64("userID")
"memberID"int64c.GetInt64("memberID")
"familyID"int64c.GetInt64("familyID")
"role"model.Rolemiddleware.RoleOf(c)（类型断言封装）
"pver"intc.GetInt("pver")
"request_id"stringc.GetString("request_id")（S2 的 request-id 中间件写入，Auth 不重复写）

三条禁令，S4 收口时会 grep 全仓验收：① 禁裸键——不许出现 c.Set("uid", ...) / c.GetInt64("fid")，claim 的短名只活在 JSON 里，context 键用全名；② 禁 GetInt8 读角色——role 存的是 model.Role 类型，GetInt8 拿到的是零值，静默把你降成「无角色」；③ 禁从请求参数取 family_id——参数可伪造，context 里的才由签名背书。三个键名打错一个字母，Gin 不报错、只给你零值，这类 bug 靠纪律和 grep 防，不靠编译器。

步骤 1 · 中间件本体

完整 · server/internal/platform/middleware/auth.gopackage middleware

import (
    "errors"
    "net/http"
    "strings"

    "github.com/gin-gonic/gin"

    "homecube/internal/homeos/model"
    "homecube/internal/homeos/repo"
    "homecube/internal/platform/jwtutil"
    "homecube/pkg/response"
)

// MemberLoader 中间件对「查成员」的全部要求——只依赖接口，测试可注入内存实现。
type MemberLoader interface {
    FindActiveByID(id int64) (*model.Member, error) // 软删或非在档 status 返回 nil + ErrNotFound
}

// Auth 全站唯一鉴权入口。secret 是 access 密钥（cfg.JWTSecret）。
func Auth(secret string, members MemberLoader) gin.HandlerFunc {
    return func(c *gin.Context) {
        deny := func() { // 所有失败一个出口：401 + 1005，不细分
            response.Fail(c, http.StatusUnauthorized, response.CodeUnauthenticated, "未认证或登录已失效")
            c.Abort()
        }
        raw := c.GetHeader("Authorization")
        tok, ok := strings.CutPrefix(raw, "Bearer ")
        if !ok || tok == "" {
            deny()
            return
        }
        claims, err := jwtutil.Parse(secret, tok, jwtutil.TypeAccess)
        if err != nil { // 验签 / 过期 / 类型三关，一个出口
            deny()
            return
        }
        if claims.MemberID > 0 { // 有家庭会话：查成员状态与 pver（无状态与可撤销之间的桥）
            m, err := members.FindActiveByID(claims.MemberID)
            if err != nil && !errors.Is(err, response.ErrNotFound) {
                response.FailErr(c, err) // 查库本身出错 → 5000，不冒充 1005
                c.Abort()
                return
            }
            if m == nil || m.FamilyID != claims.FamilyID || m.Pver != claims.Pver {
                deny() // 被移除 / 已退出 / 角色变了（pver 对不上）→ 旧 token 立刻死
                return
            }
        }
        // 六个 context 键，全站唯一写法（request_id 由 S2 的中间件负责，不在此重复）
        c.Set("userID", claims.UserID)
        c.Set("memberID", claims.MemberID)
        c.Set("familyID", claims.FamilyID)
        c.Set("role", claims.Role)
        c.Set("pver", claims.Pver)
        c.Next()
    }
}

// RoleOf 读角色的唯一姿势：model.Role 类型断言。禁 GetInt8。
func RoleOf(c *gin.Context) model.Role {
    v, exists := c.Get("role")
    if !exists {
        return 0 // 0 不是合法角色值——没经过 Auth 就取角色，矩阵判定必然拒绝
    }
    r, _ := v.(model.Role)
    return r
}

注意 deny 里 Fail 之后紧跟 c.Abort()：中间件拒绝必须终止链条，否则 handler 还会接着写一遍响应。这个「写响应 + Abort」的成对动作封装成闭包，五个失败分支共用，就不会漏。

两个依赖注入说明：① MemberLoader 只要求一个方法，GORM 版 repo 天然满足（S1·D4 的隐式实现又一次上岗）；② Auth(secret, members) 在基准签名之外多带一个数据访问参数——密钥进中间件、查库走接口，测试才能不碰真库。装配处把 member repo 传进去即可。

步骤 2 · 测试

完整 · server/internal/platform/middleware/auth_test.gopackage middleware

import (
    "net/http/httptest"
    "testing"

    "github.com/gin-gonic/gin"

    "homecube/internal/homeos/model"
    "homecube/internal/homeos/repo"
    "homecube/internal/platform/jwtutil"
)

func setup(t *testing.T, members MemberLoader) *gin.Engine {
    t.Helper()
    gin.SetMode(gin.TestMode)
    r := gin.New()
    g := r.Group("/api/homeos", Auth("test-secret", members))
    g.GET("/probe", func(c *gin.Context) { // 仅测试装配，不注册进生产路由
        c.JSON(200, gin.H{"familyID": c.GetInt64("familyID"), "role": RoleOf(c)})
    })
    return r
}

func doReq(r *gin.Engine, header string) *httptest.ResponseRecorder {
    w := httptest.NewRecorder()
    req := httptest.NewRequest("GET", "/api/homeos/probe", nil)
    if header != "" {
        req.Header.Set("Authorization", header)
    }
    r.ServeHTTP(w, req)
    return w
}

func TestAuth(t *testing.T) {
    mem := repo.NewMemoryMemberRepo()
    mem.Seed(&model.Member{ID: 10, UserID: 1, FamilyID: 3, Role: model.RoleOwner, Pver: 2, Status: model.StatusActive})
    r := setup(t, mem)

    good, _ := jwtutil.Sign("test-secret", jwtutil.Claims{
        UserID: 1, MemberID: 10, FamilyID: 3, Role: model.RoleOwner, Pver: 2, Type: jwtutil.TypeAccess})
    stalePver, _ := jwtutil.Sign("test-secret", jwtutil.Claims{
        UserID: 1, MemberID: 10, FamilyID: 3, Role: model.RoleMember, Pver: 1, Type: jwtutil.TypeAccess})
    refreshAsAccess, _ := jwtutil.Sign("test-secret", jwtutil.Claims{Type: jwtutil.TypeRefresh})

    cases := []struct{ name, header string; wantCode, wantBiz int }{
        {"没带头", "", 401, 1005},
        {"格式不对", "Token abc", 401, 1005},
        {"签名错", "Bearer xxx.yyy.zzz", 401, 1005},
        {"refresh 冒充", "Bearer " + refreshAsAccess, 401, 1005},
        {"pver 过期", "Bearer " + stalePver, 401, 1005},
        {"合法通过", "Bearer " + good, 200, 0},
    }
    for _, tc := range cases {
        t.Run(tc.name, func(t *testing.T) {
            w := doReq(r, tc.header)
            if w.Code != tc.wantCode {
                t.Fatalf("HTTP = %d, want %d, body=%s", w.Code, tc.wantCode, w.Body.String())
            }
            // body 里 "code":<n> 用 strings.Contains 断言即可，别解析整个信封
        })
    }
}

「pver 过期」这条用例值得盯三秒：token 签名完全合法、也没过期，但库里成员的 pver 已经是 2，token 里还是 1——拒绝。下下周一角色变更接口（S4·D17）做的就是把库里 pver +1，让某个人手里的旧 token 走上这条用例的路。机制今天已经就位。

坑现象正确姿势
拒绝后忘了 c.Abort()中间件写了 401，handler 又接着写 200，日志出现 superfluous WriteHeaderAbort 与写响应成对出现；本卡 deny 闭包已封装
把 Bearer 前缀一起送去 Parse永远「token is malformed」strings.CutPrefix 剥掉再用；注意 Bearer 后有一个空格
用 c.GetInt8("role")拿到的永远是 0，权限判定全拒或全放（看你矩阵怎么写）role 是 model.Role，走 RoleOf(c)
键名打错（familiyID）不报错，静默零值；越权查询 family_id=0 查不到数据，你以为是库坏了六个键抄进 notes；收口日 grep 全仓核对
查库失败也回 1005数据库抖动被伪装成「登录失效」，全员被登出还查不出原因系统错误走 FailErr → 5000；1005 只给「身份不合法」
每个请求查三次库（user/member/family）中间件比业务还重只查 member 一次：status、pver、family 归属一锅端；其余信息信 token 快照

今日名词卡

术语一句话解释
Bearer 认证Authorization: Bearer <token> 头；「持票人」语义——票对就认，所以票必须短命可撤销
c.Abort()终止 Gin 处理链：后续中间件与 handler 不再执行
context 六键userID/memberID/familyID/role/pver/request_id；Auth 写五个，request_id 归 S2 的中间件
裸键禁令claim 短名（uid/fam）只活在 JWT JSON 里；context 一律全名，防手滑防歧义
MemberLoader中间件依赖的最小接口（一个方法）；GORM repo 隐式满足，测试注入内存实现
pver 比对token 快照 pver vs 库里 pver：不等即拒——「已签发的 token 收不回」的补救桥
零值陷阱Gin 取不存在的键返回零值不报错；角色 0 不合法、familyID 0 查无数据，都靠纪律兜住
公开组 / 受保护组/api/homeos/auth 公开，其余全挂 Auth；分界线就画在路由装配处，一眼可审计

卡壳时查什么

正文自足，只有两种情况出去查：

  • Gin 中间件执行顺序与 Abort 语义：gin.Context 文档（可选，S2 中间件那张卡也讲过一遍）。
  • strings.CutPrefix 忘了怎么用：标准库文档一句话的事；Go 1.20+ 才有它，老教程里的 strings.TrimPrefix 不区分「有没有这个前缀」，别混用。

401 排查顺序：先 curl -i 确认头带了且格式对 → 把 token 中段解码看 typ/pver → 查库对 pver 与 status。三步必中。
