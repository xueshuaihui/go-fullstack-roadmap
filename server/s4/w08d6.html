2. PUT 的两根轴：改哪些字段（白名单）× 改谁（编辑权）

PUT /api/homeos/members/{id} 的 body 只有三个字段：name、relation、guardian_id。这条接口压根不接受 role、status、user_id、family_id——不是「收到后拒绝」，是 DTO 里没有这些字段，Gin 绑定时直接忽略。这是本站的一条硬口径：

能力不声明就不存在。角色变更有自己的接口（S4·D17 的 PUT members/{id}/role），status 是明天 S4·D13 的 family/leave 的事，user_id 与 family_id 是身份归属、任何编辑接口都不许动。把它们塞进 PUT 的 DTO 再「用角色判断拦一下」，等于把升权通道开在字段层，判定也就此散成第二份。

部分更新用指针：*string 为 nil 表示「这次不改」，非 nil（哪怕空串）表示「改成这个值」。值类型做不到这件事——空串到底是「清空称谓」还是「前端没带这个字段」？S1·D2 的指针语义第六次上岗。

你是谁能改谁能改哪些字段越界给什么码

4. 移除的三道门，以及那条 409 + 1010

DELETE /api/homeos/members/{id} 走完整三道门，顺序不许换：

  1. 定界：FindByID(ctx, familyID, id) 捞不到 → 404 + 1001（别家成员的存在性一点都不能泄露）；
  2. 判权：owner 恒可、其余不可 → 403 + 1003；
  3. 状态门：这条门是今天的新东西——homeos_member 里在档的 owner 行恒为一条（唯一性由转让保证：今天第 6 节的转让在同一个事务里一降一升，不存在两个主人），所以「移除掉这个家庭唯一的主人」这个动作本身不是不允许，而是必须先换主人 → ErrStateNotAllowed → 409 + 1010。

两道门叠加会产出两种容易混的结果，今天把它钉死：owner 用这条接口动自己 → 1010（你是唯一主人，先转让）；member/ward/guest 用这条接口动自己 → 1003（矩阵里压根没有「把自己移除」这条边）。为什么非得分开？因为对 member 来说「我要走」是个真实需求，那条路叫退出，是明天 POST family/leave 的语义：退出是本人意愿、档案留档；移除是 owner 对他人身份的清除、要软删留痕。把两件事塞进一条接口，就会得到「member 能自己踢自己，owner 反倒踢不掉自己」这种口径混乱。

被移除的人，手里的票什么时候死？下一次请求就死：D5 的中间件对每个带 mid 的请求都要 FindActiveByID，软删行捞不到 → 401 + 1005；他拿 refresh 去换票，换票同样要过在档校验，签不出新会话。别顺手调 RevokeAllByUser——那是 D6「重置密码 = 全设备下线」的动作，按账号撤销；一个成员可能同时在 5 个家庭里有身份，踢出这一家不该把他在别家的有效会话一起干掉。跨家庭精确撤销需要 (user, family) 维度的通道，接口清单里没有，明天之后由 pver 那条路子的同类思路解决（D14 讲判定、D17 讲失效，今天只记这笔账）。

5. 头像上传：与附件同一族限额，但不是同一份口径

POST /api/homeos/members/{id}/avatar 收 multipart/form-data，字段名固定 file。首次接触 multipart，最小讲解三条：

  • c.FormFile("file") 返回 (*multipart.FileHeader, error)——它只是文件头：名字、声明的类型、字节数，内容还没读进内存，要 file.Open() 拿 Reader 才读；
  • file.Filename 与 file.Header.Get("Content-Type") 都是客户端自己写的，只能当线索，不能当证据；
  • SaveUploadedFile(dst) 把临时文件落到位，dst 的目录你得自己按家庭拼。
限额附件（后面财务面正式讲）头像（今天）超限的码
张数每笔流水 ≤ 3 张一个成员一张，覆盖式：传新即换旧张数对头像没有意义，不产生错误
单张大小≤ 5MB≤ 5MB（同一档）400 + 4002
格式jpg / png / webpjpg / png / webp（同一族白名单）400 + 4002
请求里压根没带文件——400 + 1004（参数错误，与「文件不合格」不同族）

关键口径：不发明新错误码。码表里 4002 那一行写的是「附件超限（>3 张 / 单张 >5MB / 格式非 jpg·png·webp）」，头像超限是同一类用户动作（「你传的文件不合格」），复用 4002；只有「没带 file 字段」「id 不是数字」这种请求本身畸形才走 1004。

落盘路径 uploads/{family_id}/avatars/{member_id}.{ext}——按家庭分目录是隔离纪律在文件系统上的延伸，和「每条查询带 WHERE family_id = ?」是同一件事的两个面。库里 homeos_member.avatar 存相对路径字符串（S3 建表时这列就是 TEXT NOT NULL DEFAULT ''），不存 base64：头像进 base64 会把一行 member 撑成几十 KB，列表接口一次就拖几百 KB，缓存与网络全遭殃。

6. 转让：一个事务两行 UPDATE，外加一笔已知窗口

POST /api/homeos/family/transfer-owner，body 只有一个 {member_id}——目标家庭永远来自 token 的 fam，转让不可能把主人身份转到别人家去。它是唯一能产出 owner 成员的通道之一（另一个是建家庭，见 D7 的坑表：「建档只收 ward/member；owner 唯一来源是建家庭与转让」）。

情形结果为什么是这个码
发起人不是 owner403 + 1003判权拒绝：矩阵里 family:transfer 只给 owner
member_id 是别家的 / 已软删404 + 1001定界在前：捞不到就是不存在

今天留下一笔明账，并且不修它：转让写完，旧 owner 手里那张 access token 的 role 快照还是 1，最长 15 分钟内他仍按 owner 被判定；新 owner 手里的票还按 member 判定。这不是遗漏，是「无状态 JWT 的快照会过时」这件事的现场证据——把 homeos_member.pver +1 才能立刻作废，那是 S4·D17 那条接口的增量。今天只做三件事：事务两行、给发起人重签（IssueForSession）、把「15 分钟窗口」写进 notes/。

import (
    "context"
    "fmt"

    "homecube/internal/homeos/model"
    "homecube/internal/homeos/repo"
    "homecube/pkg/response"
)

// editableFields 是 PUT members/{id} 的字段白名单全集：不在表里的字段不是这条接口的能力。
// role / status / user_id / family_id / pver / version 一律不在（角色是 D17，status 是 D13）。
var editableFields = map[string]bool{
    "name": true, "relation": true, "guardian_id": true,
}

// canEditMember 编辑权判定的唯一实现（homeos 域内）。
// 临时形态：S4·D14 建 platform/authz 后本函数整体搬走，调用点一行不改。
// 返回该 actor 对这个 target 可改的字段集；nil = 一律不可改（→ 403 + 1003）。
func canEditMember(actor, target *model.Member) map[string]bool {
    switch {
    case actor.Role == model.RoleGuest:
        return nil // 访客只读，连自己都不改
    case actor.Role == model.RoleOwner:
        return editableFields
    case actor.ID == target.ID:
        if actor.Role == model.RoleWard {
            return map[string]bool{"name": true}
        }
        return map[string]bool{"name": true, "relation": true}
    case target.Role == model.RoleWard && target.GuardianID != nil &&
        *target.GuardianID == actor.ID:
        return editableFields // 监护人替自己带的孩子改资料（D7 埋的 guardian_id 今天兑现）
    }
    return nil
}

// assertRemovable 移除接口的状态门（第三道门）。前两道门：定界在 repo、判权在矩阵。
func assertRemovable(target, actor *model.Member) error {
    if target.ID == actor.ID {
        if target.Role == model.RoleOwner {
            return response.ErrStateNotAllowed // 唯一 owner 未转让即移除 → 409 + 1010
        }
        return response.ErrForbidden // 「把自己移除」这条边不存在：退出是 D13 的 leave
    }
    if target.Role == model.RoleOwner {
        return response.ErrStateNotAllowed // owner 行不能被任何人干掉，转让是唯一出路
    }
    return nil
}

type MemberService struct {
    members repo.MemberRepo
    auth    *AuthService // 转让后要重签：D7/D9 的 IssueForSession
}

// UpdateMember 部分更新：in 里 nil 的字段不碰。actor 是发起人的成员行。
func (s *MemberService) UpdateMember(ctx context.Context, familyID int64, actor, target *model.Member, in *UpdateMemberInput) (*model.Member, error) {
    fields := canEditMember(actor, target)
    if fields == nil {
        return nil, response.ErrForbidden // 403 + 1003：看得见，改不了
    }
    if in.Name != nil {
        if !fields["name"] {
            return nil, response.ErrForbidden
        }
        target.Name = *in.Name
    }
    if in.Relation != nil {
        if !fields["relation"] {
            return nil, response.ErrForbidden
        }
        target.Relation = *in.Relation
    }
    if in.GuardianID != nil {
        if !fields["guardian_id"] {
            return nil, response.ErrForbidden
        }
        if target.Role != model.RoleWard {
            return nil, response.ErrInvalidParam // 1004：只有 ward 有监护人
        }
        g, err := s.members.FindByID(ctx, familyID, *in.GuardianID) // 定界：别家的监护人当不存在
        if err != nil {
            return nil, err // ErrNotFound → 404 + 1001
        }
        if g.ID == target.ID || g.Status != model.StatusActive {
            return nil, response.ErrInvalidParam // 1004：不能自我监护、不能挂已退出的人
        }
        target.GuardianID = in.GuardianID
    }
    if err := s.members.Update(ctx, target); err != nil {
        return nil, fmt.Errorf("update member: %w", err)
    }
    return target, nil
}

UpdateMemberInput 就是三个指针字段（Name/Relation *string、GuardianID *int64）。成员编辑今天不带 version 乐观锁：家庭名册的并发写不在本期清单要求内，乐观锁的正式战场是财务流水与面配置。不要顺手把 1009 加进来——加了就等于提前把后面的判据搬走。

import (
    "io"
    "net/http"
    "path/filepath"
    "strconv"

    "github.com/gin-gonic/gin"

    "homecube/internal/homeos/model"
    "homecube/pkg/response"
)

const avatarMaxBytes = 5 << 20 // 单张 ≤ 5MB

// avatarMimes 扩展名 → 期望嗅探结果。webp 的头部不保证在标准库嗅探表里，见下方核字节。
var avatarMimes = map[string]string{
    ".jpg":  "image/jpeg",
    ".jpeg": "image/jpeg",
    ".png":  "image/png",
    ".webp": "image/webp",
}

// UploadAvatar 处理 POST /api/homeos/members/{id}/avatar。
func (h *MemberHandler) UploadAvatar(c *gin.Context) {
    id, err := strconv.ParseInt(c.Param("id"), 10, 64)
    if err != nil {
        response.Fail(c, 400, response.CodeInvalidParam, "参数错误") // 1004：id 本身畸形
        return
    }
    fam := c.GetInt64("familyID")

    // ① 请求体上限：MaxBytesReader 超限直接断流，不把大文件读进内存再判。
    //    这行今天照抄，正式讲在财务面附件那一课（三条限额同族）。multipart 封装有额外开销，留 64KB 余量。
    c.Request.Body = http.MaxBytesReader(c.Writer, c.Request.Body, avatarMaxBytes+64*1024)

    file, err := c.FormFile("file")
    if err != nil {
        response.Fail(c, 400, response.CodeInvalidParam, "参数错误") // 没带 file 字段 → 1004
        return
    }
    if file.Size > avatarMaxBytes {
        response.Fail(c, 400, response.CodeAttachmentLimit, "文件超限或不合法") // 4002
        return
    }
    ext := filepath.Extname(file.Filename).ToLower()
    want, ok := avatarMimes[ext]
    if !ok {
        response.Fail(c, 400, response.CodeAttachmentLimit, "文件超限或不合法") // 4002：白名单外
        return
    }

    // ② 读前 512 字节嗅探真类型：Filename 与 Content-Type 都是客户端写的，不算证据。
    head := make([]byte, 512)
    f, err := file.Open()
    if err != nil {
        response.FailErr(c, err)
        return
    }
    defer f.Close()
    n, err := io.ReadFull(f, head)
    if err != nil && err != io.ErrUnexpectedEOF {
        response.FailErr(c, err)
        return
    }
    got := http.DetectContentType(head[:n])
    if ext == ".webp" {
        got = sniffWebP(head[:n], got) // 嗅探表覆盖不到 webp 时手工核 RIFF….WEBP
    }
    if got != want {
        response.Fail(c, 400, response.CodeAttachmentLimit, "文件超限或不合法") // 4002：扩展名与内容不符
        return
    }

    // ③ 编辑权判定不在这里 —— handler 不调 canEditMember，交给 service（判定只有一处）
    mem, err := h.members.FindByID(c.Request().Context(), fam, id) // 定界在前
    if err != nil {
        response.FailErr(c, err)
        return
    }
    actor, err := h.members.FindActiveByID(c.Request().Context(), c.GetInt64("memberID"))
    if err != nil {
        response.FailErr(c, err)
        return
    }
    res, err := h.avatars.Save(c.Request().Context(), fam, actor, mem, file)
    if err != nil {
        response.FailErr(c, err) // ErrForbidden → 403 + 1003
        return
    }
    response.OK(c, gin.H{"member_id": mem.ID, "avatar": res.Path})
}

sniffWebP 是五行小函数：前 4 字节 RIFF 且第 8-12 字节 WEBP 就返回 "image/webp"，否则原样返回嗅探结果。AvatarService.Save 里三件事——canEditMember 判定（头像算 name 那一档，本人/owner/监护人可传）→ 落盘 uploads/{family_id}/avatars/{member_id}.{ext}（先写临时名再 rename，避免传一半留半张）→ 写库。旧头像文件删除失败只记日志不回滚：库里已经是新路径，旧文件成了孤儿，这属于清理任务的事，不该让一次上传失败。

上传根目录今天是一个包内常量（./uploads），不要现在就去 config 里加 UPLOAD_DIR：那个变量的正式出生是在财务面附件那一课（同时带限额配置与目录挂卷口径）。今天抢着加，等于提前拿走后面的增量，还留一个没人读的配置项——那正是本站反例里「注册了但没用了的假入口」的配置版。在 avatarRoot 那行上写一句注释指向那里就够。

步骤 4 · 移除与转让

片段 · <repo>/server/internal/homeos/service/member_edit.go 追加（前置：上面的 MemberService）// RemoveMember 三道门：定界（repo 的 scope）→ 判权（矩阵）→ 状态（assertRemovable）。
func (s *MemberService) RemoveMember(ctx context.Context, familyID, targetID int64, actor *model.Member) error {
    target, err := s.members.FindByID(ctx, familyID, targetID) // ① 定界：别家 → ErrNotFound
    if err != nil {
        return err
    }
    if actor.Role != model.RoleOwner {
        return response.ErrForbidden // ② 判权 → 403 + 1003 // TODO(S4·D14)：收进 platform/authz
    }
    if err := assertRemovable(target, actor); err != nil {
        return err // ③ 状态门 → 409 + 1010 / 403 + 1003
    }
    return s.members.SoftDeleteInFamily(ctx, familyID, targetID, actor.ID)
}

// TransferOwner 事务两行：旧主人降 member、新主人升 owner。owner 恒一条就在这里保证。
func (s *FamilyService) TransferOwner(ctx context.Context, familyID int64, actor *model.Member, targetID int64) (*model.Family, *model.Member, error) {
    if actor.Role != model.RoleOwner {
        return nil, nil, response.ErrForbidden // TODO(S4·D14)：同上
    }
    if targetID == actor.ID {
        return nil, nil, response.ErrStateNotAllowed // 409 + 1010：转让前后主人没变
    }
    target, err := s.members.FindByID(ctx, familyID, targetID) // 定界在前：别家的 id → 404 + 1001
    if err != nil {
        return nil, nil, err
    }
    if target.Role != model.RoleMember {
        return nil, nil, response.ErrInvalidParam // 1004：ward/guest 不具备接任资格
    }
    err = s.db.WithContext(ctx).Transaction(func(tx *gorm.DB) error {
        if e := tx.Scopes(scope.InFamily(familyID)).Model(actor).
            Updates(map[any]any{"role": model.RoleMember, "version": gorm.Expr("version + 1")}).Error; e != nil {
            return fmt.Errorf("demote old owner: %w", e)
        }
        if e := tx.Scopes(scope.InFamily(familyID)).Model(target).
            Updates(map[any]any{"role": model.RoleOwner, "version": gorm.Expr("version + 1")}).Error; e != nil {
            return fmt.Errorf("promote new owner: %w", e)
        }
        return nil
    })
    if err != nil {
        return nil, nil, err // 任一行失败：主人没换过，两行都保持原样（S3 事务课第三次实战）
    }
    // 已知窗口：对方手里的 role 快照最长再活 15 分钟 —— pver+1 的正解在 S4·D17，今天只记账
    fam, err := s.families.FindByID(ctx, familyID)
    if err != nil {
        return nil, nil, err
    }
    return fam, target, nil
}

转让的 handler 里，事务成功后调 h.auth.IssueForSession(ctx, userID, actor) 给发起人重签一对 token——他刚从 owner 变成 member，不重签他就还拿着旧身份在会话里。不给目标方重签：他此刻手里的票是旧 role 的快照，那 15 分钟窗口已经写在上面那行注释里，属于 D17 的账。

func (f *boundaryFixture) mustUploadAvatar(t *testing.T, memberID, token, kind string, wantStatus, wantCode int) {

今日名词卡

术语一句话解释
字段白名单接口只声明它能改的字段；白名单外的 JSON 键被绑定层忽略，不是被拒绝
部分更新（指针 DTO）*string 为 nil 表示「这次不改」，非 nil 表示「改成这个值」，空串也是改

移除 vs 退出移除是 owner 对他人身份的清除（软删留痕）；退出是本人意愿（status 变更，明天 D13）
owner 唯一性在档 owner 恒一条，由转让事务保证；建档与邀请都产不出 owner
multipart 文件头FormFile 给的是名字/类型/大小，内容还没读；名字与类型都是客户端自报的
嗅探（magic bytes）读文件头几十到几百字节判断真实类型，比扩展名与 Content-Type 可信
覆盖式上传头像一个成员一张，传新即换旧路径；旧文件删不掉就进清理任务，不让上传失败
15 分钟窗口角色变了但旧 access 的快照还有效，最长活到 TTL；pver+1 才是收口（S4·D17）
