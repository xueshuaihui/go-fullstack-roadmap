bcrypt 密码哈希与注册接口

S4 开工。今天把「你是谁」的第一块砖放下去：POST /api/homeos/auth/register。注册接口的技术含量不在路由——S2 你就会了——而在密码：数据库里永远只存哈希，永远不存明文，而且要用专门为密码设计的 bcrypt，不是随手一个 SHA256。今天还要认识贯穿整个 S4 的一个词：防枚举。

今日目标

知识讲义

1. 哈希不是加密：单向，且故意慢

加密可逆（有密钥就能解回来），哈希不可逆。密码属于「服务端根本不需要知道明文」的数据，所以只能哈希：注册时把哈希存库，登录时把用户输入的密码再哈希一次比对——而不是「解密出来比对」。

那为什么不能直接 sha256(password)？两个原因：

攻击裸 SHA256 的问题bcrypt 的对策
彩虹表 / 预计算同一个密码的哈希值全网相同，查表即破每次哈希自动混入随机 salt，同密码不同哈希
暴力穷举GPU 每秒可算百亿次 SHA256cost 因子故意把单次哈希拖慢到几十毫秒——正常登录无感，穷举成本放大百万倍

bcrypt 的哈希串自带说明书：$2a$10$N9qo8uLO... 里 2a 是算法版本、10 是 cost、后面是 salt + 摘要拼在一起。所以校验时不需要单独存 salt——把整串哈希和明文一起喂给 CompareHashAndPassword 就行。

密码策略是服务端的事：≥8 位且同时含字母与数字。校验不通过返回 400 + 1004（参数错误）。前端也拦一道？可以，但那只算用户体验——绕过前端直接 curl 的人，最终撞的还是你服务端的这道墙。

2. 防枚举：让攻击者问不出「这个手机号注册过吗」

「枚举攻击」= 攻击者拿一批手机号逐个调你的接口，靠响应的差异推断哪些号码是你的用户。注册接口天然藏不住（手机号重复必须报 1006，否则用户不知道为什么注册失败），但登录接口必须藏住：「手机号不存在」和「密码错误」返回完全相同的 401 + 1002——这是明天 D2 的主戏，今天先在注册接口上建立两个习惯：

  • 错误 message 不复述内部细节（不说「该手机号已存在于 homeos_user 表」，只说「手机号已注册」）；
  • 无论走到哪个失败分支，耗时形态尽量一致——bcrypt 的「故意慢」在这里帮了忙：密码校验分支慢，其他分支也不要快到离谱。

3. 注册接口在三层里的位置

S2 立的分层今天照用：handler 只做「绑定 → 调 service → 按 error 写响应」，service 管业务规则（策略校验、查重、哈希），repo 管存取。注册属于认证域，路由挂在 /api/homeos/auth 组下——这个组今天是公开的（不需要 token），D5 建好鉴权中间件后，其余路由全部挂到受保护组里。

步骤 2 · passutil 包

完整 · server/internal/platform/passutil/passutil.gopackage passutil

import (
    "fmt"
    "unicode"

    "golang.org/x/crypto/bcrypt"
)

// HashPassword 把明文密码哈希成 bcrypt 串。cost 用库默认值（10）。
func HashPassword(plain string) (string, error) {
    b, err := bcrypt.GenerateFromPassword([]byte(plain), bcrypt.DefaultCost)
    if err != nil {
        return "", fmt.Errorf("hash password: %w", err) // %w 保链（S1·D3 纪律）
    }
    return string(b), nil
}

// CheckPassword 校验明文与哈希是否匹配。不匹配不是 error，是 false。
func CheckPassword(hash, plain string) bool {
    return bcrypt.CompareHashAndPassword([]byte(hash), []byte(plain)) == nil
}

// ValidPassword 密码策略：≥8 位，且同时含字母与数字。不合规 → 1004。
func ValidPassword(p string) bool {
    if len(p) < 8 {
        return false
    }
    var hasLetter, hasDigit bool
    for _, r := range p {
        switch {
        case unicode.IsLetter(r):
            hasLetter = true
        case unicode.IsDigit(r):
            hasDigit = true
        }
    }
    return hasLetter && hasDigit
}

range 字符串得到的是 rune（一个 Unicode 码点），不是 byte——所以 len(p) 数的是字节数，中文密码每字占 3 字节。教学期策略按字节数算就够，知道这个差异即可。

步骤 3 · service 与 handler

完整 · server/internal/homeos/service/auth.go（注册部分）package service

import (
    "context"
    "errors"
    "fmt"
    "regexp"

    "homecube/internal/homeos/model"
    "homecube/internal/homeos/repo"
    "homecube/internal/platform/passutil"
    "homecube/pkg/response"
)

var phoneRE = regexp.MustCompile(`^1[3-9]\d{9}$`)

type AuthService struct {
    users repo.UserRepo // 接口（S1·D4）；测试用内存实现，跑服务用 GORM 实现
}

func NewAuthService(users repo.UserRepo) *AuthService {
    return &AuthService{users: users}
}

// Register 注册：手机号 + 验证码 + 密码。
func (s *AuthService) Register(ctx context.Context, phone, code, password string) (*model.User, error) {
    if !phoneRE.MatchString(phone) || !passutil.ValidPassword(password) {
        return nil, response.ErrInvalidParam // → 1004 / 400
    }
    if code != "123456" { // TODO(S4·D2)：验证码 store 建好后换真校验，今天用约定 mock 值
        return nil, response.ErrCaptchaInvalid // → 3003 / 400
    }
    exists, err := s.users.ExistsByPhone(ctx, phone)
    if err != nil {
        return nil, fmt.Errorf("register: check phone: %w", err)
    }
    if exists {
        return nil, response.ErrConflict // → 1006 / 409，message 只说「手机号已注册」
    }
    hash, err := passutil.HashPassword(password)
    if err != nil {
        return nil, fmt.Errorf("register: %w", err)
    }
    u := &model.User{Phone: phone, PasswordHash: hash}
    if err := s.users.Create(ctx, u); err != nil {
        if errors.Is(err, response.ErrConflict) { // 并发注册撞唯一索引：仍按 1006 报
            return nil, err
        }
        return nil, fmt.Errorf("register: create user: %w", err)
    }
    return u, nil
}
完整 · server/internal/homeos/handler/auth.go（注册部分）package handler

import (
    "github.com/gin-gonic/gin"

    "homecube/internal/homeos/service"
    "homecube/pkg/response"
)

type AuthHandler struct {
    auth *service.AuthService
}

func NewAuthHandler(auth *service.AuthService) *AuthHandler {
    return &AuthHandler{auth: auth}
}

type registerReq struct {
    Phone    string `json:"phone" binding:"required"`
    Code     string `json:"code" binding:"required"`
    Password string `json:"password" binding:"required"`
}

// Register 处理 POST /api/homeos/auth/register
func (h *AuthHandler) Register(c *gin.Context) {
    var req registerReq
    if err := c.ShouldBindJSON(&req); err != nil {
        response.Fail(c, 400, response.CodeInvalidParam, "参数错误")
        return
    }
    u, err := h.auth.Register(c.Request.Context(), req.Phone, req.Code, req.Password)
    if err != nil {
        response.FailErr(c, err)
        return
    }
    response.Created(c, gin.H{"user": gin.H{"id": u.ID, "phone": u.Phone}})
}

路由装配处（main.go 或 router.go）加一行：auth.POST("/register", authHandler.Register)，组前缀 /api/homeos/auth。另需两件事：model.User 补 PasswordHash string 字段（若 S3 建表时已有则跳过）；哨兵错误集补 ErrCaptchaInvalid（→ 3003 / 400），与 S1·D4 的 CodeOf 映射表对齐。

常见坑（新手 100% 会踩）

坑现象正确姿势
存明文密码「方便调试」一旦上线就是事故；git 历史里永远留着你存过的明文从第一条注册数据起就只存哈希，没有例外
用 == 比哈希串bcrypt 每次 salt 不同，同密码两次哈希结果不同，永远比不上校验只用 CompareHashAndPassword，它自己从哈希串里取 salt
把 bcrypt error 当「密码错」密码不匹配返回的是 error，你全按 500 处理封装成 bool（今天的 CheckPassword）：不匹配 = false，不是系统错误
cost 调太低或太高太低防不住穷举；太高（如 15）登录一次卡一秒用 bcrypt.DefaultCost（10），单次几十毫秒，教学与生产都合适
错误 message 泄露内部「用户表中已存在该 phone」——攻击者拿它做枚举字典message 面向用户：「手机号已注册」，细节进日志不进响应
忘了唯一索引并发双击注册出两条同手机号记录，1006 永远不触发service 查重只是快速失败；数据库唯一索引才是最后防线（S3 建表时 phone UNIQUE）

今日名词卡

术语一句话解释
bcrypt专为密码设计的慢哈希：自带随机 salt，cost 因子控制耗时
salt（盐）混入哈希的随机值，让同一密码每次哈希结果不同，废掉彩虹表
cost 因子bcrypt 的慢度旋钮；每 +1 耗时翻倍。默认 10
防枚举让「不存在」与「凭证错」响应同形（登录统一 401 + 1002），攻击者问不出注册名单
1006 唯一冲突手机号、邀请码、同家庭内账户名撞唯一约束时的业务码，HTTP 409
3003 验证码错验证码错误或已过期，HTTP 400。明天 D2 建验证码 store 后全面启用
公开路由组/api/homeos/auth 下注册/登录类接口不挂鉴权中间件；其余全挂（D5）
