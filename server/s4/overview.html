S4 · 鉴权与家庭隔离

这是全站最重要的一段。前面三个阶段你有了能跑的三层与真数据库，但任何人都能调你的接口、任何家庭的数据都彼此可见。S4 结束时，服务会长出两道门禁：认证（你是谁——注册、登录、双 token、轮换）与授权（你能干什么、能看谁家的数据——家庭上下文注入、四级角色、权限矩阵）。本阶段要落地施工清单的 24 条接口（认证 7 + 家庭 7 + 成员与邀请 10），是单阶段接口数最多的一段之一。

为什么把「鉴权」和「家庭隔离」放在同一个阶段

因为它们共用同一个事实：token 里携带当前会话家庭。登录签发的 JWT 带 uid/mid/fam/role/pver/typ 六个 claim，此后每一条业务查询的 WHERE family_id = ? 都从 token 来——不是从请求参数来。参数里的 family_id 永远不可信；token 里的 family_id 由密钥背书。切换家庭因此等于重新签发 token，而不是在进程里换一个变量。把这两件事分开教，你就会写出「鉴权过了但数据串家」的服务。

本阶段不做什么（明确划掉，免得手滑）

  • 不发真实短信：验证码是本地 mock，真实短信通道属课程范围外
  • 不做 Redis 黑名单 / 事件总线：token 撤销靠 refresh 哈希存库 + pver 成员校验，够用且能讲清
  • 不做财务面的任何接口（S6）、不做面配置接口（壳基座阶段）——但权限矩阵的「面配置行」今天先定死，接口出生时直接接上
  • 不做「家庭级覆盖」与「对象级 ACL」两层权限：判定顺序只有三层——显式拒绝 > 角色默认矩阵 > 字段级可见性
  • 不做 L2/L3 字段级加密：私密流水只做「行级可见性」（不返回给非作者与 owner 之外的人）
