字段级与私密流水行级可见性

昨天那张矩阵收尾时留了一句话：读不走矩阵——跨家庭的读被 scope 定界拦成 404 + 1001，同家庭里「这人看得见、但这一部分不该给他看」交给了今天。三层判定序的最后一层今天落地，两个维度一起：字段级（同一个对象，不同角色看到的字段集合不同）与行级（命中 is_private 的流水仅作者与 owner 可读）。这是本站基准里唯一一条「不得混层的例外」，也是 D8 那句「列表不返回手机号」欠下的正课。

今日目标

知识讲义

1. 三层走完：第三层管的是「通过了这条边之后，给看哪几列、给看哪几行」

把昨天那张分层表补完整，今天填掉最后一格：

层答什么问题谁在管拒绝的形态
① 显式拒绝这个人 / 这一行还作数吗？不在档（D13 的 status 与软删，走 scope.OnFile）、访客过期、票里的 pver 对不上死票 401 + 1005；捞不到行 404 + 1001
② 角色默认矩阵这个角色对这个动作有没有边？D14 + D15 的 authz.Allow写动作资格不成立 → 403 + 1003
③ 字段级可见性（今天）边通过了，但这次读到的对象里，哪几个字段该出现？这一行该不该出现？authz 的投影表 + 行级谓词（同一份实现，两种形态）不发 403：字段直接不出现；整行不可见则与「不存在」同形 404 + 1001

第三层为什么一律不发 403？因为它发生在「已经允许你读」之后。403 说的是「东西在这，你不许动」——那是写路径的口径（D15 讲义 3）。读路径上第 ③ 层一旦发 403，就等于替探测者确认「这个字段存在 / 这一行存在」，D11 花一整天装上的同形锁当场白装。所以第 ③ 层只有两种出口：裁掉（字段不出现在 JSON 里）或藏起整行（谓词让它在 SQL 里就不出来，单条查询落到 404 + 1001）。

基准里那句「不得混层的例外」指的是：行级可见性是全站唯一一个细到「单行」的判定，它既不塞进矩阵（矩阵只管动作资格），也不伪装成字段加密（本期不做 L2/L3 字段加密，见总览「本阶段不做什么」）。矩阵答「能不能进这个面」，行级答「这一行给不给你看」，两层必须分开实现、互不替代。

2. 字段级可见性：同一个对象，不同角色看到不同的字段集合

三个例子把这一层说尽：成员手机号（在 homeos_user 上，D8 的成员列表今天之前一律不返回）、流水备注（note 是作者写的自由文本，可能写着「给妈的体检费」）、私密标记（is_private 本身也是信息——让别人知道「这笔有内容不给你看」就是泄露）。

读方向的表长这样（视图 = 一类对象的返回行；✓ = 该角色读这一类对象时这个字段出现）：

视图 · 字段owner成人 memberwardguest本人那一行
member.row · id / name / relation / role / status / avatar / has_account✓✓✓✓✓
member.row · guardian_id✓✓✗✗—（不是身份字段）
member.row · phone✓✗✗✗✓（自己的号码不是秘密）

注意最后两行：金额、日期、分类照给——家庭账本要能对齐，这是共账的产品事实；裁掉的只有「作者写的那句话」和「这笔是不是私密」。金额本身不是靠字段级保护的，那是行级的事：一笔标了私密，整行连金额都不出来（见下节），两层的分工不能混。

写方向今天一并收编。D12 的 canEditMember 里那张字段集表（owner 三个字段、member 本人两个、ward 只有自己那一个），D14 把「能不能动这个人」搬进了矩阵，字段集原样留在 service 并写了 TODO(S4·D16)——今天这张表也进 authz，注释清零。

3. 行级谓词：判定在 authz 一处，落在 repo 的 scope 上

规则只有一句：命中 is_private 的行，仅作者本人与家庭 owner 可读。它的 SQL 形态是一段可以拼进 WHERE 的谓词 + 参数：

读者谓词效果
owner1 = 1（无参数）恒真：owner 可见全部行，这是全站口径
member / ward / guest(is_private = false OR member_id = ?)，参数 = 读者的成员 id非私密行照给；别人的私密行在 SQL 里就被排除

为什么必须进 SQL，而不是查出来再在 Go 里逐行扔？这条纪律 S3·D10 已经立过一次（「用查出来再过滤代替 where 条件」的坑），今天同一条再讲一遍的两个新理由：① 分页会被打穿——一页 20 行滤剩 13 行，游标推进的口径就假了；② 计数与聚合会和列表分叉——列表看不见、SUM 里却含着，后面的报表与导出全在对不上数。WHERE 里的谓词让「可读行集合」成为唯一一份，列表、单条、导出、报表天然同口径。

叠加位置很关键：在家庭 scope 之上再挂这一层，顺序是先定界再可见性——

片段 · repo 侧的叠加姿势（示意；流水表 S6·D1 才建，今天的落点是谓词本体与测试）pred, args := authz.TxReadPredicate(viewer.MemberID, viewer.Role)
q := r.db.WithContext(ctx).Model(&model.Transaction{}).
    Scopes(scope.InFamily(fam), scope.OnFile(model.StatusActive)). // ① 定界 + 在档：别家的行根本不进候选
    Where(pred, args...)                                            // ② 行级可见性：这一层筛掉「在你家但不给你看」的行

谓词不许写进 handler，也不许写成 handler 里的一句 if tx.IsPrivate && role != model.RoleOwner。三个理由一次说清：① 那句 if 是第二份判定实现，D14 立的「判定只有一份」当场作废，收工的 grep 也会红；② 走到 if 时行已经被捞进内存，泄露在 return 之前就已发生，审计日志、错误上报、慢查询采样都可能把它带出去；③ 每个接入口（列表、单条、导出、报表）都要重写一遍这句话，漏一个就是一个洞——而 repo 的一处叠加，接入口自动生效。

4. 越权读私密行为什么仍是 404 + 1001，而不是把行返回再抹字段

两条路都能让「别人看不见这笔账」，但只有第一条是对的。对照着看代价：

做法响应长什么样泄露了什么
藏整行（谓词进 WHERE，捞不到 → ErrNotFound）404 + 1001，与「这笔不存在」逐字节同形（D11 的判据）什么都没泄露：连「这个 id 上有一笔私密流水」都不是事实
返回行再抹字段200 + {id: 88, amount_cents: 0, note: ""} 之类① id 存在性送出去了，探测者用 200/404 分布就能扫出「谁家有几笔私密的」；② 抹成 0 的金额会被前端当成真实的 0 元流水参与合计；③ 客户端分不清「没这笔」和「有但不给看」，UI 只能猜

口径落在错误码表的两行上：1001 是「资源不存在」，越权读一律复用本码（与真不存在同形，不泄露存在性）；1003 是「权限不足」，登记场景之一就是「非作者改他人数据」。所以私密流水的读写不同形：别人的私密行，GET 撞 404 + 1001，PUT/DELETE 撞 403 + 1003（敢动手才谈得上拒绝）。字段级那半边的出口更简单：字段名压根不出现在 JSON 里——「能力不声明就不存在」的读方向版本，前端拿不到键就不渲染，比拿到 null 更难误解。

一条例外今天先记账，别顺手改：账户余额与归档判据不吃这个谓词。私密行的钱是真实的钱，可见性管「看见哪些行」，不管「钱算不算数」——余额把别人的私密支出算进去是账务事实，不是泄露。这条在流水接口出生那天的测试里钉死（S6·D13），今天只把它写进 notes/，免得你手滑把谓词塞进 SUM。

import (
    "homecube/internal/homeos/model"
)

// View 读方向的对象视图。一个视图 = 一类返回行的字段口径。
// 契约字符串：它和 Action 一样是对外语义的一部分，改名等于改接口。
type View string

const (
    ViewMemberRow View = "member.row" // GET /api/homeos/members 的每一行
    ViewTxRow     View = "tx.row"     // 流水行：接口 S6 出生，字段口径今天定死（矩阵先行的同族做法）
)

// readable 读投影表：视图 → 角色 → 可见字段名。fail-closed 与 Allow 同一族：
// 视图没登记、或角色不在这一行里 → 返回 nil → 投影出来是空对象，测试当场红。
// 这张表和 matrix 是两件事而不是两份实现：matrix 答「能不能动」，这里答「读的时候给看哪几列」。
var readable = map[View]map[model.Role][]string{
    ViewMemberRow: {
        model.RoleOwner:  {"id", "name", "relation", "role", "status", "avatar", "guardian_id", "has_account", "phone"},
        model.RoleMember: {"id", "name", "relation", "role", "status", "avatar", "guardian_id", "has_account"},
        model.RoleWard:   {"id", "name", "relation", "role", "status", "avatar", "has_account"},
        model.RoleGuest:  {"id", "name", "relation", "role", "status", "avatar"},
    },
    ViewTxRow: {
        model.RoleOwner:  {"id", "account_id", "category_id", "amount_cents", "occurred_at", "member_id", "note", "is_private"},
        model.RoleMember: {"id", "account_id", "category_id", "amount_cents", "occurred_at", "member_id"},
        model.RoleWard:   {"id", "account_id", "category_id", "amount_cents", "occurred_at", "member_id"},
        model.RoleGuest:  {"id", "account_id", "category_id", "amount_cents", "occurred_at", "member_id"},
    },
}

// selfExtra 「这一行就是读者自己」时额外可见的字段。
// 「是不是本人」是调用方算好的事实——authz 不查库、不看请求，与 Allow 的 conds 同一姿势。
var selfExtra = map[View][]string{
    ViewMemberRow: {"phone"},
    ViewTxRow:     {"note", "is_private"},
}

// FieldsOf 返回 role 读 v 这个视图时可见的字段名。self = 这一行是不是读者自己。
func FieldsOf(role model.Role, v View, self bool) []string {
    base := readable[v][role] // 视图没登记 → nil；角色不在行里 → nil。都是 fail-closed。
    if !self {
        return append([]string{}, base...)
    }
    return append(append([]string{}, base...), selfExtra[v]...)
}

// Project 按字段集裁剪一行。row 里没有的键不补 null——「能力不声明就不存在」的读方向。
// 只在这里裁；业务 handler 里不许再出现第二份「这个字段给不给看」的判断。
func Project(row map[string]any, fields []string) map[string]any {
    out := make(map[string]any, len(fields))
    for _, f := range fields {
        if v, ok := row[f]; ok {
            out[f] = v
        }
    }
    return out
}

// InFields 字段名在不在集合里。写字段的调用点用它问一句，不自写 map。
func InFields(fields []string, name string) bool

import (
    "homecube/internal/homeos/model"
)

// TxReadPredicate 私密流水的行级可见性谓词：作者列就叫 member_id。
// 返回一段 SQL 片段与参数，调用方（finance 的 repo）把它挂在 family scope 之后。
// 这是全站唯一一份「谁能读到哪一行」的实现：SQL 形态与下面的布尔形态同源于这一条规则。
func TxReadPredicate(memberID int64, role model.Role) (string, []any) {
    if role == model.RoleOwner {
        return "1 = 1", nil // owner 全可见，谓词恒真
    }
    return "(is_private = false OR member_id = ?)", []any{memberID}
}

// CanReadTx 同一个规则的布尔形态：内存 repo 与测试用它，保证「两套实现同一张测试表」不破。
// isPrivate=false → 家庭内共读；私密 → 仅作者与 owner。
func CanReadTx(role model.Role, readerID, authorID int64, isPrivate bool) bool {
    if !isPrivate || role == model.RoleOwner {
        return true
    }
    return readerID > 0 && readerID == authorID
}

两件事必须讲清：① 谓词不管「这个人是不是这个家的」——scope.InFamily 是第一道，fam<=0 时它已经把整条查询短路成 1 = 0；还没进家庭的人（mid=0）走不到谓词这一步，走到了也只是候选集为空。谓词是第二道，不代替第一道。② 一个规则两个形态不算两份实现——SQL 形态给数据库用，布尔形态给内存实现与测试用，两者同源、同一条断言表盯着（步骤 3）。

写方向把 D12 那张表搬进 authz。rule 结构多一列字段表（同包同表，不是新建入口），Allow 与 Of 一行不动：

片段 · <repo>/server/internal/platform/authz/authz.go 追加（前置：D14 的 rule / matrix / has）// EditScope 写字段时「动的是谁」。两个取值，别自造第三个：
// 传错 bool 编译器帮不了你，用枚举至少能被 grep 到、也能被 switch 穷尽检查兜住。
type EditScope int

const (
    EditSelf  EditScope = 1 // 动的是自己那一行
    EditOther EditScope = 2 // 动的是别人（owner 替任何人、监护人替自己名下 ward）
)

// writable 挂在 rule 上：动作 → 角色 → 「动自己 / 动别人」两档字段集。
var writable = map[Action]map[model.Role]map[EditScope][]string{
    ActionMemberUpdate: {
        model.RoleOwner:  {EditSelf: {"name", "relation", "guardian_id"}, EditOther: {"name", "relation", "guardian_id"}},
        model.RoleMember: {EditSelf: {"name", "relation"}, EditOther: {"name", "relation", "guardian_id"}},
        model.RoleWard:   {EditSelf: {"name"}}, // 没有 EditOther：ward 动不了任何人
    },
}

// WritableFields 先问 Allow（同一份 fail-closed），不为真一律 nil；
// 为真时按 scope 取字段集，取不到也是 nil。nil 的语义 = 「一个字段都不许改」。
func WritableFields(role model.Role, act Action, scope EditScope, conds ...bool) []string {
    if !Allow(role, act, conds...) {
        return nil
    }
    return writable[act][role][scope]
}

为什么字段表要跟着 Action 走而不跟 View 走：写方向的字段集是「这条边能碰到哪几个字段」，它天然属于动作；读方向的字段集是「这一行给看哪几列」，它属于对象视图。硬把两者塞进一张表，就会出现「读成员列表要传一个 member:update 动作」这种一看就歪的签名。

// TestTxReadViewpoints 三视角 × 私密/非私密。want 是手写的常量列——
// 测试里不许再造一个 if 去「算」可见性，那等于交付第二份实现。
func TestTxReadViewpoints(t *testing.T) {
    const (authorID = 10; peerID = 12; ownerID = 11)
    _ = ownerID
    cases := []struct {
        name      string
        role      model.Role
        reader    int64
        author    int64
        isPrivate bool
        want      bool
    }{
        {"作者读自己的私密行", model.RoleMember, authorID, authorID, true, true},
        {"同家庭其他成员读别人的私密行", model.RoleMember, peerID, authorID, true, false},
        {"owner 读别人的私密行", model.RoleOwner, ownerID, authorID, true, true},
        {"同家庭其他成员读非私密行", model.RoleMember, peerID, authorID, false, true},
        {"ward 读别人的私密行", model.RoleWard, peerID, authorID, true, false},
        {"guest 读别人的私密行", model.RoleGuest, peerID, authorID, true, false},
        {"guest 读非私密行", model.RoleGuest, peerID, authorID, false, true},
    }
    for _, tc := range cases {
        t.Run(tc.name, func(t *testing.T) {
            if got := CanReadTx(tc.role, tc.reader, tc.author, tc.isPrivate); got != tc.want {
                t.Fatalf("CanReadTx(%d, reader=%d, author=%d, private=%v) = %v, want %v",
                    tc.role, tc.reader, tc.author, tc.isPrivate, got, tc.want)
            }
        })
    }
}

// TestPredicateShape 谓词的两个形态：owner 恒真、其余带一个成员 id 参数。

// TestPredicateSQL 不连库的 SQL 断言（D10 立的 DryRun + ToSQL 姿势第二次上岗）：

func TestPredicateSQL(t *testing.T) {
    db, err := gorm.Open(postgres.New(postgres.Config{

// TestFieldsOfProjection 读投影：手机号只在 owner 视角与「本人那一行」出现；
// 视图没登记 → 空集合（fail-closed），投影出来是空对象而不是全字段。
func TestFieldsOfProjection(t *testing.T) {
    row := map[string]any{"id": 1, "name": "阿B", "phone": "13800000002", "guardian_id": nil}
    if got := Project(row, FieldsOf(model.RoleMember, ViewMemberRow, false)); has(fields(got), "phone") {
        t.Fatal("member 读别人的行看见了手机号")
    }
    if got := Project(row, FieldsOf(model.RoleMember, ViewMemberRow, true)); !has(fields(got), "phone") {
        t.Fatal("member 连自己的手机号都看不见")
    }
    if got := Project(row, FieldsOf(model.RoleOwner, ViewMemberRow, false)); !has(fields(got), "phone") || !has(fields(got), "guardian_id") {
        t.Fatal("owner 少见了字段")
    }
    if got := Project(row, FieldsOf(model.RoleGuest, ViewMemberRow, false)); has(fields(got), "phone") || has(fields(got), "guardian_id") {
        t.Fatalf("guest 读到了敏感字段：%v", got)
    }
    if got := FieldsOf(model.RoleMember, View("not.registered"), false); len(got) != 0 {
        t.Fatalf("视图没登记却给了字段：%v", got)
    }
    // tx.row 今天不接线也要有断言：备注与私密标记只给 owner 与作者本人
    if has(FieldsOf(model.RoleMember, ViewTxRow, false), "note") {
        t.Fatal("member 读别人的流水行拿到了备注")
    }
    if !has(FieldsOf(model.RoleMember, ViewTxRow, true), "note") {
        t.Fatal("作者读不到自己写的备注")
    }
}

    }

}

func same(a, b []string) bool {
    if len(a) != len(b) {
        return false
    }
    for i := range a {
        if a[i] != b[i] {
            return false
        }
    }
    return true
}

常见坑（新手 100% 会踩）

坑现象正确姿势
handler 里 if tx.IsPrivate && role != model.RoleOwner 跳过一行行已经出了数据库；导出、报表、日志各漏一处，且收工 grep 红谓词在 authz、叠加在 repo 的 family scope 之后；业务包一个角色比较都不许有
把越权读的私密行返回再抹字段200 + 半空的行；探测者用 200/404 分布扫出「谁家有几笔私密的」，前端把抹成 0 的金额当真不可读的行不出来 → ErrNotFound → 404 + 1001，与真不存在逐字节同形（D11 判据）
读方向发 403 + 1003「这个 id 上确实有东西」被送出去，D11 的锁白装403 只属于写路径（矩阵拒绝 / 非作者改他人）；读的出口是裁字段或同形 1001
字段表复制一份进 service「方便调用」两处各改各的，改了 authz 忘了 D12 那张表， ward 又能改 guardian_id 了读用 FieldsOf、写用 WritableFields，都在 authz；editableFields 与 TODO(S4·D16) 同批删净
把行级谓词塞进矩阵当一行 ActionAllow 开始关心「具体哪一行」，签名塞不下，判定与定界糊在一起矩阵管动作资格（②层）；「这一行给不给你看」是谓词（③层）。两件事两个函数，同一个包
投影代替定界「先查出来再裁字段」被当成隔离，跨家庭行也进了内存定界必须在 SQL（D10 的纪律）；字段投影可以在出口做，但敏感字段最好连查询都不发起（今天的 needPhone 那一支）
被裁的字段返回 null 或空串前端分不清「没有这个字段」和「字段是空的」，合计与表单全乱Project 只复制存在的键；不给的键就不出现在 JSON 里
顺手把谓词也加进余额聚合账户余额算少了，家庭账对不上，而测试全绿可见性管「看见哪些行」，不管「钱算不算数」：余额与归档判据不吃谓词，这条在流水接口出生那天用断言钉
把字段可见性也导出给前端GET /permissions 变成第二份界面规格，改字段集等于改前端契约导出不改：Of 只答动作两栏；前端按「拿不到键就不渲染」处理
给 ViewTxRow 抢着接线流水接口还不在本期清单的这一段，硬造一条路由就是「注册了但没用的假入口」字段口径与谓词今天定死并测试覆盖，接线留给流水接口出生那天（同 D15 的「矩阵先行」）

今日名词卡

术语一句话解释
字段级可见性同一个对象、不同角色看到的字段集合不同；出口是「键不出现」，不是拒绝
行级可见性同一接口、不同读者看到不同行集合；命中 is_private 的行仅作者与 owner 可读——全站唯一的例外，不混进矩阵
视图（View）一类返回行的字段口径名（member.row / tx.row），读方向的键；契约字符串
投影（Project）按字段集合裁一行：集合里有且 row 里也有才复制，缺的键不补 null
谓词（predicate）一段可拼进 WHERE 的 SQL 片段加参数，由 authz 产出、repo 叠加
布尔孪生（CanReadTx）同一条规则的 Go 形态，给内存实现与测试用；与 SQL 形态同源，不是第二份判定
写字段集（WritableFields）矩阵的补充列：这条边通过后能改哪几个字段；nil = 一个都不许改（403 + 1003）
本人事实（self）「这一行是不是读者自己」，由调用方算好递进来；authz 不查库、不看请求
藏行 vs 抹字段整行不可见 → 谓词 + 404/1001；行可见但部分列不给 → 投影裁键。两者出口不同，混用就泄露
fail-closed 空投影视图没登记或角色不在表里 → 字段集为空 → 返回空对象，测试当场红而不是全量泄露
