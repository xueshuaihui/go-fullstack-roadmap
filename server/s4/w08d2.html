邀请：发起、列表、接受与撤销

家庭建好了，今天请人进门。四条接口一次落地：POST /api/homeos/members/invite 发起邀请（仅 owner）、POST /api/homeos/family/invite/accept 接受邀请、DELETE /api/homeos/family/invites/{id} 撤销邀请、GET /api/homeos/members 成员列表。邀请码是今天的主角：一个 8 位随机串，同时以「码 / 链接 / 二维码」三种形态出门——三态共用同一入参口径，服务端只认码本身。

今日目标

知识讲义

1. 邀请的生命周期

片段 · 状态流转（无代码，看图）owner 发起 ──► 在效期内 ──┬─► 被接受：写 member + used_at 落章，码死
                          ├─► 被撤销：软删（deleted_at + deleted_by），三态同时失效
                          └─► 过期（7 天）：什么都不用做，accept 时按 expires_at 判死
所有死法在 accept 眼里是同一句话：400 + 3002「邀请无效或已过期」

和上周验证码的四性质对照着记：有效期、一次性、随机性全同款，只是限流换成了「仅 owner 可发起」这道角色闸。这不是巧合——凡是「拿一串字符换一次权限」的机制，安全性质就这几条。

2. 三态一口径：服务端永远只认 code

邀请可以以三种形态到达被邀请人：手抄的 8 位码、分享链接（码在 URL 里）、二维码（码在图里）。服务端不做三套接口：链接由前端把码拆出来、二维码扫出来也是码，accept 的入参永远只有一个 {code}。这样撤销一次 = 三态全灭（都依赖同一条库记录），不存在「链接撤了二维码还能扫」的缝。二维码怎么生成？纯客户端的事，服务端不参与——清单里没有生成二维码的接口，也不许加。

3. accept 是最像「登录」的一次写操作

接受邀请发生三件事，顺序不能乱：① 验码（在效期、未用、未撤销，否则 3002）；② 写成员行（user_id 绑定被邀请人、role = member、relation 由入参给、码上 used_at 落章）——②之前先查家庭数上限，两侧都拦 3004（昨天拦创建侧，今天拦加入侧）；③ 会话切到新家庭 = 重签 token（昨天的 IssueForSession 第二次上岗），响应把新 token 和新 member/family 一起带回。注意 accept 用的是被邀请人自己的 access token——必须先注册登录，才谈得上接受邀请；「裸码进门」不存在。

「仅 owner 可发起/撤销邀请」今天先写在 service 里（一行角色判断 + 注释），这是临时形态：本阶段 D14 会把全部角色判定收进 platform/authz 的唯一实现，届时这些散落的 if 逐个删掉。先让它跑，再让它对，最后让它归位。

4. 成员列表：小集合不分页

GET /api/homeos/members 返回当前家庭全部在档成员。一个家庭撑死十几口人——这是「非分页小集合」，响应就是 {"list":[...]}，不带 next_cursor / has_more（游标分页留给流水那种无界列表）。每项含 id / name / relation / role / status / avatar / guardian_id 与「是否有账号」标记——注意不返回手机号：字段级可见性是 D16 的正课，今天先把「列表不等于全字段」的习惯立住。

今日增量（在学习仓里落盘）

今天属增量类型 ②+③：加四条路由与 handler + 补邀请生命周期测试。表 homeos_invite S3 已建（列：family_id / code / created_by / expires_at / used_at / used_by + 通用列含软删对）；code 上有唯一索引。缺列就补迁移（类型④）。

步骤 1 · service：邀请三动作

完整 · server/internal/homeos/service/invite.gopackage service

import (
    "context"
    "crypto/rand"
    "errors"
    "fmt"
    "math/big"
    "time"

    "homecube/internal/homeos/model"
    "homecube/internal/homeos/repo"
    "homecube/pkg/response"
)

const inviteCodeAlphabet = "ABCDEFGHJKMNPQRSTUVWXYZ23456789" // 去掉易混的 I/L/O/0/1，手抄友好
const inviteTTL = 7 * 24 * time.Hour

type InviteService struct {
    invites repo.InviteRepo
    members repo.MemberRepo
    auth    *AuthService
}

func NewInviteService(invites repo.InviteRepo, members repo.MemberRepo, auth *AuthService) *InviteService {
    return &InviteService{invites: invites, members: members, auth: auth}
}

// genInviteCode 8 位 crypto/rand 随机码。
func genInviteCode() (string, error) {
    out := make([]byte, 8)
    max := big.NewInt(int64(len(inviteCodeAlphabet)))
    for i := range out {
        n, err := rand.Int(rand.Reader, max)
        if err != nil {
            return "", fmt.Errorf("gen invite code: %w", err)
        }
        out[i] = inviteCodeAlphabet[n.Int64()]
    }
    return string(out), nil
}

// CreateInvite 仅 owner 可发起。撞唯一索引就重生成，最多 3 次。
func (s *InviteService) CreateInvite(ctx context.Context, familyID, memberID int64, role model.Role) (*model.Invite, error) {
    if role != model.RoleOwner { // TODO(S4·D14)：收进 platform/authz 唯一实现，届时删除本分支
        return nil, response.ErrForbidden // → 1003 / 403
    }
    for attempt := 0; attempt < 3; attempt++ {
        code, err := genInviteCode()
        if err != nil {
            return nil, err
        }
        inv := &model.Invite{FamilyID: familyID, Code: code, CreatedBy: memberID,
            ExpiresAt: time.Now().Add(inviteTTL)}
        err = s.invites.Create(ctx, inv)
        if errors.Is(err, response.ErrConflict) {
            continue // 31^8 的空间里撞码约等于中彩票，但代码必须兜住
        }
        if err != nil {
            return nil, fmt.Errorf("create invite: %w", err)
        }
        return inv, nil
    }
    return nil, fmt.Errorf("create invite: %w", response.ErrConflict)
}

// AcceptInvite 验码 → 拦 3004 → 写成员 + 落章 → 重签 token（会话切到新家庭）。
func (s *InviteService) AcceptInvite(ctx context.Context, userID int64, code, relation string) (*LoginResult, error) {
    inv, err := s.invites.FindByCode(ctx, code) // 已软删（撤销）的查不出来
    if err != nil && !errors.Is(err, response.ErrNotFound) {
        return nil, fmt.Errorf("accept: %w", err)
    }
    if inv == nil || inv.UsedAt != nil || time.Now().After(inv.ExpiresAt) {
        return nil, response.ErrInviteInvalid // → 3002 / 400：四种死法一句话
    }
    n, err := s.members.CountActiveByUser(ctx, userID)
    if err != nil {
        return nil, fmt.Errorf("accept: count: %w", err)
    }
    if n >= maxFamiliesPerUser {
        return nil, response.ErrFamilyLimit // → 3004：加入侧也拦
    }
    mem, err := s.members.CreateForUser(ctx, inv.FamilyID, userID, relation, model.RoleMember)
    if err != nil {
        return nil, fmt.Errorf("accept: create member: %w", err)
    }
    now := time.Now()
    if err := s.invites.MarkUsed(ctx, inv.ID, mem.ID, now); err != nil {
        return nil, fmt.Errorf("accept: mark used: %w", err)
    }
    res, err := s.auth.IssueForSession(ctx, userID, mem) // 会话切到新家庭：重签
    if err != nil {
        return nil, fmt.Errorf("accept: reissue: %w", err)
    }
    return res, nil
}

// RevokeInvite 仅 owner；软删留痕（deleted_at + deleted_by），三态同时失效。
func (s *InviteService) RevokeInvite(ctx context.Context, familyID, memberID int64, role model.Role, inviteID int64) error {
    if role != model.RoleOwner { // TODO(S4·D14)：同上，收进 authz
        return response.ErrForbidden
    }
    // 跨家庭撤销：invite 必须属于当前会话家庭，否则与「不存在」同形 → 1001（越权读语义）
    return s.invites.SoftDeleteInFamily(ctx, familyID, inviteID, memberID)
}

步骤 2 · handler 四条 + 成员列表

片段 · server/internal/homeos/handler/invite.go（前置：昨天的 context 六键取法）type acceptInviteReq struct {
    Code     string `json:"code" binding:"required"`      // 三态一口径：只认码
    Relation string `json:"relation" binding:"required,max=10"`
}

// AcceptInvite 处理 POST /api/homeos/family/invite/accept（受保护：用被邀请人自己的 token）
func (h *InviteHandler) AcceptInvite(c *gin.Context) {
    var req acceptInviteReq
    if err := c.ShouldBindJSON(&req); err != nil {
        response.Fail(c, 400, response.CodeInvalidParam, "参数错误")
        return
    }
    res, err := h.invites.AcceptInvite(c.Request().Context(),
        c.GetInt64("userID"), req.Code, req.Relation)
    if err != nil {
        response.FailErr(c, err)
        return
    }
    response.OK(c, res) // 与登录同形：user/member/family/两个新 token
}

// RevokeInvite 处理 DELETE /api/homeos/family/invites/{id}；id 非数字 → 1004
func (h *InviteHandler) RevokeInvite(c *gin.Context) {
    id, err := strconv.ParseInt(c.Param("id"), 10, 64)
    if err != nil {
        response.Fail(c, 400, response.CodeInvalidParam, "参数错误")
        return
    }
    err = h.invites.RevokeInvite(c.Request().Context(),
        c.GetInt64("familyID"), c.GetInt64("memberID"), middleware.RoleOf(c), id)
    if err != nil {
        response.FailErr(c, err)
        return
    }
    response.OK(c, gin.H{"revoked": true})
}

发起邀请 handler 同形（POST，响应带 code 与 expires_at）；GET /api/homeos/members 走 MemberService 列表查询，响应 {"list":[...]} 不带游标字段。路由四条全挂受保护组。哨兵集补 ErrInviteInvalid（→ 3002 / 400）。

常见坑（新手 100% 会踩）

坑现象正确姿势
邀请码用时间戳或自增 id 拼码可预测，陌生人扫库进门crypto/rand + 去混淆字母表；唯一索引兜底撞码
accept 不校验 used_at一码多用，全家都能拿同一张码进来一次性消费：UsedAt 非空即 3002
撤销用硬删（DELETE FROM）谁撤的、何时撤的查无对证软删成对：deleted_at + deleted_by，这就是最小审计
为链接/二维码各开一个接口撤销链接后二维码还活着——三态不同步三态一口径：服务端只认 code，包装是客户端的事
accept 成功不重签 tokenB 的 fam 还停在旧家庭（或 0），进新家门却看旧家数据会话家庭一变就 IssueForSession，昨天立的规矩今天用上
3004 只拦创建侧被邀请加入绕过上限，一个账号进 20 个家庭创建与加入两侧同一常量同一判断
members 列表返回手机号家庭里 guest 也能看到全家号码列表只给展示字段；敏感字段的可见性 D16 正式落地

卡壳时查什么

正文自足，只有两种情况出去查：

  • 软删在 GORM 里的行为（为什么 FindByCode 自动查不出已撤销的）：回 S3 阶段总览找软删那张卡，重点看 deleted_at 的默认查询条件。
  • c.Param("id") 与路由 {id} 的对应：S2 的路由那课讲过，一分钟能翻到。

3002 排查心法：四种死法一个出口，所以先查库——SELECT code, expires_at, used_at, deleted_at FROM homeos_invite，四列里哪列「死」了一目了然。
