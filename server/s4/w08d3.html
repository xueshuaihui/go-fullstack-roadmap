多家庭与切换家庭 = 重签 token

一个账号至多 5 个家庭：自家、爸妈家、合租屋。今天三条接口把「多家庭」闭环：GET /api/homeos/families 看我加入的所有家庭、POST /api/homeos/families/switch 切换当前会话家庭、GET /api/homeos/family 看当前会话家庭详情。核心只有一句话，也是全站基准钉死的一句话：切换家庭 = 重新签发 token，不做进程内切上下文。

今日目标

知识讲义

1. 为什么不在服务端存「当前家庭」

tempting 的做法：库里给 user 加一列 current_family_id，切换就是 UPDATE 一列。三个理由否决它：

  • 多端打架：手机切到爸妈家、平板还停在自家——「当前」到底是谁的？服务端存会话状态，就得给每个端各存一份，session 管理的老麻烦全回来了；
  • 与无状态架构逆行：你的鉴权是「验签即认人」，加一个库内会话状态等于在快车道上设收费站；
  • token 即会话：fam 本来就在 claims 里。切换 = 用旧 token 的合法身份换一张 fam 不同的新 token——客户端拿新 token 替换旧的，天然多端各自独立：这台设备切了，那台不受影响。

所以 switch 接口的响应与登录同形：{user, member, family, access_token, refresh_token}——它本质上就是「不验密码的重新登录」。前端侧的纪律（F3 会学）：当前家庭只归壳管理，业务页面永远从 token 会话读上下文，不自存一份。

2. 3001：跨家庭的「不存在」

switch 入参 {family_id} 是客户端给的——可伪造。规则：该 family_id 下没有你的在档成员身份，一律 404 + 3001（家庭不存在或当前账号无权访问）。注意这和上周的 1005 分工：token 本身不合法 → 1005；token 合法但想去的家庭与你无关 → 3001。两者都做到了「不泄露目标家庭是否存在」。

3. 三条接口的数据形状

接口响应 data要点
GET /families{"list":[{family, member}]}每项是「家庭 + 我在其中的成员身份（role/relation/status）」；小集合不分页；只列在档身份
POST /families/switch与登录同形新 token 的 fam/mid/role/pver 全部来自目标家庭的成员行；旧 refresh 照常轮换入库
GET /family{family}当前会话家庭（token 的 fam）详情；fam=0 或家庭已解散 → 3001

switch 时旧的一对 token 怎么办？access 让它自然过期（15 分钟窗口内旧 token 仍然合法——它指向旧家庭，读旧家庭数据本来就有权限，不算漏洞）；refresh 走正常轮换：签发新对时把当前会话的旧 refresh 撤销，避免 refresh 越积越多。这些取舍周日的费曼复盘要能自己讲出来。

今日增量（在学习仓里落盘）

今天属增量类型 ②+⑤：加三条路由与 handler + 把 login 的 primarySession 从占位换成真查询。

步骤 1 · service

片段 · server/internal/homeos/service/family.go 追加（前置：昨天的 FamilyService 与 IssueForSession）type FamilyBrief struct {
    Family *model.Family `json:"family"`
    Member *model.Member `json:"member"` // 我在该家庭的身份：role/relation/status
}

// ListFamilies 我加入的全部家庭（在档身份）。小集合，不分页。
func (s *FamilyService) ListFamilies(ctx context.Context, userID int64) ([]FamilyBrief, error) {
    members, err := s.members.ListActiveByUser(ctx, userID)
    if err != nil {
        return nil, fmt.Errorf("list families: %w", err)
    }
    out := make([]FamilyBrief, 0, len(members))
    for _, m := range members {
        fam, err := s.families.FindByID(ctx, m.FamilyID)
        if err != nil || fam == nil {
            continue // 家庭已解散而身份还没清干净：跳过，不炸整个列表
        }
        out = append(out, FamilyBrief{Family: fam, Member: m})
    }
    return out, nil
}

// SwitchFamily 校验成员身份 → 重签 token。会话家庭一变，token 必须整套换。
func (s *FamilyService) SwitchFamily(ctx context.Context, userID, familyID int64) (*LoginResult, error) {
    mem, err := s.members.FindActiveByUserAndFamily(ctx, userID, familyID)
    if err != nil && !errors.Is(err, response.ErrNotFound) {
        return nil, fmt.Errorf("switch: %w", err)
    }
    if mem == nil {
        return nil, response.ErrFamilyNoAccess // → 3001 / 404：不是你家的门，装不存在
    }
    return s.auth.IssueForSession(ctx, userID, mem) // 与登录同形的响应从这来
}

// CurrentFamily token 里 fam 指向的家庭详情。
func (s *FamilyService) CurrentFamily(ctx context.Context, familyID int64) (*model.Family, error) {
    if familyID == 0 {
        return nil, response.ErrFamilyNoAccess // 还没进任何家庭：3001，前端据此引导建家庭/受邀
    }
    fam, err := s.families.FindByID(ctx, familyID)
    if err != nil || fam == nil {
        return nil, response.ErrFamilyNoAccess
    }
    return fam, nil
}

哨兵集补 ErrFamilyNoAccess（→ 3001 / 404）。同时把上周 login 里的 primarySession 占位换成真实现：取该用户 status 在档的第一个成员及其家庭——没有则 (nil, nil)，token 的 fam/mid 为 0。

步骤 2 · handler 与路由

片段 · server/internal/homeos/handler/family.go 追加（前置：昨天的 FamilyHandler）type switchReq struct {
    FamilyID int64 `json:"family_id" binding:"required"`
}

// ListFamilies 处理 GET /api/homeos/families
func (h *FamilyHandler) ListFamilies(c *gin.Context) {
    list, err := h.families.ListFamilies(c.Request().Context(), c.GetInt64("userID"))
    if err != nil {
        response.FailErr(c, err)
        return
    }
    response.OK(c, gin.H{"list": list}) // 小集合：只有 list 键，没有 next_cursor
}

// SwitchFamily 处理 POST /api/homeos/families/switch
func (h *FamilyHandler) SwitchFamily(c *gin.Context) {
    var req switchReq
    if err := c.ShouldBindJSON(&req); err != nil {
        response.Fail(c, 400, response.CodeInvalidParam, "参数错误")
        return
    }
    res, err := h.families.SwitchFamily(c.Request().Context(), c.GetInt64("userID"), req.FamilyID)
    if err != nil {
        response.FailErr(c, err)
        return
    }
    response.OK(c, res)
}

// CurrentFamily 处理 GET /api/homeos/family：fam 只从 context 来，不接受参数
func (h *FamilyHandler) CurrentFamily(c *gin.Context) {
    fam, err := h.families.CurrentFamily(c.Request().Context(), c.GetInt64("familyID"))
    if err != nil {
        response.FailErr(c, err)
        return
    }
    response.OK(c, gin.H{"family": fam})
}

路由三条挂受保护组。注意 GET /family（单数）与 GET /families（复数）是两个不同端点，Gin 的树不冲突；别把 switch 挂成 GET——它改会话状态，语义上是写操作。

常见坑（新手 100% 会踩）

坑现象正确姿势
switch 只回 {"ok":true} 不发新 token客户端 fam 还是旧家庭，切换等于没切switch 响应与登录同形，新 token 是响应的灵魂
库里存 current_family_id多端切换互相打架会话状态只活在 token 里；库不知道也不该知道「你当前在哪」
switch 不验成员身份传谁的 family_id 就切进谁家FindActiveByUserAndFamily 查无 → 3001；身份行是唯一门票
跨家庭切换失败返回 403探测者用响应差异扫出你有哪些家庭3001 / 404，与「家庭不存在」同形
GET /family 接受 ?id= 参数参数一传就能看别人家详情fam 只从 context（token）来，接口不收家庭 id 参数
families 列表把已退出身份也列出来切进去才发现进不去，体验断裂只列 status 在档的；已退出身份留在库里给历史数据署名用
switch 后旧 refresh 不撤销refresh 表越积越多，撤销语义模糊IssueForSession 里把该用户当前未撤销的 refresh 一并撤掉再发新票

今日名词卡

术语一句话解释
当前会话家庭token 里 fam 指向的那个家庭；一切家庭域查询的边界
切换 = 重签switch 不改服务端任何状态，只是换发一张 fam 不同的新 token
3001家庭不存在或当前账号无权访问，404；与「真不存在」同形
token 即会话会话状态全部由签名的 claims 承载，服务端无状态；多端天然独立
FamilyBrief「家庭 + 我的成员身份」的成对结构：列表页一次拿全，不用二次请求
primarySession登录时的默认会话家庭：第一个在档成员身份；没有则 fam=0
fam=0 状态已注册未进家庭：认证全过、家庭域全 404/3001，前端引导建家庭或受邀
写语义的 POSTswitch 改会话所以用 POST；GET 一律无副作用

卡壳时查什么

正文自足，只有两种情况出去查：

  • claims 六键的含义忘了：回 S4·D3 的讲义表，一分钟的事。
  • Gin 路由树对 /family 与 /families 的匹配规则：gin.RouterGroup 文档（可选）；实在疑惑，测试里各打一发看响应。

切换后「数据还是旧家庭的」十有八九是客户端没换 token——curl 手工验收时把新旧两张 token 分别解码对比 fam，一眼定位问题在票还是在查询。
