refresh 轮换与登出

昨天的 JWT 是无状态的——签出去就收不回，这是它的优点也是它的软肋。今天补上「收得回」的那一半：refresh token 哈希存库。从此登出有真实效果、续期有轮换记录、被盗的 refresh 能单独作废。两条接口：POST /api/homeos/auth/refresh 与 POST /api/homeos/auth/logout。

今日目标

知识讲义

1. 为什么 refresh 要存库：把「收不回」变成「收得回」

access tokenrefresh token
状态无状态：只验签，不查库有状态：验签之后还要查库确认未被撤销
每请求开销零次查询（每个业务请求都带它）一次索引查询（7 天才用一次，不心疼）
可撤销性不可单独撤销，靠 15 分钟自然过期 + pver 兜底随时可撤销：登出、改密、检测到重放

存库的必须是哈希（sha256 十六进制串），不是 token 本身：refresh token 等于「7 天有效的登录凭证」，明文存库 = 拖库即全员账号沦陷。哈希存库后，拖库者拿到的东西无法反推 token——和密码用 bcrypt 是同一个思想，只是 refresh 本身已是高熵随机串，不需要 bcrypt 的「慢」，sha256 足够。

2. 轮换：每次续期都换一张新票

refresh 的流程是严格的一换一：

  • 客户端提交 {refresh_token}；
  • 服务端验签（refresh 密钥 + typ=refresh）→ 按哈希查库 → 必须存在、未撤销、未过期；
  • 先把旧记录标记撤销，再签发新的一对 access + refresh，新 refresh 哈希入库；
  • 响应与登录同形：data:{user, member, family, access_token, refresh_token}。

轮换的价值在检测重放：旧 refresh 用过之后又来一次，说明「合法客户端」和「偷 token 的人」各持一份——这时拒绝并撤销整条链。教学期做到「重放必失败（401 + 1005）」即可，链式撤销属加固项，不展开。所有失败形态——验签错、查无记录、已撤销、已过期——统一 401 + 1005，不细分（细分就是给探测者递梯子）。

3. 登出：撤销当前 refresh，access 让它自然死

POST /api/homeos/auth/logout 入参 {refresh_token}，效果是把库里对应记录标记 revoked_at。access token 不单独撤销——它最多再活 15 分钟，且中间件还压着成员状态与 pver 两道校验（明天 D5）。重复登出、拿已撤销的 token 登出，都返回 200：登出是幂等的，客户端登出失败重试不该看到报错。

今日增量（在学习仓里落盘）

今天属增量类型 ②+⑤：加两条路由与 handler + 把 D3 的 refresh 签发接上存库。表 homeos_refresh_token S3 应已建（列：id / user_id / token_hash / expires_at / revoked_at + 通用列）；缺了就今天补迁移（类型④），token_hash 上建索引。

步骤 1 · service：Refresh 与 Logout

完整 · server/internal/homeos/service/token.gopackage service

import (
    "context"
    "crypto/sha256"
    "encoding/hex"
    "errors"
    "fmt"
    "time"

    "homecube/internal/homeos/model"
    "homecube/internal/platform/jwtutil"
    "homecube/pkg/response"
)

// hashToken refresh token 入库前的 sha256。库被拖走也无法反推 token。
func hashToken(tok string) string {
    sum := sha256.Sum256([]byte(tok))
    return hex.EncodeToString(sum[:])
}

// storeRefresh 签发时入库（login / refresh / switch / accept 共用）。
func (s *AuthService) storeRefresh(ctx context.Context, userID int64, refresh string) error {
    return s.refreshTokens.Create(ctx, &model.RefreshToken{
        UserID:    userID,
        TokenHash: hashToken(refresh),
        ExpiresAt: time.Now().Add(jwtutil.RefreshTTL),
    })
}

// Refresh 轮换：验签 → 查库 → 撤旧 → 签新 → 存新。任何一步失败都归 1005。
func (s *AuthService) Refresh(ctx context.Context, refreshToken string) (*LoginResult, error) {
    claims, err := jwtutil.Parse(s.refreshSecret, refreshToken, jwtutil.TypeRefresh)
    if err != nil {
        return nil, fmt.Errorf("%w: refresh 验签失败", response.ErrUnauthenticated) // → 1005 / 401
    }
    rt, err := s.refreshTokens.FindByHash(ctx, hashToken(refreshToken))
    if err != nil && !errors.Is(err, response.ErrNotFound) {
        return nil, fmt.Errorf("refresh: %w", err)
    }
    // 查无 / 已撤销 / 已过期：三种真相一个出口，不细分
    if rt == nil || rt.RevokedAt != nil || time.Now().After(rt.ExpiresAt) {
        return nil, fmt.Errorf("%w: refresh 已失效", response.ErrUnauthenticated)
    }
    u, err := s.users.FindByID(ctx, claims.UserID)
    if err != nil || u == nil {
        return nil, fmt.Errorf("%w: 用户不存在", response.ErrUnauthenticated)
    }
    member, family := s.primarySession(ctx, u.ID) // D9 起改为「按 claims.FamilyID 取会话家庭」
    if err := s.refreshTokens.Revoke(ctx, rt.ID); err != nil { // 撤旧必须在签新之前
        return nil, fmt.Errorf("refresh: revoke old: %w", err)
    }
    access, newRefresh, err := s.issueTokens(u, member)
    if err != nil {
        return nil, fmt.Errorf("refresh: %w", err)
    }
    if err := s.storeRefresh(ctx, u.ID, newRefresh); err != nil {
        return nil, fmt.Errorf("refresh: store new: %w", err)
    }
    return &LoginResult{User: u, Member: member, Family: family,
        AccessToken: access, RefreshToken: newRefresh}, nil
}

// Logout 撤销当前 refresh。幂等：查无或已撤销也返回成功。
func (s *AuthService) Logout(ctx context.Context, refreshToken string) error {
    rt, err := s.refreshTokens.FindByHash(ctx, hashToken(refreshToken))
    if err != nil && !errors.Is(err, response.ErrNotFound) {
        return fmt.Errorf("logout: %w", err)
    }
    if rt == nil || rt.RevokedAt != nil {
        return nil // 幂等：登出永远「成功」
    }
    if err := s.refreshTokens.Revoke(ctx, rt.ID); err != nil {
        return fmt.Errorf("logout: revoke: %w", err)
    }
    return nil
}

配套三处小改：① AuthService 增加 refreshTokens repo.RefreshTokenRepo 字段；② model.RefreshToken struct（若 S3 未建：ID/UserID/TokenHash/ExpiresAt/RevokedAt *time.Time）；③ 昨天 Login 的尾部补 s.storeRefresh(ctx, u.ID, refresh)——D3 签发的 refresh 从今天起入库。哨兵集补 ErrUnauthenticated（→ 1005 / 401），CodeOf 映射同步。

步骤 2 · handler 与路由

片段 · server/internal/homeos/handler/auth.go 追加（前置：昨天的 AuthHandler）type refreshReq struct {
    RefreshToken string `json:"refresh_token" binding:"required"`
}

// Refresh 处理 POST /api/homeos/auth/refresh：入参 {refresh_token}，响应同登录。
func (h *AuthHandler) Refresh(c *gin.Context) {
    var req refreshReq
    if err := c.ShouldBindJSON(&req); err != nil {
        response.Fail(c, 400, response.CodeInvalidParam, "参数错误")
        return
    }
    res, err := h.auth.Refresh(c.Request.Context(), req.RefreshToken)
    if err != nil {
        response.FailErr(c, err)
        return
    }
    response.OK(c, res)
}

// Logout 处理 POST /api/homeos/auth/logout：撤销当前 refresh，幂等。
func (h *AuthHandler) Logout(c *gin.Context) {
    var req refreshReq
    if err := c.ShouldBindJSON(&req); err != nil {
        response.Fail(c, 400, response.CodeInvalidParam, "参数错误")
        return
    }
    if err := h.auth.Logout(c.Request.Context(), req.RefreshToken); err != nil {
        response.FailErr(c, err)
        return
    }
    response.OK(c, gin.H{"revoked": true})
}

路由组加两行：auth.POST("/refresh", ...)、auth.POST("/logout", ...)。这两条也在公开组——refresh 时 access 可能已过期，不能要求带有效 access 才许续期。

import (
    "context"
    "errors"
    "testing"

    "homecube/internal/homeos/repo"
    "homecube/pkg/response"
)

func TestRefreshRotationAndLogout(t *testing.T) {
    svc, codes := newTestAuthService() // 测试辅助：内存 repo 全家桶 + 随机测试密钥
    ctx := context.Background()
    codes.Send("13800000001")
    if _, err := svc.Register(ctx, "13800000001", codes.PeekForTest("13800000001"), "secret99"); err != nil {
        t.Fatal(err)
    }
    login, err := svc.Login(ctx, "13800000001", "secret99", "")
    if err != nil {
        t.Fatal(err)
    }

    // 1) 正常轮换：拿到新的一对，且与旧的不同
    r1, err := svc.Refresh(ctx, login.RefreshToken)
    if err != nil {
        t.Fatalf("refresh 应成功: %v", err)
    }
    if r1.RefreshToken == login.RefreshToken {
        t.Fatal("轮换后 refresh 必须是新的")
    }
    // 2) 重放旧 refresh：必须 401+1005
    if _, err := svc.Refresh(ctx, login.RefreshToken); !errors.Is(err, response.ErrUnauthenticated) {
        t.Fatalf("旧 refresh 重放应失败(1005)，got %v", err)
    }
    // 3) 登出后，最新 refresh 也作废
    if err := svc.Logout(ctx, r1.RefreshToken); err != nil {
        t.Fatal(err)
    }
    if err := svc.Logout(ctx, r1.RefreshToken); err != nil {
        t.Fatalf("登出必须幂等，got %v", err)
    }
    if _, err := svc.Refresh(ctx, r1.RefreshToken); !errors.Is(err, response.ErrUnauthenticated) {
        t.Fatal("登出后 refresh 必须失败(1005)")
    }
}

常见坑（新手 100% 会踩）

坑现象正确姿势
明文存 refresh token拖库 = 全员 7 天凭证泄露只存 sha256 哈希；查询按哈希等值匹配
先签新再撤旧，中间出错新旧两张 refresh 同时有效，轮换失去意义顺序钉死：撤旧 → 签新 → 存新；撤旧失败直接 500，不发新票
refresh 失败细分错误 message「已撤销」vs「不存在」vs「过期」给了探测者三种回显一律 401 + 1005，message 同一句
把 refresh 挂在鉴权中间件后面access 过期后连续期入口都进不去，用户被登出refresh / logout 都在公开组
登出失败向用户报错客户端重试风暴；token 反正 7 天后也死登出幂等：撤销与否都 200
refresh 响应的 data 缺字段前端要写两套解析逻辑refresh 与 login 同形：{user, member, family, access_token, refresh_token}
拿 access token 调 refresh期望报错却 500Parse 的 wantType=refresh 拦住 → 1005；测试里补这条用例

今日名词卡

术语一句话解释
refresh 轮换（rotation）每次续期作废旧 refresh、签发新 refresh；重放旧票必失败
token_hashrefresh 的 sha256 十六进制串，库里的唯一形态；等值查询走索引
revoked_at撤销时间戳；非空即作废。登出、轮换、重置密码（本周六）都写它
1005 未认证token 无效/过期/已撤销的统一出口，401；细分形态不对外
幂等同一操作执行 N 次效果与 1 次相同；logout 是标准例子
有状态凭证验签之外还要查库确认未被撤销；refresh 有状态，access 无状态
重放检测已轮换的旧 refresh 再次出现 = 大概率被偷；教学期先做到拒绝，链式撤销属加固
RefreshTokenRepoCreate / FindByHash / Revoke / RevokeAllByUser 四个方法；最后一个周六重置密码用

卡壳时查什么

正文自足，只有两种情况出去查：

  • sha256 标准库用法：crypto/sha256 文档（可选，两行代码的事）。
  • GORM 里「部分列更新」怎么写（Revoke 只写 revoked_at 一列）：回 S3 阶段总览找 GORM 更新那张卡复习。

调试轮换问题的心法：每一步都看库里那行记录——revoked_at 是不是按预期从 NULL 变成时间戳。SQL 一眼能看穿的事，不要靠加日志猜。
