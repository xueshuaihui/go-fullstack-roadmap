周六 · S4 收口与费曼自测

十八张卡做完了。今天的任务不是写新功能，是把它们变成一条你能够着的能力：24 条接口逐条划掉、六条阶段判据逐条自测、全程能脱稿讲出来。这三件事的顺序有讲究——先核销（有没有做），再自测（做得对不对），最后费曼（是不是真的懂）。三关都过，S6 那 30 条财务接口才站得住；有一关是糊过去的，S5 第一天你就会在 httptest 的红灯里把它捡回来。

今日目标

知识讲义

1. 「做过十八张卡」和「有一条能力」差在哪

日卡的编排是加法：每天往里添一块（一条路由、一个包、一组测试）。能力是乘法：这些块必须能按顺序串起来、彼此不矛盾、且你能凭空复述。S4 这一阶段最容易出现的假完成长这样：单接口测试全绿，但 accept 之后没重签（于是 fam 还是 0）、switch 之后旧 refresh 没撤（于是 refresh 表越堆越多）、transfer-owner 之后新票带着旧 pver（一出门就 1005）——每一处单看都是绿的，连起来每一步都断。所以今天做三件事，一件都不能省：

动作它在测什么省掉的代价
① 24 条逐条核销（成功档 + 失败档）「实现过」和「口径对」是两件事：成功档证前者，失败档证后者接口存在但错误码是猜的，前端与审计都按错的口径写
② 全链路剧本（一条会话从头走到尾）顺序、状态传递、以及跨接口的副作用（重签、撤销、pver 自增）「鉴权过了但数据串家」「票刚死又被救活」这类只在串联里露馅的 bug
③ 判据自测 + 费曼知识有没有长在你身上——脱稿能不能讲出为什么下一阶段复用这些机制时改不动，因为你不知道为什么写成这样

2. 24 条的核销标准：为什么「测试绿了」不算一条划掉

今天给「划掉」下一个可执行的定义。一条接口算核销，必须同时满足四条：

要求怎么算达到反例（本站基准明确反对的写法）
真实现没有占位返回、没有 TODO(S4、handler 不返回硬编码 mapD8 的成员列表曾返回手搓字段 map，D16 才换成真查询 + 投影——今天它是被核销的那条
成功档201/200 且 data 的形状与出生那页写的字段一致（谁带新 token、谁不带，都在这一栏查）「差不多对」：转让成功但响应没带发起人新票，前端拿旧身份继续跑
失败档至少一条 httptest 断言钉住它最容易被写错的那个码跨家庭读回 403+1003（泄露存在性），或无票回 401+1002（把认证码用成资格码）
口径一致同一个失败原因在 24 条里永远是同一个码：不存在/越权读 = 1001，认证失败 = 1002，资格不足 = 1003，参数 = 1004，票失效 = 1005，唯一冲突 = 1006，邀请无效 = 3002，家庭不可达 = 3001，上限 = 3004，处境不允许 = 1010同一条接口上「id 非数字」一处回 1004 一处回 1001

核销表（下一页那张 24 行的表）里的失败档，我全部按你前面十四张卡里真实写过的码抄了一遍——没有一条是新加的口径。如果你跑出来和表上不一样，先怀疑实现而不是表：这张表的每一格都能在前面某张卡的讲义或完成检查里找到出处（最后一列就写着是哪张卡）。

3. 六条阶段判据：每条都得变成一个能证伪的动作

本阶段总览那六条判据写的是「能讲清」「测试绿」，这类句子没法直接自测——今天把它们各翻译成一条命令或一个动作：

判据今天的验法（可证伪形式）不达就回
① 24 条全划掉步骤 2 那张表 24 格手抄进 notes/ 逐条划；一格划不掉就是没达标看该条接口的「出生卡」那一列，回那张卡的步骤
② 全链路跑通：注册 → 登录 → 建家庭 → 发起邀请 → 接受邀请 → 切换家庭步骤 3 的 curl 剧本，前 11 条一路 200/201，且 switch 后解码新票的 fam/mid/role/pver 四值全换D9；串联断言的组织法回 D6
③ A 家的票读 B 家的资源 = 404 + 1001，不是 403步骤 4 的同形对照实验：两条跨家庭请求（成员、邀请）都回 1001，且响应体与「一个真不存在的 id」逐字节相同D11 的八条断言；scope 的写法回 D10

⑤ 脱稿讲清 pver 如何让旧票立刻失效、refresh 为什么必须「旧的先作废」画出一次失效链（改角色 → access 死 → refresh 也死 → 重登）并说出撤旧为什么在签新之前D17（失效链与 refresh 那道门）、D4（轮换五步）、D5（比对那一行）
⑥ 全仓三条 grep 零命中步骤 4 那三条命令逐条跑，输出为空；再多跑两条今天新增的（editableFields、pver + 1 恰好两处）D5 的六键纪律、D14 的判定唯一、D16 的投影唯一

4. 费曼自测怎么用：讲绊 = 没毕业

做法很死板，但有效：拿一张纸写下十八个主题（不看书），每个主题对着空气讲 60 秒，只许讲「为什么这样设计」，不许复述「做了什么」。讲绊的地方立刻标一个数字：绊在第几句。下面是十八个主题的自测清单和「绊了回哪一节」——这一页抄进 notes/，绊住的格子用红笔写「回 X 讲义 Y」。

主题（卡）60 秒里必须说清的三句讲绊了就回

验证码 store（D2）四性质各防什么；登录为什么用 1002 而注册用 3003；查无此人为何还要跑一遍校验该卡讲义 3「计时侧信道」

自测时最诚实的信号是「讲得出做法、讲不出理由」。比如「切换家庭要重签 token」谁都背得出，但接着问「为什么不直接在中间件里把 context 的 familyID 换掉」就卡住——那说明 D9 那天你写的是代码不是理解。理由讲不出的那条，明天早上重看那张卡的讲义第一节，比再做一遍接口有用。

卡壳时查什么

今天不写新逻辑，卡壳基本都是「口径对不上」。四种情况出去查：

  • 某条接口的错误码和核销表不一致：翻到「出生卡」那一列对应页的完成检查——本周每一条码都在那页写死过，没有一条是今天新定的。
  • 跨家庭读回 403、或同形实验两份响应不一样：S4·D11（八条断言与分诊）与 S4·D10（scope.InFamily 的 fail-closed 与 DryRun 断言）。
  • 「响应带新票」的三步有一步没带：D7（建家庭）、D8（accept）、D9（switch）、D12（转让重签 + 今天 D17 补的「事务后重读」时序）——四处都走 IssueForSession 这一个出口。
  • 死票与无票分不出来（1005 与 1002 混用）：D5 的「所有失败一个出口」与 D2 的「凭证错」语境；1002 只属于登录类接口的凭证校验，业务路由上的 401 一律 1005。
  • 字段集合和 D16 那两张表不一致：S4·D16 的 member.row / tx.row 投影表；被裁字段必须是不存在的键而不是 null。
