CI 升级：-race 全量、覆盖率棘轮与四道门禁

本周第一天。S5·D6 你建过一个最小的 CI workflow——大概是「拉代码、装 Go、go build、go test」四步，它的价值是「让绿灯不再依赖你的记性」。今天把它升级成真正能拦人的东西：竞态检测全量跑、覆盖率有一道只升不降的门槛、CI 里有真数据库、外加四道把你这 22 周守的纪律变成机器检查的门禁。

今日目标

知识讲义

1. 三个开关各自在做什么

开关它改变了什么代价为什么 CI 必须开
-race编译时给每一次内存读写插入「访问记录」代码，运行时比对是否有两次访问同一地址且至少一次是写、且没有同步。有就打印完整堆栈并以非 0 退出慢 2-10 倍、吃内存 5-10 倍；只能检测到这次真的跑出来的竞争数据竞争是「本机从来不复现、上线偶发」的头号来源。S5 你已经用它抓过报表聚合里的竞争，CI 不开等于把那次的成果交还给运气
-covermode=atomic覆盖率计数器用原子操作累加。-race 模式下这是默认值，显式写出来是为了让意图可见略慢你的被测代码里有 goroutine（报表并发聚合），非原子的计数器本身就是一个竞争
-count=1禁用测试结果缓存每次都真跑不加它，CI 可能拿一个缓存的绿灯糊弄你——S1·D1 的 Makefile 里就已经带着它了

本机为什么可以偷懒？因为本机的循环要快：改一行、跑一个包、看结果，十几秒。全量 -race 在你的项目规模上可能要几分钟，一天跑十次就没了半小时。合理分工是：本机 go test -race ./internal/finance/... 跑相关包，CI 跑全量。但有一条不许偷懒——-race 本机也要开，因为它检测的是「你有没有写出竞争」，不是「这次跑得够不够久」。

2. 覆盖率是棘轮，不是目标

覆盖率数字本身没有意义：它能被无用测试刷高，也能因为一段难测的胶水代码而虚低。它真正的用处是当棘轮（ratchet）——一道只许往上、不许往下的门槛，专门拦「新写的代码一行测试都没有」这种退化。

  • 起步值取你现在的真实值向下取整到 5 的倍数。今天跑出来 63.8%，门槛就设 60。不要设成 80 然后花一周补测试——那会让 CI 连续红一周，而红灯看久了就不看了，这是 CI 最贵的失败模式。
  • 只升不降。每次覆盖率明显上台阶（比如从 63% 到 71%），就把 COVER_MIN 上调到 70，并在提交信息里写明「棘轮上调」。想下调？那要在 notes/ 里写清是哪段代码变得不可测、为什么接受。
  • 门槛检查不许用「看最后一行」这种脆弱方式。go tool cover -func 的输出最后一行是 total: 那一行，用 tail -1 去取它是最常见写法，也是最脆的（工具输出格式一变就静默失效）。用 awk '/^total:/' 按内容匹配，格式变了会明确报错而不是给你一个空值。

3. 四道门禁：把纪律变成机器检查

这 22 周你守了四条纪律，它们全靠「记得」和「review 时看见」。人一定会累，所以今天把它们变成四个脚本。门禁的三个设计原则，比脚本本身更重要：

  1. 必须能在本机跑（make gates，一秒内出结果）。CI 上红了你复现不了，就等于没红。
  2. 必须留显式豁免口（一行注释 + 理由）。没有豁免口的门禁，遇到第一个误伤就会被整个注释掉——那时你失去的不是一道门禁，是「门禁有用」这个信念。
  3. 失败信息要能直接照着改：打印文件、行号、命中的内容，而不是一句「检查失败」。
门禁拦什么为什么值得拦
① 无 emoji源码、迁移、脚本里的表情符号日志与错误信息要能被 grep、能被 diff、能在任何终端与日志采集管道里保持字节稳定。emoji 是多字节字符，被截断就成乱码；而且用户可见的装饰本来就该由前端负责，服务端掺进去只会让文案与代码分家。中文注释不在禁止之列——门禁针对的是特定码位范围，不是「非 ASCII」
② 无 offset 分页.Offset(、SQL 里的 OFFSET、PageResult、total_page、page_size 这类形状列表一律游标分页。offset 分页在数据变动时会重会漏，而且深翻页的性能是线性劣化。这条一旦松口，前端触底续读、导出行数对账全部塌方
③ 无跨 schema joininternal/finance 里出现 homeos_* 表名（反之亦然），以及任何 JOIN homeos. / JOIN finance.两个模块的表在物理上是两条独立演进线（S8·D4 你刚见过：两套迁移、两张版本表）。跨 schema join 一旦写下，将来拆服务就得先拆 SQL。跨模块要数据，走平台层的接口
④ 无表外错误码业务代码里出现的裸错误码数字字面量错误码表是全站合同（前端拦截器、冒烟脚本、S8·D10 的接口核账都依赖它）。码只能来自 pkg/response 的常量，写成裸数字就等于在合同外面另开一条线——而 1000、5001 这种「看着挺像」的表外码，正是这样混进来的

还有一条几乎免费的第五道，属前端产物：web/pages.json 里不许出现 tabBar 字段（底栏由壳自绘，两者并存会出现双底栏、页面栈不可预期）。一行 grep 的事，今天顺手加上——它是全站唯一一条查前端文件的门禁，所以要放在 scripts/gates/ 里单独一个脚本，别混进 Go 的扫描范围。

4. CI 里怎么有数据库：service container 与同一份脚本

你的测试里有相当一部分要真库（S3 起就是）。CI 上有两种做法：给每个测试塞一个假 DB（要引额外的 mock 依赖，而且测不到真 SQL），或者在 CI 里起一个真的 Postgres。GitHub Actions 的 services: 就是干这个的：它在你这个 job 旁边起一个容器，把端口映射到 runner 的 localhost，并支持健康检查——和你昨天在 compose 里写的 healthcheck 是同一套思路。

建库之后的 schema 怎么来？关键决定：CI 里跑的迁移脚本，必须和本机 make up 跑的是同一份文件（deploy/migrate.sh）。做法是用 docker run 起一个一次性的 migrate 容器，把 deploy/ 与 server/migrations/ 挂进去，加 --network host 让它能通过 127.0.0.1:5432 摸到 service container。这样一来：

  • 「CI 绿」与「本机能起」这两件事被同一份脚本绑在一起，不会出现「CI 用另一套命令建的库」这种分叉。
  • 你改迁移脚本时，CI 会立刻告诉你是不是改坏了——它顺便成了 deploy/migrate.sh 的测试。

同理，建两个 schema 也复用 deploy/initdb/01-schemas.sql，用 psql 客户端容器执行一次。CI 里不出现任何一份「只在 CI 里存在」的配置，这是本节唯一要你记住的话。

5. 两个容易踩的 Actions 细节

  • go.mod 在 server/ 下，不在仓库根。所以要么给每个 run 步骤写 working-directory: server，要么用 defaults.run.working-directory 一次设好（今天用后者）。而 docker run 那两步要反过来设成仓库根，因为它们要挂 ./deploy 与 ./server/migrations——这个来回切换是 Actions 配置里最容易写错的地方。
  • Go 模块缓存要显式指路。setup-go 的 cache: true 默认在仓库根找 go.sum，找不到就不缓存（且不报错）。必须写 cache-dependency-path: server/go.sum，否则每次 CI 都重下全部依赖，慢得让你不想看结果。

步骤 1 · 门禁①：无 emoji

完整 · scripts/gates/no-emoji.py#!/usr/bin/env python3
"""门禁一：源码、迁移与脚本里不许出现 emoji。

用 python 而不是 grep 的原因：按码位范围判定要 grep -P，
而 macOS 自带的 BSD grep 不支持 -P。这道门禁必须本机与 CI 表现一致。
确实需要保留时，在同一行加注释 gate:allow-emoji 并写明理由。
"""
import pathlib, sys

RANGES = [
    (0x1F300, 0x1FAFF),   # 表情与象形文字
    (0x2600,  0x27BF),   # 杂项符号与装饰符
    (0x2B00,  0x2BFF),   # 星号与箭头类装饰
    (0xFE00,  0xFE0F),   # 变体选择符（emoji 的「彩色开关」）
]
ALLOW  = "gate:allow-emoji"
ROOTS  = ["server", "deploy", "scripts", "web/src", "web/pages.json"]
EXTS   = {".go", ".sql", ".sh", ".py", ".yml", ".yaml", ".json", ".vue", ".js"}

def is_emoji(ch):
    o = ord(ch)
    return any(lo <= o <= hi for lo, hi in RANGES)

def files():
    for root in ROOTS:
        p = pathlib.Path(root)
        if p.is_file():
            yield p
        elif p.is_dir():
            for f in p.rglob("*"):
                if f.is_file() and f.suffix in EXTS:
                    yield f

hits = []
for f in files():
    for i, line in enumerate(f.read_text(encoding="utf-8", errors="ignore").splitlines(), 1):
        if ALLOW in line:
            continue
        bad = "".join(sorted({c for c in line if is_emoji(c)}))
        if bad:
            hits.append(f"{f}:{i}: {bad}  →  {line.strip()[:80]}")

if hits:
    print(f"[FAIL] 门禁一 · 无 emoji：命中 {len(hits)} 处")
    print("\n".join(hits))
    print("确实要保留，就在同一行加 gate:allow-emoji 并写明理由")
    sys.exit(1)
print("[ok] 门禁一 · 无 emoji")

步骤 2 · 门禁④：无表外错误码

完整 · scripts/gates/no-undeclared-code.sh#!/usr/bin/env bash
# 门禁四：业务代码里不许出现裸的错误码字面量。
# 码只能来自 pkg/response 的常量表；命中即失败，除非该行带 gate:allow-code。
set -uo pipefail

# 表内全部合法值的形状：1001-1010 / 3001-3004 / 4001-4002 / 5000
PAT='(^|[^0-9A-Za-z_.])(100[0-9]|1010|300[1-4]|400[12]|5000)([^0-9]|$)'
CODE_TABLE="server/pkg/response/code.go"   # 唯一豁免：码常量表本身

hits=$(grep -rnE "$PAT" --include='*.go' \
          server/internal server/cmd server/pkg 2>/dev/null \
       | grep -v "^$CODE_TABLE:" \
       | grep -v 'gate:allow-code' || true)

if [ -n "$hits" ]; then
  echo "[FAIL] 门禁四 · 无表外错误码：命中如下"
  echo "$hits"
  echo "改用 pkg/response 里的常量；确实是别的含义的数字（如毫秒超时），"
  echo "要么换成 5*time.Second 这种写法，要么在该行加 gate:allow-code 并写明理由"
  exit 1
fi
echo "[ok] 门禁四 · 无表外错误码"

       | grep -v 'gate:allow-page' || true)

完整 · scripts/gates/no-cross-schema-join.sh#!/usr/bin/env bash
# 门禁三：模块间不许直查对方的表，任何地方都不许跨 schema join。
# 注意：连平台层也不许 join——对账那种要读两边的场景，做法是分两步查再在 Go 里合并。
set -uo pipefail
ALLOW='gate:allow-schema'

h1=$(grep -rn 'homeos_' --include='*.go' server/internal/finance 2>/dev/null | grep -v "$ALLOW" || true)
h2=$(grep -rn 'finance_' --include='*.go' server/internal/homeos 2>/dev/null | grep -v "$ALLOW" || true)
h3=$(grep -rniE 'join[[:space:]]+(homeos|finance)\.' --include='*.go' --include='*.sql' \
        server 2>/dev/null | grep -v "$ALLOW" || true)

hits="$h1$h2$h3"
if [ -n "$hits" ]; then
  echo "[FAIL] 门禁三 · 无跨 schema join / 跨模块直查表：命中如下"
  echo "$hits"
  echo "跨模块要数据请走 internal/platform 的接口"
  exit 1
fi
echo "[ok] 门禁三 · 无跨 schema join"
完整 · scripts/gates/no-native-tabbar.sh#!/usr/bin/env bash
# 门禁五（前端产物）：pages.json 不许出现原生 tabBar 字段，底栏由壳自绘。
set -uo pipefail
FILE=web/pages.json
[ -f "$FILE" ] || { echo "[ok] 门禁五 · $FILE 不存在，跳过"; exit 0; }

if grep -nE '"tabBar"[[:space:]]*:' "$FILE"; then
  echo "[FAIL] 门禁五 · pages.json 里出现了原生 tabBar：会与自绘底栏并存，出现双底栏"
  exit 1
fi
echo "[ok] 门禁五 · 无原生 tabBar"

步骤 4 · Makefile 追加

片段 · Makefile 追加（缩进是真 TAB）COVER_MIN ?= 60        # 棘轮：只许上调。改动写进提交信息

.PHONY: gates cover cover-check ci-local

gates:
	python3 scripts/gates/no-emoji.py
	bash scripts/gates/no-offset-page.sh
	bash scripts/gates/no-cross-schema-join.sh
	bash scripts/gates/no-undeclared-code.sh
	bash scripts/gates/no-native-tabbar.sh

# 全量 -race + 覆盖率（CI 用的就是这一条）
cover:
	cd server && go test -race -count=1 -covermode=atomic -coverprofile=cover.out ./...
	cd server && go tool cover -func=cover.out > cover.txt

# 门槛检查：按内容匹配 total 行，不靠「最后一行」这种脆弱假设
cover-check:
	awk -v min=$(COVER_MIN) \
	  '/^total:/ { gsub("%","",$3); v=$3+0; \
	    if (v >= min+0) printf "覆盖率 %s%% ≥ 门槛 %s%%\n", $3, min; \
	    else { printf "覆盖率 %s%% 低于门槛 %s%%\n", $3, min; bad=1 } } \
	   END { exit bad?1:0 }' server/cover.txt

# 在本机复现 CI 的完整一轮：门禁 + 格式 + 全量测试 + 门槛
ci-local: gates lint cover cover-check

awk 那段值得看懂：/^total:/ 只处理以 total: 开头的行；gsub("%","",$3) 把 63.8% 变成 63.8；v >= min+0 里的 +0 是强制数值比较（awk 里字符串比较 "9" > "60" 会成立，这是个经典陷阱）；END { exit bad?1:0 } 让 make 看到非 0 就红。如果 cover.txt 里没有 total: 行，脚本会因为 bad 未定义而按 0 退出——所以门槛检查前必须先确认 cover 那步真的产出了文件，这就是 ci-local 里两者顺序绑在一起的原因。

步骤 5 · 升级 CI workflow

完整 · .github/workflows/ci.yml（覆盖 S5·D6 那个最小版）name: ci

on:
  push:
    branches: [main]
  pull_request:

jobs:
  server:
    name: 门禁 + 全量测试
    runs-on: ubuntu-latest

    # ---- CI 里的真数据库。健康检查与 compose 里那套同思路 ----
    services:
      postgres:
        image: postgres:16
        env:
          POSTGRES_USER: homecube
          POSTGRES_PASSWORD: homecube123
          POSTGRES_DB: homecube
        ports: ['5432:5432']
        options: >-
          --health-cmd "pg_isready -U homecube -d homecube"
          --health-interval 5s --health-timeout 3s --health-retries 12

    # ---- 测试进程读的变量。名字与 compose / .env.example 完全一致 ----
    env:
      DB_HOST: 127.0.0.1
      DB_PORT: "5432"
      DB_USER: homecube
      DB_PASS: homecube123
      DB_NAME: homecube
      DB_SSLMODE: disable
      AUTO_MIGRATE: "false"
      JWT_SECRET: ci-only-not-a-real-secret-0000000000
      JWT_REFRESH_SECRET: ci-only-not-a-real-refresh-000000
      UPLOAD_DIR: /tmp/ci-uploads
      CORS_ORIGIN: http://localhost:8080
      TRUSTED_PROXIES: 172.28.0.0/16
      GIN_MODE: release

    # go.mod 在 server/ 下，默认工作目录设成它；下面两步 docker 会临时改回根
    defaults:
      run:
        working-directory: server

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-go@v5
        with:
          go-version: '1.24'
          cache: true
          cache-dependency-path: server/go.sum   # 不写这行就不会缓存，且静默

      - name: 门禁（五道）
        working-directory: .
        run: make gates

      - name: 格式与静态检查
        run: |
          test -z "$(gofmt -l .)" || { gofmt -l .; exit 1; }
          go vet ./...

      - name: 建两个 schema（复用 deploy/initdb，不在 CI 里另写一份）
        working-directory: .
        run: |
          docker run --rm --network host \
            -v "$PWD/deploy/initdb:/initdb:ro" \
            -e PGPASSWORD=homecube123 \
            postgres:16 \
            psql -h 127.0.0.1 -U homecube -d homecube -f /initdb/01-schemas.sql

      - name: 跑迁移（复用 deploy/migrate.sh）
        working-directory: .
        run: |
          docker run --rm --network host \
            -v "$PWD/server/migrations:/migrations:ro" \
            -v "$PWD/deploy/migrate.sh:/migrate.sh:ro" \
            -e DB_HOST=127.0.0.1 -e DB_PORT=5432 \
            -e DB_USER=homecube -e DB_PASS=homecube123 \
            -e DB_NAME=homecube -e DB_SSLMODE=disable \
            migrate/migrate:v4.17.1 sh /migrate.sh up

      - name: 全量 -race 测试 + 覆盖率
        run: |
          mkdir -p /tmp/ci-uploads
          go test -race -count=1 -covermode=atomic -coverprofile=cover.out ./...
          go tool cover -func=cover.out > cover.txt

      - name: 覆盖率门槛
        working-directory: .
        run: make cover-check

      - name: 上传覆盖率明细
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: coverage
          path: server/cover.txt

CI 红了不许用「重跑一次」糊过去。一个偶发红的 CI，一周后就没有人再看它。偶发红的三个常见根因，按概率排：① 测试之间共享了数据库状态（同一个手机号、同一条流水）——每个测试自己造数据、用完自己清；② 依赖了执行顺序或时间（跨秒、跨月边界）；③ 并发测试用了同一条超时 ctx。三样都在你已有的测试纪律里，CI 只是把它们暴露出来。

常见坑

坑现象正确姿势
cache-dependency-path 没写每次 CI 都重下全部依赖，慢三四分钟，且不报错cache: true + cache-dependency-path: server/go.sum
忘了 working-directory 在 docker run 那两步要切回根docker: Error ... /deploy/initdb: no such file or directory，看着像挂载写错了Go 步骤在 server/，挂仓库文件的两步显式写 working-directory: .
覆盖率门槛一上手就设 80CI 连红一周，你就再也不看了取当前真实值向下取整到 5 的倍数，之后只上调
用 tail -1 取覆盖率总数工具输出格式一变就静默拿到空值，门槛形同虚设awk '/^total:/' 按内容匹配，取不到就明确失败
门禁没有豁免口第一个误伤出现，整道门禁被注释掉每道门禁都认一行 gate:allow-* 注释，且要求写理由
emoji 门禁写成「禁止非 ASCII」你的中文注释与中文错误文案全部中枪按 emoji 码位范围判定，不是按 ASCII
门禁只在 CI 跑红了要 push 才知道，改一次等三分钟make gates 必须本机能跑，而且秒级出结果
CI 里另写一套建库命令「CI 绿但本机起不来」，两边配置慢慢分叉CI 复用 deploy/initdb 与 deploy/migrate.sh，一份都不另写
CI 红了就重跑偶发失败被掩盖，一周后没人再看 CI红必须查明根因：多半是测试间共享状态或依赖执行顺序

今日名词卡

术语一句话解释
workflow.github/workflows/*.yml：由事件触发的一组 job
job / stepjob 是一台干净的 runner 上的一段工作，step 是它里面按顺序执行的命令
service containerjob 旁边的依赖容器（这里是 Postgres 16），端口映射到 runner 的 localhost，支持健康检查
--network host让一次性容器直接用 runner 的网络栈，于是 127.0.0.1:5432 就能摸到 service container
-race竞态检测器：编译期插桩 + 运行期比对，检出即非 0 退出。慢 2-10 倍
-covermode=atomic覆盖率计数器用原子操作；有 goroutine 的项目必须用它
-count=1禁用测试结果缓存，保证每次都真跑
覆盖率棘轮 ratchet只升不降的门槛，作用是拦「新代码没测试」这种退化，不是追高数字
门禁 gate一条机器可查的纪律。三原则：本机能跑、有豁免口、失败信息可照着改
豁免注释gate:allow-*：写在命中行上的显式例外，必须带理由
upload-artifact把 CI 产物（这里是覆盖率明细）留存下来，方便事后查
偶发红 flaky同样的代码有时绿有时红。根因通常是测试间共享状态或依赖顺序，不许靠重跑解决
