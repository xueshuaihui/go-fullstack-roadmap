多阶段 Dockerfile：从二进制到一个能跑的镜像

72 条接口你已经全部写完，make run 在本机能起。但「在我机器上能跑」不是交付，是事故预告。从今天起的 12 天只做一件事：把这套东西变成干净机器上一条命令能复现、CI 能拦、上线能跑的机器。今天不新增任何业务接口，只写两个文件：server/Dockerfile 与仓库根的 .dockerignore。

课前须知：Docker 第一次登场，先记住四句话

1. 镜像（image）是一个只读的文件系统快照 + 一份启动说明。它不是虚拟机，里面没有内核，也没有「开机」这回事——它就是一堆文件和一条 ENTRYPOINT。

2. 容器（container）是镜像的一次运行实例。同一个镜像可以同时起十个容器，各自有独立的文件系统视图与进程。删掉容器，镜像还在。

3. Dockerfile 是构建配方，一行指令产出一「层」（layer）。层会被缓存，也会被复用：docker build 从上往下执行，只要某一层的输入没变就直接用缓存，一旦变了，它和它下面的所有层全部重建。今天所有的「先后顺序」讲究都从这一条推出来。

4. 构建上下文（build context）是你执行 docker build 时那个目录的全部内容。它会被打包发给 Docker 引擎，所以目录里有 web/node_modules 的话，每次构建都要先搬几百兆。.dockerignore 就是这一层的 .gitignore。

知识讲义

1. 为什么 Go 项目的镜像能小到二十兆

S1·D1 讲过一句话：go build 直接出静态二进制，没有运行时、目标机器不需要装 Go。这句话在容器里的兑现形式就是多阶段构建（multi-stage build）：一个 Dockerfile 里写多个 FROM，前面的阶段负责「造」，最后一个阶段负责「跑」，中间只把造出来的那一个文件搬过去。

阶段基础镜像体积量级里面有什么进不进最终镜像
buildergolang:1.24-alpine约 300 MBGo 工具链、模块缓存、你的全部源码不进
runtimealpine:3.20约 8 MB一个 shell、CA 证书、时区数据、/app/homecube这就是最终镜像

前端类比：builder 阶段等于 npm run build 的那台 CI 机器（装了 Node、装了 node_modules），runtime 阶段等于你最后丢给 CDN 的 dist/ 目录。没人会把 node_modules 一起上传到 CDN，同理也不该把 Go 工具链打进运行镜像。

为什么用 alpine 而不是更极端的 scratch（空镜像）？三个理由：① 你的家庭表里有时区字段，服务端要 time.LoadLocation("Asia/Shanghai")，这需要 /usr/share/zoneinfo，即 tzdata 包——scratch 里没有，一查就报 unknown time zone；② 排查问题时要能 docker compose exec server sh 进去看一眼，scratch 连 shell 都没有；③ 容器健康检查（S8·D3 会写）要在容器内执行一条命令，同样需要 shell。scratch 与 distroless 是「体积再压十兆」的优化，属于前瞻，不是今天的取舍。

2. CGO_ENABLED=0：为什么要关掉 C 胶水层

Go 默认在部分标准库里用 C 代码（cgo）：最典型的是 net 包的域名解析和 os/user。开了 cgo，产出的二进制会动态链接到构建机的 C 库（glibc / musl）。

后果很具体：你在 golang:1.24-alpine（musl libc）里构建，却把二进制拷到 debian（glibc）里跑，会直接 no such file or directory 或段错误——报错信息还完全不指向真实原因。CGO_ENABLED=0 强制走纯 Go 实现，产出一个不依赖任何外部 C 库的静态二进制，随便往哪个基础镜像里丢都能跑。

CGO_ENABLED=1（默认）CGO_ENABLED=0
链接方式动态链接 C 库纯静态
DNS 解析走系统 resolver（读 /etc/nsswitch.conf）纯 Go resolver，直接读 /etc/resolv.conf
跨基础镜像构建机与运行机的 C 库必须兼容无关
代价—极少数依赖 cgo 的库用不了（如某些 SQLite 驱动）。本项目用 Postgres 纯 Go 驱动，零代价

3. -ldflags "-s -w" 与 -trimpath：两个便宜的开关

  • -s 去掉符号表，-w 去掉 DWARF 调试信息。合起来通常让二进制小 25%-30%。代价：不能再用 dlv / gdb 对这个二进制下断点、看变量。生产容器里本来也不挂调试器，所以这笔交易划算；本机开发照旧用 make build（不带这些 flag），别把自己的调试能力也砍了。
  • -trimpath 把编译时的本机绝对路径从二进制里抹掉。不加的话，/Users/你/xxx/server/internal/finance/... 这种字符串会原样躺在产物里，任何人 strings 一下就能读到你的目录结构。加了之后路径变成 homecube/internal/finance/...。panic 时的堆栈也一样干净——这一点在 S8·D9 看容器日志时会直接受益。

4. 分层与缓存：Dockerfile 里行序就是性能

把「几乎不变的东西」放前面，「天天变的东西」放后面，这是 Dockerfile 唯一的排版原则。

对照 · 坏写法 vs 好写法# 坏：改一行 Go 代码，依赖也要重新下载
COPY server/ ./
RUN go mod download          # 每次都跑，几百兆依赖每次重下
RUN go build -o /out/homecube ./cmd/homecube

# 好：go.mod / go.sum 不变 → 这一层命中缓存 → 依赖不重下
COPY server/go.mod server/go.sum ./
RUN go mod download
COPY server/ ./
RUN go build -o /out/homecube ./cmd/homecube

怎么判断缓存有没有命中？docker build 的输出里，命中的步骤会写 CACHED。前端对应物是「把 package.json 的 npm ci 单独一层」，同一个道理。

构建上下文用仓库根，不是 server/。因为 .dockerignore 只能放在上下文根目录，而你要挡的 .env、.git、web/node_modules 三样都在仓库根。所以命令是 docker build -f server/Dockerfile -t homecube-server:dev .——注意最后那个点，它才是上下文；-f 只指定配方文件在哪。

5. .dockerignore 要挡什么，以及为什么这是安全问题不只是性能问题

条目挡它的理由不挡会怎样
.env、.env.*里面有数据库口令与两把 JWT 密钥今天它进不了镜像（我们只 COPY server/），但它进了构建上下文；将来任何人写一句 COPY . /src，密钥就永久留在镜像层里——docker history 与解包镜像都能读出来，删掉再提交也没用
.git整个提交历史，含被删掉的敏感文件上下文凭空大几十兆，且等于把 git 历史一起打包
web/node_modules前端依赖，服务端镜像完全用不到每次构建先搬几百兆给 Docker 引擎，慢到你想砸键盘
bin/、uploads/本机构建产物与用户上传的附件本机架构的二进制混进上下文；真实家庭数据被带进镜像
server/playground/语法练习沙盒，每个子目录自带独立 go.mod被 COPY server/ 一起搬进去，构建时容易撞上一堆与主模块无关的编译噪音
notes/、*.md你的学习笔记笔记里的口令示例、手机号示例会跟着镜像一起分发

一句话总结这一节：.gitignore 保护的是远端仓库，.dockerignore 保护的是镜像。两者名单高度重叠但不完全相同——比如 web/dist 该被 .gitignore 挡，但在 S8·D2 里它恰好是前端镜像的构建产物（在自己的上下文里生成，不受根 .dockerignore 影响）。

今日增量（在学习仓里落盘）

今天属增量类型 ⑥：工程化收口产物——这一类只在 S8 开放（S1-S7 引入部署物会把「每天可跑」变成「每天等构建」）。三个文件：server/Dockerfile、仓库根 .dockerignore、Makefile 追加两个目标。收工时 make build 与 make test 仍必须绿。

步骤 1 · server/Dockerfile

完整 · server/Dockerfile# ---------- 阶段一：builder（不进最终镜像） ----------
FROM golang:1.24-alpine AS builder
WORKDIR /src

# 先只拷依赖清单：这两行不变，下面的 download 就命中层缓存
COPY server/go.mod server/go.sum ./
RUN go mod download

# 再拷源码（.dockerignore 已把 playground 与笔记挡在外面）
COPY server/ ./

# 纯静态二进制：不链接 C 库，不携带本机路径，不带符号表
ENV CGO_ENABLED=0 GOOS=linux
RUN go build -trimpath -ldflags "-s -w" -o /out/homecube ./cmd/homecube

# ---------- 阶段二：runtime（这就是最终镜像） ----------
FROM alpine:3.20
# ca-certificates：出站 HTTPS 要验证书；tzdata：家庭时区要能 LoadLocation
RUN apk add --no-cache ca-certificates tzdata \
 && addgroup -S app && adduser -S -G app app
WORKDIR /app
COPY --from=builder /out/homecube /app/homecube
# 附件目录：S6 的 UPLOAD_DIR 指到这里，S8·D3 会挂一个卷给它
RUN mkdir -p /app/uploads && chown -R app:app /app
USER app
EXPOSE 8080
ENTRYPOINT ["/app/homecube"]

三条要点：

  • WORKDIR /src 之后 COPY server/ ./ 把 server/ 的内容铺到 /src，所以 /src/go.mod 存在、go build ./cmd/homecube 的路径才对得上。
  • USER app：不用 root 跑业务进程。容器逃逸时，root 与非特权用户的差别很大；顺带一个副作用——非 root 用户写不了 /app，所以上面那句 chown 不能省。
  • ENTRYPOINT 用数组（exec）形式，进程就是 PID 1，能直接收到 docker stop 发的 SIGTERM——这是 S5 写的优雅关闭在容器里能生效的前提。写成 ENTRYPOINT /app/homecube（shell 形式）会多套一层 /bin/sh，信号被 sh 吃掉，容器每次都等 10 秒被 SIGKILL 硬杀。

!.env.example 这一行的取反必须写在 .env.* 后面。.dockerignore 与 .gitignore 一样按顺序匹配、后写的覆盖前写的。S8·D3 会新建 .env.example（只有变量名与占位值、没有真密钥），它需要进仓库、但不需要进镜像——今天先把规则写对，那天就不会踩。

常见坑

坑现象正确姿势
忘了 CGO_ENABLED=0在 alpine 里构建、换个基础镜像跑就 not found 或段错误，报错完全不指向真实原因构建阶段显式 ENV CGO_ENABLED=0，产静态二进制
用 scratch 求最小体积一查带时区的时间窗就 unknown time zone Asia/Shanghai要么用 alpine + tzdata，要么在 Go 里 import _ "time/tzdata" 把时区库编进二进制
COPY . . 写在 go mod download 前面改一行代码，依赖重下一遍，构建从 20 秒变 3 分钟先 COPY go.mod go.sum + RUN go mod download，再拷源码
在 Apple Silicon 上构建，拿到 x86 服务器跑exec format errordocker build --platform linux/amd64 -f server/Dockerfile -t ... .；构建完用 docker inspect 核架构
没有 .dockerignore构建开头「Sending build context to Docker daemon」显示 800MB，每次都要等挡掉 web/node_modules、.git、bin/、uploads/
ENTRYPOINT 写成 shell 形式docker stop 后每次都卡 10 秒才被杀，S5 写的优雅关闭看起来「没生效」用数组（exec）形式，让业务进程当 PID 1 直接收 SIGTERM
以 root 跑容器没有明显现象，但容器内进程与宿主 root 同权adduser + USER app，并把要写的目录 chown 给它
把 -s -w 也加进 make build本机想用 dlv 调试，发现断点打不上、看不到变量瘦身 flag 只进镜像构建，本机 make build 保持原样

今日名词卡

术语一句话解释
镜像 image只读文件系统快照 + 启动说明；类比「构建产物 + 一份运行环境清单」
容器 container镜像的一次运行实例，有独立文件系统视图与进程树；删容器不删镜像
层 layer一条 Dockerfile 指令的产物，可缓存可复用；某层变了，它下面全部重建
构建上下文 build contextdocker build 最后那个路径的全部内容，会被打包发给引擎
多阶段构建一个 Dockerfile 里多个 FROM，只有最后一个阶段的产物成为镜像
CGO_ENABLED=0禁用 C 胶水层，产出纯静态二进制，与基础镜像的 C 库彻底解耦
-ldflags "-s -w"去符号表与调试信息，体积降两三成，代价是这个二进制不能用调试器
-trimpath从二进制与 panic 堆栈里抹掉本机绝对路径
.dockerignore构建上下文的忽略名单；语法同 .gitignore，支持 ! 取反
ENTRYPOINT / CMD容器启动时执行什么。exec（数组）形式让进程当 PID 1，能直接收到信号
tag镜像的名字后缀，如 homecube-server:dev。latest 是默认 tag，也是个陷阱：它不表示「最新」，只表示「没写 tag」
docker history列出镜像的每一层与其体积，用来确认「密钥/源码没有被打进去」
