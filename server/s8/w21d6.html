周六 · 干净机器复现与 E2E 冒烟

本周你写了 Dockerfile、nginx、compose、迁移脚本，还结清了三笔部署伏笔。它们各自都验过，但「五个零件各自能用」和「一条命令能从零跑通」是两件完全不同的事。今天四小时只做后者：把本周五个增量串成一条完整能力，用一个端到端冒烟脚本证明它真的活着，然后把全过程写进 README——写不出来的步骤，就是你其实没搞懂的地方。

今日目标

知识讲义

1. 「干净机器」到底干净在哪

S1 收口那天你做过一次干净检出验证，抓的是「忘了提交」和「依赖了本机环境」两类事故。今天同一件事，但面积大了十倍——因为现在牵涉的不只是文件，还有镜像、数据卷、网络、端口、环境变量五类本机状态。

本机状态它会怎么骗你怎么清
已构建的镜像你改了 Dockerfile 但 build 命中了旧层，或者干脆忘了 --build，跑的还是三天前的二进制docker compose down --rmi local
数据卷库早就初始化过了，今天的 initdb 钩子根本不执行；schema 是你上周手工建的docker compose down -v
.env它是本机文件、不进 git。干净检出里没有它——这正是最容易漏的一步README 第一步就是 cp .env.example .env
占用的端口8080 被你另一个项目占着，compose 报 address already in use，看起来像配置错了先 docker compose down，再查是谁占着
本机装的工具你手上有 jq、有 psql、有 go，别人没有。脚本用了它们就只在你能跑脚本只用 bash + curl + python3（三者都是 macOS 与主流 Linux 的自带物）

所以今天的验证要一次清干净：

可跑 · 把本机状态清零cd <你的学习仓根目录>
docker compose down -v --rmi local     # 容器 + 网络 + 数据卷 + 本地构建的镜像，全清
docker system df                       # 顺手看一眼还剩什么，心里有数

真·干净机器怎么找？四选一，从便宜到贵：① 同一台机器上 git clone 到 /tmp 的新目录 + 上面那套清理（能抓九成问题，今天用这个）；② Docker Desktop 的「Clean / Purge data」（连镜像缓存一起清）；③ 新建一个系统用户账号跑一遍（$HOME 里的配置也隔离了）；④ 开一台最便宜的云主机（最接近真实交付，S8·D12 的上线检查单会用这个口径）。①与④的差别就是「你本机装过什么」——所以第④条留到毕业前做一次即可。

2. 冒烟测试：为什么是这五步，为什么全走 HTTP

「冒烟」这个词来自硬件：新板子第一次通电，先看会不会冒烟，再谈功能。软件里的冒烟测试同理——它不追求覆盖率，追求「主干链路一条不断」。今天这五步是这样挑的：

步骤接口它同时在验证什么
注册POST /api/homeos/auth/register库连通、homeos schema 迁移到位、密码哈希、验证码链路、唯一约束
登录POST /api/homeos/auth/login两把 JWT 密钥都配对了、access/refresh 签发正常
建家庭POST /api/homeos/familiesfamily_id 这条全站命脉、创建者自动成为 owner、面配置初始化
建账户 + 记一笔POST /api/finance/accounts、POST /api/finance/transactionsfinance schema 迁移到位、跨模块的家庭上下文传递、金额以分为单位、幂等键生效
查报表GET /api/finance/reports/summary时间窗编码解析、聚合查询能读到刚写进去的那一笔、并发聚合不炸

为什么全部走 HTTP，而不是写成一个 Go 测试直接调 service？因为冒烟要验的是「整台机器」：nginx 有没有把 /api 转对、Gin 的路由分组有没有挂上、中间件顺序对不对、环境变量有没有真的传进容器、迁移有没有真的跑过。进程内测试全都绕过了这些——它能绿，而 docker compose up 起不来。S2/S4 用 httptest.NewRecorder 测 handler、S5 用 NewServer 测并发，那些是单元与集成层；今天是系统层，必须从最外面那个端口打进去。

断言口径也统一：每一步都断言响应体里的 code（成功是 0），HTTP 状态只在需要区分「401 还是 500」时才看。因为你的三键信封是全站的合同，冒烟脚本就是这份合同的第一个外部执法者。

3. 可重复执行：冒烟脚本最容易腐烂的地方

一个只能跑一次的冒烟脚本，价值会在一周内归零——因为第二次跑它必然失败，然后你就再也不跑了。让它可重复的两个技巧：

  • 手机号每次生成都不同。手机号有唯一约束，重复注册会撞 1006。用当前秒级时间戳拼一个号码，天然不重复。
  • 幂等键每次生成都不同。client_request_id 是用来防「同一笔请求被提交两次」的，如果你两次运行用同一个键，第二次会被正确地判定为重复——脚本自己把自己挡住了。用同一个随机运行号 RUN_ID 拼进所有幂等键。

顺带一个便宜但极有价值的加测：故意用同一个 client_request_id 发两次不同的请求体，断言返回 1008。这是幂等机制唯一能被外部观察到的地方，冒烟脚本里带上它，等于每次部署都自动回归一遍。

4. 今天唯一需要你按自己实现改一行的地方

注册流程要先拿验证码。开发期的验证码怎么送到脚本手里，取决于你 S4 那课的实现口径：常见做法有两种——开发模式下把验证码放在 sms-code 响应的 data 里返回，或者打进日志。脚本把这件事隔离在一个变量里：

片段 · 唯一的适配点SMS_CODE_FIELD="${SMS_CODE_FIELD:-debug_code}"   # 验证码在 sms-code 响应 data 里的字段名

如果你当时选的是「打进日志」，就把 read_sms_code 那个函数体换成一行 docker compose logs server 加一次 grep。只改这一个函数，其余步骤都不用动——这就是把不确定性收在一处的意义。

步骤 1 · scripts/smoke.sh

完整 · scripts/smoke.sh#!/usr/bin/env bash
# E2E 冒烟：全部走 HTTP，从最外面那个端口打进去。
# 用法：BASE=http://localhost:8080 bash scripts/smoke.sh
set -euo pipefail

BASE="${BASE:-http://localhost:8080}"
SMS_CODE_FIELD="${SMS_CODE_FIELD:-debug_code}"   # 唯一的适配点，见讲义第 4 节

# ---- 每次运行都不同，于是脚本可重复执行 ----
RUN_ID=$(date +%s)-$$
PHONE="139$(date +%H%M%S)$((RANDOM % 90 + 10))"
PASSWORD='SmokePass1x'                        # ≥8 位、含字母与数字
NOW_MONTH=$(date +%Y-%m)                        # 时间窗 month 档：YYYY-MM
NOW_TS=$(date -u +%Y-%m-%dT%H:%M:%SZ)

TMP=$(mktemp)
trap 'rm -f "$TMP"' EXIT

STATUS=""; RESP=""

# ---- 工具函数 ----------------------------------------------------
jget() {   # 从 JSON 里按点路径取值：jget data.access_token / jget data.list.0.id
  python3 -c '
import json, sys
node = json.load(sys.stdin)
for part in sys.argv[1].split("."):
    if isinstance(node, list):
        node = node[int(part)]
    elif isinstance(node, dict):
        node = node.get(part)
    else:
        node = None
    if node is None:
        break
print("" if node is None else node)
' "$1"
}

api() {    # $1=method $2=path $3=body(可空) $4=token(可空)
  local args=(-s -o "$TMP" -w '%{http_code}' -X "$1" "$BASE$2"
              -H 'Content-Type: application/json')
  if [ -n "${3:-}" ]; then args+=(-d "$3"); fi
  if [ -n "${4:-}" ]; then args+=(-H "Authorization: Bearer $4"); fi
  STATUS=$(curl "${args[@]}")
  RESP=$(cat "$TMP")
}

need() {   # 断言 code 相等，并给出一条能直接看懂的失败信息
  local step="$1" want="$2" got
  got=$(printf '%s' "$RESP" | jget code)
  if [ "$got" != "$want" ]; then
    echo "[FAIL] $step：期望 code=$want，实际 code=$got（HTTP $STATUS）"
    echo "       响应体：$RESP"
    exit 1
  fi
  echo "[ok] $step (code=$got)"
}

pick() {   # 从响应里取一个字段，取不到就直接失败：不让空值往下游漂
  local what="$1" val
  val=$(printf '%s' "$RESP" | jget "$2")
  if [ -z "$val" ]; then
    echo "[FAIL] 取不到 $what（路径 $2）；响应体：$RESP"; exit 1
  fi
  printf '%s' "$val"
}

# ---- 主干链路 ----------------------------------------------------
echo "== 冒烟开始 BASE=$BASE RUN_ID=$RUN_ID PHONE=$PHONE"

api POST /api/homeos/auth/sms-code "{\"phone\":\"$PHONE\"}"
need "发送验证码" 0
SMS_CODE=$(pick "验证码" "data.$SMS_CODE_FIELD")

api POST /api/homeos/auth/register \
    "{\"phone\":\"$PHONE\",\"password\":\"$PASSWORD\",\"code\":\"$SMS_CODE\"}"
need "注册" 0

api POST /api/homeos/auth/login "{\"phone\":\"$PHONE\",\"password\":\"$PASSWORD\"}"
need "登录" 0
TOKEN=$(pick "access_token" "data.access_token")

# 负例：不带 token 读账户，必须 401 + 1005（不是 500，也不是 200 空列表）
api GET /api/finance/accounts
need "未认证读账户 → 1005" 1005
[ "$STATUS" = "401" ] || { echo "[FAIL] 期望 HTTP 401，实际 $STATUS"; exit 1; }

api POST /api/homeos/families \
    "{\"name\":\"冒烟家庭\",\"timezone\":\"Asia/Shanghai\",\"currency\":\"CNY\"}" "$TOKEN"
need "创建家庭" 0
FAMILY_ID=$(pick "family_id" "data.family.id")

# 切换家庭 = 重新签发 token，所以这一步之后 TOKEN 必须换掉
api POST /api/homeos/families/switch "{\"family_id\":$FAMILY_ID}" "$TOKEN"
need "切换家庭" 0
TOKEN=$(pick "新 access_token" "data.access_token")

# 分类是预置数据（family_id 为空的那一批），直接取树里第一个能用的
api GET /api/finance/categories "" "$TOKEN"
need "读分类树" 0
CATEGORY_ID=$(pick "分类 id" "data.list.0.id")

api POST /api/finance/accounts \
    "{\"name\":\"冒烟钱包\",\"type\":\"wallet\",\"currency\":\"CNY\",\"initial_balance_cents\":0,\"client_request_id\":\"smoke-acc-$RUN_ID\"}" \
    "$TOKEN"
need "创建账户" 0
ACCOUNT_ID=$(pick "账户 id" "data.account.id")

TX_BODY="{\"account_id\":$ACCOUNT_ID,\"category_id\":$CATEGORY_ID,\"type\":\"expense\",\"amount_cents\":1234,\"occurred_at\":\"$NOW_TS\",\"note\":\"冒烟\",\"client_request_id\":\"smoke-tx-$RUN_ID\"}"
api POST /api/finance/transactions "$TX_BODY" "$TOKEN"
need "记一笔" 0

# 负例：同一个幂等键 + 不同请求体 = 幂等冲突 1008
api POST /api/finance/transactions "${TX_BODY/1234/5678}" "$TOKEN"
need "同键不同体 → 1008" 1008

api GET "/api/finance/reports/summary?period=$NOW_MONTH" "" "$TOKEN"
need "查报表" 0

# 负例：非法时间窗编码必须 400 + 1007，不回落默认档
api GET "/api/finance/reports/summary?period=not-a-period" "" "$TOKEN"
need "非法时间窗 → 1007" 1007

echo "[SMOKE PASS] 主干链路全通，RUN_ID=$RUN_ID"

脚本里有三处路径是按「常见形状」写的，与你的实现不一致就改这三行，其余别动：data.family.id（创建家庭的响应）、data.account.id（创建账户的响应）、data.list.0.id（分类树的第一项）。改法只有一个原则：让脚本读你真实的响应，而不是改你的响应去迁就脚本——服务端是契约的持有者。

步骤 4 · README 的复现章节

片段 · README.md 追加一节## 在一台干净机器上跑起来

### 前置

- Docker 与 Docker Compose v2（`docker compose version` 有输出）
- bash、curl、python3（macOS 与主流 Linux 自带）
- 空闲端口：8080（正门）、127.0.0.1:8081（服务端）、127.0.0.1:5432（数据库）

### 四步

    git clone <仓库地址> && cd <仓库目录>
    cp .env.example .env        # 然后把两把 JWT 密钥改成 `openssl rand -hex 32` 的输出
    make up                     # 迁移 → 构建 → 起 postgres/server/web
    make smoke                  # 端到端冒烟，最后一行应是 [SMOKE PASS]

浏览器打开 http://localhost:8080 就是前端；
`curl -s http://localhost:8081/healthz` 应返回
`{"code":0,"message":"ok","data":{"status":"ok"}}`。

### 收工

    make down        # 停服务，数据保留
    make reset       # 连数据卷与本地镜像一起清掉

### 起不来时按这个顺序查

| 症状 | 先看哪 |
|---|---|
| `address already in use` | 8080/8081/5432 被别的项目占着；`make down` 后重试 |
| server 一直 `(health: starting)` 然后 unhealthy | `docker compose logs server`。多半是 DB_* 或两把 JWT 密钥没配 |
| 迁移报 `no schema has been selected to create in` | 数据卷是旧的，initdb 钩子没执行过；`make reset` 后重新 `make up` |
| 接口全 404 + 1001 | `web/nginx.conf` 的 `proxy_pass` 结尾多了斜杠，路径前缀被吃掉了 |
| 页面能开、接口 502 | server 容器没健康；`docker compose ps` 与 `logs server` |
| 冒烟脚本第一步就失败 | `SMS_CODE_FIELD` 与你的验证码实现口径不一致 |
