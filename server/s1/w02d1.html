HTTP 语义、handler 签名与路由模式

第二周开工。上周六你把服务跑起来了，今天把「请求进来后发生什么」这条链路的规矩立清楚：状态码表达 HTTP 层语义，响应体里的 code 表达业务契约，两者各司其职；路由模式怎么匹配、404 和 405 分别由谁负责，今天一次说透，并给全站装上「未知路径 → 404 + 1001」的兜底。

今日目标

知识讲义

1. 状态码是信封，body 里的 code 是信纸

HTTP 状态码回答「这次传输与处理在协议层是什么结果」，分三类就够用：

类常用码语义本项目对应
2xx 成功200 / 201 / 204请求被正确处理200 查询与动作；201 创建（response.Created）
4xx 客户端错400 / 401 / 403 / 404 / 405 / 409请求本身有问题：换对请求就能成功由错误码表经 HTTPStatus 映射而来（D4）
5xx 服务端错500 / 502请求没问题，服务器搞砸了5000 内部错误；未知错误一律回落这里

本项目的契约是「双层语义」：HTTP 状态按错误码表映射，body 永远是三键信封，业务细节看 code。比如「家庭不存在」= HTTP 404 + body {"code":3001,…}；「越权读」= HTTP 404 + {"code":1001,…}——与真不存在同形，不给探测者任何区别信号（S4 会用一整个测试验证这条）。客户端逻辑因此很简单：先看 HTTP 状态决定「重试还是报错」，再看 code 决定「报什么错」。

两个易混码：401 = 你没登录/凭证无效（对应 1002、1005），403 = 我知道你是谁，但你没权限（对应 1003）。还有个特例要背下来：本项目越权「读」返回 404（与不存在同形），越权「写」才返回 403。

2. handler 签名：所有请求处理长得一样

片段 · 前置：import "net/http"func handleXxx(w http.ResponseWriter, r *http.Request) {
    // r.Method / r.URL.Path / r.PathValue("id") / r.URL.Query() / r.Body
    // 读请求 → 干活 → 用 response 包写出
}

r 里今天用到三样：r.PathValue("id") 取路径通配段的值（类型是 string，要 int64 自己转，明天 D8 练）；r.URL.Query() 取查询参数；r.Body 是请求体流（明天 D8 的主角）。

3. Go 1.22 路由模式：三种形态与两条匹配规则

模式匹配什么说明
"GET /api/ping"只匹配这一个路径方法+路径 = 精确匹配（等同老写法的 /api/ping/{$}）
"GET /files/{$}"只匹配 /files/（带尾斜杠）{$} 表示「到此为止」，不带它时老式 "/files/" 是前缀匹配——新老混用是 404 悬案的头号来源
"GET /api/ping/{echo}"/api/ping/任意一段{echo} 通配一段，值用 r.PathValue("echo") 取；{path...}（带省略号）通配多段

匹配规则两条：① 更具体的模式优先——/api/ping/{echo} 与 /api/ping/health 同时注册，后者赢，与注册顺序无关；② 路径对上了但方法不对 → Mux 自动回 405，不用你写一行代码。什么都没匹配上 → 404，但这个 404 是 Mux 的默认裸响应（纯文本），我们要换成统一信封——见下。

4. 404 兜底：注册 "/"，让所有漏网之鱼进统一信封

Mux 没有 Gin 那种 NoRoute 钩子（S2 换 Gin 后用它），标准库的等价做法：注册一个最不具体的模式 "/"。它匹配一切没有被更具体模式接走的请求：

片段 · 前置：response 包已落地（D6）mux.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
    response.Fail(w, http.StatusNotFound, response.CodeNotFound, "资源不存在")
})

全站纪律从此成立：任何未知路径都是 404 + 1001 + 统一信封，没有裸文本 404 漏出去。405 呢？Mux 自动送的 405 也是裸的——S1 先容忍（教学期），S2·D3 写中间件时用 Gin 的 NoMethod 一并收编。

教学期端点声明：今天的 /api/ping 与 /api/ping/{echo} 是练手用的假数据端点，不属于任何业务接口，S2·D1 换 Gin 时整个家族一并删除。假数据只能活在教学期与测试里——「注册了却没用/没实现的路由」是本项目明令避开的反例，S2·D1 的删除动作就是这条纪律的第一次执行。

今日增量（在学习仓里落盘）

今天属增量类型 ②：加路由与 handler 骨架（先返回假数据，S2·D1 删）。全部改动在 server/cmd/homecube/main.go 与 main_test.go。

步骤 1 · 注册三条新路由

完整 · server/cmd/homecube/main.go（覆盖 D6 版本）package main

import (
    "log"
    "net/http"

    "homecube/pkg/response"
)

func newRouter() http.Handler {
    mux := http.NewServeMux()
    mux.HandleFunc("GET /healthz", handleHealthz)

    // —— 教学期练手端点：S2·D1 换 Gin 时整个家族删除 ——
    mux.HandleFunc("GET /api/ping", handlePing)
    mux.HandleFunc("GET /api/ping/{echo}", handlePingEcho)

    // 404 兜底：一切没被接走的请求 → 404 + 1001 + 统一信封
    mux.HandleFunc("/", handleNotFound)
    return mux
}

func handleHealthz(w http.ResponseWriter, r *http.Request) {
    response.OK(w, map[string]string{"status": "ok"})
}

// handlePing 裸练统一响应体：固定假数据，教学期专用。
func handlePing(w http.ResponseWriter, r *http.Request) {
    response.OK(w, map[string]any{"pong": true})
}

// handlePingEcho 裸练路径参数：把 {echo} 命中的那段原样回显。
func handlePingEcho(w http.ResponseWriter, r *http.Request) {
    echo := r.PathValue("echo")   // string；D8 练「转不成 int64 就 400 + 1004」
    response.OK(w, map[string]string{"echo": echo})
}

func handleNotFound(w http.ResponseWriter, r *http.Request) {
    response.Fail(w, http.StatusNotFound, response.CodeNotFound, "资源不存在")
}

func main() {
    addr := ":8080"
    log.Println("homecube listening on", addr)
    if err := http.ListenAndServe(addr, newRouter()); err != nil {
        log.Fatal(err)
    }
}

步骤 2 · 表驱动测试补四条路径

片段 · main_test.go 新增（前置：D6 的 TestHealthz 与 import）func TestRoutes(t *testing.T) {
    tests := []struct {
        name       string
        method     string
        path       string
        wantStatus int
        wantFrag   string   // body 里必须包含的片段（D2 表驱动模式的变体）
    }{
        {"ping 返回信封", "GET", "/api/ping", 200, `"pong":true`},
        {"路径参数回显", "GET", "/api/ping/hello", 200, `"echo":"hello"`},
        {"未知路径统一 404", "GET", "/no/such/path", 404, `"code":1001`},
        {"方法不对 Mux 自动 405", "POST", "/healthz", 405, "Method Not Allowed"},
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            w := httptest.NewRecorder()
            req := httptest.NewRequest(tt.method, tt.path, nil)
            newRouter().ServeHTTP(w, req)
            if w.Code != tt.wantStatus {
                t.Fatalf("状态码 = %d, want %d（body: %s）", w.Code, tt.wantStatus, w.Body.String())
            }
            if !strings.Contains(w.Body.String(), tt.wantFrag) {
                t.Fatalf("body = %s, 应包含 %s", w.Body.String(), tt.wantFrag)
            }
        })
    }
}

第四条用例值得盯着看一眼：POST /healthz 的响应是 Mux 自动生成的裸 405，所以断言片段是纯文本——它是「还没被统一信封收编」的活证据。S2·D3 用中间件收编 405 时，这条用例会同步改成断言统一信封。

常见坑（新手 100% 会踩）

坑现象正确姿势
老式 "/files/" 当成精确匹配/files/a/b/c 全被它接走不带方法的老模式是前缀匹配。一律用 Go 1.22 新式 "GET /files/{$}" 或 "GET /files"
以为 405 要自己写给每个路径注册全部方法挨个判断，代码爆炸模式带方法名，Mux 自动 405；你要做的只是 S2·D3 把它收进统一信封
注册 "/" 后担心它抢走一切不敢注册兜底「更具体优先」：所有带方法/带路径的模式都比 "/" 具体，兜底只接漏网之鱼
把 PathValue 的返回当 int 用编译失败：string 与 int64 不能比它是 string。转换与「转失败 → 400 + 1004」是明天 D8 的正课
教学端点忘删S2 之后 /api/ping 还挂在路由表里，成了没用的假入口S2·D1 的清单第一条就是删它。今天 commit 信息里已埋了提醒
状态码与 body code 各说各话404 的 body 里写着 code 0，或 200 的 body 里写着 1001永远走 response.Fail/FailErr 出口，两层语义由 HTTPStatus 一张表钉死

今日名词卡

术语一句话解释
4xx vs 5xx4xx = 换对请求就能成功（客户端的锅）；5xx = 服务器的锅
401 vs 403401 未认证/凭证无效（1002/1005）；403 已认证但无权限（1003）
双层语义契约HTTP 状态按码表映射；业务细节看 body 的 code。客户端先看状态、再看码
越权读同形越权「读」返回 404+1001，与真不存在不可区分；越权「写」才 403
路由模式"METHOD /path"；{$} 止于此，{name} 通配一段，{name...} 通配多段
更具体优先Mux 按具体程度匹配，与注册顺序无关
405 Method Not Allowed路径命中、方法不符；Go 1.22 的 Mux 自动返回
NoRoute 兜底标准库用 "/" 等价实现；Gin 有现成钩子（S2）
教学期端点/api/ping* 家族：练手用、假数据、S2·D1 必删
安全方法 / 幂等GET 不应改数据（安全）；重复执行结果不变（幂等）。S2 讲写接口时展开

卡壳时查什么

正文自足，只有两种情况出去查：

  • 某个状态码的准确语义：MDN · HTTP 响应状态码（可选，中文）。
  • 路由模式的边角规则（模式冲突、{$} 与 {x...} 连用）：net/http · ServeMux（可选，读 Routing 一节即可）。

路由问题的调试铁律：用 curl -i 看原始响应，别用浏览器——浏览器会替你缓存、重定向、发额外请求，把 Mux 的真实行为搅浑。404 了就先问三件事：方法写没写进模式？尾斜杠？有没有更具体的模式抢走？
