表驱动测试与 httptest

D2 你写过第一个表驱动测试，这几天它又被你复制了好几份。今天把这门手艺规范化：表的字段怎么起名、子测试怎么命名才能被 -run 精确单跑、t.Fatal 与 t.Error 什么时候用哪个、断言 JSON 用字符串片段还是解码回结构体。今日增量属类型 ③：给 response 包与两个 handler 补齐规范测试，覆盖成功 + 1001 + 1004 三条路径。测试是接下来 20 周你唯一的「安全带」，今天值得慢一点。

今日目标

知识讲义

1. 规范表的 anatomy

片段 · 前置：import "testing"tests := []struct {
    name string   // 用例名：说人话，描述「输入特征 → 期望」，会成为子测试名
    in   Xxx       // 输入；多个输入就多个字段，别硬塞 map
    want Yyy       // 期望输出；复杂结果拆 wantA/wantB，别造「万能期望 struct」
}{ … }

三条纪律：① 用例名是给人读的失败报告——「路径参数不是数字_应400」远胜「case3」；② 一行用例只验一件事，塞五个断言的用例失败时你要读半天才知道哪件塌了；③ 表和循环体分家——加用例只加一行表项，永远不碰循环体，这就是「表驱动」的全部红利。

2. 子测试：命名与单跑

可跑 · 在仓库根执行，感受 -run 过滤cd server
go test -v -count=1 -run 'TestParsing/路径参数不是数字' ./cmd/homecube
# -v：打印每个子测试的 PASS/FAIL；-count=1：禁用缓存（D1 讲过，永远带着）

两个细节：-run 的值是正则，用 / 分隔「父测试/子测试」；用例名里的空格会被转成下划线（-run 'X/a_b_c' 匹配用例 "a b c"）——所以本站惯例是用例名不含空格，中文直接连写，过滤时不用猜转义。

t.Fatal/Fatalf = Error + 立即终止当前子测试；t.Error/Errorf = 记一笔失败但继续跑。选择规则一句话：后续断言依赖这一步的结果就用 Fatal，否则用 Error。「状态码都不对」后面再断言 body 毫无意义 → Fatal；「三个字段各验各的」→ 三个 Error，一次跑完看全貌。

你在旧教程里见过 tt := tt 这行咒语——那是 Go 1.22 之前「循环变量全循环共用一份」时代的补丁，配合 t.Parallel() 使用。Go 1.22 起循环变量每轮迭代都是新变量，本项目不需要这行咒语；见到别人的代码里有，知道是历史包袱即可。

3. 断言 JSON：从「字符串片段」升级到「解码回结构体」

前几天我们断言 strings.Contains(body, `"code":1004`)——快，但脆：字段顺序、空格、数字格式一变就误报。规范姿势是把响应体解码回结构体，逐字段断言：

片段 · 前置：import "encoding/json"；response.Body 已落地（D6）var got response.Body
if err := json.Unmarshal(w.Body.Bytes(), &got); err != nil {
    t.Fatalf("响应体不是合法 JSON: %v", err)
}
if got.Code != tt.wantCode { t.Errorf("code = %d, want %d", got.Code, tt.wantCode) }

json.Unmarshal 是 Decoder.Decode 的兄弟：后者从流里读（D8 解请求体），前者把一整段 []byte 解进变量（测试里断言响应）。Data 字段是 any，解码后是 map[string]any——要断言 data 内部字段时做类型断言（D5），或者干脆给 data 定义一个测试用的小 struct 再解一次。

4. NewRecorder vs NewServer：一条分界线记 20 周

httptest.NewRecorder()httptest.NewServer(h)
本质假的 ResponseWriter，不起网络，进程内直调 handler真起一个 localhost 随机端口 的 HTTP 服务，给你真 URL
速度/稳定性微秒级，零端口冲突毫秒级，占用端口，用完必须 defer ts.Close()
能测什么路由匹配、handler 逻辑、状态码与 body——99% 的接口测试必须走真网络栈的场景：真实客户端行为、超时、并发
本站使用期S2 / S4 主力（S1 今天已经在用）S5 并发与工程化专用（配 -race）

纪律一句话：能用 Recorder 解决的绝不开 Server。测试套件的耗时与「时红时绿」概率，都是按你开了多少真端口计的。

步骤 1 · response 包：FailErr 的三条路径

import (
    "encoding/json"
    "errors"
    "fmt"
    "net/http/httptest"
    "testing"
)

func TestFailErr(t *testing.T) {
    tests := []struct {
        name       string
        err        error
        wantStatus int
        wantCode   int
    }{
        {"哨兵NotFound_包装两层仍404+1001",
            fmt.Errorf("load: %w", fmt.Errorf("repo: %w", ErrNotFound)), 404, CodeNotFound},
        {"哨兵InvalidParam_400+1004", ErrInvalidParam, 400, CodeInvalidParam},
        {"陌生错误_回落500+5000", errors.New("something exploded"), 500, CodeInternal},
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            w := httptest.NewRecorder()
            FailErr(w, tt.err)

            if w.Code != tt.wantStatus {
                t.Fatalf("状态码 = %d, want %d", w.Code, tt.wantStatus) // 状态码错，body 不用看了
            }
            var got Body
            if err := json.Unmarshal(w.Body.Bytes(), &got); err != nil {
                t.Fatalf("响应体不是合法 JSON: %v", err)
            }
            if got.Code != tt.wantCode {
                t.Errorf("code = %d, want %d", got.Code, tt.wantCode)
            }
            if got.Message == "" {
                t.Errorf("message 不应为空")
            }
        })
    }
}

func TestOK(t *testing.T) {
    w := httptest.NewRecorder()
    OK(w, map[string]string{"status": "ok"})
    if w.Code != 200 {
        t.Fatalf("状态码 = %d, want 200", w.Code)
    }
    if ct := w.Header().Get("Content-Type"); ct != "application/json; charset=utf-8" {
        t.Errorf("Content-Type = %q", ct)
    }
}

完整 · server/cmd/homecube/routes_test.go（新建；同时删除 main_test.go 里的 TestRoutes 与 TestParsing）package main

import (
    "encoding/json"
    "net/http/httptest"
    "strings"
    "testing"

    "homecube/pkg/response"
)

func TestRoutesCanonical(t *testing.T) {
    tests := []struct {
        name       string
        method     string
        path       string
        body       string
        wantStatus int
        wantCode   int
    }{
        // 成功路径
        {"healthz_成功_200+0", "GET", "/healthz", "", 200, response.CodeOK},
        {"ping_成功_200+0", "GET", "/api/ping", "", 200, response.CodeOK},
        {"路径参数合法_200+0", "GET", "/api/ping/123", "", 200, response.CodeOK},
        {"JSON合法_200+0", "POST", "/api/ping/echo", `{"name":"shuai"}`, 200, response.CodeOK},
        // 1001 路径：未知资源
        {"未知路径_404+1001", "GET", "/no/such/path", "", 404, response.CodeNotFound},
        // 1004 路径：请求不合法
        {"路径参数非数字_400+1004", "GET", "/api/ping/abc", "", 400, response.CodeInvalidParam},
        {"JSON语法烂_400+1004", "POST", "/api/ping/echo", `{"name":`, 400, response.CodeInvalidParam},
        {"未知字段_400+1004", "POST", "/api/ping/echo", `{"nmae":"x"}`, 400, response.CodeInvalidParam},
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            w := httptest.NewRecorder()
            req := httptest.NewRequest(tt.method, tt.path, strings.NewReader(tt.body))
            newRouter().ServeHTTP(w, req)

            if w.Code != tt.wantStatus {
                t.Fatalf("状态码 = %d, want %d（body: %s）", w.Code, tt.wantStatus, w.Body.String())
            }
            var got response.Body
            if err := json.Unmarshal(w.Body.Bytes(), &got); err != nil {
                t.Fatalf("响应体不是合法 JSON: %v（原始: %s）", err, w.Body.String())
            }
            if got.Code != tt.wantCode {
                t.Errorf("code = %d, want %d", got.Code, tt.wantCode)
            }
        })
    }
}

注意 D7 那条「POST /healthz → 405 裸文本」用例没有进这张表——它的响应不是统一信封，解码断言不适用，留在 TestRoutes 被删前请把它挪进独立的 TestMethodNotAllowed，用字符串断言。一张表只装同一形状的东西，这也是规范的一部分。

常见坑（新手 100% 会踩）

坑现象正确姿势
用例名带空格再想 -run 过滤匹配不上——空格被转成了下划线用例名不用空格；或过滤时写 用例_名
状态码已错还继续断言 body一条用例刷出五个失败，噪音盖住病根依赖性断言用 Fatalf 提前收场；独立断言才用 Errorf
字符串片段断言一切 JSON字段顺序/格式微调 → 测试误报一片解码回结构体断字段；字符串精确断言只留给「字节级契约」（如 healthz）
忘了 -count=1改了代码测试还是绿——跑的是缓存Makefile 里已焊死（D1）；手敲命令时也带上
旧教程的 tt := tt 照抄进来无害但莫名其妙Go 1.22+ 不需要；知道它是循环变量旧时代的补丁即可
每个测试都开 NewServer套件变慢、偶发端口冲突、CI 时红时绿进程内一律 NewRecorder；NewServer 是 S5 并发测试的工具
测试之间共享可变状态单跑绿、全量跑红（或反过来）每个子测试里新建 repo/recorder；顺序无关是表驱动的前提

今日名词卡

术语一句话解释
表驱动测试用例是数据（表），循环体是解释器；加用例 = 加一行
子测试（t.Run）表里每行一个独立测试上下文，可单跑、失败隔离
t.Fatal vs t.Error前者终止当前子测试，后者记录后继续；按「后续断言是否依赖」选
-run / -v / -count=1正则过滤 / 逐条打印 / 禁缓存——手敲测试命令三件套
json.Unmarshal把整段 []byte 解进变量；Decoder 的「非流式」兄弟
NewRecorder进程内假响应记录器；S2/S4 接口测试主力
NewServer真端口的本地测试服务；S5 并发与超时场景专用，用完 defer Close
覆盖率（-cover）被测试执行到的语句占比；数字只是线索不是目标，S5 接进 CI
测试替身为测试造的假依赖；D5 的内存 repo 就是第一个

卡壳时查什么

正文自足，只有两种情况出去查：

  • testing 包的完整能力（Setup/子测试并行/基准测试）：testing 文档（可选，今天只需要 Test/Run/Fatal/Error 四件事）。
  • httptest 两个工具的边界：httptest 文档（可选，包文档开头两段就是分工说明书）。

测试红了的标准动作：先读失败输出的第一行（哪个子测试、got/want 各是什么），再决定是代码错还是用例错——两边都可能错，不许为了让它绿而放宽断言。放宽断言让测试变绿，等于把烟雾报警器的电池拆了。
