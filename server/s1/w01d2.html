变量、类型、控制流与指针

今天的正菜是指针——Go 里第一个让 JS/TS 出身的人真正卡住的概念。变量与控制流部分你会觉得「就这？」，那就快点过；把省下的时间全给指针和第一个表驱动测试。今天的测试函数不是玩具：它是错误码 → HTTP 状态的映射，S1·D4 会扩成全表并一直用到 S8。

今日目标

知识讲义

1. 变量、类型与零值

两种声明方式，规则简单粗暴：函数内部、且右边能看出类型时，一律 :=；包级别（函数外）只能 var。

片段 · 函数内name := "homecube"        // 类型推断为 string，等同 TS 的 const name = "homecube"
var count int              // 只声明不赋值：count 自动是 0（零值），不存在 undefined
var ratio = 0.5            // var + 推断，包级别声明只能这么写

零值是 Go 和 JS 心智差异最大的地方之一：变量声明了不赋值，不是 undefined，而是该类型的「零」——数字 0、字符串 ""、布尔 false、指针 nil。设计良好的 Go 类型「零值即可用」，D5 会见到实例。

基础类型对照，只需记差异：

JS/TSGo差异要点
numberint / int64 / float64整数和浮点是不同类型，混算直接编译失败。本项目 id 一律 int64，金额一律 int64（以分为单位，全项目禁止用浮点存钱）
stringstring不可变，同 JS。+ 拼接在循环里是坑，见「常见坑」
booleanbool非布尔值不能当条件：if x（x 是 int）编译失败，必须写 if x != 0
null / undefinednil只有一个 nil，是指针/slice/map/接口等「引用类」类型的零值
隐式转换（"1"+1=="11"）没有隐式转换int64(x) 显式转，转错了编译器拦你

2. 控制流：三件小事

片段// if 可以带一条初始化语句，err 的作用域被限制在 if/else 里——全项目最常见的句式
if err := doSomething(); err != nil {
    return err
}

// 循环只有 for 一个关键字，没有 while
for i := 0; i < 5; i++ { }
for cond { }              // 等同 while (cond)
for k, v := range m { }   // 遍历 map/slice；range 明天 D3 细讲

// switch 自带 break，不会穿透；case 可以是任意表达式
switch {
case code == 0:
    status = 200
default:
    status = 500
}

没有三元表达式。cond ? a : b 在 Go 里就是四行 if/else，这是故意的设计——别去找 trick。

3. 值传递与指针：今天唯一的新世界观

先立一条铁律：Go 的一切传参都是复制。传 int 复制一个数，传 struct 复制整个 struct（明天 D3 会疼一次），传指针复制的是一个地址。所以严格地说，Go 没有「引用传递」这个概念——指针传递仍然是值传递，只不过值的内容是地址。

可跑 · 先读懂再跑package main

import "fmt"

func doubleVal(x int)   { x = x * 2 }   // 改的是副本，外面看不到
func doublePtr(x *int)  { *x = *x * 2 }  // 顺着地址改原件，外面看得到

func main() {
    n := 21
    doubleVal(n)
    fmt.Println(n)   // 21：复制品被改了，原件没动
    doublePtr(&n)   // &n = 「n 的地址」，类型是 *int
    fmt.Println(n)   // 42：*x = 「x 指向的那个值」，改到了原件
}

三个符号一次记牢：

写法读法出现位置
&x取 x 的地址表达式里；结果是 *T 类型
*int「指向 int 的指针」这个类型类型位置
*p解引用：p 指向的那个值表达式里；p 是 nil 时当场 panic

什么时候传指针？就两条：① 函数要改调用方的东西；② 东西太大，复制心疼。除此之外传值。与 C 不同，Go 指针不能做算术（p+1 编译失败），所以它没有 C 指针那种「越界扫内存」的恐怖故事，放心用。

panic 今天只需一句：程序遇到不可恢复错误直接崩掉，最常见触发就是解引用 nil 指针。它和 error 的分工、以及在 HTTP 服务里怎么兜住它，S2·D3 讲中间件时正式展开。

4. 沙盒约定与表驱动测试首秀

从今天起立一条规矩（全期有效）：纯语法练习放 server/playground/dN/，每个子目录自带独立 go.mod。一个目录一个 package main，多个练习就多个子目录——主模块的 go build ./... 会自动跳过嵌套模块，练习再多也不会污染构建。

然后是今天的重头戏：表驱动测试。Go 的测试是语言内置的——文件以 _test.go 结尾，函数以 Test 开头、参数是 *testing.T，不需要任何测试框架。「表驱动」就是把用例排成一张表（一个 slice），循环跑：

片段 · 表驱动测试的骨架（完整可跑版见「今日增量」）func TestXxx(t *testing.T) {
    tests := []struct {        // 匿名 struct，明天 D3 正式讲 struct
        name string
        in   int
        want int
    }{
        {"成功", 0, 200},
        {"不存在", 1001, 404},
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            if got := Xxx(tt.in); got != tt.want {
                t.Errorf("Xxx(%d) = %d, want %d", tt.in, got, tt.want)
            }
        })
    }
}

两个关键点：t.Run 把每个用例变成子测试，失败时报出用例名，还能用 go test -run TestXxx/不存在 单跑一条；tt 是社区惯用名（test table 的一行）。这个模式会陪你 22 周——S2 测 handler、S4 测越权、S6 测报表口径，全是它。

步骤 1 · 指针沙盒（playground/d2）

可跑cd <你的学习仓根目录>   # 即「仓库根」，D1 定义过
mkdir -p server/playground/d2 && cd server/playground/d2
go mod init d2
完整 · server/playground/d2/main.gopackage main

import "fmt"

// swap 交换两个 int：必须用指针，否则改的是副本
func swap(a, b *int) {
    *a, *b = *b, *a
}

func main() {
    x, y := 1, 2
    swap(&x, &y)
    fmt.Println(x, y) // 2 1

    var p *int // nil 指针
    fmt.Println(p == nil) // true；此时写 *p 会 panic，别试也可以试一次感受下
}
可跑go run .   // 在 playground/d2 目录下执行，输出 2 1 和 true

步骤 2 · 被测函数：server/pkg/response/code.go

包名 response（目录名去掉复数含义，就叫 response）。今天只放一个纯函数：

完整 · server/pkg/response/code.gopackage response

// HTTPStatus 把业务错误码映射为 HTTP 状态码。
// 今天先覆盖四个码；S1·D4 落成错误码常量全表后，这里会扩成完整映射。
// 未知码一律回落 500——宁可报服务器错误，不可把错误码当成功放出去。
func HTTPStatus(code int) int {
    switch code {
    case 0:
        return 200
    case 1001: // 资源不存在（越权读也返回本码，与「真不存在」同形）
        return 404
    case 1004: // 参数错误
        return 400
    case 5000: // 服务器内部错误
        return 500
    default:
        return 500
    }
}

魔法数字 1001、1004 直接写在代码里是临时状态。D4 会把它们全部换成 CodeNotFound、CodeInvalidParam 这样的具名常量，并把全站错误码表一次落齐。今天先忍——增量颗粒度纪律：一天只干一类事。

步骤 3 · 第一个表驱动测试：server/pkg/response/code_test.go

完整 · server/pkg/response/code_test.gopackage response

import "testing"

func TestHTTPStatus(t *testing.T) {
    tests := []struct {
        name string
        code int
        want int
    }{
        {"成功返回 200", 0, 200},
        {"不存在返回 404", 1001, 404},
        {"参数错误返回 400", 1004, 400},
        {"内部错误返回 500", 5000, 500},
        {"未知码回落 500", 9527, 500},
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            if got := HTTPStatus(tt.code); got != tt.want {
                t.Errorf("HTTPStatus(%d) = %d, want %d", tt.code, got, tt.want)
            }
        })
    }
}

注意测试文件的包名也是 response（不是 main），和被测代码同包，才能直接调 HTTPStatus。

常见坑（新手 100% 会踩）

坑现象正确姿势
函数里改参数，以为外面会变改了个寂寞，不报错要改原件就传 *T；传值 = 复制
解引用 nil 指针panic: runtime error: invalid memory address用指针前判 p != nil；报错第一行就有文件和行号
& 与 * 用混cannot use &x (type **int) as *int已经是 *int 就不要再 &；类型不对时把类型念一遍就懂了
int 与 int64 混算invalid operation: mismatched types显式转换 int64(x)。本项目 id/金额全用 int64
:= 在 if 里声明后，外面还想用undefined: errif err := … 的 err 只活在 if/else 块里；要在外面用就先 var err error
把 slice/map 当「引用传递」函数里 append 外面看不到，但改元素外面看得到它们也是值传递（复制一个描述结构）。D4 讲 slice 三要素时正式拆解
循环里用 + 拼字符串能跑，量大时慢得离谱标准答案是 strings.Builder——S5 做报表拼接时正式兑现，今天先知道有这回事

今日名词卡

术语一句话解释
零值（zero value）类型自带的默认值：0 / "" / false / nil。没有 undefined
:=函数内的声明+赋值+类型推断，仅限函数内
指针（*T）存地址的值；&x 取地址，*p 解引用
值传递Go 唯一的传参方式：一切皆复制，指针复制的是地址
panic不可恢复错误，程序崩溃。与 error 的分工 S2·D3 讲
表驱动测试用例排成 slice，循环 + t.Run 逐条跑。Go 社区默认测试姿势
子测试（t.Run）给每个用例起名，失败可定位、可单跑
playground 约定语法练习放 server/playground/dN/，各自独立 go.mod，不进主模块
struct把多个字段捆成一个类型。D3 详讲
error 与 %werror 是普通值，包装用 %w。D4 详讲
接口（interface）方法名的约定，方法齐了就算实现。D5 详讲

卡壳时查什么

本站正文自足，只有两种情况出去查：

  • 指针绕不过来：做一遍 A Tour of Go 的 Pointers 一节（可选，十分钟，带交互练习）。
  • 测试输出看不懂：testing 包文档（可选）；其实只需认识 ok（过了）、FAIL（挂了）、--- FAIL: TestXxx/用例名（哪条挂的）。

调试指针问题的土办法，比任何文档都快：fmt.Println(x, &x) 把值和地址都打出来，看「函数内外地址是否相同」。地址相同 = 同一个东西，不同 = 被复制了。
