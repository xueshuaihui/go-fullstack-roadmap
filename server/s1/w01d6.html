周六 · net/http 起服务，把本周串成 GET /healthz

本周第一个「能跑起来给别人看」的产物：一个真实的 HTTP 服务，GET /healthz 返回全站统一响应体，且有测试断言它。今天没有新世界观，只有一件事——把 D1-D5 的五个微增量串成一条完整能力：骨架（D1）、表驱动测试（D2）、model（D3）、错误码与哨兵（D4）、接口（D5），全部在今天合体。S2·D1 换 Gin 时，你会发现今天手写的每一行都能在 Gin 里找到对应物。

今日目标

知识讲义

1. HTTP 服务的本质：一个接口 + 一个循环

Go 标准库把「一个 HTTP 服务」拆得极简：监听循环（http.ListenAndServe 收连接、解析报文）+ 一个接口（每个请求交给谁处理）。这个接口就是 http.Handler：

片段 · 标准库源码，只需读type Handler interface {
    ServeHTTP(w ResponseWriter, r *Request)
}

眼熟吗？昨天 D5：「方法齐了就算实现」。http 包不认识你的任何类型，但任何带 ServeHTTP(w, r) 方法的类型都能当处理器。而普通函数没有方法——于是标准库给了个适配器 http.HandlerFunc：它是个函数类型，自己带 ServeHTTP 方法（方法体就是调用自己），所以 http.HandlerFunc(yourFunc) 一转，普通函数就成了 Handler。HandleFunc 注册函数帮你把这个转换也做了。

S2 的 Gin 干的事本质相同：gin.HandlerFunc 也是函数类型 + 适配器，只是参数从 (w, r) 换成了包了一层的 *gin.Context。今天手写过适配器，S2·D1 你会一眼看穿框架。

2. ServeMux 与 Go 1.22 的路由模式

http.ServeMux（multiplexer，多路复用器）是标准库自带的「路由器」：按路径把请求分发给注册的 handler。Go 1.22 起它升级了两件大事：

能力写法说明
方法 + 路径模式mux.HandleFunc("GET /healthz", h)模式 = "方法 路径"。只注册 GET /x 时，POST /x 自动收到 405（Mux 送的，不用你写）
路径参数"GET /families/{id}" + r.PathValue("id")通配一段路径并取出；{id...}（带省略号）是前缀通配，下周 D7 会撞上它的坑
更精确的模式优先/families/new 胜过 /families/{id}Mux 自动按「更具体优先」匹配，不看你注册顺序

没匹配到任何模式 → Mux 自动回 404。下周 D7 要把这个 404 换成全站统一响应体（404 + 1001），今天先让它裸着。

3. ResponseWriter：一支只能按顺序写的笔

handler 的两个参数：r *http.Request 是请求（只读），w http.ResponseWriter 是「正在书写的响应」。书写有严格顺序：

片段 · 一个 JSON handler 的标准三步w.Header().Set("Content-Type", "application/json; charset=utf-8")  // ① 先写头
w.WriteHeader(200)                                                  // ② 再定状态码
json.NewEncoder(w).Encode(body)                                     // ③ 最后写 body（内部调 Write）
  • WriteHeader 只能调一次；第一次 Write 时若还没调，自动按 200 补一次。
  • 状态行和头一旦发出（即第一次 Write 之后）就覆水难收——再 Set header 无效、再 WriteHeader 会在日志里刷 superfluous WriteHeader。
  • JSON 响应必须显式设 Content-Type，不然默认是 text/plain，浏览器和客户端库都不会帮你解析。

4. httptest：不起真服务也能测 handler

httptest.NewRecorder() 给你一个假的 ResponseWriter（把响应记在内存里），httptest.NewRequest 造一个假的 *Request，然后直接调用你的 mux 或 handler——没有网络、没有端口、毫秒级跑完：

片段 · 前置：import "net/http/httptest"w := httptest.NewRecorder()
req := httptest.NewRequest("GET", "/healthz", nil)
mux.ServeHTTP(w, req)          // mux 是 http.Handler——又是 D5 的接口
// 断言 w.Code（状态码）、w.Header()（头）、w.Body.String()（响应体）

本站的分工纪律：NewRecorder（进程内直调，快、稳）是 S2/S4 测 handler 的主力；NewServer（起一个真实端口、给你真 URL）留到 S5 测并发场景才登场。今天以及未来两周，你只需要 Recorder。

步骤 1 · response 包补全：Body 与四个写出函数

完整 · server/pkg/response/response.gopackage response

import (
    "encoding/json"
    "net/http"
)

// Body 是全站唯一响应信封。任何接口、任何状态码，Body 都是这三个键。
type Body struct {
    Code    int    `json:"code"`
    Message string `json:"message"`
    Data    any    `json:"data"`   // 空接口（D5）：信封形状固定，装什么各接口自定
}

// write 是三个出口共用的「笔顺」：先 header、再状态码、后 body。
func write(w http.ResponseWriter, httpStatus int, b Body) {
    w.Header().Set("Content-Type", "application/json; charset=utf-8")
    w.WriteHeader(httpStatus)
    _ = json.NewEncoder(w).Encode(b) // 序列化 Body 理论上不会失败；故意忽略须注释（D4 纪律）
}

// OK 成功：HTTP 200 + code 0。
func OK(w http.ResponseWriter, data any) {
    write(w, http.StatusOK, Body{Code: CodeOK, Message: "ok", Data: data})
}

// Created 创建成功：HTTP 201 + code 0。S2 写接口开始用。
func Created(w http.ResponseWriter, data any) {
    write(w, http.StatusCreated, Body{Code: CodeOK, Message: "ok", Data: data})
}

// Fail 明确知道码和状态时用。
func Fail(w http.ResponseWriter, httpStatus, code int, msg string) {
    write(w, httpStatus, Body{Code: code, Message: msg})
}

// FailErr 拿着 error 时用：CodeOf（D4）认哨兵 → 码，HTTPStatus（D4）码 → 状态。
// 认不出的错误一律 5000/500——内部细节绝不外泄，细节留给日志（S5 建）。
func FailErr(w http.ResponseWriter, err error) {
    code := CodeOf(err)
    Fail(w, HTTPStatus(code), code, err.Error())
}

S2·D1 换 Gin 时这四个函数的第一个参数会从 http.ResponseWriter 换成 *gin.Context，函数名与语义全期不变——这就是把响应层收进 pkg/response 的意义：契约只有一份，框架随便换。

步骤 2 · healthz handler 与 main.go 装配

完整 · server/cmd/homecube/main.go（覆盖 D1 的占位版）package main

import (
    "log"
    "net/http"

    "homecube/pkg/response"
)

// newRouter 装配全部路由并返回 http.Handler。
// 拆成独立函数是为了测试：测试里不 ListenAndServe，直接拿 router 调 ServeHTTP。
func newRouter() http.Handler {
    mux := http.NewServeMux()
    mux.HandleFunc("GET /healthz", handleHealthz)
    return mux
}

// handleHealthz 健康检查：永远返回统一响应体。
func handleHealthz(w http.ResponseWriter, r *http.Request) {
    response.OK(w, map[string]string{"status": "ok"})
}

func main() {
    addr := ":8080" // 先写死；S5 起从环境变量 PORT 读
    log.Println("homecube listening on", addr)
    if err := http.ListenAndServe(addr, newRouter()); err != nil {
        log.Fatal(err) // 起不来就别装了：直接崩，让进程管理器看到失败
    }
}

步骤 3 · httptest 断言

完整 · server/cmd/homecube/main_test.gopackage main

import (
    "net/http/httptest"
    "strings"
    "testing"
)

func TestHealthz(t *testing.T) {
    w := httptest.NewRecorder()
    req := httptest.NewRequest("GET", "/healthz", nil)
    newRouter().ServeHTTP(w, req)

    if w.Code != 200 {
        t.Fatalf("状态码 = %d, want 200", w.Code)
    }
    if ct := w.Header().Get("Content-Type"); !strings.Contains(ct, "application/json") {
        t.Fatalf("Content-Type = %q", ct)
    }
    // 断言精确到整个信封：三键缺一不可，顺序无关
    want := `{"code":0,"message":"ok","data":{"status":"ok"}}`
    if got := strings.TrimRight(w.Body.String(), "\n"); got != want {
        t.Fatalf("body = %s, want %s", got, want)
    }
}

这里断言的是字符串级精确匹配（json.Encoder 按字段声明序输出，稳定）。S2 起会用「解码回结构体再比字段」的宽松断言，今天先体验最严的一档。

常见坑（新手 100% 会踩）

坑现象正确姿势
先 Write 再设 headerheader 静默丢失，Content-Type 是 text/plain笔顺：Header().Set → WriteHeader → Write。response.write 已替你钉死
WriteHeader 调两次日志刷 superfluous response.WriteHeader call只调一次；写 JSON 统一走 response 包的出口函数就不会犯
端口被占listen tcp :8080: bind: address already in uselsof -i :8080 找到进程 kill 掉——多半是你上一个 make run 忘了 Ctrl+C
注册 "/families" 却匹配到 /families/1老式模式（无方法、无 $）是前缀匹配Go 1.22 精确路径写 "GET /families"；下周 D7 讲 {$} 与 {id...} 的区别
测试里 NewRequest 忘写方法空方法不匹配 "GET /healthz" 模式，收到 405/404，还以为 handler 坏了方法、路径都写实；断言失败先打印 w.Code 和 w.Body
拿 NewServer 测一切测试变慢、偶发端口冲突、CI 上时红时绿进程内测试一律 NewRecorder；NewServer 留给 S5 的并发场景
