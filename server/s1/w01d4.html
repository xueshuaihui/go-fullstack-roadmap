slice、map、defer 与 error 包装

今天四个知识点，前三个是「工具」，最后一个是「世界观」：Go 的 error 就是一个普通值，没有 try/catch，没有异常栈，函数把 error 当返回值一层层往上传。而「包装」让这条传递链不丢信息——%w 与 errors.Is 是全站错误处理的地基。今日增量同样分量十足：错误码常量全表落成 Go 代码，一次落齐，此后 20 周不再动。

今日目标

知识讲义

1. slice：数组上面的一层「视图」

slice 不是数组，是一个三字段的小结构：指向底层数组的指针 + 长度 len + 容量 cap。理解一切 slice 怪象只需要这一句：传 slice = 复制这三个字段，但底层数组是共享的。

可跑package main

import "fmt"

func main() {
    s := []int{1, 2, 3}          // 字面量创建；make([]int, 0, 10) 是另一种
    t := s[:2]                     // 切片 = 共享底层数组的视图：t 是 [1 2]
    t[0] = 99                      // 改 t 的元素 = 改 s 的元素（同一个数组）
    fmt.Println(s)                 // [99 2 3]

    t = append(t, 4)               // len(t)==cap 时 append 会另起新数组
    fmt.Println(s, t)              // s 不再跟着变——t 已经搬走了

    for i, v := range s {          // range 给出下标和元素的副本
        fmt.Println(i, v)
    }
}

「改元素外面看得到、append 外面看不到」——这不是玄学：改元素走的是共享的底层数组；append 一旦扩容就把数据搬进新数组，副本里的指针从此和你无关。要函数帮你 append 并拿到结果，就让函数把 slice 返回出来：s = add(s, x)，全项目统一这个姿势。

2. map：哈希表，三件事记牢

片段 · 前置：无m := map[int64]string{}      // 键 int64、值 string；make(map[int64]string) 亦可
m[1] = "owner"

name := m[2]                  // 键不存在 → 得到值类型的零值 ""，不报错！
name, ok := m[2]              // comma-ok：ok=false 表示真没有。区分「没存」和「存了零值」只能靠它
delete(m, 1)                  // 删除；删不存在的键是无害空操作
  • 遍历无序：for k, v := range m 每次顺序都可能不同，Go 故意的。要有序就取出键排序。
  • value 不可寻址：m[k].Name = "x" 编译失败（昨天踩过）。存指针 map[int64]*User，或取出改完整体放回。
  • 并发读写会崩：两个 goroutine 同时读写同一个 map 直接 fatal error。解法是加 sync.Mutex——明天 D5 的内存仓储照抄一次，S5 正式讲。goroutine 是什么今天只需一句：可以并发执行的函数调用。

3. defer：注册一条「函数返回前才执行」的语句

片段 · 前置：无func read() error {
    f, err := os.Open(path)   // os 包打开文件，返回 *os.File 与 error
    if err != nil {
        return err
    }
    defer f.Close()           // 注册在此、执行在函数返回前——无论走哪个 return
    // …中间随便多少个 return 分支，Close 都不会漏
}

三条规则：LIFO（同函数多个 defer，后注册先执行）；参数在注册那一刻就求值（defer fmt.Println(i) 打印的是注册时的 i）；标准用途是「成对操作的后一半」——Close、Unlock、recover（S2·D3 中间件里会见到第三种）。「打开后下一行立刻 defer 关闭」要练成肌肉记忆。

4. error 是值：包装、哨兵与 errors.Is

error 其实是个接口——任何类型只要有 Error() string 方法就是 error。接口明天 D5 正式讲，今天先用结论。关键设计：error 是普通返回值，谁出错谁返回，调用方决定处理还是上抛：

片段 · 前置：import "errors" 与 "fmt"// 哨兵错误（sentinel）：包级别预定义的错误值，调用方拿它做判断
var ErrNotFound = errors.New("not found")

// 中间层：包一层上下文再上抛。%w 是「包装」，%v 是「拍扁」
func findUser(id int64) error {
    return fmt.Errorf("find user %d: %w", id, ErrNotFound)
}

// 顶层：errors.Is 沿着包装链逐层拆开比对
if errors.Is(err, ErrNotFound) { /* 404 */ }
写法结果什么时候用
fmt.Errorf("…: %w", err)新 error 里保住了原 error，链可拆默认姿势。每过一层加一句上下文（这个函数在干什么、参数是什么）
fmt.Errorf("…: %v", err)原 error 被拍成字符串，链断了几乎不用。断链 = 上层 errors.Is 全部失灵
errors.Is(err, target)沿链逐层问「是不是它」判断哨兵错误的唯一正确姿势
err == ErrNotFound只比最外层，被包过就 false禁用。这是「明明 NotFound 却走了 500」事故的头号来源
errors.As(err, &target)沿链找「某个类型」的错误并取出S3 处理数据库驱动错误时用，今天混脸熟

为什么值得这么讲究？看这条真实链路：response.FailErr（D6 写）要把错误翻译成统一响应体——repo 层返回 fmt.Errorf("find family %d: %w", id, ErrNotFound)，FailErr 用 errors.Is(err, ErrNotFound) 认出它，回 404 + 1001。中间隔了几层包装都认得出来，这就是 %w 链的价值。认不出的错误一律 500——错误码表里的 5000。

步骤 1 · 错误码常量全表

完整 · server/pkg/response/code.go（覆盖 D2 的版本）package response

// 全站错误码表——唯一版本。0 成功；1001-1010 通用；3001-3004 家庭/成员；
// 4001-4002 财务；5000 服务器内部错误。禁止新增此表之外的码。
const (
    CodeOK               = 0    // 成功
    CodeNotFound         = 1001 // 资源不存在；越权读也返回本码（与「真不存在」同形，不泄露存在性）
    CodeAuthFailed       = 1002 // 认证失败（凭证错误；防枚举：「手机号不存在或验证码错」统一本码）
    CodeForbidden        = 1003 // 权限不足（角色矩阵拒绝 / 面未启用 / 字段不可见 / 非作者改他人数据）
    CodeInvalidParam     = 1004 // 参数错误
    CodeUnauthenticated  = 1005 // 未认证 / token 无效或过期
    CodeConflict         = 1006 // 唯一约束冲突（手机号、邀请码、同家庭内账户名）
    CodeBadTimeWindow    = 1007 // 时间窗编码非法，不回落默认档
    CodeIdempotent       = 1008 // 幂等冲突：client_request_id 已用过且请求体不同
    CodeVersionConflict  = 1009 // 版本冲突：乐观锁 version 不匹配
    CodeStateNotAllowed  = 1010 // 业务状态不允许（如余额非 0 归档）
    CodeFamilyNotFound   = 3001 // 家庭不存在或当前账号无权访问
    CodeInviteInvalid    = 3002 // 邀请无效 / 已过期 / 已使用
    CodeCaptchaInvalid   = 3003 // 验证码错误或已过期
    CodeFamilyLimit      = 3004 // 账号家庭数已达上限
    CodeAmountInvalid    = 4001 // 金额非法（≤0、超出可用余额、转账两端同账户）
    CodeAttachmentLimit  = 4002 // 附件超限（张数 / 单张大小 / 格式）
    CodeInternal         = 5000 // 服务器内部错误
)

// HTTPStatus 把业务错误码映射为 HTTP 状态码。未知码一律回落 500。
func HTTPStatus(code int) int {
    switch code {
    case CodeOK:
        return 200
    case CodeNotFound, CodeFamilyNotFound:
        return 404
    case CodeAuthFailed, CodeUnauthenticated:
        return 401
    case CodeForbidden:
        return 403
    case CodeInvalidParam, CodeBadTimeWindow, CodeInviteInvalid,
        CodeCaptchaInvalid, CodeAmountInvalid, CodeAttachmentLimit:
        return 400
    case CodeConflict, CodeIdempotent, CodeVersionConflict,
        CodeStateNotAllowed, CodeFamilyLimit:
        return 409
    default:
        return 500
    }
}

步骤 2 · 哨兵错误集

完整 · server/pkg/response/errors.gopackage response

import "errors"

// 哨兵错误集：repo/service 层往上抛的就是这些值，
// FailErr（D6 落地）用 errors.Is 认出它们并翻译成对应错误码。
var (
    ErrNotFound     = errors.New("not found")      // → 1001 / 404
    ErrForbidden    = errors.New("forbidden")      // → 1003 / 403
    ErrInvalidParam = errors.New("invalid param")  // → 1004 / 400
    ErrConflict     = errors.New("conflict")       // → 1006 / 409
    ErrInternal     = errors.New("internal error") // → 5000 / 500
)

// CodeOf 把哨兵错误翻译成业务码；认不出来的一律 5000。
// 注意 errors.Is 而不是 ==——链被包装过也要认得出来。
func CodeOf(err error) int {
    switch {
    case err == nil:
        return CodeOK
    case errors.Is(err, ErrNotFound):
        return CodeNotFound
    case errors.Is(err, ErrForbidden):
        return CodeForbidden
    case errors.Is(err, ErrInvalidParam):
        return CodeInvalidParam
    case errors.Is(err, ErrConflict):
        return CodeConflict
    default:
        return CodeInternal
    }
}

为什么只立 5 个哨兵、而码表有 18 个？因为哨兵是「跨层传递的通用语」，够 repo/service 表达常见失败即可；3001-3004、4001-4002 这类领域专属错误，S4/S6 会在各自模块里定义自己的哨兵，再由 handler 翻译成本表的码。码表是对外契约，一次定死；哨兵是内部词汇，随阶段生长。

常见坑（新手 100% 会踩）

坑现象正确姿势
切片后 append，以为原 slice 会跟着变有时变有时不变（取决于 cap），行为像随机记住三要素模型；append 的结果永远接住：s = append(s, x)
读 map 不存在的键得到零值，不报错，bug 静默扩散用 comma-ok：v, ok := m[k]
往 nil map 里写panic: assignment to entry in nil map声明后先 make 或字面量初始化，再写
依赖 map 的遍历顺序每次跑顺序不同，测试时红时绿map 无序是语言规格。要有序：取键、排序、再遍历
defer 写在循环里资源到函数结束才释放，量大时文件句柄耗尽循环体抽成独立函数，defer 放函数里
defer 的参数以为是执行时求值defer fmt.Println(i) 打印注册时的 i参数立即求值；要延迟取值就包一层闭包 defer func(){ … }()
用 %v 包 error上层 errors.Is 全部失灵，全走 500包装永远 %w
用 == 比包装过的 error同上判断哨兵永远 errors.Is
吞掉 error（_ = f()）出错无声无息，事故现场没有线索要么处理、要么包上下文上抛；故意忽略必须写注释说明为什么可以忽略

今日名词卡

术语一句话解释
slice 三要素底层数组指针 + len + cap；传参复制这三字段，数组共享
append追加元素，容量不够就换新数组——所以必须接住返回值
comma-okv, ok := m[k]：区分「不存在」与「存了零值」
defer注册在返回前执行的语句；LIFO；参数立即求值
error一个接口：有 Error() string 方法就是 error。接口明天 D5 正式讲
哨兵错误（sentinel）包级 var ErrXxx = errors.New(…)，跨层传递的「通用错误词汇」
%w 包装fmt.Errorf 的动词：加上下文且保住原错误链
errors.Is沿包装链逐层比对目标错误；判断哨兵的唯一姿势
errors.As沿链找特定类型的错误；S3 处理驱动错误时用
goroutine可并发执行的函数调用。S5 正式讲；明天 D5 的 sync.Mutex 与它有关，照抄即可
Repository 接口「存取数据」这组能力的约定。明天 D5 正式讲并落盘

卡壳时查什么

正文自足，只有两种情况出去查：

  • slice 的共享/扩容还是绕不清：Go Slices: usage and internals（可选，官方博客，配图最好的一张）。
  • error 处理想看点成体系的：errors 包文档（可选，开头的包说明就是官方口径的 %w/Is/As 教程）。

自查口诀：slice 出问题画三要素，map 出问题想 comma-ok，defer 出问题标执行顺序，error 出问题把链打印出来——fmt.Printf("%v\n", err) 会打出整条包装链，%w 有没有断一眼看穿。
