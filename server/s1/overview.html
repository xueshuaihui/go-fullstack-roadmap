S1 · Go 与最小 HTTP

这两周不碰数据库、不碰 Gin、不碰前端。只做一件事：把一个空的仓库变成一个能跑起来、能测、构建恒绿的最小 HTTP 服务，并且把 Go 里最反直觉的四件事（指针、值/引用语义、接口隐式实现、error 是普通值）亲手过一遍。

为什么 S1 只用标准库，不直接上 Gin

Gin 的 c.JSON() 替你做了三件事：设 Content-Type、序列化、写状态码。你没自己写过一遍，就不知道它替你做了什么，出问题时也不知道该往哪看。S1 用 net/http 把这三件事手做一次，S2·D1 平移到 Gin 时你会立刻看出「哦，原来框架只是把这段收进了 Context」。先懂标准库的 handler 签名，再懂框架——这一条对 React 出身的人尤其划算，你已经知道 fetch 和 axios 的关系是同一回事。
