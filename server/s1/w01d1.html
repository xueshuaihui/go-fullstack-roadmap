课前须知：给 React 开发者的四句话

1. 没有 node_modules。依赖装进全局模块缓存（$HOME/go/pkg/mod），项目里只有一个 go.mod + go.sum。go.sum 是锁文件，角色等同 package-lock.json，必须提交。

2. 没有 export。首字母大写就是 public，小写就是 private。作用域单位是 package（目录），不是文件——同一个目录下所有 .go 文件共享一个命名空间，不需要 import 彼此。

3. 没有 babel/tsc 那一层。go build 直接出静态二进制，没有运行时、不需要目标机器装 Go。这就是为什么 S8 的 Dockerfile 能用「多阶段构建 + scratch 镜像」把镜像压到十几 MB。

4. 编译器比 linter 凶。声明了不用的变量、import 了不用的包，编译直接失败，不是 warning。前几天你会被它烦，两周后你会离不开它。

1. 装 Go（约 5 分钟）

系统命令验证
macOSbrew install gogo version → go1.24.x darwin/arm64
Linux官网 tar.gz 解到 /usr/local/go，把 /usr/local/go/bin 加进 PATHgo version
Windows官网 .msi 一路下一步go version

装完顺手确认两件事：

可跑go env GOPATH     # 模块缓存与 go install 的落地目录，默认 ~/go，不用改
go env GO111MODULE # 应该是 on 或空（空即默认 on）。若是 off，执行 go env -w GO111MODULE=on

不要去配 GOPATH/src 那套老目录。网上 2019 年之前的 Go 教程都在讲「代码必须放在 $GOPATH/src/ 下」——那是模块模式之前的规矩，现在完全不需要。你的仓库爱放哪放哪。

编辑器用 VS Code 装官方 Go 扩展，首次打开会提示装 gopls 等工具，全装。然后开两个设置（settings.json）：

片段{
  "go.formatTool": "goimports",
  "editor.formatOnSave": true,
  "editor.codeActionsOnSave": { "source.organizeImports": "explicit" }
}

gofmt 是官方唯一的格式化器，全宇宙 Go 代码风格 100% 一致——没有 prettier vs eslint 之争，也没有 code review 里为缩进吵架这回事。

2. 第一个模块：go.mod 到底是什么

找个临时目录试一次（这个练手模块待会儿就删，不进学习仓）：

可跑mkdir -p /tmp/hello && cd /tmp/hello
go mod init example.com/hello

得到 go.mod：

生成物module example.com/hello

go 1.24

对照着看：

前端Go说明
package.json 的 namemodule 行但这个「名字」同时是 import 路径前缀，见下
dependenciesrequire 块go get 会自动写进来
package-lock.jsongo.sum校验和锁文件，必须提交
node_modules/—没有对应物。依赖在全局缓存 $HOME/go/pkg/mod
engines.nodego 行最低语言版本

最容易搞错的一点：module 后面那个字符串不是包名，是 import 路径前缀。写 module homecube，那么仓库里 pkg/response/ 目录的 import 路径就是 homecube/pkg/response——路径 = 模块名 + 相对目录，跟 npm 那种「包名与目录无关」完全不同。所以模块名一旦定了就别改，改了要全仓 sed。

写个 hello 跑一次：

可跑 · /tmp/hello/main.gopackage main

import "fmt"

func main() {
    fmt.Println("hello")
}
可跑go run .   # 输出 hello。注意是「.」不是「main.go」——见下面「常见坑」

三个关键字先记住，D2/D3 会展开：

  • package main —— 一个目录只能有一个 package 名。叫 main 的包才会被编译成可执行文件，其他名字的包只能被 import。
  • func main() —— 程序入口，无参数无返回值（命令行参数从 os.Args 读）。
  • import "fmt" —— 标准库的格式化输入输出包。导入了不用 = 编译失败。

练完把 /tmp/hello 删掉：rm -rf /tmp/hello。

3. 目标仓库的目录骨架：cmd / internal / pkg

学习仓最终长这样（今天只建目录，不填内容）：

结构<repo>/
├── notes/                      你的每日笔记（概念三行 + 卡壳点），提交进仓
├── server/
│   ├── go.mod                  module homecube
│   ├── cmd/homecube/main.go    程序入口：只做「装配」，不写业务
│   ├── internal/
│   │   ├── homeos/             家庭、成员、邀请、面配置、通知、到期中心、首页
│   │   ├── finance/            账户、分类、流水、预算、周期记账、统计、导出、附件
│   │   └── platform/           配置、日志、DB、鉴权、跨模块接口
│   ├── pkg/response/           统一响应体与错误码（注意：在模块根，不在 internal 下）
│   └── migrations/{homeos,finance}/
├── web/                        前端（agent 产出，S3 才出现）
├── Makefile
└── docker-compose.yml

三个目录的分工，用前端的话说：

目录放什么前端类比
cmd/homecube/只有 main.go。读配置 → 连库 → 装配路由 → 启动。不写任何业务判断src/main.jsx：只负责 createRoot().render(<App/>)
internal/全部业务代码。Go 编译器强制：这个目录下的包只能被本模块 import，外部项目 import 会编译失败没有对应物——这是 Go 独有的、编译器级别的「私有」
pkg/愿意被外部模块复用的东西。本项目只有 response你发布到 npm 的那部分

为什么 response 放 pkg/ 而不是 internal/？因为它是「跨模块共用且未来可能被别的服务抄走」的契约层。反过来，internal/finance 里的账户逻辑绝不该被别的项目 import，所以进 internal/。判断标准就一条：这东西被别的仓库 import 了，我是高兴还是崩溃？高兴 → pkg/，崩溃 → internal/。

internal/homeos 与 internal/finance 之间不许互相直查表：finance 不得 SELECT homeos_*。要跨模块，走 internal/platform 里的接口。这条纪律 S4 建第一个跨模块接口时会正式落地，今天先记住它存在。

4. Makefile：为什么 Go 项目几乎都有它

Go 没有 npm scripts。go build / go test 是原生命令，但真实项目总要拼一堆参数（输出路径、race、覆盖率、lint），于是用 Makefile 收口。

Makefile 的缩进必须是真正的 TAB 字符，不能是空格。用空格会报 missing separator。VS Code 里在这个文件把 editor.insertSpaces 关掉，或者干脆复制下面这段（本站给的是真 TAB）。

可跑cd <你的学习仓根目录>   # 下文一律称它为「仓库根」

步骤 3 · go.mod 与最小 main.go

可跑cd server && go mod init homecube && cd ..
完整 · server/cmd/homecube/main.gopackage main

import "fmt"

func main() {
    fmt.Println("homecube: 骨架已就位，S1·D6 起接 HTTP")
}

这个 main.go 明天就会被替换掉，但今天它必须存在——否则 make build 没有可编译的目标。

步骤 4 · Makefile

完整 · MakefileBIN     := bin/homecube
PKG     := ./server/...

.PHONY: build test run lint clean

build:
	go build -o $(BIN) ./server/cmd/homecube

test:
	cd server && go test -race -count=1 ./...

run: build
	$(BIN)

lint:
	cd server && go vet ./...
	gofmt -l server

clean:
	rm -rf bin

三条要点：

  • .PHONY 声明这些目标不是文件名。不写的话，一旦仓库里出现叫 build 的目录，make build 就会说「已是最新」而什么都不做。
  • go test 带 -race（竞态检测器）与 -count=1（禁用测试结果缓存）。-count=1 很关键：不加它，你改完代码再跑测试可能拿到缓存的旧绿灯。
  • gofmt -l 列出「没格式化」的文件，有输出就说明该跑 gofmt -w。S5 会把这一步接进 CI。

步骤 5 · 验证并提交

可跑 · 验收命令make build          # 必须无输出错误，并生成 bin/homecube
./bin/homecube      # 打印那句骨架已就位
make lint           # gofmt -l 必须无输出
make test           # 今天还没有测试文件，输出 "testing: warning: no tests to run" 属正常

git add -A

提交信息带上卡号（s1d1）。22 周下来你的 git log 就是一份可回溯的学习记录，周日费曼复盘时能直接照着讲。commit 前那一步 git status 不要省——这是唯一能拦住「把口令提交上去」的关口。

常见坑（新手 100% 会踩）

坑现象正确姿势
go run main.go单文件能跑，但一旦拆成多文件就报 undefined: xxx用 go run .（编译整个包）。Go 的编译单位是目录，不是文件
Makefile 用空格缩进Makefile:4: *** missing separator. Stop.必须是真 TAB
声明了不用x declared and not used 编译失败删掉，或写 _ = x 明确弃用。这是特性不是毛病
import 了不用"fmt" imported and not used 编译失败删掉那行 import。开 source.organizeImports 后自动处理
把 go.mod 建在仓库根之后 web/ 里的 node_modules 被 Go 工具链扫到，且 import 路径变成 <repo>/server/pkg/responsego.mod 放 server/ 下，模块名就是干净的 homecube
目录名带中文或空格各种工具链行为诡异全小写、连字符或下划线，不带空格
以为 internal/ 只是个约定—它是编译器强制的。别的项目 import homecube/internal/... 会直接编译失败，报 use of internal package not allowed

今日名词卡

术语一句话解释
module（模块）一组包的版本化集合，由 go.mod 声明。等价于一个 npm 包
package（包）一个目录 = 一个包。同目录下的文件共享命名空间，彼此不需 import
import path模块名 + 相对目录，如 homecube/pkg/response
package main唯一会被编译成可执行文件的包名，且必须配一个 func main()
go.sum依赖校验和锁文件，必须提交。角色等同 package-lock.json
internal/Go 编译器强制的私有目录，外部模块不可 import
gofmt / goimports官方格式化器；goimports 额外自动增删 import 行
go vet官方静态检查，抓「能编译但几乎肯定是 bug」的写法
-race竞态检测器开关。S5 讲并发时它是主角，今天先让它进 Makefile
指针（pointer）存地址的变量：&x 取地址、*T 是类型。D2 详讲
接口（interface）一组方法名的约定，方法齐了就算实现，无需声明。D5 详讲

卡壳时查什么

本站正文自足，不需要先读任何外部资料。只有下面两种情况才出去查：

  • 装不上 Go / 环境变量诡异：查 Go 官方安装文档（可选）。
  • 想弄清 module / package / workspace 三者关系：查 How to Write Go Code（可选，D5 之后读收益更大）。

报错信息看不懂时，先把报错原文整段贴进 notes/，再逐词读。Go 的报错信息在主流语言里算最直白的一档，通常直接告诉你文件、行号和原因——「读错误信息」这项能力从今天的第一个报错开始练。
