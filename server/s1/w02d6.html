周六 · S1 收口与费曼自测

S1 的最后一天，不写新功能。今天的三件事都是「让这两周的投资保值」：写 README（让别人——主要是三个月后的你——能把服务跑起来）、干净检出验证（证明绿灯不是本机环境的错觉）、费曼自测（把 6 条阶段判据逐条讲一遍，讲不下去的地方就是下周第一个要补的）。今天的产物不是代码，是确定性。

今日目标

知识讲义

1. README：仓库的唯一入口

README 回答三个问题，按这个顺序：这是什么 → 怎么跑起来 → 怎么验证它是对的。S8 的终极判据是「一台干净机器照着 README 能复现全套服务」，今天先立骨架，以后每个阶段往里追加一节。写 README 有个残酷的副作用：凡是你写不出步骤的地方，就是你其实没搞懂的地方——「make run 之后 curl 什么来着？」这种空白，今天就该被填掉。

2. 干净检出：抓出两类隐形事故

本机全绿不算数，有两类事故只有干净检出能抓到：

  • 忘了提交：某个文件只活在你的工作区，git status 里一直躺着 untracked。克隆出来的目录里没有它，build 当场红。
  • 依赖了本机环境：手动 export 过的变量、装在本机却没进依赖声明的工具。学习仓现在还小，这两类事故恰好最容易在这个阶段养成习惯。

做法很轻：git clone 到 /tmp 下的临时目录，跑一遍 make 三件套，跑完就删。以后每个阶段的收口日（D12/D6）都做一遍，S8 会升级成 docker compose 全套复现。

3. 费曼自测：合上资料讲一遍

规则只有一条：不看任何资料（包括本站），对着空气或白纸把题目讲一遍。讲得磕磕绊绊 = 没懂，回对应日卡重读，再讲一遍。「读了一遍感觉会了」是最常见的自欺——认出来（recognition）和讲出来（recall）是两种记忆强度，判据只认后者。

今天的 6 道题就是 S1 阶段总览的判据清单，题目与对应日卡：

步骤 1 · README.md

完整 · README.md（仓库根）# HomeCube 服务端（学习期）

模块化单体的服务端学习仓：Go + 标准库 net/http 起步，逐阶段演进。
当前进度：S1（Go 与最小 HTTP）已收口。

## 依赖

- Go 1.24+（`go version` 验证）
- make

## 运行

```
make run          # 构建并启动，监听 :8080
curl -i http://localhost:8080/healthz
# 期望：200 + {"code":0,"message":"ok","data":{"status":"ok"}}
```

## 测试与检查

```
make test         # go test -race -count=1 ./...（在 server/ 下）
make lint         # go vet + gofmt 检查
make build        # 产物在 bin/homecube
```

## 目录

```
server/
├── cmd/homecube/                 装配根：main.go 只做拼装与启动
├── internal/homeos/              家庭模块：handler / model / repository
├── internal/platform/middleware/ 横切：request-id、panic recover
├── pkg/response/                 统一响应体 + 错误码全表 + 哨兵错误
└── playground/                   语法练习沙盒（各自独立 go.mod，不进主模块）
notes/                            每日笔记与阶段自测记录
```

## 路由清单（S1 期间）

| 路由 | 说明 |
|---|---|
| `GET /healthz` | 健康检查，统一响应体 |
| `GET /api/ping` | 教学期练手端点，**S2·D1 删除** |
| `GET /api/ping/{id}` | 教学期：路径参数与查询参数练习，**S2·D1 删除** |
| `POST /api/ping/echo` | 教学期：JSON 严格解码练习，**S2·D1 删除** |
| 其他一切路径 | 404 + code 1001 统一信封 |

## 约定

- 一切响应都是三键信封 `{"code","message","data"}`；业务码见 `server/pkg/response/code.go`
- 解析失败一律 400 + 1004；未知错误一律 500 + 5000
- 提交信息带卡号（如 `feat(s1d8): …`）

README 里的路由清单与「S2·D1 删除」标注不是废话——它就是 D7 那条纪律的书面合同。S2·D1 删 ping 时，README 的路由表同步更新，合同闭环。

常见坑（收口日专属）

坑现象正确姿势
README 照着本机记忆写干净检出跑不通：漏了步骤、写错了端口先干净检出验证，照验证过程写 README，不是照记忆
干净检出红了直接改克隆目录改完忘了同步回本仓，白改克隆目录只用来发现问题；一切修改回本仓做，然后重新克隆验证
自测时偷看资料「看着看着就会讲了」的错觉费曼的规则就是合上资料；讲不下去 → 记卡壳 → 回卡重读 → 再合上再讲
卡壳点不记录，想着「回头补」回头 = never当场写进 notes/s1-review.md，明天复盘照单补课
收口日顺手加新功能「就加一个小接口」→ 收口变开口，半成品过夜收口日只收口。想法记进 notes/ 的「S2 再做」清单
git log 一片 "fix" "update"三个月后完全无法回溯学习线保持 12 天来的习惯：类型 + 卡号 + 干了什么
