请求解析：JSON 解码与查询参数

昨天的 handler 只会「往外写」，今天学会「往里读」：请求体 JSON、路径参数、查询参数三种输入的统一处理姿势，以及一条全站铁律——一切解析失败都是 400 + 1004，绝不 500，绝不泄露内部细节。今日增量属类型 ⑤：把昨天的假数据骨架换成真解析。前端出身的人今天会格外顺手，这就是服务端版的「表单校验」。

今日目标

知识讲义

1. 请求体：json.Decoder 流式解码

r.Body 是一个 io.Reader——「能吐字节的流」。眼熟吗？它也是个接口（D5）：json.Decoder 只要求「会 Read」，不关心字节来自网络、文件还是测试里的一段字符串，这就是 httptest 能塞假 body 的原因。

片段 · 前置：import "encoding/json"；EchoReq 定义见下type EchoReq struct {
    Name string `json:"name"`   // D3 的 struct tag 正式上岗：字段名映射
}

var req EchoReq
dec := json.NewDecoder(r.Body)
dec.DisallowUnknownFields()      // 出现结构体里没有的字段 → 直接报错
if err := dec.Decode(&req); err != nil {   // 注意 &req：Decode 要改你的变量，必须给指针（D2）
    response.Fail(w, http.StatusBadRequest, response.CodeInvalidParam, "参数错误")
    return
}

DisallowUnknownFields 值得单独说：默认行为是未知字段静默忽略——客户端把 name 拼成 nmae，服务端毫无怨言地收到空名字，bug 潜伏到天涯。开严格模式后拼错字段当场 400，契约错误在第一次请求就暴露。本站全期开启，S2 换 Gin 后用 ShouldBindJSON + 严格 binding 延续同一纪律。

解码错误有好几种长相——JSON 语法烂（SyntaxError）、类型不对（字符串填进了 int64）、未知字段——不需要分辨：对外一律「参数错误」。错误细节可以进日志（S5 建），但绝不进响应体。

装请求体的这个 struct 叫 DTO（Data Transfer Object，数据传输对象）：只描述「这次 HTTP 请求长什么样」，与领域模型（D3 的 model）分开。今天两者还几乎一样，S2·D2 会讲为什么必须分开——预告一句：对外契约与内部模型的生命周期不同，表加一列不该逼着所有客户端改请求。

2. 路径参数：PathValue + strconv

片段 · 前置：import "strconv"id, err := strconv.ParseInt(r.PathValue("id"), 10, 64)  // 十进制、int64
if err != nil {
    response.Fail(w, http.StatusBadRequest, response.CodeInvalidParam, "参数错误")
    return
}

PathValue 永远给你 string（D7 说过），数字 id 必须自己转。ParseInt 的三个参数：字符串、进制、位宽。转换失败是客户端的锅（400+1004），不是服务器的锅——把它的 err 原样上抛变 500 是新手高频事故。

3. 查询参数：URL.Query()

片段 · 前置：无// GET /api/ping/123?shout=1&tag=a&tag=b
q := r.URL.Query()            // 类型 url.Values，本质 map[string][]string
shout := q.Get("shout")       // 取第一个值；没传 = ""，不报错
tags := q["tag"]              // 要全部同名值就直接下标取 slice

两个要点：Get 返回空串时你分不清「没传」和「传了空」——要严格区分用 comma-ok：v, ok := q["shout"]（D4 的 map 知识直接复用）；查询参数天然全是 string，数字与布尔一律走 strconv，失败同样 400+1004。

最后一个安全件：http.MaxBytesReader(w, r.Body, n) 能把请求体限制在 n 字节内，防超大 body 打爆内存。今天不用，S6 做附件上传时正式上场——先混个脸熟。

今日增量（在学习仓里落盘）

今天属增量类型 ⑤：把 handler 从假数据换成真解析。教学端点（S2·D1 整个家族删除）升级为：GET /api/ping/{id} 真解析 id 并带查询参数，新增 POST /api/ping/echo 练 JSON 解码。返回的数据本身仍是假数据（教学期允许），但解析路径是真的。

步骤 1 · 替换 handler

完整 · server/cmd/homecube/main.go（覆盖 D7 版本）package main

import (
    "encoding/json"
    "log"
    "net/http"
    "strconv"
    "strings"

    "homecube/pkg/response"
)

func newRouter() http.Handler {
    mux := http.NewServeMux()
    mux.HandleFunc("GET /healthz", handleHealthz)

    // —— 教学期练手端点：S2·D1 换 Gin 时整个家族删除 ——
    mux.HandleFunc("GET /api/ping", handlePing)
    mux.HandleFunc("GET /api/ping/{id}", handlePingByID)
    mux.HandleFunc("POST /api/ping/echo", handlePingEcho)

    mux.HandleFunc("/", handleNotFound)
    return mux
}

func handleHealthz(w http.ResponseWriter, r *http.Request) {
    response.OK(w, map[string]string{"status": "ok"})
}

func handlePing(w http.ResponseWriter, r *http.Request) {
    response.OK(w, map[string]any{"pong": true})
}

// handlePingByID 真解析路径参数与查询参数；返回体仍是教学假数据。
func handlePingByID(w http.ResponseWriter, r *http.Request) {
    id, err := strconv.ParseInt(r.PathValue("id"), 10, 64)
    if err != nil {
        response.Fail(w, http.StatusBadRequest, response.CodeInvalidParam, "参数错误")
        return
    }
    name := "假数据家庭"
    if r.URL.Query().Get("shout") == "1" {
        name = strings.ToUpper(name) // 中文无大小写，演示查询参数生效即可
    }
    response.OK(w, map[string]any{"id": id, "name": name})
}

// EchoReq 是 POST /api/ping/echo 的请求 DTO。
type EchoReq struct {
    Name string `json:"name"`
}

// handlePingEcho 真解析 JSON 请求体：语法烂 / 类型错 / 未知字段，一律 400 + 1004。
func handlePingEcho(w http.ResponseWriter, r *http.Request) {
    var req EchoReq
    dec := json.NewDecoder(r.Body)
    dec.DisallowUnknownFields()
    if err := dec.Decode(&req); err != nil {
        response.Fail(w, http.StatusBadRequest, response.CodeInvalidParam, "参数错误")
        return
    }
    if req.Name == "" {
        response.Fail(w, http.StatusBadRequest, response.CodeInvalidParam, "参数错误")
        return
    }
    response.OK(w, map[string]string{"message": "hello, " + req.Name})
}

handleNotFound 与 main 与 D7 相同，原样保留。

注意路由表里的一个细节："POST /api/ping/echo" 与 "GET /api/ping/{id}" 路径重叠但方法不同，互不打架；若都注册成 GET，Mux 会因「echo 与 {id} 在同一位置冲突」直接 panic——模式冲突是启动期就爆的，不会潜伏到运行时。这算 Go 1.22 路由少有的「大声失败」，是好事。

步骤 2 · 测试换成真解析断言

片段 · main_test.go 新增（前置：import "strings" 与 "net/http/httptest" 已在）func TestParsing(t *testing.T) {
    tests := []struct {
        name       string
        method     string
        path       string
        body       string
        wantStatus int
        wantFrag   string
    }{
        {"路径参数是数字", "GET", "/api/ping/123", "", 200, `"id":123`},
        {"路径参数不是数字", "GET", "/api/ping/abc", "", 400, `"code":1004`},
        {"查询参数 shout 生效", "GET", "/api/ping/1?shout=1", "", 200, "假数据家庭"},
        {"JSON 合法", "POST", "/api/ping/echo", `{"name":"shuai"}`, 200, "hello, shuai"},
        {"JSON 语法烂", "POST", "/api/ping/echo", `{"name":`, 400, `"code":1004`},
        {"未知字段也拒绝", "POST", "/api/ping/echo", `{"nmae":"shuai"}`, 400, `"code":1004`},
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            w := httptest.NewRecorder()
            req := httptest.NewRequest(tt.method, tt.path, strings.NewReader(tt.body))
            newRouter().ServeHTTP(w, req)
            if w.Code != tt.wantStatus {
                t.Fatalf("状态码 = %d, want %d（body: %s）", w.Code, tt.wantStatus, w.Body.String())
            }
            if !strings.Contains(w.Body.String(), tt.wantFrag) {
                t.Fatalf("body = %s, 应包含 %s", w.Body.String(), tt.wantFrag)
            }
        })
    }
}

最后一条用例故意把 name 拼成 nmae——它就是 DisallowUnknownFields 要抓的现行犯。D7 的 TestRoutes 里 /api/ping/hello 那条用例今天会失败（hello 转不成数字了），把它改成上表的样子或直接删掉——测试跟着契约走，契约变了测试就要变。

常见坑（新手 100% 会踩）

坑现象正确姿势
Decode(req) 少了 &编译失败 non-pointer type，算运气好的Decode 要写入你的变量，必须给指针（D2 的世界观）
把解析 err 原样上抛客户端拼错 JSON，你回了 500解析失败是 4xx 的世界：一律 400 + 1004，细节进日志不进响应
不开 DisallowUnknownFields字段名拼错静默变零值，bug 潜伏严格模式常开；本站全期如此
以为 json 匹配区分大小写{"NAME":"x"} 居然也能解进 json:"name"标准库对 tag 的匹配不区分大小写。知道即可，别依赖
Query().Get 分不清「没传」和「传了空」可选参数的默认值逻辑出错要严格区分时 comma-ok：_, ok := q["shout"]
手动 r.Body.Close()多此一举服务端 handler 里 Body 由 net/http 负责关闭；要 defer Close 的是客户端请求（S5 调上游时讲）
忘了「同位置模式冲突会 panic」服务启动即崩崩在启动期是好事；看报错里的两条冲突模式，改一条

今日名词卡

术语一句话解释
io.Reader「会吐字节的流」接口；网络、文件、字符串都能是它。接口思想（D5）的标准库范例
json.Decoder从流里解出 JSON 到目标变量；配 DisallowUnknownFields 使用
DTO描述请求/响应形状的 struct，与领域模型分开。S2·D2 讲为什么
url.Values查询参数的类型，本质 map[string][]string
strconv字符串与数字互转：ParseInt / Atoi / FormatInt
400 + 1004一切「请求本身不对」的统一出口：语法、类型、未知字段、必填缺失
MaxBytesReader限制请求体大小防打爆内存；S6 附件上传时上场
教学期端点/api/ping* 家族今天扩编，S2·D1 仍是一个不留全删

卡壳时查什么

正文自足，只有两种情况出去查：

  • JSON 包的边角能力（嵌套、json.RawMessage 延迟解析）：encoding/json 文档（可选，S2 之前用不到边角）。
  • strconv 家族函数选哪个：strconv 文档（可选，记住 ParseInt 就够用本周）。

解析类 bug 的调试铁律：先用 curl 原样重放，再看服务端把它解成了什么。十有八九是三种之一：Content-Type 没带、JSON 本身有语法错、字段名与 tag 对不上。把 err 原文打出来读——encoding/json 的错误信息会直接告诉你第几个字节出的事。
