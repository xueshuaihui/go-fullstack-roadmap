Gin 换入：路由、路由分组与 NoRoute

S2 开工第一天，干三件事：把 Gin 请进来（/healthz 原样平移，你会看到 S1 手写的每块零件在框架里的对应物）、立好路由分域（/api/finance 分组登场，为周六的 6 条接口铺路）、执行删除合同（S1·D7 注册 /api/ping 时就写明「S2·D1 整个家族一并删除」——今天是这条纪律的第一次执行）。

今日目标

知识讲义

1. Gin 替你做了什么：逐件对账

S1 用标准库手写过一遍的东西，Gin 全有对应物。对完这张账，你会发现框架没有魔法，只有「替你写好的样板」：

S1 手写的Gin 的对应物说明
http.ServeMux + "GET /path" 模式gin.Engine 的路由树Gin 用 radix 树存路径，参数路由（:id）是一等公民，D6 就用它
http.HandlerFunc 适配器gin.HandlerFunc同一个把戏：函数类型 + 满足接口。只是签名从 (w, r) 换成 (c *gin.Context)
response 包的「笔顺三步」（Header→WriteHeader→Write）c.JSON(status, obj)一个调用替你做完三步 + 序列化。但全站仍然只走 pkg/response 的四个出口，信封契约不变
r.PathValue("id")c.Param("id")取路径参数，返回 string
标准库中间件 func(http.Handler) http.Handlerengine.Use(middleware...)洋葱模型一模一样，D3 专门对照

gin.Engine 自己就实现了 ServeHTTP(w, r)——也就是说它是一个 http.Handler（S1·D5：方法齐了就算实现）。这带来一个漂亮的过渡：今天 S1 的两个标准库中间件还能原样包在 engine 外面用，D3 换成 Gin 原生版之前，仓库全程绿。*gin.Context 则是把 w 和 r 打包再加一层随身背包（c.Set/c.Get）的「请求上下文」。

2. gin.New() 还是 gin.Default()：我们选 New

gin.Default() = gin.New() + 内置 Logger + 内置 Recovery 两个中间件。听起来省事，但我们不选它，理由有两条，都关乎「信封必须统一」：

  • 内置 Recovery 兜住 panic 后返回的是裸文本 500——三键信封没了，客户端解析直接炸。D3 我们写自己的 Recovery：500 + 5000 + 堆栈进日志。
  • 内置 Logger 的格式不受我们控制，也没有 request-id。D3 写自己的 AccessLog。

所以本站纪律：gin.New() 起步，中间件全部自己装配。框架送的默认值，要么理解后明确采用，要么明确拒绝——不「因为默认所以默认」。

3. 路由分域与分组：/api/finance 登场

全站路由只有两个业务域：/api/homeos/* 与 /api/finance/*，外加不带前缀的 GET /healthz。没有版本号段——URL 里出现 /api/v1 属于违规，契约的稳定性靠三键信封与错误码表保证，不靠 URL 里的数字。

Gin 的分组让分域变成结构而不是字符串前缀：

片段 · 前置：import "github.com/gin-gonic/gin"finance := engine.Group("/api/finance")
finance.POST("/categories", h)      // 实际路径 = /api/finance/categories
finance.GET("/categories", h)       // 组内只写「组前缀之后」的部分

分组还有一个 S4 才兑现的大用处：中间件可以只挂在某个组上——将来鉴权中间件挂 /api 域，/healthz 不用带 token 也能探活。今天先把组的骨架立起来（D2 往里注册第一条真路由）。

4. NoRoute：把 404 也收进信封

S1 里我们用 mux.HandleFunc("/", handler.NotFound) 兜底做过这件事（404 + 1001）。Gin 的对应物是 engine.NoRoute：所有未命中的请求进这里。不注册 NoRoute，Gin 会返回它自己的裸 404 文本——「任何响应都是三键信封」这条全站合同就破了。另有一个差异要知道：标准库 ServeMux 对「路径对了方法不对」自动回 405，Gin 默认也回 404 进 NoRoute；我们不开 HandleMethodNotAllowed（开了会返回裸 405 文本，同样破坏信封）。

5. 反例③：注册了但没用的假入口，今天清账

S1·D7 注册 /api/ping 家族时立过书面合同（README 路由表里标注「S2·D1 删除」）。今天兑现：GET /api/ping、GET /api/ping/{id}、POST /api/ping/echo 连同 handler 代码与测试用例整体删除。这就是本项目明令避开的反例③「注册了但没实现/没用了的假入口」的纪律：路由表即合同，注册过的路由要么有真实现、要么被删干净，不许留「看起来能访问」的死入口骗用户和测试。

今日增量（在学习仓里落盘）

今天属增量类型 ②：路由平移与收口——/healthz 与 NoRoute 上 Gin，response 包签名换 *gin.Context，/api/ping 家族删除。收工时 make build / make test 必须绿。

步骤 2 · response 包换签名

S1·D6 预告过这一刻：四个出口函数的第一个参数从 http.ResponseWriter 换成 *gin.Context，函数名与语义全期不变。这就是把响应层收进 pkg/response 的回报：换框架只改这一个文件。

完整 · server/pkg/response/response.go（覆盖 S1·D6 版本；code.go 与 errors.go 不动）package response

import (
    "net/http"

    "github.com/gin-gonic/gin"
)

// Body 是全站唯一响应信封。任何接口、任何状态码，Body 都是这三个键。
type Body struct {
    Code    int    `json:"code"`
    Message string `json:"message"`
    Data    any    `json:"data"`
}

// write 全站唯一出口。c.JSON 替我们做完 S1 手写的「笔顺三步」。
func write(c *gin.Context, httpStatus int, b Body) {
    c.JSON(httpStatus, b)
}

// OK 成功：HTTP 200 + code 0。
func OK(c *gin.Context, data any) {
    write(c, http.StatusOK, Body{Code: CodeOK, Message: "ok", Data: data})
}

// Created 创建成功：HTTP 201 + code 0。本周六的 POST /categories 就用它。
func Created(c *gin.Context, data any) {
    write(c, http.StatusCreated, Body{Code: CodeOK, Message: "ok", Data: data})
}

// Fail 明确知道码和状态时用。
func Fail(c *gin.Context, httpStatus, code int, msg string) {
    write(c, httpStatus, Body{Code: code, Message: msg})
}

// FailErr 拿着 error 时用：CodeOf 认哨兵 → 码，HTTPStatus 码 → 状态。
// 认不出的错误一律 5000/500——内部细节绝不外泄。
func FailErr(c *gin.Context, err error) {
    code := CodeOf(err)
    Fail(c, HTTPStatus(code), code, err.Error())
}

pkg/response 自己的测试也要跟着换：Gin 提供了 gin.CreateTestContext，把 httptest.NewRecorder 包成一个可测的 *gin.Context：

片段 · response_test.go 里的改法（前置：import "github.com/gin-gonic/gin" 与 "net/http/httptest"）w := httptest.NewRecorder()
c, _ := gin.CreateTestContext(w)   // 造一个写向 w 的 *gin.Context
response.OK(c, map[string]string{"status": "ok"})
// 断言照旧：w.Code、w.Header()、w.Body.String()

步骤 3 · main.go 换 engine，删 ping 家族

删除 server/internal/homeos/handler/ 整个目录（Healthz、Ping、PingByID、PingEcho、NotFound 与它们的测试都是标准库签名，全部作废）；routes_test.go 里涉及 /api/ping 的用例一并删除。/healthz 的 handler 直接内联在装配根里——它不属于任何业务模块。

完整 · server/cmd/homecube/main.go（覆盖 S1·D12 版本）package main

import (
    "log"
    "net/http"

    "github.com/gin-gonic/gin"

    "homecube/internal/platform/middleware"
    "homecube/pkg/response"
)

// newRouter 装配全部路由并返回 http.Handler（gin.Engine 自己就是 http.Handler）。
func newRouter() http.Handler {
    engine := gin.New() // 不用 Default()：Logger/Recovery 都要自己装配（D3）

    engine.GET("/healthz", func(c *gin.Context) {
        response.OK(c, map[string]string{"status": "ok"})
    })

    // 业务域分组今天先立骨架，D2 往里注册第一条路由
    _ = engine.Group("/api/finance")

    // 未命中任何路由：404 + 1001 统一信封
    engine.NoRoute(func(c *gin.Context) {
        response.Fail(c, http.StatusNotFound, response.CodeNotFound, "资源不存在")
    })

    // 过渡期：S1 的标准库中间件把 engine 当普通 http.Handler 包住（D3 换 Gin 原生版）
    return middleware.WithRequestID(middleware.WithRecover(engine))
}

func main() {
    addr := ":8080" // 先沿用写死；D11 起从 env 的 PORT 读
    log.Println("homecube listening on", addr)
    if err := http.ListenAndServe(addr, newRouter()); err != nil {
        log.Fatal(err)
    }
}

main_test.go 的 TestHealthz 一行不用改：它测的是 newRouter() 这个 http.Handler，engine 换心脏对它透明——这就是 S1 坚持把测试架在 newRouter() 上的回报。唯一要动的是 S1·D9 那条断言完整 body 字符串的用例：Gin 的 c.JSON 会在末尾补一个换行符，精确匹配前照旧 strings.TrimRight(body, "\n") 即可。

卡壳时查什么

正文自足，只有两种情况出去查：

  • Gin 的 API 细节：gin 包文档（可选，查 Engine/Context 的方法清单）。
  • go get 报网络错：先确认 go env GOPROXY 不为 off；国内网络可设为模块代理（可选）。

平移类改动的调试铁律：先让老测试告诉你哪里断了。make test 红了看第一个失败点——今天大概率是 response 包的旧测试还在用 http.ResponseWriter 签名，逐个换成 gin.CreateTestContext 即可。
