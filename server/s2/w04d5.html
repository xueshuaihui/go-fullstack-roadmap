配置加载雏形：env 读 PORT 与 GIN_MODE

D10 把错误契约收了口，今天给第三类「随环境变的东西」安家：运行配置。还记得 S2·D1 换入 Gin 那天，main 里那句 addr := ":8080" 旁边的注释吗——「先沿用写死；D11 起从 env 的 PORT 读」。今天兑现它。新建 internal/platform/config 雏形包，教两个变量：PORT 与 GIN_MODE 的读法、默认值与非法值处理。为什么只是「雏形」？因为完整的 config——DB_* 六个变量拼 Postgres DSN、连接池四参数、AUTO_MIGRATE 门禁——要到 S3·D11 才一次定稿；今天只把「env 读取」这件事收进一个包，并把读法立成后面一路沿用的形状。

知识讲义

1. 端口和运行模式，为什么轮不到代码说了算

你的 homecube 二进制从 S2 起就只有一个，可它要活的环境不止一个：

环境端口想是谁的Gin 模式想是谁的
本机日常开发8080（习惯了）debug：路由注册、警告都打出来，方便对着看
本机 8080 被别人占了临时换 8081——凭什么要重新编译？debug
将来容器里（S3 的 compose、S8 的部署）容器内监听、外部映射，两边不必相同release：不该有 debug 横幅与多余警告
CI / 测试随机端口，免得并行任务撞车test（S2·D3 的 gin.TestMode 注释就写着「D11 起由 GIN_MODE 统一管理」）

写死 ":8080" 的债：每换一个环境就改一次代码、重编一次、而且这份改动会进 git——你临时换的 8081 会跟着提交推上去，第二天队友的 8080 就神秘失踪。行业把这笔账算了几十年，结论成文（12-factor 的第一条之一）：配置存在环境变量里，代码里不写死。代码负责「怎么跑」，环境负责「在哪跑、用什么值跑」。今天 config 包就是这条纪律在本仓的最小实现。

2. os.Getenv 的三副面孔：空串，不是错误

读环境变量的标准库入口是 os.Getenv(name)。新手对它最大的误会：以为「没设置会返回错误」。不会——它返回空字符串。没设置、设置了个空值，在 Getenv 这里同一个结果（要分辨得用双值形式 v, ok := os.LookupEnv(name)，今天用不上，先知道有这东西）。所以正确的读法不是「读—判错」，而是三段式：

片段 · 读 env 的标准三段式（本页主角 Load() 的骨架）port := os.Getenv("PORT")      // ① 读取：没设置时是 ""，不报错
if port == "" {              // ② 空 → 默认值：不设也能起
    port = "8080"
}
if n, err := strconv.Atoi(port); err != nil || n < 1 || n > 65535 {
    return error              // ③ 非空 → 必须合法：非法就拒绝，不静默回落
}

第③步的「不回落」是今天的核心判据：PORT=abc 是拼错，不是「没设置」——把它悄悄当 8080 跑起来，你要到 curl 打错端口的那一刻才发现拼错。配置错误最便宜的暴露时刻是启动那一秒（fail fast）。

3. 两个变量的读法与校验

变量含义不设时的默认合法值非法怎么办
PORTHTTP 监听端口80801–65535 的整数（strconv.Atoi 之外还要范围闸：0、99999 是合法整数、非法端口）Load() 返回错误，main log.Fatalf 拒启
GIN_MODEGin 运行模式debugdebug / release / test 三个值，一字不差同上——realse 这种拼错不配被静默当 debug 跑半年

两个顺带说清：GIN_MODE 只此三值——debug 打路由注册与开发警告，release 静音，test 给测试环境的静音档（S2·D3 你手动调过 gin.SetMode(gin.TestMode)，今天起这个决定权交给 env）。不要躺平让框架自己读：Gin 内部确实也会看 GIN_MODE，但本站的纪律是 config 是唯一读取点，main 显式 gin.SetMode 把它钉死——非法值拦在我们自己手里，错误信息写清变量名和实际值。

4. 为什么这一步只做「雏形」

今天包很小：一个 struct、一个 Load()、两个变量。故意的——完整的 config 要等数据库登场才有内容可做：

能力今天（S2·D11 雏形）定稿（S3·D11）
HTTP 侧PORT、GIN_MODE 读取 + 默认 + 校验沿用，一行不改
DB 侧不接——S2 存储还是内存 map，DB 变量此刻无处可连DB_HOST/DB_PORT/DB_USER/DB_PASS/DB_NAME/DB_SSLMODE 必填校验 + 拼 Postgres DSN，全站唯一拼装点（口径见 S3·D1 的 .env 两段）
连接池不存在四参数（MaxOpen/MaxIdle/Lifetime/IdleTime）一次讲透
门禁不存在AUTO_MIGRATE 读到 true 直接拒绝启动

雏形不是「凑合」，是先把读法立对：env → 默认 → 校验 → 返回 struct；调用方拿值，不碰 os 包。这套骨架从今天起到 S4 加 JWT_SECRET、S6 加 UPLOAD_DIR、S7 加 CORS_ORIGIN，全程只加字段、不改形状。另一个动机和 D10 完全同款：收口——错误翻译只有一个出口 FailErr，环境变量也只有一个读取点 config.Load()；散落的 os.Getenv 就是散落的翻译点，迟早有一处拼错、一处漏校验。config 住在 internal/platform/（S2·D4 立的规矩：横切住户不属于任何业务模块），main 从它取端口，业务包永远不知道 env 这回事。

今日增量（在学习仓里落盘）

今天属增量类型 ①+②：新建 internal/platform/config 雏形包（①：Config struct + Load 的默认值与非法值处理），main 从它取监听地址与 Gin 模式、删除写死的 :8080（②：装配段的接线改造）。HTTP 契约零变化——分类 6 条与 /healthz 一字不动。收工时 make build / make test 仍绿。

步骤 1 · 雏形包落盘

完整 · server/internal/platform/config/config.gopackage config

import (
    "fmt"
    "os"
    "strconv"
)

// Config 应用运行配置——S2·D11 雏形版：只 HTTP 侧两个变量。
// S3·D11 起定稿：补 DB_* 拼 DSN、连接池四参数、AUTO_MIGRATE 门禁。
// 今天立的读法（读取 → 默认 → 校验）一路用到毕业，之后只加字段不改形状。
type Config struct {
    Port    string // "PORT"：监听端口，默认 "8080"
    GinMode string // "GIN_MODE"：debug / release / test，默认 "debug"
}

// Load 全站唯一的环境变量读取点。
// 非法值返回 error 而不是静默回落默认：配置错误最便宜的暴露时刻是启动那一秒。
// 返回 error 而非 panic：怎么死由调用方（main）决定；测试也能拿 error 断言非法路径。
func Load() (Config, error) {
    cfg := Config{
        Port:    os.Getenv("PORT"),
        GinMode: os.Getenv("GIN_MODE"),
    }

    // —— PORT：空 = 用默认；一旦有值，必须是合法端口号 ——
    if cfg.Port == "" {
        cfg.Port = "8080"
    }
    if n, err := strconv.Atoi(cfg.Port); err != nil || n < 1 || n > 65535 {
        return Config{}, fmt.Errorf("config: 非法的 PORT %q：必须是 1-65535 的整数", cfg.Port)
    }

    // —— GIN_MODE：空 = 用默认；只认三个值，拼错不回落 ——
    if cfg.GinMode == "" {
        cfg.GinMode = "debug"
    }
    switch cfg.GinMode {
    case "debug", "release", "test":
    default:
        return Config{}, fmt.Errorf("config: 非法的 GIN_MODE %q：只允许 debug/release/test", cfg.GinMode)
    }

    return cfg, nil
}

// Addr 拼监听地址——main 里从此不再手写 ":"+port。
func (c Config) Addr() string { return ":" + c.Port }

错误信息里「变量名 + 实际值」两个都要有（%q 把空串、空格都显形）。这和 D10 的 %w 包装把上下文写足是同一种手感：报错是给人读的线索，不是给人添的谜。

步骤 2 · main 换血：端口与模式从 config 取

片段 · server/cmd/homecube/main.go 的 main 函数（改后完整替换；newRouter 不动）func main() {
    cfg, err := config.Load()
    if err != nil {
        log.Fatalf("拒绝启动: %v", err) // fail fast：配置不对不营业
    }

    // 模式在构造路由之前钉死（gin.SetMode 只影响之后创建的 engine）。
    // Gin 框架自己也会读 GIN_MODE，但本站不躺平：config 是唯一读取点，这里显式落定。
    switch cfg.GinMode {
    case "release": gin.SetMode(gin.ReleaseMode)
    case "test":    gin.SetMode(gin.TestMode)
    default:        gin.SetMode(gin.DebugMode)
    }

    log.Println("homecube listening on", cfg.Addr(), "mode", cfg.GinMode)
    if err := http.ListenAndServe(cfg.Addr(), newRouter()); err != nil {
        log.Fatal(err)
    }
}

对照改前：addr := ":8080" 那行连同「D11 起从 env 读」的注释一起退役——欠了十天的注释今天还清。main 里 os.Getenv 零出现、字面端口零出现；将来要加新环境变量，先在 config 加字段、加校验，调用处永远只读 cfg.X。

常见坑（新手 100% 会踩）

坑现象正确姿势
以为 Getenv 没设置会报错兴冲冲写 v, err := os.Getenv(...)——编译都过不了；或等 err 等到天荒地老它只返回空串。用 == "" 判「没给」，给默认；要分辨「没设 vs 设为空」才知道 LookupEnv
空串直接拼 ":"+portListenAndServe(":") 报 missing port in address——连默认端口都不剩，服务起不来还看不懂为什么先补默认再拼；拼地址只发生在 cfg.Addr() 一处
把密钥/口令写进代码「反正本地跑」连库口令、签名密钥进了源码，跟着 commit 推上仓——白纸黑字永久公开密钥永远只从 env 进代码，不落盘不入库；今天 PORT 是开胃菜，S3 的 DB_PASS、S4 的 JWT_SECRET 按同一纪律走（.env 由 .gitignore 拦着）
用 init() 读配置存全局变量init 在包 import 时就跑完：测试里 t.Setenv 换值再调一次 Load 的机会都没有，默认值/非法值路径全测不了配置是 Load() 的返回值不是全局变量；谁要用谁拿，测试随时「重当一次启动现场」
非法 GIN_MODE 静默回落 debugrealse 拼错，服务顶着 debug 横幅跑半年，路由与警告全在外泄非法 = 返回错误拒绝启动，不回落（与时间窗非法 1007 不回落同一个脾气：错误输入不配被惯成默认值）
PORT 校验只看 Atoi 的 errPORT=0、PORT=99999 是合法整数、非法端口，照样放行两道闸：能转整数 && 在 1–65535 内
把 config 当百宝箱，随手再加 os.Getenv 散落各处三个包各自读同一个变量、默认值抄三遍、校验只有一处有——散落的读取点新变量先进 config：加字段、加校验、加测试；调用处只读 cfg.X。收口思路与 D10「错误出口只有 FailErr」同款

今日名词卡

术语一句话解释
运行配置（env 配置）从代码外置出来、随环境而变的值；代码管「怎么跑」，环境管「在哪跑、用什么值」
os.Getenv按名读环境变量；未设置返回空串而非错误——「读取 → 默认 → 校验」三段式的起点
默认值不设时照样跑的值（8080、debug）；必须显式写在 Load 里，不许藏在调用处
fail fast配置非法就在启动那一秒拒绝——比带着错端口、错模式跑到事故现场再暴露便宜一百倍
GIN_MODEGin 运行模式三档：debug（打路由与警告）/ release（静音）/ test（测试静音档）
雏形 vs 定稿今天两变量一包叫雏形；S3·D11 补 DB_* 拼 DSN、连接池、AUTO_MIGRATE 叫定稿——读法不变，只长字段
唯一读取点全仓只有 config 碰 os.Getenv；与「错误翻译只有 FailErr 一个出口」同构的收口纪律
注入配置以 Load() 返回值交给消费方，不是全局变量；测试可以 t.Setenv 后重新 Load
横切住户不属于任何业务模块的公共设施，住 internal/platform/——config 是继 middleware 之后的第二位
