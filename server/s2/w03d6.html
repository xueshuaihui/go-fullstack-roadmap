周六 · 用「分类」6 条把三层走通

本周的大日子：72 条接口里的第一批业务接口——B4「分类」6 条——今天在三层上全部真实现。没有新世界观，只有合体：D1 的 Gin 与路由分组、D2 的绑定与 1004、D3 的三个中间件、D4 的模型与仓储接口、D5 的 DTO 与白名单转换，今天串成一条完整能力。存储是内存 map（重启即空，S3 换 Postgres），但三层的位置、依赖方向、错误词汇今天一次定死——S3 换存储时你会发现只需要动一个文件。

今日目标

知识讲义

1. 六条接口的全景表

方法与路径干什么成功今天的失败分支
GET /api/finance/categories分类列表（含已停用，带 archived 标记），服务端按 (Sort, ID) 排好序返回200 + {"list":[…]}—
POST /api/finance/categories创建分类（名称/图标/收支类型/父级）201 + 新分类绑定失败 400+1004；父级不存在 404+1001
PUT /api/finance/categories/:id编辑分类200 + 改后分类（version 已 +1）同上 + :id 非法 400+1004
PUT /api/finance/categories/sort自定义排序：按给定 id 顺序重排200 + data:null任一 id 不存在 404+1001
PUT /api/finance/categories/:id/archive停用200 + archived:true不存在 404+1001
POST /api/finance/categories/:id/restore恢复200 + archived:false不存在 404+1001

三处「今天先浅、下周加深」的地方，微增量的节奏所在：树形组装与父级三规则是 D7 的事（今天列表先返回平铺、创建只查父级存在）；停用约束（有未停用子级不可停用，1010）是 D8 的事；PUT 的 version 校验（1009）是 D10 的事。今天的目标是「六条全通、三层就位」，不是「规则全齐」。

列表的信封：分类是「非分页小集合」，响应 data 就是 {"list":[…]}，不带 next_cursor / has_more——游标分页是给流水这类长列表的，S3 随流水列表登场。排序由服务端返回顺序表达，客户端不自己排。

2. 存储：map + Mutex，以及它教会你的两件事

内存实现就是 S1·D5 MemoryFamilyRepo 模式的放大版：一个 map[int64]model.Category 存行、一个自增 seq 发 ID、一把 sync.Mutex 站岗（照抄即可，S5 正式讲并发时回头审视它）。两件值得记住的事：

  • map 遍历是无序的（S1·D4 讲过）——所以 repo 的 List 不承诺顺序，排序是 service 的职责：显式 sort.Slice 按 (Sort, ID) 排。不排序的话，同一份数据每次请求的顺序都可能不同，测试会时红时绿。
  • 重启即空是特性：内存存储本来就没承诺持久。数据「丢了」不是 bug，S3 接 Postgres 才是持久化的开始。

3. 装配根：依赖注入就一行

main.go 是全站唯一知道「具体实现是谁」的地方：repo := repository.NewMemoryCategoryRepo() → svc := service.NewCategoryService(repo) → h := handler.NewCategoryHandler(svc, familyID) → h.Register(finance组)。service 收到的是接口，不是具体类型——这就是「注入」：从外面递进去，而不是 service 自己 new。S3 换 Postgres 时改的只有装配根的第一行。测试也靠它：给 service 塞一个内存 repo，测规则不碰 HTTP。

4. familyID：教学期的常量，S4 的登录态

今天的 handler 持有一个 familyID 字段，装配时给常量 1。看起来像摆设，其实是把 S4 的插座先埋进墙里：repo 每个方法都收 familyID、每条查询都按它过滤——S4 建鉴权中间件后，这个值的来源从常量换成 token 里的家庭 id，三层代码一行不改。「每条查询必带家庭」的纪律从有分类的第一天就成立。

5. 一个将来会兑现的词：client_request_id

真实系统的写请求（今天的 POST/PUT）会带一个客户端生成的幂等键 client_request_id：网络重试时服务端认出「这单处理过了」，不会记两笔。S4 建幂等表时正式讲，今天只记住这个词——将来在流水接口看到它，不要觉得陌生。

今日增量（在学习仓里落盘）

今天是周六大增量：把本周 5 个微增量串成一条完整能力。五个文件：repo 内存实现 → service → handler → main.go 装配 → 场景测试。顺序就是依赖方向的反向：从最底层写起，每写完一层 make build 一次。

import (
    "fmt"
    "sync"
    "time"

    "homecube/internal/finance/model"
    "homecube/pkg/response"
)

// MemoryCategoryRepo 是 CategoryRepository 的内存实现：一个 map + 一把锁。
// 含 sync.Mutex → 整个 struct 必须按指针使用（S1·D3 的军规）。
type MemoryCategoryRepo struct {
    mu   sync.Mutex
    seq  int64
    rows map[int64]model.Category
}

// 编译期检查：实现不满足接口，这一行直接报错（S1·D5 的老把戏）。
var _ CategoryRepository = (*MemoryCategoryRepo)(nil)

func NewMemoryCategoryRepo() *MemoryCategoryRepo {
    return &MemoryCategoryRepo{rows: make(map[int64]model.Category)}
}

// List 返回该家庭全部分类。顺序不承诺——map 遍历无序，排序是 service 的职责。
func (r *MemoryCategoryRepo) List(familyID int64) ([]model.Category, error) {
    r.mu.Lock()
    defer r.mu.Unlock()
    out := make([]model.Category, 0, len(r.rows))
    for _, c := range r.rows {
        if c.FamilyID == familyID {
            out = append(out, c)
        }
    }
    return out, nil
}

// Get 查无或不属于该家庭，一律 ErrNotFound——「不存在」与「不是你的」同形。
func (r *MemoryCategoryRepo) Get(familyID, id int64) (model.Category, error) {
    r.mu.Lock()
    defer r.mu.Unlock()
    c, ok := r.rows[id]
    if !ok || c.FamilyID != familyID {
        return model.Category{}, fmt.Errorf("get category %d: %w", id, response.ErrNotFound)
    }
    return c, nil
}

// Create 分配 ID、置 Version=1、盖时间戳。
func (r *MemoryCategoryRepo) Create(c *model.Category) error {
    r.mu.Lock()
    defer r.mu.Unlock()
    r.seq++
    c.ID = r.seq
    c.Version = 1
    c.CreatedAt = time.Now()
    c.UpdatedAt = c.CreatedAt
    r.rows[c.ID] = *c
    return nil
}

// Update 整行替换：Version 在旧值上 +1，CreatedAt 保留，UpdatedAt 刷新。
func (r *MemoryCategoryRepo) Update(c model.Category) error {
    r.mu.Lock()
    defer r.mu.Unlock()
    old, ok := r.rows[c.ID]
    if !ok || old.FamilyID != c.FamilyID {
        return fmt.Errorf("update category %d: %w", c.ID, response.ErrNotFound)
    }
    c.Version = old.Version + 1
    c.CreatedAt = old.CreatedAt
    c.UpdatedAt = time.Now()
    r.rows[c.ID] = c
    return nil
}

步骤 2 · service：规则层

完整 · server/internal/finance/service/service.gopackage service

import (
    "sort"

    "homecube/internal/finance/model"
    "homecube/internal/finance/repository"
)

// CategoryService 只持有接口，不持有具体实现——S3 换 Postgres 的接缝。
// 注意 import 清单：没有 gin，也没有 net/http。这一层不知道 HTTP 为何物。
type CategoryService struct {
    repo repository.CategoryRepository
}

func NewCategoryService(r repository.CategoryRepository) *CategoryService {
    return &CategoryService{repo: r}
}

// List 返回全部分类（含已停用），按 (Sort, ID) 升序——顺序由服务端说了算。
func (s *CategoryService) List(familyID int64) ([]model.Category, error) {
    cs, err := s.repo.List(familyID)
    if err != nil {
        return nil, err
    }
    sort.Slice(cs, func(i, j int) bool {
        if cs[i].Sort != cs[j].Sort {
            return cs[i].Sort < cs[j].Sort
        }
        return cs[i].ID < cs[j].ID
    })
    return cs, nil
}

// Create 今天的规则只有一条：带父级时父级必须存在。
// 「父级必须是一级、收支与父级一致」两条规则 D7 补——微增量的节奏。
func (s *CategoryService) Create(familyID int64, c model.Category) (model.Category, error) {
    c.FamilyID = familyID
    if c.ParentID != 0 {
        if _, err := s.repo.Get(familyID, c.ParentID); err != nil {
            return model.Category{}, err // 父级查无 → ErrNotFound → 404+1001
        }
    }
    if err := s.repo.Create(&c); err != nil {
        return model.Category{}, err
    }
    return c, nil
}

// Update 字段级更新：只允许改 Name/Icon/Kind/ParentID。
// Sort 走专门的排序接口，Archived 走停用/恢复——一个接口只干一件事。
func (s *CategoryService) Update(familyID, id int64, in model.Category) (model.Category, error) {
    old, err := s.repo.Get(familyID, id)
    if err != nil {
        return model.Category{}, err
    }
    if in.ParentID != 0 && in.ParentID != id {
        if _, err := s.repo.Get(familyID, in.ParentID); err != nil {
            return model.Category{}, err
        }
    }
    old.Name, old.Icon, old.Kind, old.ParentID = in.Name, in.Icon, in.Kind, in.ParentID
    if err := s.repo.Update(old); err != nil {
        return model.Category{}, err
    }
    return s.repo.Get(familyID, id) // 回读：拿 Version+1 之后的最终状态
}

// Archive / Restore 今天先落动作；「有未停用子级不可停用」的规则 D8 加。
func (s *CategoryService) Archive(familyID, id int64) (model.Category, error) {
    return s.setArchived(familyID, id, true)
}

func (s *CategoryService) Restore(familyID, id int64) (model.Category, error) {
    return s.setArchived(familyID, id, false)
}

func (s *CategoryService) setArchived(familyID, id int64, v bool) (model.Category, error) {
    c, err := s.repo.Get(familyID, id)
    if err != nil {
        return model.Category{}, err
    }
    c.Archived = v
    if err := s.repo.Update(c); err != nil {
        return model.Category{}, err
    }
    return s.repo.Get(familyID, id)
}

// Sort 按给定 id 顺序重排：Sort 落成 10、20、30…
// 留 10 的间隙是行业习惯：日后往中间插一条，不用全组重排。D7 加「同父同类型」约束。
func (s *CategoryService) Sort(familyID int64, ids []int64) error {
    for i, id := range ids {
        c, err := s.repo.Get(familyID, id)
        if err != nil {
            return err
        }
        c.Sort = (i + 1) * 10
        if err := s.repo.Update(c); err != nil {
            return err
        }
    }
    return nil
}

import (

    "net/http"
    "strconv"

    "github.com/gin-gonic/gin"

// CategoryHandler 分类 6 条的翻译层：绑定 → 调 service → 写信封。零业务规则。
type CategoryHandler struct {
    familyID int64 // 教学期常量；S4 起来自登录态
    svc      *service.CategoryService
}

func NewCategoryHandler(svc *service.CategoryService, familyID int64) *CategoryHandler {
    return &CategoryHandler{svc: svc, familyID: familyID}
}

// Register 把 6 条路由挂进给定分组。路由表集中在一个函数里，README 照抄它。
func (h *CategoryHandler) Register(g *gin.RouterGroup) {
    g.GET("/categories", h.list)
    g.POST("/categories", h.create)
    g.PUT("/categories/sort", h.sort)     // 静态段优先于 :id，两条路由不冲突
    g.PUT("/categories/:id", h.update)
    g.PUT("/categories/:id/archive", h.archive)
    g.POST("/categories/:id/restore", h.restore)
}

func (h *CategoryHandler) list(c *gin.Context) {
    cs, err := h.svc.List(h.familyID)
    if err != nil {
        response.FailErr(c, err) // handler 的错误出口只有一个（D10 把这条钉成纪律）
        return
    }
    response.OK(c, gin.H{"list": ToRespList(cs)}) // D7 起 list 里装的是树
}

func (h *CategoryHandler) create(c *gin.Context) {
    var req CategoryReq
    if err := c.ShouldBindJSON(&req); err != nil {
        log.Printf("bind create category: %v", err)
        response.Fail(c, http.StatusBadRequest, response.CodeInvalidParam, "参数错误")
        return
    }
    created, err := h.svc.Create(h.familyID, ToModel(req, h.familyID))
    if err != nil {
        response.FailErr(c, err)
        return
    }
    response.Created(c, ToResp(created))
}

func (h *CategoryHandler) update(c *gin.Context) {
    id, ok := h.pathID(c)
    if !ok {
        return // pathID 已写好 400+1004
    }
    var req CategoryReq
    if err := c.ShouldBindJSON(&req); err != nil {
        log.Printf("bind update category %d: %v", id, err)
        response.Fail(c, http.StatusBadRequest, response.CodeInvalidParam, "参数错误")
        return
    }
    updated, err := h.svc.Update(h.familyID, id, ToModel(req, h.familyID))
    if err != nil {
        response.FailErr(c, err)
        return
    }
    response.OK(c, ToResp(updated))
}

func (h *CategoryHandler) archive(c *gin.Context) {
    id, ok := h.pathID(c)
    if !ok {
        return
    }
    updated, err := h.svc.Archive(h.familyID, id)
    if err != nil {
        response.FailErr(c, err)
        return
    }
    response.OK(c, ToResp(updated))
}

func (h *CategoryHandler) restore(c *gin.Context) {
    id, ok := h.pathID(c)
    if !ok {
        return
    }
    updated, err := h.svc.Restore(h.familyID, id)
    if err != nil {
        response.FailErr(c, err)
        return
    }
    response.OK(c, ToResp(updated))
}

// sortReq 排序接口的请求 DTO：ids 至少一个、逐个大于 0。
// dive = 钻进切片对每个元素执行后面的规则（新标签，照抄，D9 的测试会用到它）。
type sortReq struct {
    IDs []int64 `json:"ids" binding:"required,min=1,dive,gt=0"`
}

func (h *CategoryHandler) sort(c *gin.Context) {
    var req sortReq
    if err := c.ShouldBindJSON(&req); err != nil {
        log.Printf("bind sort categories: %v", err)
        response.Fail(c, http.StatusBadRequest, response.CodeInvalidParam, "参数错误")
        return
    }
    if err := h.svc.Sort(h.familyID, req.IDs); err != nil {
        response.FailErr(c, err)
        return
    }
    response.OK(c, nil) // 排序没有值得返回的数据：data 为 null，客户端重新拉列表
}

// pathID 解析 :id；非法（不是正整数）就地写 400+1004 并返回 false。
func (h *CategoryHandler) pathID(c *gin.Context) (int64, bool) {
    id, err := strconv.ParseInt(c.Param("id"), 10, 64)
    if err != nil || id <= 0 {
        response.Fail(c, http.StatusBadRequest, response.CodeInvalidParam, "参数错误")
        return 0, false
    }
    return id, true
}

// newTestRouter 不起真服务：内存 repo 注入，进程内直调（NewRecorder 分工纪律）。
func newTestRouter() http.Handler {
    gin.SetMode(gin.TestMode)
    engine := gin.New()
    svc := service.NewCategoryService(repository.NewMemoryCategoryRepo())
    NewCategoryHandler(svc, 1).Register(engine.Group("/api/finance"))
    return engine

// do 发一个请求并记录响应；body 为空则不带请求体。
func do(r http.Handler, method, path, body string) *httptest.ResponseRecorder {
    w := httptest.NewRecorder()
    var req *http.Request
    if body == "" {
        req = httptest.NewRequest(method, path, nil)
    } else {
        req = httptest.NewRequest(method, path, strings.NewReader(body))
        req.Header.Set("Content-Type", "application/json")
    }
    r.ServeHTTP(w, req)
    return w
}

func TestCategorySixWalkthrough(t *testing.T) {
    r := newTestRouter()

    // ① 创建一级分类「餐饮」
    w := do(r, "POST", "/api/finance/categories", `{"name":"餐饮","kind":"expense","icon":"food"}`)
    if w.Code != 201 || !strings.Contains(w.Body.String(), `"code":0`) {
        t.Fatalf("create: %d %s", w.Code, w.Body.String())
    }

    // ② 创建二级分类「早餐」挂在 1 下
    w = do(r, "POST", "/api/finance/categories", `{"name":"早餐","kind":"expense","parent_id":1}`)
    if w.Code != 201 || !strings.Contains(w.Body.String(), `"parent_id":1`) {
        t.Fatalf("create child: %d %s", w.Code, w.Body.String())
    }

    // ③ 列表：两条都在，信封是 {"list":[…]}，无游标字段
    w = do(r, "GET", "/api/finance/categories", "")
    if w.Code != 200 || !strings.Contains(w.Body.String(), `"list":[`) {
        t.Fatalf("list: %d %s", w.Code, w.Body.String())
    }
    if strings.Contains(w.Body.String(), "next_cursor") {
        t.Fatal("分类是非分页小集合，不许出现游标字段")
    }

    // ④ 编辑：2 号改名「早午餐」，version 应已 +1
    w = do(r, "PUT", "/api/finance/categories/2", `{"name":"早午餐","kind":"expense","parent_id":1}`)
    if w.Code != 200 || !strings.Contains(w.Body.String(), `"name":"早午餐"`) {
        t.Fatalf("update: %d %s", w.Code, w.Body.String())
    }

    // ⑤ 排序：把 2 排到 1 前面
    w = do(r, "PUT", "/api/finance/categories/sort", `{"ids":[2,1]}`)
    if w.Code != 200 || !strings.Contains(w.Body.String(), `"code":0`) {
        t.Fatalf("sort: %d %s", w.Code, w.Body.String())
    }

    // ⑥ 停用与恢复
    w = do(r, "PUT", "/api/finance/categories/1/archive", "")
    if w.Code != 200 || !strings.Contains(w.Body.String(), `"archived":true`) {
        t.Fatalf("archive: %d %s", w.Code, w.Body.String())
    }
    w = do(r, "POST", "/api/finance/categories/1/restore", "")
    if w.Code != 200 || !strings.Contains(w.Body.String(), `"archived":false`) {
        t.Fatalf("restore: %d %s", w.Code, w.Body.String())
    }

    // 失败路径：恢复不存在的 999 → 404 + 1001
    w = do(r, "POST", "/api/finance/categories/999/restore", "")
    if w.Code != 404 || !strings.Contains(w.Body.String(), `"code":1001`) {
        t.Fatalf("restore missing: %d %s", w.Code, w.Body.String())
    }
}

卡壳时查什么

正文自足，只有两种情况出去查：

  • Gin 参数路由的细节：gin · RouterGroup（可选，看清 :id 与静态段的优先级规则）。
  • sort.Slice 的用法：sort · Slice（可选，五行文档；less 函数返回「i 该排在 j 前面吗」）。

三层类 bug 的调试铁律：先定位「哪一层说的谎」。响应码不对 → 看 handler 是不是翻译错了；数据不对 → 看 service 的规则；数据「在库里就不对」→ 看 repo。定位手段：测试直接调 service（不起 HTTP），二分法把三层拆成两半。今天起你的每个 bug 都有三个嫌疑人，别再一个文件里翻到底。
