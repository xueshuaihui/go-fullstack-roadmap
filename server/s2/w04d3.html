接口测试：httptest 覆盖 6 条的矩阵

D6 的场景测试是「一条线串 6 个接口」——走通阶段它是对的，但作为长期资产有三个毛病：一处红后面全瞎、步骤互相依赖、红了说不清哪条合同破。今天把它升级成覆盖矩阵：表驱动、每行一个独立世界、断言从「字符串包含」换成「解码到结构体」，6 条接口的成功档与每个失败码逐一钉死。产品代码零改动，今天纯写测试。

今日目标

知识讲义

1. 场景测试的三个毛病

D6 的 TestCategorySixWalkthrough 一条测试函数从创建走到恢复。它的问题不在「错」，在「贵」：

  • 一处红，后面全瞎：第③步 Fatalf 之后，④⑤⑥根本没跑——一次失败掩盖了其他可能存在的失败。
  • 步骤互相依赖：第⑤步的 sort 依赖第①②步创建的 id。改前面任何一步，后面连环炸（D7 收紧 sort 规则时你已经亲眼见过：一条旧用例无辜变红）。
  • 红了定位慢：报错只说「sort: 400」，你还得回放前四步才知道它拿到的是什么世界。

场景测试不删——它作为「一条真实使用路径」的冒烟检查留着。但主力换成矩阵：一行一个用例，一行一个世界。

2. 覆盖矩阵：多少算够

矩阵的行不是拍脑袋凑的，「够」有明确定义：每条接口的成功档恰好一个用例；每条接口会产生的每个失败码各至少一个用例。对照 6 条接口盘一遍：

接口成功档失败档
GET /categories200 + 树无失败路径（空列表也是 200，这本身就是合同，值得钉一行）
POST /categories201 + CategoryResp400+1004（绑定失败 / 第三级 / 收支不一致）
PUT /categories/:id200 + 改后形状404+1001（不存在）、400+1004（规则拒绝）
PUT /categories/sort200 + data:null400+1004（半组 / 跨组 / 重复）
PUT /categories/:id/archive200 + archived:true409+1010（有活子级）、404+1001
POST /categories/:id/restore200 + archived:false404+1001

失败档用例同时还在测另一样东西：哨兵到错误码的端到端映射。service 抛 %w 包装的哨兵 → FailErr 翻译 → 信封里的 code——矩阵每一行失败档都是这条链的一次实弹演习。明天 D10 加 1009（版本冲突），矩阵就长一行：测试跟着合同长，合同不动测试不动。

3. 解码断言：三层各断各的

字符串包含（strings.Contains(body, `"code":1004`)）的问题：它断言的是「序列化结果的拼写」，字段顺序、空格、转义任何一个变化都会误伤，而真正的合同是结构。解码断言把 body 读回结构体，按字段断言：

层断言对象写法
HTTP 层状态码w.Code != 200
信封层业务码与 messagejson.Unmarshal 进 response.Body，断 b.Code
字段层data 里的具体形状b.Data 是 any（解码后是 map[string]any），再 marshal 一次、解码进目标结构体（json 往返）

json 往返（re-marshal）看着绕，其实是 any 类型唯一的正路：信封的 Data any 解码后只能是泛型 map，想按 CategoryResp 的字段断言，就把它再序列化一次、解码进具体类型。两行 helper 封装掉，用例里就只见 decodeBody / decodeData。

4. 每行一个世界：隔离与单跑

矩阵的每个用例都 newTestRouter() 起一台全新引擎 + 全新内存 repo，再播同一份种子数据（餐饮1、早餐2、交通3）。行与行零共享：任何一行怎么折腾数据，都影响不到下一行。t.Run(name, …) 把每行变成子测试——好处是失败互不掩盖（一行 Fatalf，其他行照跑），且能按名字单跑：

可跑 · 单跑矩阵里的某一行cd <你的学习仓根目录>/server
go test ./internal/finance/handler/ -run 'TestCategoryMatrix/停用有活子级' -v

工具仍是 httptest.NewRecorder：进程内直调 ServeHTTP，不开端口。分工纪律不变——S2/S4 都用 NewRecorder；httptest.NewServer（起真端口、走真网络）留到 S5 测「跨进程边界」的事。

今天属增量类型 ③：加测试用例——解码 helper 两个、覆盖矩阵一个（13 行）、形状专测两个。产品代码零改动。

步骤 1 · 解码 helper

片段 · handler_test.go 追加（前置：D6 的 newTestRouter 与 do；import 增加 "encoding/json" 与 "homecube/pkg/response"）// decodeBody 把响应解码进信封结构：断言对象从字符串换成字段。
func decodeBody(t *testing.T, w *httptest.ResponseRecorder) response.Body {
    t.Helper() // 报错行号指向调用处而不是本函数
    var b response.Body
    if err := json.Unmarshal(w.Body.Bytes(), &b); err != nil {
        t.Fatalf("信封都解不开，说明响应根本不是三键 JSON: %v (raw: %s)", err, w.Body.String())
    }
    return b
}

// decodeData 把信封里的 data（any）再解码进目标结构体：json 往返。
func decodeData(t *testing.T, b response.Body, dst any) {
    t.Helper()
    raw, err := json.Marshal(b.Data)
    if err != nil {
        t.Fatalf("marshal data: %v", err)
    }
    if err := json.Unmarshal(raw, dst); err != nil {
        t.Fatalf("decode data: %v (raw: %s)", err, raw)
    }
}

步骤 2 · 覆盖矩阵（13 行）

片段 · handler_test.go 追加（前置：步骤 1 的两个 helper）func TestCategoryMatrix(t *testing.T) {
    // seed 公共前奏：餐饮(1)、早餐(2, 父1)、交通(3)——每行的世界都从这里开始。
    seed := func(r http.Handler) {
        t.Helper()
        for _, body := range []string{
            `{"name":"餐饮","kind":"expense"}`,
            `{"name":"早餐","kind":"expense","parent_id":1}`,
            `{"name":"交通","kind":"expense"}`,
        } {
            if w := do(r, "POST", "/api/finance/categories", body); w.Code != 201 {
                t.Fatalf("seed 自己就失败了，别冤枉后面的断言: %d %s", w.Code, w.Body.String())
            }
        }
    }

    tests := []struct {
        name                 string
        setup                func(r http.Handler) // 行内额外前奏，可为 nil
        method, path, body   string
        wantStatus, wantCode int
    }{
        // ——— 成功档：6 条接口各一行 ———
        {"列表", nil, "GET", "/api/finance/categories", "", 200, 0},
        {"创建", nil, "POST", "/api/finance/categories", `{"name":"日用","kind":"expense"}`, 201, 0},
        {"编辑", nil, "PUT", "/api/finance/categories/2", `{"name":"早午餐","kind":"expense","parent_id":1}`, 200, 0},
        {"排序整组", nil, "PUT", "/api/finance/categories/sort", `{"ids":[3,1]}`, 200, 0},
        {"停用", nil, "PUT", "/api/finance/categories/3/archive", "", 200, 0},
        {"恢复", func(r http.Handler) {
            do(r, "PUT", "/api/finance/categories/3/archive", "")
        }, "POST", "/api/finance/categories/3/restore", "", 200, 0},

        // ——— 1004：参数与规则拒绝 ———
        {"创建缺name", nil, "POST", "/api/finance/categories", `{"kind":"expense"}`, 400, 1004},
        {"创建第三级", nil, "POST", "/api/finance/categories", `{"name":"豆浆","kind":"expense","parent_id":2}`, 400, 1004},
        {"排序半组", nil, "PUT", "/api/finance/categories/sort", `{"ids":[1]}`, 400, 1004},

        // ——— 1001：不存在 ———
        {"编辑不存在", nil, "PUT", "/api/finance/categories/999", `{"name":"幽灵","kind":"expense"}`, 404, 1001},
        {"停用不存在", nil, "PUT", "/api/finance/categories/999/archive", "", 404, 1001},
        {"恢复不存在", nil, "POST", "/api/finance/categories/999/restore", "", 404, 1001},

        // ——— 1010：状态不允许 ———
        {"停用有活子级", nil, "PUT", "/api/finance/categories/1/archive", "", 409, 1010},
    }

    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            r := newTestRouter() // 每行全新引擎 + 全新内存 repo：行间零串扰
            seed(r)
            if tt.setup != nil {
                tt.setup(r)
            }
            w := do(r, tt.method, tt.path, tt.body)
            b := decodeBody(t, w)
            if w.Code != tt.wantStatus || b.Code != tt.wantCode {
                t.Fatalf("%s %s = HTTP %d / code %d，想要 HTTP %d / code %d（raw: %s）",
                    tt.method, tt.path, w.Code, b.Code, tt.wantStatus, tt.wantCode, w.Body.String())
            }
        })
    }
}

矩阵只断两层（HTTP 状态 + 信封码），data 的字段形状交给步骤 3 的专测——一行只钉一个合同点，红了才知道红在哪。另外注意「编辑」「编辑不存在」两行的 PUT body 都没带 version：D10 启用乐观锁后这两行要补上版本凭据，矩阵会跟着合同一起长。

步骤 3 · 形状专测：解码断言的完整示范

片段 · handler_test.go 追加（前置：测试文件在 package handler 内，CategoryNode/CategoryResp 直接可用）func TestCategoryListShape(t *testing.T) {
    r := newTestRouter()
    do(r, "POST", "/api/finance/categories", `{"name":"餐饮","kind":"expense","icon":"food"}`)
    do(r, "POST", "/api/finance/categories", `{"name":"早餐","kind":"expense","parent_id":1}`)

    w := do(r, "GET", "/api/finance/categories", "")
    b := decodeBody(t, w)
    var data struct {
        List []CategoryNode `json:"list"`
    }
    decodeData(t, b, &data)

    if len(data.List) != 1 {
        t.Fatalf("一级应恰好 1 个（早餐嵌在 children 里）: %+v", data.List)
    }
    root := data.List[0]
    if root.Name != "餐饮" || root.Icon != "food" || root.Archived {
        t.Fatalf("一级字段不对: %+v", root)
    }
    if len(root.Children) != 1 || root.Children[0].Name != "早餐" {
        t.Fatalf("children 不对: %+v", root.Children)
    }
    if root.Children[0].Children == nil {
        t.Fatal("children 绝不允许为 null（解码后应是空 slice 不是 nil）")
    }
}

func TestCategoryCreateRespShape(t *testing.T) {
    r := newTestRouter()
    w := do(r, "POST", "/api/finance/categories", `{"name":"餐饮","kind":"expense"}`)
    if w.Code != 201 {
        t.Fatalf("create: %d %s", w.Code, w.Body.String())
    }
    var resp CategoryResp
    decodeData(t, decodeBody(t, w), &resp)
    if resp.ID != 1 || resp.Name != "餐饮" || resp.Kind != "expense" ||
        resp.Version != 1 || resp.Archived || resp.ParentID != 0 {
        t.Fatalf("创建响应的字段不对: %+v", resp)
    }
}

常见坑（新手 100% 会踩）

坑现象正确姿势
整个矩阵共用一台引擎上一行创建的数据漏进下一行，「创建」行的 id 断言时红时绿每行 newTestRouter()：新引擎、新内存 repo，世界从 seed 重新开始
seed 里不检查自身结果前奏失败，主断言报一个莫名其妙的错，排查半天发现是种子没播上seed 每步都断 201，失败信息写明「seed 自己就失败了」
只断 w.Code 不断 b.CodeHTTP 400 但信封里是 5000 也放行——哨兵断链这类病查不出来两层都断：HTTP 状态给基础设施，业务码给合同
对 data 用字符串包含断字段字段顺序、空格一变全红；"sort":10 还能误中 "sort":100解码进结构体按字段断；字符串包含只留在 Fatalf 的报错信息里
helper 忘写 t.Helper()报错行号全指向 helper 函数内部，不知道是哪行用例炸的每个收 *testing.T 的 helper 第一行 t.Helper()
一行用例断五件事红了只知道「这行不对」，不知道五个合同点里破的是哪个矩阵一行一个合同点；data 形状另立专测
删掉 D6 场景测试「反正矩阵覆盖了」丢掉「一条真实使用路径从头走到尾」的冒烟保障两者互补：场景测试留着，矩阵做主力

今日名词卡

术语一句话解释
覆盖矩阵行 = 用例，列 = 接口/档位；「够」= 成功档每条一行 + 每个失败码至少一行
表驱动测试用例写进 struct 切片，循环执行——加用例 = 加一行数据，不加代码
t.Run 子测试每行独立命名、失败互不掩盖，可用 -run 'Test/行名' 单跑
t.Helper()告诉报错系统「我是工具函数」，行号指向调用处
解码断言body → response.Body → data 再解码进具体 DTO，按字段断言
json 往返any 类型的 data 想进具体结构体：先 Marshal 再 Unmarshal 一次
每行一个世界用例隔离：行内独享引擎与 repo，任何行都影响不到别的行
冒烟场景测试D6 的长串测试的新身份：验证「一条真实路径能走通」
NewRecorder vs NewServer进程内直调 vs 起真端口走真网络；后者是 S5 的工具

卡壳时查什么

正文自足，只有两种情况出去查：

  • 子测试与 -run 的匹配语法：testing 包文档 · Subtests（可选，重点看名字里空格变 _ 的规则）。
  • json.Unmarshal 进 any 后数字变 float64：encoding/json 文档（可选）——这正是我们不做逐层 map 断言、直接 json 往返进 DTO 的原因之一。

矩阵类 bug 的调试铁律：先单跑红的那一行。-run 'TestCategoryMatrix/行名' -v 把它从矩阵里摘出来，世界只有 seed + setup，变量最少；还看不出，就把 w.Body.String() 打进 Fatalf（我们的报错信息已经带了 raw）——信封原文通常直接说出答案。
