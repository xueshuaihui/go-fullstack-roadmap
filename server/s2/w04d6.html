周六 · S2 收口与费曼自测

S2 的收官日。过去十二个工作日你添了十二堆零件：Gin 与路由分组、绑定与 1004、三件套中间件、三层与仓储接口、DTO 与转换、分类 6 条走通、树与父级规则、停用 1010、测试矩阵、错误收口 1009、配置加载雏形。今天不写新功能——把零件收口成一条能被验收、能被讲述、能被陌生人从 clone 跑起来的完整能力：分类域 6 条接口在 Gin 三层上全真实现，教学期假入口与假数据一个不剩。收口的四件事：全量回归、grep 清零、文档对齐、判据自测。

今日目标

知识讲义

1. 「收口」收的是什么

工作日做加法——每天一个微增量；周六做两件事：串联（把五个微增量接成一条能力，这是 d6 卡独有的增量类型）与验收（用阶段判据当合同逐条过）。S2 收口的对象可以列成四份资产：

资产清点标准是哪几天的产物
代码资产6 条接口全真实现；三层文件齐（handler/service/repo/model）；七个哨兵与唯一翻译点；三个中间件D1-D6、D8、D10
测试资产覆盖矩阵 14 行 + 形状专测 + 场景冒烟 + 绑定用例 + CodeOf 全表测试，全在 make test 里常驻D2、D6、D7、D9、D10
文档资产README 路由表与 Register 逐行一致；启动步骤照着敲就能跑今天补
纪律资产「内层不知 HTTP」「Fail 白名单」固化成 grep 巡检（D10）、「运行配置只有一个读取点」由 config 收口（D11），不再依赖记性D10、D11

注意判据里没有「代码写得多」这一项——收口衡量的是这条能力离了你这七天还记得多少：陌生人 clone 下来能跑、你口头能讲清、文档和代码不打架。

2. 假入口清零：反例的账要当面结

S1 为了练手立过 GET /api/ping 这类裸端点，当时的合同就是「S2·D1 删除」。这类注册了、没实现、或已经没用了的端点是本课程明令避开的反例：它们在路由表里挂着，读代码的人会以为契约里有它，将来重构时没人敢删——因为你不知道是不是真有谁在用。今天全仓扫尾：

  • grep -rn "api/ping" server/ —— 代码、README、注释、测试文件，一处都不该有；
  • grep -rn "假数据" server/ —— D2 骨架时代的占位返回与它的标记注释应已绝迹（注释也算线索）；
  • grep -rn "api/v1" server/ README.md —— 路由分域就是 /api/homeos 与 /api/finance 两个，任何版本段都是违规；
  • D11 把环境变量收进 config 唯一读取点——main 里既无 os.Getenv 也无写死端口，这条收口的账不带回 S3。

还有一类隐性假入口：「字段收了但没人读」。比如 DTO 里的字段 service 从不使用、模型列建了但 repo 方法从不写它——逐个对照 D9 矩阵的断言面：矩阵没断的字段，要么补断言，要么删字段。

3. 干净检出：「我这能跑」不算数

你的工作目录里有三类东西不会被 git 带走：未提交的改动、被 .gitignore 拦住的本地配置、以及只在本地存在的文件。所以收口验收的最后一步是模拟陌生人：

可跑 · 干净检出验收cd <你的学习仓根目录>
git status                       # 必须先干净——脏树 clone 必缺东西，这一步不干净就别往下走
git clone "file://$(pwd)" ../s2-clean-check
cd ../s2-clean-check
make build && make test && make lint
cd .. && rm -rf s2-clean-check    # 验收完删掉副本，不留第二个仓

缺文件（报 package … not found）就回主仓补提交，重新来一遍。这台「陌生人模拟机」S3/S6 的收口还会再用，今天把它跑熟。

4. 费曼自测：三张口述题

判据第 4、5、6 条全是「能不能讲」。对着仓库讲，讲的过程录音或记笔记，卡壳的位置就是理解空洞——不是记进 notes/ 就完事，要当场回卡重看。三道题覆盖 S2 全部世界观：

题合格线回看
一个 PUT /categories/:id 请求的六站之旅路由分组 → 中间件洋葱（RequestID/AccessLog/Recovery）→ handler 绑定 → service 规则（检查顺序：存在 1001 → 凭据 1009 → 规则 1004/1010）→ repo 接口 → 内存实现；每站说出该层「绝不」做什么D3、D4、D10
一个被 %w 包了两层的 ErrStateNotAllowed 怎么变成 409 + 1010说出 errors.Is 认哨兵、CodeOf 码、HTTPStatus 状态、FailErr 是拿着 error 的唯一出口、认不出回落 5000 的理由D10、S1·D4
为什么换存储那天 service 与 handler 一行不改接口是替换的接缝；内存实现与将来的 GORM 实现满足同一接口；装配根唯一知道具体实现；「内层不 import gin/net/http」的 grep 巡检（D10）守着这个方向D4、D10

5. 判据自测的记法：证据，不是感想

notes/s2-close.md 里每条判据记三行：判据原文 / 证据（哪个文件、哪条命令的什么输出）/ 结论（过 / 欠）。「我觉得差不多」不是证据；「make test 输出 47 个 PASS 无 FAIL」「grep -rn "api/ping" server/ 零输出」才是。有欠账就明写欠账与补法——落后不追赶，判据不裁剪：欠着的那条补完之前，S3 相应依赖它的环节（换存储只动 repo、每查询带家庭）不要急着开工。

今日增量（在学习仓里落盘）

今天是周六大增量：把本周 5 个微增量串成一条完整能力——树与父级规则（D7）、停用 1010（D8）、测试矩阵（D9）、错误收口 1009（D10）、配置加载雏形（D11）合成「一条可交付的分类域 CRUD」，并完成假入口清零、README 对齐、干净检出与判据自测。

步骤 1 · 全量回归

可跑 · 回归三连cd <你的学习仓根目录>
make build
make test
make lint

全绿才往下走。红了别跳步：先看是 D11 的配置改动引入的还是历史遗留，修完再回来。

步骤 2 · curl 全剧本（真实现 + 失败档抽测）

可跑 · 收口剧本make run     # 终端 1；终端 2 逐条核对状态码与信封三键
curl -i -X POST http://localhost:8080/api/finance/categories \
     -H 'Content-Type: application/json' -d '{"name":"餐饮","kind":"expense"}'                # 201，version:1
curl -i -X POST http://localhost:8080/api/finance/categories \
     -H 'Content-Type: application/json' -d '{"name":"早餐","kind":"expense","parent_id":1}'   # 201
curl -i http://localhost:8080/api/finance/categories                                            # 200，{"list":[…]} 二级树、无游标字段
curl -i -X PUT http://localhost:8080/api/finance/categories/2 \
     -H 'Content-Type: application/json' -d '{"name":"早午餐","kind":"expense","parent_id":1,"version":1}'  # 200，version:2
curl -i -X PUT http://localhost:8080/api/finance/categories/2 \
     -H 'Content-Type: application/json' -d '{"name":"夜宵","kind":"expense","parent_id":1,"version":1}'   # 409 + 1009：旧凭据被拒
curl -i -X PUT http://localhost:8080/api/finance/categories/sort \
     -H 'Content-Type: application/json' -d '{"ids":[2,1]}'                                   # 200，data:null
curl -i -X PUT http://localhost:8080/api/finance/categories/1/archive                           # 409 + 1010：有活子级「早午餐」
curl -i -X PUT http://localhost:8080/api/finance/categories/3/archive                           # 200 archived:true（先建一个无子级的 3 号）
curl -i -X POST http://localhost:8080/api/finance/categories/3/restore                          # 200 archived:false
curl -i -X POST http://localhost:8080/api/finance/categories/999/restore                        # 404 + 1001
curl -i http://localhost:8080/api/nope                                                          # 404 + 1001：NoRoute 也是三键信封

步骤 3 · grep 收口（讲义 2 的四条 + D10 的两条复查）

grep -rn "net/http\|gin-gonic" server/internal/finance/service/ server/internal/finance/repository/

# ↑ 五条全部零命中（或只剩 pathID 那一处白名单）；D11 的两条 config 收口检查（main 里 os.Getenv、写死 :8080 均零命中）也重跑一遍归档

步骤 4 · README 对齐

README 补三节，逐节与代码对照着写，不许凭记忆默写：

  • 路由表：6 条一表（方法 / 路径 / 成功响应 / 失败码），照抄 Register 与各 handler；
  • 启动与验收：make build / make test / make run + 步骤 2 剧本的精简版；
  • 分层说明：一段话 + <repo>/server/internal/finance/ 的目录树，写明依赖方向与「handler 只认 service」纪律，注明「内层不 import gin/net/http」的 grep 巡检是这条纪律的常驻执行者。

步骤 5 · 干净检出（讲义 3）

先 git add + commit 把树弄干净，再 clone 副本三连（build/test/lint），验收完删副本。

步骤 6 · 判据自测 + 费曼口述（讲义 4、5）

打开 S2 阶段总览的 6 条判据，逐条写 notes/s2-close.md：判据原文 / 证据 / 结论。随后费曼三题各录一遍，卡壳处标出来回看对应卡。全过才写「S2 通过」；有欠账就写欠账计划，不裁剪判据。

卡壳时查什么

正文自足，只有两种情况出去查：

  • git clone 本地路径/URL 写法：git-clone 文档（可选，file:// 协议一节）。
  • 判据原文：回 S2 阶段总览 的「阶段判据」一节逐条抄——自测必须以它为准，别凭印象转述。
