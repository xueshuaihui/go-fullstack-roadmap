周六 · 分类域从内存 map 换到 DB，接口一行不改

本周串联轴线：S2 建好的分类域 6 条接口（/api/finance/categories 家族）跑在内存 map 上，今天把 repo 换成 GORM 实现——迁移建表、接口不动、契约不变。这是 S1·D5 抽出 Repository 接口、S2·D4 按消费方归置之后的回报日：换存储那天，service/handler/路由/DTO 一行不改。今天之后，进程重启数据还在，这是项目第一次真正「记住」东西。

今日目标

知识讲义

1. 换的是哪一层：三层里只动最底下那层

S2 的分层是 handler → service → repo，repo 是接口、内存 map 是它的实现。今天的动作精确到一句话：给同一个接口写第二个实现，然后把装配处的构造函数换掉。HTTP 契约（路径、方法、DTO、响应信封、错误码）全部不动——分类 6 条接口今天之前之后都是这 6 条，接口分母不变。

层今天动不动说明
handler / 路由 / 中间件不动只认 service，感知不到存储换了
service / DTO / validator不动只认 repo 接口
repo 实现新增 GORM 实现内存实现不删——它是 S2 起 handler 测试的测试替身，无库 CI 全靠它
装配（main.go）改一行接口变量 = 新构造函数；编译期就会检查实现满足接口

2. 预置数据：family_id IS NULL 的读法与写法

分类树有「系统预置的默认树」——它不属于任何家庭，任何家庭都可见。本站的表达方式：可空的 family_id，NULL = 系统预置。于是读写规则不对称，今天必须刻进肌肉：

  • 读：WHERE family_id = ? OR family_id IS NULL——本家庭的 + 预置的；
  • 写：WHERE id = ? AND family_id = ?——只认本家庭的行，预置行不可改不可停用。想改预置分类？在自己家庭里建一个同名的自定义分类。

预置行只出自迁移里的种子 INSERT——代码路径永远造不出 family_id NULL 的行，这是「预置」与「自定义」不会互相污染的根本保证。

3. 乐观锁与 0 行的两种含义

PUT /api/finance/categories/{id} 带 version：更新语句的 WHERE 里加上 version = ?，SET 里 version = version + 1。两个人同时改，先到的成功、后到的 WHERE 匹配不上——RowsAffected = 0。但 0 行有两种含义，必须分辨（S2 内存实现里你大概率写过同样的分支）：

0 行的原因怎么判定响应
行真的不存在 / 不属于本家庭按 id + family_id COUNT 为 0404 + 1001（与不存在同形，不泄露存在性）
行存在但 version 过期COUNT 为 1409 + 1009

错误怎么变成这两个响应？走 S1·D4 的老路：repo 返回包装过的哨兵（%w），response.FailErr 用 errors.Is 认出来。今天错误码表里 1009 那一位第一次上岗，需要给哨兵集补一个 ErrVersionConflict。

4. 没有鉴权的 S3，familyID 从哪来：临时桩，明账记牢

鉴权是 S4 的事，S3 不写。但 repo 的每个方法都要 familyID 参数——本站的处理是 handler 侧一个临时桩函数：currentFamilyID(c) 固定返回种子家庭 1；S4 建好鉴权中间件后，函数体换成从 context 读真值，签名与所有调用点都不变。这不是「注册了但没实现的假入口」：6 条路由的实现全是真的，只有「当前请求属于哪个家庭」这一个问题记在 S4 的账上。桩要集中一处、注释写明还债时点——散落在各 handler 里的魔法数字 1 才是事故。

另一个「今天照抄、日后正式讲」：repo 方法签名里的 ctx context.Context。它的作用是超时与取消的传递，S5 并发周正式讲；今天你只需要知道两条规矩——handler 里传 c.Request.Context()，repo 里链上 r.db.WithContext(ctx)。

今日增量（在学习仓里落盘）

今天是周六大增量：把本周 5 个微增量串成一条完整能力——库（D1）→ 连接（D2）→ 迁移工具（D3/D4）→ 表与模型（D5 样式）全部就位，今天合成「分类域 DB 化」。涉及类型 ④（一条迁移 up/down）+ ⑤（6 条接口的存储从内存换成真查询）。

步骤 4 · GormCategoryRepo：接口的第二个实现

完整 · server/internal/finance/repository/category_gorm.gopackage repository

import (
    "context"
    "errors"
    "fmt"

    "gorm.io/gorm"

    "homecube/internal/finance/model"
    "homecube/pkg/response"
)

// GormCategoryRepo 是 CategoryRepository 的 Postgres 实现。
// 换实现不换契约：service/handler/路由/DTO 一行不改。
type GormCategoryRepo struct{ db *gorm.DB }

func NewGormCategoryRepo(db *gorm.DB) *GormCategoryRepo {
    return &GormCategoryRepo{db: db}
}

// List 全量返回「本家庭自定义 + 系统预置」，排序服务端钉死：sort ASC, id ASC。
// 分类树是小集合：不分页，响应就是 {"list":[...]}，不带 next_cursor/has_more。
func (r *GormCategoryRepo) List(ctx context.Context, familyID int64) ([]model.Category, error) {
    var rows []model.Category
    err := r.db.WithContext(ctx).
        Where("family_id = ? OR family_id IS NULL", familyID).
        Order("sort ASC, id ASC").
        Find(&rows).Error
    if err != nil {
        return nil, fmt.Errorf("list categories: %w", err)
    }
    return rows, nil
}

// GetByID 读路径带可见域：本家庭的 + 预置的。查不到 → ErrNotFound → 404+1001。
func (r *GormCategoryRepo) GetByID(ctx context.Context, familyID, id int64) (*model.Category, error) {
    var row model.Category
    err := r.db.WithContext(ctx).
        Where("id = ? AND (family_id = ? OR family_id IS NULL)", id, familyID).
        First(&row).Error
    if errors.Is(err, gorm.ErrRecordNotFound) {
        return nil, fmt.Errorf("category %d: %w", id, response.ErrNotFound)
    }
    if err != nil {
        return nil, fmt.Errorf("get category %d: %w", id, err)
    }
    return &row, nil
}

// Create 只能造本家庭的行：FamilyID 由参数钉死，请求体里说什么都没用。
func (r *GormCategoryRepo) Create(ctx context.Context, familyID int64, in model.CategoryInput) (*model.Category, error) {
    row := model.Category{
        FamilyID: &familyID, ParentID: in.ParentID,
        Name: in.Name, Icon: in.Icon, Kind: in.Kind, Sort: in.Sort,
        Version: 1,
    }
    if err := r.db.WithContext(ctx).Create(&row).Error; err != nil {
        if errors.Is(err, gorm.ErrDuplicatedKey) { // TranslateError（S3·D2）在此兑现
            return nil, fmt.Errorf("create category: %w", response.ErrConflict) // → 409+1006
        }
        return nil, fmt.Errorf("create category: %w", err)
    }
    return &row, nil
}

// Update 带 version 乐观锁；写路径只认本家庭的行（预置行不可改）。
func (r *GormCategoryRepo) Update(ctx context.Context, familyID, id int64, in model.CategoryInput, version int) (*model.Category, error) {
    res := r.db.WithContext(ctx).Model(&model.Category{}).
        Where("id = ? AND family_id = ? AND version = ?", id, familyID, version).
        Updates(map[string]any{
            "parent_id": in.ParentID, "name": in.Name, "icon": in.Icon,
            "kind": in.Kind, "sort": in.Sort,
            "updated_at": gorm.Expr("now()"),
            "version":    gorm.Expr("version + 1"),
        })
    if res.Error != nil {
        return nil, fmt.Errorf("update category %d: %w", id, res.Error)
    }
    if res.RowsAffected == 0 {
        return nil, fmt.Errorf("update category %d: %w", id, r.zeroRowCause(ctx, familyID, id))
    }
    return r.GetByID(ctx, familyID, id)
}

// SetArchived 停用/恢复共用：archive 与 restore 两条路由在 service 层翻成 archived=true/false。
func (r *GormCategoryRepo) SetArchived(ctx context.Context, familyID, id int64, archived bool, version int) error {
    res := r.db.WithContext(ctx).Model(&model.Category{}).
        Where("id = ? AND family_id = ? AND version = ?", id, familyID, version).
        Updates(map[string]any{
            "archived": archived, "updated_at": gorm.Expr("now()"), "version": gorm.Expr("version + 1"),
        })
    if res.Error != nil {
        return fmt.Errorf("set archived %d: %w", id, res.Error)
    }
    if res.RowsAffected == 0 {
        return fmt.Errorf("set archived %d: %w", id, r.zeroRowCause(ctx, familyID, id))
    }
    return nil
}

// Reorder 一次事务按 ids 重写 sort；任何一行不属于本家庭，整个重排回滚。
// Transaction 的用法今天照抄，S3·D7 正式讲。
func (r *GormCategoryRepo) Reorder(ctx context.Context, familyID int64, ids []int64) error {
    return r.db.WithContext(ctx).Transaction(func(tx *gorm.DB) error {
        for i, id := range ids {
            res := tx.Model(&model.Category{}).
                Where("id = ? AND family_id = ?", id, familyID).
                Updates(map[string]any{"sort": i + 1, "updated_at": gorm.Expr("now()")})
            if res.Error != nil {
                return res.Error
            }
            if res.RowsAffected == 0 {
                return fmt.Errorf("reorder category %d: %w", id, response.ErrNotFound)
            }
        }
        return nil
    })
}

// zeroRowCause 分辨两种 0 行：真不存在/不属于本家庭 → ErrNotFound；version 过期 → ErrVersionConflict。
func (r *GormCategoryRepo) zeroRowCause(ctx context.Context, familyID, id int64) error {
    var cnt int64
    if err := r.db.WithContext(ctx).Model(&model.Category{}).
        Where("id = ? AND family_id = ?", id, familyID).Count(&cnt).Error; err != nil {
        return err
    }
    if cnt == 0 {
        return response.ErrNotFound
    }
    return response.ErrVersionConflict
}

对照你 S2·D4 定下的 CategoryRepository 方法集：如果签名有小出入（参数名、Input 类型放哪个包），以你手上的为准，原则只有一条——今天只加实现，不改契约。GORM 的 Find/First 默认带软删过滤（模型有 gorm.DeletedAt），所有查询自动排除 deleted_at 非空的行——这件事明天正式算账。

import (
    "context"
    "errors"
    "fmt"

    "gorm.io/gorm"

func openTestDB(t *testing.T) *gorm.DB {
    t.Helper()
    if os.Getenv("DB_NAME") == "" {
        t.Skip("未设置 DB_NAME，跳过真库测试")
    }
    dsn := fmt.Sprintf("postgres://%s:%s@%s:%s/%s?sslmode=%s",
        os.Getenv("DB_USER"), os.Getenv("DB_PASS"),
        os.Getenv("DB_HOST"), os.Getenv("DB_PORT"),
        os.Getenv("DB_NAME"), os.Getenv("DB_SSLMODE"))
    gdb, err := db.Open(dsn)
    if err != nil {
        t.Skipf("库未就绪（先 make migrate-finance-up）: %v", err)
    }
    return gdb
}

func TestGormCategoryRepo(t *testing.T) {
    gdb := openTestDB(t)
    repo := NewGormCategoryRepo(gdb)
    ctx := context.Background()
    const famA, famB = int64(901), int64(902) // 测试专用家庭 id，避开种子家庭 1

    // 造数 + 清场（清场用 Unscoped 物理删，测试数据不过夜也不留软删尸体）
    t.Cleanup(func() {
        gdb.Unscoped().Where("family_id IN (?, ?)", famA, famB).Delete(&model.Category{})
    })

    // ① List 看得见系统预置树（迁移种子），看不见别家的行
    preset, err := repo.List(ctx, famA)
    if err != nil || len(preset) < 6 {
        t.Fatalf("预置树应 ≥6 条（3 一级 + 3 二级）, got %d, err %v", len(preset), err)
    }

    // ② Create → 归本家庭；List 能看见；famB 看不见
    created, err := repo.Create(ctx, famA, model.CategoryInput{Name: "宠物", Kind: "expense", Sort: 10})
    if err != nil {
        t.Fatalf("create: %v", err)
    }
    if _, err := repo.GetByID(ctx, famB, created.ID); !errors.Is(err, response.ErrNotFound) {
        t.Fatalf("跨家庭读应 ErrNotFound, got %v", err) // → handler 层即 404+1001
    }

    // ③ Update：对版本成功且 version+1；错版本 → ErrVersionConflict
    upd, err := repo.Update(ctx, famA, created.ID, model.CategoryInput{Name: "宠物用品", Kind: "expense"}, created.Version)
    if err != nil || upd.Version != created.Version+1 {
        t.Fatalf("update: %v, version %d", err, upd.Version)
    }
    if _, err := repo.Update(ctx, famA, created.ID, model.CategoryInput{Name: "再改", Kind: "expense"}, created.Version); !errors.Is(err, response.ErrVersionConflict) {
        t.Fatalf("旧版本更新应 ErrVersionConflict, got %v", err) // → 409+1009
    }

    // ④ SetArchived：停用后 List 仍返回（带 archived 标记），历史可筛可统计
    if err := repo.SetArchived(ctx, famA, created.ID, true, upd.Version); err != nil {
        t.Fatalf("archive: %v", err)
    }
    rows, _ := repo.List(ctx, famA)
    found := false
    for _, c := range rows {
        if c.ID == created.ID && c.Archived {
            found = true
        }
    }
    if !found {
        t.Fatal("停用项应仍在 List 中且 archived=true")
    }

    // ⑤ Reorder：混入别家 id → 整个重排失败回滚，sort 不变
    before, _ := repo.GetByID(ctx, famA, created.ID)
    if err := repo.Reorder(ctx, famA, []int64{created.ID, 123456789}); !errors.Is(err, response.ErrNotFound) {
        t.Fatalf("混入不存在 id 应整体失败, got %v", err)
    }
    after, _ := repo.GetByID(ctx, famA, created.ID)
    if after.Sort != before.Sort {
        t.Fatalf("回滚失败：sort %d → %d", before.Sort, after.Sort)
    }
}

常见坑（新手 100% 会踩）

坑现象正确姿势
顺手改了接口来适配 GORM「repo 方法加个参数嘛」——service/handler 跟着连环改，契约漂移方向反了：让实现去满足接口。接口要变是另一件事，走 S2 的评审口径，不夹带在换存储里
删掉内存实现S2 的 handler 测试全红：它们依赖内存替身内存实现留在仓库当测试替身；main 不再引用它而已
写路径带上 OR family_id IS NULL用户能改系统预置分类，全局默认树被一个家庭污染读带预置、写只认本家庭——两个 WHERE 长得就是不一样
0 行不分因，一律回 1009删掉的 id 去 PUT，得到「版本冲突」这种误导响应先 COUNT 分辨：不存在 → 1001，版本旧 → 1009（zeroRowCause 的职责）
gorm.ErrRecordNotFound 直接外抛FailErr 认不出它，回落 5000repo 层就地翻译成 response.ErrNotFound 再包装；GORM 的哨兵不许穿透 repo 边界
种子数据写进代码handler 启动时 INSERT 预置分类，多实例重复插、环境不一致预置行只出自迁移种子；代码路径造不出 family_id NULL
魔法数字 1 散落各 handlerS4 接鉴权时要全仓 grep 换值，漏一处就是越权口子临时桩集中一个 currentFamilyID，注释写明 S4 还债
忘了跑 finance 迁移就 make run接口全 500，日志里 relation "finance.finance_category" does not exist起服务前先 make migrate-*-up；把这条写进 README 的启动步骤（S3·D12 收口时补）
