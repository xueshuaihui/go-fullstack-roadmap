知识讲义

1. config 的契约：变量只认这张表

S2·D11 立的雏形（配置加载雏形）今天定稿。读取方式一字不改——读取 → 默认 → 校验 → 返回 struct；长出来的是 DB 侧的六个变量、两条 DSN、一个池、一道门禁。全站环境变量的口径就是 D1 两段注释里那张后端变量表（S3·D1），config 只认它：

变量必填 / 默认校验与非法处理
PORT默认 80801–65535 整数，否则拒绝启动（S2·D11 起沿用）
GIN_MODE默认 debug只认 debug/release/test，拼错不回落
DB_HOST必填空 = 缺失，报错点名变量；本机 localhost、容器网络里写服务名 postgres（D1 的两段口径）
DB_PORT默认 5432数字校验同 PORT
DB_USER / DB_NAME必填空 = 缺失；本站值固定 homecube / homecube（D1 口径）
DB_PASS必填，无默认空串一律当缺失——口令不设默认、不特判「本机没口令」；教学库的口令也堂堂正正进 .env
DB_SSLMODE默认 disable本机回环不启 TLS；生产口径 S8 部署再谈（D1 名词卡留的话）
AUTO_MIGRATE默认 false读到 true = 拒绝启动（讲义 5），兑现 D2 那句「加载到 true 会直接拒绝启动」

为什么必填项不配默认值、可选项才配？默认值是给「怎么跑都对」的旋钮（端口、SSL 模式）；连接目标与口令每一项都「猜不得」——猜出来的默认 host 会把测试打到别人的库上。猜不得的东西缺失就该死，而不是带病营业。今天的表驱动测试就测这两面：缺必填必报错、可缺省必给默认。

2. 反面教材：自创别名比缺配置更坏（本次课唯一的反面演示）

D1 表格钉过「禁止自造别名」，今天说清为什么，顺便把反面名单点出来——以下四个都是错误示范，本站 config 一律不认：POSTGRES_DSN、DB_PASSWORD、SERVER_PORT、MYSQL_DSN。三个层次的危害：

别名错在哪一层
DB_PASSWORD / SERVER_PORT同义换名。config 不认识它，DB_PASS 仍是「缺失」——最典型的事故不是「报错看不懂」，是你以为配了：值在 env 里躺着、永远没人读，直到必填校验把它当场拒了才暴露。别名被静默忽略 = 配了等于没配
POSTGRES_DSN整串外包。把六个变量的契约塌缩成一个字符串，两段口径、口令与库名分离、search_path 拼装全部失踪——「唯一拼装点」没了，DSN 形状散落到每个写 env 的人手里
MYSQL_DSN双重错误：既是别名，本站数据库更不是它——本站钉死 Postgres 16（D1 起）。见到这个变量名，说明连技术栈口径都漂了

config 的立场只有一条：只认讲义 1 那张表。写错名字的人会得到一条点名「缺 DB_PASS」的启动失败——错误信息指向真变量名，这就是正确的教育方式；给别名开门才是把口径裂口焊死在代码里。S4 的 JWT_SECRET、S6 的 UPLOAD_DIR、S7 的 CORS_ORIGIN 之后进这张表，表外无变量。

3. 双 DSN 拼装与双 schema 口径

本站一个库、两个 schema（homeos / finance），口径从 D1 立到今天：表名全 schema 限定（finance.finance_category）、不跨 schema join、迁移链各自独立。应用侧的落地形状是一个进程两套连接：config 从同一组 DB_* 拼两条 DSN，各带自己的 search_path：

片段 · DSN 拼装公式（config 内部唯一一处 Sprintf）postgres://user:pass@host:port/db?sslmode=mode&search_path=schema
连接search_path今天上岗？说明
HomeosDSN()homeosDSN 今天备好；连接等 S4 身份域 repo 出生时再开不给没人用的连接留池——「注册了但没用」的连接同样算假入口
FinanceDSN()finance今天：分类 repo 挂在这条上w05d6 那行临时接线今天退役

三个口径互相咬合，背下来：① search_path 与全限定 TableName() 是双保险——D2 说过不靠 search_path「碰巧找对」，今天连接串钉它是纪律就位，模型里的全限定名一个都不删；② 不跨 schema join——两条连接是两个世界，一条 GORM 连接上的查询永远看不见另一条的表，「finance 的迁移不许出现 homeos_*」这条禁令第一次有了物理对应物；③ 跨域调用收在 platform 接口后面（S4 的 FamilyDirectory 形状），永远不是「拿另一个 DB 句柄 join 一下」。

顺带把库里的三套身份排好座次，谁也不抢谁的活：

身份谁在用权限形状
homecube（DB_USER）Go 应用进程，两套连接都用它两个 schema 的 DML（增删改查），不做 DDL
homeos_app / finance_app只有 compose 里的 migrate 服务（HOMEOS_MIGRATE_URL / FINANCE_MIGRATE_URL，D3 上岗）各自专属：只在本 schema 有建表权，越界直接被数据库拒——应用连接不借它们的光
POSTGRES_USER（镜像管理员）只在建数据卷那一刻（D1 两段口径的另一段）日常无人使用

4. 连接池四参数：各自治什么病（D2 欠的「一次讲透」）

先想清楚池是什么：一条 Postgres 连接的出生要 TCP 握手 + 认证（生产还有 TLS），服务端每个连接还占一份内存与会话槽。请求来一条开一条，库会被握手与僵尸连接淹死。池 = 养一小批长连接反复复用；Go 的 database/sql 自带池，但它的零值是「没配置」而不是「配置好了」：MaxOpenConns=0 意思是不限、MaxIdleConns=2 意思是不忙时只留两条、ConnMaxLifetime=0 永生、ConnMaxIdleTime=0 永不退场——四条病灶一次齐活。四参数逐条对号：

参数治什么病不配 / 配错的现场本站默认
SetMaxOpenConns保险丝：同时在用的连接上限，挡住并发把库打穿零值 = 不限：一阵并发涌到 max_connections（Postgres 默认 100），服务端内存爆炸、建连风暴，殃及同库所有账号16：家用单体留足余量给第二条连接与运维 psql
SetMaxIdleConns库存：闲时保留几条随时能用，摊薄握手成本零值口径只留 2：突发过后连接被关掉，第二波流量全部重来握手 + 认证——高峰错峰地抖8：留得住常用容量，又不白占库侧资源
SetConnMaxLifetime强制轮换：到年纪就退，不管多健康不限寿命：中间设备（LB/防火墙/NAT）闲时悄悄掐线，池不知道，下一条请求拿着半死连接撞超时30m：短于链路任何一侧的空闲超时，到期换新
SetConnMaxIdleTime闲时回收：闲太久主动退场永不回收：凌晨的低峰挂着八小时前的旧连接，被防火墙掐成僵尸后仍被池递出去用5m：家用流量波谷不留隔夜连接

两条原则收束：上限从库侧容量算，不从胃口算——MaxOpen 不是「越大越稳」，200 条连接在应用侧是潇洒、在 Postgres 侧是灾难（每连接一份内存，会话槽互抢）；到期换新的语义要看清——生命周期只作用于「获取新连接」的时刻，正在执行查询的连接不会被腰斩。还有一条本站纪律：池参数不走环境变量——全站变量表（讲义 1 那张）没有它们的位置，就写死在 config 的默认值里，不自造 DB_MAX_CONNS 这种表外变量（别名禁令同款）；S8 部署真要调旋钮时再统一入表。

5. AUTO_MIGRATE 恒关：一道拒绝启动的门禁

D2 的对照实验你应该还记得现场：AutoMigrate 只加不减、类型变更保守、没有版本没有回滚、多环境各跑各的——建表权给了它，三个月后没人说得清表为什么长这样。所以本站纪律「建表权只在 migrations/」，D2 把开关预留成 AUTO_MIGRATE 并写下狠话：「S3·D11 的 config 加载到 true 会直接拒绝启动」。今天兑现：

  • 光靠「预留着别设成 true」的自觉不算数——有人会复制别人的 .env、会有人在 README 的旧例里抄错。纪律要活到代码里才能拦住下一次手滑。
  • 门禁的位置选在 config——全站唯一 env 读取点：它不在 db 包里（连接成功与否管不了建表）、不在 main 的 if 里（多一条开新入口的装配就漏守一次）。读取点 = 执法点。
  • 行为：读到 "true" 直接返回 error，main log.Fatalf，进程不启动。宁可起不来，不可悄悄建表——AutoMigrate 建出来的表会让迁移链与物理表结构分叉，明天周六的「全链重放判据」当场作废。

import (
    "fmt"
    "os"
    "strconv"
    "strings"
    "time"
)

// Pool 连接池四参数。参数表里没有它们的 env 变量位（别名禁令同款）：
// 走代码默认，S8 部署真要调时再统一入表。各自治什么病见卡面讲义 4。
type Pool struct {
    MaxOpenConns    int          // 保险丝：在用上限，0 = 不限（本站的灾难零值，必设）
    MaxIdleConns    int          // 库存：闲时保留数（库默认只 2）
    ConnMaxLifetime time.Duration // 强制轮换：到年纪就退
    ConnMaxIdleTime time.Duration // 闲时回收：闲太久主动退
}

// DefaultPool 家用单体口径：16 保险丝 / 8 库存 / 30 分钟轮换 / 5 分钟回收。
func DefaultPool() Pool {
    return Pool{MaxOpenConns: 16, MaxIdleConns: 8,
        ConnMaxLifetime: 30 * time.Minute, ConnMaxIdleTime: 5 * time.Minute}
}

// Config 运行配置·定稿版（S2·D11 雏形 → 今日加 DB 侧、池、门禁）。
// 读取方式一路不变：读取 → 默认 → 校验 → 返回 struct。
type Config struct {
    Port    string
    GinMode string

    DBHost    string
    DBPort    string
    DBUser    string
    DBPass    string // 必填、无默认；永远不落日志
    DBName    string
    DBSSLMode string

    AutoMigrate bool // 门禁字段：true = 拒绝启动（见 Load 末段）

    Pool Pool
}

// IsConfigured 真库测试的唯一 skip 判定：DB_NAME 是必填项的锚。
// 无库机器上 make test 全绿（Skip）的口径从 D2 沿用至今，只把「怎么拼」换了主人。
func IsConfigured() bool { return os.Getenv("DB_NAME") != "" }

func Load() (Config, error) {
    cfg := Config{
        Port:        envOr("PORT", "8080"),
        GinMode:     envOr("GIN_MODE", "debug"),
        DBHost:      os.Getenv("DB_HOST"),
        DBPort:      envOr("DB_PORT", "5432"),
        DBUser:      os.Getenv("DB_USER"),
        DBPass:      os.Getenv("DB_PASS"),
        DBName:      os.Getenv("DB_NAME"),
        DBSSLMode:   envOr("DB_SSLMODE", "disable"),
        AutoMigrate: os.Getenv("AUTO_MIGRATE") == "true",
        Pool:        DefaultPool(),
    }

    if n, err := strconv.Atoi(cfg.Port); err != nil || n < 1 || n > 65535 {
        return Config{}, fmt.Errorf("config: 非法的 PORT %q：必须是 1-65535 的整数", cfg.Port)
    }
    switch cfg.GinMode {
    case "debug", "release", "test":
    default:
        return Config{}, fmt.Errorf("config: 非法的 GIN_MODE %q：只允许 debug/release/test", cfg.GinMode)
    }

    // 必填四项：DB_HOST/DB_USER/DB_PASS/DB_NAME——空一律当缺失（口令不设默认、不特判）。
    // 报错点名真变量名：自造别名（DB_PASSWORD 之流）没配在这里，也别想配置在这里。
    var missing []string
    for _, f := range []struct{ name, val string }{
        {"DB_HOST", cfg.DBHost}, {"DB_USER", cfg.DBUser},
        {"DB_PASS", cfg.DBPass}, {"DB_NAME", cfg.DBName},
    } {
        if f.val == "" {
            missing = append(missing, f.name)
        }
    }
    if len(missing) > 0 {
        return Config{}, fmt.Errorf("config: 缺少必填变量 %s（只认全站变量表里的名字，别名不算）",
            strings.Join(missing, ", "))
    }

    // 门禁兑现 D2 的狠话：AUTO_MIGRATE 加载到 true = 拒绝启动。建表权只在 migrations。
    if cfg.AutoMigrate {
        return Config{}, fmt.Errorf("config: AUTO_MIGRATE=true 被拒绝：建表权只在 migrations（S3·D2 纪律）")
    }
    return cfg, nil
}

func envOr(name, def string) string {
    if v := os.Getenv(name); v != "" {
        return v
    }
    return def
}

// —— DSN 拼装：全站唯一一处 Sprintf。一个进程两套连接，各钉各的 search_path。
// 与全限定 TableName() 互为双保险；两条连接是两个世界，不跨 schema join。——
func (c Config) HomeosDSN() string  { return c.dsn("homeos") }
func (c Config) FinanceDSN() string { return c.dsn("finance") }

func (c Config) dsn(schema string) string {
    return fmt.Sprintf("postgres://%s:%s@%s:%s/%s?sslmode=%s&search_path=%s",
        c.DBUser, c.DBPass, c.DBHost, c.DBPort, c.DBName, c.DBSSLMode, schema)
}

func (c Config) Addr() string { return ":" + c.Port }

步骤 2 · db.Open 吃下池参数

片段 · server/internal/platform/db/db.go 的 Open（签名加一参，池随每条连接生效）func Open(dsn string, p config.Pool) (*gorm.DB, error) {
    gdb, err := gorm.Open(postgres.Open(dsn), &gorm.Config{
        TranslateError: true, // D2 立的，D3/D9 的 1006 链靠它——不动
        Logger:         logger.Default.LogMode(logger.Warn),
    })
    if err != nil {
        return nil, fmt.Errorf("open db: %w", err)
    }
    sqlDB, err := gdb.DB()
    if err != nil {
        return nil, fmt.Errorf("get sql.DB: %w", err)
    }
    // 池四参数：D2 说「S3·D11 一次讲透」的那四条，各自治什么病见讲义 4 的表。
    sqlDB.SetMaxOpenConns(p.MaxOpenConns)      // 保险丝：并发上限
    sqlDB.SetMaxIdleConns(p.MaxIdleConns)      // 库存：闲时保留
    sqlDB.SetConnMaxLifetime(p.ConnMaxLifetime) // 轮换：到年纪就退
    sqlDB.SetConnMaxIdleTime(p.ConnMaxIdleTime) // 回收：闲太久就退
    if err := sqlDB.Ping(); err != nil {
        return nil, fmt.Errorf("ping db: %w", err)
    }
    return gdb, nil
}

import (
    "strings"
    "testing"
)

// fullEnv 基线：九个变量全量给出（空串 = 视为未设，与 Load 的口径一致）。
// overrides 造非法现场。t.Setenv 会在子测试结束后自动复原——「注入」在测试里的样子。
func fullEnv(overrides map[string]string) map[string]string {
    env := map[string]string{
        "PORT": "", "GIN_MODE": "",
        "DB_HOST": "localhost", "DB_PORT": "5432",
        "DB_USER": "homecube", "DB_PASS": "homecube123",
        "DB_NAME": "homecube", "DB_SSLMODE": "disable",
        "AUTO_MIGRATE": "",
    }
    for k, v := range overrides {
        env[k] = v
    }
    return env
}

func TestLoad(t *testing.T) {
    cases := []struct {
        name    string
        env     map[string]string
        wantErr string // 期望错误点名；"" = 期望成功
        wantDSN string // 期望 FinanceDSN 含此片段（仅成功用例）
    }{
        {"齐全：默认 PORT/GinMode 生效", fullEnv(nil), "",
            "postgres://homecube:homecube123@localhost:5432/homecube?sslmode=disable&search_path=finance"},
        {"缺 DB_HOST：点名变量", fullEnv(map[string]string{"DB_HOST": ""}), "DB_HOST", ""},
        {"DB_PASS 空串 = 缺失：口令无默认", fullEnv(map[string]string{"DB_PASS": ""}), "DB_PASS", ""},
        {"别名 DB_PASSWORD 不算 DB_PASS", fullEnv(map[string]string{"DB_PASS": "", "DB_PASSWORD": "x"}), "DB_PASS", ""},
        {"别名 POSTGRES_DSN 不算 DB_NAME", fullEnv(map[string]string{"DB_NAME": "", "POSTGRES_DSN": "postgres://a:b@c/d"}), "DB_NAME", ""},
        {"非法 PORT", fullEnv(map[string]string{"PORT": "abc"}), "PORT", ""},
        {"PORT=0：整数合法、端口非法——范围闸", fullEnv(map[string]string{"PORT": "0"}), "PORT", ""},
        {"非法 GIN_MODE 不回落", fullEnv(map[string]string{"GIN_MODE": "realse"}), "GIN_MODE", ""},
        {"AUTO_MIGRATE=true：拒绝启动", fullEnv(map[string]string{"AUTO_MIGRATE": "true"}), "AUTO_MIGRATE", ""},
        {"DB_PORT/DB_SSLMODE 缺省给默认", fullEnv(map[string]string{"DB_PORT": "", "DB_SSLMODE": ""}), "", ":5432/homecube?sslmode=disable"},
    }
    for _, tc := range cases {
        t.Run(tc.name, func(t *testing.T) {
            for k, v := range tc.env {
                t.Setenv(k, v)
            }
            cfg, err := Load()
            if tc.wantErr == "" {
                if err != nil {
                    t.Fatalf("期望成功, got %v", err)
                }
                if !strings.Contains(cfg.FinanceDSN(), tc.wantDSN) {
                    t.Errorf("FinanceDSN = %q, 应含 %q", cfg.FinanceDSN(), tc.wantDSN)
                }
                if cfg.Pool.MaxOpenConns != 16 || cfg.Pool.ConnMaxIdleTime.String() != "5m0s" {
                    t.Errorf("池默认值不对: %+v", cfg.Pool)
                }
                return
            }
            if err == nil || !strings.Contains(err.Error(), tc.wantErr) {
                t.Fatalf("期望错误点名 %s, got %v", tc.wantErr, err)
            }
        })
    }
}

两张表对着一张表：用例里「别名 DB_PASSWORD / POSTGRES_DSN 不算数」两行，就是讲义 2 的反面名单在测试里的投影——config 只认变量表不是口号，是一条会红的断言。想再补一行「HomeosDSN() 含 search_path=homeos」的拼装用例？加一列 wantHome，三分钟的事，判据不拦你。

常见坑（新手 100% 会踩）

坑现象正确姿势
顺手写 DB_PASSWORD=... / POSTGRES_DSN=... 别名config 报「缺少必填变量 DB_PASS / DB_NAME」——值明明在 env 里躺着，永远没人读改 env 对齐变量表的名字；不许给 config 加别名门。报错点名真变量名就是在教育你
把 DB_PASS="" 当「本机没口令」放过空口令带病连库，错误现场从「启动失败」漂移到「认证失败」，排查绕远路空串一律当缺失：口令必填、无默认，教学库的口令也进 .env
以为不配池 = 有默认好值MaxOpenConns=0 是不限、MaxIdleConns=2 是不留库存——一阵并发打爆 max_connections，第二波流量全在重握手四条 Set 显式写出（16/8/30m/5m）；每条治什么病见讲义 4 的表
ConnMaxLifetime 留 0「永生」或设得比链路空闲超时还长LB/防火墙夜里悄悄掐线，池里挂着半死连接，第一个请求撞超时轮换周期短于链路上任何一侧的空闲超时；到期只影响新请求拿连接，在途查询不被腰斩
MaxOpenConns 拍脑袋设 200「稳」应用侧潇洒，Postgres 侧每连接一份内存 + 会话槽互抢，库先死上限从库侧容量倒算：家用单体 16/条、两条连接 + 运维余量，离 100 远着呢
AUTO_MIGRATE 靠注释和自觉维持有人 copy 别人的 .env 把它设成 true，AutoMigrate 半夜建表——迁移链与物理表结构分叉，明天全链重放判据当场作废门禁进 config：读到 true 拒绝启动，进程级拦截，绕不过
手拼 DSN「就留 main 这一处」两处拼装点 → 一处加 search_path 忘了另一处 → 两条连接口径漂移；测试与生产各连各的今天全收进 config；grep 验收「postgres:// 拼装点仅一处」常驻检查
拿 homeos 连接 join finance 表图省事跨 schema join 一旦出生，两条链独立重放的判据就废了，模块边界名存实亡两条连接是两个世界；跨域调用收在 platform 接口后面（S4 的 FamilyDirectory 形状）

术语一句话解释
DSN连接串：postgres://用户:口令@主机:端口/库?sslmode=…&search_path=…（D1 认脸、D2 用它连库、今天起由 config 独占拼装）

必填 vs 默认猜不得的（DB_HOST/DB_USER/DB_PASS/DB_NAME）缺失即拒启；怎么跑都行的（DB_PORT/DB_SSLMODE/PORT/GIN_MODE）给默认
别名禁令POSTGRES_DSN / DB_PASSWORD / SERVER_PORT / MYSQL_DSN 均反面示范，config 一律不认——配了等于没配
连接池养一小批长连接反复复用，摊薄 TCP/认证/TLS 握手成本；Go 的 database/sql 自带池
MaxOpenConns保险丝：同时在用的连接上限；零值 0 = 不限，必设（本站 16）
MaxIdleConns库存：闲时保留的连接数，库默认只 2（本站 8）

ConnMaxIdleTime回收：闲太久主动退场——治「隔夜僵尸」（本站 5m）
AUTO_MIGRATE 门禁恒关的执法版：config 加载到 true 直接拒绝启动，兑现 D2 的预告
一个进程两套连接homeos / finance 各一条（各配各的池）；不跨 schema join，跨域走 platform 接口；迁移专属账号 homeos_app/finance_app 不归应用用
