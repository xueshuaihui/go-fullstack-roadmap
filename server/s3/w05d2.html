GORM 基础：模型 tag 与 AutoMigrate 的边界

昨天库立起来了，今天让 Go 摸到它：装 GORM 与 postgres 驱动，落盘 platform/db.Open，给 S1·D3 的三个 model 补上 gorm tag。今天的重头戏其实是一场对照实验——亲眼看一次 AutoMigrate 干了什么，然后说清为什么本站永远不用它建表。

知识讲义

1. GORM 是什么、不是什么

GORM 是 Go 最流行的 ORM：把 struct 映射到表、把方法调用翻译成 SQL。它是 SQL 的包装层，不是替代品——本站的用法是「GORM 管 CRUD，DDL（建表/改表）归迁移」。S2 里 repo 接口后面站着内存 map，从 S3·D6 起站着 GORM，接口不变。

可跑 · 仓库根执行cd server
go get gorm.io/gorm
go get gorm.io/driver/postgres
cd ..

2. 模型 tag：struct 字段与表列的对照表

GORM 默认把 CamelCase 字段映射成 snake_case 列（PasswordHash → password_hash）。默认虽好，本站仍然每列显式写 tag——教学期少一层魔法，排错时不用背约定。三个要点：

tag 写法作用
gorm:"column:family_id"显式钉死列名，与迁移 SQL 一一对得上
gorm:"column:id;primaryKey"主键标记；First(&x, id) 这类快捷查询按它找
json:"-"与 GORM 无关但与今天有关：password_hash 这类字段永不出现在响应体里（S2 的 DTO 纪律，模型层再上一道保险）

另一个必须显式的东西是表名。本站双 schema，表的全名是 homeos.homeos_user 这种 schema 限定形式；靠连接串的默认 search_path「碰巧找对」不是本站风格，每个模型用 TableName() 方法把全名钉死：

片段 · 前置：model 包内，S1·D3 的 struct 上加方法func (User) TableName() string { return "homeos.homeos_user" }

3. 通用列在 Go 侧长什么样

S1·D3 的 model 只有业务字段；今天把 S3·D3 迁移里将出现的通用列补齐。deleted_at 用 GORM 的 gorm.DeletedAt 类型（内部是可空的 time），GORM 认得它、后面软删行为会围绕它展开（S3·D7 正式讲）；可空的外键列（family_id、deleted_by）用指针 *int64——S1·D2 讲过：指针可以是 nil，正好表达 SQL 的 NULL。

4. AutoMigrate：一次对照实验

db.AutoMigrate(&User{}) 会对比模型与现状，自动生成并执行 DDL。它很能干：建表、补缺失的列、加索引。它也很危险：

AutoMigrate 的行为为什么在本站是事故源
只加不减：删字段、改字段名不会删列库里悄悄积累僵尸列，没人说得清哪列还活着
类型变更保守且不可预期改 tag 后到底 ALTER 成什么，取决于版本与现状，无从事先 review
没有版本、没有回滚、没有执行记录出了问题只能人肉对表；迁移文件是 git 里可 review、可回放的账本，它不是
每个环境各自「迁移」一次开发库、测试库、生产库的表结构漂移，正是「我这能跑」的根源

本站纪律（背下来）：建表权只在 migrations/；GORM 只做 CRUD，不碰 DDL；环境变量里预留的 AUTO_MIGRATE 开关恒为 false——S3·D11 的 config 加载到 true 会直接拒绝启动。今天你会亲手跑一次 AutoMigrate 看它建表，然后 down -v 把库重置，让表「重新从迁移出生」（明天）。

步骤 1 · platform/db 包

完整 · server/internal/platform/db/db.gopackage db

import (
    "fmt"

    "gorm.io/driver/postgres"
    "gorm.io/gorm"
    "gorm.io/gorm/logger"
)

// Open 建立 GORM 连接并 Ping 一次——连不上就当场报错，别等第一条查询才发现。
// TranslateError 把驱动方言错误翻译成 GORM 的统一哨兵（如唯一约束冲突 →
// gorm.ErrDuplicatedKey），上层 repo 才好映射成错误码表里的 1006。
// 注意：这里绝不出现 AutoMigrate。建表权只在 migrations（S3·D3 接入）。
func Open(dsn string) (*gorm.DB, error) {
    gdb, err := gorm.Open(postgres.Open(dsn), &gorm.Config{
        TranslateError: true,
        Logger:         logger.Default.LogMode(logger.Warn), // 学习期调试可临时改 logger.Info 看 SQL
    })
    if err != nil {
        return nil, fmt.Errorf("open db: %w", err)
    }
    sqlDB, err := gdb.DB()
    if err != nil {
        return nil, fmt.Errorf("get sql.DB: %w", err)
    }
    if err := sqlDB.Ping(); err != nil {
        return nil, fmt.Errorf("ping db: %w", err)
    }
    return gdb, nil
}

连接池四参数（MaxOpen/MaxIdle 等）今天不配——S3·D11 连 config 一起收口，一次讲透。

步骤 2 · 无库即跳过的连接测试

完整 · server/internal/platform/db/db_test.gopackage db

import (
    "fmt"
    "os"
    "testing"
)

// testDSN 从 DB_* 环境变量拼 DSN；没配就 Skip——没有数据库的机器上 make test 依然全绿，
// 真库测试在起了 compose 的开发机上跑。DSN 拼装 S3·D11 会收进 config，今天测试里先手工拼。
func testDSN(t *testing.T) string {
    t.Helper()
    if os.Getenv("DB_NAME") == "" {
        t.Skip("未设置 DB_NAME，跳过真库测试")
    }
    return fmt.Sprintf("postgres://%s:%s@%s:%s/%s?sslmode=%s",
        os.Getenv("DB_USER"), os.Getenv("DB_PASS"),
        os.Getenv("DB_HOST"), os.Getenv("DB_PORT"),
        os.Getenv("DB_NAME"), os.Getenv("DB_SSLMODE"))
}

func TestOpenPing(t *testing.T) {
    if _, err := Open(testDSN(t)); err != nil {
        t.Fatalf("Open: %v", err)
    }
}

步骤 3 · 三个 model 补通用列与 tag（以 User 为例，Family/Member 同样补齐）

完整 · server/internal/homeos/model/user.go（覆盖 S1·D3 版本的字段区）package model

import (
    "time"

    "gorm.io/gorm"
)

// User 全局账号（身份表）。通用列与 S3·D3 的迁移一一对应。
type User struct {
    ID           int64          `gorm:"column:id;primaryKey" json:"id"`
    FamilyID     *int64         `gorm:"column:family_id" json:"family_id"` // 身份表例外：恒 NULL，归属记录在 homeos_member
    Phone        string         `gorm:"column:phone" json:"phone"`
    PasswordHash string         `gorm:"column:password_hash" json:"-"`     // 哈希永不出响应体；S4 注册起才写入
    Nickname     string         `gorm:"column:nickname" json:"nickname"`
    CreatedAt    time.Time      `gorm:"column:created_at" json:"created_at"`
    UpdatedAt    time.Time      `gorm:"column:updated_at" json:"updated_at"`
    DeletedAt    gorm.DeletedAt `gorm:"column:deleted_at" json:"-"`        // 软删标记；S3·D7 正式讲
    DeletedBy    *int64         `gorm:"column:deleted_by" json:"deleted_by"`
    Version      int            `gorm:"column:version" json:"version"`     // 乐观锁：写一次 +1
}

func (User) TableName() string { return "homeos.homeos_user" }

Family（homeos.homeos_family）与 Member（homeos.homeos_member）照同样式补齐通用列与 tag；业务字段明天写迁移时再对账。注意 DeletedAt 的 tag 里不加 index——加索引是 DDL，DDL 归迁移：模型 tag 里任何会驱动建表的修饰都是 AutoMigrate 思维，本站清除。

步骤 4 · 对照实验：AutoMigrate 建一次表，然后推倒

完整 · server/playground/automigrate/main.go（独立 go.mod 的沙盒，不进主模块）package main

import (
    "fmt"
    "os"

    "gorm.io/driver/postgres"
    "gorm.io/gorm"
)

type Demo struct {
    ID   int64  `gorm:"column:id;primaryKey"`
    Name string `gorm:"column:name;index"`
}

func main() {
    dsn := os.Getenv("DEMO_DSN")
    gdb, err := gorm.Open(postgres.Open(dsn), &gorm.Config{})
    if err != nil {
        panic(err)
    }
    if err := gdb.AutoMigrate(&Demo{}); err != nil {
        panic(err)
    }
    fmt.Println("AutoMigrate 完成，去 psql 里 \d public.demos 看看它建了什么")
}

常见坑（新手 100% 会踩）

坑现象正确姿势
tag 写在反引号外/用错引号tag 不生效，列名对不上，查询报 column ... does not existtag 必须是字段后紧跟的反引号字符串：`gorm:"column:x"`；go vet 能抓一部分
可空列用了 int64NULL 读进来变 0，「没家庭」和「家庭 id=0」分不清可空一律指针 *int64；S1·D2 的指针语义今天落地
DeletedAt 用 time.TimeGORM 不认，软删行为全失效用 gorm.DeletedAt（可空 time 的包装）
忘写 TableName()GORM 按复数约定找 users 表，报 relation 不存在每个模型显式 TableName() 返回 schema 限定全名
把真库测试写死没起 compose 的机器（或将来的 CI）上 make test 全红环境不齐就 t.Skip——「无库也绿」本身就是判据
用 %v 包装连接错误上层 errors.Is 断链，认不出错误类型一律 %w（S1·D4 的老纪律，DB 层同样适用）
AutoMigrate「就用这一次」表结构与迁移账本对不上，S3·D3 的迁移撞上已存在的表实验完立刻 down -v 重置；主模块代码里连 AutoMigrate 这个词都不许出现

今日名词卡

术语一句话解释
ORM对象关系映射：struct ↔ 表、字段 ↔ 列、方法调用 ↔ SQL。GORM 是 Go 生态最主流实现
gorm tag字段级元数据：列名、主键、默认值。本站只写「映射类」tag，不写「建表类」tag
TableName()模型方法，返回表全名；本站一律 schema 限定（homeos.homeos_user）
gorm.DeletedAt可空时间戳包装；GORM 见到它就启用软删语义（S3·D7 正式讲）
DDL / CRUD定义结构的语句（CREATE/ALTER/DROP）与读写数据的语句（增查改删）。本站：DDL 归迁移，CRUD 归 GORM
AutoMigrateGORM 的自动改表能力；只加不减、无版本无回滚，本站禁用（今天对照实验后关闭）
TranslateErrorGORM 配置：把驱动方言错误翻译成统一哨兵（如 gorm.ErrDuplicatedKey），供上层映射 1006
Ping连接自检：拿到连接后立刻确认「真的通」。连不上就启动失败，别带病营业
t.Skip测试的条件跳过：环境不齐时不算失败也不算通过，仓库保持绿
search_pathPostgres 的 schema 查找路径；本站不依赖它，表名全 schema 限定（迁移连接里它另有用途，S3·D3 见）

卡壳时查什么

正文自足，只有两种情况出去查：

  • GORM tag 或 API 细节：GORM 官方文档（可选，查 Model Declaration 与 Connect 两节即可）。
  • 指针与 nil 的语义模糊了：回看 S1·D2；struct 与方法回看 S1·D3。

repo 接口为什么值得抽、内存实现为什么留着当测试替身——S2·D4 讲过，S3·D6 换 GORM 实现时你会感谢那次讲解。
