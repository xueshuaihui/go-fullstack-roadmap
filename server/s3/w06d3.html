知识讲义

1. float 存钱的三宗罪

Go 的 float64、Postgres 的 DOUBLE PRECISION 都是 IEEE 754 二进制浮点。二进制小数只能精确表示 2 的负幂次组合，0.1 不在其中——它存进去的那一刻就已经是近似值。三笔债：

罪状现场
① 表示不精确0.1 + 0.2 == 0.30000000000000004；对账时「收入 − 支出 == 结余」这种天经地义的等式随机翻车
② 误差随聚合累积一万笔流水求和，每笔的微小误差全部叠加，报表合计与逐笔手工相加对不上——而且每次跑还可能不一样（求和顺序影响舍入）
③ 跨边界序列化漂移float 过 JSON、过字符串格式化、过前后端两种语言的解析器，每一跳都可能引入一次舍入；数据库里存的和页面上印的不是同一个数

「先用 float 把功能跑通，之后再换成整数分」——这是新手最常给自己画的饼。兑现时的真实账单：全表 ALTER + 每行乘 100 取整（历史误差已经写进数据，乘完也不是真值）+ 所有读写路径改类型 + 所有测试重写。金额的正确性没有增量路径，只有第 0 天的选择。今天就是第 0 天。

2. 本站金额纪律：*_cents BIGINT

方案是把钱当成「最小货币单位的整数」：人民币存分。19.99 元存 1999。整数运算在数学上精确、在硬件上快、在任何语言任何序列化格式里都无损。

层规矩
数据库列类型 BIGINT（8 字节有符号，上限约 9.2 × 1018 分 = 9.2 × 1016 元，家用记账一亿年也存不满）；列名必须以 _cents 结尾，让「这是分不是元」写在脸上
Go 侧int64，原样进出，不做任何浮点中转
APIJSON 里也是整数分（"amount_cents": 1999）；数字不加引号，前端 JS 的 Number 在 253 内无损，够用
展示层「分 → 元」的除法与格式化只发生在前端渲染的最后一刻；后端任何地方见到 / 100.0 都是纪律违规

为什么不用 Postgres 的 NUMERIC（精确小数）？它本身没毛病，毛病在 Go 侧：NUMERIC 没有原生对应类型，得引第三方 decimal 库或按 string 搬运，JSON、测试、聚合处处多一层转换。整数分是所有语言的最小公分母，零依赖零歧义。本站定死整数分。

3. 账户表：finance_0002_init_account

账户 = 钱的容器（银行卡、现金钱包、自定义）。设计上四个决定：

决定理由
family_id BIGINT NOT NULL账户永远是家庭私有，没有系统预置——与分类表（NULL=预置）语义相反，注意对比记忆
金额三列都是 *_cents BIGINTbalance_cents 当前余额、initial_balance_cents 建户初始额、credit_limit_cents 信用额度（非信用卡恒 0）；全部 NOT NULL DEFAULT 0，「没有值」和「值为零」在钱上必须是同一件事的反面——缺省即 0，不留 NULL 陷阱
不建任何跨 schema 外键「这张卡属于哪个成员」很想引用 homeos.homeos_member——不行。两个 code 的迁移链独立演进，跨 schema 外键会让 finance 的 down 依赖 homeos 的行，重放判据当场作废。跨域引用只存裸 id、由应用层保证（D5 立过的规矩，今天第一次真正遇到诱惑）
同名唯一：部分唯一索引 (family_id, name) WHERE deleted_at IS NULL「工资卡」在一个家庭里只能有一张（活着的）；软删后名字要让出来能重建——D3 部分索引的第二次应用。撞索引 → 1006

4. TranslateError 兑现日：撞唯一索引长什么样

D2 在 db.Open 里开了 TranslateError: true，今天第一次收利息：GORM 把 Postgres 的 23505（unique_violation）翻译成哨兵 gorm.ErrDuplicatedKey，repo 层用 errors.Is 一转就是 response.ErrConflict → 409 + 1006。没有 TranslateError 的话，你只能去 error 字符串里捞 "23505"——脆弱且丢人。周六的 Reorder、以后的账户/流水 repo，全靠这条链。

步骤 1 · 迁移 up

完整 · server/migrations/finance/finance_0002_init_account.up.sql-- finance 链第二条：账户。全站第一张带金额列的表——*_cents BIGINT 的纪律从这里立。
-- 无预置行：账户永远家庭私有，family_id NOT NULL（与分类表的 NULL=预置相反）。
-- 无跨 schema 外键：两个 code 的迁移链必须能各自独立 down/up。

CREATE TABLE finance.finance_account (
    id                     BIGSERIAL PRIMARY KEY,
    family_id              BIGINT NOT NULL,                -- 家庭私有，无预置
    name                   TEXT NOT NULL,                  -- 户名：工资卡 / 现金钱包…
    type                   TEXT NOT NULL DEFAULT 'custom'
                           CHECK (type IN ('bank', 'wallet', 'custom')),
    currency               TEXT NOT NULL DEFAULT 'CNY',     -- 教学期不做汇率，但列先立在
    balance_cents          BIGINT NOT NULL DEFAULT 0,      -- 当前余额（分）
    initial_balance_cents  BIGINT NOT NULL DEFAULT 0,      -- 建户初始额（分）
    credit_limit_cents     BIGINT NOT NULL DEFAULT 0,      -- 信用额度（分），非信用类恒 0
    is_default             BOOLEAN NOT NULL DEFAULT FALSE, -- 默认收付账户，每家庭至多一个（应用层保证）
    archived               BOOLEAN NOT NULL DEFAULT FALSE, -- 停用：不再出现在选择器，历史流水仍可筛
    created_at             TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at             TIMESTAMPTZ NOT NULL DEFAULT now(),
    deleted_at             TIMESTAMPTZ,
    deleted_by             BIGINT,
    version                INT NOT NULL DEFAULT 1
);

-- 同家庭内活账户不许重名；软删行让出名字（D3 部分索引的第二次应用）。
CREATE UNIQUE INDEX uq_finance_account_family_name
    ON finance.finance_account (family_id, name)
    WHERE deleted_at IS NULL;

-- 按家庭列账户是最高频查询，单列索引够用（表小，先不过度设计）。
CREATE INDEX idx_finance_account_family
    ON finance.finance_account (family_id);

步骤 3 · Account 模型

完整 · server/internal/finance/model/account.gopackage model

import (
    "time"

    "gorm.io/gorm"
)

// Account 账户：钱的容器。金额一律 int64 分（*_cents），全链路无 float。
// 照旧不写 index/uniqueIndex tag——DDL 的唯一权威是迁移文件（D2 的边界）。
type Account struct {
    ID                  int64          `gorm:"column:id;primaryKey" json:"id"`
    FamilyID            int64          `gorm:"column:family_id" json:"family_id"` // NOT NULL：非指针
    Name                string         `gorm:"column:name" json:"name"`
    Type                string         `gorm:"column:type" json:"type"`          // bank / wallet / custom
    Currency            string         `gorm:"column:currency" json:"currency"`
    BalanceCents        int64          `gorm:"column:balance_cents" json:"balance_cents"`
    InitialBalanceCents int64          `gorm:"column:initial_balance_cents" json:"initial_balance_cents"`
    CreditLimitCents    int64          `gorm:"column:credit_limit_cents" json:"credit_limit_cents"`
    IsDefault           bool           `gorm:"column:is_default" json:"is_default"`
    Archived            bool           `gorm:"column:archived" json:"archived"`
    CreatedAt           time.Time      `gorm:"column:created_at" json:"created_at"`
    UpdatedAt           time.Time      `gorm:"column:updated_at" json:"updated_at"`
    DeletedAt           gorm.DeletedAt `gorm:"column:deleted_at" json:"-"`
    DeletedBy           *int64         `gorm:"column:deleted_by" json:"-"`
    Version             int            `gorm:"column:version" json:"version"`
}

func (Account) TableName() string { return "finance.finance_account" }

对比记忆两处：FamilyID 在 User 里是 *int64（身份表恒 NULL，D2）、在 Category 里是 *int64（NULL=系统预置，D6）、在 Account 里是裸 int64（NOT NULL，永远有值）——指针与否跟着列语义走，不是随手抄。json tag 里金额字段直接叫 *_cents，API 与库表同名，中间不加翻译层。

步骤 4 · 约束测试：同名账户撞 1006 的地基

完整 · server/internal/finance/repository/account_constraint_test.gopackage repository

import (
    "context"
    "errors"
    "testing"

    "gorm.io/gorm"

    "homecube/internal/finance/model"
)

// 账户今天没有 repo（接口是 S6 的事），直接用 GORM 打表测约束本身。
func TestAccountFamilyNameUnique(t *testing.T) {
    gdb := openTestDB(t) // S3·D6 的 skip 助手，同包直接用
    ctx := context.Background()
    const famA, famB = int64(931), int64(932)
    t.Cleanup(func() {
        gdb.Unscoped().Where("family_id IN ?", []int64{famA, famB}).Delete(&model.Account{})
    })

    // ① famA 建「工资卡」：成功，金额列默认 0，version 默认 1
    first := model.Account{FamilyID: famA, Name: "工资卡", Type: "bank", Currency: "CNY",
        InitialBalanceCents: 10050, BalanceCents: 10050} // 100.50 元 = 10050 分
    if err := gdb.WithContext(ctx).Create(&first).Error; err != nil {
        t.Fatalf("create first: %v", err)
    }
    if first.Version != 1 || first.CreditLimitCents != 0 {
        t.Fatalf("默认值不对: version=%d credit_limit_cents=%d", first.Version, first.CreditLimitCents)
    }

    // ② famA 再建一张「工资卡」：撞部分唯一索引 → gorm.ErrDuplicatedKey（上层翻译成 1006 的地基）
    dup := model.Account{FamilyID: famA, Name: "工资卡", Type: "wallet", Currency: "CNY"}
    err := gdb.WithContext(ctx).Create(&dup).Error
    if !errors.Is(err, gorm.ErrDuplicatedKey) {
        t.Fatalf("同家庭同名应 ErrDuplicatedKey, got %v", err)
    }

    // ③ famB 建「工资卡」：成功——唯一范围是 (family_id, name)，不是全局 name
    other := model.Account{FamilyID: famB, Name: "工资卡", Type: "bank", Currency: "CNY"}
    if err := gdb.WithContext(ctx).Create(&other).Error; err != nil {
        t.Fatalf("跨家庭同名不该撞: %v", err)
    }

    // ④ 金额是无损整数：读回来一分不差（float 做不到这一点，这就是今天的全部意义）
    var back model.Account
    if err := gdb.WithContext(ctx).First(&back, first.ID).Error; err != nil {
        t.Fatalf("read back: %v", err)
    }
    if back.BalanceCents != 10050 {
        t.Fatalf("balance_cents = %d, want 10050", back.BalanceCents)
    }
}

常见坑（新手 100% 会踩）

坑现象正确姿势
金额用 float64 / DOUBLE PRECISION对账等式随机翻车，聚合合计每次跑不一样*_cents BIGINT + int64，一次建对没有回头路
列叫 balance，注释里写「单位分」三个月后自己都把 1999 当 1999 元花单位进列名：_cents 后缀是纪律不是风格
后端某处图方便写了 / 100.0展示层之外的地方冒出浮点，纪律破窗分→元只在前端渲染最后一刻；后端 grep 不到 100.0
金额列允许 NULL「没值」和「零元」两种语义纠缠，SUM/比较处处判空NOT NULL DEFAULT 0，钱的列没有 NULL 态
给账户表加 REFERENCES homeos.homeos_member(id)finance 的 down 从此看 homeos 的脸色，独立重放作废跨 code 只存裸 id，应用层保证一致
唯一索引忘了 WHERE deleted_at IS NULL软删过「工资卡」后重建同名，撞死人的旧行报 1006部分唯一索引只管活行（D3 的伏笔再兑现一次）
测试里断言 error 字符串含 "duplicate"驱动或语言环境一变测试就碎errors.Is(err, gorm.ErrDuplicatedKey)——TranslateError 就是为这个开的

今日名词卡

术语一句话解释
IEEE 754 浮点二进制近似小数；0.1 存不精确，是一切 float 存钱事故的根
整数分（*_cents）钱 = 最小货币单位的整数；列名带 _cents，Go 侧 int64，无损过一切边界
BIGINT8 字节有符号整数，上限 ~9.2×1018；存分够用一亿年
NUMERIC / DECIMAL数据库侧的精确小数；Go 无原生对应类型，本站不用
账户（account）钱的容器：bank / wallet / custom 三类；家庭私有（family_id NOT NULL）、无预置
initial_balance_cents建户初始额；余额 = 初始额 + 流水累计（S6 兑现这条等式）
部分唯一索引UNIQUE (family_id, name) WHERE deleted_at IS NULL：活行内不许重名
23505 / unique_violationPostgres 的唯一冲突错误码；TranslateError 把它翻译成 gorm.ErrDuplicatedKey
1006本站响应码表的「唯一冲突」：409 + 1006，由 ErrConflict 映射
跨 schema 外键禁令finance 的表不 REFERENCES homeos 的表；两个 code 必须能独立重放
