repo 纪律：每条查询带 family_id，越权读返 404

S3 判据里最硬的一条：「每条查询 WHERE family_id」。到目前为止你是在每个方法里手写这个条件——D6 的 List、D7 的软删三件套、D8 的 ListPage，写对了，但「靠自觉」的东西迟早漏。今天把它变成结构性的：收拢成 scoped/visible 两个 helper，repo 全量重构过一遍，从此裸拼 family_id 条件算违纪。另一半主题：跨家庭访问返回什么——答案是 404 + 1001，与「真不存在」完全同形，为什么不是 403，今天讲透，并用「先红后绿」证明你的测试真的有牙。

知识讲义

1. family_id 是租户边界，不是普通过滤条件

本站是多租户架构，租户就是家庭：每一行业务数据都属于且只属于一个家庭（预置行属于「无家庭」，全体共享只读）。这意味着 repo 层的每一条 SQL——不分读写、不分主次——都必须携带 family_id 条件。漏一条的后果不是「查询慢」或「结果多」，是别人家的账本出现在你的屏幕上，属于最严重的一类数据事故。这类隔离不能靠「每个方法都记得写」：人会忘，重构会丢，新方法会抄错对象。要靠结构——让「不带租户条件的查询」在代码里写不出来（或至少，一眼就能看出没经过 helper）。

2. 两个 helper：visible 管读，scoped 管写

D6 立过的规矩「读带预置、写只认本家庭」，今天物化成两个函数：

helper条件用在为什么
visible(db, familyID)(family_id = ? OR family_id IS NULL)一切读：List / GetByID / ListPage用户要看到自己的行 + 系统预置行；软删行由默认作用域自动排除，不用管
scoped(db, familyID)family_id = ?一切写：Update / SetArchived / SoftDelete / Restore / Reorder预置行是只读的公共财产，任何家庭的写操作都不许碰到它——条件里根本不出现 IS NULL 分支

两个必须是两个，不能合并成一个「智能」helper：读和写的可见范围本来就不同，合并的那一瞬间，你就要靠参数或注释区分两种语义——结构上的清晰就没了。helper 返回 *gorm.DB，链式起步：scoped(r.db.WithContext(ctx).Model(...), familyID).Where("id = ?", id)，family_id 永远是第一个进 where 的条件。

3. 越权读为什么返 404+1001，而不是 403

直觉上，「读别人家的东西被拒」似乎该返 403 Forbidden。错，而且错得很危险。对比两种响应告诉攻击者的信息：

响应攻击者听到的是
404 + 1001（本站）「这个 id 没有东西」——与 id 真不存在时一字不差。他无法区分「猜错了」和「猜对了但没权限」，遍历 id 得不到任何信号
403 + 1003「这个 id 存在，只是你没权限」——恭喜，你的接口变成了一台免费的存在性探测器：扫一遍 id 段就能画出全站的资源地图，为下一步攻击挑目标

所以本站纪律：凡是「跨家庭」撞出来的拒绝，读写一律 ErrNotFound → 404 + 1001，与真不存在同形。「同形」是关键词——两条路径的响应状态码、code、message 模板完全一致，连响应耗时的量级都不该有可辨差异。那 1003/403 留给谁？留给同家庭内部的权限问题：比如 S4 之后「成员角色不够，不能审批这笔预算」——此时资源的存在性对请求者本来就不是秘密，403 不泄漏任何额外信息。一句话：跨租户 → 装不存在；租户内越权 → 才谈 403。

S3 没有鉴权（S4 的事），currentFamilyID 桩固定返回 1——今天测「跨家庭」的方式是：测试代码往库里种一个 family_id=2 的行，然后以桩身份（家庭 1）去访问它。桩不桩的无所谓，repo 层的隔离纪律从第 0 天就是真的，S4 只是把「当前请求属于哪个家庭」从常量换成 token 解析。

4. 先红后绿：证明测试有牙

安全类测试有个特有的陷阱：它可能绿得毫无意义——比如断言写反、种子没种上、helper 根本没被走到，测试照样「通过」。所以隔离测试要多做一步验牙：

  1. 写完测试，跑绿（这是「后绿」）；
  2. 故意把被测的防线拆掉——比如把 visible 里的 family_id 条件临时注释掉；
  3. 再跑：测试必须变红，且红在预期的断言上（「跨家庭读应 ErrNotFound」而不是别处炸了）；
  4. 把防线装回去，再跑绿。

这一圈下来你才真正知道：这条测试守着这条防线。红过的测试才是资产，没红过的测试只是装饰。

步骤 1 · scope helper

完整 · server/internal/finance/repository/scope.gopackage repository

import (
    "gorm.io/gorm"
)

// visible 读路径的可见范围：本家庭的行 + 系统预置行（family_id IS NULL）。
// 软删行不需要在这里排除——模型带 gorm.DeletedAt，默认作用域自动追加 deleted_at IS NULL。
// 纪律：repo 的一切读查询必须从 visible 起步；绕过它的裸查询在 code review 里直接打回。
func visible(db *gorm.DB, familyID int64) *gorm.DB {
    return db.Where("(family_id = ? OR family_id IS NULL)", familyID)
}

// scoped 写路径的归属范围：只认本家庭。
// 刻意不含 OR family_id IS NULL——预置行是全体共享的只读财产，任何家庭的写都不许命中它。
func scoped(db *gorm.DB, familyID int64) *gorm.DB {
    return db.Where("family_id = ?", familyID)
}

步骤 3 · 跨家庭测试矩阵：七个方法一个不漏

完整 · server/internal/finance/repository/category_scope_test.gopackage repository

import (
    "context"
    "errors"
    "testing"

    "homecube/internal/finance/model"
    "homecube/pkg/response"
)

// 表驱动：读×2 + 写×5，全部用「别人家」的 familyID 去够 famA 的行，
// 统一断言 ErrNotFound——越权与不存在同形，这条纪律由这张表守着。
func TestCrossFamilyAlwaysNotFound(t *testing.T) {
    gdb := openTestDB(t)
    repo := NewGormCategoryRepo(gdb)
    ctx := context.Background()
    const famA, famOther = int64(941), int64(942)
    t.Cleanup(func() {
        gdb.Unscoped().Where("family_id = ?", famA).Delete(&model.Category{})
    })

    cat, err := repo.Create(ctx, famA, model.CategoryInput{Name: "隔离小白鼠", Kind: "expense"})
    if err != nil {
        t.Fatalf("create: %v", err)
    }

    cases := []struct {
        name string
        call func() error
    }{
        {"读/GetByID", func() error { _, e := repo.GetByID(ctx, famOther, cat.ID); return e }},
        {"读/ListPage 不泄漏", func() error {
            p, e := repo.ListPage(ctx, famOther, "", 100)
            if e != nil { return e }
            for _, c := range p.List {
                if c.ID == cat.ID { return errors.New("别家的行出现在我的分页里") }
            }
            return nil // ListPage 语义是「列我自己的」，不该报错，只断言不含 famA 的行
        }},
        {"写/Update", func() error {
            _, e := repo.Update(ctx, famOther, cat.ID, model.CategoryInput{Name: "抢来的", Kind: "expense"}, cat.Version)
            return e
        }},
        {"写/SetArchived", func() error { return repo.SetArchived(ctx, famOther, cat.ID, true, cat.Version) }},
        {"写/SoftDelete", func() error { return repo.SoftDelete(ctx, famOther, cat.ID, 42) }},
        {"写/Restore", func() error { return repo.Restore(ctx, famOther, cat.ID, 42) }},
        {"写/Reorder", func() error {
            return repo.Reorder(ctx, famOther, []int64{cat.ID})
        }},
    }
    for _, tc := range cases {
        t.Run(tc.name, func(t *testing.T) {
            if err := tc.call(); !errors.Is(err, response.ErrNotFound) {
                t.Fatalf("跨家庭应 ErrNotFound（→404+1001，与不存在同形）, got %v", err)
            }
        })
    }

    // 收尾：七次攻击过后，行必须毫发无损（version 没被动过、没被软删）
    alive, err := repo.GetByID(ctx, famA, cat.ID)
    if err != nil || alive.Version != cat.Version || alive.Archived {
        t.Fatalf("行被跨家庭操作改动了: %v %+v", err, alive)
    }
}

两个细节：① Reorder 的签名以你 S2·D6 定下的为准——原则不变：只要 id 列表里混进别家的行，整个事务回滚并 ErrNotFound（D6 的测试已有同家庭版，这里是跨家庭版）；② ListPage 那一格不断言报错：列表接口的语义是「列我自己的」，别家的行根本不在结果集里，无错可报——这正是「同形」的另一面：连「你请求了一个不存在于你世界的东西」这件事都不该有痕迹。方法名、参数如与你本地签名有出入，以本地为准，断言不变。

步骤 4 · HTTP 层同形验证：404 + 1001

完整 · server/internal/finance/repository/category_scope_http_test.gopackage repository

import (
    "encoding/json"
    "net/http"
    "net/http/httptest"
    "strconv"
    "testing"

    "homecube/internal/finance/model"
    "homecube/internal/finance/service"
)

// 打穿 handler 的一层验证：桩身份是家庭 1，去读家庭 2 的行——
// 必须拿到与「id 不存在」完全同形的 404 + 1001。
// service/router 的构造函数以你 S2·D4 定下的签名为准，这里展示断言的形状。
func TestGetOtherFamilyCategoryHTTP404(t *testing.T) {
    gdb := openTestDB(t)
    const famB = int64(2) // 桩 currentFamilyID 恒返 1，所以 2 就是「别家」
    seed := model.Category{FamilyID: &famB, Name: "别家的分类", Kind: "expense"}
    if err := gdb.Create(&seed).Error; err != nil {
        t.Fatalf("seed: %v", err)
    }
    t.Cleanup(func() { gdb.Unscoped().Delete(&seed) })

    r := setupRouter(service.NewCategoryService(NewGormCategoryRepo(gdb))) // 名字以本地为准

    do := func(id int64) (*httptest.ResponseRecorder, struct{ Code int `json:"code"` }) {
        w := httptest.NewRecorder()
        req := httptest.NewRequest(http.MethodGet, "/api/finance/categories/"+strconv.FormatInt(id, 10), nil)
        r.ServeHTTP(w, req)
        var body struct{ Code int `json:"code"` }
        json.Unmarshal(w.Body.Bytes(), &body)
        return w, body
    }

    // ① 越权读：404 + 1001
    w, body := do(seed.ID)
    if w.Code != http.StatusNotFound || body.Code != 1001 {
        t.Fatalf("越权读应 404+1001, got %d+%d", w.Code, body.Code)
    }
    // ② 同形：与「id 根本不存在」的响应一字不差（状态码与 code；message 同模板）
    w2, body2 := do(999999999)
    if w2.Code != w.Code || body2.Code != body.Code {
        t.Fatalf("越权读与不存在必须同形: %d+%d vs %d+%d", w.Code, body.Code, w2.Code, body2.Code)
    }
}

这个测试跨了包（repository 测试里 import service 与路由装配），图的是 openTestDB 现成。若你的分层洁癖发作，把它挪去 handler 包、顺手抽一个公共的测试库助手——更好的家，但别为了挪它把今天的主线拖过 30 分钟。

常见坑（新手 100% 会踩）

坑现象正确姿势
helper 只在「新方法」里用，旧方法懒得改半仓 helper 半仓手拼，等于没有纪律今天就全量重构：测试一字不改照样绿，正是重构安全的证明
把 visible/scoped 合成一个带开关的 helper调用处靠 bool 参数决定读语义还是写语义——传错一次就是事故两个函数两个名字；写路径的函数体里根本不存在 IS NULL
事务回调里对 r.db 套 scoped条件加了，但语句在事务外裸奔（D7 的坑换皮重演）scoped 的第一个参数在事务里必须是 tx
越权读返 403+1003「更语义化」接口变成存在性探测器，id 段一扫资源地图全出跨租户一律 ErrNotFound → 404+1001，与真不存在同形
同形只同了状态码，message 写着「无权访问」body 一读就穿帮，同形装了个寂寞状态码、code、message 模板全部走 ErrNotFound 同一条映射链
跨家庭测试没验牙就收工断言写反/种子没种上也照样绿，防线其实是纸糊的先红后绿：拆一次 Where 看它红，装回去看它绿
用「查出来再判断 familyID」代替 where 条件别家的行已经进了内存，日志、metrics、序列化处处可能漏隔离必须发生在 SQL 里：行根本不出数据库，才叫隔离

今日名词卡

术语一句话解释
多租户（multi-tenancy）一套库表服务 N 个互相隔离的租户；本站租户 = 家庭，边界 = family_id
scope helper把租户条件物化成函数（visible/scoped），让每条查询从它起步——纪律变结构
读范围 vs 写范围读 = 本家庭 + 预置（OR IS NULL）；写 = 只认本家庭。两个 helper，不许合并
同形响应越权读与真不存在的 404+1001 一字不差；不给攻击者存在性信号
存在性泄漏403 等于承认「资源存在」；扫 id 段即可绘制资源地图
1003 / 403本站留给同家庭内部的权限拒绝（S4 起）；跨租户永远不用它
先红后绿（验牙）故意拆掉防线看测试变红再装回——证明测试真的守着那条防线
重构改结构不改行为；验收标准 = 既有测试一字不改照样绿
表驱动测试一张 cases 表 × 一个断言循环；七个方法的隔离纪律一处写清
SQL 层隔离租户条件必须进 where，让别家的行根本不出数据库；查出来再过滤不算隔离

卡壳时查什么

正文自足，只有两种情况出去查：

  • GORM 自定义作用域（scopes）的写法：GORM · Scopes（可选——本站的两个 helper 就是它的手工版，看懂了可以尝试换成 Scopes() 风格，行为不变）。
  • 行级安全（RLS）这类数据库级隔离：今天不碰——应用层 helper 是教学与生产的主流做法；Postgres RLS 留给你好奇时自查，本站 S8 部署前都不引入。

站内回看：「读带预置写只认本家庭」的原始表述在 S3·D6；错误码表（1001/1003）与哨兵错误映射在 S1·D4；事务回调里用 tx 的纪律在 S3·D7。
