设置：主题三态与日期格式

A8 只有两条接口，但它们是「壳之所以是壳」的最后一公里：GET/PUT /api/homeos/settings。个人偏好两项——主题三态（light / dark / system）与日期格式——落进 homeos_settings 表。这条线的红线只有一句：必须是活配置，禁止死 UI：设置页上摆出来的每一项，都必须存得下、读得回、且真的被消费（主题令牌与日期渲染在前端壳 F5 那边消费，服务端负责「存了就算数」）。

↑ 这四条是「学习目标」。页面底部还有 5 条「完成检查」，全部勾掉今天才算结束。

知识讲义

1. 主题三态：存意图，不存效果

主题不是「深色开/关」两个值，而是三个：light、dark、system（跟随设备）。关键区别在服务端存什么：存 用户意图（我选了跟随系统），而不是当下效果（现在是深色）。设备切了深浅色，意图不变，效果由前端壳按 system 重新解析——服务端如果存「效果」，每次设备切换都得回写一次设置，荒谬且竞态。

为什么落服务端而不是纯本地？多端同步：手机选了深色，平板登录同一个成员也得是深色。前端壳的主题令牌消费这条设置（F5 的判据之一），服务端只保证「存得下、读得回、值合法」。

2. 日期格式：白名单，双保险

日期格式同样封闭枚举：YYYY-MM-DD / DD/MM/YYYY / MM-DD-YYYY 三值。校验两层：Go 侧白名单（拦下 400 + 1004，错误信息友好）+ DB CHECK（拦下绕过代码的写入）。昨天通知分型刚上过同款双保险，今天是第二次用——封闭枚举在本站的标配姿势。

设置影响展示，不影响存储与传输：接口里的日期字段永远是 RFC3339 时间戳、金额永远是 *_cents 整数。date_format 只告诉前端「给人看的时候怎么排」——谁要是拿它去改服务端输出格式，报表的机器可读性就完了。

3. GET 永不 404：设置永远有值

成员从没打开过设置页时，表里没有他的行。GET 返回 404 吗？不——返回默认值 + version: 0。「设置」这个资源的语义是永远存在的（没选过 = 用默认），404 会逼前端写一套「先 GET、404 就当默认」的分支，毫无收益。version: 0 是暗号：客户端拿着它来 PUT，服务端见 0 就知道走「建行」路径。

4. PUT 的三条路径

入参 version库里状态动作失败口径
0无行建行（version=1）并发撞唯一键 → 409 + 1009
n > 0有行且 version=n更新（version+1）—
n > 0有行但 version≠n拒绝409 + 1009（S6 乐观锁原样搬）

步骤 2 · service

完整 · server/internal/homeos/service/settings.gopackage service

import (
    "context"
    "errors"

    "gorm.io/gorm"
    "gorm.io/gorm/clause"

    "homecube/internal/homeos/model"
    "homecube/pkg/response"
)

var themes = map[string]bool{"light": true, "dark": true, "system": true}
var dateFormats = map[string]bool{"YYYY-MM-DD": true, "DD/MM/YYYY": true, "MM-DD-YYYY": true}

type SettingsService struct{ db *gorm.DB }

func NewSettingsService(db *gorm.DB) *SettingsService { return &SettingsService{db: db} }

// Get 无行时返回默认值 + version 0，永不 404。
func (s *SettingsService) Get(ctx context.Context, familyID, memberID int64) (*model.Settings, error) {
    var st model.Settings
    err := s.db.WithContext(ctx).
        Where("family_id = ? AND member_id = ?", familyID, memberID).First(&st).Error
    if errors.Is(err, gorm.ErrRecordNotFound) {
        return &model.Settings{FamilyID: familyID, MemberID: memberID,
            Theme: "system", DateFormat: "YYYY-MM-DD", Version: 0}, nil
    }
    return &st, err
}

// Put 三条路径：version=0 建行；匹配则更新；不匹配 1009。
func (s *SettingsService) Put(ctx context.Context, familyID, memberID int64, theme, dateFormat string, ver int) (*model.Settings, error) {
    if !themes[theme] || !dateFormats[dateFormat] {
        return nil, response.ErrInvalidParam // 400 + 1004：白名单第一层
    }
    if ver == 0 {
        st := model.Settings{FamilyID: familyID, MemberID: memberID, Theme: theme, DateFormat: dateFormat, Version: 1}
        err := s.db.WithContext(ctx).
            Clauses(clause.OnConflict{Columns: []clause.Column{{Name: "family_id"}, {Name: "member_id"}}, DoNothing: true}).
            Create(&st).Error
        if err != nil { return nil, err }
        if st.ID == 0 { return nil, response.ErrVersionConflict } // 并发建行：409 + 1009
        return &st, nil
    }
    res := s.db.WithContext(ctx).Model(&model.Settings{}).
        Where("family_id = ? AND member_id = ? AND version = ?", familyID, memberID, ver).
        Updates(map[string]any{"theme": theme, "date_format": dateFormat,
            "version": gorm.Expr("version + 1"), "updated_at": gorm.Expr("now()")})
    if res.Error != nil { return nil, res.Error }
    if res.RowsAffected == 0 { return nil, response.ErrVersionConflict }
    return s.Get(ctx, familyID, memberID)
}

response.ErrVersionConflict 若在你本地叫别的名字（S1 错误码卡落的 1009 哨兵），以本地为准；判据不变：版本不匹配 → 409 + 1009，且响应里看得出两个版本号（S6 的双版本口径）。

步骤 3 · handler 与路由

片段 · server/internal/homeos/handler/settings.go// GET：直接回 service.Get 的结果（含默认值兜底）。
// PUT body：{"theme":"dark","date_format":"DD/MM/YYYY","version":0}
func (h *SettingsHandler) Put(c *gin.Context) {
    var req struct {
        Theme      string `json:"theme" binding:"required"`
        DateFormat string `json:"date_format" binding:"required"`
        Version    int    `json:"version"`
    }
    if err := c.ShouldBindJSON(&req); err != nil {
        response.Fail(c, http.StatusBadRequest, response.CodeInvalidParam, "参数错误")
        return
    }
    st, err := h.svc.Put(c.Request.Context(), c.GetInt64("familyID"), c.GetInt64("memberID"),
        req.Theme, req.DateFormat, req.Version)
    if err != nil { response.FailErr(c, err); return }
    response.OK(c, st)
}
// 路由：homeos.GET("/settings", sh.Get) / homeos.PUT("/settings", sh.Put)

常见坑（新手 100% 会踩）

坑现象正确姿势
主题做成布尔 is_dark「跟随系统」没地方放，设备切换后设置页与实际不一致三态枚举，存意图不存效果
GET 无行返回 404前端被迫写「404 当默认」分支，新用户首屏多一次失败请求默认值 + version 0，永不 404
PUT 不做 version 校验手机与平板同时改设置，后写的静默覆盖先写的乐观锁三路径，冲突 409 + 1009
枚举只靠前端下拉框curl 一发 theme=neon 就进库，前端渲染成白板Go 白名单 + DB CHECK 双保险
按 date_format 改服务端日期输出报表与接口时间格式随人而变，机器解析全崩传输永远 RFC3339；格式设置只管展示层
设置存成家庭级一行一人改深色全家变深色(family_id, member_id) 一人一行；家庭级设置是明天的币种那类

今日名词卡

术语一句话解释
活配置存得下、读得回、被真实消费；反面是「死 UI」——摆了控件但没人读
主题三态light / dark / system；system = 跟随设备，服务端存意图
白名单校验封闭枚举逐项比对；不在名单 → 400 + 1004
version 0 暗号「我还没行，来建」；PUT 见 0 走建行路径
DoNothing upsert并发建行时不覆盖对方，靠 RowsAffected/ID 判断撞没撞，撞了回 1009
展示与传输分离date_format 只影响前端渲染；接口日期永远 RFC3339
