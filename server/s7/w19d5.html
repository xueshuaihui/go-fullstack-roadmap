财务侧接入：预算周期与周期记账规则注册

到期中心自家的提醒、待办都通了，今天轮到这个架构真正要证明的事：另一个模块把到期项交进来。财务面有两类天然带日期的东西——预算周期（周期快结束该提醒）与周期记账规则（下次执行日该上日历）。接入手法只有一条纪律：finance 只认 platform 的 DueRegistry 接口，不 import homeos，不 select homeos_*；实现由 main.go 装配时塞进来。

↑ 这四条是「学习目标」。页面底部还有 5 条「完成检查」，全部勾掉今天才算结束。

知识讲义

1. 两个接入点，注册什么

源对象注册时机Kinddue_at撤销时机
预算（周期预算）创建 / 编辑周期时budget_cycle周期结束日（如月度预算的月末）预算删除 / 改周期（改 = 同键再 Register）
周期记账规则创建 / 编辑 / 重新启用时recurring_entry下次执行日规则停用 / 删除 → Revoke

payload 里照 S7·D15 的约定塞两样：member_id（触发时通知谁——规则的创建者）与 deep_link（日历详情「前往源对象」用，S7·D18 消费）。

2. 可见性归到期中心，执行归源面

最容易想歪的一点：注册进到期中心，不等于到期中心替 finance 执行自动入账。分工一句话：

  • 执行（到日子真的记一笔账）：仍是 finance 自己在 S6 建的进程内调度，靠 client_request_id 幂等键防重复入账——那套原样不动。
  • 可见性（日历上有这一格、到期前一天有提醒）：今天注册进到期中心的部分。

为什么不让调度器统一执行？因为「执行」是业务语义（记账要开事务、要幂等、要算余额），塞进到期中心就得让 homeos 懂 finance 的账——跨模块纪律瞬间破功。到期中心永远只做三件事：登记、鸣锣（通知）、记账台账（注册表状态）。

3. 跨模块注册的位置：提交之后

S7·D15 里 homeos 自家注册用 WithTx 进事务；finance 不行——它的实现隔着接口，事务句柄传不过去（也不该传：那是 homeos 的表）。姿势改为：

片段 · finance 侧的时序① finance 自己的事务：写 finance_recurring 行 → 提交
② 提交后：due.Register(...)
③ Register 失败：只写结构化日志（S5），不让请求失败——
   规则已建成是事实；下次编辑会再 Register（upsert 幂等），自然补齐

「先业务后台账」与昨天完成回写是同一个哲学：台账差异可补，业务事实不可回滚。

4. 接口的第二个红利：不碰 DB 也能测协作

finance 的 service 只依赖接口，测试里塞一个记录调用的假实现，就能断言「创建规则后 Register 被调了一次、Kind 与 due_at 对不对」——全程不需要数据库，更不需要 homeos 出生。直查表的代码永远测不出这种「协作对不对」。

步骤 1 · finance 侧接线（以周期记账为例，预算同款）

你的 RecurringService 与规则 struct 是 S6 亲手写的，字段名（NextRunAt、金额、启停标志、日志句柄）以你本地为准。下面给出接线的标准形状，把类型名换成你本地的即可——判据在步骤 3 的测试里，不在抄写里。注意 import 列表：只有 platform，没有 homeos，跨模块纪律由编译器站岗。

完整 · 接线标准形状（RecurringRule 换成你 S6 的规则类型）package service

import (
    "context"
    "fmt"

    "homecube/internal/platform/dueregistry"
)

// RecurringService 增加一个字段（S6 的原 struct 上加）：
//   due dueregistry.DueRegistry
// 构造函数多收一个参数，main.go 装配时注入。

func (s *RecurringService) registerDue(ctx context.Context, ruleID int64, rule *RecurringRule) {
    err := s.due.Register(ctx, dueregistry.Entry{
        FamilyID:     rule.FamilyID,
        SourceSystem: "finance",
        SourceID:     ruleID,
        Kind:         dueregistry.KindRecurringEntry,
        Title:        fmt.Sprintf("周期记账 · %s", rule.Title),
        DueAt:        rule.NextRunAt,
        Payload: map[string]any{
            "member_id": rule.CreatedBy,
            "deep_link": fmt.Sprintf("pages/finance/recurring/detail?id=%d", ruleID),
        },
    })
    if err != nil {
        // 先业务后台账：规则已提交，注册失败只写日志（S5 结构化日志），下次编辑自然补齐
        s.log.Error("due register failed", "rule_id", ruleID, "err", err)
    }
}

func (s *RecurringService) revokeDue(ctx context.Context, ruleID int64) {
    if err := s.due.Revoke(ctx, "finance", ruleID, dueregistry.KindRecurringEntry); err != nil {
        s.log.Error("due revoke failed", "rule_id", ruleID, "err", err)
    }
}

// 在 S6 已有的 Create / Update / 停用 / 删除方法的「事务提交之后」各加一行：
//   建/改/启用 → s.registerDue(ctx, rule.ID, rule)
//   停用/删除 → s.revokeDue(ctx, rule.ID)

步骤 3 · 假实现断言协作

import (
    "context"
    "testing"

    "homecube/internal/platform/dueregistry"
)

// fakeDue 记录调用，不碰数据库——接口化的红利。
type fakeDue struct {
    registered []dueregistry.Entry
    revoked    []dueregistry.Kind
}

func (f *fakeDue) Register(ctx context.Context, e dueregistry.Entry) error {
    f.registered = append(f.registered, e)
    return nil
}
func (f *fakeDue) Revoke(ctx context.Context, sys string, id int64, k dueregistry.Kind) error {
    f.revoked = append(f.revoked, k)
    return nil
}
func (f *fakeDue) Complete(ctx context.Context, sys string, id int64, k dueregistry.Kind) error {
    return nil
}

var _ dueregistry.DueRegistry = (*fakeDue)(nil)

func TestCreateRuleRegistersDue(t *testing.T) {
    fake := &fakeDue{}
    svc := newTestRecurringService(t, fake) // 你 S6 的测试构造手法，注入 fake

    rule := createTestRule(t, svc)          // 建一条测试规则（S6 的手艺）

    if len(fake.registered) != 1 {
        t.Fatalf("Register 调用次数 = %d, want 1", len(fake.registered))
    }
    e := fake.registered[0]
    if e.SourceSystem != "finance" || e.Kind != dueregistry.KindRecurringEntry {
        t.Fatalf("注册项 = %+v, want finance/recurring_entry", e)
    }
    if e.SourceID != rule.ID || e.DueAt != rule.NextRunAt {
        t.Fatalf("source_id/due_at 对不上源规则: %+v", e)
    }
}
