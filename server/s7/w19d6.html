1. 角色矩阵新行：时间与协作对象

S4 建的权限矩阵是全站唯一判定处（internal/platform/authz），handler 不自写角色分支。今天给矩阵加一行「时间与协作对象」：

动作ownermemberwardguest
建提醒 / 建待办✓✓✗（由监护人代建）✗
勾选完成（含他人建的、分配给自己的）✓✓✓（仅分配给自己的）✗
编辑 / 改派✓仅自己建的或分配给自己的✗✗
归档（≈删除，软删留痕）✓仅自己建的——删他人 → 403 + 1003✗✗
读列表 / 详情✓✓（本家庭）✓（本家庭）✓（只读）

两条老纪律照旧：越权读返 404 + 1001（与不存在同形）；越权写才返 403 + 1003。「member 可勾他人建的待办」是协作语义——家务是分配给我的，我勾了算数；但「删」是所有权语义，只有创建者与 owner 有。

2. 日历三视图 = 注册表的一次投影

GET /api/homeos/calendar/events?view=day|week|month&date=… 没有自己的表（D13 的决定），查询就是对注册表的过滤：

片段 · 聚合口径四条件WHERE family_id = ?                          -- scope helper 注入，永不手写
  AND status IN ('registered', 'fired')      -- revoked 不上日历
  AND due_at 落在 date 参数解出的时间区间内    -- 日/周/月三种区间
  AND source_system IN (已出生面的 code 集)   -- 面目录（S7 前半）里 born 的那几个
  • born 过滤：未出生面就算有历史注册行也不显示——与「未启用/未出生面客户端零请求」判据同源：服务端先做到「不给数据」，客户端才可能「不发请求」。
  • date 编码沿用时间窗五档：day=YYYY-MM-DD、week=YYYY-Wnn、month=YYYY-MM；解析失败 400 + 1007，不回落到「默认今天」——回落会把编码 bug 藏起来。
  • 返回不带游标：单月事件是小集合，直接 {"list":[…]}（S3 起的老规矩：小集合不带 next_cursor）。

3. 事件详情与「前往源对象」

GET /api/homeos/calendar/events/{id} 返回注册行全量，其中 source_system / source_id / payload 里的 deep_link（D17 财务侧写的那个页面路径）供前端做「前往源对象」跳转：日历上点「周期记账 · 房租」，直达财务面的规则详情页。服务端不拼页面、不判断前端路由，只把三元组原样给出。

4. PUT reminders：一条接口串起本周所有语义

编辑提醒是本周知识点的合流处：改时间/提前量 → 同键再 Register（upsert 更新触发时刻）；改周期 → 重算下次触发；paused=true → Revoke（注册行变 revoked，日历消失）；paused=false → 再 Register（复活）。全程不需要新接口、不需要新方法——这就是把语义设计对的红利。version 乐观锁照 S6 手艺：不匹配 409 + 1009。

周期编码今天定最小文法：repeat_rule 取 daily / weekly / monthly 三值之一或 NULL（一次性）。调度器 fire 时发现 repeat_rule 非空，就把 due_at 推到下一周期并保持 registered（补上 D16 留的那半句）。非法值 400 + 1004。

步骤 2 · 日历聚合（核心查询）

完整 · server/internal/homeos/service/calendar.gopackage service

import (
    "context"
    "time"

    "gorm.io/gorm"

    "homecube/internal/homeos/model"
    "homecube/pkg/response"
)

type CalendarService struct {
    db    *gorm.DB
    faces FaceCatalog // S7 前半建的面目录查询（born 面集合），接口形态以你本地为准
}

// Range 解析 view+date 为 [start, end)。非法编码返回 1007，不回落。
func CalendarRange(view, date string) (time.Time, time.Time, error) {
    switch view {
    case "day":
        d, err := time.Parse("2006-01-02", date)
        if err != nil { return time.Time{}, time.Time{}, response.ErrBadTimeWindow }
        return d, d.AddDate(0, 0, 1), nil
    case "week": // date=YYYY-Wnn：ISO 周，解析到周一 00:00 起 7 天
        y, w, ok := parseISOWeek(date) // 形如 2026-W42 → (2026, 42)；S6 报表周档写过同款
        if !ok { return time.Time{}, time.Time{}, response.ErrBadTimeWindow }
        start := isoWeekStart(y, w)
        return start, start.AddDate(0, 0, 7), nil
    case "month":
        m, err := time.Parse("2006-01", date)
        if err != nil { return time.Time{}, time.Time{}, response.ErrBadTimeWindow }
        return m, m.AddDate(0, 1, 0), nil
    }
    return time.Time{}, time.Time{}, response.ErrBadTimeWindow // view 不在三视图内同样 1007
}

func (s *CalendarService) Events(ctx context.Context, familyID int64, view, date string) ([]model.DueRegistry, error) {
    start, end, err := CalendarRange(view, date)
    if err != nil { return nil, err }
    born := s.faces.BornCodes(ctx) // 已出生面 code 集，如 ["homeos","finance"]

    var list []model.DueRegistry
    err = s.db.WithContext(ctx).
        Where("family_id = ? AND status IN ? AND due_at >= ? AND due_at < ? AND source_system IN ?",
            familyID, []string{model.DueStatusRegistered, model.DueStatusFired}, start, end, born).
        Order("due_at, id").
        Find(&list).Error
    return list, err
}

parseISOWeek / isoWeekStart 用你 S6 报表周档写过的同款工具（当时为 YYYY-Wnn 建过解析）；如果没留档，今天照 time.Parse("2006-01-02") 的思路补一个，判据是 2026-W42 能解出周一零点、非法串返回 false。
