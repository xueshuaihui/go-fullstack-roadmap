通知表与三分型

上周到期中心的调度器一直在往 homeos_notification 写行，kind 是硬编码的字符串 "reminder"——当时说好「分型常量化时当场还债」，就是今天。本周三天干完通知域（A7 三条接口）：今天定分型与口径，明天出列表与未读红点，后天做已读回写与推送设备注册。通知表 S3 建过，今天的活是把它「定型」：三分型落成 Go 常量 + DB CHECK 双保险，未读口径收敛成唯一一个 count 函数。

知识讲义

1. 三分型：每种通知都有唯一的生产者

kind谁生产例子
budget_alert财务面的预算告警（S6 已建：超阈值触发通知）「11 月餐饮预算已用 90%」
system家庭治理动作：邀请、成员变更、面启停「妈妈加入了家庭」「财务面已启用」
reminder到期中心调度器（上周 D16 起一直在写）「到期：交房租」

分型不是装饰：前端按 kind 决定图标与点击行为（budget_alert 跳预算页、reminder 跳日历详情），服务端按 kind 决定文案模板。枚举只有三个值、写死——想加第四种，先来改这一页的决策，不许在 handler 里悄悄塞新字符串。

2. 双保险：Go 常量 + DB CHECK

Go 常量管住「代码里不许写裸字符串」（编译器帮不上忙，但 review 与 grep 帮得上）；DB CHECK 管住「绕过代码的写入」（手工 SQL、迁移脚本、未来的管理工具）。S6 给分类收支类型上过同款双保险，今天照方抓药。

3. 未读口径：一个函数，三个出口

未读数的定义只有一句话：read_at IS NULL 的行数，按 member_id 过滤。三个字段各司其职：

  • 按 member_id，不是 family_id——同一条系统通知发给全家每人一行，各读各的；也不是 user_id——同一个人在两个家庭里的未读互不相干（切家庭 = 换 token，S4 的口径）。
  • read_at 时间戳，不是 is_read 布尔——「什么时候读的」留着能排查「我明明没读过」这类申诉。

这个数会从三个出口吐给客户端：① 首页 GET /api/homeos/home/summary 的 unread（S7 前半已接）；② GET /api/homeos/notifications 响应里的 unread（明天）；③ POST /api/homeos/notifications/read 响应里的 unread（后天）。三处必须同值——红点在首页显示 3、点进通知页变 4，这种 bug 用户一眼就看穿。同值的保证不靠自觉，靠结构：全仓只允许存在一个 count 函数，三个出口都调它；明天用契约测试把「同值」钉死。

4. 还债：替换调度器里的硬编码

D16 的 fire 里写着 Kind: "reminder"，注释里立了字据今天还。替换成常量后 grep 验证：全仓不允许再有通知 kind 的裸字符串。

步骤 1 · 迁移：kind 定型

完整 · server/migrations/homeos/homeos_00NN_notification_kind.up.sql-- 若你 S3 建的通知表还没有 kind 列，先补列再上约束（以本地为准，判据不变）：
ALTER TABLE homeos_notification ADD COLUMN IF NOT EXISTS kind TEXT NOT NULL DEFAULT 'system';
ALTER TABLE homeos_notification ADD CONSTRAINT ck_notification_kind
    CHECK (kind IN ('budget_alert', 'system', 'reminder'));
-- 未读口径的两根柱子，缺谁补谁：
ALTER TABLE homeos_notification ADD COLUMN IF NOT EXISTS member_id BIGINT NOT NULL DEFAULT 0;
ALTER TABLE homeos_notification ADD COLUMN IF NOT EXISTS read_at TIMESTAMPTZ NULL;
CREATE INDEX IF NOT EXISTS idx_notification_unread
    ON homeos_notification (family_id, member_id, read_at);
完整 · server/migrations/homeos/homeos_00NN_notification_kind.down.sqlDROP INDEX IF EXISTS idx_notification_unread;
ALTER TABLE homeos_notification DROP CONSTRAINT IF EXISTS ck_notification_kind;
-- 补过的列 down 里对应删掉；S3 原有的列不许动

DEFAULT 0 的 member_id 只是让 ADD COLUMN 在已有行的表上能过；如果你的测试库里已有 member_id=0 的脏行，清掉它们——上周调度器写入的行都带着 payload 里的真实 member_id，正常不会是 0。真有 0，说明 D16 的 recipientOf 没取到值，回去查 payload。

步骤 2 · 分型常量与唯一 count 函数

完整 · server/internal/homeos/model/notification.gopackage model

import "time"

// 通知三分型：枚举封闭，加第四种先改决策再改代码。
const (
    NotificationKindBudgetAlert = "budget_alert" // 生产者：财务面预算告警（S6）
    NotificationKindSystem      = "system"      // 生产者：邀请/成员变更/面启停
    NotificationKindReminder    = "reminder"    // 生产者：到期中心调度器（S7·D16）
)

type Notification struct {
    ID        int64      `gorm:"primaryKey" json:"id"`
    FamilyID  int64      `gorm:"not null" json:"family_id"`
    MemberID  int64      `gorm:"not null" json:"member_id"` // 收件人：未读按它聚合
    Kind      string     `gorm:"not null" json:"kind"`
    Title     string     `gorm:"not null" json:"title"`
    Body      string     `gorm:"not null" json:"body"`
    ReadAt    *time.Time `json:"read_at,omitempty"`          // NULL = 未读
    CreatedAt time.Time  `json:"created_at"`
    UpdatedAt time.Time  `json:"updated_at"`
}

func (Notification) TableName() string { return "homeos_notification" }
完整 · server/internal/homeos/repo/notification.gopackage repo

import (
    "context"

    "gorm.io/gorm"

    "homecube/internal/homeos/model"
)

type NotificationRepo struct{ db *gorm.DB }

func NewNotificationRepo(db *gorm.DB) *NotificationRepo { return &NotificationRepo{db: db} }

// UnreadCount 全站未读数的唯一实现。三个出口（summary / GET notifications /
// POST read）都必须调它——谁另写一份 COUNT，谁就把「三出口同值」判据打破了。
func (r *NotificationRepo) UnreadCount(ctx context.Context, familyID, memberID int64) (int64, error) {
    var n int64
    err := r.db.WithContext(ctx).Model(&model.Notification{}).
        Where("family_id = ? AND member_id = ? AND read_at IS NULL", familyID, memberID).
        Count(&n).Error
    return n, err
}

import (
    "context"
    "strings"
    "testing"

    "homecube/internal/homeos/model"
)

func TestUnreadCountPerMember(t *testing.T) {
    db := openTestDB(t)
    r := NewNotificationRepo(db)
    ctx := context.Background()
    seed := []model.Notification{
        {FamilyID: 1, MemberID: 3, Kind: model.NotificationKindReminder, Title: "a", Body: "a"},
        {FamilyID: 1, MemberID: 3, Kind: model.NotificationKindSystem, Title: "b", Body: "b"},
        {FamilyID: 1, MemberID: 4, Kind: model.NotificationKindSystem, Title: "c", Body: "c"}, // 别人的，不算
        {FamilyID: 2, MemberID: 3, Kind: model.NotificationKindSystem, Title: "d", Body: "d"}, // 别家庭的，不算
    }
    for i := range seed { if err := db.Create(&seed[i]).Error; err != nil { t.Fatal(err) } }

    n, err := r.UnreadCount(ctx, 1, 3)
    if err != nil { t.Fatal(err) }
    if n != 2 { t.Fatalf("unread = %d, want 2", n) }
}

func TestKindCheckRejectsUnknown(t *testing.T) {
    db := openTestDB(t)
    bad := model.Notification{FamilyID: 1, MemberID: 3, Kind: "promo", Title: "x", Body: "x"}
    err := db.Create(&bad).Error
    if err == nil || !strings.Contains(err.Error(), "ck_notification_kind") {
        t.Fatalf("非法 kind 应被 CHECK 拦下, got %v", err)
    }
}
