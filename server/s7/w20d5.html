家庭设置：币种只存不算汇率

昨天（D22）落的是个人级设置：主题、日期格式，一人一行。今天把 GET/PUT /api/homeos/settings 的响应扩出一段 family——家庭级设置，全家一份，第一项就是币种。这条卡的红线只有一句，也是最容易被过度设计的一句：只存不算。服务端把币种当成一个标签存下来（CNY、USD……），永远不拿它去做任何汇率换算。金额从 S5 起就恒为 *_cents 整数，今天一行换算代码都不加。

知识讲义

1. 个人级 vs 家庭级：作用域决定权限门槛

设置分两层作用域。个人级（主题、日期格式）落 homeos_settings，(family_id, member_id) 一人一行，谁都能改自己那份，改错了也只坑自己。家庭级（币种）落 homeos_family，全家一份——它一改，全家所有金额的读法都变了。作用域越大，写权限越收紧：个人级本人可写，家庭级只有 owner 可写。这不是新规矩，是 S4 角色矩阵的自然延伸。

GET /api/homeos/settings 一次把两段都回给前端，省一次请求；但两段的写走不同权限门。响应形如：{"personal":{"theme":…,"date_format":…,"version":3},"family":{"currency":"CNY","version":7}}——两个 version 各管各的乐观锁，互不串号。

2. 只存不算：币种是标签，不是换算器

「家庭币种是 CNY」这句话，服务端只干一件事：把这个字符串存进 homeos_family.currency。它不干的事有一长串——不查汇率、不做 CNY↔USD 换算、不在金额上乘任何系数。为什么这么决绝？因为一旦服务端开始换算，你就得回答：汇率哪来的？多久更新？历史账目按当时汇率还是现在汇率重算？每一问都是一个能吞掉整周的坑，而它们全在教学范围外。

所以口径钉死：金额永远是 *_cents 的 int64（S5 财务域立的规矩），币种只是告诉前端「显示时前面加 ¥ 还是 $」。改币种不重写历史金额——那些 cents 已经按旧币存好了，服务端零换算，自然也不会去动它们。这是「只存不算」最直接的后果，也是它最省心的地方。

判据（收口日会再验一次）：全仓搜不到任何汇率/换算代码。今天增量里就带一条 grep 断言——出现 exchange、convert.*currency、rate 之类的实现即视为越界。币种字段可以读、可以写、可以校验白名单，唯独不能参与算术。

3. 币种白名单：又是封闭枚举双保险

币种不是自由文本，是 ISO 4217 的封闭集合。教学期不铺全表，落一个小白名单（CNY / USD / EUR / JPY / HKD / GBP）足够演示姿势：Go 侧白名单拦下 400 + 1004，DB 侧 homeos_family.currency 早有 CHECK（S4 建表时落的）兜底。这是本站封闭枚举的第三次同款操作（通知分型、主题、日期格式之后）——肌肉记忆该形成了。

4. owner 门：走 authz，不在 handler 写 if role == owner

「只有 owner 能改币种」这条规则，不写成语句里的 if role != owner。S4 立过规矩：角色判定收在 authz 单一实现里。今天在 S4 矩阵加一个动作 ActionFamilySettings（owner 放行、其余拒绝），handler 只调 authz.Allow(role, authz.ActionFamilySettings)，判否就 403 + 1003。昨天 D22 的个人设置不需要这道门（本人改本人），今天需要——差别就在作用域。

步骤 1 · 响应 DTO 与 Get 拼装

完整 · server/internal/homeos/service/settings.go（在 D22 的文件上追加）package service

// 币种白名单：封闭枚举，Go 侧第一层。
var currencies = map[string]bool{
    "CNY": true, "USD": true, "EUR": true,
    "JPY": true, "HKD": true, "GBP": true,
}

// SettingsView 是 GET /settings 的响应形状：个人段 + 家庭段，各带自己的 version。
type PersonalSection struct {
    Theme      string `json:"theme"`
    DateFormat string `json:"date_format"`
    Version    int    `json:"version"`
}
type FamilySection struct {
    Currency string `json:"currency"`
    Version  int    `json:"version"`   // 家庭行的 version，与个人段互不相干
}
type SettingsView struct {
    Personal PersonalSection `json:"personal"`
    Family   FamilySection   `json:"family"`
}

// GetView 把 D22 的 Get（个人段）与家庭行拼成一个响应，省前端一次请求。
func (s *SettingsService) GetView(ctx context.Context, familyID, memberID int64) (*SettingsView, error) {
    st, err := s.Get(ctx, familyID, memberID)   // D22 已落：无行返回默认值 + version 0
    if err != nil { return nil, err }
    var fam model.Family
    if err := s.db.WithContext(ctx).
        Where("id = ?", familyID).First(&fam).Error; err != nil {
        return nil, err
    }
    return &SettingsView{
        Personal: PersonalSection{Theme: st.Theme, DateFormat: st.DateFormat, Version: st.Version},
        Family:   FamilySection{Currency: fam.Currency, Version: fam.Version},
    }, nil
}

model.Family 的字段名（Currency / Version）以你 S4 落盘的家庭模型为准；判据不变——币种读的是家庭行已有的列，今天没为它建任何表或列。

步骤 2 · 币种写入：白名单 + 家庭行乐观锁

完整 · server/internal/homeos/service/settings.go（续）// PutFamilyCurrency 只改标签、只走乐观锁；不碰任何金额、不做任何换算。
// owner 门在 handler 用 authz 把（见步骤 3），service 只管值合法与版本一致。
func (s *SettingsService) PutFamilyCurrency(ctx context.Context, familyID int64, currency string, ver int) (*FamilySection, error) {
    if !currencies[currency] {
        return nil, response.ErrInvalidParam   // 400 + 1004：白名单第一层
    }
    res := s.db.WithContext(ctx).Model(&model.Family{}).
        Where("id = ? AND version = ?", familyID, ver).
        Updates(map[string]any{
            "currency":   currency,
            "version":    gorm.Expr("version + 1"),
            "updated_at": gorm.Expr("now()"),
        })
    if res.Error != nil { return nil, res.Error }
    if res.RowsAffected == 0 { return nil, response.ErrVersionConflict }   // 409 + 1009
    return &FamilySection{Currency: currency, Version: ver + 1}, nil
}

步骤 3 · handler：owner 门走 authz，按 body 分派

片段 · server/internal/homeos/handler/settings.go// PUT /settings：body 带 "family" 段 → 走币种路径（owner 门）；否则走 D22 个人路径。
func (h *SettingsHandler) Put(c *gin.Context) {
    var body struct {
        Theme      string `json:"theme"`
        DateFormat string `json:"date_format"`
        Version    int    `json:"version"`
        Family     *struct {
            Currency string `json:"currency"`
            Version  int    `json:"version"`
        } `json:"family"`
    }
    if err := c.ShouldBindJSON(&body); err != nil {
        response.Fail(c, http.StatusBadRequest, response.CodeInvalidParam, "参数错误"); return
    }
    if body.Family != nil {   // 家庭级写：先过 owner 门
        role := c.MustGet("role").(model.Role)
        if !authz.Allow(role, authz.ActionFamilySettings) {   // S4 矩阵加一行：owner 放行、其余拒绝
            response.Fail(c, http.StatusForbidden, response.CodeForbidden, "权限不足"); return   // 403 + 1003
        }
        fam, err := h.svc.PutFamilyCurrency(c.Request.Context(), c.GetInt64("familyID"),
            body.Family.Currency, body.Family.Version)
        if err != nil { response.FailErr(c, err); return }
        response.OK(c, gin.H{"family": fam}); return
    }
    // …个人级路径同 D22…
}

矩阵动作 authz.ActionFamilySettings：在 S4 的角色矩阵表里加一行，owner 放行、member/ward/guest 拒绝。错误码常量名以你 S1·D4 的码表为准，对应 1003 / 1004 / 1009。handler 里没有 if role == "owner" 这种硬分支——判定全在 authz。

func TestPutFamilyCurrency(t *testing.T) {
    db := setupFamilyWithCurrency(t, "CNY", 7)   // 家庭行 version=7
    svc := service.NewSettingsService(db)
    ctx := context.Background()

    // 版本匹配：改成功，version 8，币种变了，金额一分没动（无金额可动）。
    fam, err := svc.PutFamilyCurrency(ctx, 1, "USD", 7)

        t.Fatalf("want USD/8, got %+v err=%v", fam, err)
    }
    // 非法币种：400 + 1004。

        t.Fatalf("want 1004, got %v", err)
    }
    // 版本不匹配：409 + 1009。
    if _, err := svc.PutFamilyCurrency(ctx, 1, "EUR", 99); !errors.Is(err, response.ErrVersionConflict) {
        t.Fatalf("want 1009, got %v", err)
    }
}

常见坑（新手 100% 会踩）

坑现象正确姿势
为币种新建一张表/一列与 S4 家庭表已有的 currency 重复，两处不同步复用 homeos_family.currency，今天零迁移
服务端做起汇率换算被问「汇率哪来、多久更新、历史怎么算」，一周没了只存不算：币种是标签，金额恒 *_cents，零换算代码
改币种时顺手「转换」历史金额旧账被乘系数，账面全错且不可逆改标签不碰历史；历史 cents 已按旧币存定
member 也能改家庭币种任一成员把全家币种改了，影响所有人authz ActionFamilySettings：owner 放行，member → 403 + 1003
handler 里写 if role=="owner"角色判定散落各处，与 S4 矩阵不一致判定收进 authz 单一实现，handler 只调 Allow
个人段与家庭段共用一个 version改主题把家庭行版本也顶了，币种 PUT 莫名 1009两段各带各的 version，两条乐观锁互不串号
