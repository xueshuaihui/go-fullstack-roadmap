面清单接口：四层合成在服务端一处

今天写壳基座最核心的一个读接口：GET /api/homeos/family/modules。它下发全量面目录（7 项），每项带着四层过滤的结果标记：这个面存在吗（registry）、这家人开了吗（enabled）、出生了吗（born）、你这个角色看得见吗（visible）。四层合成只发生在服务端一个函数里——客户端拿到手的不是一堆原始数据让它自己拼，而是算完的结论。

今日目标

知识讲义

1. 四层各管一件事，合成只在一处

层问题数据源落在响应的哪个字段
① registry这个面存在吗代码（S7·D1）清单恒 7 项，code/name/icon
② 家庭启用这家人开了吗homeos_family_module 表（S7·D2）enabled（+ version 供 PUT 回传）
③ 已出生服务端代码上线了吗代码（registry.Born）born 与 availability
④ 角色可见你这个角色看得见吗registry.VisibleRoles + authzvisible

「合成在服务端一处」不是修辞，是硬约束：四层的结果只允许在一个函数里算（今天的 Compose），所有消费点——面清单接口、下周的 home/summary faces[]、S7·D11 的路由门禁——都调它或调它同源的谓词。两处各算一遍，就是「口径漂移」的开始：总有一天两个接口对同一个面给出矛盾的 enabled。

下发的是全量目录 + 标记，不是过滤后的子集。为什么？因为设置页要展示「没开的、没出生的」面让用户去开通/期待，首页矩阵只渲染标记全真的项。过滤条件（渲染 ⇔ born ∧ enabled ∧ visible）由服务端算好放进标记，客户端只做一次按标记的 filter——这不是二次裁剪，二次裁剪指客户端拿本地信息（角色、硬编码名单）再砍一刀，那才是被禁止的（S7·D5 专门测）。

2. 角色可见集的唯一实现进 authz

S4 立过规矩：权限判定只有一份实现，在 internal/platform/authz，业务代码不许自写角色分支。面的角色可见也一样：registry 里每项声明 VisibleRoles，但「owner 恒真」这条覆盖规则收在 authz 的一个函数里。今天给 authz 加：

完整 · server/internal/platform/authz/module.gopackage authz

import "homecube/internal/homeos/model"

// ModuleVisible 是「角色 → 面可见」的全站唯一判定。
// owner 恒真（管理员必须能看见家里所有面，包括对其他角色隐藏的）；
// 其余角色查 registry 声明的可见集。
func ModuleVisible(role model.Role, visibleRoles []model.Role) bool {
    if role == model.RoleOwner {
        return true
    }
    for _, r := range visibleRoles {
        if r == role {
            return true
        }
    }
    return false
}

等一下——platform 反过来 import 了 homeos/model？是的，这一处是刻意例外还是坏味道，值得较真：model.Role 是全站共享的领域词汇（S4 起 token、中间件、矩阵全在用它），它虽然物理上住在 homeos 的 model 包里，逻辑上属于平台层。依赖方向的红线是「业务模块之间不互相依赖」（finance 不 import homeos），platform 引用一个共享值类型不违反这条红线。如果你的洁癖更强，把 Role 挪到 platform/model 也行——全站 import 一次改完，今天不做。

3. availability 的两个取值

  • available：born=true，面可用（是否渲染再看 enabled ∧ visible）。
  • not_born：born=false，壳的降级表达——设置页显示「敬请期待」，首页矩阵不渲染，分包不下发。

响应是非分页小集合，按 S3 的口径：data 里只有 list，不带 next_cursor/has_more。

步骤 1 · Compose：唯一合成点

完整 · server/internal/homeos/faces/compose.gopackage faces

import (
    "context"

    "gorm.io/gorm"

    "homecube/internal/homeos/model"
    "homecube/internal/platform/authz"
)

// Item 是面清单接口的一项，也是下周 summary faces[] 的一项——同一个类型，同源合成。
type Item struct {
    Code         string `json:"code"`
    Name         string `json:"name"`
    Icon         string `json:"icon"`
    Born         bool   `json:"born"`
    Availability string `json:"availability"` // available | not_born
    Enabled      bool   `json:"enabled"`
    Visible      bool   `json:"visible"`
    Version      int    `json:"version"`       // 该行配置的 epoch，PUT 时原样带回
}

// ShouldRender 是渲染谓词：客户端唯一允许的过滤，就是按这个标记组合 filter。
func (it Item) ShouldRender() bool {
    return it.Born && it.Enabled && it.Visible
}

// Compose 四层合成的全站唯一实现。任何消费点不得自己拼这四层。
func Compose(ctx context.Context, db *gorm.DB, familyID int64, role model.Role) ([]Item, error) {
    var rows []model.FamilyModule
    if err := db.WithContext(ctx).
        Where("family_id = ?", familyID).
        Find(&rows).Error; err != nil {
        return nil, err
    }
    byCode := make(map[string]model.FamilyModule, len(rows))
    for _, row := range rows {
        byCode[row.Code] = row
    }

    metas := All()
    items := make([]Item, 0, len(metas))
    for _, m := range metas {
        it := Item{
            Code: m.Code, Name: m.Name, Icon: m.Icon, Born: m.Born,
            Visible: authz.ModuleVisible(role, m.VisibleRoles),
        }
        if m.Born {
            it.Availability = "available"
        } else {
            it.Availability = "not_born"
        }
        if row, ok := byCode[m.Code]; ok {
            it.Enabled = row.Enabled
            it.Version = row.Version
        }
        items = append(items, it)
    }
    return items, nil
}

注意查询只有 WHERE family_id = ?——scope 纪律照旧，家庭隔离条件一条不少；软删行由 GORM 的 DeletedAt 约定自动排除（你的 model 若用 *time.Time 手写列，就补上 deleted_at IS NULL，以你 S3/S4 的既有口径为准）。

步骤 2 · GET handler 与路由

完整 · server/internal/homeos/faces/handler_list.gopackage faces

import (
    "github.com/gin-gonic/gin"
    "gorm.io/gorm"

    "homecube/internal/homeos/model"
    "homecube/pkg/response"
)

// ListModules GET /api/homeos/family/modules —— 本家庭面配置 + 全量面目录。
func ListModules(db *gorm.DB) gin.HandlerFunc {
    return func(c *gin.Context) {
        role := c.MustGet("role").(model.Role)
        items, err := Compose(c.Request.Context(), db, c.GetInt64("familyID"), role)
        if err != nil {
            response.FailErr(c, err)
            return
        }
        response.OK(c, gin.H{"list": items}) // 非分页小集合：只有 list，无游标字段
    }
}
片段 · main.go 路由组（Auth 中间件同 S4）homeos.GET("/family/modules", faces.ListModules(db))

步骤 3 · 三角色测试

完整 · server/internal/homeos/faces/compose_test.gopackage faces

import (
    "context"
    "testing"

    "homecube/internal/homeos/model"
    "homecube/internal/platform/testdb"
)

func TestComposeFourLayers(t *testing.T) {
    db := testdb.Open(t)
    famID, _ := seedFamily(t, db) // 复用 S7·D2 的 seed：homeos/finance 启用，其余停用
    ctx := context.Background()

    owner, err := Compose(ctx, db, famID, model.RoleOwner)
    if err != nil {
        t.Fatal(err)
    }
    if len(owner) != 7 {
        t.Fatalf("清单 = %d 项, want 7（全量目录 + 标记）", len(owner))
    }

    byCode := map[string]Item{}
    for _, it := range owner {
        byCode[it.Code] = it
    }

    // owner 视角：visible 恒真——包括对 ward 隐藏的 finance
    for _, it := range owner {
        if !it.Visible {
            t.Fatalf("owner 视角 %s visible=false, want true", it.Code)
        }
    }
    // born 与 availability 同源一致
    if byCode["purchase"].Born || byCode["purchase"].Availability != "not_born" {
        t.Fatalf("purchase = %+v, want born=false/not_born", byCode["purchase"])
    }
    // 渲染谓词：finance 应渲染，purchase（未出生）与 diet（未启用）不应
    if !byCode["finance"].ShouldRender() {
        t.Fatal("finance 应渲染")
    }
    if byCode["purchase"].ShouldRender() || byCode["diet"].ShouldRender() {
        t.Fatal("未出生/未启用面不应渲染")
    }

    // ward 视角：finance.visible=false（角色可见集生效），homeos 仍可见
    ward, err := Compose(ctx, db, famID, model.RoleWard)
    if err != nil {
        t.Fatal(err)
    }
    for _, it := range ward {
        switch it.Code {
        case "finance":
            if it.Visible {
                t.Fatal("ward 不应看见 finance")
            }
        case "homeos":
            if !it.Visible {
                t.Fatal("ward 应看见 homeos")
            }
        }
    }
}

常见坑（新手 100% 会踩）

坑现象正确姿势
接口只下发过滤后的子集设置页拿不到「没开的面」，没法做开通入口下发全量目录 + 四层标记；渲染谓词服务端给好
handler 里又算一遍 enabled/visible两个消费点口径漂移，同一面在两个接口里一开一关只调 Compose；新消费点复用它，不复制逻辑
在 handler 写 if role == owner违反「权限判定只有一份实现」，S4 的规矩白立owner 恒真收在 authz.ModuleVisible
响应带上 next_cursor7 项的目录搞游标分页，客户端白白处理分页态非分页小集合只回 list（S3 口径）
忘了下发 version客户端 PUT 时无 epoch 可带，乐观锁形同虚设每项带 version，PUT 原样回传
用 enabled 表达 born「没出生」和「没开通」混成一个 false，降级表达丢失born/availability 与 enabled 分字段下发
