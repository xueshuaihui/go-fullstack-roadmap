首屏只有一个业务请求：summary 塞什么、不塞什么

昨天立了骨架，今天填 A 区（家庭）与 B 区（今日），并且回答聚合接口最难的问题：边界。「首屏一个请求」不等于「首页相关的一切都塞进来」——塞多了 summary 变成万能接口，塞少了客户端又开始并行补拉。今天把「塞什么、不塞什么」的判断标准一次立清，顺便给到期中心挖好接口槽：platform.DueRegistry。

今日目标

知识讲义

1. 塞与不塞的判据

一条数据能进 summary，必须同时满足两条：① 首屏第一帧就要渲染它（不是「点开某页才用」）；② 它必须服务端算（跨表聚合、权限口径、家庭时区换算——客户端算不动或不许算）。按这个判据过一遍：

数据进不进理由
家庭成员名字/称谓/头像 + 全量计数进A 区第一帧渲染；头排溢出成「+N」需要全量计数
问候语文案（「爸爸，晚上好」）不进文案是表现层。服务端只给数据（relation），客户端拼文案——改文案不发服务端版本
今日到期 count + 前 3 条进B 区第一帧渲染；count 全量、items 截断是聚合接口的标准形状
面矩阵 faces[]进C 区，昨天已真
动态流前 20 条进D 区第一屏；续读去 dynamics 接口（S7·D10）
未读数进底栏角标第一帧就要（S7·D9 换真）
动态流全量 / 通知列表 / 分包清单 / 设置 / 财务报表明细不进都是「进了某页才要」的数据，各有自己的接口；塞进来 summary 就成万能接口

「客户端不因渲染导航额外请求面清单接口」——faces[] 已经进了 summary，所以壳渲染首页时不打 GET family/modules。那个接口服务于设置页（要展示全量目录 + 开关），两个消费场景、一个合成源（昨天的契约测试钉住）。首屏仍然只有一个请求。

2. 问候语读 relation：数据归服务端，文案归客户端

首页顶部那句「爸爸，晚上好」怎么来？服务端下发的是 A 区的 members[]，其中当前成员那条带 relation（家庭内称谓的权威字段，S4 建档时立的）。客户端拿 relation + 本地时间拼出问候语。分工的道理：

  • relation 是数据：谁是爸爸由家庭维护，多端必须一致，只能服务端给。
  • 「晚上好」是文案：措辞、时段切分、节日彩蛋全是表现层迭代，进服务端就意味着改一个字发一次版。

3. 今日区与 DueRegistry：进程内调用替代事件总线

B 区的 due_today（今天到期的提醒/待办）数据属于到期中心——本阶段后半才建。但 summary 今天就要定契约，所以接口槽先挖好。原始设计里，各业务面通过事件（如 {code}.due.registered）把到期项注册给到期中心；课程范围收窄后用进程内调用替代事件总线，但两条性质必须保住：

  1. 调用点收在 platform 接口后面：业务代码只依赖 platform.DueRegistry 这个接口，不依赖任何具体实现。日后要换成真的消息总线，只换接口的实现，全部调用点一行不动——这就是 S4 立 FamilyDirectory 时说的「日后拆服务只换接口实现」，同一纪律。
  2. 幂等键 (source_system, source_id, kind)：同一笔来源对象的同一种到期项，注册多少次都只有一行。事件重放、请求重试、进程重启后的补偿注册，全靠这个三元组去重。

今天的实现是空注册表（NopDueRegistry：注册直接成功、查询恒返回 0 条）——注意这不是假数据违规：接口与调用点是真结构，实现按排期在本阶段后半换真，占位注释写明。summary 的 today 区形状今天定死：due_today.count 给全量、items[] 只给前 3 条（角标要准确数字，首屏只渲染三行）。

4. period：五档接受、非法 1007、不回落

summary 接受 period 查询参数（影响 B 区今日口径的参照期），沿用 S3 立的时间窗五档：YYYY-MM-DD / YYYY-Wnn / YYYY-MM / YYYY-Qn / YYYY。三条纪律原样适用：非法编码 → 400 + 1007，绝不回落默认档（回落会把「客户端传错了」静默成「数据看起来没问题」）；壳的切换器只暴露月/季/年三档，服务端接受五档；缺省 period 时服务端按家庭时区取当天所属月份——缺省是「没传」，不是「传错」，两回事。

今日增量（在学习仓里落盘）

今天属增量类型 ① + ⑤：DueRegistry 接口与空实现落进 platform；summary 的 family/today 两区从占位换真。

步骤 1 · platform.DueRegistry

完整 · server/internal/platform/dueregistry.gopackage platform

import (
    "context"
    "time"
)

// DueItem 是一条到期注册项。幂等键 = (SourceSystem, SourceID, Kind)：
// 同一来源对象的同一种到期项，注册多少次都只有一行。
type DueItem struct {
    SourceSystem string    // 来源面 code，如 "finance"
    SourceID     int64      // 来源对象 id（逻辑引用，无物理外键）
    Kind         string     // 到期种类，如 "bill_due" / "reminder" / "todo"
    Title        string
    DueAt        time.Time
}

// DueRegistry 是到期中心的跨模块入口。业务面注册/撤销到期项、
// 壳读今日到期，都只依赖这个接口——进程内调用替代事件总线，
// 但调用点收在接口后：日后换总线，只换实现。
type DueRegistry interface {
    // Register 幂等注册：同幂等键重复调用不产生第二行。
    Register(ctx context.Context, familyID int64, item DueItem) error
    // TodayDue 返回某天的到期：count 全量、items 由调用方截断。
    TodayDue(ctx context.Context, familyID int64, day string) (count int, items []DueItem, err error)
}

// NopDueRegistry 是空实现：注册即成功、查询恒为空。
// 本阶段后半建真到期中心时整体替换（main 装配处换一个构造函数），调用点零改动。
type NopDueRegistry struct{}

func (NopDueRegistry) Register(ctx context.Context, familyID int64, item DueItem) error {
    return nil
}

func (NopDueRegistry) TodayDue(ctx context.Context, familyID int64, day string) (int, []DueItem, error) {
    return 0, nil, nil
}

接口放 platform、实现在业务侧（真实现日后住 homeos 的到期中心包），依赖方向照 S4 的 FamilyDirectory：业务模块依赖 platform 的接口，platform 不依赖任何业务模块。

步骤 2 · summary 换真 A/B 两区

完整 · server/internal/homeos/home/summary.gopackage home

import (
    "context"
    "time"

    "github.com/gin-gonic/gin"
    "gorm.io/gorm"

    "homecube/internal/homeos/model"
    "homecube/internal/platform"
    "homecube/internal/platform/period"
    "homecube/pkg/response"
)

type memberBrief struct {
    ID       int64  `json:"id"`
    Name     string `json:"name"`
    Relation string `json:"relation"` // 称谓权威字段；问候语文案由客户端拼
    AvatarURL string `json:"avatar_url"`
    IsMe     bool   `json:"is_me"`    // 客户端据此取 relation 拼问候语
}

// Deps 是 summary 的依赖束：全部走接口/句柄注入，测试可替换。
type Deps struct {
    DB   *gorm.DB
    Due  platform.DueRegistry
}

// familySection 查 A 区：全量成员 + 计数（头排溢出「+N」用）。
func familySection(ctx context.Context, db *gorm.DB, familyID, meMemberID int64) (gin.H, error) {
    var fam model.Family
    if err := db.WithContext(ctx).
        Where("id = ?", familyID).First(&fam).Error; err != nil {
        return nil, err // 家庭不存在/无权 → FailErr 映射 404 + 1001/3001
    }
    var members []model.Member
    if err := db.WithContext(ctx).
        Where("family_id = ? AND status = ?", familyID, model.MemberStatusActive).
        Order("id").Find(&members).Error; err != nil {
        return nil, err
    }
    briefs := make([]memberBrief, 0, len(members))
    for _, m := range members {
        briefs = append(briefs, memberBrief{
            ID: m.ID, Name: m.Name, Relation: m.Relation,
            AvatarURL: m.AvatarURL, IsMe: m.ID == meMemberID,
        })
    }
    return gin.H{
        "id": fam.ID, "name": fam.Name,
        "member_count": len(briefs), // 全量计数，头排渲染截断是客户端的事
        "members": briefs,
    }, nil
}

// todaySection 查 B 区：count 全量、items 截前 3。
func todaySection(ctx context.Context, due platform.DueRegistry, familyID int64, tz *time.Location) (gin.H, error) {
    day := time.Now().In(tz).Format("2006-01-02") // 「今天」按家庭时区定义
    count, items, err := due.TodayDue(ctx, familyID, day)
    if err != nil {
        return nil, err
    }
    if len(items) > 3 {
        items = items[:3] // 截断在服务端做：首屏契约就是最多 3 条
    }
    return gin.H{"due_today": gin.H{"count": count, "items": items}}, nil
}

// parsePeriod 校验五档编码；缺省按家庭时区取当月。非法 → 1007，不回落。
func parsePeriod(q string, tz *time.Location) (string, error) {
    if q == "" {
        return time.Now().In(tz).Format("2006-01"), nil
    }
    p, err := period.Parse(q) // S6 报表落盘的五档解析；若它还住在 finance 包，今天顺手搬进 platform/period
    if err != nil {
        return "", response.ErrBadPeriod // → 400 + 1007
    }
    return p.String(), nil
}

然后改昨天的 handler：Summary(deps Deps)，A/B 两区调这两个函数，占位注释里 D8 的两块删掉；period 解析失败走 response.Fail(c, http.StatusBadRequest, response.CodeBadPeriod, "时间窗编码非法")。家庭时区 tz 从 fam.Timezone 载（time.LoadLocation，S4 建家庭时的字段；载入失败按 5000 处理——库里的时区必须是合法值，坏了是服务端的数据问题）。

依赖说明：model.Member 的 Status/Relation/AvatarURL 字段与 MemberStatusActive 常量、response.ErrBadPeriod（或你 S6 对 1007 用的哨兵名）以你既有落盘为准——今天不新增任何错误码，只是把已有的用起来。

func TestPeriodValidation(t *testing.T) {
    cases := []struct {
        in      string
        wantErr bool
    }{
        {"", false},              // 缺省 = 没传，合法
        {"2026-10", false},
        {"2026-W42", false},
        {"2026-Q4", false},
        {"2026-13", true},          // 月份越界
        {"last-month", true},      // 非法编码 → 1007，不回落
    }
    for _, c := range cases {
        _, err := parsePeriod(c.in, time.UTC)
        if (err != nil) != c.wantErr {
            t.Fatalf("parsePeriod(%q) err=%v, wantErr=%v", c.in, err, c.wantErr)
        }
    }
}

常见坑（新手 100% 会踩）

坑现象正确姿势
把问候语文案放进响应改一句「晚上好」要发服务端版本；多语言/节日文案全堆进聚合层服务端只给 relation，文案客户端拼
summary 里返回动态流全量响应体随家庭活跃度膨胀，首屏越来越慢D 区只给前 20 条 + has_more，续读走 dynamics 接口
due_today 直接查到期表home 包依赖了后半才建的表结构，排期耦合只依赖 platform.DueRegistry 接口；今天空实现，后半换真
Register 不做幂等键重试/补偿注册造成同一账单三条到期提醒(source_system, source_id, kind) 唯一约束，重复注册无副作用
period 非法时回落默认档客户端传错静默吞掉，数据「看起来没问题」400 + 1007，不回落——S3 立的横切纪律
「今天」用服务器本地时区家庭在另一个时区，凌晨的到期项错位一天today 按家庭时区算（family.Timezone）
member_count 只给头排渲染的条数「+N」溢出角标算不出来，客户端又去拉成员列表count 全量、渲染截断归客户端
