未出生/未启用面的零请求服务端保证

「未挂载/未出生的面在客户端零请求」——这条判据的前半句靠壳：入口不渲染，用户点不到。但「点不到」不等于「打不进」：设备上还躺着旧分包、请求可以重放、URL 可以手敲。今天把判据的后半句补齐：服务端自己保证。两种情况、两种语义：面未启用 → 路由门禁拒绝，403 + 1003；面未出生 → 路由根本不存在，走全站 NoRoute，404 + 1001。为什么一个 403 一个 404，今天讲透。

今日目标

知识讲义

1. 零请求是纵深防御，不是单点承诺

结构第 1 层  壳不渲染入口          → 正常用户零请求（客户端，前端线的壳负责）
第 2 层  路由门禁 403+1003     → 停用面的接口拒绝服务（今天，服务端）
第 3 层  路由不存在 404+1001   → 未出生面没有路由可打（今天确认，服务端）

任何一层单独都不够：只靠第 1 层，旧版本客户端和恶意请求直接穿透；只做第 2/3 层，用户会频繁撞错误页。每一层独立成立，合起来才叫保证。

2. 为什么未启用是 403+1003，未出生是 404+1001

情况服务端事实响应理由
面已出生、家庭未启用路由存在、代码在跑，是这家的配置不放行403 + 1003错误码表里 1003 明确覆盖「面未启用」。客户端拿到 1003 可以给出有意义的引导：「该面未启用，请管理员在面设置中开启」
面未出生二进制里没有一行该面的路由与 handler404 + 1001（NoRoute）没有东西可拒绝——路由不存在，请求自然落进全站 NoRoute。给未出生的面回 403 反而泄露「这个面存在但不给你看」；1001 与「真不存在」同形，什么都不泄露

注意这不是二选一的偏好题，是事实差异：未出生面的 404 不需要你写任何代码——不注册路由，NoRoute（S2 起就是 404 + 1001）自动兜底。你今天真正要写的只有未启用面的门禁。

对照另一条老纪律：越权读返 404+1001（与不存在同形，不泄露存在性），越权写才返 403+1003。今天的选择与它同构：能装作不存在的就装作不存在（未出生），必须解释原因的才解释（未启用——因为客户端要引导用户去开启）。

3. 门禁放哪：依赖方向决定形状

门禁要挂在 /api/finance 组上，中间件天然住 platform（S2 起中间件都在那儿）；但「这个家庭启用了哪些面」的判定逻辑在 homeos（S7·D2/D3 的表与合成）。platform 不许 import 业务模块——解法你已经见过两次了：platform 定义接口，业务侧给实现，main 装配：

结构platform/middleware：ModuleGate(gate Gate, code string)   ← 只依赖自己定义的 Gate 接口
homeos/faces：       EnabledGate 实现 Gate                ← 查 family_module（进程内，每请求一次索引查询）
main.go：            middleware.ModuleGate(faces.NewEnabledGate(db), "finance") 挂到 /api/finance 组

性能口径先说清：门禁每请求查一次 (family_id, code) 唯一索引，是一次主键级查询，教学期完全够。缓存（进程内 TTL、或挂到 pver 失效链上）是 S8 部署期的优化题，今天不做、不预埋。

步骤 1 · Gate 接口与中间件（platform 侧）

完整 · server/internal/platform/middleware/module_gate.gopackage middleware

import (
    "context"
    "net/http"

    "github.com/gin-gonic/gin"

    "homecube/pkg/response"
)

// Gate 是「这个家庭启用了这个面吗」的判定接口。
// platform 定义、homeos 实现、main 装配——依赖方向与 FamilyDirectory/DueRegistry 一致。
type Gate interface {
    Enabled(ctx context.Context, familyID int64, code string) (bool, error)
}

// ModuleGate 面路由门禁：挂在某个面的整个路由组上。
// 未启用 → 403 + 1003（配置不放行，客户端可引导开启）。
// 未出生的面不需要门禁：它没有路由，NoRoute 404 + 1001 自动兜底。
func ModuleGate(gate Gate, code string) gin.HandlerFunc {
    return func(c *gin.Context) {
        enabled, err := gate.Enabled(c.Request.Context(), c.GetInt64("familyID"), code)
        if err != nil {
            response.FailErr(c, err) // 判定本身出错 → 5000，宁可拒绝不放行
            c.Abort()
            return
        }
        if !enabled {
            response.Fail(c, http.StatusForbidden, response.CodeForbidden, "面未启用")
            c.Abort()
            return
        }
        c.Next()
    }
}

步骤 2 · Gate 实现（homeos 侧）与装配

完整 · server/internal/homeos/faces/gate.gopackage faces

import (
    "context"

    "gorm.io/gorm"

    "homecube/internal/homeos/model"
)

// EnabledGate 用 S7·D2 的配置表实现 middleware.Gate。
type EnabledGate struct {
    db *gorm.DB
}

func NewEnabledGate(db *gorm.DB) *EnabledGate { return &EnabledGate{db: db} }

func (g *EnabledGate) Enabled(ctx context.Context, familyID int64, code string) (bool, error) {
    meta, ok := Get(code)
    if !ok || !meta.Born {
        return false, nil // 防御位：未出生面本就没有路由；真打进来也一律不放行
    }
    var n int64
    err := g.db.WithContext(ctx).Model(&model.FamilyModule{}).
        Where("family_id = ? AND code = ? AND enabled = true", familyID, code).
        Count(&n).Error
    return n > 0, err
}

步骤 3 · 测试

完整 · server/internal/platform/middleware/module_gate_test.gopackage middleware

import (
    "context"
    "encoding/json"
    "net/http/httptest"
    "testing"

    "github.com/gin-gonic/gin"
)

// fakeGate 进程内假实现：门禁逻辑的测试不需要真库（分工纪律：Recorder 进程内测）。
type fakeGate struct{ enabled bool }

func (f fakeGate) Enabled(ctx context.Context, familyID int64, code string) (bool, error) {
    return f.enabled, nil
}

func setup(gate Gate) *gin.Engine {
    gin.SetMode(gin.TestMode)
    r := gin.New()
    authStub := func(c *gin.Context) { c.Set("familyID", int64(1)); c.Next() }
    g := r.Group("/api/finance", authStub, ModuleGate(gate, "finance"))
    g.GET("/accounts", func(c *gin.Context) { c.JSON(200, gin.H{"code": 0}) })
    r.NoRoute(notFound) // notFound = 你 main 里已装配的全站 NoRoute handler（404 + 1001）；测试里复用同一个函数
    return r
}

func TestModuleGate(t *testing.T) {
    // ① 未启用 → 403 + 1003
    w := httptest.NewRecorder()
    setup(fakeGate{enabled: false}).ServeHTTP(w, httptest.NewRequest("GET", "/api/finance/accounts", nil))
    var body struct{ Code int `json:"code"` }
    json.Unmarshal(w.Body.Bytes(), &body)
    if w.Code != 403 || body.Code != 1003 {
        t.Fatalf("未启用: http=%d code=%d, want 403/1003", w.Code, body.Code)
    }

    // ② 已启用 → 放行 200
    w = httptest.NewRecorder()
    setup(fakeGate{enabled: true}).ServeHTTP(w, httptest.NewRequest("GET", "/api/finance/accounts", nil))
    if w.Code != 200 {
        t.Fatalf("已启用: http=%d, want 200", w.Code)
    }

    // ③ 未出生面域：无路由可打 → NoRoute 404 + 1001（与「真不存在」同形）
    w = httptest.NewRecorder()
    setup(fakeGate{enabled: true}).ServeHTTP(w, httptest.NewRequest("GET", "/api/purchase/items", nil))
    json.Unmarshal(w.Body.Bytes(), &body)
    if w.Code != 404 || body.Code != 1001 {
        t.Fatalf("未出生面: http=%d code=%d, want 404/1001", w.Code, body.Code)
    }
}

再补一条集成口径的测试（用真库 + S7·D2 的 UpdateEnabled）：停用 finance → 打 /api/finance/accounts 得 1003 → 重新启用 → 恢复 200。它验证的不是门禁逻辑（上面已验），而是门禁读的配置与 PUT 写的配置是同一份事实——配置变更即时生效，没有第二份缓存副本在中间捣乱。

常见坑（新手 100% 会踩）

坑现象正确姿势
给未出生面回 403等于广播「purchase 面存在，只是不给你看」，泄露未发布规划未出生 = 无路由 = NoRoute 404 + 1001，与真不存在同形
给未启用面回 404客户端无法区分「打错 URL」和「没开通」，给不出「去开启」引导1003 的语义就是「面未启用」，用在刀刃上
门禁挂在 Auth 之前familyID 是 0，全量请求 403顺序：Auth → ModuleGate → handler
忘了 c.Abort()拒绝了还继续跑 handler，响应被写两次拒绝路径必须 Abort；写进中间件的肌肉记忆
handler 里各自查一遍 enabled「门禁」散落几十处，漏一处就是穿透组级中间件一处收口；handler 只管业务
platform 直接 import homeos/faces依赖方向倒挂，platform 被业务绑架platform 定义 Gate 接口，homeos 实现，main 装配
门禁判定出错时放行DB 抖一下，停用面全开err → FailErr（5000）+ Abort：宁可拒绝，不放行

今日名词卡

术语一句话解释
零请求保证未挂载/未出生面客户端零请求；服务端三层纵深、层层独立兜底
路由门禁（ModuleGate）挂在面路由组上的中间件：未启用 → 403 + 1003
NoRoute 兜底没注册的路径全站统一 404 + 1001；未出生面零代码即被它接住
同形响应「不给你看」与「不存在」回一样的 404+1001，不泄露存在性
Gate 接口platform 定义、homeos 实现的启用判定接口；依赖方向不破的第三次同款操作
c.Abort()gin 中断后续 handler 链；中间件拒绝路径必调
纵深防御每层独立成立的多次拦截，不赌任何单点
fail-closed判定出错时拒绝而非放行；门禁类代码的默认姿态

卡壳时查什么

  • 中间件链与 Abort 语义：S2·D3 的中间件课（panic/recover 也在那儿）。
  • NoRoute 404 + 1001：S2·D1 换 Gin 时立的全站口径。
  • 错误码 1001/1003 的语义边界：S1·D4 码表 + S4 越权读返 404 的纪律。
  • 接口定义在 platform、实现在业务侧：S4 FamilyDirectory、S7·D8 DueRegistry。
