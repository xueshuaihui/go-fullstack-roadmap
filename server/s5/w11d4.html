config 加载定稿：一张变量表全站唯一

S1·D6 的名词卡写过：「端口——":8080" 先写死；S5 起从 PORT 读」。D9 的 main.go 已经在用 cfg.Port 和 cfg.GinMode，但那个 config 还是 S3 搭的毛坯。今天定稿：config 包成为全站配置的唯一入口——11 个环境变量一张表、必填校验 fail-fast、默认值只写一处、DSN 由 DB_* 在代码里拼。D8 说过的纪律「环境变量表全站唯一、禁别名」，今天落成代码。

今日目标

知识讲义

1. 变量表：全站唯一，就这 11 个

变量档位默认值用在哪
PORT默认档8080D9 main.go 的 srv.Addr——S1 写死的 ":8080" 今天正式退役
GIN_MODE默认档debuggin 的模式，D8 的 logger.Init 也复用它定日志级别（不另设变量）
DB_HOST / DB_USER / DB_PASS / DB_NAME必填档无拼 DSN 的四块料；凭据不设默认值——默认密码是事故之源
DB_PORT默认档5432Postgres 惯例端口
DB_SSLMODE默认档disable本机开发不折腾证书；生产收紧属 S8
JWT_SECRET / JWT_REFRESH_SECRET必填档无S4 双 token 的两把密钥；必须两把都显式给，缺一不放行
AUTO_MIGRATE默认档false启动时是否自动迁移（S3 引入）；bool 要 ParseBool，见坑表
禁别名，一个都不许有。SERVER_PORT、DB_PASSWORD 看着「更常见」，MYSQL_DSN、POSTGRES_DSN 看着「更方便」——全都禁止。同一配置有两个名字，文档、compose、排障命令就要各写两遍，漂移只是时间问题。DSN 更是原则问题：环境只给 DB_* 零件，拼装责任在代码；让部署方手拼连接串，等于把格式错误留到运行时才发现。

2. fail-fast：坏配置不许活到第一个请求

两种失败哲学：带病运行——os.Getenv("DB_HOST") 拿到空串照样启动，直到第一个查库请求才报「dial tcp: lookup : no such host」，错误现场离病因十万八千里；fail-fast——Load() 时就把所有必填项查一遍，缺了就报错退出，进程根本不起来。启动失败是最好排查的失败：时间点确定（启动那一刻）、影响面确定（一个请求都没服务过）、信息可以做全（一次列出所有缺项，而不是修一个再炸一个）。

fail-fast 的红线只有一条：错误消息里出现变量名，不出现变量值。「缺 JWT_SECRET」是诊断信息；把已有的半截密钥打进日志，是泄密事故。

3. 默认值只在一处

「PORT 默认 8080」这句话，全仓库只允许写在 config 包的一个 getEnv 调用里。如果 main.go、测试、文档各自 os.Getenv("PORT") + "8080" 兜底，改默认值就要全仓找一遍——这正是 D2「单一事实来源」在配置域的翻版：聚合结果的 TotalCents 从 ByCategory 求和而来，默认值从 config 一处而来，谁重复谁漂移。

4. DSN()：拼装是方法，不是环境变量

结构 · 连接串的来历环境（部署方负责）          代码（config 包负责）
DB_USER=homecube      ─┐
DB_PASS=homecube123    ├─▶  cfg.DSN()  ─▶  postgres://homecube:homecube123@localhost:5432/homecube?sslmode=disable
DB_HOST=localhost      │                         └── S3 的 MustOpenDB 只认这一个字符串
DB_PORT=5432          ─┘
DB_NAME=homecube
DB_SSLMODE=disable

DSN() 是 *Config 上的方法：给它零件，它还你连接串。S3 的 platform.MustOpenDB(cfg) 从今往后调的就是它——装配层永远不直接碰 os.Getenv。

今日增量（在学习仓里落盘）

今天属增量类型 ①：新能力（config 定稿）——把 S3 的毛坯 config 升级为「唯一入口 + 必填校验 + DSN 拼装」的定稿版，外加 t.Setenv 测试。收工时 make build / make test 必须绿。

步骤 1 · config.go 定稿版

完整 · server/internal/platform/config/config.go（覆盖 S3 毛坯；已有字段名以你仓库为准，缺的补齐package config

import (
    "fmt"
    "os"
    "strconv"
    "strings"
)

// Config 是全站环境变量的唯一入口。
// 变量表全站唯一：PORT / GIN_MODE / DB_HOST / DB_PORT / DB_USER / DB_PASS /
// DB_NAME / DB_SSLMODE / JWT_SECRET / JWT_REFRESH_SECRET / AUTO_MIGRATE。
// 禁止任何别名（SERVER_PORT、DB_PASSWORD、XXX_DSN 等），禁止在 config 包之外 os.Getenv。
type Config struct {
    Port             string
    GinMode          string
    DBHost           string
    DBPort           string
    DBUser           string
    DBPass           string
    DBName           string
    DBSSLMode        string
    JWTSecret        string
    JWTRefreshSecret string
    AutoMigrate      bool
}

// getEnv 是默认值的唯一存放处。
func getEnv(key, def string) string {
    if v := os.Getenv(key); v != "" {
        return v
    }
    return def
}

// Load 读环境变量并做必填校验：缺了就 fail-fast，
// 一次列出全部缺失变量名；错误消息不携带任何变量值。
func Load() (*Config, error) {
    cfg := &Config{
        Port:             getEnv("PORT", "8080"),
        GinMode:          getEnv("GIN_MODE", "debug"),
        DBHost:           os.Getenv("DB_HOST"),
        DBPort:           getEnv("DB_PORT", "5432"),
        DBUser:           os.Getenv("DB_USER"),
        DBPass:           os.Getenv("DB_PASS"),
        DBName:           os.Getenv("DB_NAME"),
        DBSSLMode:        getEnv("DB_SSLMODE", "disable"),
        JWTSecret:        os.Getenv("JWT_SECRET"),
        JWTRefreshSecret: os.Getenv("JWT_REFRESH_SECRET"),
    }

    am, err := strconv.ParseBool(getEnv("AUTO_MIGRATE", "false"))
    if err != nil {
        return nil, fmt.Errorf("config: AUTO_MIGRATE 必须是 true/false，收到 %q", getEnv("AUTO_MIGRATE", "false"))
    }
    cfg.AutoMigrate = am

    var missing []string
    for, item := range []struct{ key, val string }{
        {"DB_HOST", cfg.DBHost},
        {"DB_USER", cfg.DBUser},
        {"DB_PASS", cfg.DBPass},
        {"DB_NAME", cfg.DBName},
        {"JWT_SECRET", cfg.JWTSecret},
        {"JWT_REFRESH_SECRET", cfg.JWTRefreshSecret},
    } {
        if item.val == "" {
            missing = append(missing, item.key)
        }
    }
    if len(missing) > 0 {
        return nil, fmt.Errorf("config: 缺少必填环境变量: %s", strings.Join(missing, ", "))
    }
    return cfg, nil
}

// DSN 用 DB_* 拼 Postgres 连接串：拼装责任在代码，环境只给零件。
func (c *Config) DSN() string {
    return fmt.Sprintf("postgres://%s:%s@%s:%s/%s?sslmode=%s",
        c.DBUser, c.DBPass, c.DBHost, c.DBPort, c.DBName, c.DBSSLMode)
}

步骤 2 · config_test.go：t.Setenv 三件套

t.Setenv 是给测试临时改环境变量的正道：测试结束自动还原，互不污染。两条纪律：① 它与 t.Parallel() 互斥（同时用直接 panic，设计如此——并行测试共享进程环境，谁改谁害人）；② 测「缺失」要显式 t.Setenv(k, "")，不能赌开发机环境里恰好没有这个变量。

可跑 · server/internal/platform/config/config_test.gopackage config

import (
    "strings"
    "testing"
)

// setRequired 把六个必填项全部给齐（值是测试假数据）。
func setRequired(t *testing.T) {
    t.Helper()
    t.Setenv("DB_HOST", "localhost")
    t.Setenv("DB_USER", "homecube")
    t.Setenv("DB_PASS", "homecube123")
    t.Setenv("DB_NAME", "homecube")
    t.Setenv("JWT_SECRET", "test-access-secret")
    t.Setenv("JWT_REFRESH_SECRET", "test-refresh-secret")
}

// clearRequired 显式清空：不赌宿主机环境。
func clearRequired(t *testing.T) {
    t.Helper()
    for _, k := range []string{"DB_HOST", "DB_USER", "DB_PASS", "DB_NAME", "JWT_SECRET", "JWT_REFRESH_SECRET"} {
        t.Setenv(k, "")
    }
}

func TestLoadDefaults(t *testing.T) {
    setRequired(t)
    cfg, err := Load()
    if err != nil {
        t.Fatalf("Load() err = %v", err)
    }
    if cfg.Port != "8080" || cfg.GinMode != "debug" || cfg.DBPort != "5432" ||
        cfg.DBSSLMode != "disable" || cfg.AutoMigrate {
        t.Errorf("默认值不对: Port=%s GinMode=%s DBPort=%s SSLMode=%s AutoMigrate=%v",
            cfg.Port, cfg.GinMode, cfg.DBPort, cfg.DBSSLMode, cfg.AutoMigrate)
    }
}

func TestLoadMissingRequiredListsAll(t *testing.T) {
    clearRequired(t)
    _, err := Load()
    if err == nil {
        t.Fatal("缺必填变量时 Load() 应报错")
    }
    for _, key := range []string{"DB_HOST", "DB_USER", "DB_PASS", "DB_NAME", "JWT_SECRET", "JWT_REFRESH_SECRET"} {
        if !strings.Contains(err.Error(), key) {
            t.Errorf("错误信息应一次列全缺项，少了 %s: %v", key, err)
        }
    }
}

func TestDSN(t *testing.T) {
    setRequired(t)
    cfg, err := Load()
    if err != nil {
        t.Fatalf("Load() err = %v", err)
    }
    want := "postgres://homecube:homecube123@localhost:5432/homecube?sslmode=disable"
    if got := cfg.DSN(); got != want {
        t.Errorf("DSN() = %s, want %s", got, want)
    }
}

func TestAutoMigrateMustBeBool(t *testing.T) {
    setRequired(t)
    t.Setenv("AUTO_MIGRATE", "yes")
    if _, err := Load(); err == nil {
        t.Error("AUTO_MIGRATE=yes 应报错，而不是被悄悄当 false")
    }
    t.Setenv("AUTO_MIGRATE", "true")
    cfg, err := Load()
    if err != nil || !cfg.AutoMigrate {
        t.Errorf("AUTO_MIGRATE=true 应解析成功: cfg=%v err=%v", cfg, err)
    }
}

步骤 3 · main.go 接上两值签名

D9 的 main.go 里那行 cfg := config.Load() // S3 建的 config；签名以仓里为准 今天定稿为两值形式——Load 可能失败，失败就是启动失败：

片段 · server/cmd/homecube/main.go（只动开头几行，D9 的生命周期逻辑不变）cfg, err := config.Load()
if err != nil {
    // err 里只有变量名，没有变量值——这不是巧合，是 Load 的纪律。
    slog.Error("配置错误，启动中止", "err", err)
    os.Exit(1)
}
logger.Init(cfg.GinMode) // D8 的装配；级别仍由 GIN_MODE 决定，不新增变量
db := platform.MustOpenDB(cfg) // S3 的装配，内部改用 cfg.DSN()
顺序有讲究：Load 在 logger.Init 之前——配置都没读齐，先别谈日志级别；Load 失败的这条 Error 用 slog 默认 logger 打也够（进程马上就退出了）。另外全仓自查一遍：除了 config 包自己，任何地方不许再出现 os.Getenv——grep -rn "os.Getenv" server/internal server/cmd --include="*.go"，命中应全部落在 platform/config 目录里。

常见坑

坑现象正确姿势
别名心痒「SERVER_PORT 不是更常见吗」——变量表开始长第二套名字全站唯一 11 个，一个不多一个不少；常见 ≠ 正确，一致才正确
环境里塞整条 DSNPOSTGRES_DSN 手拼错一个字符，运行时才炸环境只给 DB_* 零件，DSN() 在代码里拼、在测试里锁
秘密值进日志启动日志打出整个 cfg，JWT 密钥躺进日志文件错误与日志只出现变量名；不给 Config 写全量打印
缺变量带病运行DB_HOST 为空照样启动，第一个查库请求报「no such host」Load 时 fail-fast，缺项一次列全，退出码 1
默认值散落main.go、测试各写一份 "8080" 兜底，改默认要全仓搜默认值只活在 config 包的 getEnv 调用里（单一事实来源）
AUTO_MIGRATE=false 被当真用 != "" 判断开关，字符串 "false" 非空 → 每次启动都迁移bool 一律 strconv.ParseBool，解析失败也是配置错误
t.Setenv 配 t.Parallel()测试直接 panic：cannot be parallel设计如此——环境是进程级共享资源，改环境的测试必须串行
测「缺失」赌宿主环境本机没导 DB_NAME 测试能过，CI 上导了反而挂显式 t.Setenv(k, "") 清空，测试自带前提

今日名词卡

术语一句话解释
配置中心化全部环境变量只从一个包进出；其他代码只认 *Config，不认 os.Getenv
fail-fast坏配置在启动那一刻就报错退出，不许活到请求路径上
必填档 / 默认档凭据与密钥必填（无默认值），端口模式类有默认值——两档分明，不许混
DSN数据库连接串；本站由 DB_* 经 DSN() 方法拼装，环境里不存在整条 DSN
别名禁令同一配置只许一个名字；SERVER_PORT / DB_PASSWORD / XXX_DSN 一律不收
os.Getenv读环境变量，未设置或为空都返回 ""（不区分两种情况——本站统一按缺失处理）
strconv.ParseBool把 "true/false/1/0" 解析成 bool；解析失败要当配置错误上报
t.Setenv测试内临时改环境变量、结束自动还原；与 t.Parallel() 互斥
秘密不落日志密钥类变量的值永不进日志与错误消息，能出现的只有变量名
AUTO_MIGRATE启动时是否自动跑迁移的开关，默认 false——迁移要不要自动，S3 讨论过，开关今天定稿

卡壳时查什么

正文自足，只有两种情况出去查：

  • ParseBool 认哪些字面量：strconv · ParseBool（可选，1/t/TRUE/yes 之类认不认，文档一句话的事）。
  • Getenv 的空串语义：os · Getenv（可选；想区分「未设置」与「设为空」才需要 LookupEnv，本站不需要）。

配置类问题的排查顺序：先确认变量真的注入进了进程（env | grep DB_ 看当前 shell，或临时加一行只打变量名的日志），再核对名字有没有打错（别名禁令的另一面：错了没有任何兜底会救你），最后才怀疑 Load 的代码。切记排查时不要把 .env 内容整段贴进任何聊天或 issue——里面有真密钥。
