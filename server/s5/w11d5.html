httptest.NewServer：给接口上 50 路并发

S1·D6 的名词卡写过：「httptest.NewRecorder——进程内假请求，S2 起天天用；httptest.NewServer——真监听真端口，S5 讲并发时再见」。今天还这张欠条。前四个阶段的接口测试全是 NewRecorder：handler 被当普通函数调，请求不过网络。这对单请求逻辑够用——但 D1 学的东西是「同一个服务被几十路并发打」，Recorder 根本不走真实连接，测不到。今天用 NewServer 给 /healthz 上 50 路并发，并用 make test 的 -race 全量收口。

今日目标

知识讲义

1. 分工表：Recorder 管逻辑，NewServer 管链路

httptest.NewRecorder（S2/S4 的老朋友）httptest.NewServer（今天）
本质进程内直接调 router.ServeHTTP(w, req)——不过网络起一个真实监听的 HTTP 服务，用真 http.Get 打过去
端口不需要内部就是 D9 坑表那招：127.0.0.1:0 系统随机分配，永不撞车
覆盖范围路由匹配、中间件、handler、响应体以上全部 + 真实连接管理、序列化传输、并发调度
并发测试不合适——Recorder 不是为并发写设计的正路——每路 goroutine 各发各的真请求
成本近乎零多一个监听与真实往返，仍然很快（本机 loopback）

选择规则一句话：逻辑断言用 Recorder，链路与并发用 NewServer。不是谁取代谁——S2 起的 Recorder 测试一个都不删，今天是补上另一半。

2. NewServer 三件套

片段 · 标准姿势srv := httptest.NewServer(newRouter(...)) // ① 真监听；地址在 srv.URL，形如 http://127.0.0.1:54321
defer srv.Close()                        // ② 收摊：关监听、断连接——忘了它就是测试间的泄漏源
resp, err := http.Get(srv.URL + "/healthz") // ③ 用标准 http 客户端打真请求

newRouter(...) 就是你仓里 D9 用过的装配函数——测试与生产共用同一份路由装配，测的才是真东西。/healthz 不碰 DB，装配参数给什么以你仓库的签名为准。

3. 并发收错：D1 + D2 的组合收尾

50 路 goroutine 各发一次请求，结果怎么收？本周学的两件兵器正好拼上：

  • WaitGroup（D1）：主 goroutine wg.Wait() 等全员跑完——Add 在 go 之前，纪律不变。
  • 缓冲错误通道（D2）：errs := make(chan error, n)，容量 = goroutine 总数，每路至多塞一条错误——发送永不阻塞，于是连 D5 的 closer goroutine 都省了。

断言放哪？全部挪回主 goroutine：wg.Wait() 之后 close(errs)，range 出来用 t.Error 逐条报。这比在 50 个 goroutine 里散着 t.Errorf 更好读（错误集中出现在测试末尾），也彻底绕开「goroutine 里不许 t.Fatalf」的雷（D1 坑表）。

4. -race 全量：红是铁证，绿只是证据

make test 从 S1·D1 起就带着 -race，今天是第一次有资格说「全量 -race 回归」——因为仓库里终于有了足量的并发代码（D1 的并发 Save、D3 的并发聚合、D5 的池、D9 的关闭、今天的 50 路并发）。两条认知钉死：

  • 红 = 铁证：race detector 报出来的竞争 100% 是真问题（它追踪的是实际发生的内存访问顺序，不靠猜）。
  • 绿 ≠ 无竞争：它只报这次运行里实际撞上的竞争。测试并发压力不够、调度没撞上，漏网之鱼照样绿。所以并发测试要给足路数（50 路起步），且关键并发路径要有专门用例——今天这个测试就是给 /healthz 链路「制造撞车机会」的。

代价也讲清楚：-race 让测试慢 5~10 倍、吃内存成倍涨——这是测试期的价格，生产构建不带 -race，一分钱不花。

今日增量（在学习仓里落盘）

今天属增量类型 ③：测试补齐——给 /healthz 补一个 50 路并发的 NewServer 测试，不改任何产品代码。收工时 make build / make test（含 -race 全量）必须绿。

步骤 1 · 并发测试落盘

可跑 · server 仓内与 newRouter 同包（目录以你仓库为准；newRouter 为你 D9 已有的装配函数）package main

import (
    "encoding/json"
    "fmt"
    "net/http"
    "net/http/httptest"
    "sync"
    "testing"
)

func TestHealthzUnderConcurrency(t *testing.T) {
    srv := httptest.NewServer(newRouter(nil)) // /healthz 不碰 DB；装配参数以你仓库签名为准
    defer srv.Close()

    const n = 50
    var wg sync.WaitGroup
    errs := make(chan error, n) // 容量=路数：每路至多塞一条，发送永不阻塞

    for i := 0; i < n; i++ {
        wg.Add(1) // Add 在 go 之前（D1 纪律）
        go func() {
            defer wg.Done()
            resp, err := http.Get(srv.URL + "/healthz")
            if err != nil {
                errs <- fmt.Errorf("GET /healthz: %w", err)
                return
            }
            defer resp.Body.Close()
            if resp.StatusCode != http.StatusOK {
                errs <- fmt.Errorf("status = %d, want 200", resp.StatusCode)
                return
            }
            var body struct {
                Code int `json:"code"`
            }
            if err := json.NewDecoder(resp.Body).Decode(&body); err != nil {
                errs <- fmt.Errorf("decode: %w", err)
                return
            }
            if body.Code != 0 { // 响应信封：code 0 = CodeOK
                errs <- fmt.Errorf("code = %d, want 0", body.Code)
            }
        }()
    }

    wg.Wait()  // 等全员收工——此刻所有发送已完成
    close(errs) // 主 goroutine 关，安全
    for err := range errs {
        t.Error(err) // 断言集中在主 goroutine：不散、不 race、不用碰 Fatalf 雷区
    }
}

步骤 2 · 单点跑，再全量跑

验收命令cd <你的学习仓根目录>/server
go test -race -run TestHealthzUnderConcurrency ./... -v   # 单用例：PASS，且 -v 里没有 WARNING: DATA RACE
make test                                                 # 全量 -race 回归：本周所有并发用例一起过

跑完留意两件事：① 全量 -race 的耗时——和平时比慢出 5~10 倍的部分，就是「铁证保险」的价格；② 输出末尾的 ok 列表里，D1/D3/D4/D5/D9 的用例应该全在——这一屏绿，是 S5 十一天并发代码的集体体检报告。

步骤 3 · 把并发压力拧大跑一次（可选，30 秒）

把 n 临时改成 200 再跑一遍单用例。绿了改回 50（仓库里留 50，CI 时间要省）；红了——恭喜，你抓到了真问题，顺着 WARNING 三段式（D3）读栈定位。无论红绿，改动都不进提交：这一步是体验，不是增量。

为什么只测 /healthz？它是当前唯一不属于任何业务域的探活接口。报表与流水的接口要 S6 才登记——那时它们的并发测试会照今天这个模子写（NewServer + WaitGroup + 缓冲收错），今天把模子造好就够了。S5 不新增任何业务接口。

卡壳时查什么

正文自足，只有两种情况出去查：

  • NewServer/Close 的权威语义：net/http/httptest · NewServer（可选，几行注释讲完全部行为）。
  • 并发测试里 t.Fatal 为什么不能用：testing · T（可选，文档明说 FailNow 必须来自跑测试的那个 goroutine）。

并发测试红了别慌，按 D3 的三段式读 WARNING：先找两个 goroutine 各自的栈，再定位共享变量，最后想「这里该用锁还是该用通道」。若红的是产品代码而不是测试代码——今天赚大了，这正是把并发靶场搭起来的全部意义。
