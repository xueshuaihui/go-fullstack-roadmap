周六 · 统计聚合并发版：把本周串起来

本周五天的零件今天要合体成一台机器：D1 的 WaitGroup、D2 的 channel 与对照组、D3 的 Mutex、D4 的 ctx、D5 的 worker pool，全部装进一个函数——Aggregate：多账户、多分类两个维度并行聚合，超时可控，还顺手兑现 S1·D2 埋下的 strings.Builder 伏笔。老规矩：不新增任何业务接口——这个函数是 service 层骨架，S6 的报表接口登记后由 handler 调用它、把 Report 装进响应信封；今天它的唯一消费者是测试里的确定性假数据。

今日目标

知识讲义

1. 今天要拼装的机器

目标形状：Aggregate(ctx, workers, rows) 吃一批流水行，吐一份 Report。内部两条流水线——按分类聚合、按账户聚合——形状完全相同，只差「拿哪个字段当分组键」。所以正确的抽象不是复制两份池子，而是把 D5 的池泛化一个维度参数：keyOf func(AggInput) int64。Go 的函数是一等公民（S1·D5 的接口思想在这里的另一面），传个取键函数比传个 bool 标志体面得多。

本周零件在 Aggregate 里的位置
D1 · goroutine + WaitGroup池子的 worker 起法与收工计数
D2 · channel + 对照组jobs/outcomes 两条传送带；SumByCategory 当验收标尺
D3 · Mutex + -race无——今天的结果收集全走 channel，共享写为零；-race 当验收仪器
D4 · ctx首参贯穿；派活、交活、求和三处检查点；超时映射 DeadlineExceeded
D5 · pool + closer整条流水线的骨架，原样复用

D3 那行「无」值得咂摸：池化 + channel 收集之后，共享内存消失了，锁自然也就不需要了——这就是 D2 那句谚语的完整体验：通过通信来共享内存。等 S6 要在聚合里加缓存时，锁会回来；届时你能说清「这一块为什么用锁、那一块为什么用 channel」，S5 的判据就真过了。

2. strings.Builder：兑现 S1·D2 的伏笔

S1·D2 常见坑里写过：「循环里用 + 拼字符串，量大时慢得离谱」，标准答案 strings.Builder，兑现位置写着「S5 报表拼接处」——就是今天的 buildSummary。原因一句话：Go 字符串不可变，s += x 每次都整段复制，n 行就是 O(n²)；Builder 内部维护一块可增长的字节缓冲，摊还 O(n)。用法三步：var b strings.Builder → 循环里 Fprintf(&b, …) / b.WriteString(…) → b.String() 收尾。S6 的 CSV 导出是它的重头戏，今天先在 Summary 上把手感练出来。

3. 假数据的边界（S5 纪律重申）

Report 是给 S6 报表接口预备的形状，但今天假数据只活在测试里（fakeRows），service 函数本身是纯函数：进来 rows、出去 Report，不碰库不碰路由。这不是偷懒，是切分：并发骨架的正确性用假数据就能 100% 验证（确定性生成 + 串行对照），真查询接进来时只换数据源、不动骨架。

步骤 1 · 把池泛化成「按任意维度」

agg_pool.go 里的 SumByCategoryPool 保持签名不变（已有测试还指着它），内部改为委托给新的泛化版：

完整 · server/internal/finance/service/agg_pool.go（覆盖 D5 版）package service

import (
    "context"
    "sort"
    "sync"
)

// categoryKey / accountKey 是两个维度的取键函数。
func categoryKey(r AggInput) int64 { return r.CategoryID }
func accountKey(r AggInput) int64  { return r.AccountID }

// dimensionIDs 提取去重后的维度键，升序返回。
func dimensionIDs(rows []AggInput, keyOf func(AggInput) int64) []int64 {
    seen := map[int64]bool{}
    ids := []int64{}
    for _, r := range rows {
        if id := keyOf(r); !seen[id] {
            seen[id] = true
            ids = append(ids, id)
        }
    }
    sort.Slice(ids, func(i, j int) bool { return ids[i] < ids[j] })
    return ids
}

// CategoryIDs 保持 D3 的公开签名，委托给泛化版。
func CategoryIDs(rows []AggInput) []int64 { return dimensionIDs(rows, categoryKey) }

// sumOneDimension 对单个维度键求和；ctx 检查点与 D4 相同。
func sumOneDimension(ctx context.Context, id int64, rows []AggInput, keyOf func(AggInput) int64) (AggResult, error) {
    select {
    case <-ctx.Done():
        return AggResult{}, fmt.Errorf("聚合维度 %d: %w", id, ctx.Err())
    default:
    }
    time.Sleep(20 * time.Millisecond) // 模拟一次慢 IO；S6 换成真查询，检查点不动

    var total int64
    for _, r := range rows {
        if keyOf(r) == id {
            total += r.AmountCents
        }
    }
    return AggResult{ID: id, TotalCents: total}, nil
}

// sumByDimension 池化并行聚合：三角色 + closer，形状与 D5 完全一致。
func sumByDimension(ctx context.Context, workers int, rows []AggInput, keyOf func(AggInput) int64) ([]AggResult, error) {
    if workers < 1 {
        workers = 1
    }
    ids := dimensionIDs(rows, keyOf)
    jobs := make(chan int64)
    type outcome struct {
        res AggResult
        err error
    }
    outcomes := make(chan outcome)

    var wg sync.WaitGroup
    for i := 0; i < workers; i++ {
        wg.Add(1)
        go func() {
            defer wg.Done()
            for id := range jobs {
                res, err := sumOneDimension(ctx, id, rows, keyOf)
                select {
                case outcomes <- outcome{res, err}:
                case <-ctx.Done():
                    return
                }
                if err != nil {
                    return
                }
            }
        }()
    }
    go func() {
        defer close(jobs)
        for _, id := range ids {
            select {
            case jobs <- id:
            case <-ctx.Done():
                return
            }
        }
    }()
    go func() {
        wg.Wait()
        close(outcomes)
    }()

    out := []AggResult{}
    var firstErr error
    for o := range outcomes {
        if o.err != nil {
            if firstErr == nil {
                firstErr = o.err
            }
            continue
        }
        out = append(out, o.res)
    }
    if firstErr != nil {
        return nil, firstErr
    }
    sort.Slice(out, func(i, j int) bool { return out[i].ID < out[j].ID })
    return out, nil
}

// SumByCategoryPool 签名不变（D5 的测试还指着它），委托泛化版。
func SumByCategoryPool(ctx context.Context, workers int, rows []AggInput) ([]AggResult, error) {
    return sumByDimension(ctx, workers, rows, categoryKey)
}

import 块记得补 "fmt" 与 "time"（sumOneDimension 要用）。同时把 D4 的 agg_ctx.go 里的 sumOneCategory 改成委托：return sumOneDimension(ctx, id, rows, categoryKey)——一处逻辑只许活一份，这是 S2 起的老纪律。

步骤 2 · Report 与 Aggregate

完整 · server/internal/finance/service/report.gopackage service

import (
    "context"
    "fmt"
    "strings"
)

// Report 是聚合报告的骨架。S6 起由登记的报表接口把它装进统一响应信封；
// S5 不注册任何路由——今天它唯一的消费者是测试。
type Report struct {
    ByCategory []AggResult
    ByAccount  []AggResult
    TotalCents int64
    Summary    string
}

// Aggregate 多分类 + 多账户两个维度并行聚合，ctx 控制超时，workers 控制并发。
// 两个维度先后跑（各自内部并行）；把两条流水线再套一层 errgroup 并行是本周之后的练习题，今天不做——先要正确，再要更快。
func Aggregate(ctx context.Context, workers int, rows []AggInput) (*Report, error) {
    byCat, err := sumByDimension(ctx, workers, rows, categoryKey)
    if err != nil {
        return nil, fmt.Errorf("按分类聚合: %w", err)
    }
    byAcc, err := sumByDimension(ctx, workers, rows, accountKey)
    if err != nil {
        return nil, fmt.Errorf("按账户聚合: %w", err)
    }

    var total int64
    for _, r := range byCat {
        total += r.TotalCents
    }
    return &Report{
        ByCategory: byCat,
        ByAccount:  byAcc,
        TotalCents: total,
        Summary:    buildSummary(byCat, byAcc, total),
    }, nil
}

// buildSummary 拼人读摘要。strings.Builder 在此兑现 S1·D2 的伏笔：
// 循环 += 拼字符串是 O(n²)，Builder 摊还 O(n)。S6 的 CSV 导出同一套手感。
func buildSummary(byCat, byAcc []AggResult, total int64) string {
    var b strings.Builder
    fmt.Fprintf(&b, "总计 %d 分\n", total)
    b.WriteString("按分类:\n")
    for _, r := range byCat {
        fmt.Fprintf(&b, "  分类 %d: %d 分\n", r.ID, r.TotalCents)
    }
    b.WriteString("按账户:\n")
    for _, r := range byAcc {
        fmt.Fprintf(&b, "  账户 %d: %d 分\n", r.ID, r.TotalCents)
    }
    return b.String()
}

import (
    "context"
    "errors"
    "strings"
    "testing"
    "time"
)

func TestAggregateMatchesSerial(t *testing.T) {
    rows := fakeRows()                       // D3 的确定性假数据：4 账户 × 6 分类
    got, err := Aggregate(context.Background(), 4, rows)   // 本用例自己的 ctx，谁也不借
    if err != nil {
        t.Fatalf("不该出错: %v", err)
    }

    // 维度一：与 D2 串行对照组全等——本周验收的第一条
    if want := SumByCategory(rows); !equalResults(got.ByCategory, want) {
        t.Fatalf("ByCategory 与串行对照不一致:\ngot  %+v\nwant %+v", got.ByCategory, want)
    }

    // 维度二：按账户的期望值在测试里现算（4 个账户，手算得清）
    wantAcc := map[int64]int64{}
    for _, r := range rows {
        wantAcc[r.AccountID] += r.AmountCents
    }
    if len(got.ByAccount) != len(wantAcc) {
        t.Fatalf("ByAccount 条数 = %d, want %d", len(got.ByAccount), len(wantAcc))
    }
    var total int64
    for _, r := range got.ByAccount {
        if wantAcc[r.ID] != r.TotalCents {
            t.Fatalf("账户 %d: got %d, want %d", r.ID, r.TotalCents, wantAcc[r.ID])
        }
        total += r.TotalCents
    }
    if got.TotalCents != total {
        t.Fatalf("TotalCents = %d, want %d", got.TotalCents, total)
    }

    // Summary：Builder 拼出来的摘要必须逐段在场
    for _, frag := range []string{"总计", "按分类:", "按账户:", "分类 10:", "账户 4:"} {
        if !strings.Contains(got.Summary, frag) {
            t.Fatalf("Summary 缺少 %q:\n%s", frag, got.Summary)
        }
    }
}

func TestAggregateTimeout(t *testing.T) {
    rows := fakeRows()                       // 两个维度共 10 个键 × 20ms，单 worker 要 200ms

}

常见坑（串联日专属）

坑现象正确姿势
泛化时改了 SumByCategoryPool 签名D5 的测试编译失败，回头改测试迁就新签名公开签名不动，内部委托——测试是合同，合同不跟着实现改
两处 sumOne… 各留一份逻辑改一处忘另一处，两个维度行为悄悄分叉一处逻辑只活一份：旧函数一律改成委托新函数
两个维度共用一条超时 ctx 还各自计时第一条流水线吃掉全部预算，第二条必超时预算按「整份报告」定，两个维度共享同一条 ctx 是对的——红线只禁「对照组借超时 ctx」，不禁流水线内部共用
TotalCents 从 rows 再扫一遍不算错，但和 ByCategory 各算各的，两处可能不一致单一事实来源：总数从已聚合的维度结果里加出来
Summary 用 += 拼几十行看不出差别，S6 导出几万行时 O(n²) 教做人循环拼接一律 strings.Builder——伏笔已兑现，别再欠新账
