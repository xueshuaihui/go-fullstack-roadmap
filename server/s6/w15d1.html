预算模型与月度预算创建

B1-B4 的 20 条接口上周已全部划掉，从今天起进入 B5 预算段。预算表 S3 就建好了，但一直没写业务——今天给它补上 Go 侧 struct、一条部分唯一索引迁移，以及第一个接口：POST /api/finance/budgets。先把「一行预算到底是什么」定义清楚，后面四天的超支判定、未设标记、告警钩子才有地基。

今日目标

知识讲义

1. 一行预算 = 一个周期键上的一条限额

预算不做「规则引擎」，就是一张朴素的表：某家庭在某个周期键上，对某个分类（或全体）设一个金额上限。周期键复用全站时间窗五档的编码（2026-10、2026-Q4、2026……），但预算只收 month / quarter / year 三档——day/week 档传进来返回 400 + 1004。为什么砍掉两档：「按周期归零」的口径是按自然月/季/年定义的，给「某一天」设预算没有归零语义，产品上也不存在这个入口。

字段类型语义
period_keyTEXT NOT NULL周期键，如 2026-10；创建时由统一的周期解析函数校验格式
category_idBIGINT NULLNULL = 该周期总预算；非空 = 分类级预算（明天讲判定）
limit_centsBIGINT NOT NULL限额，必须 > 0，否则 400 + 4001（金额非法）
通用列—id / family_id / created_at / updated_at / deleted_at / deleted_by / version，S3 起全站同款

归零口径：10 月的预算行只管 10 月。11 月要预算就再插一行 period_key='2026-11'；10 月没花完的钱不结转。所以「复制上月预算」是前端的便捷操作（读上月行、改周期键、再 POST），服务端不存任何「周期规则」——存了就有两套真相。

2. 唯一约束：同家庭同周期同分类只许一行

重复创建必须撞唯一约束，映射成 409 + 1006。但这里有个 Postgres 的经典坑：唯一索引把 NULL 视为互不相等。(family_id, period_key, category_id) 直接建唯一索引的话，两行总预算（category_id 都是 NULL）能同时插进去——防重失效。两个手法叠加解决：

  • 表达式索引：对 COALESCE(category_id, 0) 建索引，把 NULL 归一成 0（真实分类 id 从 1 起，0 不会被占用）。
  • 部分索引：加 WHERE deleted_at IS NULL，让软删的行退出唯一约束——否则「删掉重建同周期预算」会被一行尸体挡住。

3. 创建路径上的错误码分工

情形HTTP + code说明
JSON 解析失败 / 字段类型不对400 + 1004参数错误，绑定层直接拒
period_key 不是合法五档编码（如 2026-13）400 + 1007时间窗编码非法专码，不回落到任何默认档
编码合法但是 day/week 档（如 2026-W42）400 + 1004预算不支持的档位是「参数不支持」，不是「编码非法」，两码分工要记牢
limit_cents ≤ 0400 + 4001金额非法专码，不要混用 1004
category_id 不存在或属别的家庭404 + 1001越权与不存在同形，不泄露存在性
同周期同分类已有行409 + 1006唯一约束冲突

步骤 1 · Budget struct

片段 · server/internal/finance/model/budget.go（前置：S3 已建 finance_budget 表，通用列嵌入 S3 建好的 model.Base）package model

// Budget 一行 = 某家庭某周期键上、对某分类（NULL=总预算）的限额。
type Budget struct {
    Base                          // id/family_id/时间戳/软删/version，S3 起全站同款
    PeriodKey  string `gorm:"column:period_key;not null"`
    CategoryID *int64 `gorm:"column:category_id"`       // 指针表达 NULL：总预算
    LimitCents int64  `gorm:"column:limit_cents;not null"`
}

func (*Budget) TableName() string { return "finance_budget" }

CategoryID 必须是 *int64 而不是 int64。用值类型的话「NULL」和「0」在 Go 侧不可区分，而 0 在我们的表达式索引里恰恰是总预算的归一值——类型选错，语义就塌了。

步骤 3 · POST handler

片段 · server/internal/finance/handler/budget.go（前置：S2 三层与 S4 的鉴权中间件、scope helper 已就位；response 包签名同 S2）type createBudgetReq struct {
    PeriodKey  string `json:"period_key" binding:"required"`
    CategoryID *int64 `json:"category_id"`
    LimitCents int64  `json:"limit_cents" binding:"required"`
}

func (h *BudgetHandler) Create(c *gin.Context) {
    var req createBudgetReq
    if err := c.ShouldBindJSON(&req); err != nil {
        response.FailErr(c, response.ErrBadRequest) // 400 + 1004
        return
    }
    famID := c.GetInt64("familyID")          // S4 中间件注入，禁止裸键
    b, err := h.svc.Create(c.Request().Context(), famID, req.PeriodKey, req.CategoryID, req.LimitCents)
    if err != nil {
        response.FailErr(c, err)              // service 返回哨兵：1004/4001/1001/1006
        return
    }
    response.Created(c, b)                    // 201 + code 0
}

service 层 Create 做四件事，顺序不能乱：① 用 S6·D8 写好的周期解析函数校验 period_key，编码非法 → ErrBadPeriod（1007）；编码合法但档位不在 {month, quarter, year} → ErrBadRequest（1004）；② limitCents ≤ 0 → ErrInvalidAmount（4001）；③ categoryID 非空时按 scope helper 查一次分类（带 WHERE family_id = ?），查不到 → ErrNotFound（1001）；④ 插入，捕获唯一冲突翻译成 ErrConflict（1006）。

片段 · 路由注册（server/internal/finance/handler/routes.go 的 finance 分组内追加一行）g := r.Group("/api/finance", middleware.Auth(cfg.JWTSecret))
g.POST("/budgets", budgetH.Create)

常见坑（新手 100% 会踩）

坑现象正确姿势
唯一索引不带 COALESCE两行总预算（category_id 均 NULL）同时插入成功，防重失效对 COALESCE(category_id, 0) 建表达式索引
唯一索引不带 WHERE deleted_at IS NULL软删一行后，同周期预算再也建不了部分索引把软删行排除在约束外
limit_cents ≤ 0 返回 1004错误码表被稀释，前端没法按码给文案金额非法专码 4001；1004 只管参数形状
用 float 接金额再乘 1002999.99 * 100 = 299998.99… 截断丢分DTO 里就是 int64 分，前端负责乘除 100
把「未用完结转」做进服务端预算表里出现 carry_over 列，两套真相打架归零口径写死：一期一行，不结转
手写周期键拼接（fmt.Sprintf("%d-%02d", …)）各处格式漂移，季度键拼出 2026-Q04 之类全站只认 S6·D8 的解析/格式化函数一份实现

今日名词卡

术语一句话解释
period_key（周期键）时间窗五档编码字符串；预算只收 month/quarter/year 三档
按周期归零每个周期键独立一行预算，未用完不结转下期
总预算category_id IS NULL 的预算行，管该周期全部分类合计
表达式索引建在 COALESCE(category_id, 0) 这类表达式上的索引，用来把 NULL 归一
部分索引（partial index）带 WHERE 条件的索引；这里用 deleted_at IS NULL 让软删行退出唯一约束
*int64 可空外键指针区分「NULL」与「0」；值类型做不到
1006唯一约束冲突专码，HTTP 409
4001金额非法专码（≤0 等），HTTP 400
哨兵错误service 返回预定义错误值，FailErr 按 S1·D4 的映射翻成码

卡壳时查什么

  • 唯一索引与 NULL 的行为：Postgres 官方文档 Unique Indexes（可选，一段话讲清 NULL 不相等）。
  • GORM 里怎么捕获唯一冲突：查 errors.Is(err, gorm.ErrDuplicatedKey) 的用法（可选；需要在 session 上开 TranslateError，S3 讲过）。
  • 错误码拿不准：回本站 S1·D4 的错误码全表卡，任何码都必须在那张表里。
