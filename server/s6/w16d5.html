面内设置与 CSV 导出

一天收掉 B 段最后四条接口里的三条半：GET/PUT /api/finance/settings（面内设置）与 GET /api/finance/reports/export（导出，CSV 格式决策今天一并定案）。设置接口的灵魂是「活配置，禁死 UI」——每个字段都要指得出真实消费方；导出接口的灵魂是那条红线——行数 = 同筛选条件下的查询行数，筛选参数一个都不许悄悄丢。

今日目标

知识讲义

1. 活配置：每个字段都要有消费方

「死 UI」是指设置页存在、能改、能存，但没有任何代码读它——用户改了附件上限，上传照旧。防死 UI 的办法不是自觉，是记账：每个设置字段登记消费方，登记不出来的字段不许进表。

字段类型消费方（真实读取点）
alert_threshold_pctSMALLINT，1-100D22 的 CheckAlert：今天把硬编码 80 换成读这里
attachment_max_count / attachment_max_size_kbSMALLINT / INT附件上传校验（S6·D12）：超限 → 400 + 4002，阈值从设置读
default_account_id / default_category_idBIGINT NULLGET settings 原样返回，前端记账表单预填；PUT 时校验属本家庭（404 + 1001 同形）
通用列 + version—PUT 乐观锁老三步（第三遍半了，应该已经会背）

形态口径：家庭级单行。GET 直接返回该行（表空时返回默认值行并顺手落库，即「首访播种」）；PUT 用 upsert 语义但仍走 version 乐观锁。响应是单对象不是 list——它连「有界小集合」都不是，就一行。

面内设置（/api/finance/settings）与全局设置（homeos 域，S7 落地）是两条接口：前者管财务面自己的阈值与默认项，后者管主题、通知开关这类壳级配置。今天只做前者；分域纪律不许把 finance 的字段塞进全局设置，反之亦然。

2. 导出格式决策：CSV，理由写进 notes

候选是 XLSX 与 CSV，今天定案 CSV，三条理由（收口日会检查你 notes/ 里有没有这段）：

  1. 判据与格式无关：本阶段对导出的验收是「行数 = 同筛选查询行数、字段列齐全、三参数全生效」，没有一条要求单元格样式或公式。XLSX 的增值（多 sheet、样式）在判据外。
  2. 零第三方依赖：encoding/csv 是标准库；XLSX 要引入外部库，学习仓的依赖面越小，S8 打包越快、审计面越小。
  3. 流式天然：CSV 边查边写边 Flush，内存与行数无关；XLSX 是 zip 容器，多数库要攒完整棵树才能落盘，行数红线遇上大表反而更危险。

代价也要记下来：CSV 没有类型（Excel 会把长数字转科学计数）、没有多 sheet。缓解手段：金额列导出两位小数字符串（不是裸 cents 整数，免得用户看到 300000 以为是三十万）+ 首行 BOM 让 Excel 认出 UTF-8。日后真要 XLSX，加一个 format=xlsx 参数与一个第三方库即可，接口形状不动——这也是把格式决策写进 notes 的原因：它是可逆决策，不值得今天多付依赖成本。

3. 行数红线：三参数全生效 + 全员数据

这条红线来自一个真实反例：导出接口后端不读筛选参数、且只导当前用户——用户看着筛选后的 37 行点导出，文件里是全部 500 行（或者反过来只有自己的 12 行）。口径拆成三条：

  • 筛选参数与查询接口同一套：period、account_id、category_id、member_id……导出与 GET /api/finance/transactions 共用同一个条件构建函数（D25 的 base 思想）——「全生效」不是靠自觉，是靠共享代码。
  • 全员数据：导出的是家庭维度数据，不是「我的」数据；member_id 是筛选参数而非隐含过滤。行级可见性照旧：非 owner 导不出别人私密行（D25 的红线测试同款口径）。
  • 行数可验证：同筛选条件下，导出文件数据行数 == 查询接口逐页翻完的总行数。测试里两边都数一遍。

角色口径：访客（guest）不可导出——限时只读角色对「批量带出数据」这种能力天然拒绝，403 + 1003。这是四级角色矩阵在 S6 的显式落点。

4. 流式写出：Gin 里的文件响应

片段 · 文件流响应三件套（前置：Gin 的 c.Header / c.Status / c.Writer 在 S2 用过 JSON 版）c.Header("Content-Type", "text/csv; charset=utf-8")
c.Header("Content-Disposition", `attachment; filename="transactions-2026-10.csv"`) // 文件名服务端生成，绝不拼用户输入
c.Status(200)
_, _ = c.Writer.Write([]byte{0xEF, 0xBB, 0xBF}) // UTF-8 BOM：Excel 打开中文不乱码的关键三字节

注意：文件流响应不套三键信封。{"code","message","data"} 是 JSON 接口的契约；导出返回的是文件本体，错误时才回到信封（比如 1003）——所以校验全部前置，第一个字节写出之后就不许再失败：状态码已发出，没有回头路（S1·D6 的「笔顺」纪律在文件流上更残酷）。

步骤 2 · export handler

片段 · server/internal/finance/handler/export.go（前置：authz 判 guest → 1003；条件构建函数与流水列表共享）func (h *ExportHandler) ExportTransactions(c *gin.Context) {
    if err := h.authz.RequireExport(c); err != nil { // guest → 403 + 1003，写第一字节之前拦住
        response.FailErr(c, err); return
    }
    f, err := h.svc.BuildFilter(c)          // period/account_id/category_id/member_id，与列表接口同一个解析器
    if err != nil { response.FailErr(c, err); return }

    // ……三件套 header + BOM（见讲义）……
    w := csv.NewWriter(c.Writer)
    _ = w.Write([]string{"日期", "类型", "分类", "账户", "成员", "金额(元)", "备注"})
    rows, err := h.svc.StreamExport(c.Request().Context(), f) // GORM Rows()：逐行取，不全量进内存
    if err != nil { h.log.Error("export stream", "err", err); return } // 已写出头，无法改状态码：只能记日志断流
    defer rows.Close()
    for rows.Next() {
        rec, err := h.svc.ScanExportRow(rows) // 分类/账户/成员名批量预取，循环里不许发查询（N+1 禁令）
        if err != nil { h.log.Error("export row", "err", err); break }
        _ = w.Write(rec)                     // encoding/csv 错误只在 Flush 时暴露；故意忽略须注释（S1·D4 纪律）
    }
    w.Flush()
}
片段 · 金额格式化：分 → 两位小数字符串，全程整数运算（前置：无；注意负数）func formatCents(c int64) string {
    sign := ""
    if c < 0 { sign, c = "-", -c }
    return fmt.Sprintf("%s%d.%02d", sign, c/100, c%100)
}

负数是 formatCents 的命门：Go 的 % 保留被除数符号，-12345 % 100 == -45。不先取绝对值就 Sprintf("%d.%02d", c/100, c%100)，-123.45 元会打成 -123.-45。测试必须含负数用例——转账退款、冲正流水都是负的。

常见坑（新手 100% 会踩）

坑现象正确姿势
设置字段没有消费方用户改了阈值，告警照旧 80%——死 UI每个字段登记消费方；登记不出就不进表
导出自己拼筛选条件与列表接口口径漂移，行数对不上共享同一个条件构建函数
只导当前用户的流水「全员数据」口径被破，家庭对账缺一块member_id 是筛选参数，不是隐含过滤
负金额格式化出 -123.-45Go 的 % 保留被除数符号先取符号与绝对值再拼；测试含负数
忘写 BOMExcel 打开中文列头全乱码首三字节 EF BB BF，有测试盯着
全量查进内存再转 CSV大表导出 OOM，流式白讲GORM Rows() 逐行写；名字批量预取防 N+1
写出头之后再想改状态码superfluous WriteHeader，错误混进文件流一切校验前置；第一字节之后只许记日志

今日名词卡

术语一句话解释
活配置 vs 死 UI每个设置字段都有真实读取点；改了就生效，否则不许上架
首访播种（seed on read）GET 时表空则写默认行再返回；PUT 不必处理「行不存在」分支

Content-Dispositionattachment; filename=…：告诉客户端这是下载文件；文件名服务端生成
