环比与服务端逐期累计余额

报表的最后一块硬骨头，也是本阶段第二条红线：累计余额由服务端逐期累加，前端二次累加须为 0。顺带把环比做掉：上一期同口径桶 + 变化率。两件事共享同一个前提——「期」的算术（上一期是哪期、期初余额从哪来）必须是纯函数，且和昨天的桶序列同源。

今日目标

知识讲义

1. 环比：粒度跟着档位走

「环比」= 与紧邻的上一期比，粒度随档位：月档比上月、周档比上一 ISO 周、季档比上季、年档比上年、日档比昨天。实现只有一个要点：在周期键层面做算术，不要拿日期减。「2026-01 的上一期」是 2025-12——键算术一行搞定；若拿 AddDate(0,-1,0) 从某个具体日期倒推，就会撞上 D23/D26 反复出现的月末规整化坑。上一期算出来后，复用昨天的同一个桶查询查上期数据（同一套 WHERE、同一个 Viewer），保证口径同源——环比两期用了两套过滤条件，是报表最隐蔽的错法。

片段 · server/internal/finance/service/period/prev.go（前置：D8 的解析包；纯函数，表驱动测试）// Prev 返回上一期的周期键。全部键层面算术：
//   day:     2026-03-01 → 2026-02-28（解析成真日期后减一天，day 档允许碰日期）
//   week:    2026-W01   → 2025-W53（ISOWeek 反解回该周星期四，减 7 天再取 ISOWeek，跨年自动正确）
//   month:   2026-01    → 2025-12
//   quarter: 2026-Q1    → 2025-Q4
//   year:    2026       → 2025
func Prev(p Period) Period

week 档那句「反解回星期四再减 7 天」是 ISO 周的标准技巧：星期四永远落在周的「归属年」内，拿它做锚点，跨年周边界不会算错。

2. 变化率：万分比整数 + null 语义

金额禁浮点的纪律延伸到比率：change_bp = (cur - prev) * 10000 / prev（整数除法，负增长自然是负数）。唯一的边界是 prev = 0：数学上无定义，工程上有三种错法——返回 0（谎报「持平」）、返回极大数（图表爆轴）、返回字符串（类型污染）。正确姿势：*int64 指针，序列化成 null，前端渲染「—」。

3. 累计余额：服务端逐期累加，前端零累加

trend 视图每个桶追加一个字段 running_balance_cents：截至该桶期末的家庭资金累计余额。定义拆开是两段：

  • 期初（opening）：窗口第一个桶开始前的全部净流——各账户初始余额之和 + 窗口前所有流水的净贡献。一条 SQL：occurred_at < start 的净额聚合（同样带 base 过滤与可见性）。
  • 逐桶累加：running = opening 起步，按桶序 running += income - expense，写进每个桶。

转账去哪了？家庭总口径下转账净贡献为 0：钱从 A 账户出、进 B 账户，家庭总量不变。所以累加式里根本没有 transfer 项——这不是遗漏，是口径。账户单账户口径的余额另有其人（账户接口 S6·D13 起就算好了），报表的 running 是家庭合计。

红线原文：累计余额由服务端逐期累加，前端二次累加须为 0。意思是：前端拿到 running_balance_cents 序列只做一件事——画线。它不做 reduce((a,b)=>a+b.net) 之类的再累加；服务端也不许只发净额序列让前端自己累计。为什么这么狠：多端（App/H5）各累加一遍，舍入与断桶处理稍有不一致，两条端的余额曲线就分叉，而用户会拿它和银行对账。钱相关的派生数列只允许有一个生产者。

红线怎么变成测试？给序列一个自洽判据：running[i] - running[i-1] == net[i] 对每个 i 成立，且 running[0] == opening + net[0]。任何一端偷偷改口径（比如前端又累加了一遍），差值等式当场破裂。

4. int64 会不会溢出

顺手算一笔账安下心：int64 上限约 9.2×10^18 分 = 9.2×10^16 元。一个家庭记一百万年账也到不了。真正的溢出风险在中间乘法：D22 的 used*100、今天的 (cur-prev)*10000——家庭级金额（<10^12 分）乘一万离上限还差六个数量级，安全；但同样的式子搬到「全平台汇总」场景就要重新评估。口径：乘系数前先想清楚量级上界，想不清楚就先除后乘（精度换安全）。

步骤 1 · 累加纯函数

可跑 · server/playground/d27/main.go（独立 go.mod；跑通后 WithRunning 搬进 report_service.go，目录删除）package main

import "fmt"

type Bucket struct {
    Key                 string
    IncomeCents         int64
    ExpenseCents        int64
    NetCents            int64
    RunningBalanceCents int64
}

// WithRunning 原地写入逐期累计余额：running = opening + Σ net。转账不出现——家庭口径净贡献为 0。
func WithRunning(bs []Bucket, opening int64) {
    running := opening
    for i := range bs {
        bs[i].NetCents = bs[i].IncomeCents - bs[i].ExpenseCents
        running += bs[i].NetCents
        bs[i].RunningBalanceCents = running
    }
}

func main() {
    bs := []Bucket{
        {Key: "2026-08", IncomeCents: 500000, ExpenseCents: 300000},
        {Key: "2026-09", IncomeCents: 0, ExpenseCents: 120000},
        {Key: "2026-10", IncomeCents: 520000, ExpenseCents: 610000},
    }
    WithRunning(bs, 1000000) // 期初 1 万元（1000000 分）
    for _, b := range bs {
        fmt.Printf("%s net=%d running=%d\n", b.Key, b.NetCents, b.RunningBalanceCents)
    }
    // 2026-08 net=200000  running=1200000
    // 2026-09 net=-120000 running=1080000
    // 2026-10 net=-90000  running=990000
}

常见坑（新手 100% 会踩）

坑现象正确姿势
只发净额让前端累加多端曲线分叉，红线击穿running 序列服务端产出，前端只画线
上期比率除零返回 0「上期为 0 本期 5 万」显示成持平*int64 → null，前端渲染「—」
prev 用日期倒推月末规整化、跨年周归属连环错周期键算术；week 档锚星期四
环比两期各写一套过滤本期含私密行、上期不含，比率失真同一个 aggregate 函数只换周期参数
把转账算进 running一笔内部转账让家庭余额翻倍家庭口径转账净贡献 0，累加式无 transfer 项
opening 忘了初始余额累计曲线整体平移一个常数opening = 初始余额之和 + 窗口前净流
