账户 CRUD 与默认账户唯一性

流水域闭环后，今天开账户域。表在 S3 就建好了（finance_account：名称、类型、币种、初始余额、信用额度与账单日、is_default、通用列），余额口径 D3 也定了——今天把三条接口接起来：GET 列表（每行带现算余额）、POST 创建（同家庭账户名唯一）、PUT 编辑（乐观锁）。外加一条业务规则：is_default 每家庭至多一个。

今日目标

知识讲义

1. 账户列表 = 小集合 + 派生字段

一个家庭的账户数量级是「几个到十几个」，永远一页放得下——所以 GET /api/finance/accounts 走小集合口径：返回 {"list":[…]}，不带 next_cursor/has_more（对照 D6 的大列表）。但每行要带一个表里没有的字段：balance_cents——D3 定的推导式，现场对每个账户调一次 BalanceOf。N 个账户 N 次聚合，量级小无所谓；真要省，一条 GROUP BY 全算出来，作为选做。

片段 · 列表行的形状{"id":1,"name":"招行储蓄卡","type":"debit","currency":"CNY",
 "initial_balance_cents":10000,"balance_cents":18750,
 "is_default":true,"archived_at":null,"version":3}

currency 只存不算：它只是展示与录入时的单位标签（分 = 该币种最小单位），服务端永远不做汇率换算，多币种账户各算各的余额，不合并、不折美元。

2. 名字撞了：1006 的分族逻辑

同家庭内账户名唯一（「支付宝」不能有两个）。冲突时返回 409 + 1006（唯一约束冲突族：手机号、邀请码、同家庭内账户名共用）。为什么不回 400/1004：请求本身格式完美，是它与库中既有事实相撞——409 Conflict 的语义就是「你和现存状态冲突」，1004 管的是「你话没说对」。客户端拿到 1006 才知道该提示「换个名字」而不是「检查输入」。

实现上有两层：数据库部分唯一索引兜底（撞了捕获唯一冲突转 1006），service 层可先查一次给出更友好的文案——但裁决权在索引，先查后插之间永远有并发缝，别指望它。

片段 · 部分唯一索引（S3 迁移里应已有；没有则今天补一条迁移）CREATE UNIQUE INDEX uq_finacct_name
    ON finance_account (family_id, name)
    WHERE deleted_at IS NULL;   -- 软删行不占名字：删掉「支付宝」后可以再建一个

3. 默认账户唯一性：清旧立新同事务

规则：每家庭至多一个 is_default = true。创建或编辑时若请求带 is_default: true，服务端在同一个事务里做两步：

片段 · 事务内的两步（伪码）BEGIN;
UPDATE finance_account SET is_default = false
 WHERE family_id = ? AND is_default = true AND id <> ?;   -- 清旧
INSERT/UPDATE 目标行 is_default = true ...;                  -- 立新
COMMIT;

不这么做的两种翻车：只立新不清旧 → 两个 default，前端「默认账户」不知道显示谁；清旧与立新分两个事务 → 中间崩了，全家没有 default。另定一条口径：「取消自己的 default」不允许空转——PUT 里把唯一默认账户改成 is_default:false 返回 409 + 1010（业务状态不允许：家庭必须始终有且只有一个默认账户，先设别的为默认再来）。首个创建的账户自动成为默认。

步骤 1 · 三条接口

片段 · server/internal/finance/handler/account.go 与 main.go 注册fin.GET("/accounts", accth.List)
fin.POST("/accounts", accth.Create)
fin.PUT("/accounts/:id", accth.Update)
片段 · service.Create 的关键分支（前置：AccountRepo 已有 Insert/UpdateWithVersion/ListAlive）func (s *AccountService) Create(ctx context.Context, a Actor, in *CreateAccountInput) (*model.Account, error) {
    if in.InitialBalanceCents < 0 { return nil, response.ErrAmountInvalid } // 期初余额可以为 0，不能为负
    first, _ := s.repo.CountAlive(ctx, a.FamilyID)
    if first == 0 { in.IsDefault = true }              // 首个账户自动默认
    acct, err := s.repo.Insert(ctx, a.FamilyID, in)      // 事务内含「清旧 default」；唯一索引冲突 → 转哨兵
    if errors.Is(err, gorm.ErrDuplicatedKey) {
        return nil, response.ErrUniqueConflict             // 409 + 1006
    }
    return acct, err
}

GORM 默认不把唯一冲突翻译成 ErrDuplicatedKey，需要开 TranslateError 配置；没开就直接匹配 Postgres 错误码 23505。两条路都行，选一条在全站 repo 层统一，别一处一个写法。

步骤 2 · List 拼余额

片段 · service.List（小集合 + 派生字段）func (s *AccountService) List(ctx context.Context, a Actor) ([]AccountView, error) {
    rows, err := s.repo.ListAlive(ctx, a.FamilyID) // 含归档行，archived_at 由前端过滤展示（明天做归档）
    if err != nil { return nil, err }
    views := make([]AccountView, 0, len(rows))
    for _, r := range rows {
        bal, err := s.txRepo.BalanceOf(ctx, a.FamilyID, r.ID) // D3 的推导式聚合
        if err != nil { return nil, err }
        views = append(views, toView(r, bal))
    }
    return views, nil
}

常见坑（新手 100% 会踩）

坑现象正确姿势
清旧 default 与立新不同事务中途失败全家没默认，或双默认一个事务两步走；或数据库部分唯一索引 WHERE is_default 兜底
账户名唯一忘了限定 family_id两个家庭不能各有一个「现金」唯一索引是 (family_id, name) 联合维度，且带 WHERE deleted_at IS NULL
重名回 1004「换个名字」与「检查格式」两种提示混了唯一冲突族走 409 + 1006
列表返回表里裸行没有 balance_cents，前端又去逐账户拉余额派生字段在 service 拼好再出网
把余额存回账户表「省得每次算」D3 刚定的单一事实源被打破余额永远现算；提速走缓存层，不落列
PUT 不带 version 也放行乐观锁被绕过，丢失更新复活version 必填，缺了 1004——与 D5 流水编辑同口径
currency 参与任何计算出现「折美元合计」之类的幻觉字段只存不算，多币种各自独立

今日名词卡

术语一句话解释
小集合口径不分页集合返回 {"list":[…]}，无 next_cursor/has_more；账户、分类树、成员都走它
派生字段表里没有、响应里有：balance_cents 由聚合现算后拼进视图对象
1006唯一约束冲突（409）：手机号、邀请码、同家庭内账户名同族
部分唯一索引带 WHERE 的 UNIQUE INDEX；这里让软删行不占用名字
is_default每家庭至多一个 true；首户自动默认；取消唯一默认 → 1010
清旧立新设新默认的同事务里把旧默认置 false，规则由服务端保证而非客户端自觉
TranslateErrorGORM 把驱动错误翻译成标准哨兵（如 ErrDuplicatedKey）的开关
Postgres 23505唯一冲突的数据库错误码；不开 TranslateError 时按它匹配
币种只存不算currency 是标签不是汇率入口；服务端不做任何换算

卡壳时查什么

  • BalanceOf 的公式与实现：S6·D3，今天第一次有了真实消费方。
  • 乐观锁 UPDATE 的固定形状：S6·D5，账户 PUT 原样照抄流水那套。
  • 事务怎么用（GORM Transaction 闭包）：S3 换 DB 与 S5 并发周都出现过，清旧立新再练一次。
  • 1006 与 1004 的分族：错误码表——「话没说对」1004，「与现存状态相撞」1006。
