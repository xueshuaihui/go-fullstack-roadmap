分类级预算与超支判定

昨天能创建预算了，今天让它「有用」：GET /api/finance/budgets 返回指定周期的预算列表，每行带 已用（used_cents）、剩余（remaining_cents）、是否超支（overspent）。核心是一条对流水表的聚合 SQL，外加三个口径决策：父子分类怎么归并、哪些流水算「已用」、周期边界怎么切。这三个决策每一个都能悄悄算错钱。

今日目标

知识讲义

1. 「已用」的定义：一条 SQL 说清楚

已用金额 = 该周期内、该家庭、该分类（含子分类）的支出流水之和。四个过滤条件一个都不能少：

片段 · 聚合 SQL（$1=family_id，$2/$3=周期半开区间，时区口径见下）SELECT category_id, COALESCE(SUM(amount_cents), 0) AS used_cents
FROM finance_transaction
WHERE family_id = $1
  AND deleted_at IS NULL
  AND direction = 'expense'
  AND occurred_at >= $2 AND occurred_at < $3
GROUP BY category_id;
  • COALESCE(SUM(…), 0)：一张流水都没有时 SUM 返回 NULL 不是 0。NULL 进了 Go 侧的 int64 会扫出错误或零值歧义——预算页显示「已用 null」就是事故。
  • direction = 'expense'：收入不进预算；转账更不进——转账是钱在家庭内部换口袋，家庭总支出一分没变。把 transfer 算进已用，预算会凭空膨胀一倍（转出+转入各记一次的话）。
  • 半开区间 [start, end)：10 月的区间是 [2026-10-01T00:00, 2026-11-01T00:00)。用 <= end 的话，11 月 1 日零点整的流水会被两个周期同时算进去。
  • deleted_at IS NULL：回收站里的流水不算已用（S6·D11 恢复流水时要重算预算，就是这个口径的反向）。

时区口径：occurred_at 是 TIMESTAMPTZ，周期边界必须按家庭时区切，否则东八区家庭在月底晚上记的账会掉进下个月的预算。家庭时区不从 homeos 的表里查（跨模块禁令），走 S4 建好的 platform 家庭上下文接口拿 *time.Location，再算出 UTC 边界传进 SQL。这个接口在报表五档分桶（S6·D26）还要用，今天一次接对。

2. 父子分类归并：两级树只有一条规则

分类是两级树（S2 起的老朋友）。预算可以挂在任意一级：

预算挂在已用口径实现
二级（叶子）分类该叶子自己的流水聚合结果直接取 used[leafID]
一级分类自己（若有直挂流水）+ 全部子分类流水used[parentID] + Σ used[childID]
总预算（category_id NULL）全部分类流水合计Σ 聚合结果全部行

做法：SQL 按流水上的 category_id（永远是叶子或直挂分类）GROUP BY 出 map[int64]int64，Go 侧拿着分类树做一次归并。不要在 SQL 里做树形递归——两级树用一条 parent_id 查询就能在 Go 里摊平，SQL 保持朴素，测试才好写。

双算陷阱：如果流水既可以挂一级分类又可以挂它的子分类，归并时「一级自己的直挂流水」和「子分类流水」是两拨行，相加恰好不重不漏；但如果你先把子分类流水 UPDATE 到父分类再聚合，就会和直挂流水混在一起分不清。原则：流水上的 category_id 永不改写，归并只发生在读路径。

3. 超支判定与响应形状

三个派生字段全部服务端算好，前端只渲染：remaining_cents = limit_cents - used_cents（可以为负）；overspent = used_cents > limit_cents。预算列表是有界小集合（一个家庭一个周期撑死几十行），按全站口径直接返回 {"list":[…]}，不带 next_cursor/has_more。

片段 · 响应 data（金额全是 int64 分；overspent 是服务端判定，不让前端拿 used 和 limit 自己比）{
  "period": "2026-10",
  "budget_unset": false,
  "list": [
    { "id": 1, "category_id": null, "limit_cents": 300000,
      "used_cents": 312000, "remaining_cents": -12000, "overspent": true, "version": 1 },
    { "id": 2, "category_id": 7, "limit_cents": 80000,
      "used_cents": 20000, "remaining_cents": 60000, "overspent": false, "version": 1 }
  ]
}

budget_unset 今天恒为 false（查的周期有行才走到这）；明天专门讲它什么时候必须是 true——那是全站红线之一。

步骤 1 · repo 层聚合查询

片段 · server/internal/finance/repo/transaction_repo.go 追加（前置：S3 的 GORM 实例 db 已在 repo struct 里）// SumExpenseByCategory 返回 categoryID → used_cents。空结果返回空 map，不返回 nil。
func (r *TransactionRepo) SumExpenseByCategory(ctx context.Context, famID int64, start, end time.Time) (map[int64]int64, error) {
    type row struct {
        CategoryID int64
        UsedCents  int64
    }
    var rows []row
    err := r.db.WithContext(ctx).
        Table("finance_transaction").
        Select("category_id, COALESCE(SUM(amount_cents), 0) AS used_cents").
        Where("family_id = ? AND deleted_at IS NULL AND direction = ? AND occurred_at >= ? AND occurred_at < ?",
            famID, "expense", start, end).
        Group("category_id").
        Scan(&rows).Error
    if err != nil {
        return nil, fmt.Errorf("sum expense by category: %w", err)
    }
    out := make(map[int64]int64, len(rows))
    for _, r := range rows {
        out[r.CategoryID] = r.UsedCents
    }
    return out, nil
}

步骤 2 · service 归并与判定

片段 · server/internal/finance/service/budget_service.go（前置：昨天的 Create 已在；cats 是 S2 起的分类树查询，带 family scope）func (s *BudgetService) ListForPeriod(ctx context.Context, famID int64, periodKey string) (*BudgetListResult, error) {
    p, err := period.Parse(periodKey)          // S6·D8 的解析函数；非法 → ErrBadPeriod(1007)
    if err != nil { return nil, err }
    loc, err := s.families.Timezone(ctx, famID) // platform 家庭上下文接口，跨模块只走这里
    if err != nil { return nil, err }
    start, end := p.BoundsIn(loc)              // 半开区间 [start, end)

    budgets, err := s.repo.FindByPeriod(ctx, famID, periodKey)
    if err != nil { return nil, err }
    used, err := s.txRepo.SumExpenseByCategory(ctx, famID, start, end)
    if err != nil { return nil, err }
    tree, err := s.cats.Tree(ctx, famID)        // 用于父分类归并
    if err != nil { return nil, err }

    items := make([]BudgetItem, 0, len(budgets))
    for _, b := range budgets {
        u := rollup(b.CategoryID, used, tree)   // NULL→全量合计；父级→自己+子级；叶子→自己
        items = append(items, BudgetItem{
            ID: b.ID, CategoryID: b.CategoryID, LimitCents: b.LimitCents,
            UsedCents: u, RemainingCents: b.LimitCents - u, Overspent: u > b.LimitCents,
            Version: b.Version,
        })
    }
    return &BudgetListResult{Period: periodKey, BudgetUnset: false, List: items}, nil
}

rollup 是纯函数（输入 map + 树，输出 int64），单独放一个文件、单独写表驱动测试——聚合 SQL 测不了的部分，都推给纯函数来测，这是 S5 报表段立下的老规矩。

常见坑（新手 100% 会踩）

坑现象正确姿势

overspent 让前端自己比两个端两种判定，口径漂移服务端算好布尔值，前端只渲染

卡壳时查什么

  • SUM/GROUP BY 语法拿不准：Postgres 官方文档 Aggregate Functions（可选，教程一章）。
  • GORM 的 Table/Select/Scan 组合：回本站 S3 的 GORM 查询卡；聚合查询用 Table()+Scan()，不要用 Find() 硬套模型。
  • 分类树查询长什么样：回本站 S2 分类段的卡，树在内存里摊平的做法当时立过。
