面内设置：活配置与币种只存不算

财务面的最后两条接口：GET / PUT /api/finance/settings。设置页是「死 UI」的重灾区——前端摆了一排开关，PUT 也真的存进了库，但服务端没有任何一行代码去读它，用户改了等于没改。今天的判据只有一条：存进去的每一项，都要指出谁在消费它。顺带立一条币种纪律：只存不算——currency 是个标签，服务端永远不做汇率换算。

今日目标

知识讲义

1. 活配置判据：每项都有消费方

设置项字段合法域消费方
币种currency三位大写字母（如 CNY）账户展示、CSV 导出的金额列头——只做标签，不做汇率
附件张数上限attachment_max_count1 ~ 3（法定上限 3）D8 上传接口的张数校验
附件单张上限attachment_max_size_mb1 ~ 5（法定上限 5）D8 的 MaxBytesReader 与大小校验
默认账户default_account_id本家庭未归档未软删账户，可空记账表单的账户预选
默认支出/收入分类default_category_expense_id / …_income_id本家庭未停用分类，可空记账表单的分类预选

两条推论：

  • 消费方不存在的项目不进表。比如「预算提醒阈值」——预算模块还没写，现在存进去就是一项死配置。等消费它的那条课开出来的当天，再加一列（一次迁移的事），这正是设置表可扩展性的正确用法。
  • 法定上限封死可调区间。张数最多调到 3、单张最大调到 5MB——设置能收紧、不能放大平台红线。越界值返回 400 + 1004，不静默夹取：悄悄把 9 夹成 3 会让「PUT 返回 200」和「GET 读回 3」对不上，用户以为存的是 9。这和 D14 时间窗「不回落」是同一条哲学。

2. 币种只存不算

currency 存的是 ISO 4217 风格的三位大写码。服务端对它的全部职责是：存、校验格式、原样吐回。三条禁令：

  • 不做汇率换算——没有 rates 表，没有换算函数，一处都不许出现。
  • 不跨币种聚合——余额推导（D3）按账户各算各的，账户间不做「折成同一币种再加总」；教学期一个家庭一个币种，多币种账户只是标签不同、数字不互算。
  • 不改历史——改了设置里的 currency，已落库的流水金额分文不动，历史 CSV 里存的仍是当时的 *_cents 整数。

为什么这么狠：汇率是个无底洞（历史时点价、买入卖出价、精度舍入），而记账产品的本分是把数记对。「只存不算」是范围纪律写进数据观——金额永远是 *_cents int64，currency 永远只是个标签。

3. 表形态：每家庭一行，故意不上乐观锁

设置表是全站唯一一张「没有 id、没有 version、没有软删三件套」的表：family_id 直接做主键，每家庭一行。这不是偷懒，是三个有意的取舍：

常规做法设置表的选择理由
BIGSERIAL id 主键family_id 做主键「每家庭至多一份」由主键天然保证，upsert 直接用 ON CONFLICT (family_id)
乐观锁 version（D5）后写覆盖（last-write-wins）流水被覆盖丢的是账；设置被覆盖丢的是偏好，且 PUT 是全量提交、随时可改回——上锁属过度设计
软删 deleted_at不软删设置行没有「删除」语义，只有「恢复默认」（PUT 回默认值）

GET 的口径：无行不 404——没存过设置的家庭返回一份默认值（CNY / 3 张 / 5MB / 默认项全空）。设置是「有则读、无则默认」的配置面，不是资源集合。

4. 权限：读放开，写收 owner

GET 对家庭内所有角色开放（含 guest——只读设置不涉密）。PUT 是家庭级配置变更，只给 owner：其余角色 403 + 1003。判定照旧收在 platform/authz，finance 里只问一句 CanManageSettings(role)。

步骤 2 · 模型、校验与仓储

完整 · server/internal/finance/model/setting.gopackage model

import (
    "errors"
    "regexp"
)

// 法定上限：设置只能收紧，不能放大平台红线。
const (
    HardMaxAttachmentCount = 3
    HardMaxAttachmentMB    = 5
)

var currencyRe = regexp.MustCompile(`^[A-Z]{3}$`)

type Setting struct {
    FamilyID                  int64  `json:"family_id"`
    Currency                  string `json:"currency"`
    AttachmentMaxCount        int    `json:"attachment_max_count"`
    AttachmentMaxSizeMB       int    `json:"attachment_max_size_mb"`
    DefaultAccountID          *int64 `json:"default_account_id"`
    DefaultCategoryExpenseID  *int64 `json:"default_category_expense_id"`
    DefaultCategoryIncomeID   *int64 `json:"default_category_income_id"`
}

// DefaultSetting 无行时 GET 返回的口径（有则读、无则默认，不 404）。
func DefaultSetting(familyID int64) Setting {
    return Setting{
        FamilyID: familyID, Currency: "CNY",
        AttachmentMaxCount: HardMaxAttachmentCount, AttachmentMaxSizeMB: HardMaxAttachmentMB,
    }
}

// Validate 越界一律报错（→ 1004），绝不静默夹取。
func (s Setting) Validate() error {
    if !currencyRe.MatchString(s.Currency) {
        return errors.New("currency 必须是三位大写字母")
    }
    if s.AttachmentMaxCount < 1 || s.AttachmentMaxCount > HardMaxAttachmentCount {
        return errors.New("attachment_max_count 合法域 1~3")
    }
    if s.AttachmentMaxSizeMB < 1 || s.AttachmentMaxSizeMB > HardMaxAttachmentMB {
        return errors.New("attachment_max_size_mb 合法域 1~5")
    }
    return nil
}
片段 · repo：一读一 upsert，外加默认项存在性校验func (r *SettingRepo) Get(ctx context.Context, familyID int64) (model.Setting, error) {
    var s model.Setting
    err := r.db.WithContext(ctx).Where("family_id = ?", familyID).First(&s).Error
    if errors.Is(err, gorm.ErrRecordNotFound) {
        return model.DefaultSetting(familyID), nil   // 无行不 404
    }
    return s, err
}

func (r *SettingRepo) Upsert(ctx context.Context, s model.Setting) error {
    return r.db.WithContext(ctx).
        Clauses(clause.OnConflict{Columns: []clause.Column{{Name: "family_id"}}, UpdateAll: true}).
        Create(&s).Error
}

步骤 3 · 两条路由

片段 · server/internal/finance/handler/setting.go 与路由注册fin.GET("/settings", settingh.Get)   // 家庭内所有角色可读（含 guest）
fin.PUT("/settings", settingh.Put)   // 仅 owner

func (h *SettingHandler) Put(c *gin.Context) {
    a := actorFrom(c)
    if !authz.CanManageSettings(a.Role) {                // owner → true，其余 false
        response.Fail(c, http.StatusForbidden, response.CodeForbidden, "仅所有者可修改家庭设置") // 403 + 1003
        return
    }
    var in model.Setting
    if err := c.ShouldBindJSON(&in); err != nil {
        response.Fail(c, http.StatusBadRequest, response.CodeInvalidParam, "请求体不合法"); return
    }
    in.FamilyID = a.FamilyID                              // family_id 永远取自 token，不信请求体
    s, err := h.svc.Put(c.Request.Context(), a, in)       // Validate → 默认项存在性 → Upsert
    if err != nil { response.FailErr(c, err); return }
    response.OK(c, s)
}

import (
    "encoding/json"
    "net/http/httptest"
    "strings"
    "testing"
)

func TestSettingsLiveConfig(t *testing.T) {
    r, tk := newTestRouter(t)

    // 1) 无行 GET：默认值口径（不 404）
    w := do(t, r, "GET", "/api/finance/settings", "", tk.Owner)
    if w.Code != 200 || !strings.Contains(w.Body.String(), `"currency":"CNY"`) {
        t.Fatalf("无行应返回默认设置, got %d %s", w.Code, w.Body.String())
    }

    // 2) owner PUT 收紧附件限额 → 200，且 GET 读回一致
    body := `{"currency":"CNY","attachment_max_count":1,"attachment_max_size_mb":2,` +
        `"default_account_id":null,"default_category_expense_id":null,"default_category_income_id":null}`
    w = do(t, r, "PUT", "/api/finance/settings", body, tk.Owner)
    if w.Code != 200 { t.Fatalf("owner PUT 应 200, got %d %s", w.Code, w.Body.String()) }

    // 3) 活配置证据：限额收紧到 1 张后，第 2 张附件 4002
    txID := seedOneTx(t, r, tk.Owner)
    uploadAttachment(t, r, tk.Owner, txID, "a.jpg", fakeJPEG(1024))       // 第 1 张 201
    w = uploadAttachment(t, r, tk.Owner, txID, "b.jpg", fakeJPEG(1024))
    if w.Code != 400 || decodeBizCode(t, w.Body) != 4002 {
        t.Fatalf("限额=1 时第 2 张应 400+4002, got %d %s", w.Code, w.Body.String())
    }

    // 4) 越界值不静默夹取：count=9 → 400+1004
    bad := strings.Replace(body, `"attachment_max_count":1`, `"attachment_max_count":9`, 1)
    w = do(t, r, "PUT", "/api/finance/settings", bad, tk.Owner)
    if w.Code != 400 || decodeBizCode(t, w.Body) != 1004 {
        t.Fatalf("越界应 400+1004, got %d %s", w.Code, w.Body.String())
    }

    // 5) 币种格式：小写 "cny" → 400+1004
    bad = strings.Replace(body, `"currency":"CNY"`, `"currency":"cny"`, 1)
    w = do(t, r, "PUT", "/api/finance/settings", bad, tk.Owner)
    if w.Code != 400 || decodeBizCode(t, w.Body) != 1004 {
        t.Fatalf("币种格式错应 400+1004, got %d %s", w.Code, w.Body.String())
    }

    // 6) member PUT → 403+1003（家庭级配置仅 owner）
    w = do(t, r, "PUT", "/api/finance/settings", body, tk.MemberA)
    if w.Code != 403 || decodeBizCode(t, w.Body) != 1003 {
        t.Fatalf("member PUT 应 403+1003, got %d %s", w.Code, w.Body.String())
    }

    // 7) member GET 仍可读，且第 1 步存的限额还在（last-write-wins 不影响读）
    w = do(t, r, "GET", "/api/finance/settings", "", tk.MemberA)
    var env struct{ Data json.RawMessage `json:"data"` }
    json.Unmarshal(w.Body.Bytes(), &env)
    if !strings.Contains(string(env.Data), `"attachment_max_count":1`) {
        t.Fatalf("member 应读到已存设置, got %s", env.Data)
    }
}

常见坑（新手 100% 会踩）

坑现象正确姿势
死 UIPUT 200 了，但上传口还是老常量，改了等于没改今天的步骤 4 就是判据：D8 常量退役，消费方读设置
越界值静默夹取PUT 9 张返回 200，GET 读回 3——写读不一致，用户懵合法域外一律 400 + 1004，和 D14「不回落」同一哲学
拿 family_id 信了请求体伪造 body 改别人家的设置in.FamilyID = a.FamilyID，永远取自 token
给设置表上乐观锁为改个默认分类还要处理 1009，代码翻倍last-write-wins：偏好被覆盖可改回，账被覆盖才是事故
无行时 GET 返回 404新家庭一进设置页就报错有则读、无则默认；404 只属于「资源不存在」，设置不是资源集合
default_account_id 指向已归档账户表单预选了一个不能记账的账户，提交才 1010PUT 时就校验：不存在 1004、已归档/已停用 1010（D10/D11 语义复用）
顺手写了个汇率换算「就一张 rates 表」滚成无底洞币种只存不算；换算需求出现的那天再立项，不在本阶段

今日名词卡

术语一句话解释
活配置存进去的每个设置项都有真实消费方；判据是「指出谁在读它」
死 UI前端有设置页、后端也存了，但没有任何代码消费——改了等于没改
法定上限平台红线（3 张 / 5MB）；设置只能在红线内收紧，不能放大
只存不算currency 是标签：不建汇率表、不换算、不跨币种聚合、不改历史
不静默夹取越界值 400+1004 拒收，而不是悄悄改成边界值再存
upsert / ON CONFLICT有行则更新、无行则插入；family_id 主键让「每家庭一份」天然成立
last-write-wins设置表的并发口径：后写覆盖，不上乐观锁——偏好丢了可改回
记账默认项default_account_id 与两个默认分类：记账表单的预选来源，可空
有则读、无则默认GET 设置永不 404：没存过就吐一份 DefaultSetting

卡壳时查什么

  • 被替换的附件限额：S6·D8——三条限额一个 4002；今天只是把常量换成设置读取，校验位置一律不动。
  • 为什么设置不上乐观锁：S6·D5——1009 保护的是「并发编辑会丢账」的场景，对着那张表读一遍取舍。
  • 默认项的存在性校验：S6·D9/D10/D11——账户归档、分类停用后的「不可被引用」语义。
  • 角色判定放哪儿：S4 的 authz 收口课；今天新增 CanManageSettings(role) = role == RoleOwner。
  • 迁移成对与编号：S3 第一条迁移那天——up/down 成对、编号接现有最大号。
