未设周期预算：budget_unset 红线

今天一整天只讲透一条红线，外加把 B5 的最后一个接口 PUT /api/finance/budgets/{id} 落掉。红线原文：「该周期未设预算」不是错误——接口正常返回 200，payload 带 budget_unset: true 标记，不得返回折算值。这句话每个字都有对应的错误写法，今天逐个枪毙。

今日目标

知识讲义

1. 什么叫「折算值」，为什么它是红线

用户只给 10 月设了 30 万的月预算。前端切到季视图问「2026-Q4 的预算是多少」，服务端有两种「聪明」的错法：

错法返回为什么错
折算limit_cents: 900000（月×3）用户从没设过季度预算。90 万是服务端编出来的数，用户看到「本季预算 9000 元」会以为自己设过；超支判定跟着全错。这不是计算，是造假
报错误404 + 1001「未设预算」是正常业务状态不是资源缺失。返回错误码会逼前端把「没设预算」渲染成「出错了」，还会污染错误率监控
含糊空值budget_unset:false, list:[]前端无法区分「没设」和「设了但被软删/归零」，只能靠猜

唯一正确姿势：200 + code 0，budget_unset: true，list 为空。前端拿到这个标记渲染「未设该周期预算 + 去设置」的空态入口。标记字段是显式契约的一部分，写进响应结构体，不是「文档里提一嘴」。

片段 · 未设预算时 GET /api/finance/budgets?period=2026-Q4 的完整响应{
  "code": 0, "message": "ok",
  "data": { "period": "2026-Q4", "budget_unset": true, "list": [] }
}

红线的作用域不止这一个接口。凡是「按周期读预算」的出口——本接口、报表里的预算对比列（S6·D25 起）、首页摘要的预算区（S7）——都走同一条判定：只认库里真实存在的预算行，查不到就置标记，任何地方都不许乘除折算。判定收在 service 层一个函数里，出口再多也只有一份实现。

2. 「未设」的判定条件要写全

「该周期预算不存在」= 按 (family_id, period_key) 查，deleted_at IS NULL 的行数为 0。注意两点：

  • 软删的行算「未设」。用户删掉了 10 月预算，10 月就该显示未设，而不是拿尸体行充数。
  • 判定在周期键精确匹配层做，不做「月档没有就往季档找」之类的层级回退——回退本质上还是折算的亲戚。

3. PUT：编辑限额与 version 乐观锁

B5 的第三条接口管「改」：只许改 limit_cents（想换周期就建新行，周期键不可改，否则唯一索引和历史对账全乱）。乐观锁三步，S6 前半段在流水和账户上已经练过两遍，这里是第三遍，动作应该形成肌肉记忆：

  1. 请求体必带 version；不带 → 400 + 1004。
  2. UPDATE … SET limit_cents=?, version=version+1 WHERE id=? AND family_id=? AND version=? AND deleted_at IS NULL。
  3. 影响行数为 0：再查一次——行不存在（或跨家庭，同形不泄露）→ 404 + 1001；行存在但 version 对不上 → 409 + 1009，响应 data 带双版本 payload（你提交的 version 与库里当前 version 及当前值），前端据此提示「数据已变化，请刷新」。
片段 · 1009 响应的 data 形状（全站乐观锁冲突统一这个形状）{ "submitted_version": 2, "current_version": 3, "current": { "id": 1, "limit_cents": 250000 } }

金额校验复用昨天的分工：改后 limit_cents ≤ 0 → 400 + 4001。改了限额之后还有一件挂钩的事：限额调高导致不再超阈值时，告警状态应该复位（否则本周期不会再告警）。告警是明天 S6·D22 的主题，今天先在 service 的 Update 成功分支里留一行 // TODO(S6·D22): 复位 alerted_at 注释位，明天填——这是「不许留半成品」纪律下唯一合法的 TODO：有主、有卡号、明天就兑现。

片段 · server/internal/finance/handler/budget.go 追加（前置：路由分组同昨天）type updateBudgetReq struct {
    LimitCents int64 `json:"limit_cents" binding:"required"`
    Version    int   `json:"version" binding:"required"`
}

func (h *BudgetHandler) Update(c *gin.Context) {
    id, err := strconv.ParseInt(c.Param("id"), 10, 64)
    if err != nil { response.FailErr(c, response.ErrNotFound); return } // 路径 id 不是数字 → 与不存在同形
    var req updateBudgetReq
    if err := c.ShouldBindJSON(&req); err != nil {
        response.FailErr(c, response.ErrBadRequest); return
    }
    out, err := h.svc.Update(c.Request().Context(), c.GetInt64("familyID"), id, req.LimitCents, req.Version)
    if err != nil { response.FailErr(c, err); return } // 1001/1004/1009/4001 全在哨兵映射里
    response.OK(c, out)
}

常见坑（新手 100% 会踩）

坑现象正确姿势
未设周期返回 404前端把空态渲染成错误页，监控里错误率虚高200 + code 0 + budget_unset:true，这不是错误
月预算×3 当季预算用户看到从没设过的数字，超支判定全错任何出口都不折算；只认真实行
用 list:[] 表达未设与「设了但都删了」不可区分，前端靠猜显式布尔标记，写进响应结构体
判定散落在各 handler报表、首页各写一份，总有一份漏掉红线判定收在 service 一个函数，出口共用
PUT 允许改 period_key唯一索引撞车、历史周期对不上账周期键不可改；换周期 = 建新行
1009 响应不带双版本前端只能提示「冲突」，用户不知道现在库里是多少data 带 submitted_version / current_version / current
