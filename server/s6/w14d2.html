时间窗五档参数：非法编码 400+1007 不回落

流水列表的筛选参数还缺一块拼图：时间窗。全站口径是五档——day / week / month / quarter / year，编码分别是 YYYY-MM-DD / YYYY-Wnn / YYYY-MM / YYYY-Qn / YYYY。今天把 period 参数接进 GET /api/finance/transactions：合法编码解析成 [start, end) 半开区间进 WHERE；非法编码返回 400 + 1007，绝不回落到任何默认档。这个解析器收进 platform，之后的导出接口与报表都复用它。

今日目标

知识讲义

1. 五档编码与区间换算

档编码例解析结果 [start, end)
dayYYYY-MM-DD2026-03-08当日 00:00 → 次日 00:00
weekYYYY-Wnn2026-W10ISO 8601 第 10 周的周一 00:00 → 下周一 00:00
monthYYYY-MM2026-031 日 00:00 → 次月 1 日 00:00
quarterYYYY-Qn2026-Q11/1 → 4/1（Q2: 4/1→7/1，Q3: 7/1→10/1，Q4: 10/1→次年 1/1）
yearYYYY20261/1 → 次年 1/1

两个易错点：ISO 周的编号不归「1 月 1 日所在周」直觉管——2026 年 1 月 1 日是周四，W01 从 2025-12-29（周一）开始；跨年周（2025-W52 尾巴伸进 1 月）是周档最容易翻车的地方，Go 标准库没有现成的 ISO 周解析，要自己按「该年第一个周四所在周为 W01」的规则算。季度只有 Q1-Q4，2026-Q5 与 2026-Q0 都是非法。

2. 非法编码：1007，不回落

非法清单（全部 400 + 1007）：2026-13（13 月）、2026-W54（54 周）、2026-Q5、2026-3（月不补零）、abc、2026/03（分隔符错）。红线是「不回落」：解析失败时不许悄悄当成本月、本年处理。回落的危害是静默的——用户请求 2026-W54，前端 bug 也好、手敲也好，服务端若回落到「本月」，用户看到的是一份看起来完全正常的账目，时间段却根本不是你请求的那个。错误必须吵出来：1007 就是为时间窗单设的错误码，与 1004 分开，让客户端能精确提示「时间格式不对」。

口径补一条：period 参数缺席 ≠ 非法。不带 period 就是不做时间过滤（配合其他筛选与分页照常）；带了但解析不动，才 1007。

3. 半开区间与时区

所有档统一产出 [start, end)：SQL 条件是 occurred_at >= ? AND occurred_at < ?。不用 BETWEEN（闭区间）的原因：BETWEEN '2026-03-01' AND '2026-03-31' 的右端是 31 日 00:00:00，31 日当天的账全漏；写成 23:59:59 又漏掉最后一秒里的毫秒行。半开区间「下一档的起点 = 上一档的终点」，天衣无缝，相邻窗口不重不漏——这正是分页判据「不重复、不漏」在时间轴上的孪生。

时区口径：日/周/月的「00:00」是谁的 00:00？家庭有自己的时区（建家庭时录入）。但 finance 不许直查 homeos 的表——时区通过 platform 的 FamilyDirectory 接口取（S4 建的跨模块接口，今天第一次真消费）；教学期容器统一 UTC 时也成立，接口把这层选择收在 platform 后面。

前端 shell 的时间窗切换器只暴露月/季/年三档，服务端却接受五档——不是矛盾：多出的日/周两档给财务面的日视图、周视图用。服务端能力 ≥ 前端暴露，是全站的常态设计。

今日增量（在学习仓里落盘）

今天属增量类型 ⑤+③：把流水查询从「无时间过滤」换成「period 五档过滤」+ 解析器测试。解析器本体放 internal/platform/period（共享件，导出与报表后续复用）。

步骤 1 · period 解析器

完整 · server/internal/platform/period/period.gopackage period

import (
    "fmt"
    "regexp"
    "strconv"
    "time"
)

// ErrInvalid 是「非法编码」的哨兵；上层映射 400 + 1007。绝不回落。
var ErrInvalid = fmt.Errorf("period: 时间窗编码非法")

var (
    reDay     = regexp.MustCompile(`^(\d{4})-(\d{2})-(\d{2})$`)
    reWeek    = regexp.MustCompile(`^(\d{4})-W(\d{2})$`)
    reMonth   = regexp.MustCompile(`^(\d{4})-(\d{2})$`)
    reQuarter = regexp.MustCompile(`^(\d{4})-Q([1-4])$`)
    reYear    = regexp.MustCompile(`^(\d{4})$`)
)

// Parse 把五档编码解析成 [start, end) 半开区间（loc 为家庭时区）。
func Parse(s string, loc *time.Location) (start, end time.Time, err error) {
    switch {
    case reYear.MatchString(s):
        y, _ := strconv.Atoi(s)
        start = time.Date(y, 1, 1, 0, 0, 0, 0, loc)
        return start, start.AddDate(1, 0, 0), nil
    case reQuarter.MatchString(s):
        m := reQuarter.FindStringSubmatch(s)
        y, _ := strconv.Atoi(m[1]); q, _ := strconv.Atoi(m[2])
        start = time.Date(y, time.Month((q-1)*3+1), 1, 0, 0, 0, 0, loc)
        return start, start.AddDate(0, 3, 0), nil
    case reMonth.MatchString(s):
        m := reMonth.FindStringSubmatch(s)
        y, _ := strconv.Atoi(m[1]); mo, _ := strconv.Atoi(m[2])
        if mo < 1 || mo > 12 { return start, end, ErrInvalid }
        start = time.Date(y, time.Month(mo), 1, 0, 0, 0, 0, loc)
        return start, start.AddDate(0, 1, 0), nil
    case reDay.MatchString(s):
        t, e := parseDay(s, loc)
        return t, e, e2err(t, e)  // 前置：parseDay 用 time.Date 回读校验 2026-02-30 类假日期
    case reWeek.MatchString(s):
        return parseISOWeek(s, loc) // 前置：按「该年第一个周四所在周为 W01」实现，W00/W54 → ErrInvalid
    }
    return start, end, ErrInvalid
}

time.Date 会静默归一化：time.Date(2026, 2, 30, …) 不报错，给你 3 月 2 日。day 档必须构造后回读（年/月/日与原输入一致才算合法），否则 2026-02-30 这种假日期就混过去了。

import (
    "errors"
    "testing"
    "time"
)

func TestParseFiveGranularities(t *testing.T) {
    utc := time.UTC
    ok := []struct{ in, start, end string }{
        {"2026-03-08", "2026-03-08T00:00:00Z", "2026-03-09T00:00:00Z"},
        {"2026-W10", "2026-03-02T00:00:00Z", "2026-03-09T00:00:00Z"},
        {"2026-03", "2026-03-01T00:00:00Z", "2026-04-01T00:00:00Z"},
        {"2026-Q4", "2026-10-01T00:00:00Z", "2027-01-01T00:00:00Z"},
        {"2026", "2026-01-01T00:00:00Z", "2027-01-01T00:00:00Z"},
    }
    for _, tt := range ok {
        s, e, err := Parse(tt.in, utc)
        if err != nil { t.Fatalf("%s 应合法: %v", tt.in, err) }
        ws, _ := time.Parse(time.RFC3339, tt.start); we, _ := time.Parse(time.RFC3339, tt.end)
        if !s.Equal(ws) || !e.Equal(we) { t.Fatalf("%s → [%s,%s), want [%s,%s)", tt.in, s, e, ws, we) }
    }
    bad := []string{"2026-13", "2026-W00", "2026-W54", "2026-Q0", "2026-Q5", "2026-3", "2026-02-30", "abc", "2026/03", "26-03"}
    for _, in := range bad {
        if _, _, err := Parse(in, utc); !errors.Is(err, ErrInvalid) {
            t.Fatalf("%s 应 ErrInvalid(1007)，got %v——不许回落！", in, err)
        }
    }
}

常见坑（新手 100% 会踩）

坑现象正确姿势
解析失败回落默认档用户拿到「看起来正常」的错误时间段账目1007 吵出来；回落是红线
ISO 周按「1 月 1 日所在周」算跨年周边界差一周W01 = 该年第一个周四所在周；用测试钉住 2026-W10 这类已知值
BETWEEN 闭区间月末最后一天的账全漏半开 [start, end)，右端是下一档起点
time.Date 归一化2026-02-30 变成 3 月 2 日混进查询构造后回读年月日比对，不一致 → ErrInvalid
时区拿服务器 local容器 UTC、家庭东八区，「今天」差 8 小时时区经 platform 的 FamilyDirectory 取家庭口径
把 period 空串当非法不带时间筛选的列表全被打回缺席 = 不过滤；带了才解析
1007 与 1004 混用客户端没法区分「时间格式错」与「别的参数错」时间窗专用 1007，这是它单设一码的意义
