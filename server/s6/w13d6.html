周六 · 流水·附件·账户·分类接口测试全量

知识讲义

1. 负样本矩阵：测试的地图

把「接口 × 异常输入 → 错误码」画成表，空格子就是测试空洞。今天的基准矩阵（√ = 必须有测试）：

接口10011004100610081009101040014002
POST /transactions√ 账户不存在√ 缺字段—√ 异体—√ 归档账户√ ≤0 / 两端同账户—
PUT /transactions/{id}√ 不存在/越权/已删√ 缺 version——√ 旧版本—√ 金额≤0—
DELETE + restore√————√ 恢复活行——
GET /transactions（含回收站）—√ 假游标/limit 越界——————
POST /{id}/attachments√ 流水不存在——————√ 张数/大小/格式
POST /accounts、PUT /accounts/{id}√√√ 重名—√√ 取消唯一默认——
archive/restore（账户）√————√ 余额非0/重复/默认账户——
archive/restore/sort（分类）√√ 排序集合不等———√ 父死子活/恢复未停用——

横着读是「这条接口都有哪些失败方式」，竖着读是「这个错误码在哪些接口出现」。竖着读更重要：同一个码在所有接口的触发条件必须同族同形——1001 永远是「不存在/越权/已删」三合一，任何接口都不许例外。

2. 越权同形的专项测法

「越权读返回与不存在同形」不能靠肉眼比 JSON，要断言逐字节相等：

片段 · 同形断言的形状respMissing := get(t, tokenA, "/api/finance/transactions/999999")   // 真不存在
respOther   := get(t, tokenB, "/api/finance/transactions/%d", txID)  // 存在但属于 A 的家庭
// 断言：状态码相同、body 三键逐字段相同（id 不同是 URL 差异，不进 body）

今天用 B 家庭的用户（S4 的多家庭测试脚手架）把流水单条、账户、分类三个域的同形各测一遍。

3. 契约测试：信封只有一种形状

再补一类「横切」测试：随便挑成功与失败响应各几条，断言都能解进 response.Body 三键结构、code=0 当且仅当 HTTP 2xx、列表接口的 data 里有且仅有 list/next_cursor/has_more（小集合有且仅有 list）。契约测试便宜、脆性低，但能拦住日后某次顺手改信封的「小重构」。

步骤 2 · 补空洞（示例：幂等并发一发）

完整 · server/internal/finance/service/transaction_matrix_test.go（节选：并发同键只落一笔）package service

import (
    "sync"
    "testing"
)

func TestConcurrentSameIdemKeyCreatesOne(t *testing.T) {
    svc, a := newTestTxService(t), Actor{FamilyID: 1, MemberID: 10}
    in := newTxInput("race-key-1", 2500)
    var wg sync.WaitGroup
    ids := make([]int64, 8)
    for i := 0; i < 8; i++ {
        wg.Add(1)
        go func(i int) {
            defer wg.Done()
            tx, err := svc.Create(t.Context(), a, in)
            if err != nil { t.Errorf("goroutine %d: %v", i, err); return }
            ids[i] = tx.ID
        }(i)
    }
    wg.Wait()
    for _, id := range ids[1:] {
        if id != ids[0] { t.Fatalf("同键并发落了多笔: %v", ids) }
    }
    // 8 个 goroutine 要么拿到首次创建的 id，要么拿到重放快照——必须是同一个 id
}

这条测试必须跑在 -race 下（Makefile 里 make test 本来就带）。它同时验证 D1 说的「唯一索引兜底」：并发穿过「先查后插」的缝时，第二个 INSERT 撞索引被转成重放，而不是报错给用户。如果你的实现这里翻车了——恭喜，测试干了它该干的事，回去修 service。

常见坑（新手 100% 会踩）

坑现象正确姿势
只测成功路径上线第一个用户就撞出 500负样本矩阵先行；每个错误码至少一格
测试之间共用脏数据单跑绿、全量跑红，顺序依赖每条测试自己 seed 自己清（或事务回滚脚手架），互不知晓
断言只看状态码409 对了但 code 是错的族，前端照样崩状态码与业务码成对断言，payload 关键字段也要断
并发测试没有 -race数据竞争静默通过，某天在真机上炸make test 永久带 -race 与 -count=1
「同形」靠肉眼 diffmessage 差一个字就泄露存在性两个响应逐字节断言相等
周六顺手加新功能测试没补完，功能也半成品今天只许修 bug 与补测试；新想法记进 notes/ 排到下周
