报表游标与无上限返回禁令

报表做到这里，一个绕不开的问题浮出水面：聚合结果到底要不要分页？全站口径是「列表强制游标分页、不接受无上限返回」，可报表返回的桶明明看起来「就几行」。今天把边界划清：哪些数据有界可全量、上界怎么钉死、明细下钻走哪条路、导出为什么是另一个物种。增量很小（span 校验 + 测试），但口径要一次立对——这是明天导出接口的前置课。

今日目标

知识讲义

1. 一条判断题：这个响应有界吗

全站口径把返回分两类，判据只有一条——行数上界是否先验可知且足够小：

类别响应形状例子
有界小集合{"list":[…]}，不带 next_cursor/has_more分类树、面目录、成员列表、预算列表（D20）、周期规则（D23）
无界/可增长列表{"list":[…],"next_cursor":"…","has_more":true}流水列表（D7）、动态流、通知（S7）

报表三视图属于哪类？先验有界，但界要靠参数钉死：

  • trend：桶数 = span。span 不设上限的话，span=100000 的日档查询就是一次合法的「无上限返回」——所以今天把上界写进 DTO。
  • category：行数 ≤ 分类树规模。分类树本身是有界小集合（家庭自定义 + 预置默认树），聚合结果不会超过它。
  • member：行数 ≤ 家庭成员数。成员数有产品上限，天然有界。

为什么有界集合不硬套游标信封：多出的 next_cursor: null 会逼前端给每个列表页写同一套「触底续读」逻辑，而它永远续不出第二页。信封是给「可能翻页」的数据用的；确定翻不了页，就用确定性的形状。前端 F4 段的游标练习只针对流水列表，正是这个分工。

2. span：上限、缺省与越界的三选一

span 越界时有三种候选处理：静默截断到 24（吞掉客户端 bug）、回落缺省 6（和 1007 的「不回落」精神冲突）、报错 400 + 1004。选第三种，全站对非法参数只有一个态度。上界定多少是产品决策兼工程决策：24 个月桶 = 两年趋势图，够画了；日档 24 桶不足一个月——所以再补一条口径：span 的上限随档位，day 档允许 31（一个月）、week 档 53（一年）、month 档 24、quarter 档 12、year 档 10。表驱动一张小表就管住了：

片段 · server/internal/finance/service/report_service.go（前置：D26 的 BucketRange 已在用 span）var spanMax = map[period.Granularity]int{
    period.Day: 31, period.Week: 53, period.Month: 24, period.Quarter: 12, period.Year: 10,
}
const spanDefault = 6

// normalizeSpan：缺省/空串 → 6；解析失败、<1、>spanMax[档位] → ErrBadRequest(1004)。
func normalizeSpan(raw string, g period.Granularity) (int, error) {
    if raw == "" { return spanDefault, nil }
    n, err := strconv.Atoi(raw)
    if err != nil || n < 1 || n > spanMax[g] {
        return 0, response.ErrBadRequest
    }
    return n, nil
}

注意顺序：先解析 period 定档位，再校验 span——span 的上限依赖档位。period 非法先撞 1007，轮不到 span 的 1004，两个码不会打架。

3. 明细下钻与导出：两条歧路的正确走法

报表桶点开后要看「这个月到底是哪些流水」，两种错误走法：给 summary 加 include_details=true（聚合接口夹带无界明细，一次请求打爆内存）；或前端拿全量流水自己聚合（S6·D9 立过的规矩：读单笔必须走 GET /api/finance/transactions/{id}，不得依赖「拉整月数据再客户端筛选」）。正确走法只有一条：下钻回到 GET /api/finance/transactions，带上桶的周期键当筛选参数，走它现成的游标分页——明细永远是流水接口的事，报表永远只出聚合。

导出（明天的 GET /api/finance/reports/export）看起来也是「无上限返回」，为什么被豁免？因为它不是 JSON 列表接口，是文件流：响应体是 attachment，服务端边查边写、逐行 Flush，内存占用与行数无关；「行数 = 同筛选查询行数」的红线恰恰要求它完整。豁免的是「一次响应装不下」的担忧，不豁免的是筛选口径——明天展开。

4. 游标契约复习（S3 立，S6 末自检）

  • 游标是不透明字符串：服务端把 (排序键, id) base64 编码；客户端不解析、不自造、不改一个字符。
  • 禁 offset：offset 分页在并发写入下会重复/漏行，且深翻页性能线性劣化。全站任何列表都不许出现 page/size 参数。
  • 判据三连（F4 前端侧同款）：不重复、不漏、能续读。
