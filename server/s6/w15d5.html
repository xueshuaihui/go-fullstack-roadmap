周期记账规则表 finance_recurring_rule

B6 周期记账：房租、话费、工资这类「到点自动记一笔」。今天定规则表 finance_recurring_rule 的结构，落两条接口 GET /api/finance/recurring 与 POST /api/finance/recurring。开工前先背下三句分工，这是本段最容易走歪的地方：规则只由 finance 写；到点触发归 S7 的到期中心；本表不自建定时器。

今日目标

知识讲义

1. 规则行 = 一笔「将来会自动发生的流水」的模板

字段类型语义
titleTEXT NOT NULL规则名，入账后成为流水备注前缀（如「房租」）
directionTEXT NOT NULLexpense / income；周期规则不支持转账——转账要两个账户都稳定，自动转账风险大于收益
amount_centsBIGINT NOT NULL每期金额，> 0，否则 400 + 4001
account_id / category_idBIGINT NOT NULL入账账户与分类；创建时校验属于本家庭（越权/不存在 → 404 + 1001）
freqTEXT NOT NULLweekly / monthly 两档；枚举在 Go 侧落成常量
anchor_weekdaySMALLINT NULLweekly 用：1-7（周一到周日）
anchor_daySMALLINT NULLmonthly 用：1-31
enabledBOOLEAN NOT NULL DEFAULT true停用不删行，历史入账记录保持可追溯
next_run_atTIMESTAMPTZ NOT NULL下次应执行日（家庭时区的当天零点）；给 S7 到期中心读的注册数据
通用列—id / family_id / created_at / updated_at / deleted_at / deleted_by / version

表在 S3 建库时已随 B 段表族落过骨架；今天若你的库里还没有这些列，就按上表补一条迁移（up/down 成对）。锚点两列二选一：freq=weekly 时 anchor_weekday 非空、anchor_day 为空，monthly 反之——两条 CHECK 约束写进迁移，别让脏数据活到 service 层。

2. 三句分工：谁写、谁触发、谁不定时

  • 规则只由 finance 写。GET/POST/PUT 三条接口全在 /api/finance/recurring 域下，别的模块（包括 S7 的到期中心）只读不写。到期中心发现规则停用了，是 finance 的 PUT 先改了 enabled，到期中心跟着撤销注册——数据流向永远是 finance → 到期中心。
  • 到点触发归 S7 到期中心。S7 会建 DueRegistry：全站的「到点要干事」都注册进去，由它统一扫描触发。今天 next_run_at 就是将来的注册项内容。S6 期间没有到期中心，怎么测自动入账？——明天周六直接写一个 RunDue(ctx, now) service 函数手工调用，测试里传任意时刻；S7 建好到期中心后，「谁来调 RunDue」换成它，RunDue 本身不变。
  • 本表不自建定时器。finance 里不许出现 time.Ticker、time.AfterFunc、常驻 goroutine。每个业务模块自己起定时器，进程里就有 N 个调度器：重复触发、无法统一暂停、测试不可控。「到期中心只有一个」是 S7 的判据，今天先守住不破坏它。

3. next_run_at 的计算：月末收敛是唯一的坑

weekly 简单：从生效日起找下一个锚点星期几。monthly 有个经典陷阱：锚点 31 号，2 月怎么办？ Go 的 time.Date 会「规整化」——time.Date(2027, 2, 31, …) 不报错，直接给你 3 月 3 日。规则从此漂移：3 月 31 号那期又正常，2 月永远错。正确口径是收敛到当月最后一天（2 月落 28/29），这也是各大记账产品的通行做法。纯函数实现，playground 里先跑通再进项目：

可跑 · server/playground/d23/main.go（独立 go.mod，S1·D1 立的沙盒规矩）package main

import (
    "fmt"
    "time"
)

// lastDay 返回 y 年 m 月的最后一天（m 为 1-12）。
func lastDay(y int, m time.Month) int {
    return time.Date(y, m+1, 0, 0, 0, 0, 0, time.UTC).Day() // 下月 0 号 = 本月最后一天
}

// nextMonthly 从 from（不含）之后找第一个 anchorDay 号；当月不足则收敛到最后一天。
func nextMonthly(from time.Time, anchorDay int) time.Time {
    cur := time.Date(from.Year(), from.Month(), 1, 0, 0, 0, 0, from.Location())
    for i := 0; i < 14; i++ { // 14 个月内必命中；循环上限只是防御
        day := anchorDay
        if ld := lastDay(cur.Year(), cur.Month()); day > ld { day = ld }
        cand := time.Date(cur.Year(), cur.Month(), day, 0, 0, 0, 0, from.Location())
        if cand.After(from) { return cand }
        cur = cur.AddDate(0, 1, 0) // 从 1 号推进，避开月末规整化坑
    }
    return time.Time{} // 不可达；防御性零值
}

func main() {
    tz := time.FixedZone("CST", 8*3600)
    from := time.Date(2027, 1, 15, 10, 0, 0, 0, tz)
    fmt.Println(nextMonthly(from, 31)) // 2027-01-31（本月还没过）
    fmt.Println(nextMonthly(time.Date(2027, 1, 31, 12, 0, 0, 0, tz), 31)) // 2027-02-28 收敛，不是 03-03
    fmt.Println(nextMonthly(time.Date(2028, 1, 31, 12, 0, 0, 0, tz), 31)) // 2028-02-29 闰年
}

跑通后把两个函数搬进 internal/finance/service/recurring_schedule.go，playground 目录删掉。时区口径：from 用「家庭时区的今天零点」——又是昨天那条 platform 家庭上下文接口，全 S6 段只有这一个拿时区的通道。

常见坑（新手 100% 会踩）

坑现象正确姿势
finance 里起 ticker「先把自动入账跑起来」N 个模块 N 个调度器，S7 到期中心没法收编调度只有一个（S7）；今天只写 next_run_at 数据
time.Date(2027, 2, 31, …) 直接用静默规整成 3 月 3 日，规则永久漂移锚点日 > 当月最后一天时收敛到月末
next_run_at 存服务器本地时区的「零点」容器 UTC，家庭在东八区，执行日差一天家庭时区当天零点换算成 TIMESTAMPTZ 存
GET 列表套游标信封小集合带 next_cursor:null，前端多写一套续读逻辑有界小集合直接 {"list":[…]}
停用规则用 DELETE历史自动入账的流水失去出处，不可追溯enabled=false 停用；删除走软删且是另一回事
允许周期规则做转账两端账户任一归档/停用，自动转账卡死direction 只收 expense/income

今日名词卡

术语一句话解释
周期记账（recurring）按规则到点自动生成流水；规则是模板，流水是实例
finance_recurring_rule规则表；只由 finance 写，到期中心只读
next_run_at下次应执行日；S7 到期中心的注册数据来源

time.Date 规整化Go 把超界日期静默折算进下月（2 月 31 → 3 月 3）的行为
有界小集合行数天然有限的列表；直接 list，不带游标字段
RunDue（明天登场）手工触发的执行函数；S7 起由到期中心调用

卡壳时查什么

  • time.Date / Month 算术的行为：Go 官方文档 time.Date（可选，重点读那句 normalizes）。
  • CHECK 约束写法：回本站 S3 的 DDL 卡；两张锚点互斥的 CHECK 今天照抄即可。
  • 为什么「到期中心只有一个」：回本站 S4 讲跨模块接口那天的卡——今天 Notifier、明天 DueRegistry，都是同一个思想：跨模块调用点收在 platform 接口后面。
